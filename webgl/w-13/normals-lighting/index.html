法线计算与光照方向

展示顶点法线、法线矩阵与光照方向的正确变换。

开场问题：你把球体、立方体的光照都调好了。为了做一个「压扁的盒子」，你把模型的 Y 轴缩放调成 0.5、Z 轴调成 2——几何被拉长了，可光照立刻不对劲：本该朝着光、应该最亮的那一面却发暗，本该背光的窄面反而亮得刺眼。你只改了缩放，光的方向和顶点数据一个都没动，为什么亮面和暗面会「换位」？

形变法线偏移

光照算的是 N·L，其中 N 是法线——垂直于表面的方向。当你对模型施加变换（旋转、缩放）时，顶点跟着走，法线也必须跟着正确地变化，否则它就不再垂直于变形后的表面，算出的光照自然全错。

麻烦在于「法线该怎么变」并不显然，随手糊弄都要付账：直接把法线当常量不动，物体一转身法线就错；用模型矩阵直接乘法线，旋转看着没问题，可一旦非等比缩放就出乱子；想让每个顶点都手工求一遍法线，曲面又太难，还很难保证相邻面共享顶点时法线方向一致。所以真正要问的是：存不存在一个矩阵，能把任意变换（尤其是非等比缩放）下的法线，正确地变换到世界空间？

旋转与等比缩放

先看简单情形。对纯旋转和等比缩放来说，模型矩阵左上角那个 3×3 就够了：旋转会把法线正确地旋转过去，等比缩放只是把法线按同一个比例拉长——而拉长不影响方向，最后归一化就抵消掉了。于是先写 normalize(mat3(model) * aNormal)。

这个方案做对了一件重要的事：它让法线跟着模型「转」了。物体旋转时明暗不会漂移，方向感是对的。只要你不做非等比缩放，这么写完全够用。

非等比缩放偏差

  • 非等比缩放就错。法线是「垂直关系」，不是「位置坐标」。把表面沿 Y 压扁后，原本垂直于它的法线应当朝「反方向」倾斜；直接用模型矩阵乘，法线会偏到错误的朝向，正如开场那样亮面变暗、暗面变亮。
  • 硬边会被抹平。立方体若用「所有相邻面法线平均」当作每个顶点的法线，六个面会共享同一条光滑法线，硬边消失，方盒看着像个软胶块。
  • 忘了归一化强度失真。模型缩放会让法线长度改变，N·L 的强度被整体放大或缩小，光照忽明忽暗。
  • 拿 4×4 整套矩阵去变。法线是方向量，与平移无关；若连平移一起作用，方向会被无谓地污染。

法线来源与着色

先分清法线从哪里来。硬边物体（立方体）每个面用一个面法线，顶点拆开、各面独立，得到棱角分明的平面着色（flat）；曲面（球体、车体）则把每个顶点的法线取相邻面法线的平均，共享顶点、在光栅化时插值，得到平滑着色（smooth）。演示里可以一键切换这两套数据，直接对比同一个立方体在两种法线下的明暗差别。先讲这个，是因为法线数据本身得先正确，后面的变换才有意义。

再来修「非等比缩放」。关键洞察是：法线必须始终垂直于变换后的表面。如果表面的切向量 T 被模型矩阵 M 变换，我们要求 N'·(M·T) = 0 依然成立。能满足这个条件的，是模型矩阵左上 3×3 的逆转置：

N' = transpose(inverse(mat3(model))) · N

为什么是这个矩阵？直觉上，缩放把某个轴压扁时，垂直它方向的面会「翘」起来，法线恰好要反着动——而「逆转置」做的正是把缩放的比例取倒数再转置，正好补上这一步。流程整理成：

  1. 为网格提供位置 + 法线两类 attribute（立方体每面一个面法线，保留硬边）。
  2. 由模型矩阵左上 3×3 求逆转置，得到 uNormalMatrix。
  3. 顶点着色器用它变换法线并归一化：vNormalWorld = normalize(uNormalMatrix * aNormal)。
  4. 在片段着色器中结合法线、光源、视线计算光照，并叠加沿法线的短线段，直接查看各面法线的朝向。
边界提醒：等比（均匀）缩放时，逆转置会退化成「旋转部分乘一个统一比例」，归一化后等价于直接用左上 3×3，也就是说只有非等比缩放才必须用逆转置。另外，法线矩阵只处理方向、与平移无关，取左上 3×3 即可，不必用整个 4×4；变换完务必归一化，否则点积、反射等运算得到的强度会被额外放大或缩小。

缩放畸变光照

逆转置矩阵变换

光照对不对，一半取决于法线对不对。法线描述表面朝向：曲面用平均法线做平滑着色，硬边用面法线做平面着色；而只要模型出现非等比缩放，法线就必须用模型矩阵左上 3×3 的逆转置来变换，否则它会指向错误的方向。

「法线矩阵（Normal Matrix）」是用于把法线从模型空间正确变换到世界（或观察）空间的矩阵，等于模型矩阵左上 3×3 子矩阵的逆转置，即 transpose(inverse(mat3(model)))，它保证法线在任意变换（含非等比缩放）后仍垂直于表面。边界与例外：纯旋转或等比缩放时可退化为直接用左上 3×3；它与平移无关，因此只取 3×3；变换后必须重新归一化。

关键代码

GLSL
// ===== 顶点着色器 Vertex Shader =====
attribute vec3 aPosition;
attribute vec3 aNormal;
uniform mat4 uModel;
uniform mat4 uView;
uniform mat4 uProjection;
uniform mat3 uNormalMatrix;
varying vec3 vNormalWorld;
varying vec3 vPositionWorld;
void main() {
  vec4 worldPos = uModel * vec4(aPosition, 1.0);
  vPositionWorld = worldPos.xyz;
  vNormalWorld = normalize(uNormalMatrix * aNormal);
  gl_Position = uProjection * uView * worldPos;
}

// ===== 片段着色器 Fragment Shader（平滑着色版 Smooth） =====
precision mediump float;
varying vec3 vNormalWorld;
varying vec3 vPositionWorld;
uniform vec3 uAmbient;
uniform vec3 uLightDir;
uniform vec3 uViewPos;
uniform vec3 uMatColor;
void main() {
  vec3 N = normalize(vNormalWorld);
  vec3 L = normalize(uLightDir);
  vec3 V = normalize(uViewPos - vPositionWorld);
  vec3 R = reflect(-L, N);
  float NdotL = max(dot(N, L), 0.0);
  float RdotV = max(dot(R, V), 0.0);
  vec3 ambient = uAmbient * uMatColor;
  vec3 diffuse = uMatColor * NdotL;
  vec3 specular = vec3(1.0) * pow(RdotV, 32.0) * 0.5;
  gl_FragColor = vec4(ambient + diffuse + specular, 1.0);
}

// ===== 片段着色器 Fragment Shader（平面着色版 Flat） =====
precision mediump float;
varying vec3 vNormalWorld;
varying vec3 vPositionWorld;
uniform vec3 uAmbient;
uniform vec3 uLightDir;
uniform vec3 uViewPos;
uniform vec3 uMatColor;
void main() {
  vec3 N = normalize(vNormalWorld);
  vec3 L = normalize(uLightDir);
  vec3 V = normalize(uViewPos - vPositionWorld);
  vec3 R = reflect(-L, N);
  float NdotL = max(dot(N, L), 0.0);
  float RdotV = max(dot(R, V), 0.0);
  vec3 ambient = uAmbient * uMatColor;
  vec3 diffuse = uMatColor * NdotL;
  vec3 specular = vec3(1.0) * pow(RdotV, 16.0) * 0.4;
  gl_FragColor = vec4(ambient + diffuse + specular, 1.0);
}

// ===== 顶点着色器 Vertex Shader（法线可视化辅助） =====
attribute vec3 aPosition;
uniform mat4 uModel;
uniform mat4 uView;
uniform mat4 uProjection;
void main() {
  gl_Position = uProjection * uView * uModel * vec4(aPosition, 1.0);
}
