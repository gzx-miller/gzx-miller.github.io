纹理过滤与 Mipmap

对比不同过滤模式和 Mipmap 层级的渲染效果。

开场问题：同一张棋盘纹理，铺满整屏时看着挺干净，可当相机一拉远、整块棋盘缩成指甲盖大小，画面开始「沙沙」抖动——你稍微动一下鼠标，纹理就闪成一片噪点，像信号不好。放大回去又恢复正常。

最近邻采样失真

你已经能把纹理贴到网格上，也知道每个屏幕像素会按插值出来的 UV 去采样。但采样时到底该「取哪一个纹素」这件事，你还没做决定。默认地，显卡取离 UV 最近的那一个纹素。

只取一个最近纹素，会在两个方向上同时出问题：

  • 放大时出马赛克。一个纹素被铺到很多屏幕像素上，边缘是一个个清楚的方块。
  • 缩小时出噪点。一个屏幕像素盖住了好几十个纹素，只取其中一个，等于随机丢掉了其余绝大部分信息，结果就是跳动的摩尔纹与闪烁。
  • 没法靠换图解决。想为每个缩放级别各准备一张缩小版图片，内存会成倍增长。
  • 顾此失彼。在某个距离调好的参数，换个距离又失效。

所以真正的问题是：一次采样到底该取几个纹素、按什么权重合并？放大和缩小能分开处理吗？

双线性插值采样

先解决放大。把采样方式从「取最近一个纹素」换成 LINEAR：取该点周围 2 x 2 的四个邻近纹素，按距离做双线性插值加权平均。

这个方案做对了一件事：它承认了「一个屏幕像素往往落在几个纹素中间」这个事实。放大时不再是一块块硬邦邦的方块，而是平滑过渡，边缘也不再锯齿分明。

缩小采样摩尔纹

  • 缩小时 LINEAR 依然不够：当屏幕一个像素覆盖了 4 x 4 甚至更大的一片纹素时，只平均邻近 2 x 2 个，仍会漏掉大量信息，摩尔纹照旧。
  • 它预平均的范围是固定的 2 x 2，与「这个像素实际覆盖多大面积」无关，缩放比例一变就顾此失彼。
  • 只用一张原图，缩得越小信息密度越高，硬件再怎么插值也压不住高频细节的冲突。
  • 放大与缩小被迫共用一套规则，而两者的需求其实正好相反。

多级渐远纹理

既然缩小的病根是「像素覆盖的面积远大于采样窗口」，那就从源头降低信息密度：给纹理预先准备一组逐级缩小的副本，也就是 Mipmap。缩小时硬件根据屏幕像素覆盖的纹素面积，自动挑一个大小合适的层级去采样。

于是流程变成：

  1. 按 2 的幂，用 texImage2D 的 level 参数逐级生成并上传各 mip 层。
  2. 把 MIN_FILTER 设为 NEAREST_MIPMAP_NEAREST 或 LINEAR_MIPMAP_LINEAR，MAG_FILTER 单独设置。
  3. 用缩放参数改变屏幕上纹素的覆盖比例，观察不同过滤下的清晰度差异。
  4. 用层级滑杆单独查看某一 mip 层，直观对比各层的清晰度。

光有层级还不够：如果只在单一层里取色，缩放连续变化时会在层与层之间跳变。所以再补上跨层与层内的插值——LINEAR_MIPMAP_LINEAR，也就是常说的三线性过滤：既在相邻两层各自做线性插值，又在这两层的结果之间再插一次。它质量最高，开销也最大。

走到这里，放大与缩小终于可以分开配置了。MAG_FILTER 只管放大；MIN_FILTER 只管缩小，而且它既可以是普通的 NEAREST / LINEAR，也可以是带 MIPMAP_ 的组合。

三条边界：其一，MAG_FILTER 只能设 NEAREST 或 LINEAR，不能带 MIPMAP_ 后缀——放大时根本用不到更小的层。其二，WebGL1 里一条完整的 mip 链通常要求纹理尺寸为 2 的幂，否则过滤不完整；WebGL2 或 NPOT 扩展才允许非 2 次幂纹理带 mip。其三，斜视角下纹理仍会发糊，可用各向异性过滤（EXT_texture_filter_anisotropic）改善，属于进阶优化。

锯齿与平滑对比

放大缩小过滤

纹理过滤回答的是「一次采样取几个纹素、怎么加权」。放大靠 NEAREST 与 LINEAR 二选一，缩小则必须靠 Mipmap 逐级降采样，再加上跨层插值，才能压住摩尔纹与闪烁。两者需求相反，所以要分开配置。

「Mipmap」是一组按 2 的幂逐级缩小的预生成纹理副本，用于纹理缩小时由硬件按屏幕覆盖面积自动选层、必要时跨层混合，以减轻摩尔纹与闪烁。记住边界：MIN_FILTER 可用带 MIPMAP_ 的过滤，MAG_FILTER 只能用 NEAREST / LINEAR；三线性 LINEAR_MIPMAP_LINEAR 质量最好但开销最大；WebGL1 完整 mip 链通常要求纹理为 2 的幂。

// ===== 顶点着色器 Vertex Shader =====
attribute vec3 aPosition;
attribute vec2 aUV;
varying vec2 vUV;
void main() {
  gl_Position = vec4(aPosition, 1.0);
  vUV = aUV;
}

// ===== 片段着色器 Fragment Shader =====
precision mediump float;
varying vec2 vUV;
uniform sampler2D uTexture;
uniform float uZoom;
uniform int uMipLevel;
uniform int uShowChain;
void main() {
  vec2 centered = (vUV - 0.5) / uZoom + 0.5;
  vec2 clamped = clamp(centered, 0.0, 1.0);
  if (uShowChain > 0 && uZoom > 1.2) {
    float mipFloat = float(uMipLevel);
    vec2 mipUV = vec2(clamped.x, clamped.y);
    gl_FragColor = texture2D(uTexture, mipUV);
    float levelIntensity = 0.15 + 0.05 * mipFloat;
    gl_FragColor.rgb += vec3(levelIntensity, levelIntensity * 0.5, 0.0);
  } else {
    gl_FragColor = texture2D(uTexture, clamped);
  }
}
