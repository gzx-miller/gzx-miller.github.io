WebGL 上下文与渲染管线

从 Canvas 获取 WebGL 上下文，用最简单的单色三角形看清顶点处理与片段处理两段可编程管线。

开场问题：你把 Canvas 2D 里那句 ctx.fill() 的思路原样搬进 WebGL，想画一个三角形，结果画布全黑、控制台却一个字都不报——代码没错、也没崩，为什么就是什么都没有？

二维绘图心智

Canvas 2D 让你觉得「画东西」是理所当然的：beginPath、moveTo、lineTo、fill，四行就有了一个三角形。可换成 WebGL，同样一个三角形却要写上几十行：取上下文、写两段着色器源码、编译、链接、建缓冲、传数据，最后才敢调用一次 drawArrays。

这不是 WebGL 故意为难你，而是它根本不认识「三角形」这个概念。Canvas 2D 里有一整套替你兜底的隐式成本，搬到 WebGL 上，这些成本必须由你自己承担：

  • 它不懂图元：Canvas 2D 知道「路径」和「填充」是什么意思；WebGL 只认顶点和像素，中间「怎么把顶点变成带颜色的像素」要靠你写的程序规定。
  • 它不在同一块内存里：Canvas 2D 拿到的坐标在 CPU 这一侧就画掉了；GPU 有自己的显存，你的顶点数据得显式拷贝过去，它才看得见。
  • 它没有默认状态：fillStyle 设一次就全局生效，而 WebGL 需要你在每次绘制前，自己把程序、缓冲、属性、全局量一一就位。

所以真正要问的是：一次绘制，到底要让哪些部件按什么顺序各就各位，GPU 才会画出东西？

获取图形上下文

最省事的想法是：先把「入口」拿到手，剩下的以后再说。canvas.getContext('webgl') 会返回一个 WebGLRenderingContext，你就把它当成「那个什么都能干的对象」，需要什么都在它身上找。

这个方案做对了一件很关键的事：WebGLRenderingContext 确实是所有 GPU 操作的唯一入口。编译着色器、创建缓冲、上传数据、发起绘制，全都挂在同一个对象上。如果这里返回 null（浏览器不支持 WebGL），后面的一切都无从谈起，早点判空反而能省掉一堆迷惑。

上下文与绘制落差

  • 只拿到上下文，屏幕上仍然只有 clearColor 刷出的底色——GPU 不知道该在哪、用什么颜色画，它会直接跳过绘制。
  • 你把着色器源码当普通字符串传进去，COMPILE_STATUS 却是 false，而函数并不抛异常，错误被藏在 getShaderInfoLog 里。
  • 就算程序链接成功，顶点着色器没写 gl_Position，GPU 也拿不到顶点位置，三角形无从谈起。
  • 顶点坐标以一个普通 JavaScript 数组传进去，GPU 根本读不到——它只认显存里的缓冲对象。

渲染管线装配

不推翻「上下文是入口」这一点，而是沿着这条入口把管线一段段接起来。WebGL 的启动流程本质上是一条固定顺序的装配线，缺任何一环，最后的 drawArrays 都画不出东西。

  1. 获取 Canvas，通过 getContext('webgl') 拿到 WebGL 上下文，它是后续所有调用的落点。
  2. 编写两段着色器：顶点着色器把 aPosition 写入 gl_Position，片段着色器输出 uColor。
  3. 把两段着色器分别 compileShader，再 linkProgram 链接成一个程序，随后用 getAttribLocation 与 getUniformLocation 取到变量位置。
  4. 把顶点数据通过 bufferData 上传成缓冲对象，送入显存。
  5. 绘制前设好属性与全局量，调用 drawArrays(TRIANGLES, 0, 3) 触发 GPU 跑完整条管线。

接的过程中，你会看清这条管线里只有两段是可编程的。顶点着色器每个顶点执行一次，负责把顶点放到该在的位置，必须写 gl_Position；片段着色器每个像素执行一次，负责决定这个像素是什么颜色，写 gl_FragColor。二者之间的裁剪、图元装配、光栅化由硬件固定管线完成，你写不了、也不需要写。本课这个三角形，位置来自逐顶点的 attribute，颜色来自整次绘制共享的 uniform。

还有几处容易被忽略、却会让画面直接变黑或报错的细节。顶点数据必须先经 Buffer 上传到显存，绘制前还要用 enableVertexAttribArray 与 vertexAttribPointer 把它连到 aPosition 上，否则着色器读到的是默认值。片段着色器里必须用 precision 声明浮点精度，mediump 省算力、highp 更精确但并非所有设备都保证支持——这是着色器写法与普通 JavaScript 最不一样的地方之一。

别把着色器当成「传个字符串」：compileShader 与 linkProgram 失败时都不会抛异常，只把状态置为 false。务必检查 COMPILE_STATUS / LINK_STATUS，失败时用 getShaderInfoLog / getProgramInfoLog 读出诊断信息，否则你只会看到一块黑屏。

顺带记一个不影响正确性、只影响表现与开销的设置：上下文的 antialias、alpha、preserveDrawingBuffer 这些属性只改变渲染行为，按需开启即可，别一律设成 true——它们各自都有代价。

装配线分段观测

缺环即不绘制

WebGL 画不出东西，几乎都不是「代码崩溃」，而是装配线上缺了一环。上下文是所有 GPU 操作的唯一入口，可编程的只有顶点与片段两段着色器，顶点数据必须显式上传进缓冲，最后由一次 drawArrays 把整条管线跑通。

「着色器程序（Shader Program）」是顶点着色器与片段着色器各自编译后、经 linkProgram 链接而成的可执行单元，也是 useProgram 与 drawArrays 实际使用的对象；attribute、uniform 的位置都要从链接后的程序上查询。注意着色器对象（shader）只是中间产物，链接失败的程序不可用，且同一个着色器可以被链接进多个程序。

关键代码

GLSL
// ===== 顶点着色器 Vertex Shader =====
attribute vec2 aPosition;
void main() {
  gl_Position = vec4(aPosition, 0.0, 1.0);
}

// ===== 片段着色器 Fragment Shader =====
precision mediump float;
uniform vec4 uColor;
void main() {
  gl_FragColor = uColor;
}
