WebGL2 新特性

展示 WebGL2 的 Uniform Buffer、Texture 3D、浮点纹理等新能力。

开场问题：你给场景里的每个着色器都设置同一组 uniform——时间、视口分辨率、强度。程序一多，性能分析里 CPU 侧的大头全花在一条条 gl.uniform* 调用上。你心想：数据明明就这三个数，打包成一块缓冲、上传一次、所有着色器共享，不就行了？可你在 WebGL1 里翻遍 API，也找不到「把一组 uniform 装进缓冲区」的接口。同一份数据，为什么只能一个字段一个字段地重复搬运？

逐条设置开销

这批能力的缺失不是偶然——WebGL1 定格在 OpenGL ES 2.0 那一代，很多后来成为标配的东西，它要么没有，要么得靠扩展拼凑。

沿用「逐个 gl.uniform* 设置 + 到处查扩展」的老办法，要人承担这些成本：

  • 状态切换开销。每帧、每个程序逐条调用 gl.uniform*，每一次都是 CPU 到 GPU 的提交，程序一多就成了 CPU 侧的瓶颈；
  • 数据要重复声明。「时间 / 分辨率 / 强度」这组数据被多个着色器共享，可每个程序里都得各声明一遍、各设置一遍，改一处要动 N 处，还容易不一致；
  • 基础设施全靠扩展。VAO 要 OES_vertex_array_object，3D 纹理干脆没有，代码里到处都是「有没有这个扩展」的分支判断。

问题由此落到一个很朴素的地方：能不能让一组 uniform 像顶点数据那样，被打包进一块缓冲区，一次上传、多个着色器共享？

渲染上下文升级

把上下文升级到 WebGL2：用 canvas.getContext('webgl2') 拿到基于 OpenGL ES 3.0 的上下文。它一次性解锁了一整批能力——统一缓冲区（UBO）、3D 纹理、原生 VAO、整数纹理、Transform Feedback、多目标渲染（MRT）。

这个方案做对了一件事：它把「要什么能力就得先找什么扩展」变成了「一个版本全部内置」。但升级不是把 'webgl' 改成 'webgl2' 就完事：着色器也得跟着换用 GLSL 3.0 方言。

着色器语法迁移

  • 语法不对就编不过。把 WebGL1 的 attribute / varying / gl_FragColor 原样塞进 #version 300 es，编译会直接报错——属性要写 in，跨阶段变量顶点出用 out、片段的入用 in，片段输出要自己声明一个 out 变量。
  • UBO 不是随手排的。它按 std140 布局，成员有对齐规则——vec2 要 8 字节对齐、矩阵按列分段、数组元素补齐到 16 字节。按 C 的直觉紧凑排布，数据就会错位，GPU 读到的全是垃圾。
  • 建了缓冲还得绑定。UBO 创建之后，要 getUniformBlockIndex 找到块、uniformBlockBinding 指定绑定点，再把缓冲绑到那个点上，少一步着色器里的块就是空的。
  • 不是拿到 webgl2 就万事大吉。浮点 / 整数渲染目标仍要 EXT_color_buffer_float 之类扩展，老设备可能根本拿不到 webgl2 上下文，还得准备回退。

统一缓冲区布局

先把 UBO 这条主线打通。在顶点和片段着色器里声明同名、同布局的块：layout(std140) uniform SharedData { float u_time; vec2 u_resolution; float u_intensity; };。两个阶段共享这一块数据，缓冲区只创建一块、每帧只更新一次，着色器里直接按成员名使用即可。对接它需要按顺序做对四步：

  1. 用 getUniformBlockIndex(program, 'SharedData') 拿到块的索引，再用 uniformBlockBinding 把它绑定到绑定点 0。
  2. 把存好数据的缓冲用 bindBufferBase(UNIFORM_BUFFER, 0, ubo) 绑到同一个套接点上，两者就对接上了。
  3. 按 std140 的对齐规则排布缓冲内容——vec2 之后的成员要落在 8 字节边界上，别按紧凑顺序硬填。
  4. 更新时只需一次 bufferSubData，不再逐个 uniform 调用。

顺手把状态切换也解决掉。WebGL2 原生提供 gl.createVertexArray，把「绑定缓冲 + 配置属性指针」这组状态一次性缓存进 VAO，之后绘制前只 bindVertexArray 一句，省掉每次重新配置属性——不再需要那个 OES_vertex_array_object 扩展。

再往前一步，用同一代提供的 3D 纹理做色彩分级：用 texImage3D 建一张 16×16×16 的体积纹理当查找表（LUT），着色器里声明 sampler3D，用三维坐标 texture(u_lut, vec3(u, v, w)) 取样，把输入颜色映射成另一套色调。共享的 UBO 里那个 u_intensity，正好拿来控制 LUT 与原色的混合比例。

最后对照 WebGL1 那份实现：同一画面在 WebGL1 里不能用 #version 300 es、没有 UBO、也没有 3D 纹理，只能逐个设置 uniform、用二维纹理去模拟。演示里的切换按钮，就是让你看到两套实现跑出相近的画面，但底层机制完全不同。

三个容易翻车的点：换了上下文就必须换语法——attribute 改 in、varying 改 out / in、gl_FragColor 改成自定义的 out 变量；std140 对齐是 UBO 最常见的坑，成员顺序或类型一变就要重新核对偏移；部分能力（浮点渲染目标等）仍需扩展，而且上线前要检测 webgl2 是否可用并准备回退。

六项新特性对比

扩展能力内置化

WebGL2 的意义不是「多了几个函数」，而是把一批原本要靠扩展拼凑、甚至根本做不到的能力，变成语言本身的一部分。核心的那个转变最先发生：一组共享的 uniform 从「逐个搬运」变成「一块缓冲、一次上传」，语法随之换代，UBO、3D 纹理、原生 VAO 都在这一代成了标配。

「统一缓冲区对象（Uniform Buffer Object，UBO）」是 WebGL2 中的一种缓冲，把多个 uniform 变量打包成一块内存，供多个着色器程序共享，通过绑定点与着色器里的 uniform 块对接；它替代了逐条 gl.uniform* 的设置方式，减少 CPU 到 GPU 的调用与重复声明。边界与例外：布局遵循 std140，成员有对齐规则（vec2 8 字节对齐、矩阵按列分段、数组元素补齐到 16 字节），排布错误会读到错位的垃圾数据；使用时必须 getUniformBlockIndex + uniformBlockBinding + bindBufferBase 三步对接。

关键代码

GLSL
// ===== 顶点着色器 Vertex Shader（WebGL 2 版，使用 UBO + layout location） =====
#version 300 es
precision highp float;
layout(location = 0) in vec2 a_position;
layout(location = 1) in vec3 a_color;

layout(std140) uniform SharedData {
  float u_time;
  vec2 u_resolution;
  float u_intensity;
};

out vec3 v_color;
out float v_depth;

void main() {
  v_color = a_color;
  vec2 pos = a_position;
  float s = sin(u_time + pos.x * 3.0) * 0.15;
  float c = cos(u_time * 0.7 + pos.y * 2.0) * 0.1;
  pos += vec2(s, c);
  v_depth = pos.y * 0.5 + 0.5;
  gl_Position = vec4(pos, 0.0, 1.0);
}

// ===== 片段着色器 Fragment Shader（WebGL 2 版，使用 UBO + sampler3D） =====
#version 300 es
precision highp float;
in vec3 v_color;
in float v_depth;

layout(std140) uniform SharedData {
  float u_time;
  vec2 u_resolution;
  float u_intensity;
};

out vec4 fragColor;

uniform sampler3D u_lut;

void main() {
  vec3 lutCoord = vec3(v_depth, 0.5, 0.5);
  vec3 lutColor = texture(u_lut, lutCoord).rgb;
  vec3 finalColor = mix(v_color, lutColor, u_intensity);
  fragColor = vec4(finalColor, 1.0);
}

// ===== 顶点着色器 Vertex Shader（WebGL 1 对比版） =====
attribute vec2 a_position;
attribute vec3 a_color;
uniform float u_time;
uniform float u_intensity;
varying vec3 v_color;
varying float v_depth;
void main() {
  v_color = a_color;
  vec2 pos = a_position;
  float s = sin(u_time + pos.x * 3.0) * 0.15;
  float c = cos(u_time * 0.7 + pos.y * 2.0) * 0.1;
  pos += vec2(s, c);
  v_depth = pos.y * 0.5 + 0.5;
  gl_Position = vec4(pos, 0.0, 1.0);
}

// ===== 片段着色器 Fragment Shader（WebGL 1 对比版） =====
precision mediump float;
varying vec3 v_color;
varying float v_depth;
uniform float u_intensity;
void main() {
  vec3 finalColor = mix(v_color, vec3(v_depth, v_depth * 0.8, 1.0 - v_depth), u_intensity);
  gl_FragColor = vec4(finalColor, 1.0);
}
