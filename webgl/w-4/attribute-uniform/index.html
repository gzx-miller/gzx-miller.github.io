attribute、uniform、varying 与数据传递

用动态彩色方块展示三种着色器变量类型的不同使用场景。

开场问题：你想让形状随时间上下起伏，于是把「时间」当成顶点属性，给每个顶点都存了一份一模一样的时间值。形状确实动了，可它每帧都要把整块顶点缓冲重新上传——明明只是改了一个数，却搬运了上千个顶点的数据，这活儿是不是干反了？

顶点数据粒度

在把数据送进着色器时，你手上其实混着好几种性质完全不同的数据：位置、颜色是每个顶点各不一样的；时间、变换矩阵、一个开关是这一次绘制里所有顶点和像素都一样的；还有顶点算出来的中间量，需要交给像素阶段接着用。如果不先分清它们的性质，就会用错通道、付错代价：

  • 把逐顶点数据当全局量传，一个值只能表达一个顶点，别的顶点只能拿到同一个坐标，图形直接塌掉。
  • 把全局量当逐顶点数据传，就得给每个顶点各存一份相同的值，每帧更新要整块重传，白白浪费带宽。
  • 顶点阶段算出的结果想给像素阶段用，若没有一条通道，要么重算一遍，要么根本传不过去。

所以问题的核心不是「怎么把值传进去」，而是：面对一份数据，怎么一眼判断它该走哪条通道？

统一变量适用

最省事的做法：全当全局量传，反正 uniform 设一次就处处可用。对时间、角度、颜色这类整个图形共享的数据，这确实是最划算的选择——设一次，所有顶点和像素都拿到同一个值。

这个方案做对了一件事：它认出了「全局共享」这一种粒度，并把它的成本压到了最低。当一份数据整次绘制都保持不变时，用 uniform 就是标准答案。

全局数据边界

  • 逐顶点的位置或颜色用 uniform 根本表达不了：三个顶点会拿到同一个坐标，三角形退化成一个点，颜色也只剩一块。
  • 想把逐顶点数据硬塞进一个 uniform 数组，还得在着色器里自己按下标取值，绕了一大圈，远不如属性直观。
  • 把时间这种全局量当逐顶点数据传，每帧都要重传整块缓冲，正是开场那个「搬运上千个顶点」的浪费。
  • 顶点着色器算出的量（例如波浪后的颜色）片段着色器读不到，缺一条跨阶段的通道。

数据通道分流

不推翻「全局量用 uniform」，而是按数据出现的粒度把输入分成两类，再补上一条连接两个阶段的通道。三者的分工，就是这一课真正要记住的东西。

  1. attribute——逐顶点输入。每个顶点各一份，由 CPU 端的缓冲加上 vertexAttribPointer 提供。位置 aPosition、颜色 aColor 都属于它。边界很硬：attribute 只能在顶点着色器里声明，个数受 GL_MAX_VERTEX_ATTRIBS 限制（WebGL1 通常至少 8 个）。
  2. uniform——全局只读量。单次 draw call 内所有顶点与像素共享同一份值，时间 uTime、开关 uUseAttributeColor 都属于它。它可以在每次绘制前更新，适合传时间、矩阵、颜色这类全局状态。
  3. varying——跨阶段的插值通道。顶点着色器把 aColor 赋给 vColor，片段着色器读到的就是插值后的值；光栅化会自动完成插值，你不用手写。

本课把这三种粒度放进同一个形状里各司其职：顶点着色器读入 aPosition、aColor 和 uTime，按 uTime 与各顶点自身的 aPosition 算出波浪位移，写进 gl_Position；片段着色器则在「属性色」与「按 uTime 动态算出的颜色」之间用 mix 按 uUseAttributeColor 混合。于是逐顶点的差异与全局的统一，恰好各自走对了通道。

两个易错点：uniform 必须在 useProgram 之后设置才会生效，顺序反了它就不会作用到当前程序上；另外要留意 attribute / varying 是 WebGL1 的旧关键字，WebGL2 的 #version 300 es 已改用 in / out，入门阶段先按 WebGL1 的写法对照更直观。

两种输入对比

输入通道选择

往着色器里送数据，先看它的粒度：每个顶点都不一样，就用 attribute；整次绘制都相同，就用 uniform；要从顶点阶段交到像素阶段、还希望它自动过渡，就用 varying。选对通道，值既传得进去，也不会有多余的重复上传。

「数据粒度（Data Granularity）」指一份数据在渲染中被复用的最小单位——逐顶点、逐绘制调用还是逐片元。它决定数据该走 attribute、uniform 还是 varying。记住两个边界：同一份数据在跨越阶段后粒度可能变化（顶点阶段的 varying 到了片段阶段是插值后的逐片元值）；逐实例渲染还会额外引入「逐实例」这层粒度，属于进阶话题。

关键代码

GLSL
// ===== 顶点着色器 Vertex Shader =====
attribute vec2 aPosition;
attribute vec3 aColor;
varying vec3 vColor;
uniform float uTime;
void main() {
  vec2 pos = aPosition;
  pos.x += sin(uTime + aPosition.y * 3.0) * 0.05;
  pos.y += cos(uTime + aPosition.x * 3.0) * 0.05;
  gl_Position = vec4(pos, 0.0, 1.0);
  vColor = aColor;
}

// ===== 片段着色器 Fragment Shader =====
precision mediump float;
varying vec3 vColor;
uniform float uTime;
uniform float uUseAttributeColor;
void main() {
  vec3 attrColor = vColor;
  vec3 dynamicColor = vec3(
    0.5 + 0.5 * sin(uTime * 0.7 + vColor.r * 6.28),
    0.5 + 0.5 * sin(uTime * 0.5 + vColor.g * 6.28 + 2.09),
    0.5 + 0.5 * sin(uTime * 0.3 + vColor.b * 6.28 + 4.18)
  );
  vec3 finalColor = mix(dynamicColor, attrColor, uUseAttributeColor);
  gl_FragColor = vec4(finalColor, 1.0);
}
