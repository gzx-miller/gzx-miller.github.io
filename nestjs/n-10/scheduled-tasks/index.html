定时任务：@nestjs/schedule 调度

用日报表场景展示 @Cron、@Interval、@Timeout 三种调度方式与 cron 表达式规则。

开场问题：需求是「每天早上 8 点生成昨日订单日报」。你在服务启动时挂了个 setInterval，第一次能跑，重启后时间就漂了，多开一个实例还出了两份表——定时这件事，为什么不能自己算？

时间触发型任务

日报表、心跳上报、会话清理、周报汇总，这类需求有一个共同点：它们不由用户触发，而由时间触发。没有请求进来的时候，代码也得被叫醒一次。更麻烦的是触发条件往往是「日历上的某个时刻」——每天 8 点、每周一 9 点，而不是「每隔 86400 秒」。

如果框架不管这件事，你就得在应用里自己写一套计时逻辑，还得自己处理重启、异常、多实例这些边界。代价不是「多写几行代码」，而是这套计时逻辑本身就是一台容易出错的调度器——出错的时机还偏偏在半夜。

固定间隔定时器

最朴素的做法：在某个服务启动时调一次 setInterval，间隔设成 24 小时，回调里聚合昨日订单并落库。

它做对了一件关键的事：任务真的被自动执行了，而且回调就是个普通方法，可以直接 this.orderService.aggregateYesterday()，天然复用依赖注入。这一点不可替代——比起在服务器上单独挂一个外部 crontab 脚本，服务内的定时任务能直接调用业务代码、直接用容器里的连接池，不需要再维护一份独立的环境。

重启漂移与实例重复

  • setInterval 只认「固定间隔」，表达不了「每天 08:00」这种日历时刻。间隔设成 24 小时后，执行时间由启动时刻决定，服务凌晨重启一次，日报表就永久漂到凌晨。
  • 进程一重启，计时器直接丢失，下一次触发要从启动时刻重新算起。
  • 回调抛异常时任务可能再也不跑，而且没有任何记录，看起来「一直在运行」。
  • 部署两个实例时每个实例各跑一遍，同一份报表被生成两次。
  • 运行时想查看任务、临时增删某一个，没有任何入口。

声明式触发规则

不推翻「服务内定时执行」，而是把「自己算时间」换成「声明触发规则」。引入 @nestjs/schedule 之后，一个装饰器就能声明任务，调度器负责计算下一次触发点。它提供三种调度方式，对应三种完全不同的时间语义：

装饰器时间表达方式触发次数典型场景
@Croncron 表达式（日历时刻）按表达式周期重复每天 08:00 生成日报表
@Interval固定毫秒间隔每隔 N 毫秒重复每 5 分钟上报一次健康心跳
@Timeout延迟毫秒数只执行一次启动后延迟 10 秒做预热

三者的选择逻辑很清晰：要绑定到日历上的具体时刻，用 @Cron；只关心「隔多久跑一次」，用 @Interval；只需要跑一次，用 @Timeout。「每天早上 8 点」属于第一类，只能交给 cron 表达，用毫秒间隔是凑不出来的。

cron 表达式在 NestJS 里是六段格式，依次是「秒 分 时 日 月 周」。所以 @Cron('0 0 8 * * *') 读作：第 0 秒、第 0 分、8 时、每天、每月、不限星期——即每天 08:00:00。常用通配符有三类：* 表示任意值，*/5 表示每 5 个单位，? 表示不指定。周字段的取值范围是 0 到 7，其中 0 和 7 都代表周日，写周一时就是 1。

  1. 应用启动时扫描 @Cron / @Interval / @Timeout 装饰器，把它们注册成调度任务。
  2. 调度器按触发器类型计算下一次触发时间，日报表任务落在明天的 08:00。
  3. 到点调用对应方法，日报表任务聚合昨日订单并落库。
  4. 任务抛出的异常由调度器记录，默认不会中断后续调度。
两个容易踩的坑：其一，cron 默认按服务器本地时区计算，跨时区部署时不显式指定 timezone，触发点会整体偏移，报表就错点了；其二，任务失败默认只写日志、没有告警，看起来一直在跑，其实早就没出数了——关键任务建议在方法内用 try / catch 包一层，失败时主动上报。

还有两点值得记住。测试或临时运维时，可以用 SchedulerRegistry 在运行时列出、动态增删任务，也可以把任务替换成 mock 来单测，不必真的等到早上八点。而最棘手的是分布式部署：调度器是进程内的，每个实例都会扫描到同一份 @Cron，同一份日报表被生成多次。解决办法要么是加分布式锁——例如用 Redis 的 SETNX，抢到锁的实例才执行；要么把定时任务收敛到单独的调度实例上，其它实例不加载它。

单次触发与全量扫描

调度语义精确表达

定时任务要解决的核心问题是「把时间语义写清楚」：@Cron 表达日历时刻，@Interval 表达固定间隔，@Timeout 表达只跑一次。任务挂在可注入的服务上，调度器负责计算与触发，异常处理与运行时管理都有对应手段。唯一需要额外警惕的是多实例——进程内调度在集群下会重复执行，必须用分布式锁或单实例收敛来解决。

「定时任务调度」用 @nestjs/schedule 把方法声明为任务：@Cron 按六段 cron 表达式「秒 分 时 日 月 周」周期执行，@Interval 按固定毫秒间隔执行，@Timeout 延迟执行一次。周字段取 0-7（0 与 7 均为周日），? 表示不指定；时区默认取服务器本地，跨时区部署需显式配置 timezone。任务失败默认只记日志，可用 SchedulerRegistry 动态管理任务；集群下需分布式锁避免重复触发。

关键代码

TypeScript
// report.scheduler.ts —— 定时任务服务
@Injectable()
export class ReportScheduler {
  // cron 表达式：秒 分 时 日 月 周
  // '0 0 8 * * *' = 每天 08:00:00 生成日报表
  @Cron('0 0 8 * * *')
  async generateDailyReport() {
    const data = await this.orderService.aggregateYesterday()
    await this.reportService.save('daily', data)
    this.logger.log('日报表已生成')
  }

  // 每 5 分钟执行一次（服务健康心跳）
  @Interval(5 * 60 * 1000)
  heartbeat() {
    this.healthService.ping()
  }

  // 启动后延迟 10 秒执行一次
  @Timeout(10_000)
  onBoot() {
    this.logger.log('应用启动预热完成')
  }
}
