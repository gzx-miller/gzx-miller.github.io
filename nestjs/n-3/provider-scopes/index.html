Provider 与注入作用域

用请求追踪 ID 展示 Singleton、Request、Transient 三种作用域在实例复用上的差异。

开场问题：你给审计日志加了一个 requestId，想在每条日志里标记它来自哪次请求。可这个服务是单例的，构造函数里根本没有请求对象，只能把第一次请求的 ID 存下来——之后所有请求的日志都带着同一个旧 ID，并发时甚至互相覆盖。为什么「每个请求一份」这么自然的需求，在默认的 Provider 里却做不到？

Provider 默认单例

在 NestJS 里，写进 providers 的类默认是单例作用域（Singleton）：容器在应用启动时创建一次，此后该模块内所有控制器、所有请求、所有注入方共享同一个实例。这是成本最低的选择——对象只造一次，数据库连接池、配置快照、共享缓存这类昂贵资源不会被反复创建，状态也天然一致。

代价是实例上不能保存请求级状态。你在单例服务里写 this.currentUser = user，下一个请求进来就会覆盖它；两个请求并发时，后者还可能读到前者的用户。单例适合无状态的计算与跨请求共享的资源，不适合「这次请求是谁、来自哪个租户」这类上下文。要判断一个 Provider 该用什么作用域，先问自己：这份状态属于应用，还是属于某一次请求？

默认单例还有一个容易被忽略的细节：同一个类如果在两个模块的 providers 里各登记一次，得到的是两个互不相干的实例。想真正共享，必须通过 exports / imports 复用同一份注册，或者声明为全局模块。作用域管的是「实例怎么创建」，模块管的是「实例对谁可见」，两者不能混为一谈。

请求作用域与 REQUEST 注入

把声明改成 @Injectable({ scope: Scope.REQUEST })，容器就会为每次请求创建一个新实例。同一请求内，多个消费者注入到的是同一个实例；请求结束、响应发出后，实例随之释放。

  • 需要在 Provider 里访问请求对象时，用 @Inject(REQUEST) 注入，可以读到 headers、user、租户标识等。
  • REQUEST 本身就是一个请求作用域的 Provider，所以注入它的类会自然继承请求作用域。
  • 实例按「请求上下文（ContextId）」缓存，而不是按注入点缓存——这正是同一请求内多处注入能拿到同一份实例的原因。
  • 它解决的是「请求隔离」，不解决「并发安全」：实例不再共享，但数据库、Redis 这些外部资源仍然共享。

因此请求作用域最适合承载请求级上下文：请求 ID、当前用户、租户、语言、本次请求的追踪信息，以及只在本请求内复用的轻量计算结果。

瞬态作用域

Scope.TRANSIENT 是另一种极端：每次被注入都创建一个新实例。如果 OrderService 和 ReportService 都注入了瞬态 Provider，它们各自拿到一份，互不影响；同一请求里也不会共享。

它适合「每个使用者都需要独立状态」的对象：带缓冲区的日志器、有内部游标的解析器、按消费者定制的策略对象。共享反而会出错时，瞬态是最直接的选择。

代价也要算清楚：实例数量会随注入点增长，容器不再替你复用；瞬态实例通常由注入方持有，不要把它当成跨请求缓存，也不要指望它承担全局计数之类的职责。换句话说，单例是「大家共用一份」，瞬态是「人人各自一份」，请求作用域则是「一次请求共用一份」。

作用域沿注入链冒泡

作用域的影响不止于自己。假设单例的 EnrollmentService 注入了请求作用域的 RequestContextService：容器要让 Service 拿到「本次请求」的上下文，就只能把 Service 也按请求创建。这就是作用域冒泡——依赖是请求作用域，消费者也会被推成请求作用域，并继续向上传递。

冒泡的后果是链路放大：只要链上有一个请求作用域 Provider，依赖它的控制器、服务乃至更上层的消费者都会变成每请求实例化。NestJS 为此提供了持久化 Provider（durable providers）：声明 durable: true 后，同一请求内无论被解析多少次，都只创建一份实例，而不是每条注入链各造一份。它只对请求作用域有意义，也不能突破「每个请求仍有一份」这个前提。

性能成本与使用边界

请求作用域不是免费的。每个请求都要实例化整条链，链路越长，CPU 与内存开销越大；控制器与服务不再常驻，垃圾回收压力上升；如果链上还包含请求级数据库连接或 Repository，连接池可能被迅速占满。并发量高时，这些成本会直接体现在延迟与吞吐上。

  • 把重依赖留在单例：连接池、HTTP 客户端、配置对象不应因为「需要请求信息」而变成每请求一份。
  • 只让轻量上下文进请求作用域，并用 durable: true 收敛同一请求内的重复创建。
  • 只是想把参数从控制器传到服务，优先显式传参，或用请求上下文存储方案，不必为一个字段改动整条链的作用域。
  • 请求作用域 Provider 内不要保存跨请求可变状态，也不要依赖「请求结束后还会被复用」。

一句话总结边界：需要请求隔离的上下文才用 REQUEST，需要消费者隔离的状态才用 TRANSIENT，其余默认保持 Singleton。作用域是生命周期声明，不是「更安全」的开关；选错方向，代价往往落在并发与性能上。

三种作用域的实例对照

两个反直觉点：其一，给一个底层工具类加上 Scope.REQUEST，可能把整条调用链都拖成请求作用域，性能影响远大于「只改了一行装饰器」；其二，durable: true 不是「变成单例」，它仍然每请求一份，只是避免同一请求内重复创建。
「Provider 作用域」决定 DI 容器何时创建、何时复用 Provider 实例。Singleton（默认）在模块内只创建一次，跨请求共享；Scope.REQUEST 每请求一份，同一请求内经 ContextId 共享，可用 @Inject(REQUEST) 读取请求对象，durable: true 让同一请求内只实例化一次；Scope.TRANSIENT 每个注入方各得一份。作用域会沿注入链向上冒泡：单例依赖请求作用域 Provider 时，自身也会变成请求作用域，因此要把重资源留在单例、把请求上下文限制在轻量 Provider 内。

关键代码

TypeScript
// 课程报名接口：同一请求共享上下文、跨请求隔离，审计日志器按注入方各得一份

import {
  BadRequestException,
  Body,
  Controller,
  Get,
  Inject,
  Injectable,
  Module,
  Post,
  Scope,
} from '@nestjs/common'
import { REQUEST } from '@nestjs/core'
import type { Request } from 'express'

// ═══ 1. 请求作用域上下文：每个 HTTP 请求创建一份 ═══
export interface RequestUser {
  id: string
  tenantId: string
}

@Injectable({ scope: Scope.REQUEST, durable: true })   // 说明：durable 让同一请求内的多次解析复用同一实例
export class RequestContextService {
  readonly requestId: string
  readonly tenantId: string
  private readonly startedAt = Date.now()

  constructor(@Inject(REQUEST) request: Request & { user?: RequestUser }) {
    this.requestId = String(request.headers['x-request-id'] ?? 'unknown')   // 结果：同一请求内多处注入读到同一个 ID
    this.tenantId = request.user?.tenantId ?? 'public'                      // 说明：租户信息由鉴权中间件写入 request.user
  }

  elapsedMs(): number {
    return Date.now() - this.startedAt
  }
}

// ═══ 2. 瞬态审计日志：每个注入方各得一份 ═══
let auditSeed = 0

@Injectable({ scope: Scope.TRANSIENT })
export class AuditLogger {
  readonly instanceId = `audit-${++auditSeed}`      // 结果：OrderService 与 ReportService 拿到的编号不同

  write(action: string, detail: Record<string, unknown>): void {
    console.log(JSON.stringify({
      action,
      instanceId: this.instanceId,
      at: new Date().toISOString(),
      ...detail,
    }))
  }
}

// ═══ 3. 实体仓储：没有请求状态，保持默认单例 ═══
export interface Course {
  id: number
  title: string
  capacity: number
  enrolled: number
}

@Injectable()
export class CourseRepository {
  private readonly rows = new Map<number, Course>([
    [1, { id: 1, title: 'NestJS 模块化实战', capacity: 30, enrolled: 28 }],
    [2, { id: 2, title: 'TypeORM 事务进阶', capacity: 20, enrolled: 20 }],
  ])

  findById(id: number): Course | undefined {
    return this.rows.get(id)
  }

  save(course: Course): void {
    this.rows.set(course.id, course)
  }
}

// ═══ 4. 单例业务服务依赖请求作用域：作用域随注入链上浮 ═══
@Injectable()
export class EnrollmentService {
  constructor(
    private readonly repo: CourseRepository,
    private readonly ctx: RequestContextService,   // 说明：依赖请求作用域后，本服务也按请求创建
    private readonly audit: AuditLogger,           // 说明：瞬态实例由本服务独享
  ) {}

  enroll(courseId: number, userId: string) {
    const course = this.repo.findById(courseId)
    if (!course) throw new BadRequestException('课程不存在')
    if (course.enrolled >= course.capacity) throw new BadRequestException('名额已满')

    course.enrolled += 1
    this.repo.save(course)

    this.audit.write('course.enrolled', {
      requestId: this.ctx.requestId,               // 结果：日志携带的是本次请求的 ID，而不是启动时那份
      tenantId: this.ctx.tenantId,
      courseId,
      userId,
      remaining: course.capacity - course.enrolled,
      elapsedMs: this.ctx.elapsedMs(),
    })

    return {
      courseId,
      remaining: course.capacity - course.enrolled,
      requestId: this.ctx.requestId,
    }
  }

  auditInstanceId(): string {
    return this.audit.instanceId
  }
}

@Injectable()
export class EnrollmentReportService {
  constructor(
    private readonly repo: CourseRepository,
    private readonly ctx: RequestContextService,   // 说明：与 EnrollmentService 共享同一请求内的上下文
    private readonly audit: AuditLogger,           // 说明：与 EnrollmentService 各持有一份瞬态实例
  ) {}

  summary() {
    const courses = [1, 2]
      .map((id) => this.repo.findById(id))
      .filter((course): course is Course => course !== undefined)

    this.audit.write('report.read', {
      requestId: this.ctx.requestId,
      tenantId: this.ctx.tenantId,
      count: courses.length,
    })

    return {
      tenantId: this.ctx.tenantId,
      requestId: this.ctx.requestId,
      auditInstance: this.audit.instanceId,
      courses,
    }
  }
}

// ═══ 5. 控制器：一次请求里多次注入，验证上下文共享 ═══
@Controller('enrollments')
export class EnrollmentController {
  constructor(
    private readonly enrollment: EnrollmentService,
    private readonly report: EnrollmentReportService,
    private readonly ctx: RequestContextService,
  ) {}

  @Post()
  create(@Body() body: { courseId: number; userId: string }) {
    return this.enrollment.enroll(body.courseId, body.userId)
  }

  @Get('context')
  context() {
    return {
      requestId: this.ctx.requestId,               // 结果：与 Service 内读到的值一致
      tenantId: this.ctx.tenantId,
      controllerElapsedMs: this.ctx.elapsedMs(),
    }
  }

  @Get('audit-instances')
  auditInstances() {
    return {
      enrollmentAudit: this.enrollment.auditInstanceId(),
      reportAudit: this.report.summary().auditInstance,
      // 结果：两个值不同，证明瞬态 Provider 每个注入方各得一份
    }
  }
}

// ═══ 6. 模块装配：作用域声明与普通 Provider 一样登记 ═══
@Module({
  controllers: [EnrollmentController],
  providers: [
    RequestContextService,   // 请求作用域
    AuditLogger,             // 瞬态作用域
    CourseRepository,        // 默认单例
    EnrollmentService,       // 因依赖请求作用域而上浮
    EnrollmentReportService,
  ],
  exports: [EnrollmentService],
})
export class EnrollmentModule {}
