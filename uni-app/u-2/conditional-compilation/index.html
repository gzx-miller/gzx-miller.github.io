条件编译：一套代码适配多端

用 #ifdef / #ifndef 按平台差异化代码，理解注释式条件编译在 js、template 与 css 中的写法。

开场问题：你在页面里写了一个"分享给好友"的按钮，用 // #ifdef MP-WEIXIN 圈了起来。切到 H5 平台预览，这个按钮不仅不显示，翻遍打包产物也找不到它的任何一行——它不是运行时被藏起来了，而是压根没被编译进去。

三端平台能力分叉

你在做一套三端共用的代码：分享、保存海报、唤起支付，各个平台能做的事并不一样。顺手的老办法是在逻辑里写运行时判断，比如 if (平台 === 'h5') 走这个分支、否则走那个。功能确实能跑，但代价藏在看不见的地方。

第一，各端无关的分支照样会被打进所有端的产物，小程序的包里躺着 H5 的代码，包体白白变大。第二，只有某端才有的 API（比如微信的 wx.shareAppMessage）写进判断后，其它端仍要能编译通过、能加载，稍不留神就在运行时才炸。第三，差异一旦多起来，判断会层层嵌套，读代码要同时在脑子里模拟三端。于是问题落成一个明确的问句：能不能让"只属于某端的代码"，在它不该存在的那一端根本不存在？

运行时平台判定

最朴素的做法：运行时判断当前平台，例如读 uni.getSystemInfoSync().platform，再决定走哪一段逻辑。

这个方案做对了一件事：它承认"不同平台的行为必须能分叉"，而且不依赖任何额外的构建配置——只要有平台信息，就能在同一处代码里做出选择，功能立刻可跑。

分支代码全量入包

  • 分叉之后两边的代码仍然都会被打进每一端的产物，包体不为所动，等于把三端的代码全塞进一端的包里。
  • 某端专属的 API 写进判断里，其它端在编译和加载阶段依然要面对它，写错一个拼写就可能在运行到那个分支时才报错。
  • 判断落在热路径上会被反复执行，差异一多就嵌套成"俄罗斯套娃"，性能和可读性一起变差。
  • 运行时判断只能管到 JS 逻辑，模板结构和样式里的端差异它管不到——你想让某端多渲染一段 DOM，它无能为力。

编译期条件裁剪

不推翻"按平台分叉"，而是把分叉的时机从运行时提前到编译期：用注释式条件编译。把一段代码用 // #ifdef MP-WEIXIN 与 // #endif 包起来，编译器在为目标平台构建时决定这段代码的去留——非目标平台的分支直接不进产物。

这一步换来两个关键性质：不产生任何运行时判断开销（因为判断根本不存在），以及不会把其它平台的死代码带进产物（因为它已经被裁掉了）。

先补反向表达：// #ifndef H5 表示"除 H5 之外"，用来圈定"某端不做某事"。有了正向与反向两个方向，常见的端差异就都能描述了。

再补它出现的位置——同一套注释写法能落在三个地方，因为差异可能出现在逻辑、结构或样式里：

  1. js/ts 里用 // #ifdef MP-WEIXIN 与 // #endif 包裹一行或一段代码。
  2. template 里用 HTML 注释包裹：<!-- #ifdef MP-WEIXIN --> 与 <!-- #endif -->。
  3. style/css 里用块注释包裹：/* #ifdef H5 */ 与 /* #endif */。

最后把平台标识对齐：H5、MP-WEIXIN、APP-PLUS，以及支付宝、抖音等更多小程序端的标识，官方文档里有全集。除了写进 #ifdef，部分场景还会以构建时常量的形式注入（例如 process.env.UNI_PLATFORM），供极少数无法用条件编译表达的判断使用。

三个必须守住的边界：条件编译是编译期行为，运行时看不到任何痕迹，别指望在真机上调它；每个 #ifdef / #ifndef 都必须有配对的 #endif，一页里出现多次时要保证闭合关系正确，否则整段语法错乱；一段 #ifdef 不能跨 script 与 template 之间包裹，它必须完整落在同一个区块内。差异逻辑一多，抽到外部文件再条件引入，可读性会好得多。

平台功能槽位增减

构建期分支裁剪

条件编译把"一套代码适配多端"从运行时的判断，变成构建时的选择：目标平台之外的分支在编译期就被裁掉，既不占包体，也不留运行时开销。用它表达端差异，你写的是同一份源码，产出的却是各自干净的产物。

「平台标识」uni-app 用来指代目标端的字符串常量，如 H5、MP-WEIXIN、APP-PLUS，供 #ifdef / #ifndef 引用，全集以官方文档为准。要记住的边界：标识大小写敏感、需按文档原样书写；它只做编译期的取舍，无法表达"按用户设备临时决定"这类运行时条件。

<script>
export default {
  data() {
    return {
      // #ifdef MP-WEIXIN
      platform: '微信小程序',
      // #endif

      // #ifdef H5
      platform: 'H5 网页',
      // #endif

      // #ifdef APP-PLUS
      platform: '原生 App',
      // #endif
    }
  },
}
</script>

<template>
  <view class="course">
    <text>{{ platform }}</text>

    <!-- #ifdef MP-WEIXIN -->
    <button open-type="share" @tap="onShare">分享给好友</button>
    <!-- #endif -->

    <!-- #ifndef H5 -->
    <button @tap="savePoster">保存海报到相册</button>
    <!-- #endif -->
  </view>
</template>
