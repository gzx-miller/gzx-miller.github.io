数据绑定与事件处理

用 Vue 语法在 uni-app 里做双向绑定与事件，区分 @tap、@click 与事件传参、阻止冒泡的差异。

开场问题：课程列表每一项都能点开详情，项内还有个"报名"按钮。你给按钮绑了普通的点击事件，结果点"报名"的一瞬间，详情页也被打开了——两个动作一起触发，用户看到的是一次没头没脑的跳转。

列表点击与冒泡干扰

你要处理的是一个典型的列表页：顶部搜索框实时过滤，列表项点击进详情，项内还有一个不该连带触发父级的按钮。老办法是照搬原生 DOM 那一套——用 addEventListener 监听、读 input 事件的 target、靠 return false 阻止默认行为。

但代价马上显出来：小程序没有 DOM，addEventListener 无从谈起；各端的事件对象长得不一样，H5 把值放在 event.target.value，小程序把它放在 event.detail.value，手写同步就得写三端兼容；阻止冒泡和默认行为在各端表现不一致，换一端就失灵。所以要问的是：怎么把手势和输入稳定地映射成页面状态，并让"谁触发、传什么、要不要继续冒泡"在各端都一致？

手动同步输入状态

最朴素的做法：手写双向绑定，自己把输入同步进状态，例如 <input :value="keyword" @input="keyword = $event.target.value">。

这个方案做对了一件事：它承认"输入即状态"——输入框的内容是页面数据的一部分，改数据就能改界面，数据驱动这条路走通了。

三端取值路径差异

  • 取值的路径三端不一样：H5 是 $event.target.value，小程序是 $event.detail.value，照抄一套写法就会有一端拿到 undefined。
  • "报名"按钮的点击会冒泡到父级列表项，父级绑的"打开详情"被连带触发，出现一次双重动作。
  • 把过滤逻辑直接写在模板里（当场 filter），每次渲染都要重算一遍，且没法缓存结果。
  • 循环出来的列表项如果缺少稳定 key，Vue 的 diff 会复用错行，表现为"点了 A 报名，B 却亮了"。

双向绑定屏蔽差异

不推翻"输入即状态"，而是一层层把容易出错的手工活交给框架。先补 v-model：它把"读值 + 写回"收敛成一个指令，由框架屏蔽各端事件对象的差异——用在小程序内置组件上时，v-model 会被映射成对应的 value 属性与 input 事件。:value + @input 那套手写绑定就此可以省掉。

接着补事件本身。@click 与 @tap 都能绑定点击，编译到小程序端时 @click 会被统一映射为原生 tap 事件，两者可互换，不必刻意二选一。

再补传参：@tap="fn($event, id)"。这里的 $event 会带上原生事件对象，但要注意它不是标准的 DOM Event——在小程序端，坐标和目标信息躲在 detail 与 target 里，跨端取值优先靠 v-model，或者读 e.detail。

然后是冒泡控制：给"报名"按钮加上 @click.stop，点击就不再向上冒泡，父级的"打开详情"自然不会被误触发；需要阻止默认行为时用 .prevent。这一层补完，两个动作才真正分开。

最后补列表的稳定性与派生：循环项配 :key 让 diff 复用可靠；把筛选结果交给 computed 派生，而不是在模板里现算——关键字一变自动重算，其余渲染照旧。

三个跨端陷阱：$event 在小程序端不是 DOM Event，别硬写 e.target.value，它会在一端静默取到 undefined；.prevent 对应的"默认行为"是浏览器概念，小程序端多数场景压根没有默认行为，不要指望它兜底；长按、触摸这类手势事件在不同端的触发细节也各有差异，别假设三端完全一致。

事件修饰符拦截冒泡

绑定与事件统一映射

数据绑定与事件处理，本质是把"输入同步、事件触发、传递参数、控制冒泡、列表复用"这些手工活交给框架统一映射。用 v-model 收口取值差异、用 @click / @tap 绑事件、用 .stop 切断多余冒泡、用 :key 配 computed 稳住列表，同一份交互就能在三端表现一致。

「tap 事件」小程序 / uni-app 的原生点击事件，@click 在编译到小程序端时会被统一映射为 tap，因此两者在 uni-app 中可互换使用。要记住的边界：tap 的事件对象不是 DOM Event，取值要看 detail 与 target；长按、触摸等手势要用各自的事件名，不能指望 click 一并覆盖。

关键代码

Vue
<script>
export default {
  data() {
    return {
      keyword: '',
      courses: [
        { id: 1, title: 'Vue3 组合式 API' },
        { id: 2, title: 'Pinia 状态管理' },
      ],
    }
  },

  computed: {
    filtered() {
      return this.courses.filter((c) => c.title.includes(this.keyword))
    },
  },

  methods: {
    openCourse(id) {
      uni.navigateTo({ url: `/pages/course/course?id=${id}` })
    },

    onSearchTap() {
      console.log('搜索：', this.keyword)
    },
  },
}
</script>

<template>
  <view class="search">
    <input v-model="keyword" placeholder="搜索课程" @input="onInput" />
    <button @tap="onSearchTap">搜索</button>

    <view v-for="course in filtered" :key="course.id" class="item" @tap.stop="openCourse(course.id)">
      <text>{{ course.title }}</text>
    </view>
  </view>
</template>
