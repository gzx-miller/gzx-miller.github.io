应用生命周期与全局数据

理解 App.vue 的 onLaunch、onShow、onHide、onError 与 globalData，用 getApp 跨页面共享全局状态。

开场问题：你在 App.vue 里写「启动时从缓存恢复登录态」，测试时一切正常。可用户把 App 切到后台、几个小时后切回来，token 明明已经在服务端过期了，你的恢复逻辑却一点反应都没有——同一段代码，冷启动管用，切回前台就失灵。

应用级生命周期

原因是：应用有它自己的「一生」，和单个页面的一生不是一回事。页面会被创建、显示、隐藏、销毁，一个页面可以反复进出；而应用只在启动时被创建一次，之后就是「进前台 / 退后台」的循环。你的登录态恢复写在了「只发生一次」的那个时刻，自然管不住「每次回到前台」的那件事。

旧办法习惯把应用级的事塞进页面里，代价同样藏在三处。第一，全局初始化被放进了某个页面，比如写在首页的 onLoad，可用户从扫码直达详情页时，首页压根没执行，初始化全部落空。第二，跨页面要共享的数据被塞进某个页面的 data，别的页面读不到，只好各自再请求一次。第三，异常没有统一出口，线上白屏了却拿不到任何日志。

问题于是分成两半：应用的启动与前后台切换，该在哪一层处理？跨页面要共享的那些数据，又该放在哪里？

入口页初始化时机

最省事的做法：挑一个「用户一定会经过」的页面，在它的 onLoad 里做初始化，把用户信息挂到一个模块级的变量上，别处 import 进来读。

这个方案做对了一件事：它至少把初始化收敛到了一个点，不再让每个页面各初始化一遍。当应用只有一个入口、初始化也只做一次时，这样写是能跑的。

直达路径漏判

  • 用户从扫码/分享链接直达详情页，作为「入口」的那个首页 onLoad 根本没执行，初始化整个落空。
  • 把登录态校验写在 onLaunch 里，热启动（从后台切回）不会重跑它，token 过期了也毫无察觉。
  • 用户信息存进某个页面的 data，换个页面就读不到，只能每个页面再发一次请求，数据还容易不一致。
  • 未捕获的异常没有兜底，真机上白屏了，日志里却什么都没有，问题根本无从查起。

四类应用级钩子

不推翻「收敛初始化」，而是把「应用的一生」正式交给应用入口 App.vue。它承载四个应用级生命周期：

  1. onLaunch：应用初始化完成时触发，全局只执行一次。放一辈子只做一次的事——读本地缓存、初始化全局状态、检查版本更新。
  2. onShow：应用进入前台，首次启动和从后台切回都会触发。
  3. onHide：应用进入后台，用来做收尾，如保存草稿。
  4. onError：捕获未处理的异常，统一上报。

接着要理解它们的层次关系：应用生命周期包住页面生命周期。冷启动时，顺序大致是 App.onLaunch → App.onShow → 首个页面的 onLoad → onShow → onReady；而热启动（从后台切回）只触发 App.onShow——页面实例还活着，不会重新 onLoad，onLaunch 也不会重跑。这条推论直接决定了逻辑该放哪：「一辈子只做一次」的放 onLaunch，「每次回到前台都要做」的放 onShow。开场那个失灵的登录态恢复，正确位置就是 onShow，而不是 onLaunch。

再解决「跨页面共享数据放哪」。挂在应用实例上的 globalData 可以用 getApp().globalData 在任意页面读写，正适合用户信息、登录态这类「要跨页面、但不怎么频繁变」的数据。但它有一条必须记住的边界：globalData 不是响应式的，改它不会自动刷新视图——页面要用，得在 onShow 里把它同步一份到自己的 data / ref。所以凡是高频共享、需要驱动视图的状态，应该交给 Pinia 或全局 store，而不是硬塞进 globalData。

再往下，把「必做的两件事」落到具体钩子上：登录态恢复——onLaunch 里读缓存、onShow 里每次复核（因为热启动只走 onShow）；版本更新——小程序端用 uni.getUpdateManager() 探测新版本并提示用户重启。这两件事不写在 App.vue，就一定要在某个入口页里重复写，而入口页是会被绕过的。

最后一个容易混的点：App.vue 是入口，不是配置中心。appid、页面路由、窗口样式这些配置写在 pages.json / manifest.json 里；App.vue 只放全局逻辑和全局样式。

两条最常踩的边界：onLaunch 只在冷启动执行一次，「从后台切回前台」不会重跑它，把登录态校验、数据刷新写在 onLaunch，热启动时就会全部失效，这类逻辑要放到 onShow；另外 globalData 的改动不会触发视图更新，别拿它当响应式状态用。

冷启动与前后台

应用生命周期和页面生命周期是两个层次：应用只出生一次，之后在前后台之间往返；页面会反复被创建和销毁。把「只做一次」的初始化放 onLaunch、「每次回前台」的逻辑放 onShow、异常兜底放 onError，跨页面数据用 getApp().globalData，并记住它不响应式——这样冷启动、热启动、直达页三条路径才不会各漏一块。

「冷启动与热启动」冷启动指应用进程不存在、从零拉起，会完整走一遍 App.onLaunch 与 App.onShow，并创建首个页面（onLoad → onShow → onReady）；热启动指应用已被系统保留在后台，再次打开只触发 App.onShow，页面实例与 globalData 都还在，onLaunch 不会重跑。边界：依赖「启动时执行一次」的逻辑必须放 onLaunch，「每次回到前台都要做」的逻辑必须放 onShow，否则热启动必然漏掉。

关键代码

Vue
<script>
export default {
  // globalData 挂在应用实例上，各页面通过 getApp() 读取
  globalData: {
    userInfo: null,
    isLogin: false,
  },

  onLaunch(options) {
    // 应用启动：只执行一次，读取缓存做全局初始化
    const token = uni.getStorageSync('token')
    if (token) {
      this.globalData.isLogin = true
      this.globalData.userInfo = { name: '小松鼠', token }
    }
  },

  onShow() {
    // 应用从后台切回前台（或首次进入）
    console.log('应用进入前台')
  },

  onHide() {
    // 应用进入后台，可在这里保存草稿、暂停轮询
    console.log('应用进入后台')
  },

  onError(err) {
    // 全局捕获未处理异常，上报日志
    console.error('应用异常：', err)
  },
}
</script>

<!-- 页面侧读取/写入全局数据：
const app = getApp()
console.log(app.globalData.userInfo)   // 读取
