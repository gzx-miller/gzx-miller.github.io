Handle 连接桩：定向分流与连接校验

用报销单按金额分流演示自定义节点内多 Handle 的 id 匹配，与 isValidConnection 的实时业务校验。

开场问题：一张报销单要按金额分流——小额走组长、大额走总监。可节点只有一个出口时，用户随手一拖就可能把大额单连进了普通审批，业务规则根本拦不住。

单一出口局限

前面的节点都只有一个出线口，连线方向由类型约束已经够用。但真实业务里，同一个环节常常需要多个出口或进口：报销单按金额分流、订单按渠道分发、任务按优先级走不同处理链。如果一张「报销单」节点只有一个连接点，那么「走组长」和「走总监」这两条线就会从同一个点出发、在视觉上纠缠在一起，用户根本分不清哪根是哪根。

更严重的是规则问题。业务上「大额报销必须由总监审批」是一条硬规则，可画布上默认允许任意连接，用户可以把大额单拖向组长、也可以把一个节点连到它自己。如果这类非法连接能被画出来、甚至被保存进数据，那下游的审批逻辑就要拿一堆脏数据去兜底。

事后校验代价

最省事的做法：给节点一个连接点，连上就算数，至于连得对不对，事后人工核查。这个方案对在哪里？它承认了连接的合法性可以作为「事后校验」存在，至少规则是有定义的。但把校验放到事后，就等于默认允许用户先制造错误，再回头收拾。

多出口语义缺失

  • 一个连接点无法表达「按金额分流」这种多出口语义，出口之间无法区分。
  • 业务规则拦不住乱接，非法连线照样能画出来并被保存。
  • 连接落下之后，你无法从数据层面知道这根线是从哪个出口出发的。
  • 用户没有实时反馈，只能靠猜「这根线接得对不对」。

连接桩三属性

不推翻「连接点」这个概念，而是给它补上三个属性。Vue Flow 里这个连接点叫 Handle：

  1. type 区分进出：target 表示进、source 表示出。
  2. position 决定它停靠在节点的哪条边上（左/右/上/下）。
  3. id 用来在同一个节点上区分多个桩——这正是分流的关键。

本课的自定义节点里摆了两个 source 桩，分别命名为 small-out（小额出）与 large-out（大额出），这就是「一个出口」到「多个具名出口」的升级。注意自定义节点用 #node-类型名 插槽渲染，内部可以摆放任意数量的 Handle。

最关键的联动规则：Handle 一旦设置了 id，新建连线就必须在 connection 里带上 sourceHandle 与 targetHandle，否则对接不上——线会连出去，却挂不到指定的桩上。这是多桩场景最容易忽略、也最难排查的一条。

接着解决校验。Vue Flow 提供了 isValidConnection，它会在拖线过程中实时触发，你根据 sourceHandle 与 targetHandle 编码业务规则：大额只能进「总监」、小额不能进「总监」、禁止节点自连（source === target 直接返回 false）。返回 false 的连线在松手瞬间就被丢弃，用户全程看得见线的合法性反馈。

把校验放在 isValidConnection 而不是 onConnect，差别在于时机：前者在拖拽途中就给出拒绝反馈，后者是松手之后才处理，用户要等到连完才发现不行。所以校验逻辑优先放前者。

连接被放行之后，才轮到 onConnect 落账：先验 valid，再 addEdges，并顺手记录 sourceHandle 到 targetHandle 的对应关系，分流日志就有了依据。还有一个观感细节：Handle 的 position 决定线从哪条边进出，桩位与停靠边不匹配时，连线会从节点内部斜穿过去，非常难看。建议按业务语义给多桩命名 id（如 small-out、large-out），校验、日志、排查都靠它定位。

结构化连接信息

连接桩把「连哪里」从一个模糊的拖拽动作，变成了可命名、可校验、可记录的结构化信息：用 id 区分多出口，用 isValidConnection 在拖拽途中实时拦下违规连接，用 onConnect 落账并留下分流依据。记住「设了 id 就必须显式携带 handle id」这条联动规则，多桩连线才不会错位。

「Handle 连接桩」是节点上的连接点，用 type 区分 source（出）/ target（进），用 position 决定停靠边，用 id 在同一节点上区分多个桩。一旦 Handle 设了 id，新建连线必须携带 sourceHandle / targetHandle 才能精确对接；业务校验应放在 isValidConnection 里实时触发（返回 false 的连线松手即被丢弃），放行后再于 onConnect 中读取 handle id 落账。

关键代码

Vue
<script setup lang="ts">
import { ref } from 'vue'
import { Handle, Position, VueFlow, useVueFlow } from '@vue-flow/core'
import type { Connection, Edge, Node } from '@vue-flow/core'

const log = ref<string[]>([])

function pushLog(message: string) {
  log.value = [`${message}`, ...log.value].slice(0, 6)
}

// 分流规则：小额报销走"组长"，大额报销必须走"总监"
function isValidConnection(connection: Connection | Edge): boolean {
  const { source, target, sourceHandle, targetHandle } = connection
  if (source === target) return false
  const isLarge = sourceHandle === 'large-out'
  const wantsDirector = targetHandle === 'director-in'
  // 大额单只能进总监，小额单不能进总监（演示用业务规则）
  if (isLarge && !wantsDirector) return false
  if (!isLarge && targetHandle === 'director-in') return false
  return true
}

const { onConnect, addEdges } = useVueFlow()

onConnect((connection: Connection) => {
  if (!isValidConnection(connection)) {
    pushLog('连接被 isValidConnection 拒绝')
    return
  }
  addEdges([{ ...connection, animated: true }])
  pushLog(`已连接 ${connection.sourceHandle} → ${connection.targetHandle}`)
})

const nodes = ref<Node[]>([
  {
    id: 'expense',
    type: 'expense-split',
    position: { x: 0, y: 140 },
    data: { label: '报销单' },
  },
  { id: 'lead', position: { x: 300, y: 20 }, data: { label: '组长审批（≤500）' } },
  { id: 'director', position: { x: 300, y: 260 }, data: { label: '总监审批（>500）' } },
  { id: 'paid', type: 'output', position: { x: 560, y: 140 }, data: { label: '打款' } },
])

const edges = ref<Edge[]>([])
</script>
