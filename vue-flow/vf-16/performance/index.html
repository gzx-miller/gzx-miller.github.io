性能与预渲染：大图渲染与 Nuxt 集成

用 50/200/800 节点压测对照可视区域渲染，并说明画布在 Nuxt 静态预渲染下的正确挂载方式。

开场问题：流程图一打开就有八百个节点，鼠标拖一下要等半秒才跟手，点个节点浏览器风扇狂转。难道大图只能靠删节点来救？

卡顿来自哪里

节点数一多，成本并不是线性地“多画几根线”。每个节点都是一个真实的 DOM 子树，连着自己的样式计算、布局与绘制；画布每次平移或缩放，视口变换又会触发一批元素重新定位。再加上节点内的响应式计算、监听器和事件回调，成本会同时压在渲染线程与主线程上。

所以优化要分清两类开销：同一时刻需要存在多少元素，以及单个元素有多重。前者靠视口裁剪与聚合，后者靠精简节点组件与事件逻辑。两条都做，才会同时改善首屏与交互。

只渲染视口内元素

给 VueFlow 打开 only-render-visible-elements，画布就只挂载当前视野内的节点与连线，视野外的元素等滚入后再渲染。它默认是关闭的，因为关闭时行为最直观：所有数据都有对应的 DOM，任何时刻都能测量尺寸。

开启后要接受两个事实。第一，视野外的节点可能还没被测量，它们的宽高、连接桩位置并不存在，依赖全量尺寸的布局或对齐逻辑不能在初始化阶段直接读。第二，节点离开视野会被卸载，组件内部的局部状态随之丢失——需要保留的状态应放进 node.data，而不是组件里的 ref。

  • 节点规模大、视野只覆盖局部时，开启收益最明显。
  • 依赖全量节点尺寸做布局时，先完成测量再开启，或改为按数据计算。
  • 需要节点内局部状态跨视野保留时，把状态提升到 data。

节点组件与事件回调

单个节点的渲染要足够轻。自定义节点里避免昂贵的格式化、深层嵌套组件和大范围 computed；能在数据准备阶段算好的字段，不要放进每个节点的模板里反复计算。例如金额格式、状态文案、颜色映射，都可以在生成 nodes 时一次性写进 data，模板只负责取值。节点组件越接近“纯展示”，大图越稳。

事件回调同样要克制。点击一个节点就同步遍历全量节点、做深拷贝或重排布局，等于把一次点击放大成整图操作。更稳的做法是用 findNode 精确拿到目标、用 updateNodeData 只改必要字段，批量变更合并到一次提交，高频事件做节流。回调里的工作量应该与“这次操作影响的范围”成正比，而不是与总节点数成正比。

  • 节点内不做全量数据过滤、排序或深拷贝。
  • 用 id 定位节点，避免在回调里反复 find 整个数组。
  • 拖拽、滚动等高频事件合并处理，避免每帧触发重排。
  • 复杂计算前置到数据层，节点只负责展示结果。

容器高度与预渲染

画布必须放在有明确高度的容器里。高度为 0 或依赖内容撑开时，画布拿不到有效尺寸，缩放、居中和 fitView 都会算错，表现成节点挤在角落或整片空白。固定高度或明确的最小高度，是所有测量逻辑成立的前提。

另一个坑在服务端渲染与静态预渲染。画布要在浏览器里测量 DOM，服务端没有真实布局，直接渲染容易在构建阶段报错，或产出与客户端不一致的结构。做法是用 ClientOnly 包住画布，或改成客户端动态导入，并给它准备同样高度的占位内容，避免水合时页面跳动。初始化阶段也不要直接读 window、document，这类访问应放进 onMounted。

分层布局与聚合

性能不只是“渲染得更快”，也包括“少让人看一些”。把节点按依赖分层、统一主轴方向，能显著降低视觉密度；把同一批次的节点收进可折叠的分组，展开时才渲染内部细节；用汇总节点显示“12 个任务已完成”，比铺开十二张卡片更易读，也更省 DOM。

大图还应配合缩略图导航与渐进展开：先给全局轮廓，用户定位到某一块后再加载细节。聚合与分层不会减少业务数据，却能减少同一时刻需要渲染与阅读的元素数量，这与视口裁剪是两条互补的路径。分组节点本身也会占 DOM，折叠状态要落进数据，避免展开后重复创建同一批子树。

性能演练

下面的演练可以切换 50、200、800 个节点，并开关“仅渲染可见元素”。切换后拖动或缩放画布，观察“实际渲染节点数”与视口缩放的联动；关闭裁剪时，全部节点都会留在 DOM 中，规模越大差异越明显。

先测量，再优化：不要凭感觉调参。用性能面板确认时间花在渲染、布局还是事件回调上，再决定开视口裁剪、精简节点还是改布局。开启 only-render-visible-elements 后，视野外节点没有尺寸与局部状态，依赖全量测量的逻辑要相应调整；优化效果也应在真实设备与真实节点规模下验证，而不是只看小样例。
「性能与预渲染」only-render-visible-elements 只挂载视口内元素，降低大图的同时渲染量；节点组件保持轻量，事件回调按影响范围处理而非遍历全量节点；容器必须有明确高度，画布在 SSR / 静态预渲染下用 ClientOnly 或动态导入；最后用分层布局、分组折叠与汇总节点降低视觉密度。

关键代码

Vue
<script setup lang="ts">
import { computed, nextTick, onMounted, ref } from 'vue'
import { VueFlow, useVueFlow } from '@vue-flow/core'
import type { Edge, Node, NodeMouseEvent } from '@vue-flow/core'

const COLUMNS = 10
const NODE_WIDTH = 130
const NODE_HEIGHT = 56
const SIZES = [50, 200, 800]

const size = ref(50)
const onlyVisible = ref(true)
const mounted = ref(false)

const { nodes: flowNodes, viewport, dimensions, setViewport } = useVueFlow()

function buildNodes(total: number): Node[] {
  return Array.from({ length: total }, (_, index) => ({
    id: `task-${index + 1}`,
    position: {
      x: (index % COLUMNS) * 150,
      y: Math.floor(index / COLUMNS) * 92,
    },
    data: { label: `任务 ${index + 1}` },
  }))
}

// 只保留少量跨行连线，把注意力留给节点渲染成本本身
function buildEdges(total: number): Edge[] {
  const edges: Edge[] = []
  for (let index = 0; index + COLUMNS < total; index += COLUMNS) {
    edges.push({
      id: `link-${index}`,
      source: `task-${index + 1}`,
      target: `task-${index + COLUMNS + 1}`,
      type: 'smoothstep',
    })
  }
  return edges
}

const nodes = ref<Node[]>(buildNodes(50))
const edges = ref<Edge[]>(buildEdges(50))

const rebuildCost = ref('—')
const clickCost = ref('—')
const lastAction = ref('尚未交互：点击任意节点试试')

const renderedCount = computed(() => {
  if (!onlyVisible.value) return flowNodes.value.length
  if (!mounted.value) return 0
  const { x, y, zoom } = viewport.value
  const width = dimensions.value.width || 640
  const height = dimensions.value.height || 340
  return flowNodes.value.filter((node) => {
    const left = node.position.x * zoom + x
    const top = node.position.y * zoom + y
    return (
      left + NODE_WIDTH * zoom > 0 &&
      left < width &&
      top + NODE_HEIGHT * zoom > 0 &&
      top < height
    )
  }).length
})

const renderedLabel = computed(() =>
  onlyVisible.value && !mounted.value ? '—' : String(renderedCount.value),
)

const responseHint = computed(() => {
  if (!mounted.value) return '画布初始化后会实时统计视口内实际渲染的节点数。'
  if (!onlyVisible.value) {
    return size.value >= 800
      ? '视口裁剪关闭：800 个节点全部留在 DOM 中，拖拽与缩放会明显变慢。'
      : `视口裁剪关闭：${size.value} 个节点全部渲染，规模继续增大会更明显。`
  }
  return `视口裁剪开启：当前只渲染视野内的 ${renderedCount.value} 个节点，视野外节点等滚入后再挂载。`
})

onMounted(() => {
  mounted.value = true
})

async function setSize(next: number) {
  const start = performance.now()
  size.value = next
  nodes.value = buildNodes(next)
  edges.value = buildEdges(next)
  await nextTick()
  rebuildCost.value = `${(performance.now() - start).toFixed(1)} ms`
  // 固定一个可观察的缩放层级，避免大图 fitView 后缩到看不清
  await setViewport({ x: 20, y: 20, zoom: 0.6 })
  lastAction.value = `切换到 ${next} 个节点`
}

async function refit() {
  await setViewport({ x: 20, y: 20, zoom: 0.6 })
  lastAction.value = '已复位视口'
}

function onNodeClick({ node }: NodeMouseEvent) {
  const start = performance.now()
  lastAction.value = `点击了「${String(node.data?.label ?? node.id)}」`
  clickCost.value = `${(performance.now() - start).toFixed(2)} ms`
}
</script>

<template>
  <div class="demo-container">
    <div class="demo-card">
      <h4>大图性能：视口裁剪与节点规模</h4>
      <p class="hint">
        切换节点规模，再开关注口裁剪，然后拖动或缩放画布，观察实际渲染节点数如何变化。
        容器固定高度，画布才能在有限面积内正确计算可见范围。
      </p>

      <div class="tab-bar" style="margin-top: 12px">
        <button
          v-for="item in SIZES"
          :key="item"
          class="tab-btn"
          :class="{ active: size === item }"
          @click="setSize(item)"
        >
          {{ item }} 节点
        </button>
      </div>

      <div class="controls">
        <label class="row">
          <input v-model="onlyVisible" type="checkbox">
          仅渲染可见元素
        </label>
        <button class="mini-btn" @click="refit">复位视口</button>
      </div>

      <div
        class="vf-canvas"
        style="height: 320px; border: 1px solid var(--demo-border); border-radius: 8px; overflow: hidden; background: var(--demo-surface)"
      >
        <ClientOnly>
          <VueFlow
            v-model:nodes="nodes"
            v-model:edges="edges"
            :fit-view-on-init="true"
            :only-render-visible-elements="onlyVisible"
            :min-zoom="0.3"
            :max-zoom="1.5"
            @node-click="onNodeClick"
          />
          <template #fallback>
            <div class="vf-fallback">流程图画布加载中…</div>
          </template>
        </ClientOnly>
      </div>

      <div class="prop-table" style="margin-top: 12px">
        <table>
          <tbody>
            <tr>
              <th>总节点数</th>
              <td>{{ size }}</td>
            </tr>
            <tr>
              <th>实际渲染节点数</th>
              <td>
                <span class="badge" :class="{ success: onlyVisible, warning: !onlyVisible }">
                  {{ renderedLabel }}
                </span>
              </td>
            </tr>
            <tr>
              <th>当前视口缩放</th>
              <td>{{ viewport.zoom.toFixed(2) }}×</td>
            </tr>
            <tr>
              <th>重建提交耗时</th>
              <td>{{ rebuildCost }}</td>
            </tr>
            <tr>
              <th>最近交互</th>
              <td>{{ lastAction }}</td>
            </tr>
            <tr>
              <th>点击处理耗时</th>
              <td>{{ clickCost }}</td>
            </tr>
          </tbody>
        </table>
      </div>

      <div class="tips-box">
        {{ responseHint }}
      </div>
    </div>
  </div>
</template>
