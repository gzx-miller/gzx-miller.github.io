撤销与重做：快照式历史与拖拽合并

用快照式历史实现画布撤销与重做，并按 dragstart/dragstop 把一次拖拽合并成一条记录。

开场问题：课程大纲刚排好，手一抖把「跟练示例」拖到了画布角落，又顺手删错了一个节点。此时画布上的数据已经是改坏后的版本，刷新页面也救不回来——一个可编辑的画布，怎样才能让用户安心地「改错了就退回去」？

只能前进的编辑器

最朴素的画布只维护「当前状态」：节点数组、连线数组，用户每拖一下、每删一个节点，就直接覆盖这份数据。它简单、直接，也足够应付演示，但有一个致命缺口——没有过去。

删除是不可逆的：节点对象从数组里消失，与它相连的边也一起被清理；拖拽是不可逆的：旧坐标被新坐标覆盖，松手之后没有任何地方还留着原来的位置。用户能做的只有小心翼翼地操作，或者从头再来一遍。

要补上这个缺口，编辑器必须额外保存「历史」。而历史的第一种实现思路，不是记录每一个动作，而是记录每一个状态。

快照式历史的原理

快照式历史的核心只有三步。第一步，在任何会改变图的操作发生之前，把当前整张图导出成一份快照，压入 undo 栈；第二步，撤销时从 undo 栈弹出最近一份快照，把当前状态压入 redo 栈，再用快照恢复画布；第三步，重做时反过来，从 redo 栈弹出快照，把当前状态压回 undo 栈，再恢复。

这里存的是「变更前」而不是「变更后」。因为撤销的本质是回到操作发生前的样子，变更前快照正好就是那个样子；而变更后的状态并不需要提前保存，等到真正撤销时现场再取一次即可。

  • 新操作发生时，把变更前快照压入 undo 栈，并清空 redo 栈。
  • 撤销时，undo 栈弹出、当前状态进入 redo 栈、快照写回画布。
  • 重做时，redo 栈弹出、当前状态进入 undo 栈、快照写回画布。
  • 清空 redo 的理由很直观：一旦从历史中间分叉，原来那条「未来」就不再属于当前时间线。

导出与恢复分别由 toObject() 和 fromObject() 完成。前者把节点、连线与视口打包成可序列化对象，后者把对象重新装载回画布。业务代码不需要逐字段搬运，整图替换一次完成。

拖拽合并成一条

快照式历史最容易踩的坑，是记录得太勤。节点拖拽过程中会持续触发 drag 事件，鼠标每移动一像素都可能产生一次位置变化。如果每次变化都导出一份快照，拖一次节点就能塞进几十上百条记录，undo 栈瞬间被无意义的中间态填满。

正确的粒度是「一次用户操作 = 一条历史」。在 dragstart 时把变更前快照暂存在一个临时变量里，拖拽过程中只更新画面、不碰历史；到 dragstop 时再判断位置是否真的发生变化，有变化才把那份暂存快照压入 undo 栈。这样无论中间移动了多少次，最终只留下一条可撤销的记录。

同样的思路适用于其他高频输入：连续输入的文字、滑块拖动、尺寸调整，都应该在「开始」时记快照、在「结束」时提交一条记录，而不是把每个中间值都当成独立历史。

栈深与深拷贝

快照保存的是整张图，成本随节点数量线性增长。节点上百、历史几十步时，内存占用会变得可观。因此 undo 栈必须限制深度，例如只保留最近 20 到 50 条，超出后丢弃最旧的一条；用户能回退的步数有限，但换来的是稳定的内存曲线。

另一个必须处理的问题是深拷贝。画布里的节点对象是响应式的，如果直接把引用放进栈，后续拖拽修改节点位置时，栈里那份「历史」也会跟着变，撤销时拿到的其实是当前状态。入栈前要用 JSON.parse(JSON.stringify(...)) 或结构化克隆做一次彻底复制，让快照与运行态彻底脱钩。

  • 只保存可序列化的业务数据，函数、DOM 引用、第三方实例不要混进快照。
  • 选中态、拖拽中标记属于瞬时界面状态，可在导出前剔除，减少无意义差异。
  • 视口是否纳入历史要明确：恢复视口能让用户回到当时的视野，也可能让画面突然跳动。
  • 图之外如果还有业务状态（例如标题、筛选条件），要一并纳入快照，否则撤销后会出现图文不一致。

命令模式与快照模式

历史还有另一条路线：命令模式。每个操作封装成一个带 do 与 undo 的命令对象，执行时做变更，撤销时执行反向操作——新增节点对应删除节点，移动节点对应写回旧坐标。它记录的是「动作」，不是「整张图」。

对比项快照模式命令模式
实现成本低，整图导出与恢复即可高，每个操作都要写正向与反向
内存占用高，随图规模与步数增长低，只存操作参数与少量旧值
粒度控制粗，一次操作一条整图快照细，可精确合并、拆分与协同
正确性风险低，恢复的是完整状态高，反向操作漏一步就会漂移
适用场景中小图、操作种类不多大型编辑器、协同与精细历史

对本项目这类课程画布，节点规模有限、操作集中在增删与拖拽，快照模式是性价比最高的选择：实现短、行为可预测、几乎不会出现「撤销后状态对不上」的顽固缺陷。等图规模继续增长、需要多人协同或按字段撤销时，再迁移到命令模式也不迟。

编辑历史面板实测

四个实现细节：不要在 drag 事件里频繁入栈，只在 dragstart 与 dragstop 两端处理；快照一定要深拷贝，否则历史会跟着当前状态一起被改掉；fromObject() 是异步的，恢复完成前不要允许连续点击；新操作发生后立刻清空 redo 栈，否则用户会重做出一条与当前时间线冲突的分支。
「快照式历史」用整图快照记录状态：变更前调用 toObject() 深拷贝入 undo 栈，撤销时用 fromObject() 恢复并把当前状态压入 redo 栈，重做则反向操作，任何新操作都会清空 redo 栈。拖拽要在 dragstart 记快照、dragstop 合并入栈，同时限制栈深并坚持深拷贝，才能兼顾可回退性与内存成本。

关键代码

Vue
<script setup lang="ts">
import { computed, ref } from 'vue'
import { VueFlow, useVueFlow } from '@vue-flow/core'
import type { Edge, FlowExportObject, Node } from '@vue-flow/core'

const LIMIT = 20

const initialNodes: Node[] = [
  { id: 'intro', type: 'input', position: { x: 40, y: 110 }, data: { label: '课程介绍' } },
  { id: 'practice', position: { x: 260, y: 110 }, data: { label: '跟练示例' } },
  { id: 'summary', type: 'output', position: { x: 480, y: 110 }, data: { label: '本节小结' } },
]

const initialEdges: Edge[] = [
  { id: 'e1', source: 'intro', target: 'practice' },
  { id: 'e2', source: 'practice', target: 'summary' },
]

const {
  addNodes,
  toObject,
  fromObject,
  onNodeDragStart,
  onNodeDragStop,
} = useVueFlow()

const undoStack = ref<FlowExportObject[]>([])
const redoStack = ref<FlowExportObject[]>([])
const dragging = ref(false)
const message = ref('点「加节点」或直接拖动节点，再试撤销 / 重做')
const logs = ref<string[]>([])

let dragBefore: FlowExportObject | null = null
let dragStartPosition = { x: 0, y: 0 }
let nodeIndex = 0

const canUndo = computed(() => undoStack.value.length > 0)
const canRedo = computed(() => redoStack.value.length > 0)
const total = computed(() => undoStack.value.length + redoStack.value.length)
const pointer = computed(() => undoStack.value.length)

function clone<T>(value: T): T {
  return JSON.parse(JSON.stringify(value)) as T
}

function capture(): FlowExportObject {
  // 深拷贝后入栈，避免之后画布继续变更时把栈里的快照一起改掉
  return clone(toObject())
}

function remember(text: string) {
  logs.value = [text, ...logs.value].slice(0, 4)
  message.value = text
}

function pushBefore(before: FlowExportObject) {
  undoStack.value.push(before)
  if (undoStack.value.length > LIMIT) undoStack.value.shift()
  // 出现新操作后，原来的重做分支作废
  redoStack.value = []
}

function addNode() {
  nodeIndex += 1
  pushBefore(capture())
  addNodes([
    {
      id: `extra-${nodeIndex}`,
      position: { x: 40 + ((nodeIndex - 1) % 3) * 220, y: 230 },
      data: { label: `补充章节 ${nodeIndex}` },
    },
  ])
  remember(`新增「补充章节 ${nodeIndex}」，入栈 1 条变更前快照`)
}

async function undo() {
  const before = undoStack.value.pop()
  if (!before) return
  redoStack.value.push(capture())
  await fromObject(clone(before))
  remember('撤销：恢复变更前快照，当前状态压入 redo 栈')
}

async function redo() {
  const next = redoStack.value.pop()
  if (!next) return
  undoStack.value.push(capture())
  await fromObject(clone(next))
  remember('重做：把 redo 栈顶快照重新写回画布')
}

onNodeDragStart(({ node }) => {
  dragging.value = true
  dragBefore = capture()
  dragStartPosition = { ...node.position }
  message.value = 'dragstart：只记一次变更前快照，拖动过程中不再入栈'
})

onNodeDragStop(({ node }) => {
  if (!dragBefore) return
  const moved =
    Math.abs(node.position.x - dragStartPosition.x) > 0.5 ||
    Math.abs(node.position.y - dragStartPosition.y) > 0.5

  if (moved) {
    pushBefore(dragBefore)
    remember('dragstop：整次拖拽合并为 1 条历史记录')
  } else {
    message.value = '位置没有变化，不写入历史'
  }

  dragging.value = false
  dragBefore = null
})
</script>

<template>
  <div class="demo-container">
    <div class="demo-card">
      <h4>快照式撤销 / 重做</h4>
      <p class="demo-desc">
        每次变更前调用 <code>toObject()</code> 把整张图深拷贝进 undo 栈；撤销时用
        <code>fromObject()</code> 写回，并把当前状态压入 redo 栈。拖拽从
        <code>dragstart</code> 到 <code>dragstop</code> 只算一条记录。
      </p>

      <div class="controls">
        <button class="mini-btn" type="button" @click="addNode">加节点</button>
        <button class="mini-btn" type="button" :disabled="!canUndo" @click="undo">撤销</button>
        <button class="mini-btn" type="button" :disabled="!canRedo" @click="redo">重做</button>
        <span class="badge">undo {{ undoStack.length }}</span>
        <span class="badge">redo {{ redoStack.length }}</span>
        <span class="badge" :class="{ warning: dragging }">
          {{ dragging ? '拖拽中：尚未入栈' : '空闲' }}
        </span>
      </div>

      <div class="demo-panel" style="height: 320px; padding: 0; overflow: hidden">
        <ClientOnly>
          <VueFlow
            :nodes="initialNodes"
            :edges="initialEdges"
            :fit-view-on-init="true"
            :min-zoom="0.6"
            :max-zoom="1.6"
          />
          <template #fallback>
            <div class="vf-fallback">流程图画布加载中…</div>
          </template>
        </ClientOnly>
      </div>

      <div class="grid-2" style="margin-top: 12px">
        <div class="prop-table">
          <table>
            <thead>
              <tr>
                <th>指标</th>
                <th>当前值</th>
                <th>含义</th>
              </tr>
            </thead>
            <tbody>
              <tr>
                <td>undo 栈</td>
                <td>{{ undoStack.length }} / {{ LIMIT }}</td>
                <td>变更前的整图快照</td>
              </tr>
              <tr>
                <td>redo 栈</td>
                <td>{{ redoStack.length }}</td>
                <td>撤销后可重做的状态</td>
              </tr>
              <tr>
                <td>历史指针</td>
                <td>{{ pointer }} / {{ total }}</td>
                <td>已生效记录 / 历史总数</td>
              </tr>
              <tr>
                <td>拖拽合并</td>
                <td>{{ dragging ? '记录起点中' : '已合并' }}</td>
                <td>dragstart 记一次，dragstop 入栈</td>
              </tr>
            </tbody>
          </table>
        </div>

        <div class="log-panel">
          <p v-if="!logs.length" class="hint">操作记录会出现在这里。</p>
          <p v-for="(log, index) in logs" :key="index" class="log-line">{{ log }}</p>
          <p class="hint">{{ message }}</p>
        </div>
      </div>

      <div class="tips-box">
        撤销后再做新操作，redo 栈会被清空——历史只剩一条新的前进路线，旧的重做分支无法再回来。
      </div>
    </div>
  </div>
</template>
