拖拽添加节点：物料面板与坐标换算

把物料从左侧面板拖进画布，用 screenToFlowCoordinate 把屏幕坐标换算成画布坐标后再 addNodes 落点。

开场问题：把左侧「审批」物料拖进右侧画布，明明是在鼠标位置松的手，节点却出现在左上角老远的地方；画布缩得越小，偏得越离谱——clientX、clientY 拿到的坐标到底是谁的坐标？

拖放落点预期

低代码平台最核心的那个动作，说起来只有一句：从物料区拖一个形状到画布上。用户对它的期待很朴素——我松手的地方，就是它出现的地方。可这背后有一段容易被忽略的换算，做不好就是「拖哪儿都不对」。

原因在于画布不是一块静态的画板。Vue Flow 的画布内部有一层视口变换：用户滚轮缩放、拖动空白处平移之后，画布的坐标系已经和屏幕的像素坐标系错开了。节点的 position 活在画布坐标系里，而浏览器拖放事件给到的永远是屏幕坐标系。这两个坐标系不换算就动手，位置必然错位。

浏览器原生拖放

最省事的做法：直接用浏览器原生拖放。draggable="true" 让物料可拖，dragstart 里把物料类型写进 dataTransfer，画布容器监听 drop，在事件里读出类型，然后用 event.clientX、event.clientY 当作新节点的 position，调 addNodes 放上去。

这个方案做对了两件重要的事。第一，它复用了浏览器原生的拖放能力，不用自己监听 mousedown 再手写 mousemove、画虚影、判断边界。第二，它把一次拖拽翻译成了一次数据操作：松手只是触发条件，真正建节点靠的还是 addNodes，符合「改数据即改图」的范式。

落点偏移成因

  • 画布缩放后，落点明显偏离鼠标——缩放比例越小，偏差越大。
  • 画布平移后同样偏，而且偏差方向随平移量变化，肉眼完全没法估算。
  • 把 dragover、dragenter 放任不管时，drop 事件根本不触发，页面像是「不接收」拖拽。
  • 物料类型若在 dragstart 里立刻读回，可能拿到空值，让人误判为「拖拽没生效」。
  • 每次放下都用同一个 id，后放的节点会把先放的覆盖掉，画布状态直接错乱。

屏幕坐标换算

不推翻这套原生拖放，只补上缺的那一步换算。Vue Flow 在 useVueFlow() 上提供了 screenToFlowCoordinate：把屏幕坐标交给它，它按当前视口的缩放与平移换算出画布坐标，返回的正是可以喂给 addNodes 的 position。

于是 drop 处理器的逻辑变成三步，顺序不能乱：先 preventDefault 并读出物料类型，再用 screenToFlowCoordinate({ x: clientX, y: clientY }) 换算落点，最后拼出节点对象交给 addNodes。换算这一步是整件事的关键，少了它，拖放在缩放过的画布上永远对不准。

两个容易踩的坑：其一，旧版用来做坐标换算的 project() 已被 screenToFlowCoordinate 取代，别再从旧文档里照抄；其二，dataTransfer 里写进去的数据在 dragstart 之后立刻读取可能为空，这是浏览器的安全限制，统一在 drop 里 getData 最稳妥。

接着补齐拖放协议本身。画布容器要对 dragover 与 dragenter 调 preventDefault()，浏览器才认为这块区域接受放置，drop 才会派发；物料在 dragstart 时把 effectAllowed 设成 'move'，光标就会给出正确的暗示。这两条都不是可选的美化，而是让功能真正可用的前提。

最后是身份。每一批物料可能被反复拖入，节点 id 必须每次唯一：可以用一个递增计数器拼出 approval-1、approval-2，也可以用 crypto.randomUUID()。重复 id 会让画布分不清谁是谁，后续的选中、更新、删除都会跟着出错。

还有一点常被忽略：新节点必须带上可读的 data.label。少了它，画布上出现的就是一个没有文字的空块，用户会以为拖拽失败。落点坐标也值得回显——状态栏那句「在画布坐标 (x, y) 放置了节点」，在排查坐标系问题时比任何日志都直观。

还差一层体验。物料面板与画布各自加一点拖拽高亮：面板里的物料在按下时变个边框色，画布容器在 dragenter 时亮起、dragleave 时复原。用户于是知道「这里能放」，而不是悬在空中猜。至此，一次拖拽从视觉反馈到数据落点才算闭合。

坐标转换本质

拖拽添加节点这件事的本质，是一次坐标系转换：浏览器给的屏幕坐标，必须先经过 screenToFlowCoordinate 变成画布坐标，才能成为节点的 position。搞清楚「谁在哪个坐标系里」，落点偏移这个最常见的坑就不存在了。

「screenToFlowCoordinate」是 useVueFlow() 提供的方法，把屏幕坐标（如拖放事件里的 clientX / clientY）换算成画布坐标，供 addNodes 决定节点落点。配合它还需三条约定：dragover / dragenter 必须 preventDefault() 才会触发 drop，物料类型统一在 drop 里 getData 读取，每次放置都要生成唯一 id。

关键代码

Vue
<script setup lang="ts">
import { ref } from 'vue'
import { VueFlow, useVueFlow } from '@vue-flow/core'
import type { Node } from '@vue-flow/core'

// 物料面板：拖到画布上按"画布坐标"落点
type MaterialKind = 'start' | 'approval' | 'cc' | 'end'

const materials: { kind: MaterialKind; label: string; hint: string }[] = [
  { kind: 'start', label: '开始', hint: 'input 节点' },
  { kind: 'approval', label: '审批', hint: 'default 节点' },
  { kind: 'cc', label: '抄送', hint: 'default 节点' },
  { kind: 'end', label: '结束', hint: 'output 节点' },
]

const { screenToFlowCoordinate, addNodes } = useVueFlow()

const droppedCount = ref(0)
const message = ref('把左侧物料拖进右侧画布')

function onDragStart(event: DragEvent, kind: MaterialKind) {
  event.dataTransfer?.setData('application/vue-flow-material', kind)
  if (event.dataTransfer) event.dataTransfer.effectAllowed = 'move'
}

function onDrop(event: DragEvent) {
  const kind = event.dataTransfer?.getData('application/vue-flow-material') as MaterialKind | ''
  if (!kind) return

  // 关键一步：屏幕坐标 -> 画布坐标（含缩放与平移），否则缩放后落点会飘
  const position = screenToFlowCoordinate({
    x: event.clientX,
    y: event.clientY,
  })

  droppedCount.value += 1
  const node: Node = {
    id: `${kind}-${droppedCount.value}`,
    type: kind === 'start' ? 'input' : kind === 'end' ? 'output' : 'default',
    position,
    data: { label: `${materials.find((m) => m.kind === kind)?.label ?? kind} ${droppedCount.value}` },
  }
  addNodes([node])
  message.value = `在画布坐标 (${Math.round(position.x)}, ${Math.round(position.y)}) 放置了节点`
}
</script>

<template>
  <div class="demo-card">
    <h3>拖拽添加节点（低代码画布的核心交互）</h3>
    <p>
      浏览器拖放事件给的是<b>屏幕坐标</b>，而画布可能已被缩放和平移。
      <code>screenToFlowCoordinate</code> 负责换算成画布坐标系，再交给
      <code>addNodes</code> 落点才准确。物料类型通过 <code>dataTransfer</code> 携带。
    </p>
    <div class="vf-layout">
      <aside class="vf-palette">
        <h4>物料区</h4>
        <div
          v-for="material in materials"
          :key="material.kind"
          class="material"
          draggable="true"
          @dragstart="onDragStart($event, material.kind)"
        >
          <strong>{{ material.label }}</strong>
          <span>{{ material.hint }}</span>
        </div>
        <p class="vf-tip">按住拖到右侧画布任意位置松手</p>
      </aside>
      <div
        class="vf-canvas"
        @drop="onDrop"
        @dragover.prevent
        @dragenter.prevent
      >
        <ClientOnly>
          <VueFlow :nodes="[]" :edges="[]" :fit-view-on-init="true" />
          <template #fallback>
            <div class="vf-fallback">流程图画布加载中…</div>
          </template>
        </ClientOnly>
      </div>
    </div>
    <p class="vf-status">已放置 {{ droppedCount }} 个节点 · {{ message }}</p>
  </div>
</template>
