动态组件、KeepAlive 与 Suspense

用 component 与 KeepAlive 切换并缓存面板实例，再用 defineAsyncComponent 和 Suspense 声明组件级异步边界。

开场问题：学习工作台里，我在「笔记」面板写了一半，切到「练习」再切回来——输入框全空了。同一块区域，数据为什么没跟着回来？

同区域面板切换

你做一个学习工作台：右侧是同一块区域，点「笔记」显示笔记面板，点「练习」显示练习面板。笔记面板里有一个文本输入，用户一边看课一边记；练习面板里则是几道题。用户很自然的期望是：切走再切回来，刚才写的东西还在。

这里其实藏着两个独立的问题，容易被人混为一谈。第一个是「渲染哪一个」——同一位置，此刻该显示笔记还是练习？第二个是「记住哪一个」——切走之后，那个面板里用户填了一半的状态要不要留。前者是选择问题，后者是生命周期问题，如果一开始就把它们揉在一起想，代码必然会乱。

模板分支渲染

最省事的做法：在模板里写一串条件分支，用 v-if / v-else-if 判断当前是哪个标签，分别渲染笔记组件和练习组件。

这个方案做对了一件基本的事：它准确表达了「同一位置只显示一个面板」。位置固定，内容互斥，逻辑直白，两三个面板时一眼就能看懂。如果没有切换状态的保留需求，它其实已经够用。

销毁重建导致状态丢失

  • v-if 为假时组件被销毁，内部状态随之清空；切回来是全新实例，输入内容、滚动位置、请求结果统统丢失。
  • 面板一多，模板里就是一长串 v-else-if，加一个面板要改一处分支，维护愈发笨重。
  • 想按数据动态决定渲染谁（比如配置化的工作台）做不到，分支是写死在模板里的。
  • 如果把「保留状态」硬塞进组件内部用 ref 记，就得在每个面板里重复一套「离开前存、进入后取」的样板代码。

动态组件与映射

先把「渲染哪一个」这件事交给数据。动态组件用一个 <component> 标签的 is 属性决定当前渲染谁：把 currentTab 这个响应式变量做成「标签名到组件」的映射，is 指向映射里的值，切换标签时只改数据，模板里再也不用铺条件分支。组件本身成了数据，面板可以按配置增删，模板纹丝不动。

但换成动态组件，前面那个「切走就销毁」的问题原样还在——因为动态组件只负责选择，不负责记忆。所以要再加一层：用 KeepAlive 把动态组件包住。被包住的组件在离开时不会被销毁，而是被缓存下来；再次切回时直接复用同一个实例，内部状态原封不动。至此两个问题各归其位：动态组件管「渲染哪一个」，KeepAlive 管「记住上一个」，职责分明。

角色解决的问题关心的东西
动态组件（is）渲染哪一个当前选中的组件是哪个
KeepAlive记住上一个离开的实例缓不缓存

缓存本身也需要护栏，否则就成了内存泄漏的温床。三条边界要记住：其一，KeepAlive 支持 include / exclude，按组件名控制哪些进缓存，想缓存的留下、不想缓存的路过；其二，用 max 限制最大缓存实例数，超出后按 LRU 思路淘汰最久未用的那个，避免缓存无限增长；其三，永远不要把所有动态组件都无脑缓存——缓存越多内存占用越高，该重建的面板就该让它重建。

需要感知缓存状态时，被 KeepAlive 缓存的组件可以定义 activated 与 deactivated 两个钩子：前者在每次进入（含从缓存恢复）时触发，后者在离开被缓存时触发。用它来做「切回来时刷新一下时间戳」这类动作，比在 mounted 里做更准确——因为从缓存恢复并不会再走一次 mounted。

动态组件加缓存这套组合，最典型的落点就是工作台、标签页、配置化局部区域这几种场景：一块位置要按状态切换内容，且切换回来的体验要连续。识别出「同一位置、多种内容、要保留状态」这三个特征，就等于认出了它。

缓存复用切换观察

渲染选择与缓存

这块区域的两个需求是分开的：用动态组件让 is 决定「渲染哪一个」，用 KeepAlive 决定「记住上一个」。前者把选择交给数据，后者把生命周期接管过来。再用 include / exclude 和 max 给缓存设边界，用 activated / deactivated 感知进出缓存——切换才不会丢状态，也不会悄悄吃光内存。

「动态组件与缓存」中，动态组件用 <component> 的 is 属性决定当前渲染哪个组件，只负责「渲染哪一个」；KeepAlive 缓存离开的组件实例，负责「记住上一个」，再次切回时保留内部状态。用 include / exclude 控制缓存范围，max 限制最大缓存数，并用 activated / deactivated 感知进入与离开缓存。
承接上文：课程详情页里有一块偏重、还要请求数据的学习报告，我想让它用到再加载，可每个异步组件都得自己写一遍 loading 分支——有没有办法在模板层面直接声明「这块内容在等，先显示什么」？

重模块按需加载

你在做课程详情页：顶部是标题和简介，下面挂着一块「学习报告」，里面有图表、有统计，体积明显比别的模块大，而且内容还要靠一次接口请求才能拿到。你不想让这块重内容拖慢首屏，别的页面也不该白白把它加载进来，于是决定「拆开、用到再拿」。

麻烦在于：拆分之后，组件就多出一个「还没到」的时间段。这段时间里页面显示什么？谁来保证加载完成后能自动换成真正的内容？如果每个异步模块都各写各的，页面很快就会被一堆零散的加载判断填满。

异步组件按需加载

最直接的做法有两步：用 defineAsyncComponent 把组件包一层，让它变成按需加载；再在父组件里加一个 loading 布尔，配合 v-if 与 v-else 决定显示占位还是真实内容。

这个做法做对了最关键的一点：它把「大组件」和「首屏」解耦了。组件被拆成独立 chunk，只有真正需要时才发起请求，首屏不必为它买单。同时它也承认了「加载中」是一个必须被表达的状态，而不是可以忽略的空白。

加载判断重复堆叠

  • 每个异步组件都要在父级重复一份 loading 判断，模块一多，状态变量和分支就成倍增长。
  • 组件内部还是一个 async setup，取数据也要时间，父组件却只知道「组件到了没」，管不了「数据到了没」。
  • 页面上同时挂多个异步模块时，各自的占位会此起彼伏地闪烁，视觉上非常碎。
  • 「等待」这件事被拆散在组件模板里，没有一个统一的、可声明的异步边界来描述它。

等待状态提升到模板

不推翻「按需加载」，而是把「等待」从组件内部提升到模板层面。defineAsyncComponent 依然负责把组件拆成独立 chunk 按需加载；新引入的 <Suspense> 负责另一件事：它会等待其异步依赖全部落定——既包括异步组件本身，也包括组件里的 async setup——等待期间渲染 fallback 插槽，落定后再切换到真实内容。

用法很直接：用一层 <Suspense> 包住目标组件，默认插槽写真实内容，fallback 插槽写占位。

  1. defineAsyncComponent 返回一个延迟解析的组件，用到时才去取对应 chunk。
  2. <Suspense> 捕获异步等待阶段，展示 fallback 插槽内容。
  3. 组件解析完成、且内部 async setup 也落定后，占位被替换为真实学习报告。
  4. 用网络面板查看组件 chunk 的按需加载请求与解析时机。

这样一来，「加载中」不再散落在每个组件里，而是被收敛成一处可声明的异步边界：谁包在 <Suspense> 里，谁就共享同一套等待与切换逻辑。它还能同时等待多个 async setup 与异步组件，只要其中任何一个尚未落定，就保持 fallback，直到全部就绪才一次性切换过去。

再往深想一层：为什么要把等待放在模板层，而不是继续放在组件里？因为「异步」本质上是一个跨组件的协作问题。学习报告依赖数据，数据依赖接口，任何一层没就绪，都不该让用户看到半成品。如果等待逻辑写在组件内部，父级就永远无法知道「什么时候才算真正准备好」；把它提到模板层，等于把「准备好的标准」交给使用方来定义——你要等谁、等的时候看什么，都由这层边界统一拍板。

边界要拿捏：异步边界过细，会把页面切得七零八落，增加维护复杂度；过粗，又会把不该等的内容一起拖住，让用户长时间只看到占位。关键首屏内容不宜全部异步化，应优先保证首屏可见，把异步边界留给真正偏重、且非首屏的模块。此外，异步加载失败时必须有错误兜底，本课聚焦的是成功路径与等待态。

占位替换与刷新

拆分与等待分工

Suspense 与异步组件解决的是同一件事的两面：defineAsyncComponent 决定「什么时候去拿」，<Suspense> 决定「还没拿到时显示什么」。把加载态从组件内部手写的 loading 分支，提升为模板层面可声明的异步边界，等待逻辑就只写一次，页面也不会再各个模块各自闪烁。

「异步边界」指由 <Suspense> 划定的等待范围：它会等待其内所有异步依赖（异步组件与 async setup）全部落定，期间渲染 fallback，全部就绪后统一切换到真实内容。它的价值在于把「加载中」从零散的组件内分支，收敛为模板层面可声明、可复用的等待逻辑。

关键代码

Vue
<script setup lang="ts">
import { defineComponent, h, ref } from 'vue'

const NotePanel = defineComponent({
  setup: () => () => h('p', '笔记面板会被 KeepAlive 缓存。'),
})

const PracticePanel = defineComponent({
  setup: () => () => h('p', '练习面板切回来时仍保留组件实例。'),
})

const tabs = {
  note: NotePanel,
  practice: PracticePanel,
}
const currentTab = ref<keyof typeof tabs>('note')
</script>

<template>
  <div class="demo-card">
    <h3>学习工作台</h3>
    <div class="button-row">
      <button @click="currentTab = 'note'">笔记</button>
      <button @click="currentTab = 'practice'">练习</button>
    </div>
    <KeepAlive>
      <component :is="tabs[currentTab]" />
    </KeepAlive>
  </div>
</template>
