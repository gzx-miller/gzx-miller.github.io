defineModel：组件 v-model 的现代化写法

用课程提醒设置对比 defineModel 宏与手写 props/emits，展示 Vue 3.4 起组件级 v-model 的简化写法。

开场问题：只是想给弹窗组件加一个 v-model，为什么要先声明一个 modelValue prop、再手动 emit 一个 update:modelValue 事件，还要处理 trim 这种修饰符？

多组双向绑定

你在做一个课程提醒设置的弹窗：里面有一个「是否开启提醒」的开关、一组单选的提醒频率、还有一个备注输入框。父组件希望像用原生表单一样「绑定」它们，于是用 v-model:enabled、v-model:frequency、v-model:label.trim 把值传进来。

问题出在子组件这边：按旧写法，你要为每一个绑定项各写一对「prop 加事件」，还要自己认出哪个事件对应哪个字段、以及修饰符要不要清洗输入。真正想表达的只是「这个值可以被父组件双向绑定」，可代码里却是一大堆与意图无关的样板。

属性与事件配对

最标准的做法：用 props 接收 modelValue（命名绑定时是 enabled 等），再用 emit 派发对应的 update:modelValue（命名时是 update:enabled）事件，把「我改了」这件事告诉父组件。

它守住了 Vue 最核心的一条纪律：单向数据流。父组件负责持有数据，子组件不能偷偷改父组件的值，只能通过事件请求更新。前提完全正确，只是表达它所需的「仪式」太重了——每一项绑定都要重复一遍 prop 声明、事件声明、赋值时再 emit，字段一多就显得啰嗦又易错。

样板重复与命名风险

  • 每个绑定项都要写一份 prop 与 emit 的样板，重复且容易写错名字。
  • 命名绑定要同时维护 enabled 与 update:enabled，成对出现却分散两处。
  • 修饰符（如 trim）的解析要自己写，父组件和子组件的职责边界模糊。
  • 把 prop 的值当本地状态直接用会失去响应式更新的意义，得再套一层中转。
  • 字段越多，样板代码线性增长，模板之外还藏着一堆只管转发的逻辑。

编译器宏收敛样板

不推翻单向数据流，而是用编译器宏把「prop 加事件」这对样板收敛成一行。这个宏就是 defineModel，从 Vue 3.4 起提供。它返回一个可读写的 ref：读它就是当前的绑定值；给它赋值时，既更新本地状态，又自动帮父组件派发 update 事件。于是子组件里不再需要手写 prop、也不再需要手写 emit。

命名绑定的写法同样直白：defineModel('frequency') 对应的就是父组件的 v-model:frequency。宏里的名字必须与 v-model 后面的后缀保持一致，一个组件里也可以声明多个 defineModel，各管一个绑定项。

需要默认值、必填或本地转换时，把它们写进第二个参数：defineModel('enabled', { default: false }) 就声明了一个默认关闭的开关。至于修饰符，defineModel 的第二个返回值就是修饰符对象——解构出来读一下 trim 是否为真，就能在子组件内决定要不要清洗输入，父组件不必再重复处理。

  1. 父组件用 v-model:enabled、v-model:frequency、v-model:label.trim 绑定子组件。
  2. 子组件用 defineModel 声明同名模型，不再手写 props 与 emits。
  3. 用户交互时直接给返回的 ref 赋值，Vue 自动向父组件派发 update 事件。
  4. 对带修饰符的字段，从解构出的修饰符对象读取 trim 决定是否清洗输入。
使用前必须确认的两点：defineModel 只能在 script setup 中使用，且项目里的 Vue 版本要达到 3.4 及以上，低版本跑不起来。另外，旧的 modelValue 加 emit 的写法仍然被支持，所以可以逐步替换；但新写的组件建议直接用它，减少样板。

回到开场那个弹窗：现在「开关」「频率」「备注」三处绑定，在子组件里就是三行声明加一句修饰符判断，模板与逻辑各归其位，读起来几乎和需求描述一一对应。

为什么推荐用命名模型：一个组件虽然可以声明多个 defineModel，但不带名字的那个默认对应最普通的 v-model。开关、频率这类有明确含义的字段，用命名绑定 v-model:enabled 更能表达意图，父组件读起来也一目了然。

绑定值回写观察

单向数据流不变

defineModel 并没有改变单向数据流的规则，它只是把「prop 加 update 事件」这套样板交给了编译器：你拿到的还是一个受控的 ref，赋值时框架替你同步给父组件。少写的是重复代码，守住的是同一套响应式与可预测性。

「defineModel」是 Vue 3.4 起提供的编译器宏，把「modelValue prop 加 update:modelValue 事件」收敛成一行声明，仅在 script setup 中可用。它返回一个可读写 ref，赋值时既更新本地状态又自动派发 update 事件；defineModel('frequency') 对应 v-model:frequency，第二个返回值是修饰符对象（如 trim），默认值与必填等配置写在第二个参数里。

关键代码

Vue
<script setup lang="ts">
import { computed } from 'vue'

// defineModel 是 Vue 3.4 起提供的编译器宏：让自定义组件像原生表单一样被 v-model 绑定，
// 却无需再手写 modelValue/命名 prop 与 update:xxx 事件。
// 每个 defineModel() 声明都会自动生成对应的 prop 与 update 事件。
const enabled = defineModel<boolean>('enabled', { default: false })
const frequency = defineModel<number>('frequency', { default: 1 })

// 解构出第二个返回值即可读取修饰符：父组件写 v-model:label.trim 时，这里得到 { trim: true }。
const [label, labelModifiers] = defineModel<string>('label', { default: '' })

const frequencyOptions = [
  { value: 1, text: '每天' },
  { value: 2, text: '每周' },
  { value: 3, text: '每月' },
]

const frequencyText = computed(() => frequencyOptions.find((o) => o.value === frequency.value)?.text ?? '—')

function onLabelInput(e: Event) {
  const raw = (e.target as HTMLInputElement).value
  // 修饰符在组件内部处理，父组件无需重复 trim。
  label.value = labelModifiers?.trim ? raw.trim() : raw
}
</script>

        </div>
