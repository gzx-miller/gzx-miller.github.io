过渡动画：Transition、TransitionGroup

用学习提醒展示单元素和列表元素的进入离开动画。

开场问题：一条提示语「啪」地出现、「啪」地消失，用户根本没看清发生了什么——为什么给元素写好 CSS 过渡，动画还是不着调？

提示语进出动画

你做一个学习提醒：用户完成一节课程，页面冒出一条鼓励的提示，几秒后淡出。你还想给待办清单加点手感——新加一条时从右侧滑入，删掉时滑出去。可当状态一变，提示语和列表项都是瞬间出现、瞬间消失，界面生硬得像坏了，用户甚至来不及注意到「多了什么、少了什么」。

你可能尝试过：给元素写一句 transition: opacity .3s，然后在 JS 里把它插进 DOM。结果发现淡出根本没发生——因为元素被移除的那一刻，它已经不在了，CSS 无从过渡。这就是问题真正的难点：让一个「即将被删除的节点」在删除前把动画完整播完，这件事在纯 CSS 里做不到。

手动挂类触发过渡

最省事的做法：用状态控制元素的显隐，同时手动给元素挂上过渡属性，在插入前后改 class 或 style，让浏览器有前后两帧可比较，从而触发过渡。

这个方案做对了一件本质的事：动画的前提是「同一属性有两个不同取值」。透明度、位移这些能过渡的属性，必须一帧是初值、一帧是终值，中间才有插值空间。只要满足这一条，简单元素的淡入淡出是能做出来的。

进入离开与重排

  • 元素进入时，你得先把它插进 DOM、强制浏览器重排一次，再改目标值，否则首帧和末帧被合并，动画被吞掉。
  • 元素离开时更难：要在动画播完后才移除节点，你甚至得监听 transitionend 并处理它不触发、被打断的各种情况。
  • 列表增删时，你根本不知道哪个元素该进、哪个该出、哪个只是移动了位置，逐一判断成本极高。
  • 这些「插节点、加类名、等结束、删节点」的时序逻辑，每处都要重写一遍，稍有闪失就是动画卡住或节点残留。

节点增删时机接管

不推翻「靠两个取值触发过渡」，而是把节点增删的时机从你手里接管过去。这就是 Transition：当被它包裹的元素进入或离开时，它会在正确的时刻自动添加、移除一组阶段类名，你只需要在 CSS 里针对这些类名写动画，剩下的时序全由 Vue 负责。

  1. 状态变化让文字进入 DOM，Vue 立刻挂上 fade-enter-from 与 fade-enter-active。
  2. 下一帧去掉 fade-enter-from，元素从初值过渡到终值，生效的是 fade-enter-to。
  3. 进入结束，Vue 移除全部进入类名，元素回到常态。
  4. 状态变化让文字离开时，Vue 先加 fade-leave-from 与 fade-leave-active，等动画播完才真正把节点移出 DOM。

把 name 设为 fade，所有类名就自动带上 fade- 前缀——这就是 Transition 的命名契约。你不再关心「什么时候加类、什么时候删节点」，只关心「进入和离开各长什么样」，职责一下子清晰了。

单元素的动效解决了，列表还有一层：新增一条要滑入、删除一条要滑出、剩下那些因为位置变化要平滑移动。这属于多元素的场合，交给 TransitionGroup。它和 Transition 共用同一套阶段类名规则，额外多一个 -move 类专门处理移动；用 tag 属性可以指定它渲染成什么包裹元素，比如一个无序列表。

列表过渡必须使用稳定 key。Vue 靠 key 识别每个元素的身份，才能判断谁被添加、谁被移除、谁只是换了位置。如果 key 用了数组下标，增删后下标会整体移动，Vue 会把「在末尾新增」误判成「每一项都变了」，动画立刻错乱。key 应该是数据本身自带的、稳定的唯一标识。

还想做更复杂的动效——弹性、物理缓动、路径动画——可以走 Transition 的 JavaScript 钩子：@before-enter、@enter、@leave 会在对应阶段被调用，在钩子里用 GSAP、anime.js 这类库接管动画，做完后调用传入的 done 回调，Vue 才知道这一段结束了。但无论动画多花哨，状态来源仍要保持清晰：由 v-if 或列表数据决定元素该不该存在，动画只负责渲染过渡，而不是反过来用动画去驱动状态。

一条尺度：动画应当服务于理解和反馈——让用户看清「什么进来了、什么离开了」，而不是为了装饰而拖慢操作。动效时长过长、处处都在动，反而会让人分不清主次、觉得卡顿。

过渡时序托管

过渡动画要解决的，是「状态变了，但用户没看清」的问题。方案是把节点增删的时序交给 Transition——它在进入和离开的正确时机自动加阶段类名，CSS 只管写动画；列表的多元素增删移动则交给 TransitionGroup，并务必用稳定 key。更复杂的动效走 JavaScript 钩子，但状态来源始终要清晰。

「过渡」中，Transition 在元素进入和离开时自动在正确时机添加阶段类名（如 fade-enter、fade-leave），CSS 依据这些类名执行动画，节点增删时机由 Vue 接管；TransitionGroup 处理列表中多个元素的增删移动，必须使用稳定 key。更复杂的动画可用 @before-enter / @enter / @leave 等 JS 钩子，配合 GSAP、anime.js 实现。

Vue
<script setup lang="ts">
import { ref } from 'vue'

const showTip = ref(true)
const goals = ref(['读完 🌰16', '写一个过渡动画'])
</script>

<template>
  <div class="demo-card">
    <h3>学习提醒</h3>
    <button @click="showTip = !showTip">切换提示</button>
    <Transition name="fade">
      <p v-if="showTip">过渡用于让进入和离开的 DOM 有状态变化。</p>
    </Transition>
    <TransitionGroup name="list" tag="ul">
      <li v-for="goal in goals" :key="goal">{{ goal }}</li>
    </TransitionGroup>
  </div>
</template>
