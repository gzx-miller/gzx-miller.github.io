响应式基础与计算监听

用 ref、reactive 建立响应式状态，再用 computed、watch 和 watchEffect 表达派生值与副作用。

开场问题：我明明把变量改掉了，页面却纹丝不动——数据变化到底是怎么被「听见」，又是在什么时候变成新界面的？

数据界面同步需求

做一个学习进度页：显示用户名字、已经完成的章节数量，以及当前所处阶段。点一下「完成一章」，章节数加一，当数字超过某个门槛时，阶段文案从「初级前端」变成「Vue3 熟练者」。

这件事的数据侧其实很朴素：一个数字，一个字符串。真正的问题是数据变了以后，屏幕怎么知道。在过去的写法里，这两者之间没有连线，你得亲手去搭。

手动同步与更新

最直接的做法：把数据存进普通变量，每次修改之后，紧接着手动去更新页面上的对应元素——先写 count += 1，再找到页面里那个数字节点把它改掉；阶段变了，就再找文案节点改一遍。

这个方案做对了一件重要的事：它承认「界面是数据的投影」，数据是唯一要维护的源头，界面只是它的显示结果。只要「数据一改就立刻刷新界面」这条规则能被严格执行，页面就永远是对的。问题在于，人很难严格执行这条规则。

遗漏同步与过期视图

  • 每改一个字段就要记得补一次 DOM 更新，漏掉一处，界面上就留一个过期的数字。
  • 阶段文案是由数量推导出来的，写在更新逻辑里等于把「派生关系」藏进了一堆命令式代码。
  • 数据结构一旦变成嵌套对象，手动「找到对应节点再改」的路径会越来越长。
  • 同一个数据被多个地方引用时，你得在两个地方同时改，稍不留神就出现两份不一致的真相。

响应式容器包裹

不推翻「数据是源头」，只是把「改完记得刷新」这条纪律，交给框架来执行。做法是：不再用普通变量，而是用一个能被追踪的容器包住数据。Vue 提供了两种容器，对应两种数据形态。

第一种是 ref：它把单个值包装成一个响应式引用。第二种是 reactive：它把一个对象转换成响应式代理，对象的每个属性都会被追踪。放进容器之后，事情就反转了——你只管改数据，界面会自动跟上。

原理并不复杂：模板在读取这些状态时，Vue 会自动追踪依赖，记下「这块视图用到了哪些数据」；状态一变，依赖它的视图就重新渲染。你改的是数据，更新的是视图，中间那条线由框架负责维护。

接着要记住两者各自的规矩。在 script 里读写 ref 必须使用 .value，而在模板中会自动解包——因为模板里那句表达式是由编译器处理的，它知道这是引用。这条差异是初学者最容易踩的坑：同一个值，在代码里要加后缀，在模板里不用。

然后是 reactive 的三个局限，它们决定了你该怎么选：

  • 不能整体替换：直接给变量赋一个新对象会切断响应式连接，视图不再更新；应逐个属性修改，或使用 Object.assign 合并。
  • 不能用于原始类型：数字、字符串这类单值只能用 ref。
  • 解构会丢失响应式：普通解构拿到的只是一次性的值，需要解构又想保留响应式时，用 toRefs 把属性转成 ref。

有了这些边界，选择口径就很清楚了：单个原始值优先用 ref，结构化对象优先用 reactive，或者拆成多个 ref——最终按可读性决定。表单类对象适合整体用 reactive 组织；零散的状态用一个个 ref 更直观。

验证一次这个坑：把 reactive 对象整体重新赋值（比如 profile = newProfile），你会发现视图不再跟着变——响应式连接断在了赋值那一刻。正确做法是改属性而不是换对象，或直接用 Object.assign 把新值合并进去。
  1. 用 ref 保存章节数量，用 reactive 保存用户资料这类对象状态。
  2. 点击按钮时修改 count.value 和 profile.level。
  3. 模板读取这两个状态，Vue 自动把最新状态同步到页面。
  4. 给 reactive 对象整体重新赋值，观察响应式丢失导致视图不再更新。

数字与文案联动

依赖追踪与重渲染

响应式的本质，是把「数据变 → 界面变」这条纪律从人手里交给框架：用 ref 包住单值、用 reactive 包住对象，模板读取时自动追踪依赖，变化时精确重渲染。你要记住的只是几条边界——script 里 ref 要写 .value，reactive 不能整体替换、不能装原始值、不能随意解构。

「响应式引用」指 ref，它把单个值包装成可被追踪的引用，script 中读写要用 .value，模板中自动解包；reactive 则把对象转换成响应式代理。模板读取状态时自动追踪依赖，状态变化后依赖它的视图重新渲染。reactive 不能整体替换、不能用于原始类型，解构需用 toRefs 才能保住响应式。
承接上文：「合计金额」这种数据，到底是该单独存一个变量、每次手动同步，还是根本不存、随用随算？

合计金额存与算

做一个购物车：填入单价和数量，页面实时显示合计金额。此外还有两个附带要求——每次金额变化要记一条日志，数量达到批量优惠门槛时要给出提示。

合计金额是在 单价 × 数量 这个关系下产生的新值。问题来了：它该被当成一个要维护的状态，还是当成一个要计算的结论？这个判断会直接影响后面代码里有多少 bug 在等着你。

监听触发重算

最直觉的做法：声明一个 total 变量，然后「监听」两个输入，一旦它们变化，就重新算一遍并赋值给 total。

这个方案做对了两件事：它承认「金额会变」，也承认「变化需要有人响应」。在只有一个输入源、一条计算规则、一处响应逻辑的场景里，这种做法完全够用，而且行为一目了然。

双来源与派生关系

  • 同一份事实出现了两个来源：单价数量和合计金额。它们随时可能因为漏写一次同步而互相矛盾。
  • 派生关系被写进了命令式代码里，看代码的人很难一眼看出「合计就是单价乘数量」。
  • 如果在这条同步链路上再挂一个「修改合计反向改数量」的需求，非常容易绕成死循环。
  • 多个地方都要读这个值，但没人能保证它被更新的时机，读到旧值的概率随代码量上升。

派生值与计算缓存

关键的分岔点在于：能算出来的，就不要存。把合计从「状态」降级成「派生值」，交给 computed 描述。它接收一段表达式，返回一个结果，依赖变化时自动重算；更妙的是它带缓存——只要依赖没变，重复读取不会重新执行，适合高频访问的派生数据。派生关系被写回了「数据本身」，不再是一串需要人记住的同步动作。

但「记录日志」不同。它不是数据，它是一个副作用：要做的事发生在 Vue 之外，需要明确知道「什么时候触发」。这类需求交给 watch——它监听一个明确的来源，在变化时执行一段回调，适合请求、日志、本地存储和与外部系统同步。

还有第三种：watchEffect。它自动收集回调里同步读取到的依赖，省去了手写来源列表的麻烦，适合快速建立依赖驱动的副作用；代价是依赖收集更隐式，读代码时要靠回调体反推它到底依赖了什么，复杂场景下不如 watch 好读。

工具定位典型场景
computed可缓存的派生值，依赖不变不重算合计金额、筛选后的列表
watch监听明确来源，执行副作用日志、请求、本地存储
watchEffect自动收集同步依赖，隐式快速建立依赖驱动的副作用

选择口径可以一句话记牢：能用 computed 表达的，就不要用 watch 手动同步，否则又会出现两份数据不一致；只有当需要明确的触发源与副作用时，才用 watch。

还有一个判断技巧：如果某样东西能被别的东西算出来，它就是派生值，交给 computed；如果某件事情必须去做——打点上报、写入本地存储、清理定时器——它就是副作用，交给 watch。前者回答「是什么」，后者回答「要做什么」，这句话能把大部分选择直接定下来。

两个容易漏的参数：监听对象属性时，需要 deep: true 才能检测到嵌套变化，否则对象的内部字段被原地修改时不会触发；immediate: true 可以让回调在初始化时立即执行一次，适合「首次也要上报」的场景。
  1. 单价或数量变化后，total 自动重新计算。
  2. 用 watch 监听 total，把金额变化写入日志。
  3. watchEffect 根据数量阈值给出批量优惠提示。
  4. 对比 computed 与 watch 的触发日志，验证前者只在依赖变化时重算。

重算触发与日志

计算与监听分工

计算与监听的区别，本质是「派生」与「副作用」的区别：能由状态推出来的结果用 computed，让它随依赖自动重算并享受缓存；需要对变化做出反应的事用 watch，监听明确来源、执行明确的副作用。把两者用反，就会出现两份数据打架或者一堆看不懂的隐式依赖。

「派生值」指由其他状态计算得出的结果，用 computed 描述，依赖不变时不重算。watch 用于监听明确来源并执行副作用（请求、日志、本地存储），支持 deep 与 immediate 选项；watchEffect 会自动收集同步读取到的依赖。选择顺序是：优先 computed，需要明确触发源与副作用时才用 watch。

关键代码

Vue
<script setup lang="ts">
import { reactive, ref } from 'vue'

const count = ref(1)
const profile = reactive({
  name: '林青',
  level: '初级前端',
})

function promote() {
  count.value += 1
  profile.level = count.value > 3 ? 'Vue3 熟练者' : '初级前端'
}
</script>

<template>
  <div class="demo-card">
    <h3>{{ profile.name }} 的学习进度</h3>
    <p>完成章节：{{ count }}</p>
    <p>当前阶段：{{ profile.level }}</p>
    <button @click="promote">完成一章</button>
  </div>
</template>
