Metadata 与 SEO

用 Metadata API（静态 metadata + 动态 generateMetadata）管理 title、description、OG 等 SEO 元信息。

开场问题：课程链接发到群里，别人看到的只是一条光秃秃的地址，没有标题也没有配图；可详情页的标题又必须跟着具体课程名走——这些「页面之外的文字」，到底该由谁来决定？

正文外元信息

你在做课程站，课程详情页有几百个，每个都有各自的标题、简介和封面。搜索时要能被正确收录，分享到社交平台时要能展开成一张带标题和配图的卡片。可这些信息大多不在页面正文里——它们属于页面的「元信息」，藏在正文之外的标签里。

难点也因此出现：正文可以随数据变化，元信息却常常停留在「每页手动写一段」的阶段。结果是标题忘了改、简介写得千篇一律、分享卡片永远缺一张图。更麻烦的是，元信息必须在页面被看到之前就正确，否则爬虫抓到的是错的，分享出去的是空的。

头部标签写法

最直接的做法是在页面里手写这些标签，或者在客户端用脚本去改文档标题。前者是「每个页面各自维护一段头部」，后者是「等页面跑起来再设置标题」。

它们的共同假设是：元信息可以在渲染过程中随手拼出来。对于纯静态、数量很少的页面，这个假设勉强成立；一旦页面由数据驱动、数量成百上千，这个假设就站不住了。

客户端改标题缺陷

  • 客户端脚本改标题，是在页面已经渲染之后才发生；爬虫和社交平台抓到的仍是初始空壳。
  • 每个页面各自写一段头部，字段容易写漏、格式容易不一致，改一处要改很多处。
  • 动态页面的标题依赖数据，客户端设置时用户会看到标题「闪」一下才变化。
  • 分享卡片、站点地图、爬虫规则这类东西，很容易被彻底遗忘。
  • 父子页面之间没有继承与覆盖的规则，公共描述与单页描述混在一起，难以维护。

统一元信息接口

App Router 把这件事收进了统一的元信息接口，取代了旧版的头部组件。核心是两种写法：静态的导出对象与动态的生成函数。

静态场景直接导出一个元信息对象，声明标题、描述、关键词、作者，以及开放图谱和社交卡片所需的字段。它适合内容固定的页面，也适合放在根布局里作为全站默认值。

子页面与父布局之间靠字段级覆盖来协作：子页面只写自己关心的字段，其余自动沿用父级；同名字段则子级覆盖父级。标题还提供了一个拼接模板：在父级把标题设成「默认值 + 模板」，模板里的占位符会被子页面的标题替换，于是每个子页标题都自动带上站点名，不必逐页重复。

动态场景则导出一个异步函数，从路由参数里取到标识，再去查这条数据，然后把标题、描述、封面图一并返回。因为它和页面渲染同处服务端、共享同一份数据，你可以在函数与页面里放心地取同一份数据——框架会在同一次渲染内对相同请求去重，不会因此多打一次接口。

除代码之外，还有一批「放文件就等于配置」的约定：在目录里放图标文件即成为站点图标，放分享图即成为社交卡片图，放站点地图与爬虫规则文件即自动对外提供。其中站点地图和爬虫规则也可以用代码生成：导出一个函数返回该有哪些页面、哪些路径允许抓取，框架会据此输出对应文件。分享图甚至可以用代码「画」出来，让每篇内容都有专属卡片。

两个实用细节：元信息是从父级向子级逐层派生并合并的，返回时会按字段自动去重，子页面覆盖父级同名字段，因此你不必在子页面把父级的字段再抄一遍；父级标题模板里的占位符会被子页标题替换，是批量统一标题格式的最省力方式。

静态动态字段分工

元信息随渲染生成

元信息管理的本质，是让它成为渲染的一部分，而不是事后补的一段代码。静态页面用对象声明，动态页面用函数生成，图标与站点地图交给文件约定，标题用模板自动拼接——这样每一页在还没被看到时，就已经是「正确且完整」的了。

「Metadata API」App Router 用统一的元信息接口取代旧版头部组件：可导出静态元信息对象，或动态生成函数按路由参数产出标题、描述与开放图谱字段；也支持文件约定（站点图标、分享图）与代码生成的站点地图和爬虫规则。元信息从父级向子级按字段派生并覆盖，标题模板中的占位符会被子页标题替换。

  keywords: ['Next.js', 'React', 'TypeScript'],
  authors: [{ name: '作者名' }],

    title: '我的网站',

// 动态 generateMetadata
// app/posts/[slug]/page.tsx
import type { Metadata } from 'next'

type Props = {
  params: { slug: string }
}

// 动态生成 metadata
export async function generateMetadata({
  params,
}: Props): Promise<Metadata> {
  const post = await fetch(`https://api.example.com/posts/${params.slug}`)
    .then(res => res.json())

  return {
    title: post.title,
    description: post.excerpt,
    openGraph: {
      title: post.title,
      description: post.excerpt,
      images: [post.coverImage],
    },
  }
}

export default async function PostPage({ params }: Props) {
  const post = await fetch(`https://api.example.com/posts/${params.slug}`)
    .then(res => res.json())

  return <article>{post.content}</article>
}

// 动态生成 sitemap
// app/sitemap.ts
import type { MetadataRoute } from 'next'

export default function sitemap(): MetadataRoute.Sitemap {
  return [
    {
      url: 'https://example.com',
      lastModified: new Date(),
      changeFrequency: 'weekly',
      priority: 1,
    },
    {
      url: 'https://example.com/about',
      lastModified: new Date(),
      changeFrequency: 'monthly',
      priority: 0.8,
    },
    {
      url: 'https://example.com/blog',
      lastModified: new Date(),
      changeFrequency: 'daily',
      priority: 0.9,
    },
  ]
}

// 动态生成 robots.txt
// app/robots.ts
import type { MetadataRoute } from 'next'

export default function robots(): MetadataRoute.Robots {
  return {
    rules: {
      userAgent: '*',
      allow: '/',
      disallow: '/admin/',
    },
    sitemap: 'https://example.com/sitemap.xml',
  }
}

// 动态 OG 图片生成
// app/posts/[slug]/opengraph-image.tsx
import { ImageResponse } from 'next/og'

export async function generateImageMetadata({
  params,
}: {
  params: { slug: string }
}) {
  return [
    {
      contentType: 'image/png',
      size: { width: 1200, height: 630 },
      id: params.slug,
    },
  ]
}

export default async function Image({
  params,
}: {
  params: { slug: string }
}) {
  return new ImageResponse(
    (
      <div style={{ fontSize: 60, color: 'white', background: 'black', padding: '50px' }}>
        <h1>{params.slug}</h1>
      </div>
    ),
    {
      width: 1200,
      height: 630,
    }
  )
}
