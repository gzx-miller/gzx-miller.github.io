布局与模板：共享 UI 的层级

理解根布局、嵌套布局、路由组布局和 template 的区别与嵌套机制。

开场问题：在后台的侧边栏输入框里敲了半句话，切到另一个子页面再切回来，输入的内容居然没了——明明两次渲染的是同一个 layout.tsx，为什么状态会被清空？

持久外壳与状态

后台站点总有一些 UI 是「一直待在屏幕上」的：顶部导航、侧边栏菜单、底部版权。它们不该在每次点链接时闪烁重画一遍，更不该丢掉自己的状态。可同时也存在另一类需求：某些页面希望每次进入都重新开始——比如文章页的「本次阅读计数」、进入动画、或者需要在挂载时重新执行的副作用。

这就引出一个必须想清楚的问题：当用户从 /dashboard/orders 跳到 /dashboard/settings 时，哪些部分应该原封不动地留着，哪些部分应该推倒重来？如果只有一种「共享外壳」的概念，这两类需求就会打架，你要么到处丢状态，要么该重置的偏不重置。

逐页手动引入

最朴素的做法，是把共享外壳当成普通组件，在每个页面里手动引入并包一层：app/dashboard/orders/page.tsx 里自己 import 侧边栏，再套住自己的内容。这做对了一件事——共享 UI 确实被复用起来了，你只写一份侧边栏代码。

但它把「复用」和「生命周期」混为一谈：虽然每个页面用的都是同一个侧边栏组件，可它们各自渲染各自的一份实例。于是每次导航都等于旧的卸载、新的挂载，状态自然保不住。

重复引入成本

  • 每个页面都要手动拼一遍外壳，页面一多就到处是重复的 import 与包裹。
  • 共享组件是按页面各自实例化的，导航时状态被重置，侧边栏里的输入、展开项、滚动位置全丢。
  • 没有「哪些页面归同一套外壳」的天然边界，靠人记，容易漏。
  • 需要「每次进入都重置」的场景没有专门位置，只能硬塞进页面组件里。

布局提升为约定

不推翻「共享外壳」，而是把它提升为目录级约定：在目录里放一个 layout.tsx，它自动包裹该目录及所有子目录下的页面，子页面通过 children 嵌进来。这样一来，「哪些页面共享同一外壳」由目录结构决定，而不是靠每个页面自觉引入。

关键变化在于挂载时机：layout 在导航时保持挂载、不重新创建实例，所以它用 useState 存的状态会跨页面保留。这正是侧边栏输入框不再丢字的根本原因。而根布局 app/layout.tsx 是最外层，必须包含 <html> 和 <body>，全站字体与全局样式都在这里引入。

布局是层层嵌套的：根布局在最外，app/dashboard/layout.tsx 嵌在它里面，dashboard 的页面又嵌在 dashboard 布局里。导航到 dashboard 的子页面时，只要路径仍在 /dashboard 之下，dashboard 布局就持续存在，只有 children 那部分在换。

那么「每次进入都重置」该放哪？答案是 template.tsx：它的位置和用法跟布局一样，区别在于每次导航都会重新创建一个新实例，状态随之重置。于是判断标准变得很清晰：

对比项layout.tsxtemplate.tsx
导航时是否重新挂载否，保持挂载是，重新创建
组件状态保留重置
典型适用顶部导航、侧边栏、底部等持久 UI进入动画、每次都要重跑的副作用

还有一招值得记住：路由组可以各自定义布局，从而让「同一站点的不同路径区间」套上完全不同的外壳。例如 app/(marketing)/layout.tsx 给营销页配一套轻导航，app/(dashboard)/layout.tsx 给后台配一套侧边栏，URL 里却不出现分组名。

一个常被忽略的坑：不要把「需要按页面重新执行的数据请求」放进 layout.tsx。因为布局在导航时不重新挂载，里面的请求只会在首次加载时跑一次，之后切页面拿到的是旧数据。这类逻辑应该放到 page 或 template 里，让它在该刷新的时候刷新。

模板与布局状态

挂载保持与重建

布局与模板这一课，核心是把「共享外壳」拆成两种生命周期：layout 保持挂载、状态跨导航保留，适合持久 UI；template 每次导航重建、状态重置，适合需要重跑的场合。布局按目录层层嵌套，路由组则让不同路径区间各用一套外壳。

「布局与模板」都是目录级的包裹组件，用 children 嵌住子页面。区别在于生命周期：layout.tsx 导航时保持挂载，useState 等状态会保留，适合头部、侧边栏等持久 UI；template.tsx 每次导航重新创建实例，状态重置，适合进入动画或每次都要重跑的副作用。根布局必须含 <html> 与 <body>，且不要在布局里放需要按页面重跑的数据请求。

关键代码

JSX
// app/layout.tsx - 根布局（最外层）
import './globals.css'

export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="zh-CN">
      <body>
        <header>全站头部</header>
        {children}
        <footer>全站底部</footer>
      </body>
    </html>
  )
}

// ============================================

// app/dashboard/layout.tsx - 嵌套布局
// 导航时保持挂载，状态不重置
export default function DashboardLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <div className="dashboard">
      <aside>侧边栏导航</aside>
      <main>{children}</main>
    </div>
  )
}

// ============================================

// app/dashboard/page.tsx - dashboard 首页
// 被 dashboard layout 包裹
export default function DashboardPage() {
  return <h1>仪表盘首页</h1>
}

// ============================================

// app/(marketing)/layout.tsx - 路由组布局
// 同 URL 可以有不同布局（营销页 vs 后台）
export default function MarketingLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <div className="marketing">
      <nav>营销导航栏</nav>
      {children}
    </div>
  )
}

// ============================================

// app/blog/template.tsx - 模板（每次导航重新创建）
// 与 layout 不同，template 的状态会在导航时重置
'use client'

import { useState } from 'react'

export default function BlogTemplate({
  children,
}: {
  children: React.ReactNode
}) {
  // 每次进入新文章，这个状态都会重置
  const [views, setViews] = useState(0)

  return (
    <div className="blog-template">
      <p>浏览次数：{views}</p>
      {children}
    </div>
  )
}

// ============================================

// RootLayout (app/layout.tsx)
//   └─ DashboardLayout (app/dashboard/layout.tsx)
//        └─ DashboardPage (app/dashboard/page.tsx)
