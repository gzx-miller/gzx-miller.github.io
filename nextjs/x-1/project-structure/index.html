项目结构与 App Router 目录约定

了解 App Router 的目录约定、app/ 核心文件的职责，以及 public/ 与 next.config.js 在项目中的作用。

开场问题：刚拉下一个 Next.js 项目，app/ 里躺着 page.tsx、layout.tsx、loading.tsx、error.tsx 一堆同名文件——为什么首页入口叫 page.tsx 而不是 index.tsx，这些文件分别归谁管？

手写路由表负担

你想给课程站加一个「关于我们」页面。在熟悉的单页应用里，你会打开路由配置文件，手写一条 path: '/about' 的记录，再把组件挂上去。可到了 Next.js 的项目里，你翻遍目录都找不到那张路由表，只看到一层层文件夹和几个名字固定的文件。于是第一个真实的困惑就是：页面到底写在哪、目录里的每个文件又各自承担什么职责？

再往深一层想，一个页面从来不只有自己的内容。它还要顶着全站的头部导航、踩着底部版权，中间可能还要处理「数据没回来时的加载态」、「出错时的兜底界面」、「路径不存在时的 404」。如果每个页面都各自抄一遍这些东西，重复且容易走样。所以框架需要的不是一张手势维护的路由表，而是一套用目录结构表达页面归属与共享外壳的约定。

单组件条件渲染

最朴素的做法，是把 app/ 当成一个普通文件夹：只写一个入口组件，在组件里用一个变量记下「当前想看哪个页面」，再用条件判断决定渲染哪一段 JSX。这套纯客户端 SPA 的思路确实做对了一件事——它承认页面可以被抽象成组件，UI 因此变得可拆分、可组合。

代价是它把「路由」这件本可以写在结构里的事，藏进了运行时的判断分支。你新增一个页面，就得回去改那个 if / else；共享的头部、加载态、错误兜底，也只能靠每个页面自觉去拼。

约定缺失与重复

  • URL 与代码之间没有稳定的对应关系：加一个页面就要动一处分支逻辑，漏改就漏页。
  • 共享外壳靠手动重复：头部、底部、面包屑在几十个页面里各写一份，风格漂移难以收敛。
  • 加载态、错误态、404 没有统一落点，只能每个页面各写各的。
  • 没有按路径切分的天然边界，打包时无法按路由做代码分割，路径越多首包越臃肿。
  • 服务端无法根据请求路径直接输出对应的 HTML，首屏要等 JavaScript 下载并执行完才看得到内容。

目录即路由表

不推翻「页面是组件」，而是把路由提升为目录约定：文件系统的目录层级，直接映射为 URL 层级。你不再维护路由表，目录结构本身就是路由表。app/page.tsx 对应 /，app/about/page.tsx 对应 /about，想加页面就新建一个目录加一个 page.tsx。

这个约定里，只有 page.tsx 是路由入口，其余文件都是围绕它的布局与状态约定。要先立住的是根布局 app/layout.tsx：它是必需的，且必须自带 <html> 和 <body> 标签，全局样式也在这里引入。所有页面都会被它包裹，于是「全站共享外壳」第一次有了唯一落点。

接着把状态也变成文件约定，各归其位：

文件职责
layout.tsx共享布局，导航时保持挂载；根布局必须含 <html>／<body>
page.tsx路由的唯一入口，目录层级即 URL
loading.tsx路由切换时自动显示的加载界面
error.tsx错误边界，必须是客户端组件，提供 reset 重试
not-found.tsx路径或数据不存在时的 404 界面

其中 error.tsx 需要特别留意：因为它要处理「重试」这类交互，所以文件顶部必须写 'use client'，组件会收到 error 与 reset 两个参数，前者用于上报日志（常见做法是在 useEffect 里打印），后者用于重新渲染出错的那一段。

除了 app/，项目根还有两个常被问到的位置：public/ 放静态资源，目录下的文件可以直接通过 / 访问（例如 public/logo.png 对应 /logo.png）；next.config.js 则是框架配置文件，像允许远程图片域名、开启严格模式这类开关都写在这里。

两个容易踩的坑：其一，pages/ 目录仍能运行，但已逐步淘汰，新项目请统一用 app/；其二，迁移期间 pages/ 与 app/ 可以并存，但同一条路径不能在两处同时定义，否则会在构建时冲突报错。

文件职责归属

路由迁入目录结构

项目结构这一课，真正的转变是「路由从配置文件搬进了目录结构」：目录层级即 URL，page.tsx 是唯一入口，layout／loading／error／not-found 则把共享外壳与各种状态收进约定文件名。你不再维护路由表，只需要按约定摆放文件。

「App Router」是 Next.js 基于文件系统的路由方案：以 app/ 目录组织代码，目录层级即 URL 层级，page.tsx 是唯一的路由入口，layout.tsx 提供共享布局（根布局必须含 <html> 与 <body>），loading／error／not-found 分别约定加载、错误与 404 状态。pages/ 仍可运行但已逐步淘汰，两者并存时同一路径不可重复定义。

关键代码

JSX
// app/layout.tsx - 根布局（必需）
import './globals.css'

// 根布局必须包含 html 和 body 标签
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="zh-CN">
      <body>{children}</body>
    </html>
  )
}

// ============================================

// app/page.tsx - 首页页面组件
// 只有 page.tsx 才会生成路由入口
export default function HomePage() {
  return (
    <main>
      <h1>欢迎来到 Next.js</h1>
      <p>这是首页，由 app/page.tsx 渲染</p>
    </main>
  )
}

// ============================================

// app/about/page.tsx - 关于页
// 目录层级即 URL 路径层级
export default function AboutPage() {
  return (
    <div>
      <h1>关于我们</h1>
      <p>Next.js App Router 示例</p>
    </div>
  )
}

// ============================================

// app/loading.tsx - 全局加载状态
// 路由切换时自动显示
export default function Loading() {
  return <div className="loading">加载中...</div>
}

// ============================================

// app/error.tsx - 全局错误边界
'use client'

import { useEffect } from 'react'

export default function Error({
  error,
  reset,
}: {
  error: Error & { digest?: string }
  reset: () => void
}) {
  useEffect(() => {
    console.error(error)
  }, [error])

  return (
    <div>
      <h2>出错了！</h2>
      <button onClick={() => reset()}>重试</button>
    </div>
  )
}

// ============================================

// next.config.js - Next.js 配置文件
/** @type {import('next').NextConfig} */
const nextConfig = {
  reactStrictMode: true,
  images: {
    remotePatterns: [
      {
        protocol: 'https',
        hostname: 'example.com',
      },
    ],
  },
}

module.exports = nextConfig
