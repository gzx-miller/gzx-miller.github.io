动态路由与参数

掌握动态路由参数、Catch-all、可选 Catch-all，以及 params 与 searchParams 的使用。

开场问题：商品详情页只有一个文件 app/products/[id]/page.tsx，可全站有上万件商品——这个文件名里没写数字，页面又是怎么知道用户到底点开的是哪一件的？URL 后面那串 ?utm_source=xxx 又该从哪里读？

同类页面规则化

电商站的商品详情页、内容站的分类页、搜索页，都有一个共同点：它们的「长相」是同一个，只是数据不同。你不会为每一件商品都建一个目录，而是希望一条规则覆盖一整类路径，运行时再根据实际地址取出参数，去查对应的数据。

这里其实藏着两类完全不同的「参数字段」：一类是路径的一部分，比如 /products/123 里的 123，它决定了你访问的是哪个资源；另一类是路径之外的查询串，比如 /products/123?utm_source=wechat，它通常是统计来源、分页、筛选这类附加信息。搞清楚 这两类参数各自从哪读、读出来是什么类型，是这一课要解决的核心问题。

单段参数捕获

最小的一步，是先用方括号捕获一段路径：app/products/[id]/page.tsx。页面组件会收到一个 params 对象，访问 /products/123 时 params.id 就是字符串 '123'，拿它去请求数据即可。

这一步做对了最关键的事——用文件名表达「这一段是变量」，一条路由就能覆盖整类页面。只要路径只有一段可变、且这一段必然存在，这样写就足够。

任意深度捕获

  • 分类页的路径可能有任意多段，像 /categories/electronics/phones，单段 [id] 只能吃到一段。
  • 搜索页希望 /search、/search/react、/search/react/hooks 都能命中，尾段可有可无，普通方括号表达不了「可选」。
  • 来源、分页这类信息写在查询串里，params 里读不到，得另找入口。
  • 查询串的值可能是字符串，也可能是同名参数的数组，直接当字符串用会出错。
  • 热门商品如果能提前生成静态页，首屏会更快，但静态目录没法为「未知的上万个 id」预先建好。

捕获能力分级

不推翻「方括号捕获变量」，而是把捕获能力按需要分级，并为查询串单独留一个入口。

  1. 单段参数继续用 [id]：params.id 是字符串，适合 /products/123 这类固定一段的路径。
  2. 多段捕获用 [...slug]：app/categories/[...slug]/page.tsx 访问 /categories/electronics/phones 时，params.slug 是数组 ['electronics', 'phones']。
  3. 可选尾段用 [[...slug]]：app/search/[[...query]]/page.tsx 同时匹配 /search 与 /search/react/hooks；没有尾段时 params.query 可能为 undefined，取值前先兜底。
  4. 查询串改从 searchParams 读取：页面组件同时接收 searchParams 对象，用 searchParams.utm_source 这类写法拿到来源、页码等附加信息。

到这里，「路径参数」和「查询参数」的分工就清楚了：决定资源身份的用 params，附加信息用 searchParams。两者类型也不同，前者按段数可能是字符串或数组，后者的值同样可能是字符串或数组，因此读取前应先规范化为单值再用。

接着解决「提前生成静态页」的需求。generateStaticParams() 可以在构建时返回一个参数列表，框架据此把动态路由预先渲染成一批静态页面：

在页面文件里导出 generateStaticParams()，它使用 async 返回形如 [{ id: '1' }, { id: '2' }] 的数组，构建时框架就会为这些 id 生成静态页。需要时还可以配合增量再生成，让新商品上架后自动补齐。

最后是一个版本差异，也是初学者最容易卡住的地方：在 Next.js 15 及以上，params 与 searchParams 都是 Promise，不能直接当作普通对象读取，而要先把页面组件声明为 async，再用 await 解包，例如 const { id } = await params。这个变化是为了让框架能更晚、更精准地决定何时去读取这些请求相关信息。

写法匹配示例取到的值
[id]/products/123params.id = '123'
[...slug]/categories/a/bparams.slug = ['a', 'b']
[[...query]]/search 或 /search/a/bparams.query 可能为 undefined
查询串?utm_source=xsearchParams.utm_source = 'x'
两个要注意的副作用：一是在 Server Component 中读取 searchParams，会让这条路由转为动态渲染（每次请求执行），因为它依赖每次请求都可能不同的查询串；二是 searchParams 的每个值都可能是字符串或数组，直接当字符串拼接容易出错，先判断类型再使用。

参数解析结果

路径参数与查询串

动态路由这一课，本质是把「一类页面」压进一条规则：方括号捕获单段（字符串）、三点号捕获多段（数组）、双层方括号做可选捕获，路径参数走 params、附加信息走 searchParams。generateStaticParams 负责把已知参数预先静态化，而 Next.js 15+ 中这两个参数都是 Promise，记得用 await 解包。

「动态路由」用文件名表达可变路径段：[id] 捕获单段、[...slug] 捕获多段（结果数组）、[[...slug]] 可选捕获。页面通过 params 读路径参数、通过 searchParams 读查询串，两者的值都可能是字符串或数组，使用前先规范化。generateStaticParams() 在构建期预生成动态路由的静态页；Next.js 15+ 中 params 与 searchParams 都是 Promise，需 await 解包。在 Server Component 中读取 searchParams 会使路由转为动态渲染。

关键代码

JSX
// app/products/[id]/page.tsx - 单段动态路由
// 访问 /products/123，params.id = '123'
export default function ProductPage({
  params,
  searchParams,
}: {
  params: { id: string }
  searchParams: { [key: string]: string | string[] | undefined }
}) {
  const productId = params.id
  const utmSource = searchParams.utm_source as string | undefined

  return (
    <div>
      <h1>商品 ID: {productId}</h1>
      {utmSource && <p>来源: {utmSource}</p>}
    </div>
  )
}

// ============================================

// app/categories/[...slug]/page.tsx - Catch-all 多段
// 访问 /categories/electronics/phones，params.slug = ['electronics', 'phones']
export default function CategoryPage({
  params,
}: {
  params: { slug: string[] }
}) {
  return (
    <div>
      <h1>分类路径</h1>
      <ol>
        {params.slug.map((seg, i) => (
          <li key={i}>{seg}</li>
        ))}
      </ol>
    </div>
  )
}

// ============================================

// app/search/[[...query]]/page.tsx - 可选 Catch-all
// 匹配 /search、/search/react、/search/react/hooks
export default function SearchPage({
  params,
}: {
  params: { query?: string[] }
}) {
  const query = params.query?.join(' ') || ''

  return (
    <div>
      <h1>搜索结果</h1>
      <p>关键词: {query || '（空）'}</p>
    </div>
  )
}

// ============================================

// app/products/[id]/generateStaticParams - 预生成静态页
// 构建时预先生成已知商品的静态页面
export async function generateStaticParams() {
  const products = await fetch('https://api.example.com/products').then(res => res.json())

  return products.map((product: { id: string }) => ({
    id: product.id,
  }))
}

// ============================================

// Next.js 15+ 中 params 和 searchParams 是 Promise
// 需要使用 async/await
// app/posts/[id]/page.tsx
export default async function PostPage({
  params,
}: {
  params: Promise<{ id: string }>
}) {
  const { id } = await params
  return <h1>文章 {id}</h1>
}
