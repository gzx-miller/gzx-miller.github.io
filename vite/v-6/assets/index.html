静态资源处理

理解导入哈希化、public 目录和 base64 内联三种资源处理方式。

开场问题：你写 <img :src="'./assets/' + name + '.png'"> 按名字动态切图，本地开发张张正常；构建上线后全部变成裂图——因为产物里的文件名已经变成了 logo.2d3a5b1c.png，而你的字符串还停在 logo.png。

资源路径解析

图片、字体、favicon 这些静态资源，在你的源码里是「文件」，交给浏览器时却必须变成「URL」。开发阶段 Vite 直接按源码路径把文件喂给浏览器，所见即所得；可生产构建之后，文件可能被复制到别的目录、被重命名、被压缩，甚至被整个内联进 JS。

于是同一份资源，在「源码里的路径」和「最终产物的 URL」之间裂开了一道鸿沟。如果资源全交给人工维护——手动拷进某个目录、手写最终路径——你必须替构建工具记住三件事：每个文件最后会叫什么名字、放在哪个目录、以文件还是内联的形式存在。任何一件记错，就是开头那样的 404。所以真正的问题是：当你只写了一句资源引用，究竟由谁来决定它最终的名字、位置和存在形式？

公共目录引用

最省事的做法：把所有图片、图标统统丢进 public/ 目录，代码里一律用绝对路径引用，比如 /logo.png。

这个方案做对了一件事：URL 完全稳定、完全由人掌控。你在源码里写什么地址，产物里就是什么地址，中间不经过任何加工，脑子里的路径和浏览器的路径永远一致。

旧图缓存未更新

  • 改图不生效：新版 logo.png 覆盖旧文件后文件名没变，浏览器和 CDN 仍命中旧缓存，用户看到的还是旧图。
  • 体积失控：几百 KB 的大图和 1KB 的小图标都得各发一次请求，想让小图标省掉请求也做不到。
  • 构建工具「看不见」它：public 里的文件不参与模块图，不会被压缩、内联或 Tree Shaking；文件名写错了构建期不报错，上线才 404。

内容哈希指纹

先补第一层：让构建工具接管资源。改用 import 导入，例如 import logo from './assets/logo.png'。导入之后资源被纳入模块图，Vite 会按文件内容生成哈希文件名（如 logo.2d3a5b1c.png）再输出，并把最终 URL 返回给你的变量。内容一变文件名就变，缓存天然被绕过；反过来内容不变文件名就不变，可以放心为产物设置长期强缓存。这是引用资源的第一选择。

接着补第二层：小资源内联。每次引用一个小图标都发一次请求，图标一多首屏就是几十次请求。于是 Vite 设了一个阈值 assetsInlineLimit（默认 4096 字节，即 4KB）：小于阈值的资源会被内联成 base64 data URL，直接嵌进 JS/CSS，省掉一次请求。但内联不是白捡的——base64 会让体积增大约 33%，而且没法单独缓存，所以大图不该走这条路。

再补第三层：给单个资源显式指定处理方式，覆盖默认阈值。在导入后缀上标注即可：

  1. ?url：强制返回 URL，即使小于阈值也不内联。
  2. ?inline：强制内联，即使大于阈值也内联。
  3. ?raw：不当作资源，直接作为字符串把文件内容读进来。
  4. ?worker：作为 Web Worker 导入。

最后一层是「分家住」，也是开头那个 404 的正解。public 不是被淘汰，而是有了明确分工：它只适合 favicon、robots.txt 这类「不常变更、不参与构建、必须待在根路径」的文件，原样复制到 dist 根目录，引用时必须写绝对路径 /favicon.ico；其余资源一律放 src/assets 走 import。此外，静态导入图片要有类型提示，需在 vite-env.d.ts 中声明资源模块类型（引入 vite/client 即可）。

两条容易踩的线：base64 内联会让体积涨约 33% 且无法独立缓存，大图务必让它走 URL 而不是内联；public 目录里的文件名写错了构建期不会报错，上线才 404，引用时必须写绝对路径且拼写完全一致。

三种引用对照

构建可见性优先

静态资源的取舍可以收成一句话：能被构建工具看见的（import）优先，看不见的（public）只留给必须放根路径的少数文件，小到不值得一次请求的（内联）才内联。哈希命名负责缓存，阈值负责请求数，分工清楚之后，路径 404 和「改图不生效」就都消失了。

「内容哈希」指 Vite 用文件内容算出的短哈希拼进产物文件名（如 logo.2d3a5b1c.png）。内容不变则哈希不变，内容一变哈希就变，因此可以安全地为产物设置长期强缓存。边界：哈希依赖资源被 import 走构建管线，public 目录里的文件原样复制、没有哈希，缓存策略要自己管。

TypeScript
// 1. 显式导入资源（推荐）
// 导入后 Vite 会处理哈希、压缩等优化
import logo from './assets/logo.png'
import styles from './assets/style.css'

console.log(logo) // /assets/logo.2d3a5b1c.png

// ====================
// 2. public 目录中的资源
// ====================

// public/favicon.ico 可以直接通过 /favicon.ico 访问
// public 目录的文件会原样复制到 dist 根目录
// 适合: favicon.ico, robots.txt, og-image.png

// 引用方式
const faviconUrl = '/favicon.ico'

// ====================
// 3. 内联为 base64（小资源）
// ====================

// 小于 assetsInlineLimit 阈值的资源会被内联
import tinyIcon from './assets/tiny-icon.svg'

// 默认阈值是 4kb
// 结果: data:image/svg+xml;base64,PHN2ZyB4bWxucz0i...

// ====================
// vite.config.ts 配置
// ====================

import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  build: {
    // 内联阈值（字节），默认 4096 (4kb)
    assetsInlineLimit: 4096,
    
    // 静态资源输出目录
    assetsDir: 'assets',
    
    // 资源命名规则
    rollupOptions: {
      output: {
        assetFileNames: 'assets/[name]-[hash][extname]',
        chunkFileNames: 'assets/[name]-[hash].js',
        entryFileNames: 'assets/[name]-[hash].js'
      }
    }
  }
})

// ====================
// 特殊导入语法
// ====================

// 显式获取 URL（即使大于阈值也不内联）
import bigImage from './assets/big.png?url'

// 显式内联（即使大于阈值也内联）
import forceInline from './assets/icon.png?inline'

// 作为原始字符串导入
import svgRaw from './assets/icon.svg?raw'

// 作为 Worker 导入
import Worker from './worker.js?worker'

// 作为 Web Worker URL 导入
import workerUrl from './worker.js?worker&url'
