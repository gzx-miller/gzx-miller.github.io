HMR 热更新

理解 Vite HMR 基于原生 ESM 的实现原理，以及 Vue/React 的框架集成。

开场问题：你在一个多步表单里填了半小时，最后只改了一行 CSS 的颜色，保存后整页刷新——所有输入、展开的折叠面板、滚到的位置，全部回到初始状态。

传统刷新根因

这个体验的根源是传统刷新：文件一改，整个页面重新加载，运行时的所有状态随之清零。你只是想看一个颜色的变化，却被迫重新走一遍操作路径。更隐蔽的代价在调试上——复现一个偶发问题时，你通常要点开三四层菜单、填一堆值，页面一刷新，这些前置动作全部白做。

能不能「只换掉改动的那个模块」，让页面其余部分和它的运行时状态原封不动？难点在于：一个模块被改动后，谁该被替换、谁必须保留、状态又该挂在哪里——没有一套边界规则，根本说不清替换的范围。

实时整页刷新

最省事的做法：文件保存后就让浏览器整页刷新（live reload）。新代码立刻可见，行为也完全可预期。

这个方案做对了一件事：它保证了「你看到的永远是改完后的代码」，不会出现新旧代码混用的假象。只要你不介意丢失状态，它就够用。

运行时状态清零

  • 运行时状态全丢：ref 里的值、表单输入、滚动位置、弹窗开关，全部回到初始值。
  • 层级越深的页面刷新越慢，一个改样式的动作要等整棵树重建完。
  • 它无法只重建某个组件——哪怕你只动了 CSS，整个应用也要重来一遍。
  • 调试偶发问题时，每次刷新都得重做一遍前置操作，效率极低。

模块替换粒度

不推翻「替换成新代码」，而是把替换的粒度从「整页」缩小到「模块」。Vite 的 HMR 建立在原生 ESM 的模块边界上：每个模块都是一条边界，文件改动后，服务器沿着 import 链向上寻找最近的「接受者」。

先补「谁来接受」。一个模块只要写下 globalThis._importMeta_.hot.accept()，就声明了自己可以被热替换；如果一路往上都找不到任何接受者，更新就会持续冒泡，最终退化成整页刷新。这是理解 HMR 的第一条规则：替换范围由接受者决定，而不是由文件决定。

再补「框架为什么开箱即用」。你写 Vue 时从没手动写过 accept，是因为 @vitejs/plugin-vue 已经为每个 SFC 注入了接受逻辑；React 侧则由 @vitejs/plugin-react 的 Fast Refresh 负责。框架插件替你标好了边界。

接着补「状态怎么跨更新存活」。新模块会生成新的导出，如果状态保存在模块级变量里，你需要用 globalThis._importMeta_.hot.dispose() 在替换前清理旧模块，再在 accept 回调里把新导出接到旧的引用上；更稳妥的做法是把状态放进 Pinia 这类独立 store，因为 store 不在被替换的模块里，自然不受影响。

最后补不同文件类型的行为差异。Vue SFC 里，改 <template> 或 <style> 通常不丢状态；而改 <script setup> 的逻辑时会重建组件实例，模块级状态会重置。

两个必记的坑：手动 HMR 代码一定要包在 if (globalThis._importMeta_.hot) 守卫里，因为生产构建中 globalThis._importMeta_.hot 是 undefined，不加守卫会直接报错；其次，accept 的回调里要主动应用新模块的导出，只写个空回调，界面不会随更新变化。

三类热更新差异

更新冒泡与回退

热更新的本质，是给「替换」划一条边界。模块用 accept 声明自己可以接受更新，更新就沿 import 链向上冒泡到最近的边界为止；找不到边界，才退化成整页刷新。想让状态活下来，就把它放到边界之外——比如 Pinia store。

「HMR 边界」指一个模块通过 globalThis._importMeta_.hot.accept 声明自己可被热替换（或可接受某个依赖的更新）后所形成的替换范围。边界：更新沿 import 链向上传播，遇到最近的边界即停止，没有边界就整页刷新；这套代码只在 if (globalThis._importMeta_.hot) 内有效，生产构建中该对象不存在。

关键代码

TypeScript
// HMR API 手动使用示例
// src/hmr-example.ts

export const state = { count: 0 }

export function increment() {
  state.count++
}

// 接受自身的热更新
if (import.meta.hot) {
  import.meta.hot.accept((newModule) => {
    // 模块更新时的回调
    console.log('模块已更新:', newModule)
    // 可以在这里做状态迁移
  })
}

// ====================
// 接受依赖模块的更新
// ====================

import { helper } from './helper'

export function useHelper() {
  return helper()
}

if (import.meta.hot) {
  // 接受 ./helper 的更新
  import.meta.hot.accept('./helper', (newHelper) => {
    console.log('helper 模块已更新')
    // 更新对 helper 的引用
  })
}

// ====================
// 自定义 HMR 边界处理
// ====================

// store.ts
export const store = {
  data: null
}

if (import.meta.hot) {
  import.meta.hot.accept(() => {
    // 热更新时保留状态
    // 或执行清理工作
  })
  
  // 热更新前的清理
  import.meta.hot.dispose(() => {
    console.log('模块即将被替换')
  })
}

// ====================
// Vue SFC 的 HMR（由 @vitejs/plugin-vue 自动处理）
// ====================

// Vite 会自动处理:
// - <template> 更新: 重新渲染组件，不丢失状态
// - <script setup> 更新: 销毁并重建组件，状态会丢失
// - <style> 更新: 即时更新，无需刷新

// 可以在组件中手动处理
if (import.meta.hot) {
  import.meta.hot.accept()
}
