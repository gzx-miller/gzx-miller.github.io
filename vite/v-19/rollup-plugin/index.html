Rollup 插件兼容与构建钩子

理解 Vite 与 Rollup 插件的兼容性，掌握 Vite 特有钩子和插件使用方式。

开场问题：你按文档装了 rollup-plugin-visualizer，想在开发时随时看看体积。结果本地跑了一下午，终端一条日志都没有，报告文件也没生成；直到你执行一次 vite build，报告立刻出现在 dist 里。同一份配置、同一个插件，为什么它在开发时「隐身」了？

生态插件复用

你要在产物上加一道处理——生成体积报告、压缩图片、产出清单——而社区里早就有人把它写成了 Rollup 插件。可 Vite 的开发服务器根本不是 Rollup 在跑：开发阶段它基于原生 ESM 按需转换，只有生产构建才切换到 Rollup。

如果为了同时支持两个阶段，就分别写两套插件，人要付出的隐藏成本是：逻辑重复维护两遍，两边的行为还容易悄悄跑偏；生态里现成的 Rollup 插件全都用不上，每个功能都从零写。于是问题落在：一套插件接口，怎么同时服务「开发服务器」和「生产构建」这两个形态完全不同的阶段？

插件接口兼容

最直接的做法：让 Vite 直接兼容 Rollup 的插件接口，Rollup 插件原样塞进 plugins 数组就能用。

这个方案做对了一件事：生态复用。Rollup 上已经成熟的插件不用重写，拿来即用；你不必学两套体系，只学一套就能同时理解两边的插件。

产物钩子缺位

  • 并不是所有钩子在两个阶段都会被调用。依赖「产物」的钩子——比如 generateBundle、writeBundle——只在构建时触发，开发时自然一声不响。这正是开场里插件「隐身」的原因。
  • 开发阶段 Vite 用 esbuild 做转换，与 Rollup 的 transform 路径并不完全等同，部分插件在 dev 下行为会和 build 不一致。
  • 一个只在构建才需要的重插件，如果无条件挂上，会把开发启动也一起拖慢。
  • 分不清哪些钩子属于 Vite、哪些属于 Rollup，就很容易把逻辑写在错误的阶段，调试时一头雾水。

两类钩子归属

先补「钩子分两类」。Vite 特有钩子服务于开发服务器与 HTML/HMR：config、configResolved、configureServer、transformIndexHtml、handleHotUpdate。Rollup 兼容钩子服务于模块与产物：resolveId、load、transform 在开发和构建都会跑；而 options、buildStart、generateBundle、writeBundle、closeBundle 这批「产物类」钩子只在构建时跑。记住这条分界，就能解释插件为什么会在某个阶段沉默。

接着补「用 apply 控制生效阶段」。插件对象可以声明 apply: 'serve' 只在开发生效，或 apply: 'build' 只在构建生效；也可以写成一个函数 apply(config, { command }) 返回布尔值，按条件决定挂不挂。这样，开场那个只在构建产出报告的插件，就该标上 apply: 'build'，开发它本就不该介入。

再补「执行顺序」。当多个插件都想改写同一段代码，谁先谁后就有讲究了。同一个插件数组里，标了 enforce: 'pre' 的排在最前，普通插件居中，标了 enforce: 'post' 的排在最后。理解这个顺序，转换才能按你预期一层层叠上去，而不是被别人的输出盖掉。

最后补「写一个两边都用的通用插件」。一个插件完全可以两种钩子都用：用 Vite 特有钩子做开发侧的事（比如 configureServer 挂个中间件），用 Rollup 钩子做构建侧的事（比如 transform 改代码、generateBundle 统计产物）。两边各司其职，互不干扰，一个插件就同时服务了两个阶段。

两条容易踩的线：产物类钩子只在构建触发，开发时别指望它们有反应；接入社区插件前先核对它支持的最低 Vite 版本、以及是否需要限定阶段，用 apply 或条件判断把「只在 build 用」的重插件挡在 dev 之外，避免拖慢开发。

筛选钩子分类

钩子体系构成

Vite 的插件系统就是「Rollup 插件 + Vite 扩展」：Rollup 钩子负责构建期的模块处理与产物生成，Vite 独有钩子负责开发服务器、HTML 与 HMR；再用 apply 与 enforce 把插件放到正确的阶段和顺序上。这样既能白拿整个 Rollup 生态，又不会让「只在构建用」的东西拖慢开发。

「插件钩子（plugin hook）」指插件对象上的一组约定方法，由 Rollup/Vite 在生命周期的特定时点回调，用来插入自定义逻辑；钩子分同步、异步、串行、并行等调用约定。边界：钩子的触发时机与所属阶段绑定——Rollup 兼容钩子在开发模式下并非全部执行（如 generateBundle 只在 build 触发），所以绝不能假设某个钩子在两种模式下都会跑。

关键代码

TypeScript
// vite.config.ts - Rollup 插件使用示例
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import { visualizer } from 'rollup-plugin-visualizer'
import image from '@rollup/plugin-image'

export default defineConfig({
  plugins: [
    vue(),
    // Rollup 插件可以直接在 Vite 中使用
    visualizer({
      filename: 'dist/stats.html'
    }),
    image()
  ]
})

// ====================
// Vite 特有钩子 vs Rollup 钩子
// ====================

// Vite 特有钩子（开发和构建都可能用到）:
// - config              修改 Vite 配置
// - configResolved      配置解析完成
// - configureServer     配置开发服务器
// - transformIndexHtml  转换 index.html
// - handleHotUpdate     处理 HMR 更新
// - configurePreviewServer  配置预览服务器
// - resolveId (开发时)  解析模块 ID
// - load (开发时)       加载模块
// - transform (开发时)  转换模块

// Rollup 兼容钩子（主要在构建时使用）:
// - options             构建选项
// - buildStart          构建开始
// - resolveId           解析模块 ID
// - load                加载模块
// - transform           转换代码
// - moduleParsed        模块解析完成
// - resolveDynamicImport  解析动态导入
// - buildEnd            构建结束
// - outputOptions       输出选项
// - renderStart         渲染开始
// - renderChunk         渲染 chunk
// - generateBundle      生成 bundle
// - writeBundle         写入 bundle
// - closeBundle         关闭 bundle

// ====================
// 插件应用阶段控制
// ====================

import type { Plugin } from 'vite'

function myPlugin(): Plugin {
  return {
    name: 'my-plugin',
    
    // 只在开发时生效
    apply: 'serve',
    // 或只在构建时生效
    // apply: 'build',
    // 或根据条件决定
    // apply(config, { command }) {
    //   return command === 'serve' && !config.build.ssr
    // },
    
    configureServer(server) {
      // 只有开发模式才会执行
    },
    
    generateBundle() {
      // 只有构建模式才会执行
    }
  }
}

// ====================
// 插件执行顺序
// ====================

// 1. Alias 插件
// 2. enforce: 'pre' 的用户插件
// 3. Vite 核心插件
// 4. 普通用户插件
// 5. Vite 构建插件
// 6. enforce: 'post' 的用户插件
// 7. Vite 后置构建插件（压缩、manifest 等）

// 示例:
// plugins: [
//   { name: 'pre-plugin', enforce: 'pre', ... },
//   { name: 'normal-plugin', ... },
//   { name: 'post-plugin', enforce: 'post', ... }
// ]

// ====================
// 条件应用 Rollup 插件
// ====================

export default defineConfig(({ command }) => {
  const plugins = [vue()]
  
  // 仅在构建时使用的 Rollup 插件
  if (command === 'build') {
    plugins.push(
      visualizer({
        filename: 'dist/stats.html'
      })
    )
  }
  
  return { plugins }
})

// ====================
// 编写兼容 Vite 和 Rollup 的插件
// ====================

import type { Plugin } from 'vite'

    // Rollup 兼容钩子（构建模式 + 开发模式转换）

      if (!id.endsWith('.custom')) return null

        code: transformCustomCode(code),

      }
    },
    
    // 仅构建时执行
    generateBundle(options, bundle) {
      // 构建产物生成时的逻辑
    }
  }
}

  // 转换逻辑
  return code
