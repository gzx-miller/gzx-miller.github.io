插件系统

理解 Vite 插件兼容 Rollup 插件接口，掌握常用插件的使用。

开场问题：你写了个插件想给源码里的某个函数名做替换，注册进 plugins 数组后毫无反应；同事几乎一样的插件却生效了。把两份配置一对比，唯一的差别是注册的先后位置。

日常重复自动化

日常开发里重复劳动很多：每写一个组件都要手写一行 import；ref、computed 每次都得从 vue 里引；想让某个功能只在开发阶段生效，又得手动增删代码。你希望把这些重复动作交给工具自动完成，同时保留「按阶段启用」的能力。

但真正的难点不在「怎么挂上插件」，而在「谁先谁后」。Vite 内部本身就有一批核心插件，负责编译 Vue、处理样式与资源。如果你的插件想在它们之前读到原始源码、或在它们之后修改产物，靠数组里的位置去排是很脆弱的：以后加一个插件，顺序就变了。所以问题是：插件的执行顺序，能不能被显式声明？

插件数组声明

最直接的做法：往配置的 plugins 数组里塞插件即可。例如 plugins: [vue()] 就能让 .vue 文件被正确编译；需要 JSX 就再加一个 vueJsx()。

这个方案做对了一件事：它把「扩展 Vite」统一成了「往一个数组里加东西」，不需要改 Vite 源码，插件的组合因此是可插拔的。

注册位置敏感

  • 顺序敏感：把转换插件写在 vue() 后面，拿到的可能已经是 SFC 编译后的代码，结果和预期不符。
  • 想「跑在核心插件之前」只能靠数组位置表达，加一个插件就可能把顺序撞乱。
  • 自动按需引入会生成 auto-imports.d.ts / components.d.ts，没加进 tsconfig 的 include，编辑器会报「变量未定义」。
  • 插件一旦抛错会中断整个 dev server，报错里往往只有插件名，定位只能靠猜。

三段执行排序

先解决顺序。Vite 借用了 Rollup 的插件接口，并加了几个特有钩子；同时每个插件可以声明 enforce 字段。于是插件被分成三段排序：enforce: 'pre' 的排在 Vite 核心插件之前，未声明的普通插件排在核心插件之后，enforce: 'post' 的排在所有这些之后。你的转换插件该站哪一段，用 enforce 一句话声明，不再依赖数组下标。

  1. pre 阶段：在所有核心插件之前执行，适合最早接触原始源码。
  2. 核心阶段：Vite 内置插件，负责编译 Vue、处理样式与资源。
  3. 普通阶段：未声明 enforce 的插件，在核心插件之后运行。
  4. post 阶段：最后由 enforce: 'post' 的插件收尾。

再解决「按阶段启用」。既然配置能写成函数，就能按 command 判断：command === 'serve' 时只 push 开发插件，command === 'build' 时只 push 构建插件，启用与否变成了普通的分支逻辑。

最后一块拼图是「为什么插件能通用」。Vite 插件兼容 Rollup 的插件接口——transform、resolveId 这些钩子含义一致，所以一个 Rollup 插件稍作调整就能用在 Vite 上。社区里大量插件用 vite-plugin- 或 unplugin- 前缀分发，后者还能同时适配多个打包器；自动按需引入组件与 API 的 unplugin-vue-components、unplugin-auto-import 就是这类。

记得补类型文件：自动引入生成的 dts 声明文件要加进 tsconfig.json 的 include，否则编辑器不认识自动引入的变量。插件执行出错会中断 dev server，报错信息里的插件名就是最快的定位线索。

清单与数组对照

钩子顺序与接口

插件机制把「扩展 Vite」变成了往 plugins 数组里加东西，而顺序这个最容易出错的部分，被 enforce 显式化成了 pre / 普通 / post 三段。又因为接口与 Rollup 兼容，你写一次的转换逻辑，往往能跨越打包器复用。

「enforce」是插件上的一个字段，用来声明执行阶段：enforce: 'pre' 排在 Vite 核心插件之前，enforce: 'post' 排在所有插件之后，不声明则位于核心插件之后。边界：它只调整「同一阶段内」的相对顺序，不能越过阶段；它本身也不启用或禁用插件，只负责排序。

TypeScript
// vite.config.ts - 常用插件配置
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'

export default defineConfig({
  plugins: [
    // Vue 单文件组件支持
    vue(),
    
    // Vue JSX 支持
    vueJsx(),
    
    // 自动导入 API（ref, computed 等）
    AutoImport({
      imports: ['vue', 'vue-router', 'pinia'],
      dts: 'src/auto-imports.d.ts'
    }),
    
    // 自动导入组件
    Components({
      resolvers: [ElementPlusResolver()],
      dts: 'src/components.d.ts'
    })
  ]
})

// ====================
// 插件执行顺序
// ====================

import { defineConfig } from 'vite'

export default defineConfig({
  plugins: [
    // enforce: 'pre' - 在 Vite 核心插件之前执行
    {
      name: 'pre-plugin',
      enforce: 'pre',
      transform(code, id) {
        // 最早执行的转换
        return code
      }
    },
    
    // 普通插件 - 在 Vite 核心插件之后执行
    {
      name: 'normal-plugin',
      transform(code, id) {
        return code
      }
    },
    
    // enforce: 'post' - 在所有其他插件之后执行
    {
      name: 'post-plugin',
      enforce: 'post',
      transform(code, id) {
        // 最后执行的转换
        return code
      }
    }
  ]
})

// ====================
// 条件应用插件
// ====================

export default defineConfig(({ command }) => {
  const plugins = [vue()]
  
  // 仅在开发模式生效
  if (command === 'serve') {
    plugins.push(devOnlyPlugin())
  }
  
  // 仅在构建模式生效
  if (command === 'build') {
    plugins.push(buildOnlyPlugin())
  }
  
  return { plugins }
})
