Vite 核心概念

理解 Vite 的两个阶段：开发服务器（原生 ESM）和生产构建（Rollup）。

开场问题：新同事克隆完仓库敲下 npm run dev，两秒不到页面就开了；你随后敲 npm run build，进度条却跑了半分钟才结束——同一个工具，为什么启动快得离谱、打包又慢得像在干活？

全量依赖重构建

你接手一个已经很大的前端项目，光源码目录就有几千个模块。用传统打包器时，每次改一行代码都要先把整张依赖图重新打成一个 bundle，冷启动按秒计，改得越多等得越久。真正折磨人的不是第一次启动，而是它把「打包」这件事排在了你写代码之前：你只是想看一个按钮的颜色，却要为整个项目的打包时间买单。

更麻烦的是，这些成本都得由人扛：依赖图越大启动越慢、改一行触发全量重编译、日常开发的时间被机器吃掉。根子在于传统工具只把源码当成「构建的输入」——它预设了必须先打包，浏览器才能运行。可浏览器真的需要你替它打包吗？能不能让浏览器自己按需取用源码？

原生ESM按需加载

顺着这个问句往下想，最朴素的做法是：干脆不打包，把源码原样交给浏览器。现代浏览器早就原生支持 ES 模块，你在文件里写 import，它自己就会去请求那个模块。于是启动时服务器不做任何编译，模块按需加载，用到哪个才请求哪个。

这个方案做对了一件事：放开了「先打包再运行」这个并不必要的前置依赖。冷启动因此不再随项目规模增长，改一个文件也只需要重新处理那一个文件。

裸模块名解析

  • 浏览器不认识「裸模块名」：你在源码里写 import { ref } from 'vue'，浏览器不知道 vue 该去哪里找，直接抛 Failed to resolve module specifier。
  • 浏览器不认识 .vue 和 .ts：这些不是它能执行的文件类型，原样返回只会得到语法错误。
  • 依赖包动辄包含成百上千个小文件，逐个发请求会把网络压垮，开发服务器自己也可能被请求风暴拖死。
  • 生产环境不能沿用这套：让每个用户按需拉几百个请求，首屏体验会很差。

依赖预构建编译

不推翻「源码直接交给浏览器」，而是按顺序补掉它跑不通的地方。第一个要解决的是「裸模块名找不到」，因为那是页面上第一个报错。Vite 启动时会用 esbuild 把依赖预先处理一遍，并把源码里的 import 'vue' 改写成指向 /node_modules/.vite/deps/vue.js 的真实路径——这一步就是依赖预构建，只在依赖或锁文件变化时重做一次。

第二个要解决的是「浏览器不认识 .vue / .ts」。既然浏览器只认 JS，服务器就在这个请求上即时编译：请求 /src/App.vue，Vite 当场把它编译成 JS 模块再返回。只编译被请求到的那一个模块，而不是整个项目，这才是冷启动快的原因。

  1. 浏览器发起 <script type="module">，向开发服务器请求入口模块。
  2. Vite 拦截请求，遇到裸模块名就改写为预构建后的依赖路径。
  3. 遇到 .vue / .ts 等非 JS 文件，按需即时编译成 ESM 返回。
  4. 浏览器解析到这个模块的 import，再发起下一批请求，如此逐层展开。

但开发阶段跑通了，生产阶段却不能照搬。生产环境里用户隔着网络，几百个模块请求是灾难，而且没有 Tree Shaking、没有压缩、也没有代码分割。于是 Vite 在构建阶段切换成另一个引擎：用 Rollup 把整个依赖图打好包，做 Tree Shaking 剔除死代码、做代码分割、做压缩，输出到 dist/。

到这里整个工具的形状才清晰：Vite 不是一个打包器，而是开发与生产两套引擎挂在同一份配置上。开发用原生 ESM 加按需编译换速度，生产用 Rollup 换体积与兼容性。你写的那份 vite.config.ts，同时驱动这两条链路。

常见误区：说「Vite 开发时完全不打包」并不准确——依赖会被预构建，只是你的源码不打包。预构建是一次性成本，冷启动不受项目规模影响，代价是首次启动多一次依赖预构建。
部署前先验证：npm run build 之后用 vite preview 以生产行为跑一遍 dist/。开发服务器和生产产物的行为可能不同，别等到上线才发现。

双引擎差异对照

开发生产双链路

Vite 快，不是因为把打包做得更快，而是因为开发阶段根本不需要打包。它把工程拆成两条链路：开发用浏览器原生 ESM 按需加载源码、就地即时编译，生产才切回 Rollup 做完整的优化打包。理解了这个「双引擎」结构，后面的配置、插件、HMR 都只是往这两条链路上加东西。

「依赖预构建」指 Vite 在开发启动时用 esbuild 把 node_modules 里的依赖预先打成少量 ESM 包，并改写源码中的裸模块名指向它们，结果缓存在 node_modules/.vite。边界：它只处理依赖，你的源码不参与；依赖或锁文件变化时会自动重做，否则直接复用缓存。

// Vite 开发服务器启动示例
import { createServer } from 'vite'

async function startDevServer() {
  // 创建 Vite 开发服务器
  const server = await createServer({
    root: process.cwd(),
    server: {
      port: 5173,
      open: true
    }
  })
  
  // 启动服务器
  await server.listen()
  
  // 打印服务器地址
  server.printUrls()
}

import { build } from 'vite'

async function buildForProduction() {
  // 基于 Rollup 的生产构建
  const result = await build({
    root: process.cwd(),
    build: {
      outDir: 'dist',
      sourcemap: true
    }
  })
  
  console.log('构建完成:', result)
}
