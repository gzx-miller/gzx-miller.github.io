Vite 配置文件

使用 defineConfig 获得类型提示，掌握基础配置与常用选项。

开场问题：本地调试想要 sourcemap 和固定端口，线上却必须关掉 sourcemap、换个压缩器。每次发版前你都手动翻配置文件改这几行，直到有一次忘了关 sourcemap，把整份源码映射连同 .map 一起传上了 CDN。

多环境分支配置

这类需求看起来很小：开发时想要热更新友好、能定位到源码；生产时想要体积小、不暴露内部结构。可它们全落在同一个文件里——vite.config.ts。配置项少时你还能靠记忆改；一旦有了 server、build、resolve、css 几十个字段，「不同环境要不同设置」就变成了一场手工切换。

手工切换的成本是隐性的：改配置容易漏掉某个字段；维护两份配置文件又得在命令里加 --config 切换，很容易跑错；把环境判断散写成一堆三元表达式，读起来也不知道哪段属于哪个环境。说到底，问题是：能不能用一份配置，按当前环境自动给出不同的结果？

配置对象导出

最直接的做法：在项目根目录建一个 vite.config.ts，导出一个普通对象，把 server、build、resolve.alias、plugins 一次写清楚。

这个方案做对了一件事：它把散落在命令行参数里的配置收拢到了一个入口。Vite 启动时会自动找到它，不需要你额外指定路径。配置项有了统一的归属，这是后面一切的前提。

静态取值局限

  • 静态对象没法按环境分支：build.sourcemap 只能写死成 true 或 false，开发想要、生产不想要的需求直接卡住。
  • 写成 sourcemap: process.env.NODE_ENV !== 'production' 这类表达式，会散落到每个字段上，字段一多就没人看得懂。
  • 手写对象没有类型约束，把 outDir 拼成 outdir，Vite 不报错，只会在构建时默默用了默认值。
  • 想「构建分析时才加可视化插件」，静态对象里根本没有地方放这段条件逻辑。

类型推导与分支

先解决「配置要有类型」。用 Vite 导出的 defineConfig 把对象包起来，返回值会获得完整的类型推导，字段拼错时编辑器当场标红，而不是等到构建才发现被静默忽略。

接着解决「按环境分支」。把导出的值从对象换成一个函数，函数接收 { command, mode }：command 区分是 serve（开发）还是 build（构建），mode 区分当前模式（如 development / production）。在函数体内判断这两个值，返回不同的配置。它返回的对象会与 Vite 的默认配置深度合并——这点很关键，你不必把默认值抄一遍，只写差异部分。

  1. 写静态对象，先把通用配置摆好。
  2. 套上 defineConfig，拿到类型提示。
  3. 把对象改成 ({ command, mode }) => {...} 形式的函数，函数内按环境返回分支配置。
  4. 返回值与默认配置深度合并，只有你写到的字段会被覆盖。

再解决「条件追加插件」。既然已经是函数，就能在里面写普通 JS：if (process.env.ANALYZE) plugins.push(visualizer())，只在需要分析包体积时才把可视化插件挂上去。环境差异写进函数、敏感值交给环境变量，配置文件里不该出现密钥或绝对路径。

常见误区：配置字段拼写错误不会报错，会被静默忽略。改完配置后用 vite --debug 查看最终解析结果，确认字段真的生效了。
两个高频字段：resolve.alias 用来配 @ 之类的路径别名；css.preprocessorOptions 可以往每个 SCSS 文件里注入全局变量或 @use。函数式配置返回空对象也不会丢默认行为，因为深度合并只在「你写了的字段」上覆盖。

基础进阶对照

函数式配置返回

配置文件是 Vite 的项目级入口，真正让它灵活的转折，是从「导出一个对象」变成「导出一个函数」。函数接收 { command, mode }，按环境返回不同配置，返回值再由 Vite 与默认配置深度合并。于是开发与生产的分歧集中在一个地方表达，不再散落成一堆没人看得懂的三元表达式。

「函数式配置」指 defineConfig 接收一个 ({ command, mode }) => UserConfig 形式的函数，Vite 在启动时执行它并深度合并返回值。边界：函数在每次启动（dev 或 build）时执行一次，只有返回值里写到的字段才会覆盖默认值；返回空对象是合法的，不会清空默认配置。

TypeScript
// vite.config.ts - 基础配置示例
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import path from 'node:path'

// 使用 defineConfig 获得完整类型提示
export default defineConfig({
  // 项目根目录
  root: process.cwd(),
  
  // 开发服务器配置
  server: {
    port: 5173,
    host: true,
    open: true,
    cors: true
  },
  
  // 构建配置
  build: {
    outDir: 'dist',
    sourcemap: false,
    minify: 'esbuild',
    target: 'es2015'
  },
  
  // 路径别名
  resolve: {
    alias: {
      '@': path.resolve(__dirname, './src'),
      '@components': path.resolve(__dirname, './src/components')
    }
  },
  
  // 插件
  plugins: [vue()]
})

// ====================
// 环境相关配置（函数式）
// ====================

export default defineConfig(({ mode, command }) => {
  // 根据模式返回不同配置
  const isProd = mode === 'production'
  const isBuild = command === 'build'
  
  return {
    plugins: [vue()],
    build: {
      sourcemap: !isProd,
      minify: isProd ? 'terser' : false
    },
    define: {
      __APP_VERSION__: JSON.stringify('1.0.0')
    }
  }
})

// ====================
// 条件加载插件
// ====================

import { visualizer } from 'rollup-plugin-visualizer'

export default defineConfig(({ mode }) => {
  const plugins = [vue()]
  
  // 仅在构建分析时添加可视化插件
  if (process.env.ANALYZE) {
    plugins.push(
      visualizer({
        filename: 'dist/stats.html',
        open: true
      })
    )
  }
  
  return { plugins }
})
