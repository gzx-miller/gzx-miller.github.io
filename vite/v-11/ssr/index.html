服务端渲染（SSR）

理解 Vite SSR 工作原理，以及 Nuxt 3/4 如何基于 Vite 实现 SSR。

开场问题：你给商城首页做足了 SEO，可在搜索引擎的抓取结果里，页面正文是空的；右键「查看网页源代码」，只看到一行 <div id="app"></div>——内容明明在浏览器里显示得好好的，为什么源码里什么都没有？

客户端渲染空壳

页面之所以能看见，是因为浏览器先下载到一段几乎空白的 HTML，再下载 JavaScript，由 Vue 在浏览器里把组件渲染成真实 DOM 挂上去。也就是说，用户看到的「页面」，是 JS 跑完之后才存在的。这一路上有两个代价：搜索引擎爬虫拿到的初始 HTML 里没有正文，收录不到内容；弱网或低端设备上，JS 下载与执行完成之前，用户面对的是一段白屏。

让「内容在 JS 到达之前就存在」，本质上是问：能不能让第一份 HTML 里就带着渲染好的结果？旧办法要人承担的隐藏成本有三个：把内容写成静态模板，就丧失了组件化与数据驱动；改由后端拼字符串，又等于把 Vue 的逻辑重写一遍；什么都不做，就是把首屏和 SEO 交了出去。于是问题落到一句：能不能在服务端把 Vue 组件渲染成 HTML，再让浏览器接管？

服务端直出HTML

最朴素的做法：在服务端调用 renderToString()，把组件渲染成一段完整的 HTML 字符串，直接返回给浏览器。

这个方案做对了一件事：第一份 HTML 里就带着真实内容。爬虫能读到正文，用户也能在 JS 到达之前先看到页面，白屏时间被大幅压缩。但此时这份 HTML 是「死」的——它只是字面文本，没有任何交互能力。

静态标记无交互

  • 服务端吐出的 HTML 上点按钮毫无反应——事件监听根本没绑上去，它只是一段静态文本。
  • 服务端没有 window、document，组件里若在渲染期就访问浏览器 API，服务端直接抛错。
  • onMounted 在服务端不会执行，把首屏数据请求写在这里，服务端渲染出来仍是空数据。
  • 服务端与客户端如果渲染出了不一样的结果，浏览器接管时会报 Hydration 不匹配警告，甚至回退成整段重渲染。

激活与接管流程

先补「让死 HTML 活过来」。客户端不能再 createApp 从零渲染，而要改用 createSSRApp：它会复用服务端已经生成的那份 HTML，把事件监听与响应式重新挂上去——这一步叫 Hydration（激活）。渲染用的还是同一套组件代码，服务端负责「画出来」，客户端负责「连上线」。

再补「开发期怎么在同一进程里转换服务端代码」。如果服务端也走一遍完整构建，改一行就要等构建，开发体验直接崩。Vite 的解法是中间件模式：用 createServer({ server: { middlewareMode: true } }) 启动开发服务器，把它挂到 Express 这类 Node 服务上。这样请求进来时，可以直接调用 ssrLoadModule('/src/entry-server.ts')，让 Vite 就地把源码转好再用，不必预先打包。

  1. 服务端读取 HTML 模板，经 transformIndexHtml 处理，得到带占位符的页面骨架。
  2. 用 ssrLoadModule 加载服务端入口，调用其中的渲染函数，得到组件渲染出的 HTML。
  3. 把组件 HTML 替换进模板的占位符，返回完整页面给浏览器。
  4. 浏览器下载客户端脚本，由客户端入口 createSSRApp 后 mount，完成 Hydration。

接着补「依赖怎么处理」。服务端代码跑在 Node 里，有些依赖不能被建进 SSR 产物，有些又必须被建进去，于是 ssr.external 与 ssr.noExternal 各管一头：前者让依赖保持外部引用、运行时从 node_modules 加载，后者强制把依赖打进服务端产物——只发 ESM、或需要被转换的库往往必须这样做。

最后是「产出与部署」。SSR 应用有两份产物：一份给服务端（渲染用），一份给客户端（Hydration 用），要分别构建后一起部署到一个能跑 Node 的服务器上。这也正是它与纯静态站最大的区别——目标环境必须有 Node。顺带一提，本仓库（小松鼠举栗子）本身就是 Nuxt 4 + Vite 的 SSR 应用，Nuxt 就是把上面这一整套流程封装成了开箱即用。

两条最容易踩的线：依赖浏览器 API 的代码要放进 onMounted 或 <ClientOnly> 里，避免服务端执行时找不到 window；首屏数据的请求要写在支持 SSR 的加载函数中，因为 onMounted 在服务端根本不会执行，写在那里等于服务端渲染的是空数据。

最小SSR服务器

同构渲染两端

服务端渲染拆开就是两步：服务端用 renderToString 把组件画成 HTML，客户端用 createSSRApp 把这份 HTML 接管成活的应用。前者换来首屏与 SEO，后者换来交互。它不是一个新框架，而是「同一套组件、两个渲染环境」这个约束下的必然产物——也正因为有两个环境，服务端与客户端首次渲染必须一致，浏览器 API 与首屏数据都要放在对的位置。

「Hydration（激活）」指客户端拿到服务端渲染出的静态 HTML 后，不从头渲染，而是复用这份已有的 DOM 结构，把事件监听与响应式状态重新挂上去，使其变成可交互的应用。它的前提是服务端与客户端首次渲染结果完全一致，哪怕多一个空格都会触发不匹配警告；边界：Hydration 只接管、不重建，所以依赖随机数、时间戳、浏览器 API 的差异渲染，是它最常见的失败来源。

// server.js - Vite SSR 基础服务端
import express from 'express'
import { createServer as createViteServer } from 'vite'

async function createServer() {
  const app = express()
  
  // 创建 Vite 开发服务器（中间件模式）
  const vite = await createViteServer({
    server: { middlewareMode: true },
    appType: 'custom'
  })
  
  // 使用 Vite 中间件
  app.use(vite.middlewares)
  
  // 处理所有请求
  app.use('*', async (req, res) => {
    try {
      const url = req.originalUrl
      
      // 1. 读取 HTML 模板
      let template = await vite.transformIndexHtml(url, '')
      
      // 2. 加载服务端入口
      const { render } = await vite.ssrLoadModule('/src/entry-server.ts')
      
      // 3. 渲染应用 HTML
      const appHtml = await render(url)
      
      // 4. 注入应用 HTML 到模板
      const html = template.replace('<!--app-html-->', appHtml)
      
      // 5. 返回 HTML
      res.status(200).set({ 'Content-Type': 'text/html' }).end(html)
    } catch (e) {
      // 显示错误
      vite.ssrFixStacktrace(e)
      console.error(e)
      res.status(500).end(e.message)
    }
  })
  
  app.listen(3000)
}

// ====================
// 服务端入口 (src/entry-server.ts)
// ====================

import { createSSRApp } from 'vue'
import { renderToString } from 'vue/server-renderer'
import App from './App.vue'
import { createRouter } from './router'

export async function render(url: string) {
  const app = createSSRApp(App)
  const router = createRouter()
  
  // 设置路由
  router.push(url)
  await router.isReady()
  
  // 渲染为 HTML 字符串
  const html = await renderToString(app)
  
  return html
}

// 客户端入口 (src/entry-client.ts)
// ====================

import { createSSRApp } from 'vue'
import App from './App.vue'
import { createRouter } from './router'

const app = createSSRApp(App)
const router = createRouter()

// Hydration（激活）
router.isReady().then(() => {
  app.mount('#app')
})
