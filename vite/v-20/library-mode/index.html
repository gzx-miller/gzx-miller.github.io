库模式与组件打包发布

使用 Vite 库模式打包组件库或工具库，支持多格式输出和发布到 npm。

开场问题：你的组件库发到了 npm，同事只想用其中的一个 Button。他写下 import { Button } from '@my-org/ui-lib/button'，Vite 当场报 Failed to resolve entry for package——button 明明就在包里，为什么这个子路径解析不了？

按需引入子路径

你已经知道库要一次输出多种格式、把 vue 外部化。可一个库长大后会被拆成很多块，使用者往往只想按需引其中一小片；而安装到别人机器上时，构建工具手里只有一个包名，它得靠 package.json 的字段决定「这个路径该去取哪个文件」。

如果只产出「整包一个入口」，人要付出的隐藏成本是：使用者没法按子路径引，只能整包引入再指望 Tree Shaking 兜底，包一大就救不回来；多种格式的文件名和入口字段对不上，使用方一装就报「找不到模块」；框架依赖没声明清楚，使用方可能重复安装甚至整出多实例；发布时没配清单，源码、测试、配置一起被推上 npm。于是问题落在：怎么让一个包的产物能被「按入口、按格式、按依赖关系」正确地引用？

单入口输出局限

最直接的做法：用 build.lib 配一个入口、几样格式，把 dist 发出去。

这个方案做对了一件事：库变成了一个可以被安装的包，整包 import 这一条路是通的。

子路径解析失败

  • 子路径不可达：包里只有整包入口，@my-org/ui-lib/button 这类路径找不到任何文件，于是报 Failed to resolve entry。
  • 条件导出缺失：exports 没写，Node 与现代打包器只能回退到 main / module，取到的格式可能和当前运行环境对不上。
  • external 只做了一半：它让 vue 不进产物，可使用方要是根本没装 vue（或装了个错版本），运行时还是一样找不到。
  • 发布清单失控：没配 files，src、测试、配置文件全被打进包里，体积和暴露面都白白变大。

对象式入口映射

先补「多入口」。build.lib.entry 除了传字符串，还可以传一个对象，键名就是入口名、也就是子路径名——比如 index 指向主入口、button 指向 Button 的入口文件。再配一个 fileName(format, entryName)，让每个入口按各自格式产出自己的文件（如 button.mjs / button.cjs）。这样 ./button 这条子路径就有实体文件可指了。

接着补「条件导出把入口和子路径串起来」。package.json 的 exports 用条件映射，把每条路径对应到正确的文件："." 同时给出 import / require / types，"./button" 指向对应的 .mjs 与 .cjs，"./style.css" 指向样式文件。这里有个顺序要求：types 条件要写在前面，否则 TypeScript 解析不到类型。

再补「external 与 peerDependencies 是一对」。external 让框架依赖不进产物，避免多实例；peerDependencies 声明它「由使用方提供、版本范围是这些」——两者必须配套：只 external 不声明，使用方可能不知道要装；只声明不 external，包又会自带一份。UMD 场景还要在 output.globals 里把模块名映射成全局变量名。

再补「CSS 与类型声明也是产物」。库的 CSS 会单独产出一个文件，可以用 assetFileNames 把它重命名成 index.css 并把路径写进文档；类型声明 Rollup 不会自动生成，要用 vite-plugin-dts 产出 .d.ts，并让 exports 的 types 指过去。为什么强调这两样？因为使用者看不到你的源码，只能靠「入口文件 + 类型 + CSS 路径」这三张路标找到路。

最后补「发布前用 npm pack 验收」。它会打出 tar 包但不真正发布，正好用来先看一眼究竟会发出去哪些文件；再用 files: ["dist"] 把范围收干净；把构建、类型检查、打包串进 prepublishOnly 钩子，避免把一个没构建或类型有错的版本推上去。

两条必守的线：external 管「不打包」，peerDependencies 管「由谁提供」，缺一个都会出问题；exports 的 types 条件要放在 import / require 之前，而且没有在 exports 里登记的子路径，使用者根本 import 不进来。

条件导出映射

发布一个库的难点不在写代码，而在把「产物如何被引用」交代清楚：多入口让子路径可达，exports 把每条路径与条件映射到正确文件，external 加 peerDependencies 把框架依赖交还给使用方，files 与 prepublishOnly 保证发出去的是一份构建过、清单干净、带类型的产物。库不是应用，它的产物要服务于你见不到的使用者。

「条件导出（conditional exports）」指 package.json 的 exports 字段用 import / require / types 等条件，为同一条模块路径指定不同文件，让 ESM 与 CJS 环境各取所需。边界：条件的匹配是从上到下、先命中先返回，所以 types 必须写在 import / require 之前；一旦声明了 exports，未列入其中的路径将不再可达，任何子路径都必须显式登记。

// vite.config.ts - 完整库模式配置
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import dts from 'vite-plugin-dts'
import { resolve } from 'node:path'

export default defineConfig({
  plugins: [
    vue(),
    // 自动生成类型声明
    dts({
      outDir: 'dist/types',
      insertTypesEntry: true,
      include: ['src/**/*.ts', 'src/**/*.vue']
    })
  ],
  
  build: {
    lib: {
      // 入口文件（可以是字符串或对象）
      entry: {
        index: resolve(__dirname, 'src/index.ts'),
        button: resolve(__dirname, 'src/components/Button/index.ts')
      },
      
      // UMD 全局变量名
      name: 'MyUILib',
      
      // 输出格式: 'es' | 'cjs' | 'umd' | 'iife'
      formats: ['es', 'cjs', 'umd'],
      
      // 输出文件名
      fileName: (format, entryName) => {
        if (format === 'es') return `${entryName}.mjs`
        if (format === 'cjs') return `${entryName}.cjs`
        return `${entryName}.${format}.js`
      }
    },
    
    rollupOptions: {
      // 外部化 peer dependencies
      external: ['vue', 'vue-router', 'pinia'],
      
      output: {
        // UMD 模式下的全局变量映射
        globals: {
          vue: 'Vue',
          'vue-router': 'VueRouter',
          pinia: 'Pinia'
        },
        
        // CSS 输出配置
        assetFileNames: (assetInfo) => {
          if (assetInfo.name === 'style.css') return 'index.css'
          return assetInfo.name || 'assets/[name][extname]'
        }
      }
    },
    
    // 库模式下默认不压缩 CSS
    cssCodeSplit: true,
    
    // 源码映射（便于调试）
    sourcemap: true
  }
})
