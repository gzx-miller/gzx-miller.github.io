语言概率游戏与N-gram

N-gram 只看最近 N 个词、数共现频率查表来估计「下一个词」的条件概率，不懂语法语义；但记性短、把词当孤立符号，且词组合呈稀疏灾难。

开场问题：不懂语法、不懂语义，光靠「数数」能不能接出下一个词？

仅靠数数猜下一词

用手机打字输入「今天天气」，键盘弹出「真好」「不错」「怎么样」几个候选。手机怎么猜的？它没有读懂「天气」、没联网查天气预报，做的事极其简单：翻历史记录、数数。它读过几千万条消息，数过每次「今天天气」后面跟着什么——真好 4120 次、不错 3890 次、怎么样 2540 次……按频率排序，就能给出候选。这是手机输入法的基本原理，纯粹的数数、和「理解语言」毫无关系。

只统计邻近词频率

em>prompt the method more通用：不管前面说了多少，只看最近的 N 个词来预测下一个。看 1 个词叫一元模型、2 个叫二元模型、看 N 个词就叫 N-gram。训练很简单：爬下大量文本，把每段连续的 N 个词都数一遍、统计频率、存成一张巨大的表格即可——不需要理解语言、不需要语法规则，只需要数数。

它查的其实是一张频率表

这张表怎么查？以二元模型（N=2）为例，想预测「天气」后面接什么，就翻到「前文 = 天气」那一块，数它后面各词出现次数，再除以「天气」的总出现次数（如 10000），就得到每个候选的概率：真好 23.0%、不错 21.0%、预报 18.0%……而「香蕉」只共现 3 次、概率几乎为零——语料里没数到的组合，N-gram 只能给接近 0 的概率。换个角度看，这就是条件概率：给定前面 N 个词、下一个词出现的可能性。语言模型的本质就是给「下一个词」分配一张概率分布表，N-gram 是这个想法最朴素的实现：能数则数、数不到就抓瞎。

记性太短漏生僻组合

  • 记性只有 N 个词：用 N=2 补「那只从小在胡同里长大、非常怕生人的小猫，今天第一次 ___」，模型只看最后两个词「第一次 ___」，完全不知道前面在讲一只猫。
  • 加大 N 也救不了：把 N 调到 5 看「怕生人的小猫，今天第一次」，可训练数据里见过这个完整组合的概率几乎为零。N 越大，每个具体组合出现次数越少、没见过的组合越多——练成了一个两难困境。
  • 把词当符号：即便见过「猫 → 出门」，也没法推断「小猫 → 出门」——「猫」和「小猫」是两个毫不相关的字符串，统计帮不了彼此。

迭代收束阶段

尽管有这些局限，N-gram 几十年间一直是语言技术的支柱：手机输入法候选词、早期语音识别（用它过滤「听起来像但文法奇怪」的结果）、垃圾邮件过滤、机器翻译的初级版。它有用，是因为语言里大量短距离搭配非常固定——「天气」后面接「预报」的概率远高于接「香蕉」，这些规律数数就能捕捉到。但它也做不到长句子、跨句理解、词义灵活性——这些需要一个能「理解词义」而不是「认识词的形状」的工具，这正是下一课要解决的「词」本身的问题。

数数法便宜缺长距离

N-gram 是语言预测的「数数法」：看最近 N 个词 → 查历史统计频率表 → 预测下一个词。不需要理解语言，只需要一张巨大的频率表；但它的记性只有 N 个词，超出这个范围的上下文完全看不到，也无法处理相似词之间的借力。

「N-gram」是一种不依赖语法与语义的统计语言模型，只看最近 N 个词，通过统计语料中这些词组的共现频率来估计「下一个词」的条件概率，实现简单但存在长距离依赖看不清、以及把词当孤立符号导致稀疏的局限。

关键代码

PYTHON
from collections import Counter, defaultdict

corpus = "the dog barked the cat slept the dog slept".split()
model = defaultdict(Counter)

for i in range(len(corpus) - 1):          # 数“最近 N 个词”的共现次数
    model[corpus[i]][corpus[i + 1]] += 1

def next_word(w):                          # 纯数数，不懂语法/语义
    return model[w].most_common(1)[0][0]

print(next_word("the"))                    # 接出最多的后继词
# 缺陷：只记 N 个词(记性很短) + 词被当独立符号(组合稀疏灾难)
