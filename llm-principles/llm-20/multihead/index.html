多头注意力与并行分工

多头注意力并排跑 H 套独立的 Query/Key/Value，每个头借用 d/H 维的低维工作空间各抓一种关系，拼接后经线性层融合；总成本几乎等同单头，却能同时建模多种关系（乃至涌现归纳头等上下文能力）。

开场问题：一句话里既有指代、又有语法、又有情感——一个「头」忙得过来吗？

单头挤不下多关系

上一课的注意力机制解决的是「只有一种关系」的简单句。真实句子一个词往往同时牵着好几条线。读「小明告诉小红，他喜欢她画的那幅风景画」，大脑要同时追几条不同性质的线：指代（他=小明、她=小红、那幅=风景画）、主谓（「喜欢」的施动者是「他」）、动宾（「喜欢」的对象是「风景画」）。

光盯「喜欢」这一个词，它既要往左找主语「他」、又要往右找宾语「风景画」——这是两种不同关系，要看向两个不同地方。可上一课的 Q/K/V 只有一份，一个词只能算出一组权重、问一个问题。若强行把主语宾语都算成「相关」一起加权，就会混出一个「半个他 + 半个画」的四不像——两个本该分开的关系揉成一团，反而谁都没看清。

多头并排各管一摊

既然一个头只擅长一种关系，解法朴素到家：同时跑好几个头。每个头都有自己独立的一套 Wq, Wk, Wv，独立打分、独立算权重、独立混合，互不干扰。让「喜欢」往左看主语的，是一个头；让它往右看宾语的，是另一个头。两种关系各算各的，再也不会糊成一团。

关键在于这种分工不是人工指派的：每个头的参数都从海量文本里独立训练出来，训练完一看，它们自然各占一摊——有的管指代、有的抠语法、有的盯情感色彩。现实规模：原始 Transformer 用 8 个头、BERT-base 用 12 个、GPT-3（175B）用 96 个头。一个规律是每头维度稳定在 64~128 维，模型想更强多半是「加头」而不是「把头加宽」；今天主流开源模型还常用 GQA，让几十个查询头共享少数几套 K/V 来省显存。

多头方案的精细账

「同时跑 8 个头」听上去要花 8 倍计算。如果每个头都用满整个 512 维确实如此，但多头隐藏了一个聪明的设计——把维度切开分给各头：

  1. 切维投影：Q_i = xWq_i, K_i = xWk_i, V_i = xWv_i（Wq_i ∈ R^{512×64}）
  2. 各头注意力：H_i = softmax(Q_iK_iᵀ/√d_k)V_i
  3. 拼接 + 收尾：MultiHead(x) = Concat(H_1,…,H_8)·W_o

真实数字：词向量 512 维、8 个头，每个头分到 512 ÷ 8 = 64 维；8 个头 × 64 维 = 512 维，和单头用的总维度一模一样。算完再把 8 个 64 维小结果拼回 512 维、过一个线性层 W_o 收尾。总计算量与单个 512 维头基本持平，却换来同时建模 8 种关系的能力——「免费」多看了 7 种关系。

担心「切成 8 份 = 把信息撕成 8 块、每个头只看八分之一」？——不丢。真相在 Wq_i ∈ R^{512×64} 是「512 行、64 列」的矩阵里：输入 x 是完整 512 维，xWq_i 意味着每个头都把完整的 512 维从头读到尾，再用自己那把「镜头」压进一个 64 维工作空间。所谓「切」，切的是工作空间的大小，不是输入。而且这个镜头是学出来的，每个头会线性组合出对自己这摊关系最有用的特征。输出端同样一维不少地拼回 512 维——信息只是被重新分工，从未被丢弃。

为什么 64 维够装下一种关系？因为一个头只干一件窄活：要表达「512 维完整语义」当然要 512 维，但只回答「这个动词的主语是谁」这一个问题，需要的维度少得多。把一个 512 维「通才」拆成 8 个 64 维「专才」，每个专才反而看得更清——第 1 站那个「四不像」才是真正的信息损失，多头恰恰是来给它「止损」的。

各头中途互不可见

天下没有白吃的午餐。每个头从头到尾各算各的，中途看不到彼此结果，只有末了 W_o 才汇合一次。于是那种需要「边看边商量」的关系——比如「它」既是「小猫」的代词又要当后半句主语——两个头各抓一半却没法在过程中拼起来，只能靠最后的线性层勉强缝合，表达力受限。后来的 MQA、GQA 都在「省显存、让头共享一部分」上做文章，但「多头并行、各管一摊」这个基本盘仍是每台 Transformer 的标准配置。

迭代查看各头分工

研究者把每个头的注意力权重画成热力图，发现头确实分化出一些看得懂、叫得出名字的角色：「上一个词」头（死盯前一个词）、句法头（动词找宾语、介词找名词）、指代头（代词找它指的名词）、分隔符头（没把握时一律看标点）。其中最有名的，是大模型里发现的「归纳头」（induction head）：它能完成「上文出现过 A B，这次又见到 A，下一个多半是 B」的模式补全。很多人相信正是这类头，标志着模型开始具备「照着例子现学现用」的上下文学习能力——一个个朴素的头叠加起来竟涌现出这种能力，这是多头最迷人的地方。

多头并行成本近不变

一个词常牵好几种关系，而一个头只会算一组权重、把多个焦点混成一团。多头注意力的解法是并排跑 H 个独立的头各管一种关系，再靠「每头只用 d/H 维」让总成本几乎不变；拼接 + 线性层收尾，分工全是自己学出来的。本课要点：单头的死穴（加权平均揉出「四不像」）；多头的思路（H 套独立 Q/K/V 各算各的）；维度的账（512÷8=64，总计算量≈单头却多看 7 种关系）；头会自发分工（句法头、指代头乃至归纳头）。

「多头注意力（Multi-Head Attention）」是指并排运行 H 套独立的 Q/K/V，让每个头在自己约 d/H 维的低维工作空间里专注抓住一种关系（指代、句法、情感等），再把各头结果拼接后经线性层融合；成本几乎等同单头，却同时建模多种关系，众多头叠加还能涌现「归纳头」等上下文学习能力。

# 多头注意力：把 d_model 维拆成 H 份，每个头在自己的子空间算注意力
# 一个头抓“指代”，一个头抓“句法”，一个头抓“情感”……
H = 8
d_model, d_head = 512, 64

def cut(v, head):                       # 切出第 head 头的专属维度
    sl = slice(head * d_head, (head + 1) * d_head)
    return v[:, sl]
