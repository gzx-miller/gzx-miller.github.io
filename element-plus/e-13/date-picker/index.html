日期选择：DatePicker 范围与快捷选项

用运营报表筛选演示 ElDatePicker 的日期范围、快捷周期、格式化和禁用日期。

开场问题：运营同学要查「最近 7 天」的报表，我给了他两个日期输入框，他每次得手动敲开始和结束——更糟的是敲错了一个月，报表口径就全歪了。「最近 7 天」到底是几号到几号，这种话为什么不能由代码算出来？

相对时间绝对区间

后台数据页面离不开时间筛选：运营报表、订单流水、审计日志、活动效果，几乎每个列表头上都挂着一个「时间范围」。用户嘴上说的是相对概念——最近七天、上个月、本周——而系统要的是绝对日期区间。把相对说法翻译成准确区间，是这个组件最核心的价值。

如果不用组件库，常见做法是两个原生 input type="date"，或者自己拼一个日历。前者的问题不是能不能用，而是「口径」几乎必然错乱：用户点开默认的当天、自己数着日子往前推六天，数错一天是常事；两个框之间没有约束，用户完全可能把结束日期选到开始日期之前；未来的日期也拦不住，于是筛出「明天到后天」这种根本不存在的区间。这些错误到了后端才发现，返回一堆空数据，用户还以为系统坏了。

代价说清楚：你要自己写日期格式化、自己校验先后顺序、自己造快捷选项、自己算天数——而这些代码里任何一处「包含首尾哪一端」的偏差，都会让数字对不上。

原生日期框拼接

最朴素的做法：放两个原生日期输入框，绑两个字符串变量。用户选完，你在提交前把两个值拼成一个区间。

它做对了一件事：把「一次选择」拆成了边界明确的「起点 + 终点」，语义上是对的——筛选区间本来就有两端。对于「一年一两次、随便选选」的后台，这已经能用。

起止顺序与格式混乱

  • 开始与结束是两个独立输入，用户可以把结束选到开始之前，业务上毫无意义。
  • 常用周期（最近 7 天 / 30 天）每次都要手动点两遍日历，效率低且易数错。
  • 拦不住未来日期，容易选出不存在的区间。
  • 选完之后，界面上没有任何反馈告诉用户「这次筛了几天」，区间口径不直观。
  • 日期格式全靠自己拼字符串，一旦漏补零就会出现 2026-1-5 这种不一致的写法。

成对区间选择

不推翻「起点加终点」，而是把这两端收进一个 el-date-picker，并且用 type="daterange" 一次性选好。这时 v-model 绑定的不再是单个值，而是一个包含起止两项的数组——类型声明必须同步改成数组，否则赋值时立刻报错。

  1. 用 type="daterange" 让用户在一次面板里同时选定开始和结束。
  2. 用 shortcuts 预置「最近 7 天」「最近 30 天」等常用范围，一键填充。
  3. 用 disabled-date 禁用未来日期，从源头挡掉无效报表条件。
  4. 依据选中的起止日期计算统计天数，在界面上给出筛选摘要。

第二件事是 value-format。默认情况下 v-model 拿到的是 Date 对象，跟后端打交道不方便；把 value-format 设成 YYYY-MM-DD，绑定值就变成字符串。但这里有一个必须警惕的点：value-format 会改变 v-model 的值类型——你要么全用字符串，要么全用 Date，在类型声明里一次固定下来。最怕的是一处当 Date 用、一处当字符串比，代码里埋下隐形的类型混乱。

属性作用要点
type选择模式daterange 一次选起止，绑定数组
value-format格式化绑定值会改变 v-model 的值类型，需固定声明
shortcuts预设常用周期其区间由函数动态计算
disabled-date禁用不可选日期接收 Date，返回是否禁用
clearable一键清空清空后绑定值回到空

第三步是算天数并展示摘要。用户选完区间，你在旁边算一下共几天，用标签显示出来，他立刻能确认「哦，这次查的是 7 天」。算的时候要注意口径：日期范围统计通常包含首尾两天，所以天数要按业务口径决定是否 +1。选 1 号到 7 号，直觉上是 7 天，而不是 6 天——这个一分之差，正是报表对不上数的高发原因。

三个容易踩的坑：其一，shortcuts 的区间是函数动态计算的，确认「最近 7 天」这类口径到底包含首尾哪一端，并且和后端对齐——前端显示 7 天、后端按 8 天查，是最典型的对账事故。其二，服务端落库要明确时区和当天的起止时刻，不能只把界面上那串「2026-03-01」直接存进去，否则跨时区或跨零点时口径就漂了。其三，disabled-date 只管住界面，接口层该有的校验不能省。

快捷选项手动对照

范围口径对齐后端

日期选择器把「相对说法翻译成绝对区间」这件事收进了一个面板：type="daterange" 保证两端成对出现，shortcuts 覆盖高频周期，disabled-date 挡住无效值，value-format 决定对外暴露的类型。真正需要你反复确认的不是 API，而是口径——首尾算不算、时区对不对、和后端是不是同一套算法。

「日期范围选择」用 el-date-picker 配合 type="daterange" 一次选起止，v-model 是数组；value-format 把值格式化成字符串但会改变值类型，需在类型声明中固定；shortcuts 由函数动态计算预置周期，disabled-date 接收 Date 返回是否禁用，clearable 一键清空。天数口径（是否 +1）与时区需与后端对齐。

关键代码

Vue
<script setup lang="ts">
import { computed, ref } from 'vue'
import { ElDatePicker, ElTag } from 'element-plus'

const dateRange = ref<[string, string] | null>(null)

const shortcuts = [
  {
    text: '最近 7 天',
    value: () => {
      const end = new Date()
      const start = new Date()
      start.setDate(start.getDate() - 6)
      return [start, end]
    },
  },
  {
    text: '最近 30 天',
    value: () => {
      const end = new Date()
      const start = new Date()
      start.setDate(start.getDate() - 29)
      return [start, end]
    },
  },
]

const reportDays = computed(() => {
  if (!dateRange.value) return 0
  const [start, end] = dateRange.value
  return Math.floor((new Date(end).getTime() - new Date(start).getTime()) / 86_400_000) + 1
})

function disableFuture(date: Date) {
  return date.getTime() > Date.now()
}
</script>

<template>
  <div class="demo-card date-demo">
    <div>
      <p class="demo-kicker">运营报表筛选</p>
      <h3>选择统计周期</h3>
    </div>

    <ElDatePicker
      v-model="dateRange"
      type="daterange"
      range-separator="至"
      start-placeholder="开始日期"
      end-placeholder="结束日期"
      value-format="YYYY-MM-DD"
      :shortcuts="shortcuts"
      :disabled-date="disableFuture"
      clearable
    />

    <div class="report-summary">
      <span>当前统计范围</span>
      <ElTag :type="dateRange ? 'success' : 'info'">
        {{ dateRange ? `${reportDays} 天` : '尚未选择' }}
      </ElTag>
    </div>

    <p>未来日期不可选，常用周期通过 shortcuts 一键填充。</p>
  </div>
</template>
