结果页：Result 操作反馈

用课程提交结果展示 ElResult 的成功、警告、错误和信息状态。

开场问题：用户点了「提交」之后，页面只剩几个字和一片留白——成功还是失败？接下来该做什么？没人告诉他。

状态结论与下一步

你在做一个课程发布流程。讲师填完课程信息，点了提交，后端返回结果。这时页面需要回答用户两个最朴素的疑问：发生了什么，以及接下来我该做什么。这两个问题看似简单，却在不同业务流程里反复出现——支付之后、上传之后、发布之后，都要有人来「宣布结果」。

如果每个流程都临时拼一个结果提示，代价是视觉语言四分五裂：这个页面用红字写失败，那个页面用弹窗写失败，图标有的用对勾有的用感叹号，下一步入口有时在中间有时在角落。用户每次都要重新辨认「现在我该干嘛」，学习成本被白白浪费。

文字提示与返回按钮

最省事的做法：写一个 div，根据状态条件渲染一段文字，成功就写「提交成功」，失败就写「提交失败」，再配一个返回按钮。

它抓住了最核心的一点：结果页必须有一个明确结论。有文字、有出口，就已经比一片空白强。问题是这个方案只解决了「说一句话」，没有解决「怎么把话说清楚、说完整」。

单层文案表达局限

  • 多种状态（成功 / 警告 / 出错 / 提示）的图形没有统一，全靠临时找图标。
  • 文案只有一层，用户只能看到「发生了什么」，看不到「为什么、怎么办」。
  • 没有固定的操作入口，「继续」「重试」「查看详情」的按钮位置随缘。
  • 失败页往往缺一个重试出口，用户只能自己刷新页面重来。
  • 每个业务各写一套，改风格时要满项目找，永远统一不了。

三段式结构封装

不推翻「给用户一个结论」，而是把结论结构化成固定的三段：状态图形、说明文案、下一步入口。Element Plus 的 el-result 正是这套结构的封装。

第一段是图形，用 icon 指定，取值有 success、warning、error、info 四种，分别对应成功、警告、出错、提示。四种状态共用一套视觉规范，用户一看图形就知道结果的性质。

第二段是文案，分两层：title 说清「发生了什么」，sub-title 补充「接下来怎么办」。这个分层很重要——状态名称不是终点，下一步建议才是。与其只写「审核中」，不如补一句「审核通过后将自动上线」，用户立刻知道要不要等、等到什么。

第三段是入口，放在 extra 插槽里，比如「继续操作」「查看详情」按钮，失败场景别忘了放一个重试入口。必要时还可以补上结果编号、金额这类关键业务信息，让用户能凭它追溯或核对。

这三段其实是把用户心里的三个疑问，各配了一个固定的位置回答：「出什么事了」交给状态图形，「到底成没成」交给 title，「我现在能干嘛」交给 sub-title 与操作按钮。位置固定下来之后，用户不需要每次都重新寻找答案，扫一眼就知道该往哪看。

还有一个必须分清的选择：结果页是「整页级」的反馈，适合表单提交或流程结束这种需要停留、需要明确下一步的场合。如果只是「保存成功」这类轻量提示，优先用 ElMessage 或 ElMessageBox——为一句一闪而过的提示铺满整屏，反而打断了用户的节奏。

让同一业务流程复用同一套结构：成功、失败、审核中等状态，不必各写一个页面模板，而是沿用同一个结果页，只切换 icon 与文案参数。这样整条流程的视觉语言完全一致，用户也更容易形成「看到这个页面就知道该怎么走」的直觉。

四态切换视觉对照

结果页与消息分工

结果页解决的，是「流程结束后用户没有结论、没有方向」这件事。它把「状态图形 + 说明文案 + 下一步入口」固化成统一结构，用 icon 区分四种状态，用 title 与 sub-title 分层说明，用 extra 插槽兜住后续操作。记住两点：整页级反馈才用它，轻量反馈交给消息提示；同一流程复用同一结构，只换参数。

「结果页」用 el-result 提供标准化的操作结果反馈：icon 指定 success / warning / error / info 四种状态图形，title 与 sub-title 分层说明「发生了什么、接下来怎么办」，extra 插槽放后续操作按钮。它适合表单提交或流程结束后的整页反馈；更轻量的成功或失败提示应优先使用 ElMessage 或 ElMessageBox。

关键代码

Vue
<script setup lang="ts">
import { ref, computed } from 'vue'
import { ElResult, ElButton } from 'element-plus'

type Status = 'success' | 'warning' | 'error' | 'info'

const status = ref<Status>('success')

const meta: Record<Status, { title: string; desc: string }> = {
  success: { title: '课程提交成功', desc: '讲师已收到通知，预计 2 个工作日内完成审核。' },
  warning: { title: '草稿已保存', desc: '课程内容尚未发布，学员暂时无法看到。' },
  error: { title: '封面上传失败', desc: '图片格式不支持或超过 5MB，请检查后重试。' },
  info: { title: '审核中', desc: '课程正在等待教研组审核，审核通过后将自动上线。' },
}

const current = computed(() => meta[status.value])

function setStatus(s: Status) {
  status.value = s
}
</script>

<template>
  <div class="demo-card">
    <p class="demo-kicker">操作反馈</p>
    <h3>课程发布结果页</h3>

    <div class="button-row">
      <ElButton :type="status === 'success' ? 'primary' : ''" @click="setStatus('success')">提交成功</ElButton>
      <ElButton :type="status === 'warning' ? 'warning' : ''" @click="setStatus('warning')">保存草稿</ElButton>
      <ElButton :type="status === 'error' ? 'danger' : ''" @click="setStatus('error')">上传失败</ElButton>
      <ElButton :type="status === 'info' ? 'info' : ''" @click="setStatus('info')">审核中</ElButton>
    </div>

    <ElResult :icon="status" :title="current.title" :sub-title="current.desc">
      <template #extra>
        <ElButton type="primary" @click="setStatus('success')">继续操作</ElButton>
        <ElButton @click="setStatus('info')">查看详情</ElButton>
      </template>
    </ElResult>
  </div>
</template>
