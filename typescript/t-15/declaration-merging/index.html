声明合并与模块扩展

扩展第三方库类型，掌握接口合并和模块增强。

开场问题：启动脚本明明往 window 上挂了 __APP_VERSION__，代码里读它却提示「属性不存在」；第三方库少声明了一个方法，你又不方便改它的源码——这个类型该怎么补？

第三方类型缺口

你接手一个既有项目，启动脚本在 window 上挂了一个 __APP_VERSION__，某个埋点库的实例上还多出一个官方类型里没写的 trackOnce 方法。运行时这两样都在，TypeScript 却一律报「属性不存在」。

前一种还好办，在业务代码里断言一下就能过去；后一种更麻烦——你不可能去改第三方库的源码，下次升级还会被覆盖。真正想要的是：在自己这一侧、完全不触碰对方源码的前提下，把缺失的类型补上去。

就地类型断言

最省事的做法是就地断言：(window as any).__APP_VERSION__。它马上能让编译通过，确实是「绕过类型检查」的一种手段。

要承认它的位置：当你只想临时读一个值、又完全不想引入任何配置时，这确实是最短的路径，它至少让你先跑起来。问题出在把这个手段当成方案之后。

断言丢失安全

  • 断言把类型安全直接丢掉了：拼错成 __APP_VERISON__ 也不会报错，运行时才拿到 undefined。
  • 同一个属性每处都要断一次，写法啰嗦，还容易前后不一致。
  • 第三方库缺失的类型，断言只能骗过自己，团队里其他人依旧看不到任何提示。
  • 最关键的是：编译器本来可以知道这些属性存在，只是没人告诉它。

声明合并机制

TypeScript 有一项特性专门用来回答这类问题：声明合并——多份分散的声明可以按规则拼成同一个实体，不必挤在一处写。

第一层是接口合并。同名的 interface 会被自动合并成一个类型，属性取并集：

interface AppConfig { apiBase: string; timeout: number } 与 interface AppConfig { theme: 'light' | 'dark'; locale: string } 合并之后，AppConfig 同时拥有四个属性。

这条规则的力量在于：你只需要追加一个字段，而不必重写原有的声明——这正是「增强」而非「覆盖」。

第二层是 namespace 与 class、函数、枚举的合并。同名 namespace 可以给一个已存在的类追加静态成员，比如给 Album 类补上 Album.create() 与一组常量。但有一条硬约束要记住：两个 class 之间不能互相合并，想扩展一个类的类型形状，只能借助 interface 或 namespace。

第三层，也是实战中最常用的，是模块增强。在 .d.ts 里用 declare module 为第三方包补充或改写类型，用 declare global 扩展 Window、String 这类全局对象：

declare global { interface Window { __APP_VERSION__: string } }

这样 window.__APP_VERSION__ 就有了类型提示，配合空值检查也能把可能为 undefined 的情况提出来。

这里有三个必须记住的坑。其一，模块增强必须写在模块作用域里，也就是该文件里得有 import 或 export，否则 declare module 会被当成一个新的环境声明而不是增强。其二，declare global 只在带 import / export 的模块文件中生效，放在一个没有任何导入导出的脚本文件里是无效的。其三，增强要按包逐个声明，并且尽量集中到 types/ 目录统一管理——散落在各个业务文件里的 declare 很难追踪，出现冲突时也不好排查。

把这三种合并按使用频率排一排会更清楚：接口合并多用于把同一个契约拆到多个文件里维护，或给第三方导出的接口追加字段；namespace 合并主要用于给类补静态工厂与常量；而真正解决「第三方库缺类型」的，还是模块增强——它不改源码，只在类型层面把缺口补平，依赖升级时也不会被冲掉。

声明合并是「增强」，不是「覆盖」：同名接口会把成员并起来，无法删掉或否决对方已有的属性。如果两边对同一字段给出了互相冲突的类型，编译器会把它揪出来——这反而是发现建模问题的重要信号。

增强而不覆盖

声明合并让「扩展别人」不必修改别人的源码：同名接口把属性并起来，namespace 给类追加静态成员，declare module 与 declare global 则为第三方包和全局对象补齐类型。规矩只有三条——类与类不能直接合并，模块增强必须待在模块作用域里，全局增强只在带导入导出的文件中生效。

「声明合并与模块增强」指多份分散的声明按规则拼成同一实体：同名 interface 属性自动合并，namespace 可与 class、函数、枚举合并以追加静态成员（类与类之间不能直接合并），declare module 在模块作用域内为第三方包补充类型，declare global 扩展全局对象且仅在带 import / export 的文件中生效。它用于在不改源码的前提下补类型，增强应集中到 types/ 目录统一维护。

关键代码

TypeScript
// 声明合并与模块扩展

// ── 接口合并（同名接口自动合并属性） ──
interface AppConfig {
  apiBase: string
  timeout: number
}

// 同文件中再次声明，TypeScript 自动合并
interface AppConfig {
  theme: 'light' | 'dark'
  locale: string
}

// config 拥有所有四个属性
const config: AppConfig = {
  apiBase: '/api/v1',
  timeout: 3000,
  theme: 'light',
  locale: 'zh-CN',
}

// ── 命名空间合并 ──
// 命名空间可以和类 / 函数 / 枚举合并，为它们添加额外成员
namespace Validation {
  export function isValidEmail(email: string): boolean {
    return /^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)
  }
}

namespace Validation {
  export function isValidPhone(phone: string): boolean {
    return /^1[3-9]\d{9}$/.test(phone)
  }
}

// 两个命名空间合并后同时拥有 isValidEmail 和 isValidPhone
console.log(Validation.isValidEmail('test@example.com'))  // true

// ── 模块扩展（declare module） ──
// 在 .d.ts 文件中扩展第三方模块的类型
//
// declare module 'axios' {
//   interface AxiosResponse<T = any> {
//     // 为所有响应添加自定义字段
//     serverTime: number
//     requestId: string
//   }
// }
//
// declare module 'vue-router' {
//   interface RouteMeta {
//     // 扩展路由元信息类型
//     requiresAuth?: boolean
//     title?: string
//     roles?: string[]
//   }
// }

// ── 声明文件（.d.ts） ──
// 纯类型文件，不含运行时代码，用于描述 JS 库的类型
//
// env.d.ts 示例：
// interface ImportMetaEnv {
//   readonly VITE_API_BASE: string
//   readonly VITE_APP_TITLE: string
// }

// ── 全局增强（declare global） ──
// declare global 只能在模块文件（有 import/export 的文件）中使用
// 在非模块的 .ts 文件中，顶层接口声明本身就在作用域内
export {}  // 使当前文件变为模块

declare global {
  interface Window {
    __APP_VERSION__: string
    __INITIAL_STATE__: Record<string, unknown>
  }

  // 扩展 HTMLElement，添加自定义 dataset 属性
  interface HTMLElement {
    dataset: DOMStringMap & {
      courseId?: string
      lessonIndex?: string
    }
  }
}

// 使用时无需类型断言
// window.__APP_VERSION__ = '2.0.0'

// ── 环境声明 ──
// declare 关键字告诉编译器"这个变量在运行时存在，但不在当前文件中定义"
declare const __DEV__: boolean
declare function loadScript(url: string): Promise<void>

console.log(config.apiBase)  // /api/v1
