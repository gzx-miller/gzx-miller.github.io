联合类型与控制流收窄

用订单状态机掌握字面量联合类型和条件分支收窄。

开场问题：订单卡片按状态显示「待付款 / 待发货 / 运输中」，可同事把判断写成 status === 'payed'，分支静默失效，界面卡在旧文案上——有没有办法让这种拼写错误根本进不了编译器？

状态字符串硬编码

订单有一套状态：待付款、待发货、运输中。最自然的写法，是在比较、赋值、传给接口时到处写字符串 'pending'、'paid'、'shipped'，各写各的。

代价在第一个人手滑时就会显现：状态是一个有限的集合，但字符串是无限的。你无法阻止有人写入 'refunded'、'PAID' 或 'payed'。更糟的是，一个拼错的字符串不会报错，它只会让某个分支永远不生效——订单静静停在错误的文案里，而代码看起来一切正常。所以真正要解决的是：如何让非法的业务状态无法被创建，并在每个分支里被安全地处理。

直接比较字符串

最省事的做法，就是直接拿字符串当状态用：let status = 'pending'，再配一句 if (status === 'paid') {}。

它做对了一件朴素的事：状态在运行时确实就是字符串，不需要额外概念，读写都直观，传给后端也能直接用。只要状态只有一个人维护、只在一处出现，这种写法看不出问题。

非法取值放行

  • 非法状态可以随意创建：status = 'payed' 编译照样通过，只是运行时永远匹配不上。
  • 魔法字符串散落各处，改一次名要全局搜索替换，漏掉一处就是一颗雷。
  • 每个分支里 status 仍是宽泛的 string，编辑器给不出「这个状态独有的值」的提示。
  • 新增一个状态后，遗漏处理的分支不会被指出来，只能靠人自己数。

字面量联合类型

不推翻「状态就是一个值」，而是收窄它的取值范围。用字面量联合类型把订单的所有合法状态明确列举出来：

type OrderStatus = 'pending' | 'paid' | 'shipped'

这一行把状态的合法取值收拢成了单一来源。此后 let status: OrderStatus = 'paid' 合法，而 status = 'payed' 会直接在编译期标红——非法状态再也进不了业务逻辑。

第二步是控制流收窄。TypeScript 会基于条件分支里对成员的相等比较，把参数类型逐步收窄到具体成员，于是每个分支都按该成员独有的类型与业务逻辑来写：

function describe(status: OrderStatus) {
  if (status === 'pending') { /* 此处 status 为 'pending' */ }
  else if (status === 'paid') { /* 此处 status 为 'paid' */ }
  else { /* 其余成员由编译器保证不会失配 */ }
}

  1. 用字面量联合类型列举全部合法状态，禁用散落的魔法字符串。
  2. 在函数内对状态参数做相等判断，让编译器在分支内把类型收窄为具体成员。
  3. 在收窄后的分支中安全调用该状态专属逻辑，其余分支由编译器保证不会失配。
  4. 新增一个状态值，验证所有未处理的代码位置都被编译器一一点出。

如果分支改写成 switch，效果完全同理：case 里比较到的成员同样被收窄，而在每个 case 之外，status 会被一步步缩小到「还没被处理过的成员」。这正是「新增状态后所有未处理位置都能被点出」的底气——它不靠额外工具扫描，而是类型收窄顺带给出的保证。

还有两处必须记住的细节。其一，收窄依靠相等比较，控制流越简单（if/else、switch），收窄结果越可预期，所以别在中间穿插会打断推断的写法。其二，不要在收窄之后又把它还原成宽泛类型，否则辛苦收来的精确信息当场丢失。最后，状态值的来源要收敛到一处：类型、常量与校验函数共享同一份字面量联合，任何人改状态都只改这一个地方。

订单状态流转

取值清单与收窄

联合类型做的事情，是把「这个值可能是什么」从散落各处的字符串收拢成一份清单；收窄做的事情，是让编译器顺着条件分支，把你带到一个又一个精确的分支里。合法状态只有一处定义，非法取值在编译期就被拦下，新增状态时遗漏的分支也无所遁形。

「字面量联合类型与收窄」指用 'pending' | 'paid' | 'shipped' 把一个值可能取到的状态显式列举出来，作为合法取值的唯一来源；TypeScript 再依据条件分支中对成员的相等比较，把参数逐步收窄到具体成员，使每个分支按该成员独有的类型编写。控制流越简单收窄越可预期，且不要在收窄后还原成宽泛类型。

关键代码

TypeScript
// 联合类型：限定变量只能取特定值
type OrderStatus = 'pending' | 'paid' | 'shipped'

// 控制流收窄：TS 根据条件自动缩窄类型
function getStatusText(status: OrderStatus): string {
  if (status === 'pending') return '待付款'
  if (status === 'paid') return '待发货'
  return '运输中'  // TS 知道此处只剩 'shipped'
}

// 非法状态在编译期即被拦截
// getStatusText('cancelled')  → 类型错误

const status: OrderStatus = 'pending'
console.log(getStatusText(status))  // 待付款
