模板字面量类型

构建类型安全的事件名、路由路径和 CSS 类名。

开场问题：组件约定的事件名是 onClick、onFocus，可为什么把 'onClik' 传进去，TypeScript 一声不吭？

事件名字符串拼接

你在封装一个按钮组件，对外约定四个基础事件 click、focus、submit、change，内部统一用 onXxx 的写法挂载监听。问题在于，这些名字全都是普通字符串：'onClick' 与 'onClik' 在类型上毫无分别，后者只会在用户点了按钮却没有反应时才暴露出来。

同类问题还会出现在路由路径与 CSS 类名上——凡是用「前缀 + 后缀」拼出来的字符串，只要拼接规则存在，就一定有写错的空间。把约定只写在文档或代码评审里，等于把校验推迟到了运行时，甚至是线上。

枚举合法取值

最直接的做法是枚举式地把合法值全列出来：type OnEvent = 'onClick' | 'onFocus' | 'onSubmit' | 'onChange'。写错任何一个成员，编译器都会在赋值处立刻标红。

这个方向是对的，用字面量联合把「合法取值」显式列举出来，是类型约束的基本功。它至少把错误从运行时提前到了编译期。

手工穷举成本

  • 合法值是「手工穷举」的：基础事件从四个涨到十个，这份联合就得跟着一个个手改。
  • 四个事件配四个 onXxx，再叠上四种样式状态，组合数量会翻倍增长，枚举写法很快失控。
  • 一旦拼接规则变化（比如前缀从 on 改成 handle），所有枚举值都要重写——规则本身从未被表达出来。
  • 前缀与后缀两两组合时，手写极易漏掉某些本该合法的组合。

模板字面量类型

与其列举「结果」，不如描述「规则」。模板字面量类型允许你在类型层面写一对反引号，把字符串拼接搬进类型里：type OnEvent = `on${Capitalize<BaseEvent>}`。其中 BaseEvent 是一个联合，编译器会把反引号里的每个占位符依次替换成联合的成员，自动展开出所有合法形态——你只写了规则，成员却一个不少。

当占位符是多个联合时，它做的是笛卡尔积：type CssClass = `${Prefix}-${State}`，三个前缀乘以四种状态，十二个类名被自动生成，一个不漏也一个不多。这就是模板字面量最实用的地方：把「组合出所有可能」交给编译器。

它还能配合内置的字符串工具统一大小写：Uppercase 全大写、Lowercase 全小写、Capitalize 首字母大写。这正是先写 click、再派生出 onClick 的依据——基础数据保持小写，展示形态由类型规则生成，命名规范从此只在一处定义。

再走一步，模板字面量类型可以反过来从字符串里提取片段，配合 infer 与条件类型一起用。比如从 `on${E}` 里把事件名取回来，或者把 camelCase 转成 snake_case。于是同一套规则既能生成、又能解析，事件总线、API 路由与状态机的 key 都能收敛到一份定义上。

把这些能力串起来，封装一个类型安全的事件总线大致分四步：

  1. 先定义一份「基础事件名 → 负载参数」的映射，键写成 click、submit 这样的小写名字。
  2. 用模板字面量类型 `on${Capitalize<K>}` 从基础名派生出对外的事件名，命名规范只在一处定义。
  3. 把监听与触发函数的参数约束到派生出来的名字上，触发时负载类型随事件名一起收窄。
  4. 新增一个基础事件，只改键定义即可，派生的名字与负载校验会一起更新。
需要留意类型膨胀：模板字面量与联合组合时是笛卡尔展开，两个十成员的联合一拼就是一百个键，编译器的推导次数会成倍上升。如果一个字面量能被规则完整描述，就不要把它提前展开成具体成员。

字符串约定编码

模板字面量类型把「前缀 + 后缀」这类字符串约定从注释里搬进了类型系统：它由规则生成合法取值，能调用大小写工具规范化，还能用 infer 反向解析。事件名、路由路径、CSS 类名这些曾经只靠约定维持的东西，如今在编辑阶段就会被拦住。

「模板字面量类型」用反引号在类型层面拼接字符串，形如 `${Prefix}${Suffix}`；占位符遇到联合会自动展开，多个联合则做笛卡尔组合。它常配合 Uppercase、Capitalize 等内置工具统一命名规范，也能借助条件类型与 infer 反向提取片段。适合事件名、路由、CSS 类名等强约束场景，但组合爆炸时必须警惕类型膨胀。

关键代码

TypeScript
// 模板字面量类型：在类型层面拼接和约束字符串模式

// ── 基础模板字面量 ──
type Color = 'red' | 'green' | 'blue'
type Shade = 'light' | 'dark'
type CssColor = `${Shade}-${Color}`
// 'light-red' | 'light-green' | 'light-blue' | 'dark-red' | 'dark-green' | 'dark-blue'

// ── 内置字符串工具类型 ──
type E1 = Uppercase<'hello'>       // 'HELLO'
type E2 = Lowercase<'Hello'>       // 'hello'
type E3 = Capitalize<'hello'>      // 'Hello'
type E4 = Uncapitalize<'Hello'>    // 'hello'

// ── 事件名约束 ──
type BaseEvent = 'click' | 'focus' | 'submit' | 'change'
type OnEvent = `on${Capitalize<BaseEvent>}`
// 'onClick' | 'onFocus' | 'onSubmit' | 'onChange'

// ── 路由路径类型 ──
type Module = 'vue' | 'react' | 'nuxt'
type LessonId = `${number}`
type RoutePath = `/${Module}/${LessonId}`
// '/vue/1' | '/vue/2' | ... | '/react/1' | ... | '/nuxt/1' | ...

// ── 条件类型 + 模板字面量：提取模式 ──
// 从 'on${Event}' 中提取事件名
type ExtractEvent<T> = T extends `on${infer E}` ? Uncapitalize<E> : never
type Click = ExtractEvent<'onClick'>   // 'click'
type Focus = ExtractEvent<'onFocus'>   // 'focus'

// ── 键名转换（映射类型 + 模板字面量） ──
interface ApiResponse {
  userId: number
  courseTitle: string
  isPublished: boolean
}

// camelCase → snake_case 映射（简化版）
type ToSnakeCase<S extends string> =
  S extends `${infer Head}${infer Tail}`
    ? Tail extends Uncapitalize<Tail>
      ? `${Lowercase<Head>}${ToSnakeCase<Tail>}`
      : `${Lowercase<Head>}_${ToSnakeCase<Tail>}`
    : S

type SnakeResponse = {
  [K in keyof ApiResponse as ToSnakeCase<K & string>]: ApiResponse[K]
}
// { user_id: number; course_title: string; is_published: boolean }

// ── 实际用途：类型安全的事件总线 ──
type EventMap = {
  'user:login': { userId: number }
  'user:logout': undefined
  'course:publish': { courseId: number; title: string }
}

function emit<K extends keyof EventMap>(event: K, payload: EventMap[K]) {
  console.log(`触发事件：${event}`, payload)
}

emit('user:login', { userId: 42 })
emit('course:publish', { courseId: 1, title: '模板字面量' })
// emit('user:login', { courseId: 1 })  // 错误：payload 类型不匹配

console.log('模板字面量类型演示完成')
