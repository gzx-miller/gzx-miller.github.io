类型推导与显式标注

从课程表单理解 TypeScript 如何推导类型，以及何时需要显式标注。

开场问题：课程表单里 const name = 'Vue 3 实战' 不写类型也能用，可剩余席位却得写成 ref<number | null>(20)——到底哪些类型可以让编译器自己猜，哪些必须亲手写明？

初始值类型推断

你在做一个课程发布表单，字段有课程名、价格、剩余席位。写下 const name = 'Vue 3 实战' 时，编辑器立刻知道它是字符串；再写一个数组、一个对象，结构也照样被识别出来。于是你很自然地想：既然编译器什么都能看出来，那干脆一个类型都不写，代码最干净。

麻烦在于，编译器猜的是「你此刻写下的那个值」，而不是「这个字段将来应该是什么」。当状态要在待付款、待发货、已完成之间切换，当席位可能为空，当函数要对外提供稳定接口时，靠初始值猜出来的类型要么窄得离谱，要么宽得离谱，错误会一路漏到运行时才发作。所以真正的问题不是「要不要类型」，而是哪条边界上必须由人来拍板。

省略类型标注

最省事的做法，是完全依赖推导，一个类型标注都不写：const price = 99 得到 number，const tags = ['前端', 'Vue'] 得到 string[]，const config = { host: 'localhost', port: 3000 } 得到 { host: string; port: number }。

这个方案做对了一件很重要的事：显而易见的类型不必重复书写。局部变量由初始值就能算出准确结构，再手写一遍只是噪音，而且还可能与真实类型不一致。TypeScript 的便利正来自这里——它是从值推出类型，而不是逼你到处写注解。

空数组与字面量类型

  • 空数组推导成 any[]：const list = [] 的元素类型彻底丢失，之后推入什么都放行。
  • const 推导出的是字面量类型：const status = 'idle' 被推成 'idle'，想让它承接 'loading'、'done' 根本做不到。
  • 初始值为空：let user = null 推成 null，后面想赋成用户对象就被拦下。
  • 函数参数没有标注就是隐式 any：function fetch(id) {} 里任何实参都能塞进来，错误到运行时才出现。
  • 返回值类型悄悄漂移：今天返回对象、明天返回数组，调用方毫无预警。

显式标注时机

不推翻「能推就推」，而是划出必须显式声明的边界。第一类是需要放宽为联合的值：状态要写成 'idle' | 'loading' | 'done'，可为空的席位要写成 number | null，把「可能取哪些值」明明白白交给编译器。

第二类是类型边界本身：函数的参数与返回值。参数是一份协议——你提供什么、我保证返回什么，所以公共函数优先为它们标注，形成稳定的调用契约，例如 function fetch(id: string): Promise<Data>。这里也有个取舍：返回值类型可以交由推导，但参数通常值得显式标注，因为它才是调用方唯一看得见的入口。

第三类是需要宽类型或需要补充信息的场景。const 推出来的是字面量类型，若确实要一个宽泛的 string，就显式写 const name: string = 'Vue 3 实战'；若想既保留精确的字面量推导、又校验对象结构，用 satisfies 在保留推导的同时做约束。空数组则补上元素类型：const list: Course[] = []。

场景交给推导显式标注
局部常量const price = 99几乎不必
空数组会退成 any[]const list: Course[] = []
联合状态只会是初始那一个值let status: 'idle' | 'done'
可为空只会是 nulllet user: User | null
公共函数返回值可以推导参数与返回类型写明

需要强调的一点是：显式标注的目的不是「写得更全」，而是在边界上拦住错误。当这些交界处都写明了类型，编译器就会在每次赋值与调用时替你核对——把字符串塞进 number | null 会被拦下，把错误实参传给公共函数也会被拦下，你甚至不必等到运行才发现问题。

反过来看，用 any 去「绕开」类型报错，只是把检查关掉，问题依旧留在代码里。遇到确实无法预先确定的数据，应当用 unknown 接收，再配类型守卫逐层验证，而不是提前放弃类型安全。

一句话收束这套取舍：只对必要的类型边界做显式标注，局部变量不重复写显而易见的类型。标注一旦只落在交界处，编译器就能在这些边界上替你盯着每一次赋值。

三种写法对照

推断与标注边界

类型推导与显式标注不是二选一，而是分工：编译器负责从初始值推断显而易见的类型，人负责在边界处拍板。局部常量放心交给推导，联合、可空、空数组与公共函数参数则显式写明——省下的注解是噪音，留下的标注才是契约。

「类型推导」指 TypeScript 依据变量的初始值自动推断其类型，局部常量与绝大多数返回值都无需标注，且 const 推出来的是字面量类型。当类型需放宽为联合（如可为 null）、推断不足以表达真实意图，或作为公共 API 的输入输出需要稳定契约时，才应显式标注；需要宽类型可写 const name: string，需要保留推导又要校验结构则用 satisfies。

关键代码

TypeScript
// 类型推导：TS 从初始值自动推断类型
let courseName = 'Vue 3 实战'   // 推导为 string
let price = 99                   // 推导为 number

// 显式标注：当类型无法完全推断或需要扩展时使用
let seats: number | null = 20   // 允许后续赋 null
seats = null                     // ✓ 合法

// 函数返回值推导
function formatCourse(name: string, price: number) {
  return `${name} · ¥${price}`  // 推导返回 string
}

console.log(formatCourse(courseName, price))
