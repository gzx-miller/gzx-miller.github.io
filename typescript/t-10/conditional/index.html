条件类型与类型推导

用条件类型和 infer 从联合响应中提取精确类型。

开场问题：接口响应有成功和失败两种形状，我想写一个类型只把「成功时的数据」取出来，结果它对着整个联合一起判断，一个成员都没提取到——为什么没有逐个成员分别处理？

联合响应拆分

响应类型往往是个联合：成功时是 { ok: true; data: T }，失败时是 { ok: false; error: string }。业务里真正关心的是「成功分支里那份 data 到底是什么类型」。你很自然地想为它写一个派生类型，把成功数据挖出来，可是一动手就发现：这件事得按类型形状做分支——如果它是这种形状就取 A，否则取 B。

类型层面过去没有这种能力，代价就是手工展开。每一种响应都手写一个提取类型，UserResponse 配一个 UserData，CourseResponse 再配一个 CourseData，逻辑完全一样却抄了无数遍。更麻烦的是遇到联合时，手写的类型根本不知道该针对哪个成员。

手写提取类型

最省事的做法：为每种响应单独定义一个提取类型，把成功数据的形状直接写死。

这个方案做对了一件事：它把「提取」这件事明确表达了。类型名字本身就说明了意图，使用处也能得到正确的数据形状。在响应种类很少、又不怎么变化时，这样写清楚、直接，够用。

逐个判断缺失

  • 每新增一种响应就要重抄一份提取类型，逻辑重复且容易抄错。
  • 面对联合类型时，手写类型无法「逐个成员分别判断」，要么全中要么全不中。
  • 提取规则一旦变化（比如成功标记改名），所有手写类型都要跟着改。
  • 它无法对内层未知类型做捕获，遇到泛型容器只能放弃。

条件类型分派

不推翻「按形状分支」，而是把这个分支动作交给语言本身。条件类型就是类型层面的 if-else，写作 T extends U ? X : Y：先判断 T 能否赋值给 U，是则取 X，否则取 Y。把它写成一个具名的类型别名，就得到了可以反复复用的判断规则。

真正有意思的地方在遇到联合类型时。当 extends 左边的 T 是一个裸类型参数、而实参又是联合类型时，条件类型会把分支逐个应用到每个成员，再把结果重新拼成联合——这就是分布式条件类型。所以同样是判断，它天然就懂得「分别处理」。

但如果你的本意恰恰是把整个联合当成一个整体来判断呢？只要用方括号把 T 包起来写成 [T] extends [U]，那个「裸」的条件就被打破了，分发随之被抑制，判断对象重新变成整个联合。[T] 这个包裹，正是在「逐个成员」与「整体判断」之间切换的开关。

  • [T] extends [never] 用来判断联合是否为空——因为裸判断会让 never 直接返回 never，必须包裹才能得到真值。
  • 嵌套的条件类型读起来费劲时，拆成几个具名的类型别名，比堆在一行里强得多。

而当我们想在匹配到的分支里捕获那份未知的子类型时，就用 infer——它声明一个待推断的变量，让编译器在匹配时反向把它的取值推出来。把条件类型与 infer、映射类型组合起来，那些耳熟能详的内置工具就都能自己实现：Exclude 用分发把能匹配上的成员剔除，Extract 反过来只保留匹配上的成员，NonNullable 则把 null 与 undefined 分发掉。它们本质上都是同一个机制的不同产物。

三个提醒：并非所有条件类型都会分发，只有当 extends 的左操作数是裸类型参数时才会分发；条件类型的分支只表达类型推导，千万别在里面写运行时代码；infer 的专项内容见本板块 T_21，那里会讲清它如何从函数、容器中提取内层类型。

回头再看开场那个提取成功数据的类型，就能写得又短又准：判断 R 是否满足「成功形状」，在匹配的分支里用 infer 把 data 捕获出来，其余情况归到 never。联合响应经过一分布式判断，成功数据自然就被摘了出来。

成功分支提取

分支判定与分发

条件类型把「按类型形状分支」变成了语言内置的能力：T extends U ? X : Y 做判断，裸类型参数遇到联合会逐个分发，用 [T] 包裹即可切回整体判断，配合 infer 还能捕获内层类型。Exclude、Extract、NonNullable 这些工具，都是这套机制结出的果。

「条件类型」用 T extends U ? X : Y 在类型层面做分支选择。当裸类型参数收到联合类型时，分支会逐个应用到每个成员，即分布式条件类型；用 [T] 包裹可把整个联合作为整体判断。infer 在匹配分支中捕获未知子类型，Exclude、Extract、NonNullable 等工具正是这一机制的产物。

关键代码

TypeScript
// 条件类型：T extends U ? X : Y —— 在类型层面做条件分支

// ── 基础条件类型 ──
type IsString<T> = T extends string ? true : false
type A = IsString<'hello'>  // true
type B = IsString<42>       // false

// ── 分布式条件类型 ──
// 当 T 是裸类型参数且传入联合类型时，条件会分配到每个成员上
type ToArray<T> = T extends any ? T[] : never
type StrOrNumArr = ToArray<string | number>  // string[] | number[]（而非 (string|number)[]）

// 用 [T] 包裹可禁止分布式行为
type ToArrayStrict<T> = [T] extends [any] ? T[] : never
type MixedArr = ToArrayStrict<string | number>  // (string | number)[]

// ── infer 关键字：在条件类型中捕获 / 推导子类型 ──
interface ApiResponse<T> { ok: true; data: T }

// 从 ApiResponse 中提取 data 的类型
type UnwrapData<R> = R extends ApiResponse<infer D> ? D : never
type CourseData = UnwrapData<ApiResponse<{ title: string }>>  // { title: string }

// ── 内置工具类型的实现原理 ──
// ReturnType：提取函数返回值类型
type MyReturnType<T> = T extends (...args: any[]) => infer R ? R : never
type R1 = MyReturnType<() => string>                   // string
type R2 = MyReturnType<(x: number) => { ok: boolean }> // { ok: boolean }

// Parameters：提取函数参数类型为元组
type MyParameters<T> = T extends (...args: infer P) => any ? P : never
type P1 = MyParameters<(a: string, b: number) => void>  // [a: string, b: number]

// InstanceType：提取构造函数的实例类型
type MyInstanceType<T> = T extends new (...args: any[]) => infer I ? I : never
class Lesson { title = ''; duration = 0 }
type I1 = MyInstanceType<typeof Lesson>  // Lesson

// ── Exclude / Extract / NonNullable 实现 ──
type MyExclude<T, U> = T extends U ? never : T
type MyExtract<T, U> = T extends U ? T : never
type MyNonNullable<T> = T extends null | undefined ? never : T

type Status = 'draft' | 'published' | 'archived'
type Active = MyExclude<Status, 'archived'>  // 'draft' | 'published'

// ── 递归条件类型 ──
// 将嵌套对象所有属性递归变为可选
type DeepPartial<T> = T extends object
  ? { [K in keyof T]?: DeepPartial<T[K]> }
  : T

interface Nested { a: { b: { c: string } } }
type PartialNested = DeepPartial<Nested>  // { a?: { b?: { c?: string } } }

console.log('条件类型演示完成')
