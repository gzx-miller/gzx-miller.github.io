异步返回类型与 Awaited

使用 Awaited 解包 Promise 嵌套，精确获取异步函数的返回值类型。

开场问题：我在 await 之后拿到的确实是用户对象，可只要想把「这个 async 函数真正的返回类型」抽出来复用，ReturnType<typeof fetchUser> 给我的却还是 Promise<UserProfile>——外面那层 Promise 到底谁来剥？

接口层异步函数

接口层写满了 async 函数：fetchUser、fetchOrder、fetchProduct，每个都返回 Promise。可下游真正需要的是「await 之后那个东西的类型」——缓存里存它、状态仓库的初始值标注它、Mock 数据照着它造、单元测试按它断言。同样，当你用 Promise.all 并发拉几个请求，也希望结果的元组类型能自己推导出来，而不是手写一遍。

还有错误这一面：async 函数里的 try/catch，catch 接到的 error 是 unknown，团队里有人图省事直接断言成 any 就用，字段取错了也不报错，风险被一路推到线上。类型写不准，解构时字段提示就缺失；错误不建模，catch 里拿到的数据结构就无从谈起。

函数签名显式标注

最省事的做法：在函数签名上手工标注返回类型，或者在调用处把手写的结果类型再抄一遍。函数返回什么，我就照着宣布一遍。

这个方案做对了一件事：显式标注确实让「函数是否真的返回了它承诺的结构」被检查到，这是很好的边界习惯。单看一个函数，它没什么问题。

单层解包局限

  • 手写返回类型与实现脱钩，实现一改就漂移，类型却仍然理直气壮。
  • ReturnType 拿到的是 Promise<...>，不是 await 之后的类型，还得手动再剥一层。
  • Promise.all、allSettled、race 组合出来的类型不会自动整理成你要的结构。
  • catch 里的 error 是 unknown，直接当对象用编译期就报错；有人用 as any 绕过，等于把风险留到运行时。

递归解包异步层级

不推翻「拿到真实返回类型」，而是让类型系统自己递归地把 Promise 剥掉。做这件事的内置工具就是 Awaited<T>：不是 Promise 就原样返回，是 Promise 就取它 resolve 出来的类型，如果那还是 Promise 就继续剥——一层层解到最里。手写一遍它的原理更好记：

type MyAwaited<T> = T extends Promise<infer U> ? U extends Promise<any> ? MyAwaited<U> : U : T

拆开看：它先用 infer U 把 Promise 里的东西捕获出来；若捕获到的仍是 Promise，就把它再喂回自己，递归下去；直到某一层不再是 Promise，就把它作为结果返回；至于压根不是 Promise 的类型，走最后一支原样返回。正因为是递归的，嵌套多少层都只需要写一次，这就是「深层嵌套也能解包」的来源。这段实现还有一个值得记住的细节：现实中的 Awaited 判断的是带 then 方法的类型（thenable），而不是死认 Promise 这个类，所以自定义时遇到自定义的 thenable 也能正确解包。

拼上 ReturnType，就是最常用的那记组合拳：Awaited<ReturnType<typeof fetchUser>> 一步拿到 async 函数的真实返回类型。想反复用，就封装成一个专用工具：

type AsyncReturnType<T extends (...args: any) => Promise<any>> = Awaited<ReturnType<T>>

组合请求同样交给它。用 Promise.all 并发拉取时，结果会被推导成元组，元素类型各就各位；Promise.allSettled 会给出一组带 status 的联合——成功的那支是 fulfilled 带 value，失败的那支是 rejected 带 reason；race 则给出最先完成的那个类型。用同一套解包方式，就能把它们还原成可读的具体结构。

最后是错误这一侧。先守住底线：catch 捕获到的 error 类型是 unknown，必须配合类型守卫才能安全使用，if (error instanceof Error) 之后再去读 message。想让错误进入类型体系，就在返回值上做建模——用可辨识联合把「成功」与「失败」两种结构显式分开：

type ApiResult<T> = { success: true; data: T } | { success: false; error: string }

调用方只要在 success 上分支，就能拿到对应分支独有的字段：为真时有 data，为假时有 error、不会有 data。错误从一句模糊的「出事了」，变成了类型上一清二楚的两种状态。

四个要点：Awaited 会递归解开深层嵌套的 Promise，不必手写多层；catch 捕获到的 error 是 unknown，务必配合类型守卫；它对带 then 方法的 thenable 同样适用，可作为自定义解包实现的参考；遇到嵌套 Promise 的类型问题，先检查是不是需要 Awaited，而不是直接断言。

返回类型解析对照

解包前后两层

异步返回类型的关键，是分清「函数返回的 Promise」与「Promise 解开后的值」这两层。Awaited 负责递归剥开外层，ReturnType 负责抓住函数签名，两者一拼就得到 async 函数的真实返回类型；Promise.all、allSettled、race 的结果也能据此还原。而错误同样是一种返回值，用可辨识联合把它建模出来，unknown 的 error 配上类型守卫，编译期就能覆盖两条路径。

「Awaited」会递归解包 Promise 及带 then 的对象，返回最终 resolve 出的值类型，非 Promise 则原样返回。常与 ReturnType<typeof fn> 组合取得 async 函数的真实返回类型，也用于还原 Promise.all、allSettled、race 的结构。注意 catch 里的 error 是 unknown，需配合类型守卫；遇到嵌套 Promise 先想 Awaited，别急着断言。

关键代码

TypeScript
// 异步返回类型与 Awaited：解包 Promise，获取异步函数返回值类型

// ── Awaited 基础用法 ──
// Awaited<T> 用于解包 Promise 类型

type StringPromise = Promise<string>
type UnwrappedString = Awaited<StringPromise>  // string

type NumberPromise = Promise<number>
type UnwrappedNumber = Awaited<NumberPromise>  // number

// 普通类型不变
type PlainType = Awaited<string>  // string

// ── 递归解包嵌套 Promise ──
// Awaited 会递归解包嵌套的 Promise

type NestedPromise = Promise<Promise<Promise<boolean>>>
type DeepUnwrapped = Awaited<NestedPromise>  // boolean

type DoublePromise = Promise<Promise<number[]>>
type UnwrappedArray = Awaited<DoublePromise>  // number[]

// ── 获取异步函数的返回类型 ──
// 组合 Awaited + ReturnType

async function fetchUser(id: number) {
  return {
    id,
    name: '用户' + id,
    email: `user${id}@example.com`,
  }
}

// ReturnType 得到的是 Promise<User>
type FetchUserPromise = ReturnType<typeof fetchUser>
// Promise<{ id: number; name: string; email: string }>

// 用 Awaited 解包得到实际返回值类型
type FetchUserResult = Awaited<ReturnType<typeof fetchUser>>
// { id: number; name: string; email: string }

// ── 实用类型：AsyncReturnType ──
// 封装一个便捷的工具类型

type AsyncReturnType<T extends (...args: any) => Promise<any>> =
  Awaited<ReturnType<T>>

type UserResult = AsyncReturnType<typeof fetchUser>
// { id: number; name: string; email: string }

// ── Promise.all 的返回类型 ──
// 处理多个 Promise 并发

async function getUser() {
  return { id: 1, name: 'Tom' }
}

async function getOrders() {
  return [{ id: 'O001', total: 99 }]
}

async function getDashboardData() {
  const [user, orders] = await Promise.all([getUser(), getOrders()])
  return { user, orders }
}

type DashboardData = AsyncReturnType<typeof getDashboardData>
// {
//   user: { id: number; name: string }
//   orders: { id: string; total: number }[]
// }

// ── Promise.allSettled 的返回类型 ──

async function mightFail(flag: boolean): Promise<string> {
  if (flag) return 'success'
  throw new Error('failed')
}

async function runAllSettled() {
  const results = await Promise.allSettled([
    mightFail(true),
    mightFail(false),
  ])
  return results
}

type SettledResults = AsyncReturnType<typeof runAllSettled>
// PromiseSettledResult<string>[]
// 其中每个元素是：
// - PromiseFulfilledResult<string>  { status: 'fulfilled'; value: string }
// - PromiseRejectedResult           { status: 'rejected'; reason: any }

// ── Promise.race 的返回类型 ──

async function fastResponse() {
  return 'fast'
}

async function slowResponse() {
  return 'slow'
}

async function raceDemo() {
  return await Promise.race([fastResponse(), slowResponse()])
}

type RaceResult = AsyncReturnType<typeof raceDemo>  // string

// ── try/catch 中的错误类型 ──
// catch 中的 error 默认是 unknown

async function safeFetch(url: string): Promise<{ data: string } | null> {
  try {
    const response = await fetch(url)
    const data = await response.json()
    return { data }
  } catch (error) {
    // error 类型为 unknown，需要类型守卫
    if (error instanceof Error) {
      console.error('请求失败:', error.message)
    }
    return null
  }
}

// ── 自定义 Awaited 实现 ──
// 理解 Awaited 的工作原理

type MyAwaited<T> = T extends Promise<infer U>
  ? U extends Promise<any>
    ? MyAwaited<U>
    : U
  : T

// 测试
type Test1 = MyAwaited<Promise<string>>           // string
type Test2 = MyAwaited<Promise<Promise<number>>>  // number
type Test3 = MyAwaited<boolean>                    // boolean

// ── 带 then 的对象（thenable） ──
// Awaited 也能处理有 then 方法的对象

type Thenable<T> = { then: (onfulfilled: (value: T) => any) => any }

type ThenableString = Thenable<string>
type UnwrappedThenable = Awaited<ThenableString>  // string

// ── 实用场景：API 响应封装 ──

interface ApiResponse<T> {
  code: number
  message: string
  data: T
}

async function request<T>(url: string): Promise<ApiResponse<T>> {
  const res = await fetch(url)
  return res.json()
}

async function getCourses() {
  const res = await request<{ id: number; title: string }[]>('/api/courses')
  return res.data
}

type CourseList = AsyncReturnType<typeof getCourses>
// { id: number; title: string }[]

// ── 延迟类型：模拟 sleep ──

function sleep(ms: number): Promise<void> {
  return new Promise(resolve => setTimeout(resolve, ms))
}

async function delayedGreet(name: string) {
  await sleep(1000)
  return `Hello, ${name}!`
}

type DelayedResult = AsyncReturnType<typeof delayedGreet>  // string

console.log('异步返回类型演示完成')
