枚举、常量枚举与字面量映射

比较枚举与联合字面量在状态建模中的差异和适用场景。

开场问题：课程状态写成 enum CourseStatus { Draft, Review, Published, Archived }，可打印出来是 0、1、2——日志里根本分不清哪个是「已发布」，枚举的名字去哪了？

状态集合与枚举

你要给课程的发布流程建模：草稿、审核中、已发布、已归档，一共四个状态。用字符串硬编码会让魔法字符串散落各处，于是你想到枚举——它看起来既能当类型用、又能当值用，还有自动补全。可用起来很快撞上两个疑问：为什么日志里打出的是数字而不是名字？为什么把状态存进接口之后，别人拿到 2 完全不知道对应哪个状态？

枚举不只是「一组常量」，它同时产出运行时的对象。这层运行时代价与伴随的行为，才是选型真正要权衡的地方。

数字枚举写法

先用数字枚举：enum CourseStatus { Draft, Review, Published, Archived }。成员依次是 0、1、2、3，写法最省事，比较大小也方便，status < CourseStatus.Archived 这样的判断直接可用。

它做对了一件事：把「一组合法状态」收敛成单一来源，类型与取值共用同一个名字。这个目标完全正确，后面的方案也都在保留它。

反向映射代价

  • 数字枚举的值是数字，序列化到接口或日志后只剩下 2，脱离代码就失去意义。
  • 它会生成反向映射：除了 CourseStatus.Draft → 0，还多了 CourseStatus[0] → 'Draft'；用 Object.entries 遍历时会同时拿到两组键，必须额外过滤。
  • 还有一个隐形陷阱：任何数字都能赋给数字枚举成员，const s: CourseStatus = 99 竟然不报错，状态的合法性并没有被真正约束住。
  • 枚举会产出运行时代码，虽然体积不大，但无法被树摇掉，作为库对外导出时还要考虑转译兼容性。

字符串枚举形式

把值换成字符串，就得到字符串枚举：enum CourseLevel { Beginner = 'beginner', Advanced = 'advanced' }。它只有正向映射，序列化出去就是可读的字符串，跨代码边界也不会失真；代价是失去自动递增与大小比较的能力。

若在意产物体积，可以换成 const enum：它在编译期把成员直接内联成字面量，运行时完全不产出对象。但这里有两个必须记住的坑：const enum 依赖编译器看到使用现场才能完成内联，在库的 .d.ts 声明里、以及配合 isolatedModules 的单文件转译流程下都存在兼容风险——一块文件一块文件地转译时，编译器根本没有全局信息去内联。因此对外发布的类型中应避免导出 const enum，也不要使用 declare const enum 这类 ambient 形式。

更现代的选择是干脆不用枚举，改用 as const 对象配合联合字面量：

const STATUS = { Draft: 'draft', Published: 'published' } as const， type Status = typeof STATUS[keyof typeof STATUS]。

这样得到的对象就是一个普通常量，能被树摇；由它派生的联合类型既精确又轻量。若想给每个状态补一条中文说明，就用 Record<Status, string> 把映射收敛成一张表，保证「新增状态必须补上说明」，漏了就立刻报错——这正是 satisfies 与联合字面量配合起来最顺手的地方：既校验了完整性，又保住了字面量类型。

选择 as const 还有一个常被忽略的好处：派生出来的对象就是普通值，可以直接参与逻辑判断、可以序列化、可以随手传进函数；而枚举成员在写法上处处受限，需要额外的转换才能参与比较。当状态还要与接口字段、路由参数一一对应时，这一点尤其省事。

一句话选型：需要运行时可枚举、且只在应用内部使用时，用字符串枚举；明确不对外发布又追求零运行时开销时，可用 const enum；更推荐 as const 加联合字面量——产物最轻、组合最灵活，再用 satisfies 与 Record 反过来校验配置是否完整。
用 Object.entries 遍历数字枚举时，记得过滤反向映射产生的键（例如用 isNaN(Number(key)) 判断），否则状态列表里会混进一堆数字键。

两种枚举对照

枚举与联合取舍

枚举与联合字面量解决的是同一件事：把有限的状态集合收敛成单一来源，让非法取值无法通过编译。区别在于枚举会产出运行时对象，数字枚举还带着反向映射与「任意数字都能赋值」的漏洞；const enum 会内联但不适合对外发布；as const 加联合字面量产物最轻，配合 satisfies 与 Record 还能反过来校验配置的完整性。

「枚举与常量断言」enum 提供运行时值，数字枚举有正反双向映射且不阻止任意数字赋值，字符串枚举只有正向映射、更利于序列化；const enum 在编译期内联成员、不产出运行时对象，但在 .d.ts 与 isolatedModules 场景下有兼容风险，不应对外导出。用 as const 对象配合 typeof 与 keyof 可派生联合字面量，产物更轻，再用 satisfies、Record 反向校验配置完整性。

关键代码

TypeScript
// 枚举、常量枚举与字面量映射

// ── 数字枚举 ──
// 自动递增（默认从 0 开始），支持反向映射
enum CourseStatus {
  Draft = 0,
  Review = 1,
  Published = 2,
  Archived = 3,
}

const s: CourseStatus = CourseStatus.Published  // 2
const name = CourseStatus[2]                     // 'Published'（反向映射）

// ── 字符串枚举 ──
// 每个成员必须有字符串初始值，无反向映射
enum CourseLevel {
  Beginner = 'beginner',
  Intermediate = 'intermediate',
  Advanced = 'advanced',
}

// 枚举成员可以作为类型使用
type PublishedOrArchived = CourseStatus.Published | CourseStatus.Archived

// ── const enum ──
// 编译时完全内联，不生成运行时对象，减小产物体积
// 注意：不要把 ambient const enum 发布给下游；独立转译和版本错配时容易踩坑
const enum Direction {
  Up = 'UP',
  Down = 'DOWN',
  Left = 'LEFT',
  Right = 'RIGHT',
}
const move: Direction = Direction.Up  // 编译后直接替换为 'UP'

// ── 联合类型 vs 枚举 ──
// 联合类型更轻量，适合简单场景
type StatusUnion = 'draft' | 'review' | 'published' | 'archived'

// 枚举的优势：可遍历、可反向映射、语义更清晰
// 联合类型的优势：无运行时开销、树摇友好、搭配 as const 也很强

// ── as const 对象：枚举的替代方案 ──
const STATUS = {
  Draft: 'draft',
  Review: 'review',
  Published: 'published',
  Archived: 'archived',
} as const

type StatusFromConst = typeof STATUS[keyof typeof STATUS]
// 'draft' | 'review' | 'published' | 'archived'

// ── satisfies 运算符 + Record 映射 ──
// 确保每个枚举成员都有对应配置，且不丢失类型推导
const statusConfig = {
  [CourseStatus.Draft]:     { label: '草稿', color: '#999' },
  [CourseStatus.Review]:    { label: '审核中', color: '#f90' },
  [CourseStatus.Published]: { label: '已发布', color: '#0a0' },
  [CourseStatus.Archived]:  { label: '已归档', color: '#c00' },
} satisfies Record<CourseStatus, { label: string; color: string }>

console.log(statusConfig[CourseStatus.Published].label)  // 已发布

// ── 枚举遍历 ──
function getStatusLabels(): string[] {
  return Object.entries(CourseStatus)
    .filter(([key]) => isNaN(Number(key)))
    .map(([label]) => label)
}

console.log(getStatusLabels())  // ['Draft', 'Review', 'Published', 'Archived']
