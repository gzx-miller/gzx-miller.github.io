函数类型、重载与断言函数

为 API 编写重载签名，用断言函数做运行时类型守卫。

开场问题：同一个 fetchCourse，传单个 id 时返回课程详情、传 id 数组时返回列表，可返回值类型只能写成两者的联合——调用处每次都要再判断一次，编译器为什么帮不上忙？

输入输出错配

你要写一个查询函数：传单个 id 时返回一份课程详情（带 teacher、duration），传 id 数组时返回一个课程列表。参数写成联合 number | number[] 当然能编译通过，但返回类型就变成了 CourseDetail | Course[]：拿到结果的一方根本不知道这次会得到哪一种，只能自己写判断，或者干脆断言。输入与输出之间的对应关系，在这里彻底丢失了。

还有一类更常见的问题：数据来自接口或本地 JSON，类型是 unknown。你想在校验通过之后把它安全地当业务类型使用，可写一个返回 boolean 的检查函数，编译器并不会因为「你检查过了」就改变对它的看法。

函数类型与签名

先把函数形状本身写好。函数类型最简单的写法是类型表达式 (x: number) => CourseDetail；如果这个函数还得挂载额外属性（比如缓存、元信息），就换成调用签名： interface Fetcher { (id: number): CourseDetail; cache: Map<number, CourseDetail> }。后者描述的是「可调用的对象」，比单纯的箭头类型多了一层属性。

至于两种输入形态的查询，先用一个更宽的类型顶上去：function fetchCourse(input: number | number[]): CourseDetail | Course[]。它做对了一件事：承认这个函数确实有两种输入与两种输出，实现里再按 typeof input === 'number' 分支处理，逻辑本身并没有错。

联合返回值歧义

  • 返回值被合并成联合，调用方拿到结果后无法直接确定是哪一种，输入与输出的对应关系丢失了。
  • 想访问 result.teacher 还得先判断，或者退化成类型断言，安全边界又被绕了过去。
  • 校验函数若只返回 boolean，unknown 依旧是 unknown，检查结果没有被编译器采纳。
  • 判断逻辑散落在每个调用点，重复、易漏，还难以统一维护。

重载签名拆分

第一步，把「输入形状 → 输出类型」的对应关系写成多条重载签名：先声明 function fetchCourse(id: number): CourseDetail，再声明 function fetchCourse(ids: number[]): Course[]，最后才写真正带分支的实现签名。实现签名对外不可见，调用时命中的是前面那些签名——传单个 id 就精确得到 CourseDetail，传数组就精确得到 Course[]。

顺序是有意义的：匹配严格按照声明顺序进行，重载签名必须从最具体排到最宽泛。若把宽泛的签名写在前面，后面的具体签名就永远轮不到，等于白写。另外重载数量不宜过多，超过三四个就该考虑改用联合参数或对象配置，可读性会好得多。

第二步，解决 unknown 的收窄。写一个返回类型为断言签名的函数：function assertCourse(obj: unknown): asserts obj is Course。它的返回值不再是 boolean，而是在运行时真的做检查，一旦不满足就直接抛错；只要这次调用没有抛异常，之后的代码里编译器就把 obj 当作 Course。它的价值不在于返回了什么，而在于调用之后类型被收窄了——这正是把不可信数据安全引入类型系统的钥匙。

第三步，把 this 的约束也纳入函数类型。函数的第一个参数位置可以放一个伪参数 this: T，用来精确限定方法内 this 的形状，避免在回调或方法被抽取时 this 悄悄退化。

回头看，这三个工具其实在回答同一件事：如何让「类型」与「运行时的真实行为」保持一致。重载把编译期的输入输出关系写准，断言函数则把运行时的校验结果反馈回编译期，两者一前一后，把函数边界上的不确定性收拾干净。

写法适用场景
(x: T) => R 类型表达式普通函数形状，最常见
调用签名 { (x: T): R }需要在函数上附加属性
重载签名同一函数按输入返回不同精确类型
断言函数 asserts x is T运行时校验，并让后续代码自动收窄

调用结果差异

签名对应关系

函数类型的核心，是把「输入与输出的对应关系」写进签名里：需要附加属性就用调用签名，多种输入各自对应不同输出就用重载并按由具体到宽泛排序，消费 unknown 就用断言函数把校验与收窄合成一步。签名一旦精确，调用处的判断逻辑就都省下来了。

「函数重载与断言函数」用多条重载签名描述同一函数名在不同输入下返回的精确类型，签名须由最具体到最宽泛排列，实现签名对外不可见；断言函数返回 asserts value is T，在运行时校验并让编译器在调用后自动收窄参数类型。函数形状可用 (x: T) => R 或调用签名表达，this: T 伪参数用于约束方法内的 this。

// ── 函数重载 ──
interface Course { id: number; title: string }
interface CourseDetail extends Course { teacher: string; duration: number }

// 重载签名：编译器根据参数类型选择匹配的签名
function fetchCourse(id: number): CourseDetail
function fetchCourse(ids: number[]): Course[]
function fetchCourse(input: number | number[]): CourseDetail | Course[] {
  if (typeof input === 'number') {
    return { id: input, title: `课程${input}`, teacher: '松松', duration: 120 }
  }
  return input.map(id => ({ id, title: `课程${id}` }))
}

const detail = fetchCourse(1)      // CourseDetail（自动推导）
const list = fetchCourse([1, 2])   // Course[]

// ── 断言函数（Assertion Functions） ──
// asserts 签名：调用成功后，TypeScript 自动收窄参数类型

function assertDefined<T>(value: T | null | undefined): asserts value is T {
  if (value == null) throw new Error('值不能为空')
}

function assertCourse(obj: unknown): asserts obj is Course {
  if (typeof obj !== 'object' || obj === null) throw new Error('不是对象')
  if (!('id' in obj && 'title' in obj)) throw new Error('缺少课程字段')
}

function process(raw: unknown) {
  assertCourse(raw)
  // 此处 raw 已自动收窄为 Course
  console.log(raw.title)
}

// ── 构造函数类型 ──
type Constructor<T = object> = new (...args: any[]) => T

class Lesson {
  constructor(public title: string, public id: number) {}
}

function createInstance<T>(Ctor: Constructor<T>, ...args: any[]): T {
  return new Ctor(...args)
}

const lesson = createInstance(Lesson, 'TypeScript 基础', 42)
