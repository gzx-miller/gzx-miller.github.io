泛型：复用类型关系

用通用 API 响应保留课程列表的精确数据类型。

开场问题：同一个响应包装函数，既要装课程列表、又要装用户信息，写成 any 什么都能装，可调用方却再也拿不到字段提示——能不能既只写一份实现，又保住 result.data 的精确类型？

重复实现与冲突

课程页和用户页都需要一层 { data, message } 的响应外壳：请求成功时把负载塞进 data，再附一句提示。实现逻辑完全相同，你自然想把它抽成一个工具函数复用。

可一旦抽出来，问题就来了：课程列表是 Course[]，用户信息是另一个形状，这个函数该怎么描述它的输入输出？退一步用 any 最省事，但通用性是用丢掉全部类型信息换来的——调用方拿到 any 之后，result.data 里有什么全靠记忆。所以真正要解决的是：如何复用 API、列表与工具函数的实现，同时不丢失类型之间的精确关联。

任意类型入参

最省事的做法，是让函数不关心负载类型，直接收 any：

function success(data: any) { return { data, message: '读取成功' } }

它做对了一件实实在在的事：实现只有一份，课程、用户乃至任何数据都能复用它，不需要为每种数据类型复制粘贴一遍。这正是「复用」最核心的诉求。

类型信息丢失

  • 返回的 data 是 any，元素的类型、字段名全部丢失。
  • 调用方对 any 做任何操作都不报错，写法再错也要等到运行时才暴露。
  • 想换成 unknown 更安全，却更啰嗦：每次使用前都得先做类型判断。
  • 若为课程、用户各写一份实现，就退回了复制粘贴，复用性荡然无存。

泛型参数化建模

不推翻「一份实现多处复用」，而是让类型本身也变成一个变量——这就是泛型。把会随调用而变的负载类型抽成类型参数 T，让它同时出现在参数与返回类型里：

interface ApiResult<T> { data: T; message: string }
function success<T>(data: T): ApiResult<T> {
  return { data, message: '读取成功' }
}

这里的 T 像函数的参数一样，只是一个占位。调用 success(courses) 时，实参类型 Course[] 会自动推导出 T，返回值就是 ApiResult<Course[]>，于是 result.data[0].title 精确可用。泛型的要害正在于它保住了输入与输出之间的关系：入参是什么元素类型，返回值就是什么元素类型。

  • 类型参数名应表达角色，如 T、Item、Key、Value；单字母仅用于最常见的泛型场景。
  • 仅在定义一个位置出现、与其他类型无关的参数通常没有价值，可用具体类型替代。
  • 泛型约束（如 T extends object）让实现侧能安全访问传入类型的公共属性。
  • 把重复出现的具体类型抽成类型参数，是重构泛型最常用的切入点。

如果实现内部需要访问传入类型的公共属性，就得给类型参数加上泛型约束，写成 T extends object 之类：形状满足约束的实参才允许传入，实现侧也才敢安全地读取这些属性。而日常重构里最常用的切入点，是把反复出现的具体类型抽成类型参数——当同一段逻辑里 Course、User 各写了一遍，那个位置往往就该是一个 T。

对比最小方案就能看清收益：它同样是「一次实现、处处复用」，却避开了退化成 any 或 unknown 后丢失类型信息的老路。泛型并不神秘，它只是把「此处类型由调用方决定」写进签名，让编译器沿着参数与返回值把这份关系串起来。

列表响应精确类型

最直接的验证方式是：故意传一个类型不符的实参，观察报错是否顺着泛型链路出现在调用处，而不是等到运行时才暴露。链路一旦成立，类型错误就止步于调用边界。

入参与返回值一致

泛型是把类型当作变量来建模的手段：函数、类与容器复用同一份实现，而具体的类型参数在调用时由实参自动推出。它让「入参的元素类型」与「返回值里的元素类型」保持一致，既留下了复用的便利，又没有付出丢掉类型信息的代价。

「泛型」指把类型本身当作参与建模的变量：函数、类与容器复用同一份实现，调用时由实参自动推导出具体的类型参数（如 success<T>），从而保持输入与输出之间的精确关系，避免为换取通用性而退化为 any 或 unknown 后丢失全部类型信息。类型参数名应表达角色，仅在单处出现且无关联的参数通常可用具体类型替代。

关键代码

TypeScript
// 泛型：让类型关系跟随参数流动
interface ApiResult<T> {
  data: T
  message: string
}

// T 在调用时由参数决定，返回值保留精确类型
function success<T>(data: T): ApiResult<T> {
  return { data, message: '读取成功' }
}

interface Course {
  id: number
  title: string
}

const courses: Course[] = [
  { id: 1, title: '组合式 API' },
  { id: 2, title: '组件通信' },
]

// result.data 精确推导为 Course[]
const result = success(courses)
console.log(`${result.message}，共 ${result.data.length} 门课程`)
