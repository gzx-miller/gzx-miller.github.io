keyof 与索引访问类型

构建只能读取合法配置键的设置面板。

开场问题：设置面板要按配置项名字读值，写 preferences['theme'] 没问题，可手滑写成 preferences['themes'] 只会静默拿到 undefined——有没有办法让拼错的键名根本编译不过？

动态属性访问

设置面板里有主题、密度、语言三项配置，每一项既要能读值，也要能按名字被动态访问。你希望函数接收一个「键名」参数，再按键取值，这样就不必为每一项各写一个读取函数。

麻烦出在键名的类型上：如果把它写成 string，那么 readSetting('themes') 这种拼错也能通过编译，错误直到运行时才以 undefined 的形式冒出来；而即使拼对了，返回值类型也说不清。所以真正要解决的是：动态访问对象属性时，如何避免键名拼写错误，并让返回值类型同步精确。

字符串键名入参

最省事的做法，是接受一个字符串键名，直接去对象上取值：

function readSetting(key: string) { return preferences[key] }

它做对了一件很实用的事：函数确实实现了「按名字动态取值」，调用方不必为每一项写一个专用函数，设置面板的每一行都能复用同一条读取路径。

键名类型过宽

  • 键名类型是 string，任何拼写都能传入，错字要到运行时才暴露成 undefined。
  • preferences[key] 的返回类型只能退成宽泛的联合，甚至被认为是 any。
  • 按 'theme' 取值本应得到 string，这份精确信息被一并抹平了。
  • 没有单一来源描述「合法的键有哪些」，键名散落在各处，改名时无法被编译器追踪。

属性与键名契约

把这些不足归纳起来，本质是：对象属性和字符串之间缺少一层契约。对象类型明明写清了有哪些字段，可一旦改用字符串去访问，这层信息就断掉了——键名和返回值类型同时失守。键名一旦拼错，编译器不但拦不住，还会把返回值一并放行成宽泛类型，错误于是被藏得更深。

解决思路是把「键」和「值」分成两件工具来处理。keyof 从一个对象类型取出全部属性键，组成一个字面量联合类型；索引访问类型 T[K] 再按键取回对应的值类型。把两者一起用在函数签名上：

type PreferenceKey = keyof Preferences
  // 'theme' | 'density' | 'language'
function readSetting<K extends keyof Preferences>(key: K): Preferences[K] {
  return preferences[key]
}

这样一来，键名受 K extends keyof Preferences 约束，传入不存在的键会被编译器直接拦下；返回值 Preferences[K] 则随传入的键精确变化——传 'theme' 得到 string，若对象里有数字型的键，取到就是 number。动态属性访问从此既灵活，又不可能拼错键名。

  1. 用 keyof 从对象模型提取合法键的联合，例如 PreferenceKey。
  2. 让函数参数受该键联合约束，传入不存在的键名会被编译器拦截。
  3. 通过索引访问 T[K] 取得与键匹配的值类型，保证返回类型随键同步精确。
  4. 传入不存在的键名，验证编辑器在调用处直接标红。
三个容易踩空的地方：Object.keys 默认返回 string[]，必要时通过类型断言或工具函数把它收窄为具体键；不要用宽泛的 string 索引签名绕过键约束，那等于重新回到 any 模式；结合 as const 与 satisfies，则能保留更精确的字面量联合与对象结构，与 keyof 配合效果更好。

实际使用时还有一处细节值得留意：把键名单独抽成一个具名联合，例如 type PreferenceKey = keyof Preferences，能让「合法键有哪些」这件事在代码里有个可引用的名字。按钮列表、校验函数与读取函数都能复用这一份定义，改模型时也只需改一处，不必再逐个文件地对照。

把参数类型写成 K extends keyof T，是动态访问的通用防御姿势：先固化合法的键，再按键取值。键与值的类型都来自同一份模型，谁改了模型，所有受牵连的位置都会被编译器点出来。

返回值随键变化

键联合与索引访问

keyof 与索引访问类型，把「对象有哪些合法键、每个键对应什么类型」交还给类型系统。keyof 给出键的联合，T[K] 给出值的类型，把两者写进函数签名，动态属性访问就能同时拿到灵活性与精确性，拼错的键名在编辑阶段就被拦下。

「keyof 与索引访问类型」keyof T 从一个对象类型取出全部属性键、组成字面量联合；T[K] 再按键取回对应的值类型。把两者用作函数参数类型（如 K extends keyof T），动态属性访问既灵活又不可能拼错键名，返回值类型还会随传入的键精确变化——传 'name' 得到 string，传数字型的键得到 number。切勿用宽泛的 string 索引签名绕过键约束。

关键代码

TypeScript
// keyof：从对象类型提取所有键名组成联合类型
interface Preferences {
  theme: string
  density: string
  language: string
}

// PreferenceKey = 'theme' | 'density' | 'language'
type PreferenceKey = keyof Preferences

// 索引访问类型：preferences[key] 返回对应值类型
function readSetting(prefs: Preferences, key: PreferenceKey) {
  return prefs[key]  // 类型为 string
}

const prefs: Preferences = { theme: '秋日', density: '舒适', language: '中文' }
const keys: PreferenceKey[] = ['theme', 'density', 'language']

console.log(readSetting(prefs, 'theme'))  // 秋日

// 非法键名在编译期报错
// readSetting(prefs, 'fontSize')  → 类型错误
