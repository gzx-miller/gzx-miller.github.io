映射类型与键转换

用映射类型批量转换属性，掌握修饰符和键重命名。

开场问题：同一个课程模型，要一份「字段全只读」的展示类型、一份「字段全可选」的补丁类型，难道每加一个字段，就要把 id、title、teacher 这些名字在各个版本里再抄一遍？

模型三种变体

你在维护课程后台。一份课程对象有 id、title、teacher、duration、published 五个字段。业务很快提出三类需求：编辑表单要一份「字段全可选」的补丁类型，详情页要一份「字段全只读」的展示类型，序列化到缓存前还要一份把每个字段包成 getXxx() 的访问器类型。你手上只有一份 CourseModel。

每个需求都手写一遍字段清单，最要命的不是当时写得累，而是字段一改动，这几份类型会悄悄漂移：模型加了 cover，补丁类型忘了补，编译器不会报错，运行时却少同步了一个字段。所以真正的痛点不是「少写几行」，而是「同一份结构被复制成了多个互相独立的真相」。

手写只读类型

最朴素的做法是逐字写出来——把只读这件事直接写进类型里：interface ReadonlyCourse { readonly id: number; readonly title: string; ... }。

这个写法做对了一件事：把「只读」这个意图显式地表达在了类型上，读代码的人一眼就能看出它不能被修改。这种「用意清楚的类型」要保留。问题只出在它是怎么被写出来的——它把字段当成了要复述的内容。

副本与模型分叉

  • 写好的类型是「定格」的：模型新增或重命名字段时，这份手写类型不会跟着动，两边就此分叉。
  • 需要「只读」「可选」「访问器」三套时，就要把字段清单复制三遍，任何一处漏改都是隐性缺陷。
  • 手写类型与模型之间没有任何绑定，编译器无法帮你核对它们是否一致。
  • 维护成本随「字段数 × 需求数」一起涨，字段一多就很难保证不出错。

映射类型遍历

把「列举字段」这件事交还给编译器。既然 keyof T 已经能给出一个类型上所有键组成的联合，就不必再手写键名——真正要描述的不是「哪几个字段」，而是「对每个字段做什么变换」。这就是映射类型：用 [K in keyof T] 遍历 T 的每一个键 K，右侧用索引访问 T[K] 取回该键对应的值类型。

于是「把每个属性变成只读」只需要一行： type ReadonlyCourse = { readonly [K in keyof CourseModel]: CourseModel[K] }。 这里没有出现任何具体字段名，字段增删都会自动反映到结果上。顺着这条线索，你也解释清了一件旧事：Readonly<T>、Partial<T>、Pick<T, K> 为什么长得那么像——它们不过是同一套映射语法配上不同的修饰符。

接下来是修饰符。? 让属性变为可选，前缀 - 表示把它去掉：{ [K in keyof T]?: T[K] } 得到全可选版本，{ readonly [K in keyof T]: T[K] } 得到全只读版本，-readonly 与 -? 则把只读或可选重新剥掉。

再往下是键重命名。用 as 子句可以在生成属性的同时改写键名，比如给每个字段生成一个取值的方法。这里有一个必须记住的坑：参与字符串拼接之前，键要先收窄为 string，也就是写成 string & K：

type GetterMap = { [K in keyof CourseModel as `get${Capitalize<string & K>}`]: () => CourseModel[K] }

如果某个键不该出现在结果里，就把它重命名成 never，这类键会被自动过滤掉——这是映射类型的「过滤」手法，与重命名共用同一条路径。

最后交代两条边界。其一，映射类型只作用在当前这一层：模型里若有嵌套对象，内层属性不会被一并转换，想深入必须配合递归条件类型逐层下钻。其二，as 子句里的新键必须能与模板字面量兼容，拼不出字符串的键会被静默过滤，别指望它报错来提醒你。

回看这一步的意义：映射类型并没有引入任何新的信息，它做的只是让同一份信息以不同形态出现——原模型是唯一的真相，只读、可选、重命名都只是从它出发的一个视角。视角由规则生成，就永远不会与真相脱节；而手写复制出的类型，本质上是一个迟早会走样的副本。

逐键遍历覆盖

变换规则描述

映射类型把「复制字段清单」换成了「描述变换规则」：[K in keyof T] 负责遍历，修饰符负责调整读写与可选，as 子句负责重命名与过滤。从此模型是唯一的真相，只读版、可选版、访问器版都从它派生出来，字段一改动，每一处都会自动跟上。

「映射类型」用 [K in keyof T] 遍历已有类型的全部键并逐个生成新属性，可叠加 readonly、? 及其 - 前缀来调整修饰符，再用 as 子句重命名键（键需先收窄为 string，如 string & K）或映射为 never 以过滤。它只作用于当前一层，深层结构需配合递归类型；Partial、Readonly、Pick 等内置工具都由它实现。

关键代码

TypeScript
// 映射类型：遍历已有类型的键，生成新的类型结构

interface CourseModel {
  id: number
  title: string
  teacher: string
  duration: number
  published: boolean
}

// ── 基础映射：遍历所有键 ──
type ReadonlyCourse = { readonly [K in keyof CourseModel]: CourseModel[K] }
type NullableCourse = { [K in keyof CourseModel]: CourseModel[K] | null }

// ── 修饰符：+/- readonly、+/- ?（可选） ──
type AllOptional = { [K in keyof CourseModel]?: CourseModel[K] }
// 移除可选（-?）：将所有可选属性变为必填
type AllRequired<T> = { [K in keyof T]-?: T[K] }
// 移除只读（-readonly）
type Mutable<T> = { -readonly [K in keyof T]: T[K] }

type RequiredCourse = AllRequired<AllOptional>  // 所有属性重新变为必填

// ── 键重映射（as 子句） ──
// 给每个键加 get 前缀，生成 Getter 方法映射
type GetterMap<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K]
}
type CourseGetters = GetterMap<CourseModel>
// { getId: () => number; getTitle: () => string; getTeacher: () => string; ... }

// ── 模板字面量 + 映射类型 ──
// 生成 setter 方法映射
type SetterMap<T> = {
  [K in keyof T as `set${Capitalize<string & K>}`]: (value: T[K]) => void
}

// ── 过滤键：用 never 排除不需要的键 ──
type StringKeysOnly<T> = {
  [K in keyof T as T[K] extends string ? K : never]: T[K]
}
type CourseStrings = StringKeysOnly<CourseModel>  // { title: string; teacher: string }

// 排除函数类型的键
type NonFunctionKeys<T> = {
  [K in keyof T as T[K] extends Function ? never : K]: T[K]
}

// ── 实用示例：表单校验 Schema 生成 ──
type ValidationSchema<T> = {
  [K in keyof T]: {
    required: boolean
    validator: (value: T[K]) => string | null  // 返回错误信息或 null
  }
}

const courseSchema: ValidationSchema<CourseModel> = {
  id:        { required: true,  validator: v => v > 0 ? null : 'ID 必须为正数' },
  title:     { required: true,  validator: v => v.length >= 2 ? null : '标题至少2个字' },
  teacher:   { required: true,  validator: v => v.length > 0 ? null : '讲师不能为空' },
  duration:  { required: false, validator: v => v >= 0 ? null : '时长不能为负' },
  published: { required: false, validator: () => null },
}

console.log(courseSchema.title.validator('好'))  // null（通过校验）
