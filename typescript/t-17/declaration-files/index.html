声明文件与全局类型增强

掌握 .d.ts 声明文件的编写模式、全局增强和第三方库类型补充。

开场问题：你导入了项目里那个老牌图表库，代码明明能跑，编辑器却提示「找不到模块的类型声明」并画上红线，类型提示一片空白——这行红线到底该怎么消掉？

缺少类型声明报错

你在一个 TypeScript 项目里引入了一个只提供 JavaScript 的第三方库，或者读取了一个 .css、.svg 资源文件。运行时一切正常，可编辑器全程标红，属性没有提示，参数没有约束；strict 模式下甚至直接编译不过，构建流水线卡在这一步。

根子在于：TypeScript 只认识「带类型信息的东西」。JavaScript 库、图片、样式这些模块在编译期没有任何类型声明，编译器无从判断它们导出的是什么。你要么给它补一份类型，要么就得把这段代码的检查整体关掉——而后者等于放弃类型安全，把风险留给运行时。

模块声明补齐

最省事的做法：在项目里加一行 declare module 'some-js-lib'，直接告诉编译器「这个模块存在，别管它导出什么」。红线立刻消失，编译也能通过。

这个方案做对了一件最基本的事：它把「模块是否存在」和「模块里有什么类型」拆开了，先保证编译能过。对于实在来不及补类型的临时场景，它确实能救急，而且只需一行。

空声明类型退化

  • 这样声明的导出通通是 any，参数传错、属性拼错都不会报错，这段代码等于退回「没有类型」的状态。
  • 构建工具注入的全局变量、编译期替换的常量，编译器完全不知道它们存在。
  • 挂在 window 上的自定义属性、给内置对象加的方法，写了也没有类型，编辑器一片空白。
  • 图片、样式这类资源文件的导入没有统一约定，每一处都要单独处理。

声明文件载体

不推翻「用声明补齐类型」，而是把声明写得有内容、有边界，并且分清它落在哪个作用域。这些声明的载体，就是声明文件 .d.ts——它只写类型，不含任何实现代码。

第一类是对环境本身的声明。用 declare const、declare function 描述「运行时确实存在，但实现不在这个文件里」的东西，比如构建工具注入的 __APP_VERSION__，或全局的埋点函数 ga。这样你在业务里调用它们时，类型提示和检查都在。

第二类是给第三方模块补类型，用 declare module 按模块声明导出。三种写法各有分工：

  • 完整声明：在 declare module 'lodash' 里逐条写清导出的签名，类型提示和检查立刻到位。
  • 资源文件：用通配符声明 declare module '*.module.css'，把样式导入约定成字符串到字符串的映射，一次配置全局生效。
  • 优先装类型包：库有官方或社区维护的类型包时（如 @types/xxx），直接安装远比手写可靠，也更省事。

第三类是要动全局类型的情况。给 window 挂初始化状态、给 String 或 Array 增补方法，用 declare global 追加成员。这里有一条硬规则必须记住。

declare global 只在模块文件中生效——也就是文件顶部必须有 import 或 export。纯脚本文件里写它不会报错，却也不会起作用，这一点极其容易踩坑。扩展时以 interface Window 追加属性即可，声明文件里不要写任何实现。

最后是让编译器「看见」这些声明：把声明文件放进 tsconfig 的 include 范围，或用 types 字段指定，编辑器才会加载它们。三斜线指令 /// <reference types="node" /> 是更早的引用方式，现代项目里优先用 types 与 lib 替代它。

还有两个实践细节值得留意：声明文件与源码并置时注意命名约定，别被当成实现文件参与打包；第三方增强最好集中到统一的声明目录管理，散落在各处会很难追踪谁改了什么。

四类声明用途

类型世界接口层

声明文件是 TypeScript 与「没有类型的 JavaScript 世界」之间的接口层。用 declare 描述环境里存在的东西，用 declare module 为缺类型的模块补导出，用 declare global 扩展全局对象——它只承载类型，不产生任何运行时代码，补得越具体，收获的检查就越真实。

「声明文件」指 .d.ts 文件，只包含类型信息、不含实现。declare const / declare function 描述环境中存在但实现别处的变量与函数；declare module 为无类型库或资源文件补导出，其中简写形式会把导出视为 any；declare global 用于扩展全局类型，且必须写在含 import 或 export 的模块文件里。第三方库优先安装 @types 类型包。

关键代码

TypeScript
// 声明文件与全局类型增强：理解 .d.ts 的作用

// ── 环境声明：declare 关键字 ──
// 告诉 TypeScript "这个东西存在，但实现不在这"

// 声明全局变量
declare const __APP_VERSION__: string
declare const __BUILD_TIME__: number

// 使用环境变量
const version = __APP_VERSION__
const buildTime = new Date(__BUILD_TIME__)

// 声明全局函数
declare function ga(event: string, data?: object): void

// ga('page_view', { page: '/home' })

// ── 声明模块：为无类型 JS 库补充类型 ──
// 当第三方库没有 .d.ts 文件时，可以自己写声明

// 声明一个模块
// declare module 'some-js-lib' {
//   export function init(options: { debug?: boolean }): void
//   export const version: string
// }

// 使用时就能获得类型提示
// import { init, version } from 'some-js-lib'
// init({ debug: true })

// 声明通配符模块（如资源文件）
// declare module '*.svg' {
//   const content: string
//   export default content
// }
//
// declare module '*.png' {
//   const src: string
//   export default src
// }
//
// declare module '*.module.css' {
//   const classes: { [key: string]: string }
//   export default classes
// }

// ── 全局类型增强：扩展已有类型 ──
// 注意：必须在模块文件（有 import/export）中使用 declare global

// 扩展 String 接口
// declare global {
//   interface String {
//     capitalize(): string
//     padLeft(length: number, char?: string): string
//   }
// }

// 扩展后就可以在字符串上调用这些方法
// const str = 'hello'
// str.capitalize()  // 'Hello'
// str.padLeft(10)   // '     hello'

// 扩展 Array 接口
// declare global {
//   interface Array<T> {
//     first(): T | undefined
//     last(): T | undefined
//     unique(): T[]
//   }
// }

// const arr = [1, 2, 2, 3]
// arr.first()   // 1
// arr.last()    // 3
// arr.unique()  // [1, 2, 3]

// ── 扩展 Window 对象 ──
// 为 window 添加自定义属性

// declare global {
//   interface Window {
//     __INITIAL_STATE__: {
//       user: { id: number; name: string } | null
//       theme: 'light' | 'dark'
//     }
//     myGlobalFunc: (msg: string) => void
//   }
// }

// 访问 window 上的自定义属性
// const theme = window.__INITIAL_STATE__.theme
// window.myGlobalFunc('hello')

// ── 命名空间声明 ──
// 为库的命名空间补充类型

// declare namespace MyLib {
//   interface Config {
//     debug: boolean
//     version: string
//   }
//
//   function configure(cfg: Partial<Config>): void
//   const config: Config
// }

// MyLib.configure({ debug: true })
// console.log(MyLib.config.version)

// ── 声明合并：接口自动合并 ──
// 同名的 interface 会自动合并

interface UserConfig {
  debug: boolean
}

interface UserConfig {
  version: string
}

// 合并后相当于：
// interface UserConfig {
//   debug: boolean
//   version: string
// }

const config: UserConfig = {
  debug: true,
  version: '1.0.0',
}

console.log('声明文件演示完成')
