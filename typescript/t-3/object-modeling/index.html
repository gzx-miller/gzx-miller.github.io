对象类型与领域建模

通过会员资料理解 interface 如何约束对象结构，并根据统一契约计算衍生值。

开场问题：会员卡面板要算出「还差多少分升级」，可接口返回的字段叫 member_level、组件里写的却是 level，两边到底以谁为准——怎么保证它们不会悄悄错开？

对象属性访问

会员资料里有姓名、等级、成长值三样东西：name、level、points。你在组件里直接读 member.name、用 1000 - member.points 算还差多少分，看上去很顺。

但这些数据其实来自三个地方：后端接口响应、组件接收的 Props、以及本地状态。每一处都各自描述了「一个会员长什么样」。代价就在这份重复里：字段一旦改名或增删，你只能靠人肉搜索；某个地方多写了一个不存在的字段，代码照常运行，只是读到 undefined，界面空白却一声不吭。所以问题不是「要不要描述对象」，而是如何把接口返回与业务对象建模成一份可维护的类型，避免字段漂移。

接口声明对象形状

最直接的做法，是给对象写一张「形状清单」——把字段名与类型集中声明一次，用它约束所有用到会员的地方。这就是 interface：

interface MemberProfile { name: string; level: string; points: number }

它做对的事很关键：用一组字段刻画了领域对象的形状，任何满足它的对象都成为合法值。组件拿到 member 时，编辑器知道它一定有 name 和 points，于是能顺着统一契约计算衍生值，比如 1000 - member.points。

字段类型标注过宽

  • 字段类型给得太宽：level: string 时，界面传入 'gold' 这种不存在的等级也照样通过。
  • 可选字段被滥用：把必然存在的 points 写成 points?，衍生计算立刻变成 number | undefined，到处要判空。
  • 拿数据库或接口字段名（如 member_level）当业务模型名，业务代码读起来像在念表结构。
  • 以为多写一个字段一定会报错，其实并非所有赋值都会检查——规则有区别。

结构化类型系统

关键前提是：TypeScript 采用结构化类型系统，它只比较类型之间的形状，而不关心这个类型来自哪次声明。所以只要字段对得上，一个对象就能当作 MemberProfile 使用——这正是 Props、接口响应与业务函数可以复用同一份契约的根据。

顺着这个前提做三处收紧。第一，把等级收成字面量联合：level: '普通' | '银卡' | '金卡'，非法等级在编译期即被拦下。第二，可选字段只用于数据确实可能缺失的场景，points 这种始终存在的放进必填区，衍生计算就不会被 undefined 污染。第三，公共模型用业务语言命名，避免与数据库或接口字段名混用，让契约和业务说法保持一致地演化。

两条赋值规则并不相同：把对象字面量直接赋给接口变量时，会执行多余属性检查，多出一个字段就报错；而先把对象赋给一个变量、再在变量之间互赋，则只比较形状，多余的字段会被放行。接口本身只描述形状，需要精确拒绝额外字段时，要靠多余属性检查或运行时校验。
  1. 识别领域对象的稳定字段与可变字段，用 interface 定义它的形状。
  2. 对象字面量必须同时满足必填字段与字段类型，缺漏或多出的字段由编译器拦截。
  3. 让组件 Props、接口响应与业务函数都复用同一份接口契约，并基于它计算衍生值。
  4. 给接口变量赋一个多出字段的字面量，观察多余属性检查的报错。

当领域模型被收敛为单一来源之后，改动一个字段，编译器会指出所有受影响的位置。契约不再靠记忆维护，而是由类型系统替你守着。

契约与类型兼容

interface 的价值不在「写了一个类型」，而在于把散落在接口、Props 与业务代码里的对象形状收拢成一份契约。结构化类型让形状相同的对象互通，多余属性检查在字面量赋值处兜底，而模型改名时编译器会替你找出所有调用点。

「interface 与结构化类型」指用一组字段刻画领域对象的形状，满足它即成为该类型的合法值。interface 只描述形状、不关心声明来源，因此 Props、接口响应与业务函数可复用同一份契约。可选字段只留给确实可能缺失的数据；对象字面量直接赋值会执行多余属性检查，变量间赋值只比较形状，两者规则不同。

关键代码

TypeScript
// interface 定义领域对象的结构契约
interface MemberProfile {
  name: string
  level: '普通' | '银卡' | '金卡'
  points: number
}

// 创建对象时必须满足接口定义
const member: MemberProfile = {
  name: '小栗',
  level: '银卡',
  points: 860,
}

// 基于接口计算衍生值
function getUpgradeGap(m: MemberProfile): number {
  return Math.max(0, 1000 - m.points)
}

console.log(`${member.name} · ${member.level}会员`)
console.log(`还差 ${getUpgradeGap(member)} 分升级`)
