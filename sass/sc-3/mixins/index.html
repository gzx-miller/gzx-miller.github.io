Mixin、参数与 @content

封装按钮尺寸规则，通过参数和内容块保留调用方扩展能力。

开场问题：三种尺寸的按钮，我把几乎相同的 padding、border-radius 声明复制了三遍；后来设计统一调了圆角，我又只改了其中两处——为什么「长得一样」的样式，改起来却要靠记性？

整组声明复用

按钮的三种尺寸、通知的四种状态、卡片的内外边距——这类需求的共同点是：要复用的不是某一个值，而是一整组声明。尺寸之间差的是数值，不是结构；状态之间差的是颜色，也不是结构。既然结构相同，它就该只写一遍。

复制粘贴的代价，在第一次写的时候完全看不出来。真正的账单在后面：设计调整一次，你得回忆自己复制过几处；新增一种尺寸，你得找到同类的那一段作为模板再抄一份。抄的过程中只要有一处笔误——少了 display、圆角写成 5px——都不会报错，界面看上去也「差不多对」。靠人眼维护的重复，迟早会分叉。

公共类与分组选择器

不引入 Sass 能力，最朴素的两种做法是：把公共声明提成一个公共类 .btn，让 .btn-sm、.btn-md、.btn-lg 只覆盖差异；或者用逗号把同类选择器合并成一条规则，如 .btn-sm, .btn-md, .btn-lg { border-radius: 6px; }。

这两种做法都做对了一件事：它们识别出了「共同部分」并只写了一处，这已经比三份复制强得多。前者还额外带来了一个好处——公共类可以写在组件根元素上，语义清晰，调试时一眼能看出这个按钮属于哪个家族。

类名与结构耦合

  • 公共类要求 DOM 上必须挂上那个类名。样式复用被硬绑到了结构上，想在一个原本没有 .btn 的元素上借用这套声明，就得回去改模板。
  • 它表达不了参数。sm 与 lg 的差距本质上是同一套规则换了输入值，而公共类只能表达「共同的部分」，差异部分依然要各写各的。
  • 它无法按条件裁剪。想要「带阴影的卡片」与「不带阴影的卡片」，只能预置两个类，再由使用方组合，组合数会随可选项成倍膨胀。
  • 逗号选择器会稀释语义。.notice, .alert, .toast 并在一起之后，这条规则到底属于谁变得模糊，日后想单独调整其中一个，就必须把它从组里剔出来。

Mixin参数化展开

不推翻「只写一遍」，而是把复用对象从「一条规则」升级为一个可以带输入、当场展开的声明生成器。这就是 Mixin：用 @mixin button-size($py, $px) 定义一段带参数的声明块，用 @include button-size(6px, 12px) 在需要的地方展开它。尺寸差异变成了实参差异，共同结构只存在一份。

Mixin 的参数支持位置参数、关键字参数与默认值，这一点让它比公共类灵活得多：默认值负责兜住最常见的场景，调用方只在需要偏离时才显式传参；关键字传参则让调用处的意图自解释，不必回去数参数顺序。

更进一步的问题是「调用方偶尔想加一点自己的东西」。如果为此再去定义一个新 Mixin，抽象就被切碎了。Sass 给出的答案是 @content：调用方在 @include 后接一个内容块，这个块会被注入到 Mixin 内部 @content 所在的位置。于是「固定结构由你定、可选补充由我填」成为可能，而不必牺牲复用。

还有一件必须放在边界上的事：入参校验。在 Mixin 内部用 @if 判断参数是否越界，配合 @error 直接中断编译——让错误的调用在编译期就失败，而不是产出一份没人注意的错误样式。想要真正用好 Mixin，先分清它和邻居的职责：

工具它产出什么什么时候用
@mixin一组 CSS 声明复用「一段样式块」，需要参数化或注入内容时
@function单个 Sass 值只是算一个值，不产生任何声明时
变量 / CSS 自定义属性一个值只复用一个值，不需要包裹结构时
代价要提前知道：Mixin 的展开方式是复制——每一次 @include 都会把这组声明原样写进调用处。因此它适合复用「一组声明」，不适合用来替代单个值，否则产物会无谓地变大。另外，如果发现 @content 里被塞进了大量规则，那通常意味着抽象层次切错了，应该拆成两个 Mixin，而不是继续往内容块里加东西。

复用边界与选型

Mixin 把「复制三遍」变成「定义一次、按参数展开多次」，并把可选扩展交给了 @content。但它不是万能胶：只复用一个值就用变量或函数，只想共享裸声明就用普通类或 CSS 自定义属性——选对了工具，抽象才不会反过来拖累你。

「Mixin」是 @mixin 定义的声明生成器，支持位置参数、关键字参数与默认值，通过 @include 展开；@content 让调用方在 @include 处注入额外声明。每次 @include 都会把声明复制到调用处，所以它适合复用「一组声明」而非单个值——只复用一个值应优先使用变量或函数。可在 Mixin 内用 @if 加 @error 校验入参，让非法参数在编译期直接失败；@content 只适合少量定制，注入过多说明抽象层次错了。

关键代码

SCSS
@mixin button-size($padding-y, $padding-x) {
  padding: $padding-y $padding-x;
  @content;
}

.button {
  @include button-size(0.625rem, 1rem) {
    font-weight: 600;
  }
}
// 可选参数优先使用 $name: value 的关键字调用，语义更稳。
