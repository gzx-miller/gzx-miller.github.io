@at-root 与嵌套上下文控制

从生成器或深层上下文中输出根级规则，并精确保留 at-rule。

开场问题：我在 .dashboard .panel 里写了一条「暗色主题下换 widget 边框」的规则，心里想要的是 .theme-dark .widget，编译出来却是 .dashboard .panel .theme-dark .widget——一条本该站在最外层的规则，凭什么被嵌套一路拖进了组件里？

嵌套与默认归属

嵌套是 Sass 最讨人喜欢的能力：把父子关系写在一起，读起来像 DOM 结构。但它背后藏着一条默认假定——只要你在某个选择器块里写规则，这条规则就属于这个选择器。每往下一层，选择器就长一截，特异性也跟着抬高。

大多数时候这条假定是对的，父子关系本来就该这么表达。可总有那么几条规则，从语义上根本不归当前组件管：主题级的颜色覆盖、打印时才生效的排版、工具类的补充、框架约定必须写在顶层的规则。它们被塞进组件里，唯一理由是「恰好这个组件需要在这儿改一下」。

不借助任何手段的代价很直接：要么把规则搬到嵌套之外，让它和组件分离，读到组件的人完全看不到「它在暗色下会变」；要么留下一条特异性极高、与 DOM 深度绑定的选择器。更隐蔽的是，选择器越长，越难被后续样式覆盖，于是你又被迫加 !important 或再叠一层选择器，陷入「越写越重」的循环，等哪天要调整结构，它就成了撬不动的那根钉子。

移到根级写规则

最朴素的做法：把这条规则直接写在组件块的外面，或者干脆另起一个文件，让它从根级出生。

这个办法确实做对了一件事：结果选择器是干净的根级选择器。.theme-dark .widget 就是 .theme-dark .widget，不继承任何父级，特异性也低。当这条规则确实只出现一次、又和上下文毫无关系时，搬出去干脆利落，读起来也不绕。

脱离组件上下文

  • 规则被搬离组件后，「这个组件在暗色下会变」这件事就从读代码的视野里消失了，就近维护的便利没了。
  • 如果这条规则本来就写在 @media 或 @supports 里，搬出去要么丢掉媒体条件，要么把整段查询再抄一遍。
  • 反过来，当规则已经位于 @media 块内，你想剥掉父选择器、却把媒体条件留下时，靠搬家做不到——它会连媒体查询一起带走。
  • 拆到两个位置之后，重构组件时很容易只改一处，漏掉外面那条。

剥离父级选择器

不去推翻嵌套，而是给「输出位置」补一个开关：@at-root。它的默认行为是移除当前的普通选择器上下文，把规则输出到文档顶层。写进组件里，是为了就近维护；编译出去，却是根级规则。

把它套在刚才那条规则上：

.dashboard .panel { @at-root .theme-dark .widget { ... } }

编译产物里只剩 .theme-dark .widget，父级 .dashboard .panel 被干净地剥离。规则仍然长在组件旁边，读代码的人一眼就知道它的来历，重构时也不会漏。

这里有个必须记住的细节：默认的 @at-root 剥掉的是普通选择器（style rule），像 @media、@supports 这样的 at-rule 反而会被保留。它解决的是输出位置问题，不是「清空一切上下文」。当你想更精确地控制保留哪一层，用 with / without 查询：

写法保留什么
@at-root保留 at-rule，剥掉选择器（等价于 (without: rule)）
@at-root (with: media)只保留媒体查询，剥掉选择器与其他 at-rule
@at-root (without: media)剥掉媒体查询这一层，保留选择器与其他 at-rule

还有一个容易踩的地方：在 @at-root 内部使用 & 时，它引用的仍是外层的完整选择器，展开结果常常和直觉不同。复杂场景请先把编译产物打出来对比，确认无误再定稿；需要更精细的选择器拼装时，可以配合 sass:selector 模块的 API。

别把它当挡箭牌：@at-root 用来表达「这条规则本来就在根级」，不是用来给糟糕的深层架构打补丁。当你发现嵌套深到必须靠它拉平时，先停下来反思结构本身——多数情况下，把那个类名拆出来，比强行拉平更简单也更耐改。

还有一步不能省：改完之后打开编译产物对比一眼，确认规则的输出位置与预期一致再合入。这类「位置错误」不会报语法错，它只会安安静静地生成一条你不想要的选择器。

根级组件上下文切换

输出位置控制

@at-root 管的是「这条规则该长在哪」，而不是「这条规则长什么样」。默认剥掉选择器、保留 at-rule，配上 with / without 就能精确控制上下文；真正的修养是：只在规则本不属于当前组件时用它，而不是用它掩盖失控的嵌套。

「@at-root」把规则从当前选择器上下文中取出、输出到文档顶层。默认等价于 @at-root (without: rule)：剥掉普通选择器，保留 @media、@supports 等 at-rule。用 (with: media) 只保留媒体查询，用 (without: media) 剥掉媒体查询；它解决输出位置问题，不该被当作掩盖深层嵌套的捷径。

关键代码

SCSS
.dashboard .panel {
  // 输出到文档根层级，而不是保留两个父选择器
  @at-root .theme-dark .widget {
    color: white;
  }
}

@media print {
  .article {
    @at-root (without: media) { .print-helper { display: block; } }
  }
}
