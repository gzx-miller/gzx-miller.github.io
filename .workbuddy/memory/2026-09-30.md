# 2026-09-30

## 站点产物体积诊断（nuxt generate 产物基线）

振兴问「文案写在代码里是否导致打包变大、影响加载」。做了完整测量，结论：方向对了一半，文案不是主因。

### 基线数字（.output/public，38.4 MB 总计）
- HTML 27.4 MB / 525 页（平均 53 KB/页，其中内联 `<style>` 约 25 KB/页）
- JS 8.9 MB（1244 个文件）/ JSON 1.4 MB / CSS 758 KB
- 源数据 `src/data` 1.3 MB（26 文件，22 个分类 lessons）

### JS 8.9 MB 的构成
- 首屏关键 3 个文件（Dv5kzYdG 入口 431 KB + 2 个小文件）：456 KB 原始 / **160 KB gzip**
- 22 个分类 chunk：3,575 KB（≈3.5 MB，gzip ≈920 KB）—— **每页都以 `<link rel="prefetch">` 预取**
- 488 个 `?raw` 源码副本 chunk（含 `<script setup>`/`<template>` 字面量）：2,293 KB
- 其余按需小 chunk 733 个：2,749 KB

### 关键结论
- **首屏其实不差**：456 KB JS + 200 KB CSS → gzip 187 KB。首屏真正的负担是 Element Plus（入口 chunk 431 KB；CSS 200 KB，含 240 个 `.el-` 类、331 个 CSS 变量，属全量引入）。
- **每页 HTML 里有 23 个 prefetch**：把全站 22 个分类的数据 + 组件全部预取。用户看一篇文章却下全站 500+ 课程内容。这是"文案写在代码里"最直接的代价。
- **中文文案实测**：JS 内 390,845 个汉字 = 1,145 KB UTF-8 → gzip 427 KB（压缩到 37%）。只占全站 JS 的 13%。
- **源码重复打包**：`?raw` global 把 .vue 源码原样再打一份（源侧 .vue 共 2,393 KB）。等于代码体积几乎翻倍。
- **glob 路径字符串重复 16,646 次**：`lessons/*.ts` 每个分类文件都重复声明同一批 6 组 `import.meta.glob`（`lesson-utils.ts` 里也有一份）。

### 优化优先级（尚未实施，待振兴确认）
1. 收敛 prefetch —— 用 `hooks: { 'build:manifest': (m) => { for (k in m) m[k].prefetch = false } }` 或上 `nuxt-vitalizer`。⚠️ 权衡：Lighthouse 分会好看，但真实场景下次点击变慢，建议只保留同分类。
2. 课程数据外置为按分类的 JSON + fetch，脱离 JS bundle（缓存粒度更细，JSON 解析更快）。
3. 拆分「导航轻量数据」（id/title/navTitle/path/summary）与「正文重量数据」（principle/notes/flow/problem），侧边栏只吃轻量层。
4. `?raw` 源码改为构建期聚合的按分类 sources JSON。
5. Element Plus 样式按需，砍 CSS。
6. HTML 内联 CSS 27.4 MB/525 页重复 —— 可考虑关 `features.inlineStyles`（权衡：多一个 render-blocking 请求）。

### 环境坑（复现记录）
- **Bash 工具在本机完全不可用**：报 `sandbox-center cmd decisionRecord missing actual resource subject`，不是脚本问题。
- **PowerShell 工具可用**，这是本次全部测量的执行方式。注意 `GZipStream($ms, level)` 两参构造会在 Dispose 时连带释放 MemoryStream 导致 `.Length` 为 0，必须用三参版 `leaveOpen=$true`。
