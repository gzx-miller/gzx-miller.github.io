变换、过渡与动画

使用 transform、transition 和 animate 工具类，配合状态变体实现丰富的交互动效。

开场问题：给按钮加了 hover:scale-105，鼠标移上去却「啪」地一下变大又一下变回去，毫无过渡——明明写了放大，为什么看起来像卡了一帧？

四类视觉反馈需求

你在做课程卡片列表，想做点小反馈让页面不死板：鼠标悬停卡片时轻微上浮、按钮按下时缩小一点、加载时转个圈、活动卡片揭晓时轻轻滑入。需求都不复杂，但动手时你会发现它们其实是三种不同的东西：悬停放大是元素自身形态的改变，上浮并停留是形态加上随时间平滑变化的过渡，转圈与滑入则是一段自己会跑的动画。

如果把这三件事混作一谈，写出来的效果就会自相矛盾：要么变化来得太生硬，要么动画把布局搅乱，要么本该流畅的循环在低端机上掉帧。要理清，得先区分三个概念——变换决定元素变成什么样，过渡决定状态切换时怎么平滑过去，动画决定一段独立于状态的关键帧序列。

单一变换直接声明

最省事的做法是只写变化本身：卡片给 hover:scale-105，按钮给 active:scale-95。元素确实会变，逻辑也最简单，一个类就表达完了。

它做对的是选对了变换这件事：scale 只改绘制效果，不改变元素在文档流里占的位置，旁边的元素不会跟着被推来推去。对于只需要「有反馈」的场景，这样写已经可用。真正缺的不是变换，而是从 A 到 B 之间的时间——浏览器默认不过渡，是一步到位的。

瞬时切换与过渡缺失

  • 没有过渡，状态一变就是瞬移，观感生硬，也没法表达「从哪里来、到哪里去」。
  • 一着急补上 transition-all，结果把颜色、边框、布局属性全都拖进过渡，出现意想不到的抖动。
  • 有人图省事去动画 width 或 height，每一帧都触发布局重排，小列表还好，长列表立刻卡顿。
  • 缩放和旋转一起用时，结果和预期对不上——transform 里函数的书写顺序会影响最终结果。
  • 想让多个元素错开滑入，光有 hover 触发不了，缺一段能自己播放的关键帧。
  • 对系统里开了「减少动态效果」的用户没有任何照顾，动画照放不误。

变换函数合并规则

先把「变形」这套工具用全。scale-* 缩放、rotate-* 旋转、translate-* 位移、skew-* 倾斜，它们会被合并进同一条 transform 声明，并且都不改变布局占位。配合 origin-* 控制变换原点，可以让旋转绕左上角、缩放从底部展开，观感差别很大。这就是「优先动画 transform 与 opacity」的由来——它们通常只触发合成，不惊动布局与绘制。

再补上时间：加 transition 声明哪些属性参与过渡，配 duration-* 定时长、ease-* 定缓动。关键约定是用明确的属性，不要一律 transition-all——要过渡位移就用 transition-transform，只过渡颜色就用 transition-colors。写清楚边界，既避免副作用，也让「什么会动」一眼可读。交互反馈的时长控制在 150～300ms 之间比较舒服，而且整站最好收敛到少数几个档位，随意的时长会让界面显得不协调。

v4 里怎么自定义动画：在 CSS 中用 @theme 声明 --animate-* 变量，再配一段 @keyframes，就能生成自己的 animate-* 工具类；旧式的 tailwind.config 写法需要通过 @config 加载。

接着是关键帧动画。animate-spin 适合加载转圈，animate-ping 适合雷达扩散的提示点，animate-pulse 适合骨架屏呼吸，animate-bounce 适合引导注意。它们与 hover 触发无关，是「自己会跑」的。入场那种错开的滑入，则要靠自定义 @keyframes 把透明度与位移一起写进去，而不是硬用过渡去模拟。

最后别忘两个纪律。一是写作顺序：旋转与缩放写在一条 transform 里，顺序不同结果可能明显不同，固定一个习惯（比如先位移、再旋转、后缩放）能省掉很多猜谜。二是性能预算：大量元素同时动画会抢占主线程，动画数量要有节制，并且要为用户提供「减少动态效果」的替代方案。

  1. 用 scale / rotate / translate / skew 与 origin-* 定义要呈现的变换。
  2. 加 transition 与 duration-* / ease-* 让状态变化平滑过渡，用 hover: / active: 触发。
  3. 循环或阶段性动效用 animate-*（内置 spin / ping / pulse / bounce）或自定义 @keyframes。
  4. 打开动画面板确认动画只涉及 transform 与 opacity，未触发布局重排。

缓动曲线与关键帧

三类动效职责划分

变换、过渡、动画是三件不同的事：变换决定变成什么样，过渡决定怎么平滑过去，动画决定自己怎么跑。做法上抓住两条即可——优先动画 transform 与 opacity 保证性能，时长与缓动收敛到少量档位保持一致；用明确属性而非 transition-all，顺手为「减少动态效果」的用户留一条安静的路。

「合成友好的变换」指优先让动画只涉及 transform 与 opacity——它们通常只触发合成，不引起布局重排与重绘，因此最流畅。scale / rotate / translate / skew 会合并成一条 transform 且不改变元素占位；相反，动画 width / height 等布局属性容易导致卡顿，应尽量避免。

关键代码

HTML
<!-- 悬停放大效果 -->
<button class="rounded-lg bg-orange-600 px-6 py-3 text-white transition duration-200 ease-out
  hover:scale-105 hover:shadow-lg
  active:scale-95">
  点击放大
</button>

<!-- 旋转与位移 -->
<div class="flex gap-8">
  <div class="transition duration-300 hover:rotate-12 hover:scale-110">
    <div class="h-16 w-16 rounded-lg bg-amber-300"></div>
    <p class="mt-2 text-xs text-stone-600">rotate + scale</p>
  </div>
  <div class="transition duration-300 hover:-translate-y-2 hover:shadow-xl">
    <div class="h-16 w-16 rounded-lg bg-orange-400"></div>
    <p class="mt-2 text-xs text-stone-600">translate-y</p>
  </div>
  <div class="transition duration-300 hover:skew-x-6">
    <div class="h-16 w-16 rounded-lg bg-amber-500"></div>
    <p class="mt-2 text-xs text-stone-600">skew-x</p>
  </div>
</div>

<!-- 过渡曲线控制 -->
<button class="rounded-lg bg-stone-700 px-5 py-2.5 text-white transition duration-500 ease-in-out hover:bg-orange-600">
  ease-in-out 过渡
</button>

<!-- 内置关键帧动画 -->
<div class="flex items-center gap-6">
  <span class="inline-flex h-8 w-8 animate-spin rounded-full border-4 border-amber-200 border-t-orange-600"></span>
  <span class="inline-flex h-3 w-3 animate-ping rounded-full bg-orange-500"></span>
  <span class="inline-flex animate-pulse text-orange-600 font-medium">加载中...</span>
  <span class="inline-flex animate-bounce text-2xl">👋</span>
</div>
