工具优先与原子类组合

用课程卡片理解工具类如何映射声明，以及何时抽取组件。

开场问题：页面里第三个「课程卡片」出现了——你复制了前两个的 class，又顺手改了两个数字。三个月后要调整卡片圆角，你在四十个文件里搜同一个类名，改到第三十个时开始怀疑人生：这堆类名到底该不该存在？

自定义类命名成本

你想做的事很简单：给一段 HTML 加点样式。传统做法是先在 CSS 文件里想一个名字，.course-card，然后写声明；HTML 那边挂上这个名字。这套流程跑了几十年，但它藏了两个必须由人来承担的成本。

第一是命名成本。你每写一个组件就得想一个语义化的类名，而类名是有限的资源——.card 被占用了，你就写 .course-card，再冲突就写 .course-card-v2。第二是推理成本。看到一个 class="course-card"，你无法知道它长什么样，必须跳到 CSS 文件里去找定义，如果它继承自 .card 又要再跳一层。样式和结构被物理地分开了。

于是问题变成：有没有一种办法，让「写样式」这件事本身不需要先想名字？

单用途工具类

Tailwind 给的最小方案叫「工具优先」：不写自定义类，直接在元素上挂单用途工具类。每个类只做一件事，类名本身就是声明。

  • flex → display: flex
  • items-center → align-items: center
  • gap-4 → gap: 1rem
  • rounded-2xl → border-radius: 1rem
  • shadow-lg → box-shadow: 0 10px 15px -3px rgb(0 0 0 / 0.1)

于是一个卡片写成 class="flex items-center gap-4 p-5 rounded-2xl shadow-lg"，读 HTML 就等于读样式——不用跳文件、不用想名字。它真正解决的是那个最原始的问题：命名瓶颈消失了，因为名字不再是抽象的语义标签，而是它恰好要施加的那条声明。

类名列表失控

但严格说，「写样式不用想名字」并不等于「代码变好了」。这个方案会露出三个问题：

  • 类串会失控地变长。一张复杂卡片挂上二三十个类名很正常，class 属性长得像一篇小作文，可读性反而下降。
  • 重复是必然的。同样的 flex items-center gap-4 p-5 rounded-2xl shadow-lg 会在十个地方出现。要改圆角，还是要改十个地方——只是从"搜类名"变成了"搜类串"。
  • 自由过头会破坏一致性。如果没人管，有人用 p-4，有人用 p-[17px]，设计约束形同虚设，风格还是会失控。

注意第三个问题其实早有答案：Tailwind 的间距、颜色、字号都来自一套预定义的设计令牌——p-4 恒等于 1rem，颜色只能从调色板里取。这层约束是工具类能保持克制的前提，而不是它的缺点。

组件抽象阈值

剩下的两个问题，答案不在 CSS 里，而在你已经在用的组件模型里。

当同一段工具类组合出现三次以上，或者这堆类名开始承载业务语义（"这是一张课程卡片"），就应该把它抽成一个 Vue 组件，把那段类串封进组件内部：

  • 组件边界承担了「可复用」的职责——改圆角只改组件内部一处。
  • 组件名承担了「语义」的职责——<CourseCard> 比 .course-card 更清楚，因为它同时管住了结构和样式。
  • 工具类继续留在组件内部——它负责的是「具体长什么样」这件小事，而抽象这件事交给组件。

这里有个常见误操作要避开：不要为了缩短 class 而用 @apply 堆一个自定义类。

不要滥用 @apply。写 .my-card { @apply flex items-center gap-4 p-5; } 看似两全其美，实际上你既失去了工具类的自描述性（读 HTML 又看不懂了），又回到了"要想类名"的老路，还没拿到组件带来的结构复用。它只在少数场合有价值——比如要给第三方库渲染出的 DOM 打补丁时。

还有一条实践细节：类名顺序不影响最终结果，因为 CSS 规则的优先级由样式表决定，不由你书写顺序决定。但团队里应当用统一排序（比如按官方推荐的属性分组顺序，或用 Prettier 插件自动排序），否则 diff 会充满无意义的抖动。

工具类映射对照

命名交给组件承担

「工具优先」不是"不用写 CSS"，而是把命名这件事从样式中拿掉，交给组件去承担。工具类负责单条声明的组合与设计令牌的约束，组件负责复用与语义，两者各管一段，谁也不越位。判断该不该抽组件，看的是重复次数和业务语义，而不是类串有多长。

「工具优先」指优先用受设计令牌约束的单用途工具类（flex / p-5 / rounded-2xl）直接在元素上组合样式，使类名即声明、无需为样式单独命名；可复用性与抽象由组件边界承担，而不是用 @apply 把工具类重新包装成自定义类名。
