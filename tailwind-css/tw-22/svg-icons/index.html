SVG 图标与当前颜色

通过 currentColor 让 SVG 继承父元素文字颜色，配合 text-* 工具类统一控制颜色和大小。

开场问题：按钮里放了个图标，代码写死成橙色，可文字一改成灰色，图标还是橙的；等到要做暗色主题，难道要一个个把图标颜色再改一遍？

图标文字组合按钮

你在做一个课程报名按钮，需要「图标 + 文字」的组合。你把设计师给的 SVG 直接内联进模板，颜色照着设计稿写死在 fill 上。单看这个按钮没问题，可接下来事情开始变多：收藏按钮要在「已收藏 / 未收藏」两种状态间变色，暗色主题上线后图标要跟着文字一起变，同一套图标在导航、卡片、按钮里还要用不同尺寸。

问题在于你没把图标当成「会随上下文变化的图形」，而是当成了「一张固定颜色的小图片」。图标真正的身份是矢量图形，它应该像文字一样，能继承颜色、能随字号缩放、能被状态变体统一驱动。

逐图标填充色写死

最直接的做法，是每个图标写死自己的颜色：fill="#ea580c"，需要什么色就填什么色。这样做在只有一两个图标、只有一种状态的场景里，直观且不用思考。

它做对的是把颜色确定下来——设计师给的色值直接落地，不会跑偏。可一旦颜色需要随上下文改变，「写死」就变成了负担：同一个图形在两处要用两种颜色，就得维护两份 SVG；主题一换，改色点成倍增加。

改色连锁与体积代价

  • 颜色写死后，状态切换（悬停、选中）与主题切换都得逐个改，改漏一处就不一致。
  • 图标尺寸靠固定像素写死，和相邻文字的字号对不齐，视觉基线总是偏一点。
  • 为了要几个图标而整包引入一个图标库，产物体积被没用到的那几百个图标拖大。
  • 把 fill 型与 stroke 型图标混着用，线宽粗细不一，放在一起观感很乱。
  • 图标与文字的间距、垂直对齐没有统一约定，每个按钮各写一套，按钮之间高矮不齐。

继承色关键字替换

关键在于换掉颜色来源：把 SVG 内部的 fill 或 stroke 设成 currentColor。currentColor 是 CSS 里的关键字，含义是「取当前元素的文字颜色」，于是图标不再是固定色块的图片，而是一块会跟随上下文变色的图形。此时用 text-* 工具类控制颜色，文字和图标会一起变——主题切换、状态变色全部零成本。

颜色解决后，尺寸也跟着用同一套思路：因为矢量图形会随字号缩放，用 w-* / h-* 指定大小，或者干脆让父级用 text-* 控制字号，图标就会和周围文字比例协调。再配上 flex items-center gap-2 让图标与文字居中对齐、间距统一，按钮之间自然就齐了。

推荐用线性图标：以 stroke 描边绘制的线性图标比填充式更容易借助 currentColor 变色，文件通常也更小，风格更统一。Heroicons、Lucide 等库都提供了现成的 currentColor 变体，直接可用，不必自己把每个图形的颜色都改成 currentColor。

图标数量多起来之后，把「路径 + 默认尺寸」封装成一个小图标组件是值得的：组件内部仍是 currentColor，对外只透传 class，颜色与大小依旧由使用处的 text-* 与 w-* 决定。这样既复用了图形结构，又保留了「跟随上下文变色」的能力——如果反过来把颜色和尺寸也写进组件的默认值里，就等于把写死的老问题搬进了组件内部。

还有两个细节值得固定成规矩。其一，同一套图标要保持一致的 stroke-width，混用不同线宽（有的 1.5、有的 2）放在一排里会明显不齐，观感变脏。其二，内联 SVG 时尽量只引入用到的那几个图形，而不是把整个图标库打进来，避免产物体积无谓膨胀。

  1. 在 SVG 内部把 fill / stroke 改为 currentColor。
  2. 用 text-* 工具类同时控制文字与图标颜色。
  3. 用 w-* / h-* 或父级 text-* 大小控制图标尺寸。
  4. 切换主题色后确认图标与文字颜色同步变化。

图形随文字联动

颜色尺寸继承上下文

图标的颜色不该写死在图形里，而应继承上下文。把 fill / stroke 换成 currentColor，颜色交给 text-*，尺寸交给 w-* / h-*，图标就能和文字同步变色、同步缩放，主题切换与状态联动都不用额外写一遍。再养成用线性图标、统一线宽、按需引入的习惯，观感和体积都可控。

「currentColor」是 CSS 关键字，取值为当前元素的文字颜色（color）。把 SVG 的 fill 或 stroke 设为 currentColor 后，图标便会继承父元素的文字色，于是用 text-* 工具类即可同时控制文字与图标颜色，主题切换和状态变体都能零成本跟随。
