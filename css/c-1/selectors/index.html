选择器详解

理解通配、类型、类、ID、属性、伪类、伪元素与组合器的匹配差异与特异性。

开场问题：我想只给课程目录的「一级条目」加个橙色左边框，顺手写了 .menu li，结果嵌在里面的子目录条目也一起变了色——一条选择器到底圈住了哪些元素？

后代选择器范围

场景很小：课程网站的侧边栏有一份目录，一级条目下面还可能嵌套子目录。需求是「一级条目加下边距和橙色左边框」。你随手写下 .menu li { ... }，上线后子目录条目也带上了边框，视觉上乱成一团。更麻烦的是，.menu 后来在购物车页也被复用了，同一份样式把购物车的商品列表也改了一遍。

这类问题有两个方向，方向相反却都表现为「样式莫名其妙」：选多了，污染到不该管的元素；选少了，样式干脆不生效。它们都没有报错、没有提示，能依靠的只有你对匹配规则的理解。而一旦多条规则同时命中一个元素，还要看谁「更硬」——这就是选择器必须一次讲清的原因。

类型与类选择器

最朴素的写法：直接用标签名或类名去选。p { line-height: 1.6 } 统一段落行高，.btn { padding: 8px 16px } 统一按钮内边距。

这个方案做对了一件大事：绝大多数「整站统一」的排版，一条类型或类选择器就能一次写完，简单、可读、没有歧义。当页面上只有一种按钮、一种段落时，它完全够用。

伪类与伪元素

  • 管不了状态：按钮悬停、输入框聚焦、奇数行——这些「元素正处于某一种情况」没有标签名可写。
  • 管不了局部：段落首字母放大、在元素前后插入一个图标，这是元素的「某个部分」，不是元素本身。
  • 管不了结构：只想要「直接子元素」或「紧跟其后的兄弟」，标签名无从表达这层关系。
  • 选得中但打不赢：多条规则命中同一个元素时，谁生效不看出场顺序，只看权重。
  • 直写标签名会全局生效，一处改动会牵动别的页面，像开场那样把购物车也改掉。

四类基础选择器

先把「按身份选」补成一整套：通配 * 匹配所有元素（常用来做全局重置）；类型 p、div 匹配标签名；类 .card 匹配 class 包含该值的元素；ID #header 匹配 id 等于该值的元素；属性 input[type="text"] 匹配带有某特性的元素。

再把「状态」和「局部」也算进来。伪类表达状态：a:hover 悬停、input:focus 聚焦、li:nth-child(odd) 奇数项。伪元素表达元素上那块「虚拟的部分」：p::first-letter 命中首字母，.tip::before 在元素前插入内容。为什么伪元素能凭空造出一个东西？因为它命中的是盒子上的一个虚拟位置，而不是 DOM 里的真实节点。

这里有个帮你分清两者的记号约定：伪类写一个冒号，伪元素写两个冒号。老写法允许伪元素也用一个冒号，但按双冒号来写，一眼就能分辨「这是在描述状态，还是在描述元素身上的某个部分」。属性选择器也比想象中灵活，除了精确匹配 [type="text"]，还能按前缀、后缀、包含来匹配，比如一次性选中页面上所有的外部链接。

最后补上「结构关系」，也就是组合器：空格是后代选择器，选中所有层级；> 是子元素选择器，只选直接子级；+ 只选紧挨着的那一个后置兄弟；~ 选中后面所有同级兄弟。开场那个「子目录被染色」的问题，把 .menu li 换成 .menu > li 就精确了。

组合器还有一个容易被忽视的特点：它表达的是结构关系，而不是元素身份。也就是说 .menu > li 里的 > 描述的是「谁是谁的直接子级」，一旦你在中间插了一层 div 做包裹，原有的直接子级关系就被破坏了，样式会突然失效——这也是重构结构时最常踩的坑之一。

但选得准还不够，还得能赢。两条规则同时命中一个元素时，比较的是特异性：大致是 ID > 类/属性/伪类 > 类型/伪元素，处在同一级时后声明的胜出（C_06 会把这张权重表彻底讲透）。所以日常一般用类名而不是 ID——不是 ID 不好用，而是它权重太高，日后想覆盖会很难受。

两个工程习惯：选择器不要嵌套过深，.page .content .list .item .link 这种既难维护、匹配也慢，能用一个语义类名解决就别堆四层；样式不生效时，先打开开发者工具看哪条规则最终胜出、它来自哪个文件，再决定是改选择器还是调顺序，别靠猜。

匹配范围与特异性

选择器回答的是两个问题：一条规则圈住了哪些元素，以及它和别的规则谁说话更算数。把身份、状态、局部、结构四类匹配补齐，再用特异性判断胜负，开场的「染色溢出」与「不生效」就都能提前避开。

「选择器」决定匹配对象：通配匹配全部，类型匹配标签名，类/ID 匹配 class 与 id，属性匹配特性，伪类匹配状态，伪元素匹配元素上的虚拟部分，组合器（后代、>、+、~）表达元素间的结构关系。它们各具特异性，命中同一元素时以特异性大小决定胜负，同级时后声明者胜。

关键代码

CSS
/* 通配选择器：匹配所有元素 */
* {
  box-sizing: border-box;
  margin: 0;
  padding: 0;
}

/* 类型选择器：匹配指定标签 */
p {
  line-height: 1.6;
  color: #333;
}

/* 类选择器：匹配 class 包含指定值的元素 */
.btn {
  padding: 8px 16px;
  border-radius: 6px;
  cursor: pointer;
}

/* ID 选择器：匹配 id 等于指定值的元素 */
#header {
  background: #fff;
  box-shadow: 0 2px 8px rgba(0,0,0,0.1);
}

/* 属性选择器：匹配拥有指定属性的元素 */
input[type="text"] {
  border: 1px solid #ddd;
  padding: 6px 10px;
}

/* 伪类选择器：匹配处于特定状态的元素 */
a:hover {
  color: #e8590c;
  text-decoration: underline;
}

/* 伪元素选择器：匹配元素的某个部分 */
p::first-letter {
  font-size: 2em;
  font-weight: bold;
  float: left;
  margin-right: 4px;
}

/* 组合器：子元素选择器 */
.nav > li {
  display: inline-block;
  margin: 0 8px;
}
