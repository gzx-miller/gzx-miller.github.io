CSS :has() 选择器

用 :has() 实现"父元素选择器"效果，根据子元素状态样式化容器。

开场问题：表单里第二个输入框填错了，你希望外层整块变成红框——可 CSS 只能顺着 DOM 往下选，父元素要怎么写，才能知道「我的孩子出错了」？

父级感知子级状态

设想你在做一个注册表单。需求有几条：只要有任意一个输入框报错，整个表单容器就标红、加浅红底；输入框的包装层在获得焦点时要亮起一圈描边；卡片列表里，带封面图的卡片走「左图右文」布局，不带图的只留文字；另外，「后面紧跟一个副标题」的主标题要收窄下边距。

这些需求的共同点是：要改变的样式挂在外层元素上，判断依据却在内部或相邻元素身上——父容器得知道孩子出错了、孩子被聚焦了、以及自己身后有没有兄弟。而传统 CSS 选择器只能从父往子、从前向后选，根本没有「选中所有包含犯错孩子的父元素」这种写法。于是每加一条规则，就要在脚本和样式之间再加一次同步，成本会随着表单字段一起增长。

脚本切换类名

最省事的做法是回到 JavaScript：用校验逻辑判断有没有错误，再给表单容器 toggle 一个 form--error 类，CSS 只负责给这个类上色。

它做对了一件实事：这条路真的能跑通，而且至今仍是处理复杂状态时最直接的方案。当状态本来就是你自己的数据（比如接口返回的字段错误），用脚本显式表达出来反而更清晰，调试时也能一眼看到类名是什么时候加上的。

状态同步重复

  • 每个「外层随内层变化」的需求都要单独写一遍监听与类切换，逻辑越堆越多。
  • 状态来自 :checked、:focus、:hover 这类纯 CSS 伪类时，脚本也得把它们全部模拟一遍，否则样式跟不上。
  • 判断逻辑散落在脚本里，新增一个表单字段就可能漏掉一处同步。
  • 服务端渲染时脚本还没执行，首屏会先出现「没有错误态」的默认外观，然后闪一下。
  • 组件库通常不给「按子元素反选父级」的能力，最终还是得自己加类。

父元素选择能力

换一个角度：如果选择器本身就能表达「包含某个孩子」这个条件，上面那些同步逻辑就都不需要了。这正是 :has() 提供的父元素选择能力——它写在条件位置，描述当前元素「里面有什么」。

回到表单：.form:has(.error) 的意思是「内部含有 .error 元素的表单」，它直接命中外层容器，一行 CSS 就能把标红这件事交还给样式表：

.form:has(.error) { border-color: #fa5252; background: #fff5f5; }

脚本里那套「判断 + toggle 类名」的代码，整段可以删掉，并且服务端渲染出来的首屏就是正确的外观，不会再有切换时的闪烁。

状态类的需求同样如此。复选框的选中态不必再由脚本同步到父元素上，直接让标签去观察它内部的输入框：.label:has(input:checked) { background: #e8590c; color: #fff; }。同理，输入框获得焦点时高亮整个包装层，只写 .input-wrapper:has(input:focus)；要给必填字段加星号，可以写 .form-group:has([required]) label::after { content: ' *'; }——注意这里用的是属性选择器 [required]，判断的是子元素有没有这个属性，与它的值是空、是 true 还是别的都没有关系。

布局分支也可以交给选择器：.article-card:has(img) 只给带图的卡片套上「左图右文」的网格，不带图的卡片自然保持默认排版。想反过来——只处理没有图片的卡片——把 :has() 放进 :not() 里即可：.card:not(:has(img)) { padding: 16px; }。

还有一个反直觉但很好用的用法：:has() 能选中后面紧跟着某个兄弟的元素，也就是「往前选」。比如让有副标题的主标题收窄下边距：.title:has(+ .subtitle) { margin-bottom: 4px; }。它的含义是「后面紧跟一个 .subtitle 的 .title」。过去这类需求要么给标题额外加类，要么用 :last-of-type 绕，现在一条选择器就说清了。

使用时记住三点。第一，:has() 已在主流浏览器获得基线支持（2023 年起），可以放心用在现代项目里。第二，它支持与 :not() 以及相邻兄弟组合器搭配，但这类选择器相对昂贵，别大面积嵌套叠加，尤其不要用在长列表的每一个子项上。第三，样式一旦依赖 DOM 结构，结构变化时就要同步检查 :has() 的条件——把图片删掉、把副标题改名，都可能让匹配悄悄失效，而且不会报任何错误。

错误卡片筛选

关系伪类选择

:has() 补上了 CSS 一直缺的那半截能力：让选择器从「往下、往后选」变成「能看见自己内部与身后」。它把「父级随子级状态变化」这件事从脚本手里交还给样式表——表单错误态、选中态、聚焦态、有无图片的布局分支、以及向前选兄弟，都可以用一条选择器加一个条件写完，页面与样式之间那层同步代码随之消失。

「:has() 选择器」是一个父元素 / 关系选择器：它把「当前元素内部是否含有符合条件的元素」写成匹配条件，例如 .form:has(.error) 命中所有含错误提示的表单容器，.label:has(input:checked) 命中含有被选中复选框的标签。它还能与 :not() 组合成 .card:not(:has(img))，以及用 .title:has(+ .subtitle) 选中后面紧跟副标题的标题。

关键代码

CSS
/* :has() 基本用法：选择包含特定后代的元素 */

/* 选择含有 .error 子元素的表单 */
.form:has(.error) {
  border-color: #fa5252;
  background: #fff5f5;
}

/* 选择含有 img 的文章卡片 */
.article-card:has(img) {
  display: grid;
  grid-template-columns: 120px 1fr;
  gap: 12px;
}

/* 选择含有 :checked 的标签 */
.label:has(input:checked) {
  background: #e8590c;
  color: #fff;
  border-color: #e8590c;
}

/* 组合使用：选择不含有图片的卡片 */
.card:not(:has(img)) {
  padding: 16px;
}

/* 选择含有必填字段的表单组 */
.form-group:has([required]) label::after {
  content: ' *';
  color: #fa5252;
}

/* 选择后面跟着特定兄弟元素的元素（选择前面的兄弟） */
.title:has(+ .subtitle) {
  margin-bottom: 4px;
}
.subtitle {
  color: #868e96;
  font-size: 14px;
}

/* 选择含有聚焦输入的容器 */
.input-wrapper:has(input:focus) {
  border-color: #e8590c;
  box-shadow: 0 0 0 3px rgba(232, 89, 12, 0.1);
}

/* 选择含有 hover 子元素的父容器 */
.nav-item:has(a:hover) {
  background: #fff4e6;
}

/* 嵌套使用：含有含有... */
/* .container:has(.card:has(.active)) { ... } */

/* 注意：:has() 不能在 :has() 内部使用（浏览器限制）*/
/* 注意：性能考虑，避免过度使用复杂的 :has() 选择器 */
