CSS 层叠层（@layer）

用 @layer 显式声明层顺序，解决多来源样式的优先级管理。

开场问题：你只想把第三方 UI 库的按钮圆角改小一点，自己的样式写了三遍都被压过去，最后不得不加上 !important——为什么明明是「我的项目」，样式却说了不算？

多来源样式层叠

设想你在一个已经跑了一阵的课程后台里工作。项目引入了第三方 UI 库，又加了一套工具类，同时还有自己的组件样式。某天产品说：按钮圆角统一改成 8px。你写下 .btn { border-radius: 8px }，没生效；加一层父级变成 .page .btn，还是没生效；最后写成 .page .btn.btn { border-radius: 8px !important }，终于生效了。

真正的代价在这里：下一次别人要改这个按钮，就得写得更长、加上更多 !important 才能压过你。更麻烦的是，你的样式能不能赢，往往并不由你决定——它取决于 CSS 文件在页面里的加载顺序，而顺序由打包工具和懒加载时机决定，会随着每一次构建、每一次路由切换而改变。也就是说，同一个项目换一次打包配置，颜色可能就变了，而没人改动过一行样式代码。

提高特异性手段

最朴素的办法是提高特异性：往上叠选择器、叠类名，或者干脆用 !important。

它确实做对了一件事：当规则被压住时，你手里一直有一个能立即生效的手段。在紧急修一个线上样式 bug 的时候，先加 !important 止血是合理的，它不该被完全否定——只是它属于「止血」，不属于「治疗」。

特异性升级代价

  • 特异性会变成军备竞赛：.page .btn 压不过 .page .btn.btn，谁想覆盖谁就写得更长，样式表越来越难读。
  • !important 会打乱整条层叠规则，一旦用了，后面的人也只能用 !important 去压它，层层加码。
  • 依靠书写顺序并不可靠：第三方库可能是异步加载进来的，加载时机一变，谁后声明就跟着变。
  • 工具类本应「一句顶一句」稳定压过组件样式，但在特异性相近时也压不住。

分层顺序与优先级

换个思路：不去比谁的特异性更高，而是先把样式的层级关系一次性约定好，让优先级与书写顺序彻底解耦。这就是 @layer。用法很简单，先用一行声明层的先后：

@layer reset, base, components, utilities;

这一行规定了四个层的优先级：靠后声明的层优先级更高，所以 utilities 高过 components，components 高过 base，base 高过 reset。之后再往每个层里写规则：

@layer components { .btn { padding: 8px 16px; } }，@layer utilities { .m-0 { margin: 0; } }

关键差别在于：层与层之间比较的是层顺序，不再看选择器长短。只要把工具类放进 utilities 层，无论它写在 CSS 文件的前面还是后面、无论它用了多少个类名，它都稳定地压过 components 层。而在层内部，则照旧按常规层叠比较——特异性优先，同特异性看声明先后，你原来的直觉在层内依然成立。

一句话记法：未分层的样式优先级高于所有分层样式；分层之间按声明顺序，后者胜；层内则按常规层叠。把这三条背下来，绝大多数「为什么会这样」的疑问都能自己推出来。

这条规则解释了两种常见现象。第一，没有放进任何层的样式，优先级高于全部 @layer，所以组件里临时写的、没归层的样式总能盖住框架层——这既是便利，也是隐患。第二，想收拾第三方库，不必再去改它的源码或堆特异性，只要在引入时把它整体送进一个靠前的层：

@import 'third-party-ui.css' layer(vendor);

这样库的样式永远排在 base、components 之前，业务代码只要写进更靠后的层，就能干净地覆盖它。需要更细的粒度时，层还可以嵌套：@layer components { @layer button { .btn { border-radius: 6px; } } }，其中 components.button 是一个独立的子层，它比 components 自身更晚，因此可以稳定地覆盖组件层的通用按钮样式。

两个坑要记住。其一，层内的 !important 仍然会提升优先级，把它写进层里并不等于被驯服，务必谨慎。其二，调整 @layer 声明的先后会同时改变整组的相对优先级，所以要把层的顺序当成一份对外接口来对待，别随手插队。

默认与分层对比

优先级交由层级

@layer 要解决的不是「哪条规则更特别」，而是「谁该听谁的」这个问题本身。它用一行声明把 reset、base、components、utilities 的先后固定下来，让优先级与文件书写顺序、打包顺序脱钩；再配合 @import ... layer(vendor) 收纳第三方库，业务代码就不必再靠堆特异性和 !important 去硬拼。

「层叠层 @layer」是 CSS 用来显式声明优先级顺序的机制。写法是先用 @layer reset, base, components, utilities; 声明层的先后，越靠后的层优先级越高；随后把规则分别写进各层。层之间只比层顺序、不比选择器特异性，层内仍按常规层叠比较。此外，未分层的样式优先级高于所有分层样式，而 @import url(...) layer(vendor) 可以把第三方库整体归入指定层。

关键代码

CSS
/* 声明层顺序：越靠后优先级越高 */
@layer reset, base, components, utilities;

/* reset 层：优先级最低 */
@layer reset {
  * {
    margin: 0;
    padding: 0;
    box-sizing: border-box;
  }
}

/* base 层：基础样式 */
@layer base {
  body {
    font-family: system-ui, sans-serif;
    line-height: 1.6;
    color: #333;
  }
  a {
    color: #e8590c;
    text-decoration: none;
  }
  a:hover {
    text-decoration: underline;
  }
}

/* components 层：组件样式 */
@layer components {
  .btn {
    padding: 8px 16px;
    border-radius: 6px;
    border: none;
    cursor: pointer;
    font-size: 14px;
  }
  .btn-primary {
    background: #e8590c;
    color: #fff;
  }
  .btn-secondary {
    background: #f1f3f5;
    color: #333;
  }
}

/* utilities 层：工具类（优先级最高的层） */
@layer utilities {
  .text-center {
    text-align: center;
  }
  .font-bold {
    font-weight: 700;
  }
  .m-0 {
    margin: 0;
  }
  .p-0 {
    padding: 0;
  }
}

/* 未分层的样式：优先级高于所有 @layer */
.override {
  color: #000;
  /* 即使在 utilities 层之后声明，也比 utilities 层优先级低？不！
     未分层的样式优先级最高 */
}

/* 嵌套层 */
@layer components {
  @layer button {
    .btn {
      /* 内部嵌套层 */
    }
  }
}

/* @import 引入第三方样式并归入指定层 */
/* @import 'reset.css' layer(reset); */
/* @import 'third-party-ui.css' layer(vendor); */
