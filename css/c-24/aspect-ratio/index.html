aspect-ratio 与 object-fit

用 aspect-ratio 控制元素宽高比防止布局偏移，用 object-fit 控制图片/视频的填充方式。

开场问题：列表里的图片还没加载完时页面是好好的，图片一到，下面的内容「啪」地往下跳了一截——用户刚想点的按钮瞬间被推走了，这该怎么治？

封面尺寸不固定

设想你在做课程列表：每条课程都配一张封面图，图片地址由接口返回，尺寸并不固定——有的 16:9，有的 4:3，有的干脆是方图。你按设计稿给图片容器写了一个固定高度，以为这样就能先把位置占好。

上线后冒出两个问题。第一，图片还没下载完时容器的高度不对，图一加载出来，下面的内容整体往下跳，用户刚要点的地方被推走，甚至误触——这就是布局偏移。第二，为了消掉跳动你改用固定宽高，结果比例不同的图片被强行拉伸，人物都变形了。要跳出这个两难，得先意识到：「元素占多大地方」和「图片在盒子里怎么放」其实是两件事。把它们混在一起来解决，才会两头都做不好。

固定像素尺寸

最朴素的做法是把尺寸写死：给图片 width: 300px; height: 200px。

它做对了一件重要的事：布局在图片到达之前就已经确定，浏览器不必等图片下载完才决定页面长什么样，跳动消失了。承认这一点很关键——避免布局偏移的正解，本来就是「提前把空间留出来」；我们可以保留这份功劳，只把「写死的数字」换成「比例」。

图片拉伸变形

  • 写死宽高会让比例不同的图片被拉伸变形，因为 img 默认的填充方式就是 object-fit: fill。
  • 固定像素宽度在响应式下不成立：容器变窄时，图片不会跟着变。
  • 每种比例都要手算一遍高度，新增一种比例就得改一次样式。
  • 容器尺寸变化时，高度不会跟着宽度推导，于是产生留白或溢出。

内边距撑出比例

历史上最常见的绕法是「padding 撑比例」：在外层容器上写 padding-top: 56.25%，让高度等于宽度的 56.25%（也就是 16:9），再把真正的内容绝对定位铺满其中。

它做对了：用百分比 padding 撑出一个随宽度变化的高度，比例稳定、兼容性好。问题是它需要一个额外的定位包裹层，子元素必须全部改成绝对定位，56.25% 这种数字也看不出对应哪个比例，维护起来并不直观。

后来 CSS 把这件事变成了一条声明：aspect-ratio。它直接表达「宽高比」，由宽度推导高度：

.cover { width: 100%; aspect-ratio: 16 / 9; }

浏览器在布局阶段就能算出元素高度，图片有没有到位都不影响，跳动从根上消失。想让宽度有上限、超过就停下，可以叠加 max-width。比例也不限于宽屏：1 / 1 是正方，4 / 3 是传统比例，21 / 9 是超宽幅——写成分数形式，比记忆那串百分比清楚得多。

但 aspect-ratio 只解决了「占多大地方」，没解决「图片怎么放进去」。图片本身的原始比例如果和盒子不一致，就会出现拉伸或留白。这时交给 object-fit——它决定替换元素（如 img、video）在给定盒子里的填充方式。

取值效果
fill（默认）拉伸填满整个盒子，可能改变原始比例、出现变形
contain保持比例完整显示，装不满的方向留白
cover保持比例放大到填满盒子，超出部分被裁掉
none完全不缩放，保持原始尺寸，可能溢出或被裁
scale-down在 none 与 contain 中取较小的那个，即「只在需要缩小时才缩」

实践中最常用的是 cover：无论原图是什么比例，它都能铺满容器且不变形，代价是边缘会被裁掉一点。裁掉哪一部分可以用 object-position 调整，例如人像常写 object-position: center top，把视觉重心留在上方。

两个必须记住的点。第一，object-fit 只有在图片盒子有明确尺寸时才看得出效果——通常要写 width: 100%; height: 100%，否则盒子跟着图片走，自然无从「填充」。第二，cover 只是「显示时裁掉」，图片文件本身并没有被裁切，它的体积与流量一分没少；需要真正裁剪请另做处理。

把两者合起来，就是防布局偏移的标准写法：

.cover { width: 100%; aspect-ratio: 16 / 9; object-fit: cover; object-position: center; }

aspect-ratio 负责在图片下载前就把空间占好，object-fit: cover 负责图片到位后铺满且不变形。两张拼图各管一段，缺一条都会退回开场的那个问题：只留 aspect-ratio，图片会被拉伸；只留 object-fit，加载时照样跳。

比值与填充对照

占位与填充分界

aspect-ratio 与 object-fit 解决的是两件相邻但不同的事。前者回答「这个盒子该占多大」——在布局阶段就由宽度推出高度，把位置提前留好，从而消掉布局偏移；后者回答「图片该怎么装进这个盒子」——cover 裁剪铺满、contain 完整留白、fill 拉伸变形、none 不缩放、scale-down 取较小者。两者配合，才是「加载前不跳、加载后不变形」的完整答案。

「aspect-ratio 与 object-fit」前者用比值（如 16 / 9、1 / 1）固定元素的宽高比，浏览器在布局阶段即可由宽度推导高度，常用于给图片、视频提前预留空间以消除布局偏移；后者决定替换元素在其盒子内的填充方式：fill 拉伸填满（默认）、contain 完整显示可能留白、cover 保持比例裁剪铺满、none 保持原始尺寸、scale-down 取 none 与 contain 中较小者。两者结合通常写作 width: 100%; aspect-ratio: 16 / 9; object-fit: cover;。

关键代码

CSS
/* aspect-ratio：固定宽高比 */

/* 16:9 宽屏比例 */
.ratio-16-9 {
  aspect-ratio: 16 / 9;
  width: 100%;
  /* 高度自动计算，保持 16:9 */
}

/* 1:1 正方形 */
.ratio-square {
  aspect-ratio: 1 / 1;
}

/* 4:3 传统比例 */
.ratio-4-3 {
  aspect-ratio: 4 / 3;
}

/* 21:9 超宽屏 */
.ratio-ultrawide {
  aspect-ratio: 21 / 9;
}

/* 与 min-width/max-width 配合 */
.responsive-ratio {
  aspect-ratio: 16 / 9;
  width: 100%;
  max-width: 800px;
}

/* 旧版 hack（不推荐，用 aspect-ratio 替代） */
/*
.ratio-old {
  position: relative;
  padding-top: 56.25%;
}
.ratio-old > * {
  position: absolute;
  top: 0; left: 0;
  width: 100%; height: 100%;
}
*/

/* object-fit：替换元素的填充方式 */

/* cover：裁剪填满（保持比例） */
.img-cover {
  width: 100%;
  height: 100%;
  object-fit: cover;
  /* 图片填满容器，超出部分裁剪 */
}

/* contain：完整显示（可能留白） */
.img-contain {
  width: 100%;
  height: 100%;
  object-fit: contain;
  /* 图片完整显示，可能有留白 */
}

/* fill：拉伸填满（变形） */
.img-fill {
  width: 100%;
  height: 100%;
  object-fit: fill;
  /* 拉伸填满，可能变形（默认值） */
}

/* none：保持原始尺寸 */
.img-none {
  width: 100%;
  height: 100%;
  object-fit: none;
  /* 不缩放，保持原始尺寸 */
}

/* scale-down：取 none 或 contain 中较小的 */
.img-scale-down {
  object-fit: scale-down;
}

/* object-position：调整显示位置 */
.img-position {
  object-fit: cover;
  object-position: center top;
  /* 居中顶部 */
}

/* 防止 CLS（布局偏移）最佳实践 */
.img-cls {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
  /* 图片加载前就预留好空间 */
}
