格式化上下文

理解 BFC / IFC / FFC / GFC 的创建方式与布局影响。

开场问题：父容器里明明塞了几个浮动子元素，它自己的高度却塌成了 0，背景色一块都看不见——父元素为什么「包不住」亲生骨肉？

高度塌陷与重叠

你在做一个经典的两栏页：左侧用 float 做侧栏，右侧放正文自适应剩余宽度；正文里几个相邻段落之间，间距也莫名地「消失」了一层。父容器的高度塌陷、侧栏与正文重叠、段落间距少了一截——三个看似无关的怪现象，其实是同一个东西在背后作祟。

这个东西叫格式化上下文：它规定了「盒子内部的元素按什么规则排布」。浮动元素脱离常规流、相邻外边距互相折叠、行内元素按基线对齐，全都由所在上下文的规则决定。不看清这层规则，你就会一直对着现象打补丁——加个空标签、写死一个高度，问题暂时消失，下次换个场景又冒出来。

应急补救写法

最省事的做法是「看现象出招」：父容器塌了，就给它写死一个 height；浮动影响了下文，就插一个 <div style="clear: both"> 的空标签。这套办法做对了一件事：它确实让当前这块页面立刻好看起来，改起来也直观。

只要内容高度固定、布局不再变动，这就算是「解决」了。问题出在「内容固定」这个假设上。

写死高度溢出

  • 写死的高度不会随内容变化，内容一多就溢出、一少就留白。
  • 插入空标签清除浮动会污染 DOM，语义上毫无意义的节点越攒越多。
  • 换成 overflow: hidden 虽然能包裹浮动，却会连带裁掉真正需要溢出的内容，还可能影响滚动行为。
  • 相邻段落的外边距为什么会合并，这套做法一个字都解释不了，只能靠记忆硬背。

浮动脱离常规流

不推翻「临时补救」，而是去理解规则本身：浮动元素会脱离常规流，不再参与父容器的高度计算，所以父容器自然包不住它；而块级元素上下相邻的外边距会折叠，取两者中的较大值，于是 30px 配 20px 只剩 30px。要改变这两个行为，就得让父容器建立一个新的布局规则——也就是创建一个新的格式化上下文。

最常见的是块级格式化上下文（BFC）。它一建立，父容器就会把内部的浮动元素重新纳入高度计算，同时阻断自身与外部、以及内部相邻盒之间的外边距折叠。创建方式有很多，但副作用差别很大：

  • overflow 取非 visible：有效，但可能裁掉溢出内容。
  • float 取非 none：会连自己都脱离常规流。
  • position: absolute 或 fixed：同样会脱离文档流。
  • display: flow-root：专门用来创建 BFC，且没有任何附带副作用，是当下的首选。
  • flex / grid 容器：本身就会建立对应的格式化上下文。

BFC 的三个经典用途，正好一一对应开场那三个怪现象：包裹浮动，让父容器重新量到自己孩子的高度；阻止外边距折叠，让段落间距如实生效；不与浮动重叠，让自适应宽度的正文自动避开侧栏，形成真正的两栏。display: flow-root 一写上，这三件事同时解决，而且不留后患。

接着把家族补齐。行内元素也有自己的上下文：一行文字里，文字、span、strong 这些行内级元素会落在同一个行盒里，按基线对齐，由 line-height 和 vertical-align 决定它们怎么站队——这就是行内格式化上下文（IFC）。它是自然形成的：只要一个块里只含行内级元素，这块内容就处于 IFC 之中，不需要你手动创建。

而当你写下 display: flex 或 display: grid，容器内部就分别切换成弹性格式化上下文（FFC）和网格格式化上下文（GFC）——它们不再遵循块级那套上下堆叠的规则，而是由主轴、交叉轴或网格轨道接管布局。换句话说，FFC 与 GFC 本质上就是 flex / grid 容器内部默认建立的格式化上下文，只是平时我们习惯说「用了 flex 布局」，而没意识到这一步同时也换掉了内部的布局规则。

类型创建方式主要作用
BFC（块格式化上下文）overflow 非 visible、display: flow-root、float 非 none、绝对定位、flex / grid 容器包裹浮动、阻止外边距折叠、不与浮动重叠
IFC（行内格式化上下文）块容器内只含行内级元素时自然形成行盒排列、基线对齐
FFC（弹性格式化上下文）display: flex / inline-flex按主轴与交叉轴排布子项
GFC（网格格式化上下文）display: grid / inline-grid按网格轨道排布子项
一条可长期沿用的结论：需要创建 BFC 时，优先写 display: flow-root。它既能把浮动包住、把外边距折叠挡住，又不像 overflow: hidden 那样暗中裁剪内容或改变滚动行为——用「副作用最小」的方式解决老问题。

BFC与IFC对照

格式化上下文归属

格式化上下文规定盒子内部的布局规则。BFC 能包裹浮动、阻断外边距折叠，display: flow-root 是最干净的创建方式；IFC 决定一行内行内元素的排列与基线对齐；display: flex / grid 则分别建立 FFC 与 GFC，各自接管主轴与网格布局。把浮动溢出、外边距折叠、行内对齐这三类老问题，统一归到「当前处于哪种上下文」里去想，解法就清楚了。

「格式化上下文」规定盒子内部元素的布局规则：BFC（块格式化上下文）可包裹浮动、阻断外边距折叠，常见创建方式有 overflow 非 visible、display: flow-root、float 非 none、绝对定位以及 flex / grid 容器，其中 display: flow-root 是建立 BFC 又无副作用的首选；IFC（行内格式化上下文）决定一行内行内元素的排列与基线对齐，当块容器只含行内级元素时自然形成；display: flex / grid 分别建立 FFC 与 GFC。浮动元素会脱离常规流，父容器包不住时用 BFC 包裹是经典解法。

关键代码

CSS
/* BFC：块级格式化上下文 */

/* 创建 BFC 的方式 */

/* 方式 1：overflow 非 visible */
.bfc-overflow {
  overflow: hidden;
  /* 创建 BFC */
}

/* 方式 2：display: flow-root（推荐，无副作用） */
.bfc-flow-root {
  display: flow-root;
  /* 专门创建 BFC */
}

/* 方式 3：浮动 */
.bfc-float {
  float: left;
  /* 创建 BFC */
}

/* 方式 4：绝对定位 */
.bfc-absolute {
  position: absolute;
  /* 创建 BFC */
}

/* BFC 作用 1：包含浮动（清除浮动） */
.clearfix {
  display: flow-root;
  /* 子元素浮动不会溢出容器 */
}

/* BFC 作用 2：防止外边距折叠 */
.no-collapse {
  display: flow-root;
  /* 子元素 margin 不会与外部 margin 折叠 */
}
.no-collapse p {
  margin: 16px 0;
  /* 不会与外部 margin 折叠 */
}

/* BFC 作用 3：阻止文字环绕浮动 */
.two-column {
  overflow: hidden;
  /* 创建 BFC，不与浮动重叠 */
}
.sidebar {
  float: left;
  width: 200px;
}
.content {
  display: flow-root;
  /* 自适应剩余宽度 */
}

/* IFC：行内格式化上下文 */
.ifc-text {
  line-height: 1.6;
  vertical-align: middle;
  /* 行内元素基线对齐 */
}

/* FFC：Flex 格式化上下文 */
.ffc-flex {
  display: flex;
  /* 创建 FFC */
}

/* GFC：Grid 格式化上下文 */
.gfc-grid {
  display: grid;
  /* 创建 GFC */
}
