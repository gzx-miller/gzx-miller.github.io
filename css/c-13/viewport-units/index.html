视口与容器单位

理解 vw / vh / dvh / cqw / rem / ch 的基准与适用场景。

开场问题：移动端用 height: 100vh 做整屏首屏，底部却总有一截被浏览器地址栏盖住——明明写的是「一整屏高度」，为什么到手却不满？

尺寸基准选择

你在做一个落地页：首屏 hero 区要占满整屏，下面是一个「刚好能放下 20 个字符」的搜索框，再往上还有一套按钮尺寸，希望用户放大字号时整体跟着变大。三件小事，全都卡在同一个决定上——长度的基准取谁。

拿 16px 这样的定值去写，屏幕一变、设备一换就追不上；可一旦换成相对单位，又得先回答「相对于什么」。单位选择不是记忆题，而是一道基准题：基准定错，算出来的尺寸就永远差一口气。不掌握它，你会得到被遮挡的首屏、靠猜宽度的输入框，以及一改字号就散架的布局。

全用像素写法

最省事的做法：所有尺寸一律用像素。height: 640px、width: 300px、font-size: 16px。这个方案做对了一件事：基准是死的，结果就确定。设计稿标多少就写多少，屏幕上量出来分毫不差。

在固定尺寸的屏幕上，这套写法完全够用。麻烦出在「屏幕不是固定的」这个前提上。

固定值跨屏失效

  • 设备宽度从 320px 到 1440px 不等，写死 300px 的卡片在宽屏里显得孤零零，在窄屏里又可能溢出。
  • 「占满一整屏」这个需求用像素根本表达不了——你并不知道对方屏幕有多高。
  • 「刚好容纳 20 个字符」更是写不出来，因为字符宽度随字号变化。
  • 用户把浏览器默认字号调大以看得更清楚时，你写死的 16px 纹丝不动，可访问性直接失守。

基准改为视口

不推翻「用数值描述尺寸」，而是把「基准」从常量换成环境。第一个自然的想法是百分比，但百分比量的是包含块，遇到「想要视口的高度」这种诉求时，根元素本身就没有一个更高的参照物了。所以需要一组直接以视口为基准的单位：vw 与 vh，各占视口宽度、视口高度的 1%。width: 100vw 就是整屏宽，height: 100vh 就是整屏高。

但整屏高这个诉求在移动端立刻翻车：vh 参照的是工具栏收起时的最大视口，可地址栏一展开，可见区域就矮了一截，元素底部被顶出屏幕。为此 CSS 补了三个动态单位：dvh 是动态视口高度，跟随工具栏的收起与展开实时变化；svh 取工具栏展开时的最小高度；lvh 取工具栏收起时的最大高度。移动端全屏内容优先用 dvh，就是让「一整屏」真正对齐你眼睛看到的那一屏。

还有一对与视口相关的单位值得记住：vmin 取视口较短边的 1%、vmax 取较长边。让一个正方形始终铺满缩放，就写 width: 50vmin 配 height: 50vmin，它跟着较短边缩放，横竖屏切换都不会溢出。

接着解决「全局缩放」和「定字符宽」。rem 相对于根元素字号，只要在 :root 上写 font-size: 16px，全套尺寸改用 rem 后，改这一处就能整体缩放——用户偏好被尊重，设计稿的倍数关系也保住了。em 则相对于当前元素字号，适合「内边距随字号成比例」这类局部关系，但要小心它逐层继承会累乘。ch 是字符 0 的宽度，约等于一个汉字的宽度，用它做输入框宽度就能恰好容纳指定字符数；正文段落限制在 60ch ~ 75ch，正是最舒服的阅读行宽。ex 是字母 x 的高度，做细小的垂直对齐时很有用。

最后是容器单位 cqw / cqh：它们不看向视口，而看向最近的容器查询容器，需要祖先先声明 container-type: inline-size。同一个组件放进宽容器就是大尺寸、放进窄容器就自动变小，这正是组件级自适应的关键——视口没变，容器变了，样式就该跟着变。

单位基准典型用途
vw / vh视口宽 / 视口高整屏布局、视口相关的比例
dvh / svh / lvh动态 / 最小 / 最大视口高移动端全屏，避开工具栏遮挡
vmin / vmax视口较短 / 较长边随屏幕缩放的正方形
rem / em根字号 / 当前元素字号可全局缩放的尺寸、随字号成比例的内距
ch / ex字符 0 宽 / 字母 x 高输入框定字符宽、正文最佳行宽
cqw / cqh容器宽 / 容器高组件级响应式，随宿主容器变化
一条实践红线：字号与间距尽量不要用绝对单位。缩放与用户偏好场景下，绝对单位会让布局彻底失去弹性——该跟着字号走的地方，请交给 rem 与 em。

不同基准对照

各类单位基准

选单位的本质是选基准：视口相关的交给 vw / vh，移动端全屏改用 dvh；可全局缩放的用 rem，随字号联动的内距用 em；要定字符数就交给 ch；组件要看的是容器而不是视口，那就用 cqw / cqh。基准选对，自适应几乎是自动发生的。

「视口单位与容器单位」是一组以环境尺寸为基准的长度单位：vw / vh 以视口宽高为基准各占 1%，其中 dvh 会随移动端工具栏动态变化，比固定的 vh 更贴近可见区域；cqw / cqh 以最近的容器查询容器为基准，需配合 container-type 使用。搭配 rem（相对根字号）与 ch（字符 0 宽度），即可分别覆盖可缩放的全局尺寸与定字符宽的输入框。移动端全屏优先 dvh，绝对单位避免用于字号与间距。

关键代码

CSS
/* vw：视口宽度的百分比 */
.vw-full {
  width: 100vw;
  /* 始终等于视口宽度 */
}

/* vh：视口高度的百分比 */
.vh-full {
  height: 100vh;
  /* 注意：移动端工具栏会导致问题 */
}

/* dvh：动态视口高度（推荐移动端使用） */
.dvh-full {
  height: 100dvh;
  /* 工具栏收起/展开时动态调整，更准确 */
}

/* svh / lvh：最小/最大视口高度 */
.svh-height {
  height: 100svh;
  /* 小视口高度（工具栏展开时） */
}

/* vmin / vmax：视口较小/较大边的百分比 */
.vmin-square {
  width: 50vmin;
  height: 50vmin;
  /* 正方形，随视口较小边缩放 */
}

/* rem：相对于根元素字体大小 */
.rem-size {
  font-size: 1.5rem;
  /* 1.5 * 根字号（通常 16px = 24px） */
}
:root {
  font-size: 16px;
  /* 修改根字号可全局缩放 */
}

/* em：相对于当前元素字体大小 */
.em-padding {
  font-size: 16px;
  padding: 1em;
  /* 1em = 16px */
}

/* ch：字符 0 的宽度（约等于一个汉字宽度） */
.ch-measure {
  width: 60ch;
  /* 最佳阅读宽度约 60-75ch */
}

/* cqw / cqh：容器查询单位（相对于容器宽度/高度） */
/* 需配合 container-type 使用 */
.container {
  container-type: inline-size;
}
@container (min-width: 400px) {
  .card {
    font-size: 2cqw;
    /* 容器宽度的 2% */
  }
}

/* ex：x 高度（小写字母 x 的高度） */
.ex-valign {
  height: 2ex;
}
