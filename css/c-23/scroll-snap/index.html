Scroll Snap 滚动定位

用 scroll-snap 实现精准的滚动定位，适合轮播、图片画廊和分页滚动。

开场问题：你写了个原生滚动轮播，用户松手后它总停在两张图中间，半张图卡在边上——怎么让滚动「自己停」在整页上？

松手整页停位

设想你在给课程详情页做一个移动端的图片画廊：一排封面横向排列，用户左右滑动切图，松手后应当稳稳停在某一整页上，而不是停在两张图之间露出半张。同类需求还有全屏分页的落地页、顶部的横向标签条。

不用 CSS 的方案，就得自己写脚本：监听 scroll 事件，读 scrollLeft，算出最近那一项的偏移量，再调用 scrollTo 把它「纠正」过去。这条路的代价，是一整套滚动手感的问题全要自己扛：手指还在惯性滑行时你强行 scrollTo，会和用户的动量打架，感觉像被抢了方向盘；scroll 事件在惯性滚动中一帧触发好几次，每帧都要算一次；触摸滑动、鼠标滚轮、键盘方向键的差异还得分别处理。而这些细节做不好的直接后果，就是用户觉得「这个轮播很别扭」。

手动对齐点计算

最朴素的做法，就是上面那套「先滚、再纠正到最近的对齐点」：监听滚动停止，量出偏移量，除以单项宽度得到索引，再滚回索引对应的整数倍位置。

它做对了一件关键的事：找准了正确的思路——滚动本身交给浏览器，脚本只负责把停下来的位置对齐。这也正是 Scroll Snap 背后的模型，值得保留；要改的只是「由谁来做这件事」。

惯性滚动判定

  • 需要自己判断「滚动是否结束」，判断早了会被惯性甩开，判断晚了用户已经看到错位。
  • 惯性滚动中频繁触发 scroll，每帧一次读取与写入，很容易掉帧。
  • 触摸、滚轮、键盘、滚动条的交互差异都要额外分支处理。
  • 每一项的宽度随响应式变化时，对齐计算要跟着重写。
  • 脚本未加载或被禁用时，滚动完全失去吸附能力。

声明式吸附规则

既然「先滚，再纠正到最近的对齐点」是对的，那就把这套逻辑交给浏览器，用声明式的写法告诉它对齐规则。这套能力叫 Scroll Snap，只需要两处声明：容器上说明滚动方向与对齐的严格程度，子项上说明自己要对齐到容器的哪个位置。

容器一侧用 scroll-snap-type 声明两个参数：轴与严格度。

.gallery { display: flex; overflow-x: auto; scroll-snap-type: x mandatory; gap: 16px; }

轴取 x 或 y，严格度取 mandatory 或 proximity。mandatory 表示强制停靠——只要滚动停下，浏览器一定把最近的对齐点吸附到边界上；proximity 表示接近时才吸附，松手位置离对齐点太远就随它去。轮播这类「必须一页一页看」的场景用 mandatory；长文档里希望滚动保持自然、只在快要对齐时轻轻吸附的，用 proximity。

最容易踩的坑：Scroll Snap 不会自己创建滚动容器。如果元素没有可滚动的溢出内容（例如忘了写 overflow: auto 或 overflow: scroll），scroll-snap-type 不会有任何效果——这常常是「明明写了属性却完全不动」的真正原因。

子项一侧用 scroll-snap-align 说明对齐点：

.slide { flex: 0 0 100%; scroll-snap-align: center; }

start 对齐容器起始边，end 对齐结束边，center 对齐中心。flex: 0 0 100% 让每一页正好占满容器宽度，配合居中对齐就是标准的整页轮播。

实际项目里最常见的一种错位来自固定导航：页面向下滚动时，对齐到顶部的子项被 80px 高的吸顶导航挡住了一截。解决办法不是在子项上加 margin，而是在滚动容器上留出偏移：

.page { scroll-padding-top: 80px; scroll-snap-type: y mandatory; }

scroll-padding 相当于给容器的可滚动区域加了一圈内边距，所有对齐点都以此为基准。与之对称的是子项上的 scroll-margin，它从元素这一侧外扩对齐基准，例如 scroll-margin: 16px 会让对齐时两边各留一点空隙。记住区分：scroll-padding 写在容器上，scroll-margin 写在子项上。

mandatory 虽然好用，却也有脾气：如果某个子项比容器还高（或还宽），浏览器会发现无论怎么对齐都无法把这一项完整停住，滚动体验就会变得别扭，甚至让人滑不过去。遇到内容长短不一的列表，改用 proximity 往往更稳。另外，高速滑动时用户可能一次越过好几个对齐点，若希望「一次只走一页」，可以在子项上加 scroll-snap-stop: always；平时保持默认的 normal 即可。

最后两个实用细节。轮播通常不希望露出滚动条，可以用 scrollbar-width: none，再配合 ::-webkit-scrollbar { display: none } 覆盖旧版内核——它只是把滚动条画没了，滚动能力本身不受影响。而全屏分页的落地页，本质就是让容器 height: 100vh 且 scroll-snap-type: y mandatory，每一节 height: 100vh 加 scroll-snap-align: start：一套纯 CSS 的「一屏一屏」翻页就完成了。

吸附轴与严格度

浏览器接管吸附

Scroll Snap 的价值在于把「滚动手感」这件很难做好的事交还给浏览器：容器用 scroll-snap-type 声明轴与严格度，子项用 scroll-snap-align 声明对齐点，中间不需要任何脚本参与。只要记住它需要 overflow 才会真正滚动、用 scroll-padding 避开吸顶导航、并在内容高度不齐时对 mandatory 保持警惕，原生轮播、画廊和分页滚动都能几行 CSS 写完。

「滚动吸附 Scroll Snap」是 CSS 原生实现的滚动定位机制。容器上写 scroll-snap-type 声明两个参数——滚动轴（x / y）与严格度（mandatory 强制停靠 / proximity 接近才吸附）；子项上写 scroll-snap-align 声明对齐点（start / center / end）。它必须配合 overflow: auto 或 scroll 才生效，可用 scroll-padding（写在容器）与 scroll-margin（写在子项）微调对齐位置。

关键代码

CSS
/* Scroll Snap 容器设置 */

/* 水平滚动 + 强制对齐 */
.snap-x-mandatory {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  /* x: 水平方向，mandatory: 强制对齐 */
  gap: 16px;
  scrollbar-width: none;
}
.snap-x-mandatory::-webkit-scrollbar {
  display: none;
}

/* 垂直滚动 + 接近时对齐 */
.snap-y-proximity {
  overflow-y: auto;
  scroll-snap-type: y proximity;
  /* y: 垂直方向，proximity: 接近时才对齐 */
  height: 400px;
}

/* 子项：对齐到起始位置 */
.snap-item-start {
  scroll-snap-align: start;
  /* 对齐到容器起始位置 */
}

/* 子项：居中对齐 */
.snap-item-center {
  scroll-snap-align: center;
  /* 对齐到容器中心 */
  flex: 0 0 100%;
}

/* 子项：对齐到结束位置 */
.snap-item-end {
  scroll-snap-align: end;
  /* 对齐到容器结束位置 */
}

/* scroll-padding：处理固定导航栏遮挡 */
.snap-container {
  scroll-padding-top: 80px;
  /* 顶部留出 80px 给固定导航 */
  scroll-snap-type: y mandatory;
}

/* scroll-margin：子项的边距调整 */
.snap-item {
  scroll-margin: 16px;
  /* 对齐时的边距 */
}

/* 全屏分页滚动 */
.fullpage {
  height: 100vh;
  overflow-y: scroll;
  scroll-snap-type: y mandatory;
}
.fullpage section {
  height: 100vh;
  scroll-snap-align: start;
}

/* 轮播图效果 */
.carousel {
  display: flex;
  overflow-x: auto;
  scroll-snap-type: x mandatory;
  scroll-behavior: smooth;
}
.carousel-item {
  flex: 0 0 100%;
  scroll-snap-align: center;
}

/* 注意：scroll-snap 不会创建滚动容器，需配合 overflow 使用 */
/* 注意：mandatory 强制对齐可能导致内容无法停留，需谨慎使用 */
