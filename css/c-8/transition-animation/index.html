过渡与动画

用卡片交互动效对比 transition 与 animation 的触发方式与适用场景。

开场问题：按钮悬停时颜色「啪」地一下就变了，想让它平滑一点却不知从何下手；另一边，加载图标要自己一直转，可它根本没有鼠标事件可以触发——这两种变化，是同一回事吗？

交互反馈两类动效

你在做一组交互反馈：卡片悬停要微微上浮，按钮按下要柔和变色，加载时那个小圆圈要不停旋转。如果只是把 :hover 里的颜色改掉，界面确实"响应"了，但变化是瞬时的，像被硬生生切换过去，观感生硬；而加载图标更棘手，它的转动不依赖任何用户操作，你连一个触发点都找不到。

根子在于：面对"值要变化"这件事，浏览器其实提供了两条完全不同的路径。一条是补间——在两个状态之间自动算出中间帧；另一条是关键帧——由你直接描述整段变化过程。分不清这两条路，就会在需要自动播放时硬凑一个触发条件，或者在只有两个状态时煞有介事地画一堆关键帧。

属性值直接切换

最省事的做法：直接改属性值。:hover 里写上新的颜色或位置，让元素在两种状态间切换。

这个方案做对了最基础的一层：状态被区分开了。悬停与未悬停是两个明确的视觉状态，用户能感知到交互发生了。当变化很小、或者你只想要"切换"而非"过渡"时，它简单直接，没有多余成本。

瞬时切换局限

  • 值的变化是瞬时的，没有中间过程，观感生硬，缺了过渡的圆润。
  • 变化必须由状态改变触发（:hover、类名切换等），没有任何事件可挂的持续动效无从下手。
  • 多阶段的变化——比如弹跳要先上、再下、再上——两个状态根本表达不了。
  • 想让动效循环播放、反向播放或中途暂停，也无从配置。

过渡属性与补间

第一条路径是 transition（过渡）。在起始状态上声明要过渡的属性、时长与缓动函数，浏览器就会在状态切换时自动补齐中间帧：

.btn { transition: background 0.3s ease, transform 0.2s ease-out; }，配合 .btn:hover { background: #d9480f; transform: translateY(-2px); }。简写顺序是 property / duration / timing-function / delay，例如 transition: all 0.3s ease-in-out 0.1s。

但要记住它的边界：transition 只负责两个状态之间的插值，触发条件必须是状态变化；它一次只连接"起点"和"终点"两点，中间插不进第三个形态。缓动函数（ease、linear、ease-in-out 等）则决定这段补间的节奏是匀速还是先慢后快。

第二条路径是 animation（动画）。用 @keyframes 定义任意多个关键帧，再用 animation 挂到元素上，它便能自动播放，无需任何触发：.spinner { animation: spin 1s linear infinite; }，配合 @keyframes spin { from { transform: rotate(0deg); } to { transform: rotate(360deg); } } 就得到一个转不停的加载圈。关键帧还能写成多阶段，比如弹跳的 0%, 20%, 50%, 80%, 100% 停在原位、40% 抬到最高。

动画还有几个过渡没有的能力：forwards 能让它播完后停在最后一帧而不弹回起点，alternate 让往返播放更自然，animation-play-state: paused 可以随时暂停。调试动效时，把 animation-duration 临时调慢到几秒，就能逐步看清关键帧之间是怎么补间的——比盯着飞速闪过的一瞬间去猜可靠得多。时长与缓动函数共同决定观感的流畅与节奏，这也是它俩最值得反复微调的地方。

把两者的能力放在一起对比，选择就清晰了。

能力transitionanimation
触发方式状态变化（:hover 等）自动播放 / JS 控制
关键帧不支持，只有起止两点支持 @keyframes
循环单次infinite 持续循环
反向 / 暂停不支持alternate / animation-play-state
性能与无障碍：优先过渡 transform 与 opacity，它们走合成器、开销低且不触发重排；动画里避免动 width、height、margin 这类会引发重排的属性。另外，别忘了用 @media (prefers-reduced-motion: reduce) 为动效提供降级，尊重用户在系统里设置的"减弱动态"偏好。

两种动效对照

触发与循环分工

过渡与动画解决的是同一个问题的两面：当变化只是两个状态之间的插值、且由交互触发时，用 transition；当动效需要自动播放、循环、反向或中途暂停时，用 @keyframes 动画。区分开「谁触发、有几帧」，再挑对合成友好的属性，动效就能既流畅又克制。这条判断链其实很短：先问它由谁触发、有几个关键帧，答案自然指向某一条路径。

「transition 与 animation」transition 在状态变化（如 :hover）时于两个值之间补间过渡，只连接起止两点；animation 通过 @keyframes 定义关键帧，可自动播放、infinite 循环、alternate 反向与 animation-play-state 暂停，适合无需用户触发的持续动效。动效优先用 transform 与 opacity，并用 prefers-reduced-motion 提供降级。

关键代码

CSS
/* transition 过渡：需要状态变化触发 */
.btn {
  background: #e8590c;
  transition: background 0.3s ease, transform 0.2s ease-out;
  /* 过渡属性 + 时长 + 缓动函数 */
}
.btn:hover {
  background: #d9480f;
  transform: translateY(-2px);
}

/* transition 简写：property duration timing-function delay */
.card {
  transition: all 0.3s ease-in-out 0.1s;
}

/* 常用缓动函数 */
.ease-linear { transition-timing-function: linear; }
.ease-in { transition-timing-function: ease-in; }
.ease-out { transition-timing-function: ease-out; }
.ease-in-out { transition-timing-function: ease-in-out; }

/* @keyframes 关键帧动画 */
@keyframes fadeIn {
  from {
    opacity: 0;
    transform: translateY(20px);
  }
  to {
    opacity: 1;
    transform: translateY(0);
  }
}

/* 使用动画 */
.animate-fade-in {
  animation: fadeIn 0.5s ease forwards;
  /* 动画名 + 时长 + 缓动 + 填充模式 */
}

/* animation 完整属性 */
.spinner {
  animation: spin 1s linear infinite;
  /* 无限循环旋转 */
}
@keyframes spin {
  from { transform: rotate(0deg); }
  to { transform: rotate(360deg); }
}

/* 多阶段关键帧 */
@keyframes bounce {
  0%, 20%, 50%, 80%, 100% {
    transform: translateY(0);
  }
  40% {
    transform: translateY(-20px);
  }
  60% {
    transform: translateY(-10px);
  }
}
