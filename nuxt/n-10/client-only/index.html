ClientOnly 与客户端专属渲染

掌握 ClientOnly 组件、import.meta.client 判断与 .client.ts 后缀等客户端专属渲染方式。

开场问题：你要在页面里放一个图表，这个库内部会拿 document 去量容器尺寸。本地 dev 跑得好好的，SSR 一开，服务端渲染到图表那一步直接抛出 document is not defined，整个页面变成 500。你只是想「让服务端跳过画图这一小块」，为什么会闹出这么大动静？

浏览器专属依赖

接上一课：SSR 里两端的执行环境不同，有些内容天生只能在浏览器里跑——直接操作 DOM 的图表库、依赖 window 与 navigator 的浏览器 API、以及「当前时间」这类动态值。把它们硬塞进 SSR，要么报错，要么 mismatch。旧办法各有代价。

直接整页关掉 SSR（ssr: false），等于把首屏和 SEO 的收益一起赔了进去；在每个用到的地方写 typeof(window) !== 'undefined' 兜底，逻辑散落各处，而且模板结构两端仍可能对不上；干脆不用这个库，则需求根本做不了。

于是问题落到：能不能只把「确实只能在浏览器跑的那一小块」摘出来、延后到客户端，其余部分照常 SSR？

客户端环境判定

最直接的判断是 import.meta.client：在 setup 里写 if (import.meta.client) { ... }，把只该在浏览器执行的逻辑包起来。

它做对了一件事：这是一个编译期常量。Nuxt 构建时会把它直接替换成 true 或 false，服务端那份产物里的分支会被静态消除，不留下运行时判断的开销。

但它只管得住「逻辑」，管不住「模板里那块要渲染的 DOM」。

模板结构注水失配

  • import.meta.client 只切 JS 分支。模板里基于它渲染出的结构，在服务端仍会生成一份不同的 DOM，照样可能 mismatch。
  • 在 setup 顶层用 typeof(window) !== 'undefined' 兜底，能防报错，但服务端与客户端首次渲染结构不同，mismatch 依然会发生。
  • 直接给整个页面加上 ssr: false，就是放弃了前面几课讲的所有 SSR 好处——首屏更快、SEO 可抓。
  • 当第三方库需要的是「在应用启动时初始化一次」，而你把它塞进某个组件里判断，就会变成每个组件实例都要重复初始化。

延迟渲染工具选择

正确的做法是按「要推迟的是什么」来选工具，而不是一把梭。

  1. 要推迟的是一整块渲染（比如图表组件），用 <ClientOnly> 把它包起来，并用 <template #fallback> 给出服务端期间的占位：服务端不执行这块子树，自然不会碰到 document；首屏有占位，客户端接管后再替换成真正的内容。
  2. 占位要长得像最终内容。fallback 的结构和尺寸尽量与真实组件相仿，否则内容突然出现时会把周围布局撑开，产生 CLS（累计布局偏移）这种「页面抖一下」的体验。
  3. 只是想避开某一次浏览器 API 的调用、而不涉及整块 DOM，用 import.meta.client 就够；只是想在挂载之后写一个客户端专属的值（如当前时间、navigator.userAgent），用 onMounted 最轻。
  4. 需要让第三方库在整个客户端初始化一次，就把插件命名为 *.client.ts，Nuxt 只在客户端加载它，比在每个组件里判断干净得多。

最后要克制：这些手段本质上都是「绕过 SSR」，用得越多，SSR 的首屏与 SEO 收益就被削得越薄。只对确有必要的那部分使用——一个图表可以 ClientOnly，但整页数据没必要跟着一起跳过服务端。

两个常见误用：fallback 占位如果和最终内容差太多，会让页面在渲染完成的一刻跳一下（CLS）；为了省事直接给整页 ssr: false，则把首屏体验和 SEO 一起关掉了——客户端专属渲染应该只覆盖那一小块不兼容 SSR 的内容。

加载前后内容差异

局部浏览器接管

客户端专属渲染不是「把 SSR 关掉」，而是「只把不兼容 SSR 的那一小块留给浏览器」：整块内容用 <ClientOnly> 加 fallback 占位，单次 API 调用用 import.meta.client 分支，挂载后再写入的值交给 onMounted，需要全端初始化的库用 *.client.ts。用得越少，SSR 的首屏与 SEO 就保留得越完整。

「CLS（Cumulative Layout Shift，累计布局偏移）」衡量页面加载过程中可见元素发生意外位移的 Web Vitals 指标：某个元素在渲染中途「跳」了位置，分数就会累加。在不兼容 SSR 的部分使用 <ClientOnly> 时，<template #fallback> 的占位必须与客户端最终内容的结构、尺寸相仿，否则占位被替换的那一刻会把周围内容顶开，产生明显的 CLS。边界：占位「矮了」或「空了」都会在替换时引发跳动，可用最小高度等预留空间来避免。
