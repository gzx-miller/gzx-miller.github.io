运行时配置

掌握 runtimeConfig 的公有/私有配置、环境变量映射及与 app.config.ts 的区别。

开场问题：你把两个配置都写进了同一个 runtimeConfig：一个 secretKey 放在顶层，一个 apiKey 放在 public 里。上线后你在浏览器里搜打包好的 JS，发现 apiKey 赫然躺在里面，而 secretKey 怎么也搜不到。同一份配置，凭什么一个能被用户翻出来、另一个藏得住？

公有私有配置混同

「配置」这个词其实把两件完全不同的事混在了一起。一类是主题色、功能开关这种代码的一部分，定了就不该变；另一类是数据库地址、密钥、按环境切换的接口域名这种随运行环境变化的东西。前者可以写死在仓库里，后者绝不能。

旧办法通常只有两种，各有代价。把所有值都写死在配置文件里：换个环境就得改代码重新构建，CI 上根本没法改。把所有值都塞进环境变量：服务端没问题，可前端要用一个本来就该公开的公钥时，客户端进程读不到 process.env，你还得自己想办法把它注入到浏览器里。

更麻烦的是第三笔成本：需要打进客户端的公钥，和绝不能出服务端的密钥，如果放在同一个地方，打包时无法区分。稍不留神把密钥写进会被序列化给客户端的那一侧，就等于把它公开了——而且本地开发时你完全看不到异常，直到上线后才暴露。

于是问题落到：能不能用一个统一入口管理配置，同时明确标出「哪部分是公开的、哪部分只给服务端」，并且靠环境变量在各环境覆盖默认值？

两层结构集中声明

在 nuxt.config.ts 里用 runtimeConfig 集中声明配置，并且分成两层：顶层是私有配置，比如 secretKey、dbUrl；public 下是公有配置，比如 apiKey、appVersion。

这个方案做对了一件事：用同一个入口管配置，并在写代码时就显式声明了可见范围。选错了位置会立刻在结构上显得别扭，而不是等到上线才靠搜索 JS 排查。

环境覆盖与读取方式

  • 只声明了默认值，各环境要怎么覆盖？总不能在每个环境的 CI 里都改一次 nuxt.config.ts。
  • 服务端和客户端的读法不一样：在浏览器里调用 useRuntimeConfig() 后写 config.secretKey 拿到的是 undefined，调试时很容易误判成「配置没读到」。
  • 它和 app.config.ts 的关系不清——把主题色放错地方，就会出现「改了配置却没生效」。
  • 把密钥误放进 public 而不自知：本地能正常读到，一切看起来都对，直到有人打开浏览器开发者工具。

前缀环境变量覆盖

不推翻这套分层，而是把「覆盖、读取、安放」三件事各自补清楚。

先补覆盖方式：用带 NUXT_ 前缀的环境变量在部署时覆盖默认值。规则是固定的——NUXT_PUBLIC_ 前缀的变量映射到 config.public 下（如 NUXT_PUBLIC_API_KEY 对应 config.public.apiKey），NUXT_ 前缀的变量映射到顶层私有配置（如 NUXT_SECRET_KEY 对应 config.secretKey）。这样一来，同一份代码在不同环境靠注入环境变量切换，不用改一行代码。

再补读取场景。服务端用 useRuntimeConfig(event)，可以读到全部配置，包括私有项；客户端用 useRuntimeConfig()，只能读到 public 下的配置。这个差异不是缺陷，而是一条明确的安全边界：凡是要读密钥的逻辑，必须待在服务端一侧（server/api、server/routes 或服务端中间件里），不要在组件里试图读取它。

最后补构建期常量的安放。主题色、功能开关这类不敏感、不随环境变化、构建后就固定的常量，放 app.config.ts，用 useAppConfig() 读取。它和 runtimeConfig 的定位刚好互补：一个在构建期确定、不读环境变量，一个在运行时由环境变量注入。分清了这条线，就不会再出现「配置改了不生效」的困惑。

最该记住的一条：不要把密钥放进 public 配置——它会被打包并暴露到客户端代码里，任何访问者都能看到。反过来，public 是专门留给「本来就要暴露给浏览器的公钥、版本号」的。另外要意识到 runtimeConfig 是在应用启动时读取环境变量的，修改它之后需要重启 dev server 或重新部署才生效，热更新不会带上新值。

配置定义与使用对照

分层声明与可见范围

运行时配置解决的是「同一份代码怎么在不同环境跑成不同样子，同时不把秘密带出服务器」：分层声明决定可见范围，NUXT_ 前缀的环境变量负责覆盖，useRuntimeConfig(event) 与 useRuntimeConfig() 的差异守住安全边界，而构建期固定、不随环境变化的东西交给 app.config.ts。想清一个值「要不要给浏览器看、跟不跟环境变」，答案就唯一了。

「公有运行时配置（public runtimeConfig）」指定义在 runtimeConfig.public 下的配置项，服务端与客户端都能读取，并且会被序列化进发往客户端的载荷。它适合承载本来就要暴露给浏览器的公钥、CDN 域名、应用版本号。边界：放进来的东西等同于公开，绝不能放密钥或任何服务端凭证；它与私有配置共用 NUXT_ 前缀映射规则，但公有项要多一段 PUBLIC_（即形如 NUXT_PUBLIC_API_KEY），并且只有它能在客户端被读到。

<script setup lang="ts">
import { ref, computed } from 'vue'

const activeSection = ref<'config' | 'env' | 'usage'>('config')

const publicApiKey = ref('pk_live_abc123')
const secretKey = ref('sk_live_xxx')
const appVersion = ref('1.0.0')

const runtimeConfigCode = `// nuxt.config.ts
export default defineNuxtConfig({
  runtimeConfig: {
    // 私有配置（仅服务端）
    secretKey: process.env.SECRET_KEY || 'dev-secret',
    dbUrl: process.env.DATABASE_URL,
    
    // 公有配置（客户端 + 服务端）
    public: {
      apiKey: process.env.PUBLIC_API_KEY || '',
      appVersion: '1.0.0',
      baseUrl: process.env.PUBLIC_BASE_URL || 'http://localhost:3000',
    },
  },
})`

const envFileCode = `# .env 文件
SECRET_KEY=my-super-secret-key
DATABASE_URL=postgresql://localhost:5432/mydb
PUBLIC_API_KEY=pk_live_abc123
PUBLIC_BASE_URL=https://example.com

# .env.production
SECRET_KEY=prod-secret-key
PUBLIC_API_KEY=pk_live_prod`

const usageCode = `// 服务端 API 中使用
// server/api/data.ts
export default defineEventHandler((event) => {
  const config = useRuntimeConfig(event)
  // 可以访问所有配置
  const secret = config.secretKey
  const dbUrl = config.dbUrl
  const apiKey = config.public.apiKey
})

// 客户端组件中使用
const config = useRuntimeConfig()
// 只能访问 public 下的配置
console.log(config.public.apiKey)  // ✅
console.log(config.public.appVersion)  // ✅
// console.log(config.secretKey)  // ❌ undefined

// 使用 useAppConfig（编译时配置）
const appConfig = useAppConfig()
console.log(appConfig.theme)  // 不可在运行时修改`

const appConfigCode = `// app.config.ts（编译时配置）
export default defineAppConfig({
  theme: {
    primaryColor: '#e85d04',
    borderRadius: '8px',
  },
  features: {
    darkMode: true,
    analytics: false,
  },
})

// 与 runtimeConfig 区别：
// app.config.ts → 构建时确定，不可用环境变量
// runtimeConfig → 运行时确定，可用环境变量`
