useAsyncData：异步数据管理

深入 useAsyncData 的 key 管理、去重策略、数据转换与 lazy 模式。

开场问题：聊天页里，用户点开 A 会话，还没加载完又点了 B，接着又点回 A。三个请求都发出去了，最后屏幕上显示的消息却来自 B——明明你最新点的是 A。代码没错，只是手指比接口快了一点。

复杂异步编排需求

你想在组件里跑一段不那么简单的异步逻辑：有时要先算出参数再请求、有时要同时拉好几个接口、有时要对返回结果换算一下再用、有时还得控制「并发时谁生谁死」。最朴素的写法仍然是 onMounted 里 await，而它的代价比想象中多。

它在 SSR 阶段不执行，首屏没数据；每处都要重写 loading 与 error；多个请求串行 await，一个慢就拖住整页；更要命的是竞态——先发的请求不一定先回来，晚到的旧结果会覆盖新结果，正是开场里 B 顶掉 A 的原因。

于是问题落到：能不能有一个比 useFetch 更底层的 API，让我自己掌控 key、并发策略、数据转换和请求时机？

手动键调用形式

最朴素的写法是：const { data, pending, error, refresh } = await useAsyncData('users', () => $fetch('/api/users'))。

它做对了一件事：把「异步逻辑」和「响应式状态」拆开了。你只提供两样东西——一把 key 和一个返回 Promise 的处理函数；至于加载态、错误态、以及结果如何在服务端与客户端之间传递，全交给它。因为 key 由你自己给，你也就第一次有了「控制同一份数据怎么被缓存、怎么被复用」的抓手。

键冲突与数据覆盖

  • key 得你自己保证全局唯一。两个地方写出相同的 key，后写的会覆盖前者的数据，而且不报错。
  • 默认情况下，同一个 key 的并发请求可能各跑各的；快速切换时，先发的旧请求后返回，会覆盖掉新请求的结果——就是开场的竞态。
  • 原始响应会被直接写进 data。像 price 以「分」为单位这种事，就得在模板里到处做除法换算，既啰嗦又容易漏。
  • 数据没回来时 data 是 undefined，模板里直接访问 data.items 会当场报错。
  • 一个不重要的统计接口若也用默认方式（阻塞导航），整个路由切换都得等它。

四层控制力补齐

不推翻这套用法，而是顺着「key → 并发 → 数据形状 → 时机与缓存」的顺序，一层层补足控制力。

  1. 手动 key：给每次获取指定一把全局唯一的 key。Nuxt 靠这把 key 做结果缓存与请求去重——这也是它比 useFetch 更底层的地方：key 不再由 URL 自动生成，而是你说了算。
  2. 并发与去重：要同时拉多个接口，别写成上下两句 await（那是串行），而是先分别调用、拿到各自的 Promise 后再统一等待。要处理同 key 的并发冲突，就用 dedupe 指定策略：'defer' 让进行中的同 key 请求共享结果，'cancel' 则取消前一个、只保留最新一次——开场那种「连点」造成的覆盖，用 'cancel' 就能治好。
  3. 整理数据：transform 会在写入 data 之前对原始响应做加工（比如把「分」换算成「元」），它的返回值类型就是最终 data 的类型；default 则给 data 一个安全的初始值，让模板在数据到达之前也不会撞上 undefined。
  4. 时机与缓存：用 useLazyAsyncData（等价于 lazy: true）让请求不阻塞导航，请求期间 pending 为真，配合它渲染加载态即可；注意 lazy 只影响「导航要不要等」，并不改变请求什么时候发出，那是 immediate: false 单独控制的，两者含义不同。若要更细地决定「缓存从哪来、命中就不请求」，可用 getCachedData 自定义取缓存的逻辑；需要手动重取时，仍调用 refresh()。
三个易混点：key 必须全局唯一，撞 key 会静默覆盖数据；lazy 只管导航是否等待、不管请求时机，跳过首次执行要用 immediate: false；default 的返回类型要与最终数据兼容，否则模板里还是会冒出 undefined。

同段代码选项差异

缓存去重与并发控制

useAsyncData 把控制权交还给你：一把手动指定的 key 决定缓存与去重，dedupe 决定并发时共享还是取消，transform 与 default 负责数据形状，lazy 决定导航要不要等。当你需要的不只是「取一个 URL」，而是「编排一段异步逻辑」时，它才是那把更合手的工具。

「useAsyncData」比 useFetch 更底层的异步数据 composable：由你手动提供全局唯一的 key 和一个返回 Promise 的处理函数，Nuxt 据此完成 SSR/CSR 数据传递、缓存与请求去重。通过 dedupe 控制并发策略（'defer' 共享进行中的同 key 请求、'cancel' 取消旧请求保留新请求）、transform 加工响应、default 提供初始值、lazy 与 useLazyAsyncData 不阻塞导航。边界：key 必须全局唯一，重复即互相覆盖；lazy 只影响是否阻塞导航、不改变请求时机；immediate: false 与 lazy: true 语义不同。

<script setup lang="ts">
import { ref, computed } from 'vue'

const scenario = ref<'basic' | 'dedupe' | 'transform' | 'lazy'>('basic')

const scenarios = {
  basic: {
    title: '基本用法',
    code: `const { data, pending, error, refresh } = 
  await useAsyncData('users', () => $fetch('/api/users'))`,
    desc: '手动指定 key，控制缓存和去重逻辑。key 相同的请求会复用结果。',
  },
  dedupe: {
    title: '去重策略',
    code: `const { data } = await useAsyncData('users', 
  () => $fetch('/api/users'), 
  { dedupe: 'defer' }  // 或 'cancel'
)`,
    desc: 'defer：已有相同 key 的请求进行中，则等待其完成共享结果。cancel：取消前一个请求，发起新请求。',
  },
  transform: {
    title: '数据转换',
    code: `const { data } = await useAsyncData('products', 
  () => $fetch('/api/products'),
  { 
    transform: (data) => data.map(p => ({
      ...p, price: (p.price / 100).toFixed(2)
    })),
    default: () => [],  // 初始默认值
  }
)`,
    desc: '在服务端获取原始数据后，用 transform 处理格式；default 提供 data 的初始值，避免 undefined。',
  },
  lazy: {
    title: 'Lazy 模式',
    code: `// 不等待 SSR，客户端再请求
const { data, pending } = useLazyAsyncData(
  'analytics', 
  () => $fetch('/api/analytics')
)`,
    desc: 'useLazyAsyncData 不会阻塞导航，数据到达前 data 为 undefined、pending 为 true。适合非核心内容。',
  },
}
</script>
