API 路由：Server Routes

掌握 server/api/ 目录创建 API 路由，理解方法后缀与请求参数的获取。

开场问题：你想给页面加一个后端接口，于是新建了 server/api/hello.ts，里面只写了一个返回对象的函数。你没有装 Express、没有写 app.get('/api/hello', handler)，也没有在任何一个地方「注册」过这个路由，可浏览器里请求 /api/hello 竟然直接通了——这个接口到底是被谁登记进去的？

显式路由登记

在传统的 Node 后端里，「一个 URL 对应一段代码」这件事必须显式登记。你用 Express 写接口，路由表就是那个中枢：app.get('/api/hello', handler)、app.post('/api/users', handler)，每加一个接口都要在这里多写一行。路由表和处理函数分居两处，接口一多，它就成了一份需要维护的清单。

这份清单的成本有三样。第一是路径写两遍：文件里定义了一次，路由表里又声明一次，改了目录或文件名，两处得同时对齐，漏改一个就是线上 404。第二是中枢会膨胀：所有接口都往同一个文件里堆，它随接口数量线性变长，启动时要一次性加载完。第三是没有结构约束：路径怎么写、允许哪些方法、参数从哪儿取，全靠每个 handler 自己记约定，谁都没法保证一致。

于是问题落到：能不能让「文件本身」就是端点，路径由文件在目录里的位置推导出来，连允许的 HTTP 方法也由文件名写清楚？

文件即端点约定

在项目根目录建一个 server/api/ 目录，按想要的路径在里面放文件。文件内容只做一件事：默认导出一个 defineEventHandler 处理函数，返回什么，接口就响应什么。

具体到开场那个例子：server/api/hello.ts 里导出 defineEventHandler(() => ({ message: '你好，小松鼠！' }))，它就自动成为 /api/hello；返回值会被自动序列化成 JSON。

这个方案做对了一件事：路径不再写第二遍。文件在哪儿，接口就在哪儿，路由表被文件系统取代了。这条约定和 Nuxt 的 pages/ 路由是同一套心智模型——目录结构即路径结构，你只是把「页面」换成了「接口」。

默认响应全部方法

  • 只按文件推导路径，默认对所有 HTTP 方法都响应：GET、POST、DELETE 打进来都命中同一个 handler，一个删除接口被 GET 也能触发。
  • 参数还没着落：查询串和请求体是两种形态，不区分来源就会把请求体当查询串去取，拿到的是 undefined。
  • 动态段 [id].ts 里的那个 id 不会自己冒出来，自己拿 event.path 切字符串既易错又没法类型化。
  • 想返回一个 404 却只能 throw new Error()，它一律变成 500「服务器内部错误」，前端拿不到你想表达的状态码。

后缀限定请求方法

不推翻「文件即端点」，而是在文件名与处理函数上一层层补约定。

先补方法。给文件名加后缀限定它能响应的方法：users/index.get.ts 只接 GET，users/index.post.ts 只接 POST，users/[id].delete.ts 只接 DELETE。不带后缀的文件会对各种方法都做出响应——这正是上面那个坑，所以写写操作接口时，后缀不是可选项，而是必须显式做的决定。

再补参数。取值一律走 h3 提供的工具，而不是自己去翻原始请求对象：readBody(event) 读请求体（是异步的），getQuery(event) 读查询串，getRouterParam(event, 'id') 读动态段。这些函数是自动导入的，不用手写 import，而且返回的值会按同一套规则序列化回 JSON。

接着补响应的表达力。要改状态码用 setResponseStatus(event, 201)，要加响应头用 setResponseHeader(event, 'Cache-Control', 'max-age=3600')；要报错就用 createError({ statusCode: 404, statusMessage: 'Not Found' }) 抛出，它会被转换成带状态码的错误响应，前端拿到的就是 404 而不是裸 500。

最后把这一层和周边划清边界。server/api 的路由空间与 pages 完全独立，接口文件与页面文件同名互不冲突；server/middleware/ 下的文件会自动注册为服务端中间件，对每个服务端请求生效，适合做鉴权；server/utils/ 里导出的函数同样自动导入，可在 API 处理器与中间件中复用。

一个容易踩的坑：不带方法后缀的处理文件会对各种 HTTP 方法都做出响应。写删除、修改这类有副作用的接口时一定要加 .delete.ts / .put.ts 后缀，否则一个普通的 GET 请求就能触发写操作——这类问题在本地测试里几乎不会暴露，上线后却可能被爬虫误触发。

三类接口写法对照

端点推导约定收益

server/api/ 把后端接口变成了文件系统约定的产物：目录位置决定路径，文件后缀决定方法，导出 defineEventHandler 决定行为。你因此少维护一张路由表，也少了一次「路径写两遍」的机会；参数与错误则统一从 h3 的工具进出，接口的进出形态在文件层面就写清楚了。

「事件处理器（event handler）」指 defineEventHandler 默认导出的那个函数，它接收一个封装了请求与响应的 event 对象，返回值即响应体并自动序列化为 JSON。边界：它是自动导入的（来自 h3），不要手写 import；请求数据一律通过 readBody / getQuery / getRouterParam 这类工具读取，而不是直接操作 event.node.req，否则会绕过 h3 的解析与类型，拿到未经处理的内容。

<script setup lang="ts">
import { ref } from 'vue'

const activeTab = ref<'basic' | 'method' | 'params'>('basic')

const apiExamples = {
  basic: {
    title: 'GET 接口',
    code: `// server/api/hello.ts
export default defineEventHandler((event) => {
  return { message: '你好，小松鼠！' }
})

// 请求 GET /api/hello
// 响应 { "message": "你好，小松鼠！" }`,
  },
  method: {
    title: 'RESTful 方法',
    code: `// server/api/users/index.get.ts → GET /api/users
export default defineEventHandler(async (event) => {
  return [{ id: 1, name: '松鼠' }]
})

// server/api/users/index.post.ts → POST /api/users
export default defineEventHandler(async (event) => {
  const body = await readBody(event)
  return { id: 2, ...body }
})

// server/api/users/[id].delete.ts → DELETE /api/users/:id
export default defineEventHandler((event) => {
  const id = getRouterParam(event, 'id')
  return { deleted: id }
})`,
  },
  params: {
    title: '参数与工具',
    code: `// 路由参数
const id = getRouterParam(event, 'id')

// 查询参数
const query = getQuery(event)  // ?page=1&size=10

// 请求体
const body = await readBody(event)

// 设置响应头
setResponseHeader(event, 'Cache-Control', 'max-age=3600')

// 设置状态码
setResponseStatus(event, 201)

// 返回错误
throw createError({
  statusCode: 404,
  statusMessage: 'Not Found'
})`,
  },
}

const demoResult = ref('')
const demoLoading = ref(false)

async function callDemoApi(type: 'hello' | 'users' | 'error') {
  demoLoading.value = true
  demoResult.value = ''

  await new Promise(r => setTimeout(r, 500))

  if (type === 'hello') {
    demoResult.value = JSON.stringify({ message: '你好，小松鼠！' }, null, 2)
  } else if (type === 'users') {
    demoResult.value = JSON.stringify([{ id: 1, name: '松鼠' }, { id: 2, name: '栗子' }], null, 2)
  } else {
    demoResult.value = JSON.stringify({ statusCode: 404, statusMessage: 'Not Found' }, null, 2)
  }
  demoLoading.value = false
}
</script>

<template>
  <div class="demo-card">

      <button v-for="(val, key) in apiExamples" :key="key"
              :class="{ active: activeTab === key }"
              @click="activeTab = key as keyof typeof apiExamples">
        {{ val.title }}
      </button>
    </div>
