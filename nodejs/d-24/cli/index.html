CLI 参数与命令行工具

解析命令行参数，使用 commander 等库构建专业的命令行工具。

开场问题：你写了个部署脚本，约定用 deploy --env prod --port 8080。同事敲成了 --port=8080（用等号连写），脚本既不报错、也不退出，静默地套用了默认端口 3000，把服务发到了错误的环境；CI 里流水线一路绿灯——因为从退出码看，它「成功」了。

原始参数字符串

命令行工具得先读懂用户敲进来的参数，才谈得上干活。最原始的做法是直接摆弄 process.argv，可它交到你手上的只是一串没有结构的字符串，于是三笔成本全落到了你身上：

  • --port 8080 到底是「一个带值的选项」还是「两个各自独立的参数」，没有任何标注，全靠你的代码去猜。
  • 用户可能写成 --port 8080、--port=8080、-p 8080 好几种形态，手写解析漏掉任何一种，参数就默默丢了。
  • 解析失败若程序不吭声地继续跑，脚本和 CI 根本无从判定失败，错误会被一路带到生产环境。

怎样让参数解析既稳，又能在出错时被机器明确地判定为「失败」？

手写循环解析

最直接的做法：从 process.argv.slice(2) 拿到用户参数，写一个循环——遇到 --key 就往后看一项，是值就配对，否则当作布尔开关。

它做对了一件必须记住的事：认清了「用户参数从 argv[2] 开始」。process.argv[0] 是 node 可执行文件路径，argv[1] 是脚本自身路径，这两个都是运行时塞进来的，不是用户输入，必须跳过。这个认知后面无论用哪套方案都不能丢。

等号短选项解析

  • 等号形式失守：--port=8080 被当成一个整体，键名成了 port=8080，值反而没了。
  • 短选项没处理：-p 8080 直接被忽略，因为循环只认 -- 开头。
  • 规则太粗：布尔开关和带值选项共用一条判断，一旦值本身以 - 开头（比如一个负数的偏移量），就会被误判成新选项。
  • 错误被吞掉：用户传了非法的 --port abc，程序照样用默认值跑完，退出码还是 0，CI 判不出失败。
  • 没有 --help：用户只能翻源码猜有哪些参数、各自什么含义。
  • 不可扩展：每加一个参数就要改一段手写解析，越写越脆，边界情况永远补不完。

内置解析工具

先补「不要手写解析」这件事。小工具用内置的 util.parseArgs，它会替你处理 --key=value 与 --key value 两种形态、区分布尔开关、并把未声明的未知参数报出来；功能更复杂的 CLI 再上 commander / yargs / cac，它们额外提供子命令、类型转换与自动生成的帮助信息。之所以先补它：手写解析的每一种形态都是一个坑，而标准库与成熟框架已经把这些形态收敛好了，这是投入产出比最高的一步。

再补帮助与版本。让工具支持 --help 自动输出用法、每个选项的含义，--version 输出版本号，用户不必读源码就能上手。

接着补最关键的一环——退出码。参数解析失败时，要打印用法提示（usage），并以非零退出码结束进程。退出码 0 表示成功、非零表示失败，这是 shell、CI，以及用 && 串联的多条命令判断「上一步到底成没成」的唯一依据。一个「静默用默认值继续跑」的 CLI 是最危险的，因为它把错误伪装成了成功，让问题在后面更贵的地方才暴露。

最后补子命令拆分。复杂 CLI 会像 git remote add 那样有层级结构，把每个子命令拆成独立模块，各自维护自己的选项与帮助文本，既不容易互相干扰，也方便单独测试。

收尾时用两类输入各验证一遍：跑 --help 看帮助是否完整清晰；再故意传一个非法参数，确认它输出了 usage 并且以非零退出码结束。

发给自动化脚本用的 CLI，成败信号只认退出码。人看的是屏幕上的输出，CI 看的是你 process.exit() 传出去的整数。忽略这一点，等于让你的工具在流水线里永远「成功」。

解析结果观察

类型化参数结构

命令行参数在运行时永远只是字符串，把它变成「带名字、带类型、能校验」的结构，才是 CLI 的第一层工程化。第一项先认清 argv[2] 这个起点，然后果断把解析交给 util.parseArgs 或成熟框架，最后用退出码把成败明确地告诉调用方——参数解析就不再是脆弱的字符串游戏。

「退出码」是进程结束时返回给父进程（shell、CI、调用脚本）的整数，约定 0 表示成功、非零表示失败，是自动化判断一步命令成败的唯一依据。边界：被信号强制终止时，shell 报出的码通常是 128 + 信号编号；调用方只看退出码，并不看你 console.log 了什么，所以「打印了错误却仍然返回 0」对 CI 而言就是成功；参数解析失败属于使用错误，标准做法是输出 usage 并以非零码退出。

import process from 'node:process'
import path from 'node:path'
import fs from 'node:fs/promises'

// ───────── 基础：process.argv ─────────

// 运行: node cli.js --name Alice --age 30 --verbose
console.log('process.argv:', process.argv)
// [
//   'C:\\Program Files\\nodejs\\node.exe',  // [0] node 路径
//   'D:\\project\\cli.js',                  // [1] 脚本路径
//   '--name',                               // [2] 参数1
//   'Alice',                                // [3] 参数2
//   '--age',
//   '30',
//   '--verbose'
// ]

// 去掉前两个元素
const args = process.argv.slice(2)

// ───────── 手动解析参数 ─────────

function parseArgs(argv) {
  const options = {
    _: [] // 位置参数
  }

  for (let i = 0; i < argv.length; i++) {
    const arg = argv[i]

    if (arg.startsWith('--')) {
      // 长选项: --name value 或 --name=value
      const eqIndex = arg.indexOf('=')
      if (eqIndex !== -1) {
        const key = arg.slice(2, eqIndex)
        const value = arg.slice(eqIndex + 1)
        options[camelCase(key)] = coerce(value)
      } else {
        const key = arg.slice(2)
        // 下一个参数不是选项，则作为值
        if (i + 1 < argv.length && !argv[i + 1].startsWith('-')) {
          options[camelCase(key)] = coerce(argv[i + 1])
          i++
        } else {
          options[camelCase(key)] = true // 布尔标志
        }
      }
    } else if (arg.startsWith('-') && arg.length > 1) {
      // 短选项: -n value 或 -abc (多个布尔标志)
      const key = arg.slice(1)
      if (key.length === 1 && i + 1 < argv.length && !argv[i + 1].startsWith('-')) {
        options[key] = coerce(argv[i + 1])
        i++
      } else {
        // 组合短选项: -abc → -a -b -c
        for (const char of key) {
          options[char] = true
        }
      }
    } else {
      // 位置参数
      options._.push(arg)
    }
  }

  return options
}

function camelCase(str) {
  return str.replace(/-([a-z])/g, (_, c) => c.toUpperCase())
}

function coerce(value) {
  // 自动类型转换
  if (value === 'true') return true
  if (value === 'false') return false
  const num = Number(value)
  if (!isNaN(num) && value !== '') return num
  return value
}

// 一个简单的文件处理 CLI 工具
// 用法:
//   node cli.js read <file>          读取文件
//   node cli.js write <file> <text>  写入文件
//   node cli.js list [dir]           列出目录
//   node cli.js --help               帮助

const HELP_TEXT = `
文件处理 CLI 工具

用法:
  node D24Cli.js <command> [options]

命令:
  read <file>           读取文件内容
  write <file> <text>   写入文件
  list [dir]            列出目录内容（默认当前目录）

选项:
  -h, --help            显示帮助
  -v, --verbose         显示详细信息
  -e, --encoding <enc>  文件编码 (默认: utf-8)

示例:
  node D24Cli.js read package.json
  node D24Cli.js write hello.txt "Hello World"
  node D24Cli.js list ./src -v
`

async function main() {
  const options = parseArgs(args)

  if (options.help || options.h) {
    console.log(HELP_TEXT)
    return
  }

  const command = options._[0]
  const encoding = options.encoding || options.e || 'utf-8'
  const verbose = options.verbose || options.v

  try {
    switch (command) {
      case 'read': {
        const file = options._[1]
        if (!file) {
          console.error('错误: 请指定要读取的文件')
          process.exit(1)
        }
        if (verbose) console.log(`读取文件: ${file} (编码: ${encoding})`)
        const content = await fs.readFile(file, encoding)
        console.log(content)
        break
      }

      case 'write': {
        const file = options._[1]
        const text = options._[2]
        if (!file || text === undefined) {
          console.error('错误: 请指定文件名和内容')
          process.exit(1)
        }
        if (verbose) console.log(`写入文件: ${file}`)
        await fs.writeFile(file, text, encoding)
        console.log(`已写入: ${file}`)
        break
      }

      case 'list': {
        const dir = options._[1] || '.'
        if (verbose) console.log(`列出目录: ${dir}`)
        const files = await fs.readdir(dir)
        for (const file of files) {
          if (verbose) {
            const stat = await fs.stat(path.join(dir, file))
            const type = stat.isDirectory() ? '目录' : '文件'
            const size = stat.size.toString().padStart(8)
            console.log(`${type}  ${size}B  ${file}`)
          } else {
            console.log(file)
          }
        }
        break
      }

      case undefined:
        console.error('错误: 请指定命令')
        console.log(HELP_TEXT)
        process.exit(1)

      default:
        console.error(`错误: 未知命令 "${command}"`)
        console.log(HELP_TEXT)
        process.exit(1)
    }
  } catch (err) {
    if (verbose) {
      console.error('详细错误:', err)
    } else {
      console.error('错误:', err.message)
    }
    process.exit(1)
  }
}
