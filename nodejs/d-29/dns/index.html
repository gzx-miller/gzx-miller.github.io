dns 域名解析

使用 dns 模块解析域名，查询各类 DNS 记录（A、AAAA、CNAME、MX、TXT、NS）。

开场问题：本地联调时，你在 hosts 文件里把 api.internal 指到 127.0.0.1，浏览器和 fetch 都通；可脚本里调 dns.resolve4('api.internal') 却直接报 ENOTFOUND。同一个域名，为什么一个解析得到、一个查不到？

域名解析双路径

你要在建立连接前把域名换成 IP，或者校验收件域名有没有配对的邮件服务器。这件事看起来只有一个答案，实际却处处是分叉。

如果假设「域名解析只有一个结果」，就有几笔成本要人扛：把 IP 写死在代码里，服务换 IP 就要改代码重新发版；靠系统命令去查，临时、不可编程，不同平台输出还不一样；忽略 hosts 与缓存，本地联调和线上行为对不上，排查半天才发现「你查的地方和程序连的地方根本不是一回事」。

问题落到一句话：一个域名到 IP 的解析究竟发生在哪一层，为什么从不同入口去问，得到的答案会不一样？

系统解析器与连接

用 node:dns 的 dns.lookup('example.com', callback)：它走系统解析器，也就是先读 hosts 文件、再查系统缓存与系统配置的 DNS 服务器，最后交回一个地址。

这个方案做对了一件关键的事：它的行为和浏览器、和其它系统程序保持一致。你接下来真正要发起的连接用哪个 IP，lookup 就报哪个 IP——包括 hosts 里那条本地覆盖。所以「发起连接之前」这个时刻，它才是对的那个入口。

单一地址与记录缺口

  • lookup 只给你一个地址，问不到 MX、TXT、NS 这些记录——想校验收件域名，它根本给不了这个能力。
  • 正因为 lookup 读 hosts，而 dns.resolve*() 不读 hosts、直接向 DNS 服务器查询，所以 hosts 里手动改过的域名在 resolve4 下会报 ENOTFOUND——这就是开场那个「一个通、一个不通」的由来。
  • dns.lookup() 默认跑在 libuv 线程池里：解析请求一多，线程池被占满，解析会排队变慢，还可能拖累同一池子里的文件 I/O。
  • 每次请求都解析、不做缓存，DNS 一抖动就会把等待放大到所有并发请求上，整站跟着变慢。
  • 只处理 A 记录会漏掉现实：AAAA（IPv6）不少环境在用，一个域名也常有多个 A 记录，只取一个并不代表全貌。

两类查询入口分工

先把两个入口的分工划清楚，这是理解这道题的关键。dns.lookup() 走系统解析器，包含 hosts 文件与系统缓存，行为与实际建立连接一致；dns.resolve*() 系列则绕开系统，直接向 DNS 服务器查询指定类型的记录。所以「为了避免连错」用前者，「为了查记录本身」用后者。

接着把记录类型补齐，resolve 系列正是为此而生：resolve4 查 IPv4 的 A 记录、resolve6 查 IPv6 的 AAAA、resolveMx 查邮件交换、resolveTxt 查文本记录、resolveNs 查权威名称服务器、resolveCname 查别名。校验收件域能不能收信，看的就是 MX；这些是 lookup 永远给不了的信息。

再补反向解析：dns.reverse(ip, callback) 把 IP 换回主机名。排查网络问题时，日志里出现一个陌生 IP，反查一下常常能立刻定位到来源。

最后是缓存与降级，因为解析是最容易被忽略的单点。给解析结果加一层应用层缓存，按记录的 TTL 决定缓存多久——TTL 是这条记录在缓存里能活多少秒，也是「改了 DNS 却迟迟不生效」的原因。缓存之外还要有降级预案：查询失败时用上一次成功的结果兜底，或者切到备用解析服务，别让一次 DNS 抖动直接变成全站不可用。

别把两件事混在一起：dns.lookup() 走系统解析器、会读 hosts，resolve*() 直接查 DNS 服务器、不读 hosts，两者结果不同是正常的，不是 bug；高频解析要加缓存并考虑线程池排队；DNS 要有失败降级方案，缓存上次成功结果或切换备用解析。

记录类型查询对照

解析路径与缓存

域名解析不是一个函数，而是一条有分叉的路径：lookup 走系统、和真实连接一致，resolve* 直连 DNS 服务器、能查各种记录类型。分清「我要的是连接结果，还是记录本身」，再给解析加上按 TTL 的缓存与失败降级，域名这一环才算稳。

「TTL」全称 Time to Live，指一条 DNS 记录允许被缓存器保留的秒数；它决定了改完解析记录后，旧地址还要在缓存里存活多久。边界与例外：不同的解析器和中间缓存可能不完全遵守 TTL；TTL 设为 0 表示不缓存，会带来更高的查询频率；查询失败的结果也会被「负缓存」一段时间，所以刚配好的域名可能暂时仍报 ENOTFOUND。

import dns from 'node:dns'
import { Resolver } from 'node:dns'

// ───────── 域名解析 ─────────

// 1. 查找 A 记录（IPv4 地址）
dns.lookup('example.com', (err, address, family) => {
  if (err) {
    console.error('解析失败:', err.message)
    return
  }
  console.log('IPv4 地址:', address)
  console.log('地址族:', family) // 4 或 6
})

// 2. 查找 IPv6
dns.lookup('example.com', { family: 6 }, (err, address) => {
  if (!err) console.log('IPv6 地址:', address)
})

// 3. 获取所有地址
dns.lookup('example.com', { all: true }, (err, addresses) => {
  if (!err) {
    console.log('所有地址:', addresses)
    // [{ address: '93.184.216.34', family: 4 }]
  }
})

// - 使用系统的 DNS 解析机制
// - 会读取 hosts 文件
// - 会走系统配置的 DNS 服务器

// 重要区别：
// dns.lookup 是系统级的，可能受系统配置影响
// dns.resolve 是纯网络的，更快但可能和系统不一致

// 实际开发中，http.get 等用的是 dns.lookup

// ───────── 解析各种记录类型 ─────────

// A 记录（IPv4）
dns.resolve4('example.com', (err, addresses) => {
  if (!err) console.log('A 记录:', addresses)
})

// AAAA 记录（IPv6）
dns.resolve6('example.com', (err, addresses) => {
  if (!err) console.log('AAAA 记录:', addresses)

// MX 记录（邮件服务器）
dns.resolveMx('gmail.com', (err, records) => {
  if (!err) {
    console.log('MX 记录:')
    records.forEach(r => {
      console.log(`  优先级 ${r.priority}: ${r.exchange}`)
    })
  }
})

// TXT 记录（文本记录，常用于验证）
dns.resolveTxt('example.com', (err, records) => {
  if (!err) console.log('TXT 记录:', records)
})

// NS 记录（域名服务器）
dns.resolveNs('example.com', (err, records) => {
  if (!err) console.log('NS 记录:', records)
})

// CNAME 记录（别名）
dns.resolveCname('www.example.com', (err, records) => {
  if (!err) console.log('CNAME 记录:', records)
})

// SOA 记录（起始授权记录）
dns.resolveSoa('example.com', (err, soa) => {
  if (!err) console.log('SOA 记录:', soa)

// SRV 记录（服务定位）

// Node.js 内置的 dns.lookup 会用系统的 DNS 缓存
// dns.resolve 系列默认没有缓存

// 简单的 DNS 缓存实现
class DnsCache {
  constructor(ttl = 300000) {
    this.cache = new Map()
    this.ttl = ttl // 默认 5 分钟
  }

  resolve(hostname, type = 'A') {
    return new Promise((resolve, reject) => {
      const key = `${hostname}:${type}`
      const cached = this.cache.get(key)

      // 缓存命中且未过期
      if (cached && Date.now() < cached.expireAt) {
        resolve(cached.value)
        return
      }

      // 实际查询
      dns.resolve(hostname, type, (err, records) => {
        if (err) {
          reject(err)
          return
        }

        // 存入缓存
        this.cache.set(key, {
          value: records,
          expireAt: Date.now() + this.ttl
        })

        resolve(records)
      })
    })
  }

  clear() {
    this.cache.clear()
  }
}
