crypto 加密、哈希与安全随机数

使用 crypto 模块进行哈希、HMAC、对称加密与安全随机数，掌握密码存储与数据签名的最佳实践。

开场问题：你自信地把密码存成 sha256 摘要，明文永不落库；可一份审计报告指出，明面上是三千个账号，库里却只对应不到一百种哈希值——同一套「只存摘要」的做法，为什么会变成这样？

通用哈希的两个「性格」

你最初的写法大概是：注册时算一遍 createHash('sha256') 把摘要存库，登录时把输入的密码再算一遍，和库里的值比对。方向没有错——哈希是单向的，明文永远不落库，哪怕整库被拖走，攻击者拿到的也只是一串定长摘要，而不是用户的原始密码。这条底线必须守住。

问题出在通用哈希函数与生俱来的两个「性格」上。它公开且确定：同样的输入永远得到同样的输出；它又为快而生：设计目标就是尽快算出结果。这两点合在一起，埋下三类只能由你来兜的成本：

  • 确定意味着可以预计算：常见密码的摘要是一张谁都能查的表，破一个就等于破一片。
  • 快意味着可以暴力枚举：主流 GPU 每秒能对 SHA-256 尝试数十亿次，短弱密码几小时就见底。
  • 没有随机意味着「相同密码得到相同摘要」：拖库后统计频次，就能把成批用同一密码的账号直接圈出来。

有没有一种存法，既保留「不可逆」，又让「破一个」不再等于「破一批」，同时把暴力枚举拖慢到不划算？

相同摘要惹出的风险

  • 两个用户都用了同一个弱密码，两行哈希一模一样，破一个等于破一双。
  • sha256('123456') 是全网皆知的定值，攻击者不必爆破，拿彩虹表查表即得明文。
  • 哈希太快：SHA-256 在消费级 GPU 上每秒可尝试数十亿次，八位小写字母的组合几小时就能穷举完。
  • 取巧会翻车：md5 与 sha1 已被证明存在碰撞，只能用于非安全的完整性校验，绝不能拿来存密码或签名。
  • 连比对方式都可能泄密：用 === 逐字节比较会在第一个不同字节处提前返回，耗时随匹配程度变化，留下时序攻击的缺口。

先加随机盐，再让它慢下来

先补随机盐。注册时用 randomBytes(16) 生成一段随机字节当盐，与密码一起送进哈希函数，最后把盐和摘要一并存储。之所以先补它：它正是「相同密码产生相同摘要」这个最致命问题的直接解药，改动还最小。盐不是秘密、不需要保密，它的作用只是让每个用户的计算结果都带上随机性——攻击者再想用一张彩虹表通吃，就得为每个盐各重算一张，成本瞬间爆炸。

补完盐还差一件事：盐只防「预计算」，不防「在线暴力破解」，SHA-256 那个「快」的毛病还在。于是再补慢——改用刻意拖慢的密钥派生函数，把迭代次数（成本因子）显式调高，让单次校验耗时被人为拉到毫秒级，每秒可尝试次数就从数十亿压到几百。

  1. 用 randomBytes(16) 为这个用户生成独立随机盐。
  2. 用 pbkdf2Sync(password, salt, 10000, 64, 'sha512') 或 scryptSync 反复迭代得到摘要。
  3. 把盐与摘要一起入库；校验时用同一个盐重算，再用 timingSafeEqual() 比对。

生产里更省心的做法是直接上 bcrypt 或 argon2：它们把盐与成本参数一起编码进结果字符串，你不用自己维护这两样。timingSafeEqual() 这一环也别漏——它做常数时间比较，不因内容不同而改变耗时，正是用来堵上前面那个时序缺口。

两个常见误区：一是以为「加了盐就安全」——盐只解决预计算，真正拉高暴力破解成本的是「慢」；二是随手在摘要上加一个固定字符串当盐——固定值等于全局共用一个盐，完全起不到随机化作用。盐必须每个用户独立、每次生成都随机。

摘要、HMAC、加密与签名各管一段

顺着「摘要用在哪」这条线，还有几处边界要分清。完整性校验用裸哈希就够：createHash('sha256') 算文件校验和，确认下载没被改动。消息认证则必须换成 createHmac('sha256', secret)——密钥参与运算，攻击者不知道密钥就伪造不出签名，这正是裸哈希与 HMAC 的分界：有没有密钥。

而需要把数据解回来的机密性场景，用的是对称加密 createCipheriv('aes-256-gcm', key, iv)。GCM 自带认证标签（authTag），解密时校验它就能发现密文被改过；IV 每次加密都必须重新随机生成、绝不能复用，否则相同明文会被加密成相同密文，直接暴露规律。随机性本身交给 randomBytes()，需要一个不碰撞的标识就用 randomUUID()——它们都基于密码学安全的随机源，不要用 Math.random() 替代。

若还需要「谁能加密、谁能解密」分离，就轮到签名与验签出场：用私钥签名 crypto.sign('sha256', data, privateKey)、用公钥验签 crypto.verify(...)，既证明「是谁发的」，也证明「内容没被改」。

密钥放在哪、以后怎么换

无论是 HMAC 的 secret、AES 的 key，还是签名的私钥，都一律通过环境变量或密钥管理服务提供，绝不硬编码进仓库——一旦提交，就等于把钥匙挂在了公开的门上，还得连带清理 Git 历史。方案设计时还要预留密钥轮换的路径：用带版本号的标识标记每条密文或签名，新数据用新密钥，旧密钥保留一段时间以便解开历史数据，轮换时才不会导致存量数据直接读不出。

各算法摘要位数

按用途挑算法

摘要算法的选型，本质是先分清「要不要能解回来、要不要证明真伪」：能解回来用加密，证明真伪用带密钥的 HMAC 或签名，而验证密码这个特殊场景要的既不是快也不是可逆，而是「不可逆 + 每个用户随机 + 慢到打败暴力枚举」。加盐慢哈希把这三点一次凑齐，密码存储才算真正立住；密钥则一律外置，并预留轮换路径。

「加盐慢哈希」先用每个用户独立的随机盐参与运算，再交给一个刻意拖慢的密钥派生函数（scrypt、PBKDF2、bcrypt、argon2）反复迭代，产出定长摘要的密码存储方式。边界：盐不是密钥、无需保密，但要和摘要一起存；盐只解决「相同密码产生相同摘要」，真正拉开暴力破解成本的是「慢」；md5 / sha1 这类快速哈希无论加不加盐都不能用于存密码或签名；比对必须用常数时间的 timingSafeEqual()。

关键代码

JavaScript
// ═══════════════════════════════════════════
// 1. 哈希：完整性校验与摘要长度
// ═══════════════════════════════════════════

import {
  createHash, createHmac, createCipheriv, createDecipheriv,
  randomBytes, randomUUID, scryptSync, timingSafeEqual,
  generateKeyPairSync, sign, createVerify
} from 'node:crypto'

const fileCheck = createHash('sha256').update('订单 1024 的内容').digest('hex')  // 结果：64 位十六进制摘要
const sha256Len = createHash('sha256').update('订单 1024').digest('hex').length  // 结果：64，对应 256 位
const md5Len = createHash('md5').update('订单 1024').digest('hex').length        // 结果：32，仅遗留兼容
const sha1Len = createHash('sha1').update('订单 1024').digest('hex').length      // 结果：40，已证明碰撞

// ═══════════════════════════════════════════
// 2. HMAC：带密钥的消息认证
// ═══════════════════════════════════════════

const secret = process.env.APP_SECRET                     // 说明：密钥来自环境变量，不硬编码
function signPayload(payload) {
  return createHmac('sha256', secret).update(payload).digest('hex')   // 结果：64 位签名
}
function verifyPayload(payload, signature) {
  const expected = createHmac('sha256', secret).update(payload).digest('hex')
  return timingSafeEqual(Buffer.from(signature), Buffer.from(expected))  // 结果：true，常数时间比较
}

// ═══════════════════════════════════════════
// 3. 加盐慢哈希：密码存储
// ═══════════════════════════════════════════

function hashPassword(password) {
  const salt = randomBytes(16).toString('hex')            // 说明：每个用户独立随机盐
  const hash = scryptSync(password, salt, 64).toString('hex')   // 说明：刻意拖慢，压低每秒尝试次数
  return `${salt}:${hash}`                                 // 结果：盐与摘要一并存储
}
function verifyPassword(password, stored) {
  const [salt, hash] = stored.split(':')                   // 说明：取出当初的盐
  const candidate = scryptSync(password, salt, 64)         // 说明：用同一个盐重算
  return timingSafeEqual(candidate, Buffer.from(hash, 'hex'))   // 结果：true / false
}

// ═══════════════════════════════════════════
// 4. AES-256-GCM：每次随机 IV 与 authTag
// ═══════════════════════════════════════════

function encrypt(plain, key) {
  const iv = randomBytes(12)                               // 说明：IV 每次加密都随机生成，绝不复用
  const cipher = createCipheriv('aes-256-gcm', key, iv)
  const data = Buffer.concat([cipher.update(plain, 'utf8'), cipher.final()])
  return { iv, authTag: cipher.getAuthTag(), data }        // 结果：密文、IV、认证标签都要保存
}
function decrypt({ iv, authTag, data }, key) {
  const decipher = createDecipheriv('aes-256-gcm', key, iv)
  decipher.setAuthTag(authTag)                             // 说明：密文被改则 final() 抛错
  return Buffer.concat([decipher.update(data), decipher.final()]).toString('utf8')
}

// ═══════════════════════════════════════════
// 5. 安全随机数与签名验签
// ═══════════════════════════════════════════

const resetToken = randomBytes(32).toString('hex')         // 结果：64 位随机令牌，不可预测
const requestId = randomUUID()                             // 结果：v4 UUID
const { privateKey, publicKey } = generateKeyPairSync('ec', { namedCurve: 'P-256' })
const signature = sign(null, Buffer.from('转账 100 元'), privateKey)   // 说明：私钥签名
const ok = createVerify(null).update('转账 100 元').verify(publicKey, signature)  // 结果：true

// ═══════════════════════════════════════════
// 6. 用途选择与禁区
// ═══════════════════════════════════════════

const forbiddenForSecurity = ['md5', 'sha1']               // 说明：碰撞已证明，禁用于密码与签名
const integrityAlgos = ['sha256', 'sha512', 'sha3-256']    // 结果：完整性校验可选的安全算法
const passwordSchemes = ['scrypt', 'pbkdf2', 'bcrypt', 'argon2']  // 结果：加盐慢哈希阵营
const keyRotationPlanned = true                            // 说明：预留轮换路径，旧密钥仍能解历史数据
