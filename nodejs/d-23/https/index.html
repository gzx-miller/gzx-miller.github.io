HTTPS 与 TLS 配置

理解 HTTPS 的原理，掌握 Node.js HTTPS 服务器的创建和 TLS 配置。

开场问题：你用 OpenSSL 生成了一对自签名证书，https.createServer 也跑起来了，浏览器地址栏却挂着「不安全」的红色警告；同事那边少发了一层中间证书，Chrome 干脆拒绝连接，而加 -k 跳过校验的 curl 却能通。同样是「用了 HTTPS」，为什么一个警告、一个能连、一个被拒？

明文传输窃听风险

HTTP 是明文传输，链路上的任何一跳都能偷看和改写你的请求。你想「加密」，于是把服务从 http 换成 https。但「加密」其实只解决了一半问题，旧办法留下的三笔成本，必须由你自己补上：

  • 明文可被窃听、篡改：公共 WiFi 能给你注入广告，运营商能看到你请求里的全部内容。
  • 没有身份验证：你以为连的是银行，中间人却分别跟你和银行各建一条 TLS，把你的加密流量在自己这里解密、再转发，你全程毫无察觉。
  • 只加密不认证：攻击者可以在链路中间篡改请求内容与响应，你既不知道对方是谁，也判断不了拿到的数据真假。

怎么让对方除了「加密」，还能证明「它确实是自称的那台服务器」？

私钥与证书加载

最直接的做法：把私钥和证书读进来，交给 https.createServer({ key, cert }, handler)，监听 443 端口。

它做对了一件很重要的事：建立了一条加密通道。TLS 握手会协商出会话密钥，此后应用数据在网络上看都是密文，窃听者拿不到明文——这一步是 HTTPS 的基础，不可省略。

自签证书信任缺失

  • 加密不等于可信身份：自签名证书不在操作系统的受信任根证书库里，浏览器没法验证「证书上的域名是否真的归你」，于是报不安全。
  • 少发中间证书：服务器只发了自己的证书、没带中间 CA，客户端就无法把「你的证书」一路接到任何受信任根上，链是断的。
  • 协议版本过旧：SSLv3 与 TLS 1.0/1.1 存在已被公开的漏洞，继续开放等于给攻击者留后门。
  • 私钥管理松懈：权限过松或被提交进仓库，谁拿到私钥谁就能冒充你的站点。
  • 证书到期无人监控：到期那一刻，所有客户端直接拒绝连接，等于全站宕机。

证书链信任验证

先补证书链。证书不是孤立的一张纸，而是「服务器证书 → 中间 CA → 受信任根 CA」一条链，每一环都由上一环的私钥签名。客户端顺着这条链一路验到系统内置的受信任根，才能确认域名与身份。之所以先补它：没有身份验证的加密，等于「跟一个自称是银行的人加密聊天」——中间人照样能解密转发，这正是 HTTPS 要防的头号威胁。所以生产必须用 CA 签发的证书，本地开发用 mkcert 或 OpenSSL 自签名就够了，它提供加密，但不提供「被信任的身份」。

再补协议版本与密码套件。在服务器选项里显式设置最低版本，并优先使用 TLS 1.3：

  1. 准备证书：本地用自签名，生产用 CA 签发或 Let's Encrypt 自动续期。
  2. https.createServer 传入 key 与 cert；也可以在反向代理或负载均衡层终止 TLS。
  3. 显式设置 minVersion: 'TLSv1.2' 与强密码套件，禁用 SSLv3 与 TLS 1.0/1.1。
  4. 用在线 TLS 检测报告核对协议版本与套件配置是否符合预期。

接着补全站强制加密：开启 HSTS，让浏览器此后只允许用 HTTPS 访问你的域名，堵住「第一次访问还是明文、被劫持降级」的口子。

最后补密钥与证书的生命周期管理。私钥要收紧文件权限、妥善备份、绝不进代码仓库；证书要设置到期监控，留出足够的续期窗口——Let's Encrypt 的证书有效期只有 90 天，靠自动续期才跑得稳，手动续期一定要提前量；方案还要预留更换私钥的路径，避免出问题时手忙脚乱。

架构上的选择：TLS 不一定非得在应用里终止，也可以交给反向代理或负载均衡层，应用只处理普通 HTTP。好处是证书集中管理、续期只改一处；代价是从网关到应用那段内网流量是否是明文，需要按你的安全边界单独评估。

四页签配置对照

加密与身份证明

HTTPS 由两部分构成：TLS 负责把流量加密，证书链负责证明「对方是它自称的那台服务器」。只做前者，你得到的是一条「跟身份不明者加密对话」的通道；只有把证书验到受信任的根、再把废弃协议关掉、把证书当密钥一样管理起来，HTTPS 才真正成立。

「证书链」是从服务器证书经由中间 CA 一路签名到受信任根 CA 的验证路径，客户端逐环校验签名与域名，最终把身份锚定在系统/浏览器内置的根证书上。边界：根证书由操作系统与浏览器预置，不随站点下发；自签名证书依然提供加密，但不在信任库里，浏览器会报「不安全」；服务器漏发中间证书会让链断掉，部分客户端直接拒绝握手；CA 签发的正式证书还需在到期前续期，否则验证链会因过期而失效。

// GET 请求
function httpsGet(url) {
  return new Promise((resolve, reject) => {
    https.get(url, (res) => {
      let data = ''

      res.on('data', (chunk) => {
        data += chunk
      })

      res.on('end', () => {
        resolve({
          statusCode: res.statusCode,
          headers: res.headers,
          body: data
        })
      })
    }).on('error', reject)
  })
}

// 完整请求（带选项）
function httpsRequest(options, body = null) {
  return new Promise((resolve, reject) => {
    const req = https.request(options, (res) => {
      let data = ''

      res.on('data', (chunk) => {
        data += chunk
      })

      res.on('end', () => {
        resolve({
          statusCode: res.statusCode,
          headers: res.headers,
          body: data
        })
      })
    })

    req.on('error', reject)
    req.setTimeout(10000, () => req.destroy(new Error('请求超时')))

    if (body) {
      req.write(body)
    }
    req.end()
  })
}

function addSecurityHeaders(res) {
  // 强制 HTTPS（HSTS）
  res.setHeader(
    'Strict-Transport-Security',
    'max-age=31536000; includeSubDomains; preload'
  )

  // 内容安全策略
  res.setHeader(
    'Content-Security-Policy',
    "default-src 'self'; script-src 'self'"
  )

  // 防止 MIME 类型嗅探
  res.setHeader('X-Content-Type-Options', 'nosniff')

  // 防止点击劫持
  res.setHeader('X-Frame-Options', 'DENY')

  // XSS 保护（现代浏览器主要靠 CSP）
  res.setHeader('X-XSS-Protection', '1; mode=block')

  // 引荐来源信息控制
  res.setHeader('Referrer-Policy', 'strict-origin-when-cross-origin')
}
