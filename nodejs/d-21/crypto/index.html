crypto 加密实践

使用 crypto 模块进行哈希、HMAC、对称加密等操作，掌握密码存储和数据签名的最佳实践。

开场问题：数据库被拖走了一份拷贝，你原本很镇定——密码存的是哈希，反推不出明文。可审计报告一句话把你钉住：库里三千个账号，只对应不到一百个不同的哈希值。也就是说大量用户用了同一个密码，攻击者只要撞破其中一个，剩下的人一起完蛋。

通用哈希局限

你最初的做法大概是这样：注册时算一遍 createHash('sha256') 把摘要存进库，登录时把输入的密码再算一遍，和库里的值比对。「只存摘要、不存明文」是密码存储的底线，方向没有错。

问题在于，通用哈希函数有两个特性恰好成了攻击者的帮凶。它是公开且确定的——同样的输入永远得到同样的输出；它又是为快而生的——设计目标就是尽快算出结果。这两点合起来，埋下了三类只能由你来兜的隐藏成本：

  • 确定性意味着可以预计算：常见密码的哈希值是一张谁都能查的表，攻破一个就等于攻破一片。
  • 快意味着可以暴力枚举：主流 GPU 每秒能对 SHA-256 做数十亿次尝试，短弱密码几个小时就见底。
  • 没有随机意味着「相同密码 → 相同摘要」：拖库后统计频次，就能直接把「批量用同一密码」的账号圈出来。

有没有一种存储方式，既保留「不可逆」，又让「撞破一个」不再等于「撞破一批」，同时让暴力枚举慢到不划算？

直存摘要隐患

最省事也最常见的做法：直接存 sha256(password)，登录时用同样的算法再算一次比对。

这个方案确实做对了一件关键的事：哈希是单向的，明文永远不落库。哪怕整库泄露，攻击者拿到的也只是一串定长摘要，而不是用户的原始密码。这条底线必须保留——后面所有的补救都建立在它之上。

相同摘要风险

  • 相同密码得到相同摘要：库里两个用户都用了 123456，两行哈希一模一样，破一个等于破一双。
  • 彩虹表可反查：sha256('123456') 是全网皆知的定值，攻击者不必爆破，查表即得明文。
  • 哈希太快：SHA-256 在消费级 GPU 上每秒可尝试数十亿次，八位小写字母的组合几小时就能穷举完。
  • 取巧会翻车：md5 与 sha1 已被证明存在碰撞，只适合做非安全的完整性校验，绝不能用于密码或签名。
  • 比对方式本身也可能泄密：用 === 逐字节比较会在第一个不同字节处提前返回，比较耗时会随匹配程度变化，留下时序攻击的缺口。

引入随机盐机制

先补随机盐。注册时用 randomBytes(16) 生成一段随机字节当盐，把它和密码一起送进哈希函数，最后把盐和摘要一并存储。之所以先补它：它是「相同密码产生相同摘要」这个最致命问题的直接解药，改动最小。盐不是秘密，不需要保密，它的作用只是让每个用户的计算结果都带上随机性——攻击者再想用一张彩虹表通吃，就得为每个盐各重算一张，成本瞬间爆炸。

补完盐，还差一件事没解决：盐只防「预计算」，不防「在线暴力破解」，SHA-256 那个「快」的毛病还在。于是再补慢——改用刻意拖慢的密钥派生函数，把迭代次数（成本因子）作为参数显式调高，让单次校验耗时被人为拉到毫秒级，从而把每秒可尝试次数从数十亿压到几百：

  1. 用 randomBytes(16) 为这个用户生成独立随机盐。
  2. 用 pbkdf2Sync(password, salt, 10000, 64, 'sha512')，或 scryptSync，反复迭代得到摘要。
  3. 把盐与摘要一起入库；校验时用同一个盐重算，再用 timingSafeEqual() 比对。

生产里更省心的做法是直接上 bcrypt 或 argon2，它们把盐和成本参数一起编码进结果字符串，你不用自己维护这两样。注意 timingSafeEqual() 这一环：它做常数时间比较，不因内容不同而改变耗时，正是用来堵上前面那个时序缺口。

顺着同一条「摘要用在哪」的线，还有几处边界要分清。完整性校验用裸哈希就够：createHash('sha256') 算文件校验和，用来确认下载没被改动。消息认证则必须换 createHmac('sha256', secret)——密钥参与运算，攻击者不知道密钥就伪造不出签名，这正是裸哈希与 HMAC 的分界：有没有密钥。而需要把数据解回来的机密性场景，用的是对称加密 createCipheriv('aes-256-gcm', key, iv)；GCM 自带认证标签（authTag），解密时校验它就能发现密文被改，IV 每次加密都必须重新随机生成、绝不能复用。至于密钥，一律通过环境变量或密钥管理服务提供，绝不硬编码进仓库；方案还要预留轮换路径，让旧密钥仍能解开历史数据。若需要「谁能加密、谁能解密」分离，才轮到 RSA 这类公私钥体系出场。

两个常见误区：一是以为「加了盐就安全」——盐只解决预计算，真正拉高暴力破解成本的是「慢」；二是以为可以自己在摘要上随便加个固定字符串当盐——固定值等于全局共用一个盐，起不到随机化的作用。盐必须每个用户独立、每次生成都随机。

各算法摘要位数

按用途选择算法

摘要算法的用途，本质上是先分清「要不要能解回来、要不要证明真伪」：能解回来用加密，证明真伪用带密钥的 HMAC，而验证密码这个特殊场景要的既不是快也不是可逆，而是「不可逆 + 每个用户随机 + 慢到打败暴力枚举」。加盐慢哈希把这三点一次凑齐，密码存储才算真正立住。

「加盐慢哈希」指先用每个用户独立的随机盐参与运算，再交给一个刻意拖慢的密钥派生函数（scrypt、PBKDF2、bcrypt、argon2）反复迭代，产出定长摘要的密码存储方式。边界：盐不是密钥、无需保密，但要和摘要一起存；盐只解决「相同密码产生相同摘要」，真正拉开暴力破解成本的是「慢」；md5/sha1 等快速哈希无论加不加盐都不能用于存密码；比对必须用常数时间的 timingSafeEqual()。

// ═══════════════════════════════════════════

import crypto from 'node:crypto'

// ───────── 哈希 (Hash) ─────────
// 单向、不可逆，用于验证数据完整性

// 1. MD5（不安全，仅用于兼容旧系统）
const md5Hash = crypto.createHash('md5')
  .update('Hello, World!')
  .digest('hex')
console.log('MD5:', md5Hash)

// 2. SHA-256（推荐）
const sha256Hash = crypto.createHash('sha256')
  .update('Hello, World!')
  .digest('hex')
console.log('SHA-256:', sha256Hash)

// 3. SHA-512
const sha512Hash = crypto.createHash('sha512')
  .update('Hello, World!')
  .digest('base64')
console.log('SHA-512 (base64):', sha512Hash)

// ───────── HMAC (带密钥的哈希) ─────────
// 用于验证消息的完整性和真实性

const secret = 'my-secret-key'
const message = '重要消息'

const hmac = crypto.createHmac('sha256', secret)
  .update(message)
  .digest('hex')

console.log('HMAC:', hmac)

// 验证 HMAC
function verifyHmac(message, signature, secret) {
  const expected = crypto.createHmac('sha256', secret)
    .update(message)
    .digest('hex')
  // 用 timingSafeEqual 防止时序攻击
  return crypto.timingSafeEqual(
    Buffer.from(signature, 'hex'),
    Buffer.from(expected, 'hex')
  )
}

// ───────── 对称加密 ─────────
// 同一个密钥用于加密和解密

// AES-256-GCM（推荐，带认证）
function encrypt(text, secretKey) {
  // 密钥必须是 32 字节（256位）
  const key = crypto.scryptSync(secretKey, 'salt', 32)

  // 初始化向量 IV，每次加密都要不同
  const iv = crypto.randomBytes(16)

  const cipher = crypto.createCipheriv('aes-256-gcm', key, iv)

  let encrypted = cipher.update(text, 'utf-8', 'hex')
  encrypted += cipher.final('hex')

  // 获取认证标签（用于验证数据完整性）
  const authTag = cipher.getAuthTag().toString('hex')

  // 返回 iv + authTag + 密文（都需要保存/传输）
  return {
    iv: iv.toString('hex'),
    authTag,
    encryptedData: encrypted
  }
}

function decrypt(encryptedData, iv, authTag, secretKey) {
  const key = crypto.scryptSync(secretKey, 'salt', 32)

  const decipher = crypto.createDecipheriv(
    'aes-256-gcm',
    key,
    Buffer.from(iv, 'hex')
  )

  decipher.setAuthTag(Buffer.from(authTag, 'hex'))

  let decrypted = decipher.update(encryptedData, 'hex', 'utf-8')
  decrypted += decipher.final('utf-8')

  return decrypted
}

// 使用示例
const secretKey = 'my-super-secret-password'
const originalText = '这是需要加密的敏感信息'

const encrypted = encrypt(originalText, secretKey)
console.log('加密结果:', encrypted)

const decrypted = decrypt(
  encrypted.encryptedData,
  encrypted.iv,
  encrypted.authTag,
  secretKey
)
console.log('解密结果:', decrypted)

// 公钥加密，私钥解密
function encryptWithPublicKey(publicKey, text) {
  return crypto.publicEncrypt(
    publicKey,
    Buffer.from(text, 'utf-8')
  ).toString('base64')
}

function decryptWithPrivateKey(privateKey, encryptedData) {
  return crypto.privateDecrypt(
    privateKey,
    Buffer.from(encryptedData, 'base64')
  ).toString('utf-8')
}

// 私钥签名，公钥验签
function signData(privateKey, data) {
  const sign = crypto.createSign('SHA256')
  sign.update(data)
  sign.end()
  return sign.sign(privateKey, 'hex')
}

function verifySignature(publicKey, data, signature) {
  const verify = crypto.createVerify('SHA256')
  verify.update(data)
  verify.end()
  return verify.verify(publicKey, signature, 'hex')
}

// ───────── 随机数生成 ─────────

// 加密安全的随机数

console.log('随机字节 (hex):', randomBytes.toString('hex'))

// 生成随机整数
function randomInt(min, max) {
  return crypto.randomInt(min, max + 1)
}

// 生成 UUID
const uuid = crypto.randomUUID()
console.log('UUID:', uuid)

// ───────── 密码哈希 ─────────
// 注意：生产环境用 bcrypt/argon2，不要自己实现！

// 简单的 PBKDF2 示例（内置）
function hashPassword(password, salt) {
  salt = salt || crypto.randomBytes(16).toString('hex')
  const hash = crypto.pbkdf2Sync(
    password,
    salt,
    100000,  // 迭代次数
    64,      // 密钥长度
    'sha512'
  ).toString('hex')
  return { salt, hash }
}

function verifyPassword(password, salt, hash) {
  const inputHash = crypto.pbkdf2Sync(
    password,
    salt,
    100000,
    64,
    'sha512'
  ).toString('hex')
  return crypto.timingSafeEqual(
    Buffer.from(hash, 'hex'),
    Buffer.from(inputHash, 'hex')
  )
}

// - bcrypt (简单，经过验证)

// ───────── 常见加密算法对比 ─────────

// 哈希算法：
// MD5       - 不安全，已破解，仅兼容
// SHA-1     - 不安全，已破解
// SHA-256   - 安全，推荐
// SHA-512   - 安全，更慢
// SHA-3     - 最新标准

// 对称加密：
// AES-128-CBC - 安全，但需要自己处理认证
// AES-256-GCM - 推荐，带认证标签
// ChaCha20    - 移动设备友好

// 非对称加密：
// RSA-2048    - 常用，密钥至少 2048 位
// RSA-4096    - 更安全，更慢
// ECDSA       - 椭圆曲线，密钥更小更快

// 密码哈希：
// PBKDF2      - 内置，可用
// bcrypt      - 推荐，简单易用
// argon2      - 最强，最新标准

// ───────── 安全最佳实践 ─────────
// 永远不要自己实现加密算法
// 不要用 MD5 和 SHA-1 做安全用途
// 对称加密用 AES-GCM（带认证）
// 密码存储用 bcrypt/argon2，不要用普通哈希
// 密钥不要硬编码在代码中，用环境变量或密钥管理服务
// IV（初始化向量）每次都要随机生成
// 比较敏感数据用 timingSafeEqual 防止时序攻击
// 用 crypto.randomBytes 生成安全随机数，不要用 Math.random
// 定期轮换密钥
