Worker 线程与 CPU 密集任务

用 Worker 线程卸载 CPU 密集计算，保持事件循环响应。

开场问题：你给接口加了一个「导出全量报表」功能，跑一次要八秒。上线后第一个用户点了导出，整个服务的健康检查开始超时，负载均衡把实例标记成不健康——一个只用一次的功能，把所有人都拖住了。

主线程计算独占

报表导出本身不是慢查询，它是纯计算：几百万条记录在内存里做聚合、排序、格式化。可你忘了 Node.js 的一个前提——一个 Node 进程只有一个主线程，也只有一个事件循环。事件循环既要跑你的同步代码，也要处理网络 I/O、定时器、各种回调。

于是当那段八秒的计算开始跑，事件循环被它一个人占满，其它事情全部排队：健康检查请求进不来，别的接口连轮到的机会都没有。你以前试图绕过这件事，无非三条路：

  • 把大计算切成小片，用 setTimeout 一片一片做——你得手写状态机保存进度，逻辑碎成一地。
  • 把计算挪到另一个外部服务或命令行工具里——多了一套要部署、要监控、还要走网络的组件。
  • 干脆接受阻塞——平时没事，一到大任务，P99 延迟直接炸穿。

三条路都不想走，问题就剩一句：能不能让一段计算离开主线程，但结果还能拿回来？

工作线程使用

能。worker_threads 让你把一段代码放进独立线程里跑。把计算逻辑单独写进一个 worker 文件，主线程用 new Worker('./worker.js') 把它拉起来，两边用消息说话。

这个方案做对了一件最关键的事：计算真的搬到了另一个线程。主线程的事件循环不再被那段循环占着，健康检查、其它接口该响应就响应。worker 里算完，把结果 postMessage 回主线程；主线程监听 message 事件收到结果，再决定怎么回给用户。

为什么是线程不是进程：同一个进程内的线程共享进程地址空间，创建与切换都比进程轻；代价是它们仍然不能共享普通变量，见下一段。

创建线程开销

  • 每次都 new Worker() 太贵：起一个线程要重新初始化一整套 JS 运行环境。如果任务是「高频、单次不大」，光创建开销就可能超过计算本身。
  • 想在 worker 里改主线程的一个计数器，做不到。worker 有自己独立的内存，你在里面 count++，主线程那个 count 纹丝不动。
  • 传一个几 MB 的大数组过去，postMessage 会做一次结构化克隆——按值深拷贝。数据越大拷贝越慢，反而可能把主线程也拖住。
  • worker 里抛出的异常不会自动回到主线程的 try/catch，必须监听 worker 的 error 事件，否则任务静默失败。
  • 消息里只要带了函数、类实例的方法或 DOM 节点，直接抛 DataCloneError，克隆算法只认「可复制的数据」。

线程池与数据传递

先补复用。既然创建线程贵，那就别每次新建——维护一个固定数量的 worker 池，任务来了排队、派给空闲的线程，用完不销毁。Piscina 这类库就是替你把这层池化做掉。之所以先补它，是因为真实业务里的 CPU 计算往往「高频、单次不大」，创建开销才是最吃时间的那一块。

再补大数据的传递方式。结构化克隆本质是「复制」，复制大对象就一定带着代价，于是有两种更省的通道：

  • Transferable：把一个 ArrayBuffer 的所有权「转移」给 worker，转移之后主线程手里那份就失效了——不拷贝，零成本，适合「这份数据之后只有 worker 用」的场景。
  • SharedArrayBuffer：真正被多个线程共享的内存，谁都别传，直接读写同一块。代价是你得自己用 Atomics 处理并发读写。

接着补生命周期与错误。worker 的 error 事件捕获线程内未处理的异常，exit 事件告诉你线程结束；terminate() 是最后的兜底，处理超时就强行收掉，别让一个卡死的计算永久占着一条线程。

最后记住一条判断边界：Worker 适合 CPU 密集，不适合 I/O 密集。I/O 等待本来就靠事件循环天然并发，你把它塞进 worker，无非是把「等网络」换成「占着一条线程在等」，白白浪费线程。

诊断顺序别搞反：动手之前先用性能分析确认瓶颈真的是 CPU 密集。如果慢在等数据库、等下游接口，那是 I/O 问题，加 worker 不但没用，还会因为线程变多让内存和调度更糟。

重计算任务搬迁

Worker 线程解决的是「单线程事件循环被一段同步计算独占」的问题：把计算搬进独立线程，用消息把结果拿回来，主线程始终留得住响应能力。代价是线程之间不共享普通内存，数据要么复制、要么转移所有权、要么共享 SharedArrayBuffer——这条边界决定了它只值得用在 CPU 密集场景。

「结构化克隆」是 postMessage 在两个线程之间传递数据时使用的复制算法：支持对象、数组、Map/Set、ArrayBuffer 与 TypedArray 等，但无法克隆函数、类原型方法、DOM 节点和 Symbol，遇到就抛 DataCloneError。正因为它是复制而非共享，worker 之间才不能直接读写对方的普通变量；要免拷贝就用 Transferable 转移 ArrayBuffer 所有权，要双向共享就用 SharedArrayBuffer 并配合 Atomics。
