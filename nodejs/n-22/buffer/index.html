Buffer 与二进制数据处理

理解 Buffer 的创建、编码转换、拼接和截取，掌握二进制数据处理的基本操作。

开场问题：你下载一个中文文件，按字符串的 length 切了一刀做分片上传，拼回来的文件里，某个汉字变成了两个乱码方块——长度明明算对了，字节却在中间被切断了，为什么？

字符与字节不是一回事

原因是 JavaScript 的字符串是 UTF-16 码元序列，它数的是「字符」，而文件、网络、加密这些底层操作面对的却是「字节」。中文、emoji 在 UTF-8 里要占好几个字节：一个汉字占 3 字节，一个 emoji 往往占 4 字节。于是「第 100 个字符」和「第 100 个字节」根本不在同一个位置，按字符切，正好把一个多字节字符劈成两半。

你想用字符串硬扛过去，会遇到三笔必须自己承担的隐藏成本：

  • 把一段非 UTF-8 的原始字节转成字符串时，非法字节会被替换成 �，信息当场丢失，再也拼不回去。
  • 网络分片陆续到达，用字符串拼接再切割，多字节字符一旦跨了分片边界就被切坏。
  • 读协议头、算加密分块、定位文件偏移时，「长度」必须按字节算，字符串的 length 给不了你想要的数。

怎么在 Node 里表示「一段原始字节」？

用 Buffer 表示字节序列

用 Buffer.from(字符串) 得到一段字节，用 buf.toString() 转回文本。Node 里文件读取、网络收发、加密的底层数据本来就都是 Buffer。

它做对的一件事：Buffer 是固定长度的字节序列，索引的单位就是字节。它是 Uint8Array 的子类，所以 buf[0] 拿到的是第 0 个字节的值、buf.length 是字节数（而不是字符数），Buffer.byteLength(文本) 则直接告诉你一段文本按字节算是多长——这正是上面那些场景真正需要的语义。

创建方式与「不清零」的隐患

  • 用 new Buffer(n) 创建已被废弃，既不安全又语义含糊；新代码一律走 Buffer.from / Buffer.alloc。
  • 编码必须配对：写入用 Buffer.from(str, 'utf8')、读出却用 toString('hex')，得到的就是乱码；用 'ascii' 或 'latin1' 处理中文，超出一个字节范围的字会被压成 ?。
  • Buffer.allocUnsafe(size) 来自 V8 堆之外的内存池，不清零，里面可能残留上一个请求的数据——涉密内容必须用 Buffer.alloc 或手动 fill(0)。
  • buf.slice() / buf.subarray() 返回的是共享内存的视图而不是拷贝，你改切出来的那一小段，原 Buffer 里对应的字节也跟着变。
  • 在循环里反复 Buffer.concat() 拼接，每轮都要重新分配并整段拷贝一次，分片一多就是 O(n²)。

定死创建、编码与拼接三件事

先把创建方式定死：从现有的东西构造用 Buffer.from()；要一块确定安全、已清零的内存用 Buffer.alloc(size)；只有确认会立刻写满、且不涉密时，才用 Buffer.allocUnsafe(size) 换速度。之所以先卡这一步，是因为「残留内存」是安全事件，不是性能问题。

再补编码转换。Buffer.from(str, charset) 负责「文本 → 字节」，buf.toString(charset) 负责「字节 → 文本」，两端用同一个 charset：UTF-8 是默认的文本编码；hex 与 base64 是给传输与持久化用的表示层编码，其中 base64 会把体积撑大约 4/3。记住一句：字节本身没有编码，编码只是你解释它的方式，解释错了就出乱码。

再补分片拼接。从流里拿到的是一段段 chunk，正确做法是先把它们收进数组，结束时先算总长度、Buffer.allocUnsafe(total) 预分配一块，再逐段 copy 写进去——只分配一次、只拷贝一趟，避开循环里的 O(n²)。另外要留个心：把大量文本编码成字节、或把一整个大文件读进内存，体积都会短暂膨胀，这种大体积转换应改用流式处理，分段编解码。

最后补多字节边界。即便按字节切分，也可能正好切断一个 UTF-8 字符，所以处理文本流时要么用 StringDecoder（它会把跨 chunk 的半个字符缓存到下一次再吐），要么自己保证只在字符边界上切。想真正拷贝一份而不是拿到共享视图，就用 Buffer.from(buf.subarray(...))。

别把「视图」当「副本」：slice 和 subarray 都是零拷贝的视图，改动会互相影响。需要独立数据时务必显式复制，否则一处看似无关的写操作会诡异地改到别处的数据。

各编码下的字节对照

二进制世界的统一单位

Buffer 是 Node 面对二进制世界的统一单位：一段按字节索引、长度固定的字节序列，是文件、网络与加密数据的最小载体。用它只要守住三件事——创建走 from / alloc、读写编码配对、拼接先预分配；再记住 slice / subarray 是共享视图而非拷贝、大体积编解码要走流式，二进制处理就基本不会踩坑。

「Buffer 池」是 Node 在 V8 堆之外维护的一块内部预分配内存（默认 Buffer.poolSize 为 8 KiB）：小于该阈值的 Buffer.allocUnsafe（以及很多 Buffer.from 的结果）会从这块池里切片分配，因此更快，但也因此不清零、可能残留旧数据，且多个小 Buffer 可能共享同一池内存。边界与例外：涉密数据必须用 Buffer.alloc 或手动 fill(0) 清零；需要独立副本时，不要依赖池内切片的 slice / subarray 结果。

关键代码

JavaScript
// ═══════════════════════════════════════════
// 1. Buffer 是固定长度的字节序列
// ═══════════════════════════════════════════

import { Buffer } from 'node:buffer'

const name = Buffer.from('栗子')                        // 说明：UTF-8 编码交给 Buffer
console.log(name.length)                               // 结果：6，一个汉字占 3 字节
console.log(Buffer.isBuffer(name))                     // 结果：true
console.log(name instanceof Uint8Array)                // 结果：true，它是 Uint8Array 子类
console.log(name[0])                                   // 结果：第 0 个字节的值

// ═══════════════════════════════════════════
// 2. 三种创建方式，allocUnsafe 不清零
// ═══════════════════════════════════════════

const safe = Buffer.alloc(4)                           // 结果：4 个 0 字节，已清零
const fast = Buffer.allocUnsafe(4)                     // 说明：可能残留旧数据（池内切片）
fast.fill(0)                                           // 说明：涉密数据务必清零
const fromText = Buffer.from('Hello', 'utf8')          // 说明：从字符串构造

// ═══════════════════════════════════════════
// 3. 编码转换：字节长度与字符长度不同
// ═══════════════════════════════════════════

const text = '栗子🌰'
console.log(Buffer.byteLength(text))                   // 结果：10，emoji 占 4 字节
console.log(text.length)                               // 结果：4，按 UTF-16 码元数
console.log(fromText.toString('hex'))                  // 结果：48656c6c6f
console.log(fromText.toString('base64'))               // 结果：SGVsbG8=
// ascii / latin1 处理中文会丢信息，得到 '?' 或乱码

// ═══════════════════════════════════════════
// 4. subarray / slice 是共享内存的视图
// ═══════════════════════════════════════════

const view = fromText.subarray(0, 2)                   // 说明：零拷贝，不是副本
view[0] = 0x68                                         // 说明：改视图会改到原 Buffer
const copy = Buffer.from(fromText.subarray(0, 2))      // 说明：显式复制才独立

// ═══════════════════════════════════════════
// 5. 大片段先预分配再逐段 copy
// ═══════════════════════════════════════════

const chunks = [Buffer.from('Hello, '), Buffer.from('World')]
const total = chunks.reduce((sum, c) => sum + c.length, 0)  // 说明：先估总长
const merged = Buffer.allocUnsafe(total)                    // 说明：只分配一次
let offset = 0
for (const chunk of chunks) {
  chunk.copy(merged, offset)                                // 说明：逐段写入
  offset += chunk.length
}
console.log(merged.toString())                              // 结果：Hello, World
// 大体积编码转换会短暂膨胀，应改用流式分段处理
