服务端输入与路径安全

防止路径穿越、注入、超大请求和敏感信息泄漏。

开场问题：文件下载接口只做了一件事——把用户传来的文件名拼到上传目录后面去读。有人把文件名填成 ../../../etc/passwd，服务器居然把系统里的账号文件当成「上传目录里的文件」读了回来。

文件名拼接风险

你在写一个下载接口：前端把要下载的文件名交给后端，后端在固定的 uploads/ 目录里找到它、读出来后返回。这个设计看起来天经地义——目录是你自己定的，用户顶多挑个文件名而已。

问题出在你把「文件名」当成了可信数据。用户交上来的字符串里可以合法地包含 ../，而 ../ 在路径里的含义是「回到上一层目录」。多写几层，就能从 uploads/ 一路退回根目录，把你本来绝不允许访问的文件，变成一颗看起来「待在允许目录里的」文件。这类攻击叫路径穿越。

更要紧的是，这种危险不是孤例。请求体大小、字段类型、数据库查询——只要外部输入被直接喂给某个「有解释权」的系统（文件系统、SQL 引擎、Shell），就有被劫持的可能。所以真正该问的是：服务端要在哪个位置、用什么原则，把不可信的输入拦下来？

黑名单式拦截

最省事的补法，是黑名单：看到文件名里有 .. 就拒绝。一行判断，能挡掉开场那个案例。

这个方案做对了一件事：它第一次把「校验」放进了请求进入的地方，而不是等文件都读完了才后悔。方向是对的，问题出在「黑名单」这种形式本身就不牢靠。

编码与路径绕过

  • 黑名单只挡你想到的写法。把 .. 写成 URL 编码的 %2e%2e，甚至编码两次，同一次穿越就可能绕过去。
  • 绝对路径也没被挡住：文件名填 /etc/passwd 时，前面的目录可能被它整个覆盖，拼接形同虚设。
  • Windows 上还有 ..\ 与盘符写法，同一段代码在 Linux 拦得住、到 Windows 就漏。
  • 字段长度没限制：一个超长的参数或路径，足以让解析和日志先被拖垮。
  • 光校验文件名没用——数据库查询若还是拼字符串，注入这条路照样开着。

白名单与规范化校验

不推翻「在边界校验」，而是把黑名单换成白名单 + 规范化后校验这套更稳的组合。核心思路是：别去枚举所有坏输入，只放行你确定安全的那一类。

  1. 白名单校验字段：文件名只允许字母、数字、点、下划线与短横线，并限定长度；字段的类型与取值范围也一次校验到位。你确定要的形态只有一种，其余一律拒绝。
  2. 规范化路径：用 path.resolve(base, name) 把拼接结果变成一条规整的绝对路径——.. 会在这一步被真正地「走出去」。
  3. 确认仍在允许目录内：规范化之后再比对这条路径的前缀确实是 base，否则拒绝。
  4. 其余边界各管各的：请求体限制最大体积，数据库访问一律用参数化占位符（? / $1）而不拼字符串，进程以最小权限账户运行。

为什么先补白名单？因为它成本最低、覆盖面最广，能把绝大多数畸形输入挡在门外。为什么紧接着必须补「规范化后校验」？因为单靠白名单，规则写得再细也总有漏；只有让路径先变成它最终的样子、再回头确认它没跑出允许范围，这个判断才是可靠的。最后补上体积与参数化，是因为它们防的是另外两类完全不同的东西——资源耗尽与注入，各用各的防线。

两个最容易记反的点：其一，先 path.join 再 path.resolve 校验——「拼完」不等于「安全」，必须规范化之后再确认前缀仍在 base 目录内；其二，前端校验永远只是体验优化，绕过它易如反掌，服务端不能把它当作依赖。

还有一条常被忽视的收尾：错误响应本身也是信息泄漏面。把内部路径、堆栈、依赖库版本原样返回给客户端，等于给攻击者递了一份地图。出错时对外只给稳定的错误码和一句人话，细节留在服务端日志里。依赖项也要纳入同一条防线——定期审计、及时升级含漏洞的版本，你信任的库也可能成为入口。

路径穿越拦截边界

外部输入不可信

服务端安全有一条地基式的判断：所有外部输入都不可信。落到实现上就是两句话——用白名单只放行确定的形态，用「规范化后再校验」确认路径没跑出允许范围；剩下的体积限制、参数化查询、最小权限各守一类事故。防线要独立分层，这样即使某一层被绕过，也不会全面失守。

「路径穿越」指攻击者利用文件名或路径参数里的 .. 等片段，让程序访问到允许目录之外的文件。防护的做法是先 path.resolve 规范化、再校验结果仍在 base 目录内，并配合字段白名单（限制字符与长度）。注意 URL 编码与双重编码可能绕过朴素的字符串黑名单，且前端校验不能替代服务端校验。

import path from 'node:path'
import fs from 'node:fs/promises'

// ───────── 路径穿越攻击 (Path Traversal) ─────────
// 攻击者通过 ../ 等方式访问预期外的文件

// 危险的写法：直接拼接用户输入
async function unsafeReadFile(userInput) {
  // 攻击者传入: ../../etc/passwd
  const filePath = path.join('./data', userInput)
  // 可能变成: ./data/../../etc/passwd → /etc/passwd
  return await fs.readFile(filePath, 'utf-8')
}

// 安全的写法：规范化后验证是否在允许目录内
async function safeReadFile(userInput) {
  const baseDir = path.resolve('./data')
  const filePath = path.resolve(baseDir, userInput)

  // 验证解析后的路径是否仍在 baseDir 内
  if (!filePath.startsWith(baseDir + path.sep) && filePath !== baseDir) {
    throw new Error('非法路径访问')
  }

  return await fs.readFile(filePath, 'utf-8')
}

// 更好的做法：使用 path.normalize + 白名单验证
function sanitizePath(userPath, baseDir) {
  const resolvedBase = path.resolve(baseDir)
  const resolvedPath = path.resolve(resolvedBase, userPath)
  const relative = path.relative(resolvedBase, resolvedPath)

  if (relative.startsWith('..') || path.isAbsolute(relative)) {
    throw new Error('路径穿越检测')
  }

  return resolvedPath
}

// 1. 类型与格式验证
function validateEmail(email) {
  if (typeof email !== 'string') return false
  if (email.length > 254) return false
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/
  return emailRegex.test(email)
}

function validateUsername(username) {
  if (typeof username !== 'string') return false
  // 只允许字母数字下划线，3-20 位
  return /^[a-zA-Z0-9_]{3,20}$/.test(username)
}

// 2. 长度限制
function validateInput(input, maxLength = 1000) {
  if (typeof input !== 'string') return false
  return input.length <= maxLength
}

// 3. 数字范围验证
function validatePage(page, maxPage = 1000) {
  const num = Number(page)
  if (!Number.isInteger(num)) return false
  return num >= 1 && num <= maxPage
}

function escapeHtml(str) {
  if (typeof str !== 'string') return str
  return str
    .replace(/&/g, '&amp;')
    .replace(/</g, '&lt;')
    .replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;')
    .replace(/'/g, '&#x27;')
    .replace(/\//g, '&#x2F;')
}

import { execFile, spawn } from 'node:child_process'

// 危险：使用 exec + 字符串拼接
// import { exec } from 'node:child_process'
// exec(`ls ${userInput}`, callback) // 可能被注入

// 安全：使用 execFile + 参数数组
function listFiles(dir) {
  return new Promise((resolve, reject) => {
    execFile('ls', ['-la', dir], (err, stdout, stderr) => {
      if (err) reject(err)
      else resolve(stdout)
    })
  })
}

// 更安全：白名单验证目录
function safeListFiles(dir) {
  const allowedDirs = ['/tmp', '/var/log']
  if (!allowedDirs.includes(dir)) {
    throw new Error('不允许的目录')
  }
  return listFiles(dir)
}

// ───────── 速率限制 (Rate Limiting) ─────────

class RateLimiter {
  constructor(limit, windowMs) {
    this.limit = limit           // 时间窗口内最大请求数
    this.windowMs = windowMs     // 时间窗口（毫秒）
    this.requests = new Map()    // IP -> 时间戳数组
  }

  isAllowed(ip) {
    const now = Date.now()
    const windowStart = now - this.windowMs

    let timestamps = this.requests.get(ip) || []

    // 移除窗口外的记录
    timestamps = timestamps.filter((t) => t > windowStart)

    if (timestamps.length >= this.limit) {
      this.requests.set(ip, timestamps)
      return false
    }

    timestamps.push(now)
    this.requests.set(ip, timestamps)
    return true
  }

  // 定期清理过期数据
  startCleanup() {
    setInterval(() => {
      const now = Date.now()
      const windowStart = now - this.windowMs
      for (const [ip, timestamps] of this.requests) {
        const filtered = timestamps.filter((t) => t > windowStart)
        if (filtered.length === 0) {
          this.requests.delete(ip)
        } else {
          this.requests.set(ip, filtered)
        }
      }
    }, this.windowMs)
  }
}

// 1. 不要在日志中记录敏感信息
function sanitizeForLog(obj) {
  const sensitive = ['password', 'token', 'secret', 'apiKey']
  const result = { ...obj }
  for (const key of sensitive) {
    if (key in result) {
      result[key] = '***REDACTED***'
    }
  }
  return result
}
