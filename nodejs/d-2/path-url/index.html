路径、URL 与跨平台文件定位

用 node:path 与 node:url 做跨平台路径处理，并在 ESM 中定位当前模块。

开场问题：你以为 path.join 会把用户输入「关」在数据目录里，可 path.join('/app/data', '../../etc/passwd') 老老实实还给你 /etc/passwd——一个负责拼接路径的函数，凭什么不帮你挡住向上跳的那两级？

字符串拼接隐患

你要读一个文件，它的位置由几段拼出来：一个基准目录、一个子目录、一个来自配置或用户输入的文件名。最顺手的写法是用字符串接起来：base + '/' + name。在你本机上它一直能跑通。

可一旦换到别的环境，这套拼法就要人自己扛下几笔隐藏成本：Windows 的分隔符是反斜杠、盘符还长成 C:\，POSIX 是正斜杠、根是 /，同一串字符在两边根本不是同一个位置；.. 和 . 需要有人折叠，否则会拼出 a/./b/../c 这种没人看得懂的路径；相对的起点要靠「当前在哪个目录」来猜，而这个目录会随启动方式变化。拼错任何一处，报错往往只是一句 ENOENT，你还得自己反推路径到底算成了什么。

所以问题落到一句话上：Node 里要怎样把一个文件的位置表示准确、且跨平台一致？

路径拼接与规范化

用内置的 node:path。它替你做两件事：path.join 把给出的各段用当前平台的分隔符接起来，顺便规范化掉多余的分隔符和点；path.resolve 则从右往左解析，遇到绝对路径片段就停下，最后还你一个绝对路径。

这个方案做对了一件关键的事：把「分隔符」和「规范化」交给运行时去处理，你只负责描述路径的各个片段，不再手写 / 或 \。于是 path.resolve(baseDir, fileName) 就能得到一条绝对路径，在哪个平台都成立。

越界访问防护缺口

  • path.join 只做拼接与规范化，不做「关在目录里」这件事：path.join('/app/data', '../../etc/passwd') 会得到 /etc/passwd，向上跳照跳不误。
  • 它对绝对片段的处理和 path.resolve 正好相反：path.join('/app', '/etc') 得到 /app/etc，而 path.resolve('/app', '/etc') 得到 /etc。
  • path.resolve 的相对起点是当前工作目录（process.cwd()），同一个脚本从不同目录启动，解析出的绝对路径会不一样。
  • 路径字符串和 URL 是两种表示：在 ESM 里拿模块自身位置得到的是 file:// 开头的 URL，直接当路径传给 fs 会被拒绝，因为文件名里多了个协议前缀。

拼接与绝对路径分工

不推翻 path，而是先把两个函数的语义分工钉清楚：要「把几段接起来」用 join，要「得到一个绝对路径」用 resolve；并且在脑海中记住 resolve 从右往左、碰到绝对片段就丢弃前面，join 只接不抛。分清了这一步，先前的第二种混乱就消失了。

接着补上起点可控。既然 resolve 依赖当前工作目录，就别再让它去猜：先用 path.resolve(baseDir) 得出一个明确的绝对基准目录，再用 path.join 往上拼相对片段。基准来自配置或环境变量，而不是「代码碰巧在哪里被启动」。

然后补上模块自身的位置。ESM 里没有 __dirname，但每个模块都有一个 globalThis._importMeta_.url，它是一条 file:// URL。把「URL」翻译成「文件路径」用 fileURLToPath()，反过来用 pathToFileURL()。跨的是「表示形式」这道坎——URL 用正斜杠、带编码，路径按平台走，两者不能混着用。Node 20.11 以上还直接给了 globalThis._importMeta_.dirname 和 globalThis._importMeta_.filename，省掉手动换算。

再补上跨平台核对。既然路径在两端表示不同，就要能在不换机器的情况下验证另一端的解析结果：path.win32 和 path.posix 让你显式指定按哪个平台的规则解析，在 Windows 上也能算出 POSIX 的答案。

最后补上边界校验。既然 join 不负责安全，就得自己来：把用户输入规范化之后，确认结果仍然落在允许的基准目录内——用 resolve 得到绝对路径，再判断它是否以基准目录开头。演示里把 .. 从输入中抹掉，做的是等价的判断：不许越出这一层。

别凭印象互换两个函数：path.join 不是安全边界，.. 该拦要你自己拦；resolve 与 join 遇到绝对片段的行为相反，用错了会悄悄改变目标路径却毫无报错。

相对路径规范化

分隔符与起点托管

文件定位的本质是：把「分隔符」和「起点」这两件平台相关的事，从你手里交给 path。拼接用 join、求绝对路径用 resolve，起点显式指定而不是依赖工作目录，ESM 里用 globalThis._importMeta_.url 推出模块自身位置，最后再自己确认结果没有越界。

「路径规范化（normalization）」指把 .、..、重复分隔符折叠成规范形式的纯字符串操作，path.join 与 path.resolve 都会顺带完成它。必须记住的边界：它只看字符串、不查文件系统，所以 .. 之后的结果照样可以越出你期望的目录，不提供任何安全保证；真正要防越界，得在规范化之后额外校验结果是否仍在允许的基准路径内。

关键代码

JavaScript
// ═══════════════════════════════════════════
// D02 - node:path 和 node:url 路径处理
// ═══════════════════════════════════════════

import path from 'node:path'
import { fileURLToPath, pathToFileURL } from 'node:url'

// ───────── path 模块核心 API ─────────

// 1. 路径拼接与解析
const baseDir = '/home/user/projects'
const fileName = 'src/index.js'

// path.join: 拼接路径片段，会规范化结果
const joinedPath = path.join(baseDir, fileName)
// '/home/user/projects/src/index.js'

// path.resolve: 解析为绝对路径（从右向左，遇到绝对路径停止）
const resolvedPath = path.resolve('src', 'index.js')
// 相当于 process.cwd() + '/src/index.js'

// 2. 路径信息提取
const fullPath = '/home/user/docs/report.pdf'

path.dirname(fullPath)   // '/home/user/docs'  — 目录名
path.basename(fullPath)  // 'report.pdf'        — 文件名（含扩展名）
path.basename(fullPath, '.pdf')  // 'report'  — 文件名（不含扩展名）
path.extname(fullPath)   // '.pdf'              — 扩展名

// 3. 路径规范化
path.normalize('/home//user/../user/docs/./file.txt')
// '/home/user/docs/file.txt' — 解析 . 和 ..，合并重复分隔符

// 4. 相对路径计算
path.relative('/home/user/a', '/home/user/b/c')
// '../b/c' — 从第一个路径到第二个路径的相对路径

// 5. 路径分隔符与环境判断
path.sep        // Windows: '\\', POSIX: '/'
path.delimiter  // Windows: ';',  POSIX: ':'
path.isAbsolute('/home')  // true — 是否绝对路径

// ───────── 跨平台兼容 ─────────

// Windows 特有
path.win32.join('C:\\Users', 'name')  // 'C:\\Users\\name'

// POSIX 特有（Linux/macOS）
path.posix.join('/home', 'user')      // '/home/user'

// ───────── url 模块与 file URL 转换 ─────────

// 1. 文件路径转 file URL
const filePath = '/home/user/data.json'
const fileUrl = pathToFileURL(filePath)
// URL { href: 'file:///home/user/data.json' }

// 2. file URL 转文件路径
const urlStr = 'file:///home/user/data.json'
const convertedPath = fileURLToPath(urlStr)
// '/home/user/data.json'

// 3. ESM 中获取 __dirname 和 __filename（替代方案）
import.meta.url              // 当前模块的 file URL
const __filename = fileURLToPath(import.meta.url)
const __dirname = path.dirname(__filename)

// Node.js 21+ 可直接用：
// import.meta.filename
// import.meta.dirname

// ───────── URL 解析（WHATWG URL API） ─────────

const url = new URL('https://user:pass@example.com:8080/path?query=1#hash')
url.protocol    // 'https:'
url.hostname    // 'example.com'
url.port        // '8080'
url.pathname    // '/path'
url.search      // '?query=1'
url.hash        // '#hash'
url.username    // 'user'
url.origin      // 'https://example.com:8080'

// 构造 URL
const apiUrl = new URL('/api/users', 'https://api.example.com')
apiUrl.searchParams.set('page', '1')
apiUrl.searchParams.set('limit', '10')
// 'https://api.example.com/api/users?page=1&limit=10'

// ───────── 最佳实践 ─────────
// 始终用 path.join / path.resolve 拼接路径，不要手动拼字符串
// 跨平台项目避免硬编码路径分隔符
// 处理文件 URL 用 fileURLToPath / pathToFileURL
// ESM 模块中用 import.meta.url 获取当前文件路径
