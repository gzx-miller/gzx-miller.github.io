包管理、SemVer 与可重复安装

理解 package.json、锁文件、版本范围、脚本和依赖审计。

开场问题：package.json 里写的是 "axios": "^1.6.0"，团队五个人各跑一次 pnpm install，装出来的却是五个不同的小版本——同一份代码，昨天构建还能过，今天在 CI 上挂了。

声明式依赖解析

你在做一个应用，需要用到几十个第三方库。这些库自己又依赖别的库，层层叠下去，真正落到你机器上的可能是一棵几百个节点的依赖树。你不可能把这棵树手抄一遍，于是把「我要什么」写成声明，交给包管理器去解析。

关键在于，package.json 里写的从来不是「某一个确定版本」，而是一个允许移动的范围。^1.6.0 的意思是「1.6.0 及以上、但还不跨到 2.0.0 的任何版本」。于是同一份声明，在不同时间执行会解析出不同的结果。这就引出一个必须回答的问题：怎么保证每个人、每台机器、每次构建，装出来的都是同一棵树？

精确锁定版本号

最省事的做法：把版本写死，"axios": "1.6.0"，不带任何 ^ 或 ~。这样每次装的都是同一个版本，本地和 CI 自然一致。

这个方案做对了一件事：它抓住了问题的核心——差异来自「范围」。只要能固定住解析结果，可重复安装就成立。问题是，只固定「直接依赖」还远远不够。

间接依赖漂移

  • 你只钉住了自己写的直接依赖，它们的间接依赖（依赖的依赖）仍带着范围，照样会漂。
  • 把几十个直接依赖全部写死，版本一升级就要人工改一遍，既累又容易漏。
  • 写死意味着放弃补丁级的安全修复：明明 1.6.1 修了漏洞，你的死版本还停在 1.6.0。
  • 就算今天碰巧一致，也说不清具体是怎么解析出来的——没有一份「当时到底装了哪些版本」的记录可以拿来对账。

语义化版本与锁文件

不推翻「固定解析结果」，而是把它拆成两层：用范围表达意图，用锁文件记录结果。声明和结果各司其职，问题就解开了。

第一层是 SemVer 范围。语义化版本把版本号拆成「主版本.次版本.补丁」，并约定各自的含义：主版本变动多半意味着不兼容，次版本是向后兼容的新功能，补丁是向后兼容的修复。范围符号就建立在这套约定之上：

  • ^4.1.0（脱字符）允许次版本与补丁更新，也就是 >=4.1.0 且 <5.0.0——日常依赖用它，自动吃到兼容的修复。
  • ~4.1.0（波浪号）只允许补丁更新，即 >=4.1.0 且 <4.2.0——对次版本都不敢信时用它。
  • 4.1.0（不带符号）是精确锁定这一个版本，范围最窄。
  • * 或 latest 最危险：范围宽到没有边界，不同时间安装必然不同，问题几乎无法复现。

第二层是锁文件。第一次安装时，包管理器会把整棵依赖树（包括所有间接依赖）解析出的精确版本、来源和完整性校验信息，全部写进一个锁文件（pnpm-lock.yaml、package-lock.json 或 yarn.lock）。此后安装都以锁文件为准，范围只在「更新锁文件」的那一刻才重新参与解析。那棵树于是不再是「按范围算出来的」，而是「照锁文件还原出来的」。

两层合起来，还需要一条纪律把它们对齐：把锁文件提交进仓库，让每个人都拿到同一份结果记录；再在 CI 上用冻结模式安装——pnpm install --frozen-lockfile。冻结模式的含义是：只允许照锁文件安装，一旦发现 package.json 与锁文件对不上就直接失败，而不是悄悄帮你改。这样，「本地装的和 CI 装的不一样」不再是一个偶发问题，而会在安装那一刻被立刻打断。

三条容易踩的线：不要盲目自动升级主版本，那正是语义化版本里允许破坏兼容的那一档；安装脚本（postinstall 等）拥有执行任意代码的权限，来源必须审查；依赖升级要小步走——升级一批、验证一批，避免一次性大版本跳跃后无从定位。

最后是依赖的日常维护。运行时真正用到的库进 dependencies，只在构建、测试阶段用的工具进 devDependencies，两者分开声明，生产环境才不会白装一堆工具。再定期做依赖审计（如 pnpm audit），发现已知漏洞就评估升级路径——把安全维护也纳入同一套「范围加锁文件」的秩序里。

版本范围升级档位

意图与结果分离

可重复安装的诀窍，是把「意图」和「结果」分成两件事：package.json 里的范围只负责表达你愿意接受哪些升级，锁文件负责记录实际解析出的每一个精确版本。提交锁文件、CI 用冻结模式安装，本地、CI 与生产才会落在同一棵依赖树上。

「SemVer 与锁文件」语义化版本把版本拆为「主.次.补丁」，范围符 ^ 允许次版本与补丁更新（>=4.1.0 <5.0.0），~ 只允许补丁更新（>=4.1.0 <4.2.0），不含符号则精确锁定。锁文件记录整棵依赖树的精确版本，应提交进仓库；CI 用 --frozen-lockfile 冻结安装，锁文件与 package.json 不一致时直接失败。注意 * 与 latest 范围过宽会导致无法复现，主版本升级可能破坏兼容。

// ═══════════════════════════════════════════
// D12 - 包管理与 SemVer 示例
// ═══════════════════════════════════════════

// ───────── SemVer (语义化版本) ─────────
// 格式：MAJOR.MINOR.PATCH
// 主版本.次版本.修订版本

// MAJOR (主版本): 不兼容的 API 变更
// MINOR (次版本): 向下兼容的功能新增
// PATCH (修订版本): 向下兼容的问题修复

// 示例：2.4.1
// 主版本 2，次版本 4，修订版本 1

// ───────── 版本范围符号 ─────────

// 精确版本
// "2.4.1"       必须完全等于 2.4.1

// 范围符号
// ^2.4.1        兼容 2.x.x，>=2.4.1 <3.0.0  (主版本不变)
// ~2.4.1        兼容 2.4.x，>=2.4.1 <2.5.0  (次版本不变)
// >=2.4.1       大于等于 2.4.1
// <=2.4.1       小于等于 2.4.1
// >2.4.1        大于 2.4.1
// <2.4.1        小于 2.4.1
// 2.4.1 - 3.0.0  范围，包含两端

// 预发布版本
// 1.0.0-alpha    Alpha 测试版
// 1.0.0-beta     Beta 测试版
// 1.0.0-rc.1     发布候选版

// ───────── package.json 常用字段 ─────────

const examplePackageJson = {
  name: 'my-awesome-package',
  version: '1.2.3',
  description: '一个示例包',
  main: 'dist/index.cjs',        // CommonJS 入口
  module: 'dist/index.mjs',      // ESM 入口
  types: 'dist/index.d.ts',      // TypeScript 类型声明
  type: 'module',                // ESM 模式 (.js 默认 ESM)

  // 入口点（现代推荐）
  exports: {
    '.': {
      import: './dist/index.mjs',
      require: './dist/index.cjs',
      types: './dist/index.d.ts'
    },
    './utils': {
      import: './dist/utils.mjs',
      require: './dist/utils.cjs'
    }
  },

  // 运行时依赖
  dependencies: {
    'express': '^4.18.0',
    'lodash': '~4.17.21'
  },

  // 开发依赖
  devDependencies: {
    'typescript': '^5.0.0',
    'vite': '^4.0.0',
    'vitest': '^0.34.0'
  },

  // 对等依赖（需要使用者安装）
  peerDependencies: {
    'react': '>=17.0.0'
  },

  // 可选依赖
  optionalDependencies: {
    'fsevents': '^2.3.0'
  },

  // 脚本
  scripts: {
    dev: 'vite',
    build: 'vite build',
    test: 'vitest',
    lint: 'eslint src/',
    preview: 'vite preview'
  },

  // 引擎版本要求
  engines: {
    node: '>=18.0.0',
    npm: '>=9.0.0'
  },

  // 仓库信息
  repository: {
    type: 'git',
    url: 'https://github.com/user/repo.git'
  },

  // 许可证
  license: 'MIT',

  // 作者
  author: 'Your Name <email@example.com>',

  // 关键字
  keywords: ['nodejs', 'example', 'demo'],

  // 私密包（不会发布到 npm）
  private: true,

  // 工作区（monorepo）
  workspaces: [
    'packages/*'
  ]
}
