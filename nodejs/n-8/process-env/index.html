进程、环境变量与优雅退出

集中校验环境配置，并在 SIGTERM 时停止接流量和释放资源。

开场问题：本地用默认值把服务跑得好好的，生产环境却漏配了 PORT，服务照样「正常」起来了，直到第一笔流量打进来才暴露——为什么少了一个环境变量，程序不会在启动那一刻就当场拒绝运行？

进程自带的运行时输入

每个 Node 进程启动时都会拿到一张运行时视图，它就是全局的 process 对象。process.argv 是命令行参数数组，process.env 是环境变量表，process.exitCode 决定进程结束时报给操作系统的退出码——这几项把「程序本身」与「它运行在什么环境里」连了起来。

最省事的做法不必任何封装：要端口就写 process.env.PORT，要密钥就读 process.env.TOKEN。改动最小，换环境也不用动代码。可这份便利只是把成本挪进了看不见的地方。

随处读取留下的三笔账

  • 取值点散落各处：一处把 PORT 敲成 PROT，拿到的只是 undefined，语言不会替你把关。
  • 类型永远是字符串：process.env.PORT 拿到的是 '3000' 而非 3000，忘了转换就会出现字符串拼接这类怪结果。
  • 缺项不报错：配上 || 3000 兜底，漏配被悄悄咽下，服务跑在错误的端口或连错数据库，要等运行到那一行才炸。
  • 测试没法替换：业务代码自己直接读环境变量，单元测试想塞一份假值都无从下手。

问题收敛成一句：怎样让「配置」在程序真正开始干活之前，被完整、正确地确定下来？

启动阶段一次性读取并校验

把配置收进一个独立模块，在启动阶段一次性读完所有需要用到的变量，然后逐个处理：能转类型的转成真实类型，必填的检查是否真的存在。为什么先做收口——「分散、字符串、可能缺失」这三个乱源，只有集中到一处才能一次解决。

收口还带来两个好处：业务代码从此只依赖一个配置对象，不再到处触碰 process.env；测试也可以注入一份假配置，把「环境」这件事从用例里隔离出去。

再补上快速失败：必填项缺失就抛错、拒绝启动，而不是拿默认值蒙混。启动即失败，比运行到一半才出错少一个数量级的排查成本——这正是开场那个「悄悄跑错端口」的根治办法。

再补上校验与转型：端口用 Number() 转换后再确认落在合法范围，布尔类开关显式解析成 true / false。记住一条前提：环境变量的类型是你在边界上补出来的，不是它自然带来的。

信号与退出码

进程不会无缘无故消失。容器编排停止实例时发来 SIGTERM，你在终端按下 Ctrl+C 时收到 SIGINT，调度系统还会发 SIGHUP。收到这些信号时，进程该做的是收尾，而不是立刻倒下。

主动结束时要区分两种写法：设置 process.exitCode = 1 是「告诉进程该以什么码退出，然后让它自然结束」，异步清理能继续跑完；而 process.exit(1) 是「立刻掐断」，来不及完成任何在途工作。退出码本身也有约定：正常结束用 0，失败用非零，运维与 CI 都靠它判断这次运行是否成功。

优雅退出的顺序

收到停止信号之后，收尾动作要按固定次序执行，顺序错了就会对外制造失败：

  1. 先停止接收新请求，让上游的负载均衡把流量导向别的实例。
  2. 再等待仍在处理中的存量请求跑完——「优雅」二字正落在这里：不丢任何一笔在途请求。
  3. 然后释放资源：关闭数据库连接池、断开与下游的连接。
  4. 最后设置退出码、让进程结束。

次序不能颠倒：先关连接池，正在处理的请求会因为借不到连接而失败；先用 process.exit() 抢跑，还没跑完的异步清理会被直接截断，在途请求一并丢失。

给清理留一条兜底

优雅退出也需要上限。K8s 默认给进程 30 秒（terminationGracePeriodSeconds），超过这个窗口还没退出的实例会被强杀。所以业务侧应当自己设一个更早的兜底超时：到点就强制退出，不让一个卡住的连接把自己无限挂起。

别让 process.exit() 抢在清理前面：它会立即终止进程，正在进行的异步清理和在途请求都来不及收尾。正确做法是设好 exitCode、让清理流程自然跑完、进程因没有待办而自行退出；只有在兜底超时到点时，才动用强制退出。

同一份配置的两种解析

两头都要守住的时机

配置与退出，本质上是同一件事的两面：时机。配置要在启动阶段一次读全、转型、校验，缺项就拒绝启动；退出要在收到信号后先摘流量、再等存量跑完、最后释放资源。把这两端守住，滚动部署时才不会「悄悄跑错端口」，也不会「丢请求」。

「优雅退出（graceful shutdown）」指进程收到停止信号（常见为 SIGTERM）后，依次停止接收新请求、等待存量任务完成、释放数据库连接池等资源，最后才结束进程，使退出对外表现为「无失败请求、无连接泄漏」。边界与例外：不要用 process.exit() 强行截断异步清理，否则丢失未完成的请求；优雅退出自身要设兜底超时（K8s 默认给 30 秒），超时后强制退出，避免进程无限挂起。

JavaScript
// ═══════════════════════════════════════════
// 1. 启动阶段集中读取配置
// ═══════════════════════════════════════════

import process from 'node:process'

// 环境变量在模块加载时一次性读取，业务代码不再到处 process.env
const args = process.argv.slice(2)                            // 命令行参数从下标 2 开始
const nodeEnv = process.env['NODE_ENV'] ?? 'development'      // 缺省值只写在一处
const port = Number(process.env['PORT'] ?? 3000)              // 显式转成数字，它不是字符串

export const config = {
  nodeEnv,
  port,
  logLevel: nodeEnv === 'production' ? 'info' : 'debug',      // 同一份代码按环境解析出不同值
  verbose: args.includes('--verbose'),                        // 结果：production 下日志级别为 info
}

// ═══════════════════════════════════════════
// 2. 缺少必填项时拒绝启动
// ═══════════════════════════════════════════

function loadConfig(env) {
  const required = ['DATABASE_URL', 'API_KEY']                // 必填清单集中一处
  const missing = required.filter((key) => !env[key])         // 缺项在启动时就暴露
  if (missing.length > 0) {
    throw new Error(`缺少环境变量: ${missing.join(', ')}`)     // 结果：拒绝启动，而非默默降级
  }
  return {
    databaseUrl: env.DATABASE_URL,
    apiKey: env.API_KEY,
    port: Number(env.PORT ?? 3000),
  }
}

export const runtime = loadConfig(process.env)                // 启动即校验一次

// ═══════════════════════════════════════════
// 3. 收到信号后按顺序收尾
// ═══════════════════════════════════════════

import { createServer } from 'node:http'

const server = createServer((req, res) => res.end('ok'))
const connections = new Set()                                 // 在途连接，退出时要等它们跑完

let shuttingDown = false
function shutdown(signal) {
  if (shuttingDown) return                                    // 重复信号只处理一次
  shuttingDown = true
  server.close(() => {                                        // 1. 停止接收新请求
    Promise.all([...connections].map((conn) => conn.close()))  // 2. 等待存量任务完成
      .then(() => { process.exitCode = 0 })                   // 3. 释放资源后自然退出
  })
}

process.on('SIGTERM', () => shutdown('SIGTERM'))              // 容器编排发来的停止信号
process.on('SIGINT', () => shutdown('SIGINT'))                // 终端 Ctrl+C

// ═══════════════════════════════════════════
// 4. 清理超时的兜底强制退出
// ═══════════════════════════════════════════

function armDeadline(timeoutMs = 10_000) {
  const timer = setTimeout(() => {
    console.error('清理超时，强制退出')                        // 结果：退出码 1，进程不再挂起
    process.exit(1)                                           // 说明：只在兜底时才强制退出
  }, timeoutMs)
  timer.unref()                                               // 不独自拖住事件循环
  return timer
}

// 说明：优雅路径用 process.exitCode 自然退出；process.exit 会截断异步清理，只留给兜底超时
