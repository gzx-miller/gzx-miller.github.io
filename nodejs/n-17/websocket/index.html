WebSocket 实时通信

用 WebSocket 实现实时聊天，掌握连接、心跳、广播和重连策略。

开场问题：用户反馈「卡住了，收不到新消息」。你打开服务端一看，这条连接的日志还老老实实写着「已连接」——服务端都以为它活着，可 socket 这一侧的 send 送出的消息就是到不了对面，两边谁也没报错，消息究竟丢在哪了？

长连接得有人负责「还活着吗」

你已经用 WebSocket 做实时推送：一次握手之后连接一直开着，服务端随时可以把新消息推给客户端。这类长连接是聊天、协作、实时通知的底座，但它带来的问题和管理普通 HTTP 请求完全不同——一次请求答完就断，你根本没有「连接状态」要操心；而长连接要一直活着，就得有人负责确认它是不是真的还活着。

麻烦在于，TCP 连接是「沉默」的。它不会主动告诉你对面已经掉线，链路上的路由器、NAT、负载均衡器也可能在空闲一段时间后静默地掐断这条连接，而两端的连接对象却仍然存在、状态栏上仍显示「已连接」。于是代价很具体：服务端以为自己还在跟一个活人说话，消息发出去却石沉大海；客户端以为自己还连着，界面却再没更新过。所以核心问题是：怎么及时知道一条长连接其实已经死了，并在它死掉之后可靠地接回来？

最省事的写法：断了就重连

最直接的做法：连上就一直用，什么也不管。客户端在 onclose 里直接重新 new WebSocket(url)，断了就立刻重连。

这个方案做对了一件事：它承认了「连接会断」是常态，并给出了最小的补救——断了就再来一次。网络稳定、没有中间设备捣乱时，它确实能跑。

静默断开与重连惊群

  • 它只认得「客户端主动感知到的断开」。被中间设备静默掐掉的连接，onclose 可能很久甚至永远不触发，那条「假死」连接就一直挂着。
  • 断线时立刻重连，一旦服务端正在重启，所有客户端会在同一时刻一起涌上来，形成重连惊群，把刚起来的服务再打挂一次。
  • 一直重连却没有上限，网络长时间不通时会变成停不下来的无效请求，白白耗电耗流量。
  • 服务端若只维护一张「连接表」却从不清理，死连接越积越多，广播时既浪费又容易出错。

应用层心跳加退避重连

不推翻「断了就重连」，而是把它拆成两件独立的事：先用心跳主动探测连接是不是还活着，再用退避策略决定断了以后怎么重连。顺序不能反——不先发现「假死」，重连根本不会被触发。

第一件事是应用层心跳。协议层的探活往往太慢、而且在很多网络环境里不生效，所以要在应用层自己确认：客户端和服务端按固定间隔互发一个极小的 ping / pong 消息，约定好「多久没收到对方的响应就算失效」，超时了就把这条连接主动关掉——关闭的动作会触发 onclose，把那条静默死亡的连接正式标记为已断开。这就补上了最小方案漏掉的第一类连接：客户端察觉不到的假死。

第二件事是指数退避重连。断线后不要立刻重连，先等一小段再试；仍然失败就把等待时间翻倍（比如 1 秒、2 秒、4 秒、8 秒……），直到设一个上限。这样服务端短暂不可用时，重连压力会随时间自动减轻，而不是持续高压。但光有退避还不够：如果所有客户端都从「1 秒」起步，它们依然会在同一些时刻齐步重连。所以还要给每次等待加一点随机抖动（jitter），把同一批客户端的重连时刻错开，从根上避免惊群。

  1. 握手完成后，服务端把这条连接登记进连接表，记录身份与状态，供定向广播使用。
  2. 按固定间隔互发 ping / pong；约定时间内没收到响应，就主动关闭并清理连接表。
  3. 断线后按指数退避重连，等待时间封顶，并叠加随机抖动错开重连时刻。
  4. 断网再恢复，验证重连成功、消息补发，并对比加入抖动前后的重连分布。
两个必须记住的边界：其一，WebSocket 的鉴权要么在握手阶段完成、要么在首条消息里完成，它走的是升级后的自定义协议，不能直接复用 HTTP 那套中间件逻辑；其二，重连的等待时间一定要带随机抖动，否则退避只能缓解、不能消除惊群。

两件事补齐后，服务端这一侧的职责也清晰了：维护一张连接表，记录每个在线连接，据此向全部或指定客户端广播消息；心跳超时和连接关闭时，把失效项从表里清掉。这里有一条容易被忽视的运维要求——连接是持久资源，数量很贵。单机连接数要限制，心跳成功率、在线连接数、广播耗时都应做成可观测指标，否则连接一多，你连「哪里出问题」都看不到。当服务从一台扩到多台，某个节点上的连接表只认识自己那部分用户，跨节点广播还需要一条共享的发布订阅通道（例如 Redis 的 Pub/Sub）来把消息转发给其它实例。

握手与心跳日志

长连接的维持要点

长连接真正的难点不在「连上」，而在「维持」。应用层心跳负责及时戳破那些看起来还活着的假死连接，指数退避加随机抖动负责让断线后的重连既持久又不惊群；服务端再用一张可观测的连接表支撑广播。把这些补齐，实时通道才算真的可用。

「长连接保活」WebSocket 在 HTTP 升级握手后建立持久双向连接，但中间设备可能静默断开，因此需要应用层心跳（定时互发 ping / pong，超时即判定失效并主动关闭）来探测连接活性，断线后按指数退避重连并加入随机抖动以避免重连惊群。服务端用连接表管理在线连接并据此广播；鉴权须在握手阶段或首条消息完成，多实例部署需借助 Redis Pub/Sub 等实现跨节点广播。

// ═══════════════════════════════════════════
// 1. HTTP 升级握手
// ═══════════════════════════════════════════

import { createServer } from 'node:http'
import { WebSocketServer } from 'ws'

const httpServer = createServer()
const wss = new WebSocketServer({ server: httpServer })   // 说明：由 Upgrade 握手升级为双向连接

wss.on('connection', (socket, req) => {
  const userId = new URL(req.url, 'http://local').searchParams.get('uid')  // 说明：握手阶段取出身份
  socket.send(JSON.stringify({ type: 'welcome', userId }))                 // 结果：连接建立后服务端即可主动推送
})

// ═══════════════════════════════════════════
// 2. 连接表与向目标集合广播
// ═══════════════════════════════════════════

const clients = new Map()                                 // 结果：userId → socket，服务端唯一知道谁在线
wss.on('connection', (socket, req) => {
  const userId = new URL(req.url, 'http://local').searchParams.get('uid')
  clients.set(userId, socket)                             // 说明：登记进连接表
  socket.on('close', () => clients.delete(userId))        // 说明：断开即清理，避免死连接堆积
})
function broadcast(payload) {
  const text = JSON.stringify(payload)
  for (const socket of clients.values()) socket.send(text)   // 说明：向全部在线连接推送
}

// ═══════════════════════════════════════════
// 3. 应用层心跳
// ═══════════════════════════════════════════

const HEARTBEAT_MS = 30_000
const alive = new WeakSet()                               // 说明：记录本轮心跳收到过响应的连接
wss.on('connection', (socket) => {
  alive.add(socket)
  socket.on('pong', () => alive.add(socket))              // 结果：收到 pong 才续命
})
setInterval(() => {
  for (const socket of clients.values()) {
    if (!alive.has(socket)) { socket.terminate(); continue }  // 说明：超时判定假死，主动关闭以触发重连
    alive.delete(socket)
    socket.ping()                                         // 说明：探测下一轮是否还活着
  }
}, HEARTBEAT_MS)

// ═══════════════════════════════════════════
// 4. 退避重连与随机抖动
// ═══════════════════════════════════════════

function nextDelay(attempt) {
  const base = Math.min(30_000, 1000 * 2 ** attempt)      // 说明：指数退避，封顶 30 秒
  return base + Math.random() * base * 0.3                // 结果：叠加抖动，错开重连时刻防惊群
}
