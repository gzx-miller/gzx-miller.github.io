视频合并与拼接

掌握三种视频拼接方法：concat 协议（无损）、concat 滤镜（需重编码）和 concat 分离器（需编码格式一致）。

开场问题：你把两段分辨率、帧率看着都一样的 MP4 用 concat 拼在一起，第一段播得好好的，第二段一开始就音画不同步、画面还闪一下——参数明明「一模一样」，拼出来为什么会坏？

时间戳与拼接难点

拼接的需求很朴素：把片头、正片、片尾三段合成一个文件。可你很快发现，「合起来」在视频里不像复制粘贴文本那样直接。文件不是一串连续字节，而是一堆带时间戳的压缩帧，容器还额外记着「哪一帧在什么时刻播、音视频怎么对齐」。于是旧办法把成本都压在了你身上：用剪辑软件重新导出，快是快不起来，画质还要掉一轮；靠肉眼判断两段「像不像」，却看不出编码参数里的时基、像素格式是否真的一致；直接手写命令，又常常分不清几种拼接方式各自的前提。

真正要回答的是：什么情况下可以「原样粘」，什么情况下必须「拆开重编」，而这两条路又各自要求输入满足什么前提？

虚拟输入拼接

最省事的是 concat 协议：ffmpeg -i "concat:input1.ts|input2.ts" -c copy output.ts。它把多个文件用竖线连成一个「虚拟输入」，再交给 FFmpeg 按顺序读出来。

这个方案做对了一件关键的事：它用的是 -c copy，不重新编码。数据包只是被按顺序搬运并重新封装，速度极快、画质零损失。当所有片段本来就是同一套编码参数、又是 TS 这类「适合直接粘」的容器时，这一条命令就够了。

规格不齐隐患

  • 两段的编码参数只要差一点点——码率、分辨率、时基、像素格式，甚至编码器写进码流的头信息不同——拼出来的第二段就会花屏、音画不同步，而且命令不会报错，你得播到那一段才发现。
  • concat: 协议只对少数容器友好，TS 最稳；拿两个 MP4 直接这样拼，结果经常是坏的。
  • 片段一多，一条命令里排满竖线既难读也难维护；文件名里带空格或特殊字符时特别容易翻车。
  • 它没法给每一段指定入点、出点，想剪掉片头几秒，只能先把每段各自裁好再拼。
  • 每段的时间戳都是从 0 各自开始的，直接首尾相接，第二段的时间戳会「往回跳」，播放器可能卡住或跳帧。

无损粘贴与重编

不推翻「原样粘」，而是先把拼接这件事分成两条本质不同的路：「粘数据包」和「重新编码」。前者快而无损，但要求输入规格一致；后者通吃一切，但要付出时间与画质。选哪种，只取决于你的片段参数是否一致、以及能不能接受重编码。

第一层先补「更好用的粘法」。把要拼的文件写成一份列表 list.txt，每行一条 file 'xxx.mp4'，然后用 concat 分离器读取：ffmpeg -f concat -safe 0 -i list.txt -c copy output.mp4。它和协议一样不做重编码，但更灵活：片段可以来自不同的容器，还能给每条加 inpoint / outpoint 指定入点、出点，不用再单独裁剪。

第二层补「参数一致性」这道门槛。无论协议还是分离器，都要求所有片段的分辨率、帧率、编码格式、时基、像素格式完全一致。所以稳妥的做法是先统一再拼：

  1. 把每段都转成同一规格，例如统一到 -vf scale=1920:1080,fps=30 -c:v libx264 -c:a aac。
  2. 确认所有片段都是 H.264 + AAC 这类「同款」编码，像素格式也一致。
  3. 用 concat 分离器 -c copy 把它们无损拼起来。

第三层留给「参数就是没法统一」的情况——素材来源各异，硬要统一反而麻烦。这时改用 concat 滤镜，它把每段解码成帧后重新编码输出，因此能吃下任意组合：-filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1[v][a]" -map "[v]" -map "[a]"。这里的 n=2 表示两段输入，v=1:a=1 表示输出同时带一路视频和一路音频；每段都要按「先视频、后音频」成对写进滤镜图。代价是它必然重编码，慢，而且有一次画质损失。

两个最容易踩的点：拼接不同帧率的素材时，一定先用 fps 滤镜统一帧率，否则时间戳错乱会导致音画不同步；列表文件里的路径含空格或特殊字符时容易失败，建议用相对路径并逐行检查。

拼完别急着交付，用 ffprobe 查一下总时长，确认它等于各片段之和——差得多，多半就是某一段没被正确读入。

三种拼接路径

参数一致判定

拼接只有两种本质选择：参数一致、又能接受不加修饰，就用 concat 协议或分离器 -c copy 无损直拼；参数不一致、又必须合到一起，才动用 concat 滤镜重编码。判断顺序永远是「先看参数、再看是否允许重编码」，而不是记住某一条命令。

「concat 分离器」指用 -f concat -i list.txt 读取一份文件列表来顺序拼接的输入格式。它比 concat: 协议更灵活：可指定每段的 inpoint/outpoint、可混合不同容器，但仍要求各片段的编码参数完全一致，且不做重编码——参数不一致时必须改用 concat 滤镜重编码。

关键代码

BASH
# concat 协议拼接（要求编码参数完全一致）
ffmpeg -i "concat:input1.ts|input2.ts" -c copy output.ts

# concat 分离器拼接（推荐，先创建 list.txt）
# list.txt 内容：
#   file 'input1.mp4'
#   file 'input2.mp4'
ffmpeg -f concat -safe 0 -i list.txt -c copy output.mp4

# concat 滤镜拼接（不同编码参数，需重编码）
ffmpeg -i input1.mp4 -i input2.mp4 -filter_complex "[0:v][0:a][1:v][1:a]concat=n=2:v=1:a=1[v][a]" -map "[v]" -map "[a]" output.mp4

# 拼接 3 个视频（n=3）
ffmpeg -i input1.mp4 -i input2.mp4 -i input3.mp4 -filter_complex "[0:v][0:a][1:v][1:a][2:v][2:a]concat=n=3:v=1:a=1[v][a]" -map "[v]" -map "[a]" output.mp4

# 只拼接视频流（无音频）
ffmpeg -i input1.mp4 -i input2.mp4 -filter_complex "[0:v][1:v]concat=n=2:v=1:a=0[v]" -map "[v]" output.mp4
