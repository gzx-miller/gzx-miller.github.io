码率控制与视频质量

理解码率（Bitrate）对视频质量和文件大小的影响，掌握 CBR、CRF、VBR 等码率控制模式。

开场问题：同一个源文件，用 -crf 18 和 -crf 28 各导一遍，画面上几乎分不出差别，文件大小却差了一大截。crf 这个既不是分辨率、也不是码率的数字，到底在控制什么？为什么不直接填一个目标码率？

画质体积与码率

导出视频时，真正被权衡的其实只有三样东西：画质、体积、码率。码率指每秒用多少比特来存储画面，码率越高画质越好、文件也越大。听起来只要「想要什么画质就填多少码率」就够了，但码率并不是一个能直接填准的旋钮。

原因在于画面复杂度是变化的：一段静止的风景每秒可能几百 Kbps 就够了，紧接的爆炸镜头同一秒却需要好几 Mbps。如果写死一个码率，简单的场景会把多余的比特浪费掉，复杂的场景又不够用、出现块状模糊。所以真正的问题是：怎么在有限的存储空间和带宽下，选对码率策略，让画质稳定又可控？

指定目标平均码率

最直接的写法是指定一个目标平均码率，用 -b:v（b 是 bitrate，v 指视频）：

ffmpeg -i input.mp4 -c:v libx264 -b:v 2M output.mp4

它做对了一件事：结果可预期。你大概知道输出会有多大、需要多大带宽，这对「文件必须塞进某个上限」的场景很实用。

恒定码率固有缺陷

  • 它把简单和复杂场景一视同仁，简单处浪费比特、复杂处又不够，画质在片段之间忽好忽坏。
  • 它只是「平均」达到目标，实际码率会上下波动，遇到高复杂度瞬间出现峰值，弱网下容易卡顿。
  • 它回答不了「我要固定的画质」这个问题——你填的是比特数，而不是你想要的好看程度。
  • 单遍的码率控制对文件大小只是「大致」命中，想精确卡到某个体积往往还差一截。

CRF质量导向编码

不推翻它，而是先换一个以质量为档位的旋钮——CRF（恒定速率因子）。用 -crf 指定一个质量等级，编码器会按画面复杂度自动分配码率：复杂处多给、简单处少给，最终整段的感知画质保持一致，而不是码率保持一致。

对 x264/x265，CRF 的取值范围是 0-51，默认 23，值越小质量越高、文件越大。日常常用的区间是 18-28：18 接近视觉无损，23 是默认值，28 是仍可接受、体积更小的折中。想更省体积可以换成 H.265，同等画质文件更小，代价是它默认 CRF 为 28 且转码更慢。

CRF 有一个副作用：遇到复杂场景它会让码率飙得很高。如果既要 CRF 的质量、又不想让峰值失控（比如给网络播放用），就叠加一个峰值上限，用 -maxrate 限定最大码率、-bufsize 给一个缓冲窗口：

ffmpeg -i input.mp4 -c:v libx264 -crf 23 -maxrate 3M -bufsize 6M output.mp4

再往下走，会遇到两类明确要求「码率必须稳定」的场景。真正常见的做法有两种：

  1. CBR（恒定码率）：把目标、上限、下限都钉死在同一个值上，用 -b:v 3M -maxrate 3M -minrate 3M -bufsize 6M。码率被强制恒定，最适合直播推流这类带宽固定、不能容忍波动的传输。
  2. VBR（可变码率）：只指定目标平均码率与峰值，用 -b:v 2M -maxrate 3M -bufsize 4M，让码率在区间内浮动，在质量与体积之间取得平衡。

如果对文件大小要求很精确，还可以用两遍编码：先扫一遍分析复杂度，再编一遍分配码率，落在目标体积上会更准。而确定参数之前，稳妥的做法是先剪10 秒有代表性的样片分别试几个 CRF，比过画质与体积再定最终值。

三条容易踩的边界：-crf 只作用于视频，音频要另外用 -b:a 控制，否则音频体积不受影响；码率不是越高越好，超过源本身的信息量只是白白撑大文件；动画内容的画面比实拍更「平坦」，通常用更低的码率就能达到同等观感。

三种模式对照

质量恒定与码率上限

码率控制的核心是「让固定的量是质量还是码率」。要画质稳定、体积随内容浮动，用 CRF（常用 18-28，越小越好）；担心峰值太高就加 -maxrate 与 -bufsize；要码率恒定适配直播就用 CBR；想在两者之间平衡就用 VBR。归档前先用样片对比，再定参数。

「CRF（恒定速率因子）」是 x264/x265 的一种码率控制模式：不指定码率，而是指定一个质量档位，让编码器按画面复杂度自动决定每个瞬间用多少比特，从而让整段的感知画质保持一致。取值范围 0-51，默认 23，值越小质量越高、文件越大，常用区间为 18-28。边界与例外：CRF 只影响视频，音频需另用 -b:a 控制；它会让复杂场景码率飙升，需要配合 -maxrate/-bufsize 限峰；不同编码器的编号不通用（H.265 默认 28），跨编码器不能直接照搬同一个数值。

关键代码

BASH
# CRF 模式：高质量（接近视觉无损）
ffmpeg -i input.mp4 -c:v libx264 -crf 18 output.mp4

# CRF 默认质量（23 为默认值）
ffmpeg -i input.mp4 -c:v libx264 -crf 23 output.mp4

# H.265 编码（同等画质文件更小）
ffmpeg -i input.mp4 -c:v libx265 -crf 28 output.mp4

# CRF + 限制最大码率（防止峰值）
ffmpeg -i input.mp4 -c:v libx264 -crf 23 -maxrate 3M -bufsize 6M output.mp4

# CBR 恒定码率（适合流媒体）
ffmpeg -i input.mp4 -c:v libx264 -b:v 3M -maxrate 3M -minrate 3M -bufsize 6M output.mp4

# VBR 可变码率
ffmpeg -i input.mp4 -c:v libx264 -b:v 2M -maxrate 3M -bufsize 4M output.mp4
