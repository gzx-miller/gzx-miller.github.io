GIF 动图生成与优化

从视频生成高质量 GIF 动图，掌握调色板生成、尺寸优化和播放控制。

开场问题：你把一段 6 秒的视频直接转成 GIF，原片明明很干净，转出来人脸却发绿、天空的渐变碎成一块块噪点——转换命令没报任何错，颜色却说烂就烂了。

GIF色彩数量上限

你想把一小段画面做成动图，发到聊天里、贴进文档。视频文件太大，GIF 到处都能直接显示，看起来顺理成章。

可 GIF 是 1987 年定下来的格式，每张图最多只允许 256 种颜色，而且每一帧都是一张完整的像素图。于是成本全落到你身上：颜色得由工具自己压到 256 种，压不好就发花；帧率和画面尺寸直接决定文件大小，稍不注意就是几十 MB；很多聊天工具还有体积上限（比如 10MB），超了根本发不出去。所以要回答的是：怎么在 256 色的硬约束下，既保住观感又把体积压进限制里？

帧率与尺寸缩减

最短的转换命令只有一行：ffmpeg -i input.mp4 -vf "fps=10,scale=320:-1" output.gif。

它做对了一件最要紧的事：先砍掉体积的两个乘数。GIF 的大小几乎正比于「帧数 × 单帧像素数」，而这两项都由你说了算。fps=10 把 30 帧/秒压到 10 帧/秒，帧数直接变成三分之一；scale=320:-1 把宽度缩到 320（-1 表示高度按原比例自动算），像素数掉一大截。两刀下去，文件通常就从几十 MB 降到几 MB。

色偏与帧率继承

  • 颜色不对。不指定调色板时，FFmpeg 会拿一张通用色表去套所有画面，人脸的红、树叶的绿最先被牺牲，于是出现开场那种发绿的肤色和成块的噪点。
  • 不写 fps 就继承源帧率。一段 30 帧/秒的素材会老老实实生成 30 张/秒的 GIF，体积是 10 帧/秒时的三倍，而肉眼看不出差别。
  • 缩放算法没指定。默认算法在大幅缩小时边缘发糊，文字与小图标最容易看出来。
  • 从中间截一段时要留意 -ss 的位置：放在 -i 之前是快速定位、可能落在关键帧上，放在之后才逐帧精确——位置不同，起点会差几帧。
  • 调色板是「为这一段内容统计出来的」。换了素材还复用上一次的调色板文件，颜色会明显偏。
  • 循环次数不在你能精细控制的范围内，而渠道对体积和播放方式都有要求，发布前不实测就不知道能不能用。

色彩量化两遍法

不推翻「砍帧率、砍尺寸」，而是先解决最刺眼的那件事：颜色。核心思路是别让 FFmpeg 自己猜 256 色，而是从这段画面里统计出一张最合适的调色板——这一步叫色彩量化，分两遍完成。

第一遍，扫过整段画面，挑出最有代表性的 256 种颜色，存成一张调色板图片：ffmpeg -i input.mp4 -vf "fps=10,scale=320:-1:flags=lanczos,palettegen" palette.png。注意这里的滤镜链要和最终输出完全一致——调色板是按缩放后的画面统计的，尺寸不一致就白统计了。

第二遍，把原视频按这张调色板逐帧映射成 GIF：ffmpeg -i input.mp4 -i palette.png -lavfi "[0:v]fps=10,scale=320:-1:flags=lanczos[x];[x][1:v]paletteuse=dither=bayer:bayer_scale=5:diff_mode=rectangle" output.gif。这里 [0:v] 是第一路输入的视频、[1:v] 是调色板，paletteuse 负责映射；dither 是抖动，用相邻像素颜色交错来「假装」出 256 色之外的颜色，bayer 快、floyd_steinberg 观感更细腻但慢。

两遍法还有个更省事的写法：不落中间那张 PNG，用 split 在同一条命令里把输入分两路，一路去 palettegen、一路等着 paletteuse：ffmpeg -i input.mp4 -filter_complex "[0:v]fps=10,scale=320:-1:flags=lanczos,split[a][b];[a]palettegen[p];[b][p]paletteuse" output.gif。它的本质仍然是两遍，只是都在内存里完成。反过来，留着那张 PNG 便于反复调参：调好一次，后续可以复用它多试几种 paletteuse 的写法。

颜色解决后，再回头继续压体积。既然 256 色就是天花板，干脆主动降到更少：palettegen=max_colors=128 把色数砍半，文件更小，代价是渐变更容易断带——这一步属于画质换体积，要看着画面做取舍。同理，stats_mode=diff 让统计更偏向画面变化的部分，做界面录屏这类「大块静止、局部在动」的素材会更干净。

接着处理「怎么播」和「取多长」：-loop 0 表示无限循环，也是 FFmpeg 输出 GIF 的默认行为；想让动图只播一次或指定次数，循环次数是记在 GIF 内部的 Netscape 扩展里的，不同工具的写法并不统一，要精确控制得借助专门工具。截取片段时用 -ss 00:00:10 -t 5 取出你要的那 5 秒，再套上面整条滤镜链——先截取再降帧缩放，统计出来的调色板才对得上这一小段。

如果机器上装了 gifsicle，还能再收一道尾：gifsicle -O3 --colors 128 input.gif -o output.gif。-O3 会做帧间差分，只保存与上一帧不同的区域，并重建全局色表——不改内容，纯省体积。没装这个工具就跳过，前面的手段已经够用。

两个容易忽略的点：调色板和内容强绑定，换了片段一定要重新生成 palette.png，否则颜色会明显偏；帧率不是越高越好，GIF 用 10 到 15 帧/秒通常足够，再往上是体积成倍涨、观感几乎没变。发布前把成品在浏览器或目标聊天工具里实际播一遍，确认循环行为与体积都满足渠道限制。如果怎么压都下不来，认真考虑改用无声 MP4 或 WebP 动图——同等质量下它们小得多。

调色板与两遍法对照

抖动与减色补偿

GIF 的一切限制都来自「每帧 256 色」这个天花板：先用 fps 与 scale 把体积的两个乘数压下来，再用 palettegen + paletteuse 两遍法把 256 色用在刀刃上，必要时减色、抖动、上 gifsicle 继续抠体积。调色板只对当前片段有效，这是它最容易被忽略也最容易翻车的边界。

「色彩量化」指把真彩色图像减少到有限种代表色的过程，GIF 的上限是 256 色，所以量化不可避免、且一定有损。palettegen 负责从画面中统计出这 256 种代表色，paletteuse 负责按调色板逐帧映射，并用抖动让相邻像素交错的颜色在视觉上合成为中间色。边界：调色板与具体内容强相关，换片段必须重新生成；减色与抖动都能压体积，但前者会带来断带、后者会增加噪点。

关键代码

BASH
# 简单视频转 GIF（色彩效果差）
ffmpeg -i input.mp4 output.gif

# 指定尺寸和帧率
ffmpeg -i input.mp4 -vf "fps=10,scale=320:-1" output.gif

# 第一步：生成调色板（关键，避免色偏）
ffmpeg -i input.mp4 -vf "fps=10,scale=320:-1:flags=lanczos,palettegen" palette.png

# 第二步：使用调色板生成高质量 GIF
ffmpeg -i input.mp4 -i palette.png -lavfi "[0:v]fps=10,scale=320:-1:flags=lanczos[x];[x][1:v]paletteuse=dither=bayer:bayer_scale=5:diff_mode=rectangle" output.gif

# 从指定时间开始，持续 5 秒
ffmpeg -ss 00:00:10 -t 5 -i input.mp4 -vf "fps=10,scale=320:-1" output.gif

# 循环播放 GIF（0 = 无限循环）
ffmpeg -i input.mp4 -vf "fps=10,scale=320:-1" -loop 0 output.gif
