画面填充（Pad）与宽高比转换

使用 pad 滤镜为视频添加黑边或自定义颜色边距，将视频适配到不同宽高比的播放区域。

开场问题：一段竖屏 1080×1920 的视频要塞进 16:9 的横屏播放器。直接 scale=1920:1080，人被压成了矮胖子；你想只加黑边、不拉伸，于是写下 pad=1920:1080:(ow-iw)/2:(oh-ih)/2，结果命令直接报错，说输出尺寸不能比输入小——黑边一根都没加上。「补边」和「缩放」，到底谁该先谁该后？

比例不符适配

播放器、广告位、社交平台对宽高比的要求各不相同：横屏 16:9、竖屏 9:16、方形 1:1。把一段素材放进比例不同的容器，本该有个不损失内容的办法——不裁剪、不拉伸，只在边上留出空白，这就是常说的 letterbox（上下留边）与 pillarbox（左右留边）。

旧办法是让播放器自己加黑边。它有两个必须由人承担的隐藏成本：一是不可控，边补在哪儿、什么颜色，全由播放器决定，文件一旦交给别人、换一个播放器，可能就被拉伸铺满了；二是不可批处理，你没法把「补边」这一步固化进流水线，更没法在补边之后再接别的处理。所以真正的问题是：怎样在不裁剪、不拉伸内容的前提下，把画面放进一个比例不同的容器，并且保证输出尺寸合法、比例显示正确？

画布扩容与补边

最直接的写法是用 pad 滤镜，它不去动原始画面，只是把画布换大一点，把原画面摆到新画布的某个位置上：

ffmpeg -i input.mp4 -vf "pad=1920:1440:(ow-iw)/2:(oh-ih)/2" output.mp4

语法是 pad=w:h:x:y:color：w / h 是输出的新画布尺寸，x / y 是原始画面在新画布上的左上角位置，color 是填充色（默认黑色）。上面这行把 16:9 的 1920×1080 放进 4:3 的 1920×1440 画布，用 (ow-iw)/2 : (oh-ih)/2 让原画面居中，左右各留出黑边。

它做对了一件事：原画面的每一个像素都被原样保留，只靠扩大画布来改变整体比例，既没裁掉内容、也没把内容拉变形。对「源比目标小」这种情形，这就够了。

输出尺寸下限

  • pad 只会把画布变大：输出尺寸不能小于输入尺寸。竖屏 1080×1920 想 pad 成 1920×1080，高度反而变小了，命令直接报错——这正是开场那一幕的根因。
  • 它不负责缩放。源是 1080×1920、目标是 1920×1080 时，真正需要的「先把画面缩小到能放进去的尺寸」这一步，pad 自己做不到，内容是挤在画布一角还是铺满，取决于上游。
  • 源尺寸是奇数时，居中表达式 (ow-iw)/2 会算出半像素，取整后一边比另一边多一像素，补出来的边左右不对称。
  • 它按像素个数布局。碰到非方形像素的素材，画面的实际显示比例和存储比例对不上，光按像素补边会让内容看起来被压扁或拉长。

缩放补边串联

不推翻 pad，而是先补上它前面缺的那一步——先缩放、再补边。既然 pad 只能扩大画布，那就用 scale 把内容先缩到画布能容纳的大小，两者在同一条滤镜链里依次执行：

ffmpeg -i input.mp4 -vf "scale=1920:-2,pad=1920:1080:(ow-iw)/2:(oh-ih)/2" output.mp4

这段的效果等价于 CSS 里的 object-fit: contain：先把画面等比缩进目标区域，剩下的空隙用黑边填满。注意 scale 必须排在 pad 前面——反过来就是在一个还没缩小的画面上补边，结果完全不同。整套宽高比转换其实就靠这两个滤镜的先后组合：

  1. contain（适配并加黑边）：scale 等比缩小 → pad 补边居中，用来把任意素材塞进固定画布。
  2. cover（填满并裁切）：scale 等比放大到盖住画布 → crop 裁掉溢出部分，用来让画面铺满、宁可裁掉边缘。
  3. 纯补边：仅当源本来就比目标小时，单独用 pad 即可。

第二步要专门说 scale 里的 -2，它和 pad 的取偶是一回事。当只想指定一维、让另一维按比例自动算时，可以把它写成 -1 或 -2：-1 只保证算出来的值是整数，-2 则会再把结果就近取到偶数。为什么非要偶数？因为大多数编码器采用色度下采样，宽高能被 2 整除才不报错、不产生条纹。scale=1920:-2 就是「宽度定死 1920，高度按比例算、并取偶」，这一步替下游挡掉了奇数尺寸的麻烦。

万一 pad 本身是最后一步、没人帮忙取偶，也可以让它自己对齐，用取整表达式把输出尺寸顶到偶数上：

ffmpeg -i input.mp4 -vf "pad=ceil(iw/2)*2:ceil(ih/2)*2" output.mp4

填充颜色不用另外做滤镜，pad 的 color 参数直接接受颜色名、十六进制值和表达式，例如把它换成 white 或品牌色。默认黑边在深色背景里几乎看不出来，但放到浅色背景下，一条纯黑的边就会很突兀，这时换成白边或品牌色更自然。

最后是那个最容易被忽略、也最容易解释「为什么补完边画面还是变扁了」的问题：SAR 与 DAR。SAR（样本宽高比）是单个像素的宽高比，DAR（显示宽高比）是你眼睛看到的画面宽高比，两者满足 DAR = SAR × 存储宽高比。关键点在于：scale 和 pad 改变的都只是像素尺寸，不会自动校正 SAR。方形像素的素材 SAR 是 1:1，这时像素比例就是显示比例；但老式标清或变形宽银幕素材的 SAR 并不是 1:1，你按像素数补完边，播放器仍会按它自己的 SAR 去解释，于是画面看起来还是不对。遇到这类素材，要么先确认并统一 SAR（例如把它规整成方形像素），要么在流程里显式设置采样比例，别默认「像素对齐了，显示就对齐了」。

两条必须记住的边界：pad 只能扩大画布，输出尺寸不能小于输入尺寸，源比目标大时必须先用 scale 缩下来；-1 只保证整除、-2 才保证偶数，凡是交给编码器的尺寸尽量走 -2。另外补边之后最好用 ffprobe 核对分辨率与宽高比，必要时检查 sample_aspect_ratio，避免「像素对了、显示却变形」。

常见补边命令

内容摆位与取偶

补边要回答的是「画布怎么换、内容往哪摆」。记住两条：pad 只能把画布变大，所以源比目标大时必须先用 scale 缩；尺寸一律用 -2 或取整表达式顶到偶数，别让编码器替你冒险。最后别被像素骗了——scale / pad 动的是像素尺寸，真正决定显示胖瘦的是 SAR 与 DAR。

「SAR / DAR」SAR（Sample Aspect Ratio，样本宽高比）描述单个像素的宽高比，DAR（Display Aspect Ratio，显示宽高比）是观众看到的画面宽高比，二者关系为 DAR = SAR × 存储宽高比。方形像素素材的 SAR 为 1:1，此时像素比例即显示比例。边界与例外：scale 与 pad 只改变像素尺寸，不会自动校正 SAR，老式标清或变形宽银幕素材按像素补边后仍可能显示变形；处理这类素材要先确认或统一采样比例，必要时显式规整为方形像素，再用 ffprobe 核对 sample_aspect_ratio。
