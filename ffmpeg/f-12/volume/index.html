音量调整与音频滤镜

使用 volume 滤镜调整音量，掌握标准化、动态范围压缩、静音检测等音频处理技术。

开场问题：你给三条素材统一加上 -af "volume=2.0" 想把声音都提起来，导出后一条震得人耳朵疼、一条听着刚好、还有一条依然偏小——同一个「翻倍」，为什么结果差这么多？

采样值乘增益

音量滤镜的本质很朴素：把音频的每个采样值乘上一个系数。乘 0.5 是减半，乘 2.0 是翻倍，写成分贝就是 -6dB 与 +6dB。它处理的是「这一个文件相对它自己」的增减，压根不知道这段声音原本有多响。

于是「让不同视频听起来一样大」这件事，只能让人来扛。旧办法无非两条：一条是逐条试听、手动试系数——素材一多就没法收场，而且换个人听结果又不一样；另一条是靠耳朵挑静音段来修剪——既慢又容易漏。真正的问题是：怎样让一批响度各异的素材，输出后听起来是同一个音量？

音量滤镜增益参数

最直接的写法就是用 volume 滤镜，参数既可以是倍数，也可以是分贝：

ffmpeg -i input.mp4 -af "volume=0.5" -c:v copy output.mp4

ffmpeg -i input.mp4 -af "volume=3dB" -c:v copy output.mp4

这个方案做对了一件事：增益是精确、可复现的——你说乘多少就乘多少，同一段素材跑两遍结果完全一致，比在剪辑软件里凭手感拖音量条靠谱得多。

固定增益偏差

  • volume 是固定增益，不是「听感对齐」。源文件本身偏小的那条，乘 2.0 之后仍然偏小；源文件本来就满的那条，乘 2.0 直接冲破上限——于是出现开场里「一条震耳、一条刚好、一条偏小」的分裂结果。
  • 增益过头会削波失真（Clipping）：采样值一旦越过最大值就被硬切平，波形被切掉的那部分永久无法还原。你没法靠「再调小一点」把已经切掉的声音补回来。
  • 倍数与分贝容易混。乘 2.0 约等于 +6dB，而 +3dB 只约等于乘 1.41；写成 volume=-3dB 是降低 3 分贝，不是「减到三分之一」。记错一个符号，方向就反了。
  • 只靠 volume 根本测不出「峰值到没到顶」。你不先量一遍就往上加，等于闭着眼睛往墙上撞。
  • 修剪静音也好不到哪去：没有现成的检测手段时，只能人肉快进，长视频里漏掉几段静音几乎不可避免。

峰值测量前置

不推翻 volume，而是先补上「动手之前先测量」这一层。调音量前，先用 volumedetect 把当前峰值报出来：

ffprobe -f lavfi -i "amovie=input.mp4,volumedetect" -f null -

它会告诉你最大音量和平均音量各是多少分贝。知道峰值离 0dB 还有多少余量，你才能决定「最多能加几 dB」而不削波。

第二层，补上「按听感对齐」的能力，这就是 loudnorm 滤镜要解决的。它实现的是 EBU R128 响度标准化，参数只关心三件事：I 是目标整体响度、TP 是真实峰值上限、LRA 是允许的响度动态范围。

ffmpeg -i input.mp4 -af "loudnorm=I=-16:TP=-1.5:LRA=11" -c:v copy output.mp4

它和 volume 的根本差别在于：volume 只管「乘一个数」，loudnorm 管的是「最终落在多响」。无论源文件原本是 -30 LUFS 还是 -10 LUFS，经过它处理后都会收敛到 I 指定的目标附近，这才是「听起来一样响」的实现方式。网络视频常用 -16 LUFS，广播标准常用 -24 LUFS。

第三层，把 loudnorm 做成两遍处理。单次运行是「边测边调」的动态过程，可能带来轻微的音量起伏；更稳的做法是先跑一遍量出实际的 measured_I、measured_TP、measured_LRA，再把这三个值回填进第二次命令并打开 linear=true，让增益变成一次平稳的整体缩放。

第四层，补上静音检测。silencedetect 能找出低于阈值的静音片段，配合参数控制「多长才算静音」：

ffmpeg -i input.mp4 -af silencedetect=noise=-30dB:d=0.5 -f null -

它的时间戳输出在 stderr 里，常被脚本接走去自动切片或去掉空白段。

两条必须记住的边界：其一，volume 的分贝与倍数是两种不同单位，volume=0.5 是减半（约 -6dB），volume=-3dB 是降低 3 分贝，别把「倍」当「dB」；其二，削波不可逆，任何增益前都要先用 volumedetect 探峰值，必要时再串一个 limiter 兜住上限。想「让文件听起来一样响」时不要用 volume 硬拉，改用 loudnorm。

网络与广播响度

相对增益与响度

音量这件事要分清两个层次：volume 是「对当前文件乘一个数」，是相对增益，改不了不同素材之间的响度差；loudnorm 是「把最终响度收敛到某个目标」，处理的是听感上的一致。要用 volume 就永远先测峰值、防止削波；要让一批视频听起来一样响，就把目标交给 loudnorm。

「LUFS（Loudness Units Full Scale）」是 EBU R128 等标准采用的响度计量单位，反映人耳感知到的整体音量，与只描述单点峰值的 dBFS 不同——同一段音频的 LUFS 值往往明显低于它的峰值 dBFS。它区别于 volume 的固定增益：loudnorm 用 I 设定目标 LUFS、TP 限制真实峰值、LRA 界定响度动态范围。边界与例外：网络视频常取 -16 LUFS、广播取 -24 LUFS；单次 loudnorm 是动态处理，追求稳定时应先测量再回填做第二遍两遍处理。

关键代码

BASH
# 调整音量（减半）
ffmpeg -i input.mp4 -af "volume=0.5" -c:v copy output.mp4

# 调整音量（+3 dB）
ffmpeg -i input.mp4 -af "volume=3dB" -c:v copy output.mp4

# EBU R128 响度标准化（网络视频 -16 LUFS）
ffmpeg -i input.mp4 -af "loudnorm=I=-16:TP=-1.5:LRA=11" -c:v copy output.mp4

# 广播响度标准（-24 LUFS）
ffmpeg -i input.mp4 -af "loudnorm=I=-24:TP=-2:LRA=7" -c:v copy output_broadcast.mp4

# 静音检测
ffmpeg -i input.mp4 -af silencedetect=noise=-30dB:d=0.5 -f null -

# 检测音频峰值（防止削波）
ffprobe -f lavfi -i "amovie=input.mp4,volumedetect" -f null -
