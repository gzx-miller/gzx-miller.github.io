视频裁剪（Crop）

使用 crop 滤镜裁剪视频画面，去除黑边、聚焦特定区域或调整为不同宽高比。

开场问题：一段 1080p 视频上方压着 60 像素黑边，你写下 crop=1920:960:0:60，一跑果然裁得干干净净。可当你想把这行参数复用到另一段素材上——不是偏了几十像素、黑边还留一条，就是编码器直接报错说尺寸不能被 2 整除。同一个「去掉黑边」的诉求，参数为什么不能通用？

画面矩形裁取

裁剪要干的是一件很朴素的事：从画面里取出一块矩形。拿掉多余的黑边、把注意力收进某个角落、或者把横屏画面切出中间的竖屏区域，「裁剪」都是它们的共同动作。

旧办法是让人来框选：打开剪辑软件、拖动四条边、导出。它有两个必须由人扛的隐藏成本：一是不可脚本化，今天框一次，明天换一批素材还得再框一遍，无法批量；二是口径不一致，黑边到底从第几像素开始，全凭眼睛估，两段素材、两个人做，结果就对不齐。所以真正的问题是：怎样用一组可以计算、可以复用的参数，精确地切出任意一块区域，并且保证结果符合编码器的尺寸要求？

四参数写死坐标

最直接的写法是把四个数字写死，这就是 crop 滤镜的基本语法：

ffmpeg -i input.mp4 -vf crop=1280:720:0:0 output.mp4

四个参数依次是 w:h:x:y：输出宽、输出高、以及裁剪起点相对于原始画面左上角的坐标。它做对了一件事：位置和尺寸都被明确写了出来，没有歧义，一眼就能看懂你在切哪一块。对一段尺寸固定、黑边已知的素材，这一行永远有效。

固定坐标失效场景

  • 一旦源尺寸变了，写死的数字立刻失效：源是 3840×2160，同样的 1280:720:0:0 只取到了左上角一小块，而不是你想要的等比区域。
  • 黑边尺寸不是整数时手填的坐标会偏：真实黑边是 62 像素，你按整数写了 y=60，结果顶端留下 2 像素的一条黑边，怎么放大都看得见。
  • 偶数对齐是个硬要求：如果源高度是 1081，写 ih-120 得到 961，是奇数——很多编码器的色度采样要求宽高能被 2 整除，轻则报警告、重则直接失败，勉强编出来两侧还会有条纹。
  • 想切一个居中的竖屏或方形区域时，起点得自己拿计算器算，算错一个括号就整体偏移，而且换一段素材又要重算。

表达式替代坐标

不推翻「写参数」这件事，而是让参数自己算——crop 的 w/h/x/y 都支持表达式，可以直接引用当前画面的尺寸变量：in_w / in_h 是输入宽高，iw / ih 是它们的简写，out_w / ow 是输出（裁剪后）的宽。

用这些变量，居中裁剪就不用再手算坐标了。比如裁一个居中的 9:16 竖屏：

ffmpeg -i input.mp4 -vf crop=ih*9/16:ih:(in_w-ih*9/16)/2:0 output.mp4

这里高度保留原始 ih，宽度按竖屏比例算成 ih*9/16，x 用 (in_w - 裁剪宽)/2 把画面推到水平正中。换成方形就是 crop=ih:ih:(in_w-ih)/2:0，逻辑完全一样。表达式让「居中」这件事跟源尺寸解耦了：无论素材多宽多高，居中永远是居中的。

去黑边也是同理。假如你确认上下各有 60 像素黑边，可以写成：

ffmpeg -i input.mp4 -vf crop=iw:ih-120:0:60 output.mp4

宽度不动（iw），高度砍掉 120，起点下移 60。可是「上下各 60」这个前提靠肉眼并不可靠，所以更稳妥的做法是先让工具自己量——用 cropdetect 扫一遍：

  1. 先探测：ffmpeg -i input.mp4 -vf cropdetect -f null -，它会在控制台反复打印候选参数。
  2. 从日志里挑出现次数最多的那一组 crop=w:h:x:y，那才是稳定的黑边边界。
  3. 把探测结果直接填回真正要跑的裁剪命令：ffmpeg -i input.mp4 -vf crop=1920:960:0:60 output.mp4。
  4. 导出后用 ffprobe 复核输出分辨率，确认尺寸没偏、宽高都是你预期的值。

最后要专门处理奇偶对齐这个问题——它既是坑，也有干净的解法。裁剪后的宽高最好都是偶数：一方面多数编码器的色度下采样要求尺寸能被 2 整除，奇数尺寸轻则报警告、重则直接失败，勉强编出来两侧还有条纹；另一方面它保证了之后拼接、缩放时不会出现半像素的错位。既然 w/h 也支持表达式，就可以把结果直接压到偶数上。比如把上面那段高度对齐成偶数：

ffmpeg -i input.mp4 -vf crop=iw:floor((ih-120)/2)*2:0:60 output.mp4

读法是「先减掉要裁的黑边，再除以 2 向下取整、乘回 2」——无论源高是奇是偶，算出来的高度都会是偶数。这是一个可以一直带在身边的习惯：凡是交给编码器的宽高，都顺手取个偶。

裁剪还经常和缩放连着用，此时用逗号把两个滤镜串起来，前一个的输出就是后一个的输入：

ffmpeg -i input.mp4 -vf "crop=1920:800:0:140,scale=1280:720" output.mp4

三个容易踩的边界：视频裁剪用的是 -vf crop，别顺手写成 -af（-af 处理的是音频，同名参数对不上）；x/y 里的表达式如果含逐帧变化的量，会每一帧都重算一次，固定值能省下不必要的开销；cropdetect 给出的只是建议值，遇到画面本身就有纯色边框（比如白底视频）时可能误判，务必人眼复核一遍。

生成器与自动检测

跨素材参数复用

裁剪的核心是「用可计算的参数描述一块矩形」。写死 w:h:x:y 能跑，但只要源尺寸一变就会错位；把坐标换成基于 in_w / in_h 的表达式，「居中」和「等比」就能跨素材复用。搭配 cropdetect 让工具替你量黑边，并始终让裁出的宽高落在偶数上——这块区域才既准又稳。

「crop 滤镜」用于从画面中裁出一块矩形，语法为 crop=w:h:x:y，x / y 是裁剪起点相对原图左上角的坐标，并支持 in_w / in_h / out_w 等表达式变量实现居中与等比裁剪。边界与例外：裁剪后的宽高建议取偶数，否则部分编码器的色度采样会失败或产生条纹；黑边起点应先用 cropdetect 探测而非肉眼估；视频要用 -vf 而非 -af；含逐帧变量的 x/y 表达式会每帧重算，固定值更省性能。

关键代码

BASH
# 裁剪指定区域 crop=w:h:x:y
ffmpeg -i input.mp4 -vf crop=1280:720:0:0 output.mp4

# 自动居中裁剪 9:16 竖屏画面
ffmpeg -i input.mp4 -vf crop=ih*9/16:ih:(in_w-ih*9/16)/2:0 output.mp4

# 裁剪掉上下各 60 像素黑边
ffmpeg -i input.mp4 -vf crop=iw:ih-120:0:60 output.mp4

# 自动检测黑边参数
ffmpeg -i input.mp4 -vf cropdetect -f null -

# 使用检测到的参数裁剪
ffmpeg -i input.mp4 -vf crop=1920:960:0:60 output.mp4

# 裁剪 + 缩放组合
ffmpeg -i input.mp4 -vf "crop=1920:800:0:140,scale=1280:720" output.mp4
