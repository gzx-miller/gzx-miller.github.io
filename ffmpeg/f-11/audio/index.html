音频处理基础

掌握音频采样率、声道数、编码格式、码率等核心参数的调整方法。

开场问题：你只想把视频里音频的采样率从 48000 改成 44100，顺手写下 ffmpeg -i input.mp4 -ar 44100 output.mp4，跑完后发现文件比原片大了将近三倍，画面也比原来糊了——你明明只动了音频，画质为什么会跟着掉？

音视频独立流

一个音视频文件里，画面和声音是两条各自独立的流（stream），彼此不知道对方的参数。视频流有分辨率、帧率、码率；音频流也有自己的一整套：采样率（每秒采样多少次，常见 44100Hz 或 48000Hz）、声道数（单声道、立体声、5.1 环绕声）、编码格式（AAC、MP3、Opus）与码率（决定音质和体积）。这四样凑齐，才算把一段声音描述清楚。

麻烦在于「统一」这件事必须由人扛。旧办法无非两条：一条是整段重新编码——为了改一个采样率，把好好的 H.264 画面也重压一遍，耗时翻倍、画质还掉了；另一条是干脆不处理——可不同来源的素材采样率、声道数五花八门，拼在一起就忽左忽右、忽大忽小。所以真正的问题是：怎样只改音频的参数，同时让视频原封不动？

采样率声道与码率

FFmpeg 给音频参数各配了一个开关：-ar 设采样率、-ac 设声道数、-b:a 设音频码率、-c:a 指定音频编码器。想改哪一样就写哪一样：

ffmpeg -i input.mp4 -ar 44100 -c:v copy output.mp4

这个方案做对了一件事：它把音视频分开对待——你想动的是声音，那就只让音频这一路干活，画面走旁路。

视频连带重编码

  • 漏写 -c:v copy，视频就会被连带重新编码。这正是开场那个「只改音频、画质却掉了」的结果：你没有对视频编码作任何声明，FFmpeg 默认把所有流都重新编一遍。
  • 改 -ar / -ac 一定会触发音频重采样并重新编码，它做不到像 -c copy 那样「只搬家、不重做」。想无损只改这两个参数，技术上是不可能的。
  • 把多声道直接降成单声道时，-ac 1 会把各声道简单相加，原本接近满幅的声音可能直接削波失真；这种场合更该用 pan 或 aresample 控制混音增益。
  • 用 -c:a copy 抽音轨时，若只换了扩展名却没换编码，文件的外表会和内容对不上——把 AAC 硬叫成 .mp3，播放器能出声，但标签全错，后续脚本按扩展名判断就会踩坑。
  • 想让容器收下一段它不支持的音频编码，比如把 FLAC 塞进 MP4，-c copy 会直接报错退出，而不是帮你悄悄转码。

探测与画面锁定

不推翻这套参数，而是按顺序一层层补齐。第一层，先探测再动手。你不知道源文件是 48000 还是 44100、是双声道还是 5.1，就不该拍脑袋写命令，先让 ffprobe 把音频流参数报出来：

ffprobe -v error -select_streams a:0 -show_streams input.mp4

其中 -select_streams a:0 只挑第 0 条音频流，免得视频流的信息混进来干扰判断。看清了再决定改什么。

第二层，锁定视频不动。只要这次任务与画面无关，命令里就永远写上 -c:v copy。这不是可有可无的优化，而是防止「改音频把画面拖下水」的保险。

第三层，挑对音频编码器。同一段声音换成不同编码，体积和兼容性差得很远：aac 兼容性最好，几乎所有设备和平台都认，是最稳妥的默认；libmp3lame 老设备通吃；libopus 在低码率（如 96k）下音质明显优于 AAC，适合语音通话和 WebRTC；flac 与 pcm_s16le 是无损，文件大，留给归档。

ffmpeg -i input.mp4 -c:a aac -b:a 128k -c:v copy output.mp4

第四层，只留声音或换掉声音。用 -vn（no video）丢掉视频流，就得到一条纯音轨；保留原编码直接抽出来用 -c:a copy，速度最快：

ffmpeg -i input.mp4 -c:a copy -vn output.aac

反过来，要把一条新音轨换进视频，思路是「先决定留哪条流，再写出去」：用 -map 显式点名视频流与目标音频流，其余一律不输出。

  1. 用 ffprobe -select_streams a:0 读出源音频的采样率、声道数与编码。
  2. 按目标设备或平台的要求，用 -ar / -ac / -c:a / -b:a 补齐参数。
  3. 一律附上 -c:v copy，确保画面不被重编码。
  4. 输出后再用 ffprobe 复核采样率与声道数，确认参数真的生效。
三个常见误区：一是以为 -ar / -ac 能无损，其实它们必然重采样重编码；二是改完音频忘了 -c:v copy，白白把画面重压一遍；三是把 -c:a copy 抽出的音轨随便起扩展名，内容和文件名对不上。想把立体声降到单声道又不想削波，别硬用 -ac 1，交给 pan 控制混音增益更稳。

音频操作对照

按流分别处理

音频处理的关键，是先把音视频当成两条独立的流：要改声音，就用 -ar / -ac / -c:a / -b:a 精确点名改什么，同时用 -c:v copy 把画面钉死不动。记住改采样率或声道一定伴随重采样与重编码，想无损只搬不重做，只有 -c copy 这一条路。

「音频重采样（Resampling）」指在改变采样率或声道布局时，把离散采样点重新换算到新时间网格上的过程——例如 48000Hz 降到 44100Hz，必须重新计算每一个采样值，因此一定伴随重新编码，无法用 -c copy 无损完成。边界与例外：只改 -b:a（码率）而编码器不变，同样要重编码；-ac 改变声道数时会先做声道混合，降声道可能因简单相加而削波，需要 pan 或 aresample 精细控制增益；只有在原样提取音轨时才用 -c:a copy，且输出扩展名要与真实编码一致。

关键代码

BASH
# 修改采样率为 44100 Hz
ffmpeg -i input.mp4 -ar 44100 -c:v copy output.mp4

# 转为单声道
ffmpeg -i input.mp4 -ac 1 -c:v copy output.mp4

# 设置音频码率 128 Kbps
ffmpeg -i input.mp4 -b:a 128k -c:v copy output.mp4

# 转换为 AAC 编码
ffmpeg -i input.mp4 -c:a aac -b:a 128k -c:v copy output.mp4

# 提取音频为 MP3
ffmpeg -i input.mp4 -c:a libmp3lame -b:a 192k -vn output.mp3

# 提取音频保留原编码
ffmpeg -i input.mp4 -c:a copy -vn output.aac

# 转 Opus 编码（低码率优选）
ffmpeg -i input.mp4 -c:a libopus -b:a 96k -c:v copy output.mkv
