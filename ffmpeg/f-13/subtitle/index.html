字幕处理与烧录

掌握外挂字幕、内嵌字幕和烧录字幕（Hardsub）三种字幕处理方式。

开场问题：你用 ffmpeg -i input.mp4 -i subtitle.srt -c copy -c:s mov_text output.mp4 把字幕封进 MP4，命令几秒就跑完、文件几乎没变大，你满心以为字幕「进去了」；换到一台老播放器和某个上传平台上，画面下方却空空如也——字幕到底进没进去？

外挂内嵌与烧录

字幕这件事，和「给画面贴一张图」完全不是一回事。它有三种截然不同的落法：外挂字幕是独立文件，播放时加载；内嵌字幕（软字幕）是把字幕封装成容器里的一条独立流，能开关、能切语言；烧录字幕（硬字幕）则是把文字直接渲染进画面像素里，成为图像的一部分。

旧办法往往只剩两条：要么直接烧录，可一旦烧进去就无法再移除，改一个字都得把整段视频重压一遍；要么干脆发外挂文件，可用户得自己找字幕、还得播放器肯加载。真正的问题是：怎样在「随时能关」与「一定看得到」之间做取舍，并为每种场景选对方式？

内嵌字幕流封装

最省事的做法是先把字幕封装成一条内嵌流，用 -c copy 原样搬运音视频、只给字幕换一个容器认可的编码，比如 MP4 里的 mov_text：

ffmpeg -i input.mp4 -i subtitle.srt -c copy -c:s mov_text output.mp4

这个方案做对了一件事：字幕成了一条可开关的独立流——它不占画面、能多语言并存、代价极小（音视频走 -c copy 几乎不重编码），这正是「软字幕」的全部价值。

播放器支持差异

  • 软字幕依赖于播放器肯不肯认。这就是开场那一幕的真相：字幕其实已经封进去了，只是那台旧播放器和那个平台不支持 mov_text 这条轨道，于是它一个字都不显示，看起来就像「没进去」。
  • mov_text 只支持很基础的样式。ASS 字幕里的定位、描边、动画在 MP4 里会大面积丢失，换成 MKV 才保得住。
  • 烧录一旦完成无法移除，而且必须重新编码整段视频，处理几分钟的片子可能要等上很久——这是它相比软字幕最沉重的代价。
  • 中文字幕最常栽在编码上：SRT 文件若没存成 UTF-8，烧录出来后整段是乱码方框；这时要显式告诉滤镜文件编码。
  • 一个容器里塞了多条字幕轨时，默认导出哪一条并不确定，不显式指定就可能留下错误的那条。

已有字幕流探测

不推翻这三种方式，而是先补上「先看清楚有什么」这一层。动手前用 ffprobe 把字幕流列出来，看源文件里已经封了几条、什么编码：

ffprobe -v error -select_streams s -show_streams input.mkv

-select_streams s 只看字幕流。看清之后再决定是新增一条、还是只保留其中某一条。

第二层，先选对容器。容器对字幕的兼容性差别很大：MKV 对字幕支持最好，SRT、ASS、图像字幕都能装；MP4 只能用 mov_text，样式能力有限。所以有样式要求的多语言版本，优先封进 MKV：

ffmpeg -i input.mkv -i subtitle.srt -c copy -c:s srt output.mkv

第三层，多语言时用 -map 点名，再给每条轨贴上语言标签，播放器才能正确列出「中文」「English」：

ffmpeg -i input.mp4 -i zh.srt -i en.srt -map 0 -map 1 -map 2 -c copy -c:s mov_text -metadata:s:s:0 language=chi -metadata:s:s:1 language=eng output.mp4

第四层，确实需要「人人可见」时才烧录。用 subtitles 滤镜把文字渲染进画面，中文务必指明 UTF-8 编码：

ffmpeg -i input.mp4 -vf "subtitles=filename=subtitle.srt:charenc=UTF-8" output.mp4

需要改样式时，还可以用 force_style 覆盖字号与颜色，例如 force_style='Fontsize=24,PrimaryColour=&Hffffff&'。它需要 FFmpeg 编译时启用 libass 支持，可以用 ffmpeg -filters 里有没有 subtitles 来确认。

  1. 用 ffprobe -select_streams s 查看现有字幕流，判断要新增还是替换。
  2. 要「能开关、多语言」就选软字幕，按容器挑选 -c:s（MP4 用 mov_text，MKV 用 srt 或 ass）。
  3. 多条轨时用 -map 指定保留哪些，并补上 language 标签。
  4. 只有目标平台无法播放软字幕时，才用 subtitles 滤镜烧录，并指定 UTF-8 编码。
两个常见误判：一是把「播放器没显示」当成「字幕没封进去」——多半只是该播放器不支持那条字幕流，用 ffprobe 一查便知；二是对 MP4 里的 mov_text 抱有样式的期待，ASS 的定位与动画在 MP4 中会丢，要保样式就换 MKV。另外，烧录字幕会增加编码工作量且不可逆，操作前一定留好原始文件。

三条路线对照

字幕方案选型

字幕先问一句「谁来看、要不要关」：要能开关、要多语言，就用软字幕把字幕封成独立流，并按容器选对编码（MP4 用 mov_text、MKV 用 srt 或 ass），多轨时用 -map 点名；只有目标平台完全不吃软字幕时，才用 subtitles 滤镜烧成硬字幕。别把播放器不显示误当成字幕没封进去，先 ffprobe 看一眼字幕流。

「软字幕与硬字幕（Softsub / Hardsub）」软字幕指以独立流形式封装在容器里的字幕，播放时可开关、可切语言、可多轨并存，代价是依赖播放器支持；硬字幕指用 subtitles 滤镜把文字渲染进画面像素，任何播放器都能看到，代价是不可移除且必须重编码。边界与例外：MP4 的软字幕只有 mov_text，样式能力有限，ASS 的定位与动画会丢，保样式应改用 MKV；中文字幕文件必须是 UTF-8，烧录时用 charenc=UTF-8 兜底；subtitles 滤镜依赖编译时的 libass 支持。

关键代码

BASH
# 查看字幕流
ffprobe -v error -select_streams s -show_streams input.mkv

# 添加外挂 SRT 字幕到 MP4（内嵌字幕流）
ffmpeg -i input.mp4 -i subtitle.srt -c copy -c:s mov_text output.mp4

# 将 SRT 字幕嵌入 MKV
ffmpeg -i input.mkv -i subtitle.srt -c copy -c:s srt output.mkv

# 烧录 SRT 字幕到画面（硬字幕）
ffmpeg -i input.mp4 -vf subtitles=subtitle.srt output.mp4

# 烧录 ASS 字幕（保留样式）
ffmpeg -i input.mp4 -vf subtitles=subtitle.ass output.mp4

# 指定字幕编码（中文 SRT 用 UTF-8）
ffmpeg -i input.mp4 -vf "subtitles=filename=subtitle.srt:charenc=UTF-8" output.mp4

# 烧录内嵌字幕流（第 0 个字幕流）
ffmpeg -i input.mkv -vf subtitles=input.mkv output.mp4
