数字、Math 与日期格式化

掌握浮点精度、安全整数、Math 常用方法与日期时间戳，用 Intl 做地区化格式化。

开场问题：购物车合计写 0.1 + 0.2，界面却冒出一串 0.30000000000000004；而给商品加一个 16 位自增 id 时，两个不同商品的 id 竟然判定为相等——同样两个「数字」，一个差在精度，一个差在范围。

把数字当数字用

最自然的想法是：数字就是数字，加减乘除直接用 + - * /，比较直接用 ===，算出来的结果是不是整数、有没有小数，代码不用操心。日常里这套做法大多时候是对的，直到它撞上边界——金额对不上分、超大编号认不出彼此。

要理解这两件事，得先知道 JavaScript 里其实只有一种数字类型 number，底层是 64 位双精度浮点。整数与小数共用一套二进制表示，麻烦就从这里开始。

浮点精度与安全整数范围

小数在二进制里大多无法精确表示，0.1 和 0.2 都只是接近于真实值的近似，相加后误差累积，于是 0.1 + 0.2 === 0.3 得到 false。金额场景最好避开小数运算——把金额换算成「分」，用整数从事计算，只在显示时格式化；金额需要更大范围时再考虑 BigInt，但它不能和普通 number 混合运算。

整数这边同样有边界：number 能精确表示的整数上限是 Number.MAX_SAFE_INTEGER，也就是 253 − 1。超过这个范围，相邻的两个整数可能被表示成同一个值，于是两个本该不同的 id 会相等。后端返回的雪花 id 常超过安全整数，接收时应当保持为字符串。

NaN、Infinity 与判断方法

还有两个特殊的 number。NaN 表示「不是一个数」，任何无法得到数值的运算都返回它，而且它连自己都不等于自己——NaN === NaN 是 false，因此判断要用 Number.isNaN()。全局的 isNaN() 会先把参数转成数字再判断，传字符串也可能为真，不可靠。

Infinity 表示溢出或除以零的结果，1 / 0 得到正无穷，-1 / 0 得到负无穷。要判断一个值是不是「正常的有限数」，用 Number.isFinite()；它不转换参数，Number.isFinite('1') 直接返回 false。

解析与数值格式化

从文本转数字有三个入口，行为差别很大。parseInt(str, 基数) 从左往右解析，遇到第一个非数字字符就停下，所以 parseInt('12px') 得到 12，传第二个参数还能按进制解析，parseInt('ff', 16) 得到 255；parseFloat('3.14abc') 得到 3.14；而 Number('12px') 要求整串都合法，于是返回 NaN。选择哪个，取决于你容忍多少「脏」输入。

数值转文本则靠格式化方法：toFixed(2) 固定到两位小数，常用于价格，但它返回字符串，且受浮点近似影响偶尔会「差一分钱」；toPrecision(n) 控制有效数字位数；toLocaleString() 按地区加上千分位和小数点。三者都只负责显示，不改变计算用的原始数字。

Math 常用方法与整数判断

取整是数值处理里最高频的一类。Math.round 四舍五入（.5 一律朝正方向，所以 Math.round(-2.5) 是 -2）；Math.trunc 直接丢弃小数部分；Math.floor 向下取整、Math.ceil 向上取整，它们在负数上与 trunc 分道扬镳（Math.floor(-2.7) 是 -3，Math.trunc(-2.7) 是 -2）。此外 Math.max / Math.min 取极值，Math.abs 取绝对值，Math.pow（现多用 **）求幂，Math.random 返回 [0, 1) 之间的小数，配合取整就能生成指定范围的整数。

判断整数要用 Number.isInteger()，它不像全局判断那样做隐式转换，2.0 会被认为是整数、2.5 不会。它与 Number.isFinite() 一起，构成数值校验里最稳的一对守卫。

亲手体验格式化与取整

下面的演示把这一章落到真实动作：按钮分别触发货币格式化、日期格式化和 Math 取整，直观看到 Intl 的输出和不同取整函数的差异。

Date、时间戳与地区化

Date 有三种常见创建方式：new Date() 取当前时刻，new Date(时间戳) 用毫秒数构造，new Date(年, 月, 日, 时, 分) 按字段拼。这里藏着两个坑：月份从 0 开始，new Date(2026, 9, 14) 其实是 10 月 14 日，而且 getMonth() 返回的也是 9；字符串解析的时区基准又因写法而异，new Date('2026-10-14') 按 UTC 午夜解析，而 new Date('2026/10/14') 按本地时区解析，跨时区时就差出一整天。

用来比较、排序、存储的，是时间戳：date.getTime() 返回自 1970 年 1 月 1 日 UTC 起算的毫秒数，Date.now() 直接给出当前毫秒。用时间戳做减法能算时间间隔，做大小比较能判断先后，存进数据库也不会带上时区歧义。要让人看懂，再用 Intl.DateTimeFormat 按地区格式化输出。

「时间戳」指从 1970-01-01 00:00:00 UTC 起经过的毫秒数（Date.getTime() 返回，Date.now() 取当前值）。它是与时区无关的绝对刻度，适合比较、运算与存储；展示给用户时再用 Intl.DateTimeFormat 转成对应地区的可读日期。

// 1. 浮点精度与安全整数
// ═══════════════════════════════════════════

0.1 + 0.2            // 0.30000000000000004
0.1 + 0.2 === 0.3    // false   ← 二进制无法精确表示 0.1 与 0.2
(0.1 + 0.2).toFixed(2)  // '0.30' ← 显示时再按两位小数收敛

Number.MAX_SAFE_INTEGER      // 9007199254740991  ← 2^53 - 1
Number.MAX_SAFE_INTEGER + 1 === Number.MAX_SAFE_INTEGER + 2  // true ← 超出范围后两值相等
Number.isSafeInteger(2 ** 53 - 1)  // true
Number.isSafeInteger(2 ** 53)      // false

// ═══════════════════════════════════════════
// 2. 处理超范围整数的 BigInt
// ═══════════════════════════════════════════

typeof 1n            // 'bigint'
10n + 5n             // 15n
999999999999999999n  // 999999999999999999n ← 精确表示，不丢位
// 1n + 1            // 抛 TypeError：BigInt 不能与 number 混合运算

// ═══════════════════════════════════════════
// 3. NaN 与 Infinity
// ═══════════════════════════════════════════

typeof NaN           // 'number'
NaN === NaN          // false  ← 连自己都不相等
0 / 0                // NaN
Number('abc')        // NaN
1 / 0                // Infinity
-1 / 0               // -Infinity
Number.isFinite(Infinity)  // false
Number.isFinite(123)       // true

// ═══════════════════════════════════════════
// 4. 判断方法：绕开隐式转换
// ═══════════════════════════════════════════

isNaN('abc')             // true   ← 全局 isNaN 先转数字，不可靠
Number.isNaN('abc')      // false  ← 只在本身是 NaN 时为 true
Number.isNaN(NaN)        // true
Number.isInteger(2)      // true
Number.isInteger(2.0)    // true   ← 2.0 就是整数 2
Number.isInteger(2.5)    // false
Number.isFinite('1')     // false  ← 不转换参数

// ═══════════════════════════════════════════
// 5. 解析：parseInt / parseFloat / Number
// ═══════════════════════════════════════════

parseInt('12px')         // 12     ← 解析到非数字字符即停
parseInt('ff', 16)       // 255    ← 按十六进制解析
parseInt('')             // NaN
parseFloat('3.14abc')    // 3.14   ← 保留小数，遇到非数字停止
parseFloat('3.14.15')    // 3.14
Number('12px')           // NaN    ← 要求整串合法，因此失败
Number('12')             // 12
Number('')               // 0

// ═══════════════════════════════════════════
// 6. 数值格式化：只影响显示
// ═══════════════════════════════════════════

(1.2).toFixed(3)         // '1.200'   ← 不足补零，返回字符串
(1234.5).toFixed(1)      // '1234.5'
(123.456).toPrecision(4) // '123.5'   ← 按有效数字位数
(0.0001234).toPrecision(2)  // '0.00012'
(1234567).toLocaleString('en-US')  // '1,234,567'   ← 按地区加千分位
(1234.5).toLocaleString('zh-CN')   // '1,234.5'

// ═══════════════════════════════════════════
// 7. Math 常用方法
// ═══════════════════════════════════════════

Math.round(2.5)      // 3      ← .5 向正方向
Math.round(-2.5)     // -2
Math.trunc(-2.7)     // -2     ← 直接丢弃小数
Math.floor(-2.7)     // -3     ← 向下取整，负数时与 trunc 不同
Math.ceil(-2.3)      // -2
Math.max(1, 7, 3)    // 7
Math.min(1, 7, 3)    // 1
Math.abs(-5)         // 5
Math.pow(2, 10)      // 1024
2 ** 10              // 1024   ← 与 Math.pow 等价

// ═══════════════════════════════════════════
// 8. Date 的创建与时间戳
// ═══════════════════════════════════════════

const d = new Date(2026, 9, 14)  // 月份从 0 开始，9 表示 10 月
d.getFullYear()      // 2026
d.getMonth()         // 9      ← 返回值同样是 0-based
d.getDate()          // 14
d.getDay()           // 3      ← 星期三，0 表示周日
d.getTime()          // 该时刻的毫秒时间戳

new Date(0).getTime()                 // 0
new Date('1970-01-01T00:00:01.000Z').getTime()  // 1000
Date.now()                            // 当前毫秒时间戳
new Date(1000).toISOString()          // '1970-01-01T00:00:01.000Z'

// ═══════════════════════════════════════════
// 9. 日期坑与地区化格式化
// ═══════════════════════════════════════════

new Date('2026-10-14').toISOString()   // '2026-10-14T00:00:00.000Z' ← 按 UTC 解析
new Date('2026/10/14').getFullYear()   // 2026   ← 带斜杠的写法按本地时区解析

new Intl.DateTimeFormat('zh-CN', { dateStyle: 'long' })
  .format(new Date(2026, 9, 14))        // '2026年10月14日'
new Intl.DateTimeFormat('en-US', { dateStyle: 'long' })
  .format(new Date(2026, 9, 14))        // 'October 14, 2026'

  .format(new Date(2026, 9, 14, 9, 30)) // '09:30'
