DOM 事件传播与事件委托

用课程列表理解捕获、冒泡、target 与 currentTarget。

开场问题：给列表里 100 个按钮各绑一个点击事件，新增第 101 个按钮时它却毫无反应——为什么新来的节点总是不听使唤？

列表按钮事件绑定

你在做一个课程列表：每一行都有按钮，点击切换选中状态。最直觉的写法是遍历所有行，给每个按钮绑定一个监听器。一开始没问题，直到列表变得很长——几百个监听器常驻内存；更糟的是列表会动态增删，每插入一行你都得记得重新绑一次，一旦漏掉，那个新按钮就成了「哑巴」。

要解决它，得先回答一个问题：点击一个按钮时，这个事件到底经过了哪些元素？答案涉及 DOM 的事件传播机制。理解了它，你就能把「给每个子节点绑监听」换成「在父节点守株待兔」，一次性解决绑定数量和动态节点两个难题。

逐节点绑定监听

最直接的做法：遍历子节点，逐个 addEventListener('click', ...)，每个监听器只负责自己那一行。逻辑简单，谁被点谁响应，彼此独立。

这个方案做对了一件事：它把「监听」和「元素」一一对应，心智负担低。当列表很短、而且是静态的，这确实是最清楚的写法。

监听器数量开销

  • 监听器数量等于子节点数量，列表越长内存占用越高，绑定开销也越大。
  • 动态插入的新节点不会自动拥有事件，必须手动再绑一次，容易漏。
  • 删除节点时如果不解绑，还留着对已移除元素和闭包的引用，造成内存泄漏。
  • 同一套处理逻辑被重复绑定 N 次，代码里全是重复的事件注册。

父容器冒泡监听

换一个视角：既然点击子元素时，事件会经过它的祖先，那不如在稳定的父容器上监听一次，让冒泡把事件送到这里，再判断「到底点到了谁」。这就是事件委托。

要理解它为什么成立，得先看 DOM 的事件传播，它分三个阶段：

  1. 捕获阶段：事件从 window 一路向下，抵达目标元素之前先经过各级祖先。
  2. 目标阶段：事件到达真正被点击的那个元素。
  3. 冒泡阶段：事件从目标元素一路向上，回传给各级祖先。

平时 addEventListener 默认监听的是冒泡阶段，所以只要把监听器挂在父容器上，子元素被点击时事件就会冒泡上来触发它。关键在于两个属性的区别：event.target 是真正被点击的元素，event.currentTarget 是监听器所在的元素。少了这层区分，你就分不清用户点的是按钮还是按钮外面那层行。

认出目标后，用 event.target.closest(选择器) 从实际触发元素向上寻找最近的匹配项，再通过 dataset 读取 data-* 属性，就能定位到具体是哪一行、执行对应分支。于是监听器数量从 N 降到 1，而且对动态增删的子节点天然生效——因为监听器在父容器上，新节点一插进来就自动被覆盖，无需重新绑定。

还有一个容易忽略的选择：委托的容器要挑「稳定的祖先」。如果把监听器挂在本身也会被整体替换的元素上，它一旦消失，委托就跟着失效；挂在始终存在的列表外层，才扛得住子项反复增删。这才是「委托」二字真正的落点——把职责上提到一个不会轻易变动的位置。

两个坑：其一，closest 会一直向上查到 document，使用时要结合委托容器的范围判断，避免误匹配到容器外的同类元素；其二，点击容器自身的空白区域时，closest 可能命中容器本身或返回空，处理前要先确认目标是否落在预期的子元素范围内。

还有一个前提不能忘：不是所有事件都会冒泡。focus、blur、scroll 这类事件不参与冒泡，委托在冒泡阶段就收不到它们。这种情况下要么改用捕获阶段监听，要么换用会冒泡的替代事件（例如用 focusin 代替 focus）。

单监听器响应范围

事件委托收益代价

事件委托利用冒泡，把「给 N 个子节点各绑一个监听器」变成「在父节点挂一个」。它把监听器数量从 N 降到 1，并让动态新增的节点自动拥有交互能力——代价是你要靠 closest 和 target 亲手把真实目标认出来。

「事件委托」指利用事件的冒泡特性，在稳定的父容器上统一注册一个监听器，再通过 event.target.closest(选择器) 判断真实交互目标、用 dataset 读取 data- 属性执行分支。它与捕获、目标、冒泡三阶段相关，注意 target（实际触发元素）与 currentTarget（监听器所在元素）的区别，且 focus、blur、scroll 等事件不冒泡。

关键代码

JavaScript
// 事件委托：在父元素上统一处理子元素事件
document.querySelector('.course-list').addEventListener('click', (event) => {
  // closest 向上查找最近的匹配元素
  const button = event.target.closest('button[data-course]')
  if (!button) return

  // 通过 dataset 读取 data-* 属性
  console.log(`选择了：${button.dataset.course}`)
})

// 优势：
// - 动态添加的子元素自动生效，无需重新绑定
// - 减少事件监听器数量，降低内存占用
// - 统一管理，方便移除和调试
