属性描述符与对象控制

用 defineProperty 精确控制属性行为，用 freeze/seal 锁定对象。

开场问题：配置对象 const config = { maxStudents: 50 } 里，你从没写过 config.maxStudents = 0，可程序跑一阵子之后上限就变成了 0，页面再也招不进人——到底是谁在背后改了它，能不能把这个属性改成「谁都改不动」？

共享配置可变风险

你有一份共享配置：人数上限、价格、标题。它被传给了好几个模块，有表单在用它渲染输入框，有校验逻辑在用它判断，还有一段遗留代码顺手在运行时微调了一下。配置本该是「定下来就不动」的，可只要有人拿到这个对象的引用，一次赋值就能把它改掉，而且不会报错。你在出错的地方查了半天，根本想不到问题出在前面某个模块的随手一笔。

不用属性描述符这套能力，代价有三层：第一，共享的配置随时可能被悄悄改写；第二，你想让价格不能为负数、想让某个字段由别的字段算出来，都只能靠调用方自觉；第三，内部用到的字段明明只是实现细节，却会在遍历对象时被暴露出来，别人一个 Object.keys 就带走了。

const与团队约定

最容易想到的做法是用 const 声明这个配置，并在团队约定里写一句「不要修改它」。这确实是很多人第一时间会做的事。

这个方案对的地方在于方向没错——它试图把配置和可变状态区分开，用声明方式表达「这一份是常量」。但它对的地方也仅限于此，因为 const 管的事和你想的完全不是一回事。

常量声明约束范围

  • const 锁住的只是变量本身不再被重新赋值。它完全管不到对象的属性——config.maxStudents = 0 照样成功，而且不报任何错。
  • 对象属性默认可以新增、删除、修改。想让某个字段干脆读都读不出来，或者让对象不能再被加字段，用 const 做不到。
  • 想把价格限制成「不能为负」，只能靠每个赋值点自己 Math.max(0, v)，漏掉一处就破防。
  • 想让某个属性是「由另一个字段算出来的派生值」，就得手写两处同步代码，字段一多就必然不同步。

属性描述符配置

要真正控制一个属性，得先知道「属性」在 JavaScript 里并不是一个单纯的键值对，而是带着一张描述表的。每一个自有属性都有自己的属性描述符，可以逐项配置它是可写、可枚举、可配置的，也可以把它从「存一个值」改写成「读的时候现算」。

Object.defineProperty 就是精确设置这张描述表的方法。对数据属性，可以指定 value 这个值，以及三个开关：writable 决定值能否被改，enumerable 决定它会不会出现在 for...in、Object.keys 这类遍历里，configurable 决定这个属性本身能否被删除、能否再改描述符。把 writable 设为 false，就是给单个字段上了锁；把 enumerable 设为 false，就是把内部字段藏出遍历范围之外。

对存取属性，则是用 get 与 set 两个函数代替值：读属性时执行 get，写属性时执行 set。这正是「不能为负」和「派生字段」的正解——把校验和计算集中写在一个地方，任何读取和写入都必然经过它，调用方不再有漏网的机会。

set price(v) { this._price = Math.max(0, v) }

如果对整个对象动手，语言提供了三个逐级收紧的工具，限制程度依次加深：

方法能不能新增属性能不能删除属性能不能修改属性值
preventExtensions不能可以可以
seal不能不能可以
freeze不能不能不能

一句话记住它们的区别：preventExtensions 只挡新增，seal 再挡删除，freeze 连赋值一起挡。冻结之后想核对结果，可以用 Object.getOwnPropertyDescriptor 查看某个属性的 writable 是不是已经变成 false。

有三处最容易误判。其一，freeze 只冻结一层，对象里嵌套的子对象仍可修改，需要递归处理或改用结构化克隆；其二，遍历方法如 Object.keys、values、entries 只覆盖可枚举的自有属性，设成不可枚举的字段自然不在其中；其三，属性一旦设成 configurable: false，就再也无法删除或改回描述符配置，属于不可逆操作。还有一点：freeze 后赋值在非严格模式下是静默失败——代码不报错，值却没变，最容易让人误以为改成功了。

最后回到 get，还有一个性能上的取舍：getter 每次访问都会重新执行一遍计算，如果它背后是排序、过滤这类开销大的运算，就不适合直接写成 getter，而应该把结果缓存到普通字段里，需要时再更新。

冻结与只读对照

对象属性控制权

属性描述符与对象控制解决的，是「对象属性到底由谁说了算」的问题：defineProperty 让你逐项决定一个属性能不能写、能不能枚举、能不能删，甚至从「存值」变成「计算」；freeze 这一族则把这种控制放大到整个对象。它们把「配置不许改」从一句团队约定，变成了语言层面的硬约束。

「属性描述符」指描述一个自有属性行为的配置表：数据属性描述符含 value 与 writable / enumerable / configurable，存取属性描述符则用 get / set 现算取值、并在写入时校验，由 Object.defineProperty 精确设置，用 Object.getOwnPropertyDescriptor 读取。对象级别的收紧分三级：preventExtensions 禁止新增，seal 再禁止删除，freeze 连赋值也禁止；其中 freeze 只深冻一层，且 configurable: false 不可逆。

关键代码

JavaScript
// ========== Object.defineProperty ==========
const course = {}

// 数据描述符：直接定义值和行为
Object.defineProperty(course, 'name', {
  value: 'Vue3 进阶',
  writable: false,       // 不可修改
  enumerable: true,      // 可被枚举（for...in / Object.keys）
  configurable: false,   // 不可删除或重新定义
})

// 存取描述符：getter / setter
let _price = 299
Object.defineProperty(course, 'price', {
  get() { return `¥${_price}` },
  set(v) { _price = Math.max(0, v) },
  enumerable: true,
})

course.price = -50
console.log(course.price)  // '¥0'（setter 拦截了负数）

// ========== 对象锁定三兄弟 ==========
const config = { title: '课程', maxStudents: 50, active: true }

// Object.preventExtensions：禁止添加新属性
Object.preventExtensions(config)
config.newProp = 'test'
console.log(config.newProp)  // undefined

// Object.seal：禁止增删属性，现有属性变为不可配置
const sealed = Object.seal({ a: 1, b: 2 })
sealed.c = 3; delete sealed.a
console.log(Object.keys(sealed))  // ['a', 'b']

// Object.freeze：seal + 所有属性 writable: false
const frozen = Object.freeze({ x: 10, y: 20 })
frozen.x = 99
console.log(frozen.x)  // 10（静默失败，严格模式下报错）

// ========== 常用对象方法 ==========
const obj = { name: 'Vue', price: 299, students: 1200 }

console.log(Object.keys(obj))     // ['name', 'price', 'students']
console.log(Object.values(obj))   // ['Vue', 299, 1200]
console.log(Object.entries(obj))  // [['name','Vue'], ['price',299], ...]

// Object.fromEntries：entries 的逆操作
const map = new Map([['name', 'Node'], ['price', 199]])
console.log(Object.fromEntries(map))  // { name: 'Node', price: 199 }

// ========== 属性描述符获取 ==========
const desc = Object.getOwnPropertyDescriptor(course, 'name')
console.log(desc)  // { value: 'Vue3 进阶', writable: false, enumerable: true, configurable: false }
