ES Modules 模块化与动态导入

掌握静态 import/export、模块作用域与实时绑定，用 import() 按需加载拆分首屏。

开场问题：图表库只在「统计」标签页里用得到，首屏却把它一起下载了——首页白屏时间凭空多出几百毫秒。能不能让这份代码等到真正要用的时候再下载？

一个文件一个作用域

早先写页面时，脚本都堆在 <script> 标签里，谁都能往全局对象上挂变量。共享确实方便——函数之间随手就能互相调用；可代价也直接：两个文件里同名变量会互相覆盖，依赖关系只能靠标签的先后顺序隐式维系，一旦顺序错乱，页面就在某个不显眼的地方崩掉。

模块把这件事翻了过来。每个文件拥有自己独立的作用域，顶层声明的变量不再自动跑到全局对象上；需要给外界的东西，必须显式导出。顺带它还带来一个约束：模块脚本默认处于严格模式，顶层 this 是 undefined，给未声明的变量赋值会直接抛错，把过去那些「静默写坏全局」的隐患变成了立刻可见的错误。

导出与重命名

作用域独立之后，跨文件协作就得靠明确的进出口。模块提供两种导出：export 是具名导出，一个模块可以有多个，导入方用花括号按名字取；export default 是默认导出，通常一个模块只有一个，导入方不用花括号，名字可以自己起。

具名导出适合「一组相关的工具」，默认导出适合「一个主体的东西」——比如一个组件、一个类。两者可以共存：import Cart, { taxRate } from './cart.js'，花括号外的是默认导出，花括号里的是具名导出。

名字冲突时不必迁就，两边都能重命名：导入方写 { fetchCourses as loadCourses }，导出方写 export { inner as outer }。这样对外暴露的名字和内部实现的名字可以各自舒服，不必为了对齐而妥协。

导入是实时绑定

这里有个容易想当然的地方。按以前的经验，导入进来的东西像是「值的拷贝」——拷贝一份快照，之后对方再怎么变都与自己无关。ES Module 不是这样：导入得到的是对导出绑定的引用。

也就是说，模块内部把某个导出变量的值改了，导入方下次读到的就是最新值，而不是导入那一刻的旧值。这让「导入方总是看到最新状态」这件事自动成立，不需要额外的通知机制。

但这份绑定是只读的：导入方能看到值的变化，却不能给它重新赋值，一旦尝试 count = 10 就会抛错。要更新这份共享状态，唯一合法的方式是调用模块导出的函数，由模块自己内部去改——「谁来改」被牢牢收在定义它的文件里。

静态导入的价值

模块的导入写法有两个层次：一种是写在顶层的静态 import，另一种是运行时才执行的动态 import()。先说前者。

静态 import 的语句必须出现在模块顶层，且只接受字面量路径。这在语言层面是一条限制，却换来了构建器的便利：打包器无需运行代码，就能在构建期把整个依赖图算清楚。它能据此判定哪些导出被用到了、哪些没有——没被引用的导出可以在打包时整段摇掉，这就是 Tree Shaking。对于体积敏感的库，摇掉的那点代码往往就是首屏省下的那几毫秒。

动态导入与顶层 await

可 Tree Shaking 解决的是「没用的代码」，开场那个图表库却是「有用的代码，只是暂时用不到」。这类场景需要另一种导入方式：import() 是一个返回 Promise 的函数，兑现值是模块的命名空间对象。它不必写在顶层，可以放在任意函数里，真正需要时再执行。

对打包器而言，import() 是一处天然的代码分割点：被动态导入的模块会被单独拆成一个 chunk，首屏不下载，等到执行到那一行才拉取。这也是路由懒加载的标准手段——每个路由页面动态导入，访问到哪条路由才加载哪一段代码。

模块顶层还独有一套能力：顶层 await。在模块最外层可以直接 await 一个 Promise，模块会等到它兑现后才算初始化完成。这让「先读配置、再暴露接口」这类异步准备变得线性可读，而不必再包一层 init()。要注意它只在模块顶层可用，函数内部该用 async 还得用 async。

环形依赖与模块边界

模块之间可以互相导入，但若 a.js 导入 b.js、b.js 又反过来导入 a.js，就形成了环形依赖。这种结构在初始化阶段很危险：当 b.js 开始执行时，a.js 自己还没执行完，b.js 那一刻从 a.js 读到的绑定可能仍处于未初始化状态，取出来就是 undefined，而且往往不报错，只是行为诡异地失效。

要规避它，最稳的是把共享的部分抽成第三个小模块，让原本互相依赖的两方都去依赖它，环就断了。若确实绕不开，也应把跨模块的访问推迟到函数调用时，而不是在顶层初始化阶段就急着取值。

最后回到「模块和普通脚本到底差在哪」：普通脚本共享一个全局作用域、非严格模式、靠标签顺序维系依赖；模块各自独立作用域、默认严格模式、用导入导出显式声明依赖。搞清这条边界，模块化带来的那些约束与好处就都能对上号了。

「实时绑定」指导入方拿到的是对导出绑定的引用，而非值的拷贝：模块内更新导出值，导入方读到的就是最新值；但这份绑定只读，导入方不能重新赋值。它让跨模块的状态同步自动成立，也让「由谁修改」这件事被收在定义它的模块内部。

// ═══════════════════════════════════════════
// 1. 模块作用域与默认严格模式
// ═══════════════════════════════════════════

// 每个模块拥有独立作用域，顶层变量不会挂到全局对象上
// 经典脚本：var count = 0  →  window.count === 0
// 模块脚本：var count = 0  →  全局取不到这个 count

function readThis() { return this }        // 直接调用，this 为 undefined
readThis()                                 // undefined ← 严格模式生效

// 顶层 this 在模块里也不是全局对象
// 给未声明变量赋值会直接抛 ReferenceError，而不是静默写坏全局

// ═══════════════════════════════════════════
// 2. 具名导出与默认导出
// ═══════════════════════════════════════════

// // 导出方：具名导出可以有多个，默认导出通常只有一个
// export const taxRate = 0.06
// export function calcTotal(price) { return price * (1 + 0.06) }
// export default class Cart { /* 主体类 */ }

// // 导入方：花括号内取具名导出，花括号外是默认导出
// import Cart, { taxRate, calcTotal } from './cart.js'

// ═══════════════════════════════════════════
// 3. 重命名导出：两边都能改名
// ═══════════════════════════════════════════

// // 导入时重命名，避免与本地名字冲突
// import { fetchCourses as loadCourses } from './api.js'
// // 导出时重命名，对外名字与内部实现名解耦
// export { inner as outer }

// ═══════════════════════════════════════════
// 4. 导入是只读的实时绑定
// ═══════════════════════════════════════════

const state = { _n: 0 }
const counter = { get n() { return state._n } }   // 模拟模块的实时绑定
state._n = 5
counter.n                                  // 5   ← 读到的是最新值，不是快照
state._n = 9
counter.n                                  // 9   ← 绑定持续反映内部变化
// 该绑定只读：试图 counter.n = 1 会抛 TypeError，导入方不能重新赋值

// ═══════════════════════════════════════════
// 5. 静态导入便于依赖分析与 Tree Shaking
// ═══════════════════════════════════════════

// // 静态导入写在顶层，路径是字面量，打包器无需运行即可算出依赖图
// import { add } from './math.js'
// // math.js 里的 subtract 若无他处引用，打包时会被整段移除

// ═══════════════════════════════════════════
// 6. 动态 import() 返回 Promise
// ═══════════════════════════════════════════

typeof import('./charts.js')               // 'object'  ← 拿到的是 Promise
const charts = await import('./charts.js') // 兑现为模块命名空间对象
charts.default                             // 该模块的默认导出
typeof charts                              // 'object'
// 动态导入是天然的分割点，被导入的模块会拆成独立 chunk 按需拉取
// 路由懒加载就是每个页面动态导入：访问到哪条路由才加载哪段代码

// ═══════════════════════════════════════════
// 7. 顶层 await：仅模块顶层可用
// ═══════════════════════════════════════════

const me = await fetch('/api/me').then((r) => r.json())   // 模块顶层直接 await
me.name                                    // 有值  ← 模块会等它就绪后才算初始化完成
// 注意：函数内部仍要写 async 才能用 await，顶层 await 只在模块最外层生效

// ═══════════════════════════════════════════
// 8. 环形依赖的初始化陷阱
// ═══════════════════════════════════════════

// a.js 顶层 import b.js，b.js 顶层又 import a.js
// b.js 开始执行时 a.js 还没执行完，此刻从 a.js 读到的绑定尚未初始化
// 结果：拿到 undefined，且通常不报错，行为却诡异地失效

let ready = false
const readReady = () => ready        // 闭包读到的始终是绑定，而非快照
ready = true
readReady()                          // true  ← 推迟到调用时读，才拿到已初始化的值
// 规避环形依赖：把共享部分抽成第三个小模块，或把跨模块取值推迟到函数调用时
