字符串方法与国际化

用字符串方法搜索和转换文本，用 Intl 格式化日期和货币。

开场问题：搜索框里你用 indexOf 判断关键词有没有命中，日期用字符串拼成 2026-10-01——功能都能跑，可一到中文排序和不同地区的价格显示，就总有人报「显示得不对」。

搜索高亮与地区格式

你做一个课程搜索加详情页，要完成两件事：一是在课程标题里搜索关键词并高亮出来，二是把课程价格和开课日期按用户所在地的习惯显示。看上去都是「摆弄文本」的小事，背后却是两种性质完全不同的问题——怎么在同一套字符规则里精确地查找、替换、拼接，以及同一个日期和金额，怎么按不同地区的习惯呈现。

下标查找与截取

先用最熟的手段：str.indexOf(kw) !== -1 判断是否包含，str.substring(a, b) 截一段，str.replace(/x/g, 'y') 做全局替换，日期手动拼成年月日、月份用 padStart 补零。它做对了一件实事：不依赖任何额外的库，字符串自带的方法就能完成大部分操作。

包含判断语义

  • indexOf 返回的是下标，判断「包含」还得拿它和 -1 比较，语义绕着走，一不留神就把条件写反。
  • replace 只替换第一个匹配，除非正则带上 g 标志；而用正则匹配用户输入的关键词前，还得先转义里面的特殊字符，漏一步就出错。
  • 日期格式在 zh-CN 是「2026年10月1日」，在 en-US 是「October 1, 2026」，顺序和词表完全不同；货币、相对时间也一样。手拼等于自己维护一整套地区规则，早晚出错。
  • 排序时直接比较两个中文字符串的代码单元大小，得到的顺序不符合人们的认知习惯。
  • 还有一个容易忽略的坑：'👍'.length 是 2。字符串按 UTF-16 代码单元计数，不按人眼看到的字符计数，用下标或 charAt 取「第一个字符」会把一个 emoji 劈成半个。

字符串方法升级

先把「返回下标」升级成「直接回答布尔」：includes、startsWith、endsWith 一看就知道在问什么。需要拿到所有匹配而不只是第一个时，用 matchAll——它有一个硬性前提：正则必须带 g 标志，否则直接抛错；而且它返回的是迭代器而不是数组，要用 for...of 消费，或 Array.from 收成数组再用。

替换与截取也一并升级：replaceAll 一步替换全部出现，不必再和 g 标志较劲；slice 支持负下标（从末尾往前算），at 同时接受正负下标，读「最后一个」比手写 str[str.length - 1] 直观。这里有一个必须记住的前提：字符串是不可变的，上面每个方法都返回新字符串，原串纹丝不动——所以「替换了却没生效」，几乎总是忘了把返回值接住。

拆分与填充修剪属于同一族：split 按分隔符把字符串切成数组，是解析 CSV 式文本、拆关键词的常用手段；trim 系列负责去掉首尾空白，输入框里用户随手敲的空格就靠它兜底；padStart、padEnd 用来补足位数或对齐宽度。它们同样遵循「不改原串、返回新串」的规矩。

要按人眼看到的字符拆分（比如逐个处理 emoji），用 for...of 遍历或 Array.from(str)，它们按码点走，才会把 emoji 当成一个整体，而不是两个代码单元。

再往上走，把「自己维护地区规则」换成 Intl。同一笔金额：new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' }).format(129900) 得到 ¥129,900.00，换成 'en-US' 与 USD 就得到美元写法；同一个日期交给 new Intl.DateTimeFormat('zh-CN', { dateStyle: 'full' })，直接给出本地化的长格式，样式名还提供 short、medium、full 供你按需选择。你只声明 locale 和意图，规则与数据由运行时内置。

最后补上两个「不想自己拼」的场景：Intl.Collator 提供符合语言习惯的字符串比较器，用它排中文，胜过直接按代码单元大小比较的默认顺序；Intl.RelativeTimeFormat 直接输出「3 天前」「in 2 hours」这类相对时间文案。它们与前面两个格式化器共享同一个思路——地区规则不该由业务代码维护，交给运行时更准、更稳。

Intl与字符串方法

字符串方法与 Intl 解决的是同一类问题的两端：「在同一套字符规则里精确地查找与修改」交给字符串方法和正则，「按地区习惯呈现」交给 Intl。前者要记住字符串不可变、replace 的全局语义、以及 emoji 的代码单元陷阱；后者意味着本地化词表不该由你维护，声明 locale 就够了。

「Intl 国际化 API」是 JavaScript 内置的地区感知格式化工具集，提供 NumberFormat（数字、货币）、DateTimeFormat（日期时间）、RelativeTimeFormat（「3 天前」）与 Collator（符合语言习惯的排序）等能力，规则与数据由运行时携带，只需指定 locale。字符串是不可变的，所有字符串方法（includes、matchAll、replaceAll、slice、at、split）都返回新字符串而不改动原串；其中 matchAll 要求正则带 g 标志且返回迭代器。

关键代码

JavaScript
// ========== 字符串查询方法 ==========
const title = 'Vue3 组合式 API 实战指南'

console.log(title.includes('API'))       // true
console.log(title.startsWith('Vue3'))    // true
console.log(title.endsWith('指南'))      // true
console.log(title.indexOf('组合式'))     // 5

// ========== 截取与分割 ==========
console.log(title.slice(0, 4))           // 'Vue3'
console.log(title.substring(5, 8))       // '组合式'
console.log('a,b,c,d'.split(','))        // ['a', 'b', 'c', 'd']
console.log(['Vue', 'Node'].join(' + ')) // 'Vue + Node'

// ========== matchAll：获取所有匹配 ==========
const text = '课程价格 ¥199，优惠 ¥50，实付 ¥149'
const prices = [...text.matchAll(/¥(\d+)/g)]
console.log(prices.map((m) => m[1]))  // ['199', '50', '149']

// ========== replaceAll ==========
const raw = 'vue是好的，vue很灵活，学习vue吧'
console.log(raw.replaceAll('vue', 'Vue3'))

// ========== 填充与修剪 ==========
console.log('42'.padStart(5, '0'))     // '00042'
console.log('hi'.padEnd(8, '.'))       // 'hi......'
console.log('  hello  '.trimStart())   // 'hello  '
console.log('  hello  '.trimEnd())     // '  hello'

// ========== Intl.DateTimeFormat ==========
const now = new Date()
console.log(new Intl.DateTimeFormat('zh-CN', { dateStyle: 'full' }).format(now))
// 2025年9月15日星期一
console.log(new Intl.DateTimeFormat('en-US', { dateStyle: 'medium' }).format(now))
// Sep 15, 2025

// ========== Intl.NumberFormat ==========
console.log(new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' }).format(1299))
// ¥1,299.00
console.log(new Intl.NumberFormat('de-DE').format(1234567.89))
// 1.234.567,89

// ========== Intl.Collator：中文排序 ==========
const names = ['张三', '李四', '王五', '阿明']
const collator = new Intl.Collator('zh-CN', { sensitivity: 'base' })
console.log(names.sort(collator.compare))

// ========== Intl.RelativeTimeFormat ==========
const rtf = new Intl.RelativeTimeFormat('zh-CN', { numeric: 'auto' })
console.log(rtf.format(-1, 'day'))   // '昨天'
console.log(rtf.format(3, 'hour'))   // '3小时后'
