字符串、模板字面量与国际化

用字符串方法搜索与转换文本，用模板字面量与标签模板组织插值，用 Intl 格式化输出。

开场问题：订单提示想显示「共 3 件，合计 ¥29」，代码写成 '共 ' + 3 + ' 件，合计 ¥' + 29 是正常的；可某天数量来自输入框，用户填了「3」，同样的表达式却拼出了「共3 件」，看上去没差，一旦参与比较又变回字符串，价格判断就全乱了。

用加号拼接字符串

最开始的办法很直接：要显示一句带变量的文案，就用 + 把固定文字和变量串起来，写成 '共 ' + count + ' 件，合计 ¥' + total。它做对了一件事——任何位置都能插变量，而且这是最早的、不需要任何额外语法的手段。

但两个问题很快冒出来。一是每个变量都得手动补空格和引号，句子一长就是一堆加号，读起来像括号配平题；二是 + 在遇到字符串时会把数字悄悄转成文本，3 + 4 是 7，而 '共' + 3 是 '共3'，同一个运算符，两种含义。

字符串不可变，方法返回新串

动手改字符串之前，先接受一个事实：字符串是不可变的。写下 const s = 'abc' 之后，没有任何方法能改动 s 本身，它们一律返回一个新串。所以 s.toUpperCase() 得到 'ABC'，而 s 里躺着的仍然是 'abc'。

这一点解释了那句常见的困惑——「我明明调了大写方法，怎么值没变？」答案是：返回值没有被接住。s.toUpperCase() 的结果要赋给变量或直接用，才会体现出来。把这个认知固定下来，后面所有字符串方法都只是「读一个旧串，产出一个新串」。

搜索、截取、替换与填充

有了「只读不改」的前提，日常操作就分成几类。搜索用 includes 判断是否包含，用 startsWith / endsWith 判断前后缀；截取用 slice(起, 止)，参数支持负数，'abcdef'.slice(-3) 得到尾部三个字符；取值用 at(i)，它支持负索引，'abc'.at(-1) 比 s[s.length - 1] 更直观，也避免下标算错。

替换与拆分是一对好搭档：replace 只替换第一个匹配，replaceAll 替换全部，传字符串参数时它按字面量替换，不会把内容当成正则；split 按分隔符把串拆成数组，split('') 或 [...str] 都能得到字符数组。修剪与填充则负责边界：trim 去掉两端空白（trimStart、trimEnd 只管一头），padStart(6, '0') 在左侧补零，正好把编号格式化成 '000123'。

模板字面量的插值与多行

拼接的可读性问题是真实存在的，于是语言给出了模板字面量：用反引号包裹，变量位置写 ${表达式}，换行直接敲回车即可，不必再写 \n。它把「一串文本」和「一个值」区分得很清楚，加号链条里那层犹豫也随之消失。

不过模板字面量只是让拼接好看，并没有解决「数据里混进结构」的风险——把一个用户昵称插进 HTML 时，昵称里若带 <script> 标签，照样会被当标签解析。

标签模板：还原片段与插值

解决办法是在模板前面写一个函数名，让它来接管这次拼接，这就是标签模板。写法如 html`...`，被调用的函数收到的不是拼好的字符串，而是两部分：一个由字符串片段组成的数组，以及一个按顺序排列的插值数组。函数自己决定插值怎样并入——把 <、>、& 转成实体，注入就变成了纯文本。

内置的 String.raw 就是一个标签，它取的是原始串，不解析 \n、\t 这类转义，写正则或 Windows 路径时很好用。把「片段」与「插值」拆开，正是标签模板既能做转义、又能做多语言的关键。

亲手体验模板与格式化

下面两个演示把这一章落到真实场景：一个用标签模板做中英文文本切换，用 String.raw 展示转义保留；另一个用字符串方法搜索并高亮课程，再用 Intl 输出货币和日期。

地区化输出与全文收束

最后一块是格式化。Intl 是一组按地区输出格式的构造器：Intl.NumberFormat 把数字格式化成货币或百分比，同一个 1299.5 在 zh-CN 与 en-US 下的货币符号、分组方式和小数点都可能不同；Intl.DateTimeFormat 按地区输出日期；Intl.RelativeTimeFormat 给出「1 天前」这类相对时间；Intl.Collator 提供正确的字符串排序，让中文按拼音而不是码点排。结论很清楚：不要自己拼格式串，不同 locale 的写法交给 Intl。

回头看整章：字符串始终不可变，所有方法都在返回新串；模板字面量把拼接从 + 换成 ${}；标签模板则进一步把片段与插值拆开，既支持转义又支持多语言；而货币、日期、排序的地区差异，统一交给 Intl。

「标签模板」指在模板字面量前加一个函数名来调用它，如 tag`文本 ${值}`。该函数接收字符串片段数组与插值数组两份参数，可自行决定插值如何并入，从而实现 HTML 转义、i18n 或 DSL；String.raw 就是一种内置标签模板，用于获取不解析转义字符的原始串。

function tag(strings, ...values) {
  return strings.map((part, i) => part + (values[i] ?? '')).join('')
}
tag`共 ${3} 件，合计 ¥${29}`         // '共 3 件，合计 ¥29'

String.raw`a\nb`                     // 'a\\nb'  ← 反斜杠 n 原样保留，不换行
'\n' === String.raw`\n`              // false    ← 普通模板把 \n 解析成换行

// ═══════════════════════════════════════════
// 7. 用标签模板做 HTML 转义
// ═══════════════════════════════════════════

function escapeHtml(strings, ...values) {
  const safe = values.map((v) => String(v)
    .replaceAll('&', '&amp;')
    .replaceAll('<', '&lt;')
    .replaceAll('>', '&gt;'))
  return strings.reduce((out, part, i) => out + part + (safe[i] ?? ''), '')
}
const userInput = '<img src=x onerror=alert(1)>'
escapeHtml`<p>${userInput}</p>`      // '<p>&lt;img src=x onerror=alert(1)&gt;</p>'
