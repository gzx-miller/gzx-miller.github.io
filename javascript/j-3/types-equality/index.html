数据类型、转换与相等判断

掌握 7 种原始类型与引用类型的 typeof 行为、显式转换、隐式转换规则，以及 == 与 === 的经典差异。

开场问题：订单校验里写了 if (count == 0) return '请填写数量'，用户明明要买 0 件，这句提示照样弹出来；换一个用户什么都没填，同一句提示又弹了一次——两次都是「0」，但两次的来路完全不同。

同一个变量的两种身份

你想做的是一件小事：判断两个值是不是「一样」。在编译型语言里这几乎不用想——类型不同，编译器根本不让你比。可 JavaScript 里同一个变量今天装字符串、明天装对象，比较两个「长得像」的值时，语言必须自己拿主意：是先转成同一类型再比，还是类型不同就直接判不等？

它给出的两个答案就是 == 和 ===。=== 先看类型，类型不同立刻返回 false；== 先按一套规则把两边转成同一类型，再比数值。麻烦全在「转成同一类型」这一步——它不随机，但足够反直觉，反直觉到会悄悄吃掉你的业务判断。

宽松相等的隐式转换

最省事的做法：干脆统一用 ==，反正它「聪明」，会自动把字符串和数字对齐。于是 '0' == 0 得到 true，输入框里那个空字符串也就能冒充数字 0 混过校验。

这个方案确实做对了一件事：比较必须能跨越类型边界完成。否则用户从输入框拿到的永远只是字符串，业务代码里到处是 Number() 噪音。问题在于，把「转换」藏进比较运算符，等于把一步显式的数据处理偷偷塞进了判断表达式——你眼里看到的是「相等」，运行时发生的却是「先转换、再相等」。

藏在判断里的转换

  • '0' == 0 为 true，'' == 0 也为 true——空字符串被当成 0，校验直接失效。
  • null == undefined 为 true，而这两个值与别的任何值比较都是 false，是一对只跟彼此相等的特例。
  • [] == '' 为 true，空数组经 toString() 变成空字符串，两边就「相等」了。
  • NaN == NaN 为 false，一个值连自己都不等于，用相等判断识别 NaN 天然做不到。
  • 0 === -0 为 true，可这两者当除数会得到完全相反的结果，严格相等在这里又不够严格。

把转换与比较拆开

不推翻「比较」，而是把「转换」和「比较」拆成两步：转换显式做，比较一律用严格相等。需要数字就在输入边界调用 Number()，需要字符串调用 String()，需要布尔调用 Boolean()；判断里只留 === 与 !==。这样一来，「相等」在代码里就是字面意思。

再补上类型识别。运行时要看值的类型用 typeof，但记住两个例外：

  • typeof null 返回 'object'，这是语言早期实现的遗留问题，判断 null 请直接写 x === null。
  • 除函数外，所有引用类型的 typeof 都是 'object'，数组要用 Array.isArray() 单独判断。

还有两个边界要单独处理。一是 NaN：全局 isNaN() 会先把参数转成数字再判断，传字符串也可能为真，所以要用 Number.isNaN()。二是 +0 与 -0：业务若需要区分它们，用 Object.is()——它认为 NaN 与自身相等，同时能区分正负零。

最后一个常被忽略的事实：falsy 值的清单是固定且很短的——false、0、-0、0n、''、null、undefined、NaN，就这八个。除此之外全是 truthy——空数组 [] 和空对象 {} 都是 truthy，所以用「非空判断」给数组和对象兜底时，真正该看的是 length 或 Object.keys()，而不是真假值。

反常相等逐条验证

稳定判断的三条原则

类型与相等这两件事，本质上是把「隐式转换」从表达式里请出来，放到你能看见的地方。判断一律用 ===，转换在输入边界显式完成，类型识别绕开 typeof null、数组和 NaN 这三个坑——反直觉的 bug 就少了一大半。

「严格相等」指 ===，要求类型与值同时一致，不做任何隐式转换；与之相对的 == 会先转换再比较。判断 null 用 x === null，判断数组用 Array.isArray()，判断 NaN 用 Number.isNaN()，需要区分 +0 与 -0 时用 Object.is()。

JavaScript
// ═══════════════════════════════════════════
// 1. 七种原始类型与 typeof
// ═══════════════════════════════════════════

typeof 'hello'     // 'string'
typeof 42          // 'number'
typeof true        // 'boolean'
typeof undefined   // 'undefined'
typeof null        // 'object'   ← 历史遗留问题，判断 null 请用 x === null
typeof Symbol()    // 'symbol'
typeof 1n          // 'bigint'

// ═══════════════════════════════════════════
// 2. 引用类型与 typeof 的例外
// ═══════════════════════════════════════════

typeof {}            // 'object'
typeof []            // 'object'   ← 数组要用 Array.isArray() 判断
typeof (() => {})    // 'function' ← 唯一返回 function 的类型
Array.isArray([])    // true
Array.isArray({})    // false

// ═══════════════════════════════════════════
// 3. 显式转换：在输入边界调用
// ═══════════════════════════════════════════

Number('42')       // 42
Number('')         // 0
Number('abc')      // NaN
Number(true)       // 1
Number(null)       // 0
Number(undefined)  // NaN

String(42)         // '42'
String(null)       // 'null'
String(undefined)  // 'undefined'

Boolean('')        // false
Boolean(0)         // false
Boolean([])        // true   ← 空数组是 truthy
Boolean({})        // true   ← 空对象是 truthy

// ═══════════════════════════════════════════
// 4. 隐式转换：运算符里的转换规则
// ═══════════════════════════════════════════

'5' + 3      // '53'   ← + 只要有一侧是字符串就拼接
+'5' + 3     // 8      ← 前缀 + 强制转数字
'5' - 3      // 2      ← -、*、/ 两侧都转数字
'5' * '2'    // 10

// ═══════════════════════════════════════════
// 5. == 与 === 的差异
// ═══════════════════════════════════════════

'0' == 0           // true   ← '0' 转成 0
'' == 0            // true   ← '' 转成 0
null == undefined  // true   ← 规范规定的特例
null == 0          // false  ← null 只与 undefined 宽松相等
Array() == ''      // true   ← [] 经 toString 变成 ''
Array() == false   // true   ← 两边都转成 0

'0' === 0          // false
'' === 0           // false
null === undefined // false

// ═══════════════════════════════════════════
// 6. 三个必须绕开的边界
// ═══════════════════════════════════════════

NaN === NaN          // false  ← NaN 不等于任何值，包括自身
isNaN('abc')         // true   ← 全局 isNaN 会先转数字，不可靠
Number.isNaN(NaN)    // true   ← 正确写法
Number.isNaN('abc')  // false  ← 不转换，只判断是否真的是 NaN

Object.is(NaN, NaN)  // true   ← 同值相等
Object.is(-0, +0)    // false  ← 严格相等区分不了正负零

// ═══════════════════════════════════════════
