集合：Map/Set/WeakMap 与迭代协议

用 Set 去重、Map 关联数据、WeakMap 绑定元数据，并从迭代协议理解 for...of 与生成器。

开场问题：想用对象给「标签」做计数，写下 counts[tag] = 0；某天 tag 是两个内容相同的对象，结果两次赋值只留下一条记录——对象键被悄悄转成了同一个 '[object Object]'，计数从此对不上号。

用对象当字典

需要「键指向值」时，第一反应通常是拿对象当字典：const counts = {}，然后 counts[key] = n。它确实顺手——字面量写法、能直接交给 JSON、取值也直观，简单的字符串键场景完全够用。

问题出在键的规则上。对象的键只能是字符串或 Symbol：数字键会被转成字符串，对象键会被转成 '[object Object]'，于是不同的对象写进去只会互相覆盖；键的遍历顺序对整数键也有特殊排序，未必是你插入的次序。这些限制，正是 Map 和 Set 要补上的口子。

Map 与 Set 补齐的语义

Map 允许任意类型做键，对象、函数、甚至 NaN 都能原样保留，并且按插入顺序遍历；size 直接给出条目数，has / get / delete 是一套完整的接口。注意对象键比较的是引用，只有同一个对象才能命中，这恰好解决了上面「两个对象撞成一个键」的问题。

Set 则是「值的集合」，它保证值唯一，重复添加会被忽略，判断归属用 has，展开成数组写 [...set]。它同样按 SameValueZero 比较，所以 NaN 只会存一个。列表去重、标签多选、已读标记这类场景，用它比用数组省心得多。

弱引用：WeakMap 与 WeakSet

Map 和 Set 会持有键的强引用：只要这个 Map 还活着，进去的键对象就永远不会被回收。如果拿它给 DOM 节点挂元数据，节点从页面上移除后仍被 Map 锁住，内存就漏了。

WeakMap 与 WeakSet 的键是弱引用：当键没有其他强引用时，会被垃圾回收，对应的条目自动消失，不会阻止回收。代价是键必须是对象，且集合不可枚举、没有 size，所以它们只适合「给对象挂一份私有元数据」，而不是用来做遍历或统计。典型用法就是给 DOM 元素或组件实例关联内部状态。

可迭代协议

那 for...of 为什么能同时遍历数组、字符串、Map、Set？因为它们都实现了可迭代协议：在 Symbol.iterator 这个符号属性上提供一个方法，调用它返回一个迭代器；迭代器上再有一个 next()，每调用一次返回一个对象 { value, done }，done 为 true 表示取完了。

这套约定的价值在于「统一」：for...of、展开运算符 ...、数组解构、Array.from 全都依赖它。也就是说，任何对象只要自己实现了 [Symbol.iterator]，就能被这些语法一视同仁地消费，不需要为每种语法单独适配。

生成器与惰性序列

手写迭代器得自己维护「当前到哪了」的状态，很容易写乱。生成器函数 function* 把这件事接管了：函数体里写一个 yield 就暂停一次，调用方每 next() 一下才恢复执行到下一个 yield；next(value) 还能把值回传给上一个 yield 表达式，形成双向通信。yield* 则把当前生成器的产出委托给另一个可迭代对象，逐个转发。

好处是惰性：序列不必一次性全部生成，可以按需产出——无限序列、逐行读大文件、分页拉取都能用流式方式表达，用到多少算多少。下面两个演示分别展示 Set/Map/WeakMap 与生成器逐次产出。

迭代协议的价值

迭代协议把「逐个取值」与「何时结束」抽象成统一接口，于是一套消费语法能覆盖数组、字符串、Map、Set、生成器乃至自定义对象；Map/Set/WeakMap 则补齐了对象和数组缺失的语义。选择的依据很清楚：要任意类型键、稳定顺序、快速归属判断，用 Map；要去重与集合运算，用 Set；要挂私有元数据又不妨碍回收，用 WeakMap/WeakSet。

「迭代协议」指对象在 [Symbol.iterator] 上提供方法、返回带 next() 的迭代器，且 next() 每次返回 { value, done } 的约定。for...of、展开运算符、解构、Array.from 都依赖它；生成器函数用 function* 与 yield 自动实现这套协议。

关键代码

JavaScript
// ═══════════════════════════════════════════
// 1. Map：任意类型键与插入顺序
// ═══════════════════════════════════════════

const map = new Map()
map.set('a', 1)
map.set(2, 'two')          // 数字键不会被字符串化
const objKey = {}
map.set(objKey, 'object-key')   // 对象也能当键
map.get(2)                 // 'two'
map.get('2')               // undefined  ← 数字键 2 与字符串键 '2' 不同
map.get(objKey)            // 'object-key' ← 同一引用才命中
map.size                   // 3
map.has('a')               // true
map.has('missing')         // false
const mapKeys = [...map.keys()]   // ['a', 2, objKey] ← 保持插入顺序

// ═══════════════════════════════════════════
// 2. Set：保证值唯一
// ═══════════════════════════════════════════

const tags = new Set(['Vue', 'Vue', 'React'])
tags.size                  // 2   ← 重复值被忽略
tags.has('Vue')            // true
const tagList = [...tags]  // ['Vue', 'React'] ← 保持插入顺序
const deduped = [...new Set([1, 2, 2, 3, 3])]   // [1, 2, 3] ← 数组去重的常用写法
new Set([NaN, NaN]).size   // 1   ← SameValueZero，NaN 也只留一个

// ═══════════════════════════════════════════
// 3. WeakMap：给对象挂私有元数据
// ═══════════════════════════════════════════

const meta = new WeakMap()
const node = {}            // 这里代表一个 DOM 节点或组件实例
meta.set(node, { clicks: 0 })
meta.get(node)             // { clicks: 0 }
meta.has(node)             // true
const found = meta.get(node)
found.clicks += 1
meta.get(node).clicks      // 1
// WeakMap 没有 size，也无法遍历 keys/values/entries
// 当 node 失去其他强引用后会被回收，对应条目自动消失，不阻止 GC

// ═══════════════════════════════════════════
// 4. 可迭代协议：Symbol.iterator 与 next()
// ═══════════════════════════════════════════

function makeRange(from, to) {
  let current = from
  return {
    [Symbol.iterator]() {
      return {
        next() {
          return current <= to
            ? { value: current++, done: false }
            : { value: undefined, done: true }
        },
      }
    },
  }
}
const rangeIterator = makeRange(1, 3)[Symbol.iterator]()
rangeIterator.next()       // { value: 1, done: false }
rangeIterator.next()       // { value: 2, done: false }
rangeIterator.next()       // { value: 3, done: false }
rangeIterator.next()       // { value: undefined, done: true }
const oneToThree = [...makeRange(1, 3)]   // [1, 2, 3] ← 展开语法消费迭代器
Array.from(makeRange(1, 3))               // [1, 2, 3]

// ═══════════════════════════════════════════
// 5. 生成器：yield 暂停与 next(value) 回传
// ═══════════════════════════════════════════

function* talk() {
  const received = yield 'first'   // next(值) 会回传给这里
  yield received
  yield 'last'
}
const gen = talk()
gen.next()                 // { value: 'first', done: false }
gen.next(99)               // { value: 99, done: false } ← 回传给 received
gen.next()                 // { value: 'last', done: false }
gen.next()                 // { value: undefined, done: true }

function* step(items) {
  for (const item of items) yield item
}
const stepped = [...step(['a', 'b'])]   // ['a', 'b'] ← 惰性逐个产出

// ═══════════════════════════════════════════
// 6. yield* 委托给其他可迭代对象
// ═══════════════════════════════════════════

function* inner() { yield 1; yield 2 }
function* outer() { yield 0; yield* inner(); yield 3 }
const delegated = [...outer()]   // [0, 1, 2, 3] ← yield* 转发 inner 的产出

// ═══════════════════════════════════════════
// 7. for...of / 展开 / 解构都依赖迭代协议
// ═══════════════════════════════════════════

const [firstChar] = 'abc'           // 'a'  ← 字符串解构
const [head, ...rest] = [1, 2, 3]   // head 为 1，rest 为 [2, 3]
const chars = [...'abc']            // ['a', 'b', 'c'] ← 展开字符串
Math.max(...[1, 7, 3])              // 7   ← 展开数组
const entries = new Map([['a', 1], ['b', 2]])
const entryList = [...entries]      // [['a', 1], ['b', 2]] ← Map 本身可迭代
const entryKeys = [...entries.keys()]   // ['a', 'b']
Object.fromEntries(entries)         // { a: 1, b: 2 }
