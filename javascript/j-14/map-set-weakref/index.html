Map、Set 与弱引用

用 Set 去重、Map 关联数据、WeakMap 绑定 DOM 元数据。

开场问题：用普通对象给每个 DOM 节点存一份元数据，页面上的节点早就移除了，为什么内存占用不降反升？

去重集合与元数据字典

你手头有两件事：一是收集「不能重复」的标签集合，二是建一本「字典」，用某个对象当键、把它的附加数据存起来——典型场景就是给每个 DOM 节点挂一份自己的元数据。用最常见的数组和普通对象就能先跑起来，但这里埋着两颗雷：语义不对和内存漏。

这两颗雷都不是「写错了代码」，而是「用了不匹配的工具」。容器的默认规则和你的真实意图不一致时，程序往往能跑，却在长期运行里慢慢出问题——数据被悄悄覆盖，或者内存一点点涨上去。

数组与对象存储

最省事的做法：标签用数组存，字典用普通对象 {} 当，键取节点的某个 id，值放数据。

它背后还藏着一个隐含假设：键是字符串。id 确实是字符串，所以拿对象当字典看起来毫无问题。可一旦你想直接用节点对象本身做键——比如节点根本没有稳定的 id——这个假设就会立刻崩塌。

这个方案做对了一件事：零学习成本、随手能写，数组能装、对象能查，小规模下确实够用。先用它把功能跑通、再回头换更合适的容器，这个顺序本身并没有错。真正的问题不在「能不能存」，而在它默认的规则和你想要的行为并不一致。

对象键字符串化

  • 对象键会被字符串化：一旦直接拿对象当键，它会被转成 "[object Object]"，所有对象键撞成同一个，互相覆盖。
  • 数组不会去重：同一个标签加两次，你得自己每次遍历检查一遍 has，麻烦且容易漏。
  • 内存泄漏：普通对象、数组对键是强引用。节点从页面移除后，字典仍拽着它，垃圾回收无法释放——元数据本该随节点一起消失。
  • 顺序与污染：普通对象的键顺序不保证，还会把原型链上的属性一起带进来。

Map键类型与保序

第一层，用 Map 和 Set 换掉对象和数组。Map 允许任意类型做键——包括对象、函数——用引用相等命中，不会像普通对象那样把键字符串化，因此不同对象不会互相覆盖；它还保持插入顺序，size 直接可读，需要按插入顺序遍历、或频繁增删键时，比普通对象更合适。Set 一句话保证值唯一，add 自动去重，省掉手写的 has 检查。

第二层，解决引用导致的泄漏。把字典换成 WeakMap：它的键是弱引用，当键没有其他强引用时，条目会随键一起被垃圾回收自动消失，不会阻止回收。这正是给 DOM 节点或实例挂临时元数据的正确姿势——节点被移除、无人引用后，元数据自然跟着走。WeakSet 同理。

代价是：WeakMap 与 WeakSet 不支持遍历，也没有 size，键不可枚举。它们只适合「顺着键找值」的临时关联，不能当需要枚举的字典用。

这里有个容易误解的细节：弱引用说的是「不会被字典单方面拽住」，而不是「立刻消失」。只要你的代码里还留着那个节点对象，它就依然是强引用，元数据也照常存在；只有当它再没有任何其他引用时，垃圾回收才会连同条目一起清走。所以用 WeakMap 存元数据是安全的——你拿得到的对象，数据就一定还在。

自动去重与任意键

弱引用与生命周期

Map 与 Set 提供的是对象、数组不具备的明确语义（任意键、保序、唯一）；弱引用集合解决的则是生命周期——让附加数据跟着被附加的对象一起消失。选型时先问自己一句：我要的到底是语义，还是生命周期？

「Map / Set / WeakMap」Map 允许任意类型作键并保持插入顺序，Set 保证值唯一；WeakMap / WeakSet 的键是弱引用，键被回收时条目自动消失、不阻止垃圾回收，适合关联临时元数据，但不支持遍历与 size。

JavaScript
// Map、Set 与弱引用

// ── Set：自动去重的集合 ──
const tags = new Set(['Vue', 'React', 'Vue', 'CSS'])
tags.add('Vue')       // 重复，不生效
tags.has('Vue')       // true
tags.delete('CSS')
console.log([...tags]) // ['Vue', 'React']

// 数组去重一行搞定
const dedup = [...new Set([1, 2, 2, 3, 3, 3])]  // [1, 2, 3]

// ── Map：任意类型做键 ──
const courseMap = new Map()
courseMap.set('Vue', 12)
courseMap.set('React', 8)
courseMap.get('Vue')       // 12
courseMap.has('Vue')       // true
courseMap.delete('React')
console.log(courseMap.size) // 1

// 对象做键（普通对象做不到）
const objKey = { id: 1 }
courseMap.set(objKey, '元数据')
courseMap.get(objKey) // '元数据'

// ── WeakMap：弱引用键，不阻止垃圾回收 ──
const cache = new WeakMap()
function getMetadata(element) {
  if (cache.has(element)) return cache.get(element)
  const data = { createdAt: Date.now() }
  cache.set(element, data)
  return data
}
// 当 DOM 元素被移除且没有其他强引用时，WeakMap 不会阻止其被回收

// ── WeakRef 与 FinalizationRegistry（概念） ──
const ref = new WeakRef({ name: '课程缓存' })
// ref.deref() — 如果对象未被回收则返回，否则 undefined

const registry = new FinalizationRegistry((label) => {
  console.log(`${label} 已被回收`)
})
