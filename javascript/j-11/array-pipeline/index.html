数组与不可变方法流水线

用 filter 筛选课程、toSorted 排序，组合成不改动原数组的数组转换流水线。

开场问题：课程列表新加了一个「按评分排序」的按钮，点一下列表确实排好了，可再点「恢复默认顺序」却回不去——因为排序那次调用把原数组自己改了，默认顺序在内存里根本没留下痕迹。

想到就去改数组

最初的直觉很自然：既然数据是数组，要改就直接在数组上改。push 往末尾加一件商品，pop 去掉最后一件，unshift 插到最前面，shift 摘掉最前面一件，中间位置要增删就交给 splice。这套方法把「改完」这件事做到了极致：调用一结束数组立刻是新状态，调用方甚至不必接收返回值。

它们也确实解决了问题——数据的维护不需要来回传递副本，改动就地落地，内存和心智都轻。麻烦只在数组被多方共享时才浮现。

就地修改埋下的坑

你想展示一次排序，调用 sort，原数组的顺序也一并没了；你想取前十条做分页，调用 splice，原始数据也跟着少了一段。更隐蔽的是：Vue、React 这类框架靠「引用有没有变」来判断数据是否更新，就地修改后引用原地不动，框架看不到变化，界面就不刷新。

  • 撤销历史、分页缓存、新旧对比都依赖「旧版本」，可旧版本已经被就地改没了。
  • 多个组件共享同一个数组时，一处修改会悄悄影响另一处的渲染结果。
  • 排序、截取这类纯展示需求，本不该反过来污染数据源。

既然「改」是问题所在，那就把「改」与「取值」拆开：需要判断时只读，需要新结果时产出一份新数组。

只读的检索方法

不是每个需求都要改数据。想回答「有没有、在哪、是否都满足」，有一套只读方法：includes 判断是否包含某个值，它用 SameValueZero 规则比较，因此能正确识别 NaN；find 返回第一个满足条件的元素；findIndex 返回它的下标；some 只要有一个命中就提前返回 true；every 只要有一个不满足就提前返回 false。它们一个字节都不会动原数组。

转换方法与不破坏的对应版本

真正做「加工」的是 map、filter、reduce：map 一对一映射，filter 按条件筛选，reduce 把整串折叠成一个值；flat 按深度拍平嵌套数组（默认只拍一层），flatMap 等于先 map 再 flat(1)，适合「一个元素展开成多个」的场景。这几个方法本就返回新数组，调用后原数组原封不动。

与前面的增删改一一对应，也有一套非破坏版本：splice 对应 toSpliced，下标赋值 arr[i] = x 对应 with(i, x)，sort 对应 toSorted，reverse 对应 toReversed。它们都返回新数组，把「改」翻译成「得到一份改过的拷贝」。

还有两个构造入口值得记住。Array.from 把类数组或可迭代对象转成真数组：类数组指有 length 与下标、却没有数组方法的对象，例如 arguments、DOM 的 NodeList、甚至字符串；它接受第二个参数直接做映射，写成 Array.from({ length: 5 }, (_, i) => i) 就能造出 [0, 1, 2, 3, 4]。稀疏数组则是另一回事——像 [1, , 3] 这种带空槽（hole）的数组，map、filter、forEach 会跳过空槽不执行回调，而 Array.from 会把空槽一律读成 undefined 补实。

把只读操作串成流水线

把只读检索、转换、非破坏排序按顺序串起来，就得到一条不可变流水线：每一步都基于上一步的返回值产生新数组，原数组全程没被碰过。下面这个「按关键词筛选 + 按评分排序」的演示，正是 filter 与 toSorted 的组合。

不可变流水线的价值

把操作写成链式流水线后，几个问题一起解决了：原数组始终是可信的基准，随时能「恢复默认」或重新筛一遍；框架通过引用比较就能察觉每一步的新结果，界面随之更新；每一环单独取出都能验证，调试不必在脑中模拟整段就地修改。至于写日志、发请求、改 DOM 这类副作用，交给 forEach——它遍历数组执行回调，但不返回数组，因此不能链式，这正是「副作用」与「转换」在接口上的分界。

「不可变方法」指不修改原数组、而是返回新数组的方法，例如 map、filter、reduce、toSpliced、with、toSorted、toReversed；与之相对的是 push、splice、sort 这类就地修改的方法。把不可变方法串成链式流水线，就能在保留数据源的前提下完成筛选、映射与排序。

关键代码

JavaScript
// ═══════════════════════════════════════════
// 1. 就地增删改：会改掉原数组
// ═══════════════════════════════════════════

const cart = [10, 20, 30]
cart.push(40)        // 返回新长度 4，cart 变成 [10, 20, 30, 40]
cart.pop()           // 返回 40，cart 变回 [10, 20, 30]
cart.unshift(5)      // 返回 4，cart 变成 [5, 10, 20, 30]
cart.shift()         // 返回 5，cart 回到 [10, 20, 30]
cart.splice(1, 1)    // 返回删除的 [20]，cart 变成 [10, 30]

// ═══════════════════════════════════════════
// 2. 非破坏版本：原数组保持不变
// ═══════════════════════════════════════════

const base = [10, 20, 30]
base.toSpliced(1, 1)            // [10, 30]         ← base 仍是 [10, 20, 30]
base.with(0, 99)                // [99, 20, 30]     ← base 未变
base.toSorted((a, b) => b - a)  // [30, 20, 10]     ← base 顺序未变
base.toReversed()               // [30, 20, 10]     ← base 未变
const appended = [...base, 40]  // [10, 20, 30, 40] ← 展开复制后再追加

// ═══════════════════════════════════════════
// 3. sort 就地修改 vs toSorted 返回新数组
// ═══════════════════════════════════════════

const scores = [4.6, 4.9, 4.8]
const sortedInPlace = scores.sort((a, b) => b - a)  // 返回 [4.9, 4.8, 4.6]
scores                // [4.9, 4.8, 4.6]  ← sort 把原数组也改了

const fresh = [4.6, 4.9, 4.8]
const sortedCopy = fresh.toSorted((a, b) => b - a)   // 返回 [4.9, 4.8, 4.6]
fresh                 // [4.6, 4.9, 4.8]  ← toSorted 原数组不动

// ═══════════════════════════════════════════
// 4. 只读检索：不改数组，只回答问题
// ═══════════════════════════════════════════

const withNaN = [1, 2, NaN]
withNaN.includes(NaN)                      // true   ← SameValueZero 能识别 NaN
const objItems = [{ id: 2 }]
objItems.includes({ id: 2 })               // false  ← 引用不同，比较的是引用
const nums = [3, 7, 9]
nums.find((n) => n > 5)                    // 7      ← 返回第一个命中的元素
nums.findIndex((n) => n > 5)               // 1      ← 返回它的下标
nums.some((n) => n > 8)                    // true   ← 有一个满足即可，命中即停
nums.every((n) => n > 0)                   // true   ← 全部都满足才为 true
nums.every((n) => n > 5)                   // false  ← 有一个不满足即停

// ═══════════════════════════════════════════
// 5. 转换方法：返回新数组
// ═══════════════════════════════════════════

const seq = [1, 2, 3]
seq.map((n) => n * 2)                      // [2, 4, 6]
const toFilter = [1, 2, 3, 4]
toFilter.filter((n) => n % 2 === 0)        // [2, 4]
const toSum = [1, 2, 3]
toSum.reduce((sum, n) => sum + n, 0)       // 6
const nested = [1, [2, [3]]]
nested.flat()                              // [1, 2, [3]]  ← 默认只拍一层
nested.flat(2)                             // [1, 2, 3]    ← 指定深度拍到两层
const groups = ['a b', 'c']
groups.flatMap((s) => s.split(' '))        // ['a', 'b', 'c'] ← 先映射再拍平

// ═══════════════════════════════════════════
// 6. forEach 只做副作用，不参与转换
// ═══════════════════════════════════════════

const log = []
const sideEffects = [1, 2, 3]
sideEffects.forEach((n) => log.push(n * 10)) // 返回 undefined
log                                          // [10, 20, 30] ← 结果落在外部变量

// ═══════════════════════════════════════════
// 7. Array.from 与类数组、稀疏数组
// ═══════════════════════════════════════════

Array.from('abc')                              // ['a', 'b', 'c']
Array.from({ length: 3 })                      // [undefined, undefined, undefined]
Array.from({ length: 3 }, (_, i) => i + 1)     // [1, 2, 3]  ← 第二个参数做映射

const sparse = [1, , 3]
sparse.length                                  // 3   ← 中间有一个空槽
sparse.map((n) => n * 2)                       // [2, empty, 6] ← map 跳过空槽
sparse.forEach((n) => n)                       // 只执行 2 次，空槽被跳过
Array.from(sparse)                             // [1, undefined, 3] ← 空槽补成 undefined

// ═══════════════════════════════════════════
// 8. 流水线：每一步都基于新数组，原数组不动
// ═══════════════════════════════════════════

const courses = [
  { title: 'JavaScript 基础', score: 4.8 },
  { title: 'Node.js 服务', score: 4.6 },
  { title: 'Vue 组件设计', score: 4.9 },
]
const keyword = 's'
const picked = courses
  .filter((course) => course.title.includes(keyword))
  .toSorted((a, b) => b.score - a.score)
  .map((course) => `${course.title} · ${course.score}`)
picked          // ['Vue 组件设计 · 4.9', 'JavaScript 基础 · 4.8'] ← 按评分排序后的结果
courses.length  // 3   ← 原数组始终没被改动
