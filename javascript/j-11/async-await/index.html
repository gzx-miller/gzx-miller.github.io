async/await 与异步流控

用 async 函数和 await 表达串行与并发加载，掌握异步错误处理。

开场问题：三个接口用 then 链一拼，错误处理就散落在每一层——有没有一种写法，能让异步代码看起来和同步代码一样从上往下读？

回调嵌套困境

你已经会用 Promise 了，可一旦业务变复杂，then 的嵌套和链式调用就开始失控：取值要在回调里继续套回调，错误要在每一层或末尾单独兜，中间还想插一段清理逻辑。明明业务是「先拿课程、再拿进度、最后一起处理」，代码长出来的却是一层层的回调。

async/await 要解决的，正是这个「同步语义」与「异步执行」之间的落差。它让你用一行赋值、一段 try/catch，写出读起来像同步、跑起来是异步的代码。但代价是——你得同时掌握串行与并发两种节奏，否则很容易把本该并发的操作写成慢吞吞的串行。

async函数语法

最省事的做法：给函数加 async，在需要等结果的地方加 await，剩下的逻辑照常写。

这个方案做对了一件根本的事：它把 Promise 的「落定结果」直接变成了一行赋值。const data = await fetchData() 里，data 就是成功后的值，不用再钻进 then 里找。错误也回到了熟悉的 try/catch 轨道上。

但同样是两行 await，写法上只差一点，执行起来却差着一整段等待。const a = await loadA() 再 const b = await loadB()，是等完 A 才发出 B；而 const [a, b] = await Promise.all([loadA(), loadB()])，是两件事一起发出、一起等。这个差别，正是后面所有流控讨论的起点。

串行await退化

  • 把多个互不依赖的 await 顺序写下去，就悄悄退化成了串行，总耗时变成各步之和。
  • 在循环里逐个 await，同样是一步等完再等下一步，明明可以一起发。
  • 以为加了 async 的错误会被自动捕获——其实函数返回的 Promise 若无人处理，里面的异常会变成未处理的拒绝。
  • await 写多了，清理逻辑散落各处，出错时资源没释放。

依赖关系判断依据

先记住两条底层事实。第一，async 函数总是返回一个 Promise，函数里 return 的值会自动被包装成成功结果；第二，await 会暂停当前函数的执行，直到 Promise 落定，成功就取出值、失败就抛出异常。正因为会「暂停」，连续几个 await 才天然是串行的——这正是问题的来源。

于是流控的关键，是按依赖关系选择节奏：

  • 有依赖就串行：后一步要用前一步的结果，那就老老实实逐个 await，或者用 for ... of 依次等待。
  • 无依赖就并发：先把所有 Promise 发起、收进一个数组，再用 await Promise.all(...) 一起等。总耗时从「各步之和」降到「最慢一步」。
坑：在循环里直接写 await 会退化为串行。需要并发时，要先把每个任务发起成 Promise 收集起来，循环结束再 await Promise.all 统一等待，而不是在循环体内逐个等。

想知道自己写的是串行还是并发，最直接的办法是打时间戳：串行的总耗时约等于各步之和，并发的总耗时约等于最慢的那一步。把两种写法的耗时并排看一眼，远比凭感觉判断可靠——这也是排查「页面加载为什么慢」时最快能落地的动作。

接着把错误与清理收口。await 链上的任何一次拒绝，都会像同步异常一样在函数里抛出，所以用 try / catch / finally 把它们统一罩住：catch 处理失败，finally 执行清理（关掉 loading、释放资源），无论成败都会跑。这比在每一个 then 后面各写一份错误分支要集中得多。

另一个坑：给函数加了 async 并不代表调用方不用管错误。函数内部未捕获的异常会变成这个函数返回 Promise 的拒绝，若调用方既不 await 也不 catch，它就成了「未处理的拒绝」，在很多环境下只是安静地打印一句警告，很容易被忽略。

还有两个使用边界要记牢：await 只能出现在 async 函数内部，或者在 ES Module 的顶层使用；并且并发不等于无限并发，即使改用 Promise.all 一起发，也要留意接口限流与服务端承载能力，必要时控制并发数量。

并发与串行对照

执行节奏与并发控制

async/await 把异步流程写成了同步的样子：async 让函数返回 Promise，await 暂停并取出结果。真正决定性能的是节奏——有依赖就逐个 await 串行，无依赖就收集起来用 Promise.all 并发，再用 try / catch / finally 统一收口错误与清理。

「async / await」是基于 Promise 的异步语法糖：async 函数总是返回 Promise，await 暂停该函数直到 Promise 落定并取出结果或抛出异常。串行用 for ... of 逐个 await，并发用 Promise.all 同时发起再一起等待，配合 try / catch / finally 统一处理错误与清理。await 仅能在 async 函数内或 ES Module 顶层使用。

关键代码

JavaScript
// async/await：用同步写法处理异步流程

// 模拟异步请求
const fetch = (label, ms) =>
  new Promise((resolve) => setTimeout(() => resolve(label), ms))

// ── 串行：逐个等待，总耗时 = 各步之和 ──
async function loadSerial() {
  const steps = ['课程', '通知', '进度']
  for (const step of steps) {
    const result = await fetch(step, 200)
    console.log(`已加载：${result}`)
  }
}

// ── 并发：同时发起，总耗时 ≈ 最慢那个 ──
async function loadParallel() {
  const [courses, notices, progress] = await Promise.all([
    fetch('课程', 300),
    fetch('通知', 400),
    fetch('进度', 200),
  ])
  console.log(courses, notices, progress)
}

// ── 错误处理：try/catch/finally ──
async function safeLoad() {
  try {
    const data = await fetch('数据', 100)
    console.log(data)
  } catch (err) {
    console.error('加载失败：', err.message)
  } finally {
    console.log('加载结束（无论成败）')
  }
}
