网络请求与可中断操作

用 Fetch API 发起请求并检查 res.ok，配合 AbortController 取消过期请求与监听。

开场问题：课程搜索框每敲一个字就发一次请求，网速一慢，先发出去的「苹」反而后返回，把刚发出的「苹果」结果覆盖掉了——列表里显示的是上一个关键词的内容，用户只好反复删字重打。

一个请求的往返

你想做的是一件小事：向服务器要一份课程列表。最省事的做法是 await fetch(url)——把地址丢进去，等它兑现，拿到的就是结果。它确实做对了一件事：把「发请求」变成了一个可以直接 await 的动作，不用再包裹回调，也不用记 XMLHttpRequest 的一串状态码。

但要理解它到底返回了什么，得先看清两个对象。你传给 fetch 的是 URL，或一个装着 URL 与配置的 Request 对象；拿回来的是 Response 对象。await fetch(url) 兑现的时机是响应头到达时，不是响应体下载完时——所以此刻 Response.status 已经有了，res.ok 也已经确定，正文却还要等下一步去读。

把配置放进第二参

只给 URL，等于用最朴素的 GET 去拿资源。一旦要提交表单、带鉴权头或跨域带上 Cookie，这个做法就不够了——它没地方放这些信息。

于是 fetch 的第二个参数派上用场：一个配置对象，用 method 声明动词，用 headers 补上元信息，用 body 装请求体。body 必须是字符串或二进制，直接传对象会被悄悄转成 [object Object]，所以要先用 JSON.stringify() 转好，并在 headers 里写明 Content-Type。

还有一个常被忽略的开关是 credentials。它默认是 'same-origin'，同源请求自动带 Cookie；跨域时要显式写成 'include'，否则登录态根本传不过去，接口一律回 401。反过来，若接口不需要凭证，用 'omit' 更安全，能减少不必要的凭证暴露。

状态码不是异常

朴素做法是：把请求整个包进 try/catch，出问题就交给 catch。在别的地方这也许成立，但在 fetch 这里会失效——只要服务器回了一个响应，哪怕状态码是 404 或 500，这个 Promise 也是「兑现」，不是「拒绝」。

这其实是个合理的设计：4xx、5xx 只说明这次请求的业务结果，不代表网络层出了问题。可代价是，业务代码必须自己看一眼 res.ok。它的含义很单纯——status 落在 200 到 299 之间就是 true。真正的 catch 只用来接住断网、DNS 失败这类网络错误，以及主动取消。

所以稳妥的写法是：先 if (!res.ok) 抛出带状态码的错误，再往下解析正文。这样 404 与断网会走同一个错误出口，但错误信息里带着 res.status，排查时能分清到底属于哪一类。

响应体只能读一次

拿到 Response 后，正文要自己读。多数人直接 await res.json()，拿到解析好的对象。这里有个陷阱：响应体是一段一次性的流，只能被消费一次。

比如你想先打日志再解析，写了两次读取，第二次就会抛出 TypeError: body stream already read。解决办法是在第一次读取之前调用 res.clone()，保留一份副本，两份各自去读。

至于 json() 与 text() 的区别，前者把正文按 JSON 解析成对象，后者原样返回字符串；两者都返回 Promise，因为正文此刻可能还在传输，必须异步等待。内容不是合法 JSON 时用 json() 会直接抛错，所以按内容类型选对方法，或先用 text() 拿到原文再决定怎么解析。

让请求可被中断

回到开场那个问题：旧结果覆盖新结果，根子在于「请求一旦发出就收不回来」。之前的做法是等它自己回来，再靠一层判断忽略过时的结果——这留住了正确结果，却白白浪费带宽，用户还得等旧请求跑完。更合理的做法，是让请求本身可以被中断。

AbortController 就是干这个的。它身上有一个 signal 属性，把 { signal } 放进 fetch 的配置，就等于给这次请求插了一根「取消杆」。之后任何时候调用 controller.abort()，进行中的请求会立刻以拒绝结束，拒绝原因是一个名称为 AbortError 的异常。

超时中断就是它的一个现成用法：设一个定时器，到点调用 controller.abort()，请求就会被中断；请求成功返回后记得 clearTimeout() 把定时器撤掉。若不想用定时器，也可以用 Promise.race()，让请求与一个「定时拒绝」的 Promise 赛跑，谁先完成就以谁为准。

亲手请求与取消

区分取消与失败

中断带来一个新问题：catch 里怎么分清这次是「主动取消」还是「真的网络失败」？办法是看错误的 name——AbortError 表示主动取消，此时不该弹「网络异常」的提示，静默处理即可；其余错误才按真正的失败对待。

回到搜索联想，完整做法是：每次发请求前，先把上一次的 controller 调 abort() 取消，再为本次请求新建一个 AbortController。被取消的旧请求会走进 catch 的 AbortError 分支被安静丢掉，不会再有机会把旧结果写进列表。

不过要留意一点：abort() 不是瞬时生效的，已经返回、只差写入的那次旧结果仍可能到达。所以除了取消旧请求，通常还要用一个「请求序号」或「当前 controller 是否仍是最新」的判断兜底，双保险才能彻底避免旧的覆盖新的。

「AbortSignal」是 AbortController 派生的信号对象，把它通过 signal 传给 fetch 等 API，调用 controller.abort() 后关联操作会以 AbortError 拒绝。它把「取消」从一个善后判断，变成了请求自身的一种可中断能力。

关键代码

JavaScript
// ═══════════════════════════════════════════
// 1. fetch 基本用法与 Response 对象
// ═══════════════════════════════════════════

const res = await fetch('/api/courses')   // Promise 兑现为 Response
res instanceof Response                   // true
res.ok                                    // true   ← 状态码落在 200-299
res.status                                // 200
res.statusText                            // 'OK'   ← 响应头先到，正文还没读

// ═══════════════════════════════════════════
// 2. 请求配置：method / headers / body
// ═══════════════════════════════════════════

await fetch('/api/courses', {
  method: 'POST',                                    // 默认是 GET
  headers: { 'Content-Type': 'application/json' },   // 声明请求体类型
  body: JSON.stringify({ title: 'Vue 组件通信' }),   // 请求体必须是字符串
})

// ═══════════════════════════════════════════
// 3. credentials 决定凭证是否随请求携带
// ═══════════════════════════════════════════

await fetch('/api/me', { credentials: 'include' })   // 跨域时带上 Cookie
// 'same-origin'（默认，仅同源）/ 'include'（跨域也带）/ 'omit'（从不带）

// ═══════════════════════════════════════════
// 4. 状态码不会让 fetch 拒绝
// ═══════════════════════════════════════════

const notFound = await fetch('/api/not-found')
notFound.ok        // false
notFound.status    // 404  ← 404/500 依然走兑现分支，不会进 catch
// 只有断网、DNS 失败、主动取消才会让 Promise 拒绝

// ═══════════════════════════════════════════
// 5. 响应体只能读一次，二次读取先 clone
// ═══════════════════════════════════════════

const bodyRes = await fetch('/api/courses')
const copy = bodyRes.clone()         // 第一次读取之前先复制
const data = await bodyRes.json()    // 消费原始响应体
const raw = await copy.text()        // 另一份还能继续读
// 不加 clone 直接读两次会抛：TypeError: body stream already read

// ═══════════════════════════════════════════
// 6. json 与 text 都返回 Promise
// ═══════════════════════════════════════════

const asJson = res.json()            // Promise，兑现为解析后的对象
const asText = res.text()            // Promise，兑现为原始字符串
typeof asJson                        // 'object'  ← 拿到的是 Promise，不是结果
await asJson                         // { title: 'Vue 组件通信' }

// ═══════════════════════════════════════════
// 7. AbortController 与 AbortError
// ═══════════════════════════════════════════

const controller = new AbortController()
const signal = controller.signal
controller.abort()                                   // 触发取消
await fetch('/api/courses', { signal })              // 以异常拒绝
// 这次异常的 name === 'AbortError'，表示被主动取消

// ═══════════════════════════════════════════
// 8. 用定时器实现超时中断
// ═══════════════════════════════════════════

const timeoutController = new AbortController()
const timer = setTimeout(() => timeoutController.abort(), 3000)
try {
  await fetch('/api/slow', { signal: timeoutController.signal })
} catch (e) {
  e.name     // 'AbortError'  ← 超过 3 秒被中断
} finally {
  clearTimeout(timer)          // 成功返回后撤掉定时器
}

// ═══════════════════════════════════════════
// 9. 搜索联想：取消过期请求，避免旧结果覆盖新结果
// ═══════════════════════════════════════════

let searchController
async function search(keyword) {
  searchController?.abort()                            // 先取消上一次请求
  searchController = new AbortController()
  const r = await fetch(`/api/search?q=${keyword}`, {
    signal: searchController.signal,
  })
  return r.json()
}
// 旧请求被 abort 后走 catch 的 AbortError 分支，不会再写回列表
