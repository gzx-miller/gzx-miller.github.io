JSON 与结构化克隆

用 replacer/reviver 控制序列化，用 structuredClone 深拷贝。

开场问题：把课程数据 JSON.stringify 存进 localStorage，取出来时 JSON.parse 也没报错，可紧接着 course.date.getFullYear() 却提示「不是函数」——明明存进去的时候它还是一个 Date，读出来怎么就不是了？

存储往返损耗

你在给课程管理页做本地缓存：把课程对象转成字符串写进存储，下次打开再读回来。这套做法本身没错，直到数据里出现了三类麻烦：课程有开课日期 date，是 Date 实例；学生列表里某些字段是 undefined；对象里还随手加了一个指向自身的引用方便查找。这时的序列化往返，就不再是「转成字符串再转回来」这么简单了。

不用这两组能力，代价会具体地显现出来：日期经过一轮往返会变成纯字符串，所有依赖日期方法的地方集体失效；带循环引用的对象会让序列化直接抛错，整个导出功能挂掉；而更危险的是，原始对象里若有密码、令牌这类字段，它们会被一字不差地写进本地存储和日志里——你以为只是缓存，其实是把敏感数据摊开存放了。

序列化与反序列化

最直接的做法就是用内置的 JSON.stringify 和 JSON.parse：一个把对象转成 JSON 字符串，一个把字符串变回对象，一行写一个方向。

这个方案做对了一件根本的事：它给了数据一个与语言无关的、可存储可传输的纯文本形态。对于只含字符串、数字、布尔和数组嵌套的「纯数据」，这套往返是完全可靠、零信息损失的。要保留的正是这份「可持久化的文本表示」，问题在那些超出 JSON 表达能力的东西上。

类型信息丢失

  • Date 会被序列化成 ISO 格式的字符串，解析回来仍然只是字符串，类型信息在往返中永久丢失。
  • JSON 没有 undefined、函数和 Symbol 这几种值的表示，对象属性遇到它们会被直接跳过，而同样的值出现在数组里则会变成 null。
  • 对象一旦出现循环引用，序列化会直接抛出「Converting circular structure to JSON」，而不是跳过那条引用。
  • 序列化会无差别地导出所有可枚举字段，密码、令牌这类不该落盘的数据跟着一起被写进存储。

定制转换与白名单

先解决「导出时能不能筛选和改造」。JSON.stringify 其实接受第二个参数 replacer，它可以是函数，也可以是白名单数组：写成函数时，每个键值对都会经过你，你可以返回原值、返回一个新值来替换它，或者返回 undefined 把这条属性整个剔除；写成数组时，则只有列出的键会被导出。日常最常用的两件事——把 Date 转成便于阅读的日期字符串、把敏感字段过滤掉——都能在这里一次完成。

const json = JSON.stringify(course, (k, v) => k === 'token' ? undefined : v instanceof Date ? v.toISOString() : v, 2)

接着解决「解析时能不能还原类型」。JSON.parse 的第二个参数是 reviver，它会在每个值被还原后依次回调，你可以在这里根据值的形态把它重建回原本的类型，比如把形如 2025-10-15 的字符串重新变成 Date 实例。导出时用 replacer 降级，导入时用 reviver 还原，一次序列化往返就把类型闭环接上了。

最后解决「深拷贝」。上面这套往返是「为了存字符串」而设计的，如果你真正想要的只是把对象完整复制一份、并且这份副本要能处理循环引用，那就该换用 structuredClone：它走的是结构化克隆算法，能顺着引用图把循环引用、嵌套对象以及 Date、Map、Set、ArrayBuffer 等内置类型一并正确复制出来，副本与原对象各不相干。

两条边界要分清：structuredClone 能处理循环引用，但不支持函数和 DOM 节点，遇到它们会直接抛错；而 JSON 路线既不能表示循环引用，也不能表示 undefined、函数与 Symbol。选方案前先看数据里有什么。另外，无论走哪条路，序列化之前都该先用 replacer 过滤掉密码、令牌等敏感字段。

落盘传输与结构化克隆

JSON 与结构化克隆回答的是同一个问题的两个方向：当数据要离开内存（落盘、传输）或要被完整复制一份时，怎么不丢信息、不惹麻烦。JSON 用 replacer 与 reviver 守住「筛选」和「还原」两个关口，结构化克隆则负责把整个引用图连同类一起照搬——先把数据里有没有循环引用、函数和敏感字段看清楚，再选路线。

「序列化」指把内存中的对象转成可存储、可传输的文本，JavaScript 里由 JSON.stringify 完成，可用 replacer（函数或键名数组）过滤与转换，或用对象自身的 toJSON 自定义输出；反方向由 JSON.parse 完成，可用 reviver 在解析时把字符串重建回原本的类型。JSON 无法表示 undefined、函数、Symbol 与循环引用，Date 会退化为字符串。「结构化克隆」指 structuredClone 走的深拷贝算法，能正确处理循环引用与 Date、Map、Set、ArrayBuffer 等内置类型，但不支持函数与 DOM 节点。

关键代码

JavaScript
// ========== JSON.stringify ==========
const course = {
  name: 'Node.js 实战',
  price: 299,
  date: new Date(2025, 8, 1),
  secret: '内部密钥',
  students: [{ id: 1, name: '小明' }],
}

// replacer 函数：控制序列化行为
const json = JSON.stringify(course, (key, value) => {
  if (key === 'secret') return undefined   // 过滤字段
  if (value instanceof Date) return value.toISOString().slice(0, 10)
  return value
}, 2)  // 缩进2空格

// replacer 数组：白名单模式
const filtered = JSON.stringify(course, ['name', 'price'])
// '{"name":"Node.js 实战","price":299}'

// ========== JSON.parse ==========
// reviver：还原时转换值
const restored = JSON.parse(json, (key, value) => {
  if (typeof value === 'string' && /^\d{4}-\d{2}-\d{2}$/.test(value)) {
    return new Date(value)
  }
  return value
})
console.log(restored.date instanceof Date)  // true

// ========== toJSON 方法 ==========
// 对象可自定义 toJSON 控制序列化输出
const lesson = {
  title: 'Promise',
  toJSON() { return { title: this.title, summary: '异步核心' } },
}
console.log(JSON.stringify(lesson))  // '{"title":"Promise","summary":"异步核心"}'

// ========== structuredClone ==========
// 支持：循环引用、Date、RegExp、Map、Set、ArrayBuffer 等
const original = { name: '课程', tags: ['热门'] }
original.self = original  // 循环引用，JSON.stringify 会报错

const clone = structuredClone(original)
console.log(clone.self === clone)       // true（独立副本）
console.log(clone.tags !== original.tags) // true（深层拷贝）

// ========== 对比 ==========
// 展开运算符：浅拷贝，嵌套对象共享引用
