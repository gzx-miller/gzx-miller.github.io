函数调用方式与 this 绑定

比较方法调用、脱离对象调用与 call 显式绑定。

开场问题：同一个方法，写成 teacher.introduce() 能正确打印讲师姓名，可把它取出来存进变量再调用、或者交给定时器延后执行，this.name 就变成了 undefined——this 到底听谁的？

讲师方法调用场景

你有一个讲师对象，身上有名字和一个自我介绍的 introduce 方法，方法体里用 this.name 取当前讲师的名字。现在需求来了：点击按钮时显示这句话，或者延迟一秒后显示。

你很自然地就把这个方法交给了别人去调用——传给定时器、传给事件监听、传进数组的遍历方法。结果输出里 this.name 读出来是 undefined，名字丢了。代价是：方法一旦离开它所属的对象就失去上下文，你只能靠把对象整体包一层来绕开，而每次绕开都意味着多写一层嵌套函数；更麻烦的是，这类错误不会在写代码时暴露，只在运行时某一个分支下出现，排查时错误位置还常常指向方法内部某一行，让人以为是数据的问题。这里真正需要的，是搞清楚「this 是什么」到底由谁决定。

显式传参替代this

最省事的做法：干脆不用 this，把需要的数据当参数显式传进去。写成 function introduce(teacher) { ... }，函数内部一律用 teacher.name 取值。

这个方案做对了一件很重要的事：它把「操作哪个对象」变成了显式信息，没有任何隐式上下文，读代码的人一眼就能看出这句话描述的是谁，行为完全可预测。这份确定性应该保留。

参数传递膨胀

  • 每次调用都要把整个对象当参数传进去，方法用到几个字段就得准备几个参数，调用点会越写越长。
  • 函数拿不到「是谁在调用我」这层信息，一份通用实现没法直接被不同对象复用，每个调用点都得自己声明身份。
  • 面向对象的写法里，方法本来就应该知道自己挂在哪个对象上，用参数传等于把这份责任推给了每一个调用者。
  • 只要有一个调用点忘了传参，方法内部立刻读到 undefined，而报错位置在方法里面，排查方向容易被带偏。

调用方式决定绑定

先接受一条规则：普通函数的 this 不在定义时决定，而在调用时根据调用表达式的形式决定。判断方法就是回头看调用处。以「对象.方法()」的形式调用时，this 就是点号左边那个东西；写成独立的 函数() 形式调用时，严格模式下 this 是 undefined，非严格模式下退化成全局对象。换句话说，函数定义在哪个对象里面完全不影响 this，它并不指向所谓的「父对象」——这个误传的直觉，是绝大多数 this 问题的根源。

有了这条规则，「把方法传出去为什么会坏」就一目了然了。写 const detached = teacher.introduce 取到的只是函数本身，之后 detached() 是一次独立调用，点号消失了，this 也就跟着没了。定时器回调、事件监听、map / filter 里传入的方法，全部属于这种「脱离对象」的调用，问题自然集中出现在这些地方。

需要显式指定接收者时，用 call 与 apply：两者都是「立即调用，并把第一个参数当作 this」，区别只是其余参数一个逐个传、一个用数组传。如果希望先造出一个函数、以后再调用，就用 bind——它把 this 永久锁在给定的值上，之后无论怎么调用都不变。类方法单独作为回调传参时同样会丢失绑定，正是靠 bind 或换个写法修正。

另一条路是箭头函数：它没有自己的 this，而是捕获定义时所在函数作用域的 this，并且这个值在定义的那一刻就锁定，之后用 call / apply 也改不动它。所以在「某个方法内部定义回调」的场景里，箭头函数最省事——它天然继承这个方法被调用时的 this，正好是我们想要的那个对象。反过来说，箭头函数不适合直接写成对象上的方法字面量，因为那时它捕获的是外层作用域，通常并不是这个对象本身。

把判断顺序固定下来，这类问题基本就不再靠猜：先找调用表达式，看它长什么样。用 new 调用，this 是新建出来的那个对象；用 call / apply / bind 调用，this 是指定的值；以「对象.方法()」形式调用，this 是点号左边；什么修饰都没有的独立调用，严格模式下是 undefined。而箭头函数忽略以上全部，永远使用定义时捕获的外层 this。

两种调用方式对比

箭头函数词法绑定

this 绑定要解决的，是让方法在调用时知道该为哪个对象工作；它的值由调用方式决定而非定义位置，箭头函数则是唯一在定义时就把它锁定下来的例外。

「this 绑定」指普通函数的 this 在调用时才确定，取决于调用表达式本身：new 调用指向新建的对象；call / apply / bind 指向显式指定的值；以「对象.方法()」形式调用指向该对象；独立调用在严格模式下为 undefined。箭头函数没有自己的 this，捕获定义时外层作用域的值且之后无法被改变。

关键代码

JavaScript
// this 的指向取决于函数的调用方式
const teacher = {
  name: '松松',
  introduce() {
    return `讲师：${this.name}`
  },
}

// 方法调用：this 指向调用者
console.log(teacher.introduce())  // 讲师：松松

// 脱离对象后调用：this 丢失（严格模式下为 undefined）
const detached = teacher.introduce
// detached()  → TypeError（严格模式）或 '讲师：undefined'

// 使用 .call() 显式绑定 this
console.log(detached.call({ name: '临时讲师' }))  // 讲师：临时讲师
