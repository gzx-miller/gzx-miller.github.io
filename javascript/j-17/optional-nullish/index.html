可选链、空值合并与逻辑赋值

安全访问深层属性、处理空值默认值和逻辑赋值运算符。

开场问题：接口在大部分用户身上都会返回 address，于是 res.data.user.address.city 这一行长期平安无事；直到某个用户没填地址，同一行代码抛出 Cannot read properties of undefined，整页白屏——为什么「读一个字段」会把页面读崩？

深层属性访问

你在做一张用户信息卡：头像来自 res.data.user.profile.avatar.url，城市来自 res.data.user.address.city，简介来自 res.data.user.profile.bio。这些字段全都来自接口，而接口给出的是一个形状不确定的对象：用户没填地址，address 这个键干脆不存在；权限不同，profile 可能整个都没返回。

问题就出在这里：JavaScript 读取一个深层字段时，是逐级取值的。它会先取 res.data，再取 .user，再取 .address，每一级都是在「上一个结果」上继续读属性。只要中间任何一级是 undefined，在它上面继续读属性就会抛 TypeError。也就是说，你要的其实是最后那一个字符串，却必须让前面每一级都真实存在——而接口并不保证这件事。

逻辑与逐层守卫

最朴素的做法是用逻辑与 && 逐层守卫：每一级都为真才继续往下，否则整个表达式的值就是那个「假」的中间结果。

const city = res.data && res.data.user && res.data.user.address && res.data.user.address.city

这个方案确实做对了一件事：它在每一级读取之前都先确认这一级存在，把「可能为空的路径」显式挡在了读取之前。方向完全正确，问题在于它的表达方式和判定标准都很粗糙。

路径重复与假值

  • 路径要抄一遍又一遍，res.data.user.address 在这一行里出现了四次；接口字段改名，你得把整条链从头对齐一次。
  • 守卫用的是真假值，不是「是否存在」。当 city 是一个合法的空字符串、或者某个计数值正好是 0 时，它会被 && 当成「没有」，后面的读取被短路掉，你拿到的结果变成了上一级的对象本身。
  • 想顺手给个默认值，通常接一个 || '未设置城市'，可 || 对空字符串和 0 同样会取右侧——一个「用户故意清空了城市」的正常数据，会被你替换成「未设置城市」。
  • 如果链末端是要调用的方法，守卫即使通过了，也不代表这个函数一定存在，直接调用照样抛错。

可选链短路语义

先解决「读取本身可能失败」。语言给出的答案是可选链 ?.：它在左侧为 null 或 undefined 时立即短路，整条表达式求值为 undefined；否则照常继续往下读。上面的长链于是变成 res.data?.user?.address?.city，路径只写一遍，每一级的判定也从「是不是真值」收紧成了「是不是空值」——这正是关键差别：?. 只对 null 和 undefined 短路，0、空字符串、false 都会继续往下访问。

?. 不止用于属性，还有两个配套写法：可选索引 list?.[0] 用于数组或字典可能为空的场景，可选调用 fn?.() 用于函数可能不存在的场景。这里有一条最容易踩的坑：可选链只保证「读取」这一步是安全的。写 obj.method?.() 才是「如果函数存在就调用」，而写成 obj.method?.value 只是安全读了一个属性；链末端是方法时，务必带上调用括号。

读取安全了，但读出来是 undefined 还是没解决问题——你总得有个能显示的城市。这时需要的是空值合并 ??：它只在左侧为 null 或 undefined 时取右侧，其余一切值（包括 0 和空字符串）都原样返回。把它接在可选链后面，一行就能同时完成「安全读取」和「只在真正空值时兜底」：res.data?.user?.address?.city ?? '未设置城市'。

把 ?? 与老朋友 || 对着看，差别一目了然：

左侧的值a || '默认'a ?? '默认'
0'默认'0
空字符串'默认'空字符串
null 或 undefined'默认''默认'

最后一步是把「判断有没有值，再决定要不要赋值」这条常见套路合并成一句话。逻辑赋值运算符正是为此而生：??= 只在左侧为空值时写入右侧，||= 在左侧为假值时写入，&&= 在左侧为真值时写入。初始化配置对象时，config.title ||= '默认标题'、config.theme ??= '秋日暖色' 一行一个字段，比写完整的 if 清爽得多。

逻辑赋值同样要选对运算符。用 count ||= 10 想要兜底时，一个合法的 0 会被替换成 10；想要「数为 0 也算有值」，就必须写 count ??= 10。判断标准始终是同一个：你要防的是「空值」，还是「假值」。

兜底赋值运算符

空值安全与默认值

可选链、空值合并与逻辑赋值这三件事，共同把「字段可能不存在」这件接口常态收进了一行表达式：?. 负责让读取不崩，?? 负责只在空值时兜底，??= 这一族负责把判断与赋值合并。它们的统一准则是只认 null 与 undefined，而不是「假值」——记住这一点，就能同时避开崩溃和被误吞的 0。

「可选链 ?.」指在左侧为 null 或 undefined 时短路并返回 undefined 的访问语法，覆盖属性 a?.b、索引 a?.[i] 与调用 a?.() 三种形式，只对空值短路，0、空字符串、false 会继续访问。「空值合并 ??」只在左侧为空值时取右侧，与会对所有假值取右侧的 || 不同；??=、||=、&&= 则把这类判断与赋值合并成一步。

关键代码

JavaScript
// 可选链、空值合并与逻辑赋值

// ── 可选链 ?. — 安全访问深层属性 ──
const user = { name: '小松鼠', profile: { bio: '爱收集栗子' } }
// 没有 address，传统写法会报 TypeError
console.log(user.address?.city)         // undefined（不报错）
console.log(user.profile?.bio)          // '爱收集栗子'
console.log(user.profile?.avatar?.url)  // undefined

// 可选索引访问
const list = null
console.log(list?.[0])   // undefined
console.log(list?.length) // undefined

// 可选函数调用
const callbacks = { onSuccess: () => '成功' }
console.log(callbacks.onSuccess?.())  // '成功'
console.log(callbacks.onError?.())    // undefined（不存在也不报错）

// ── 空值合并 ?? — 仅 null / undefined 时取默认值 ──
console.log(null ?? '默认值')       // '默认值'
console.log(undefined ?? '默认值')  // '默认值'
console.log(0 ?? 42)               // 0（0 不是空值）
console.log('' ?? '占位')          // ''（空串不是空值）

// ── ?? vs || 对比 ──
console.log(0 || '回退')   // '回退'（0 是 falsy）
console.log(0 ?? '回退')   // 0（?? 只看 null/undefined）
console.log('' || '回退')  // '回退'
console.log('' ?? '回退')  // ''

// ── 逻辑赋值（ES2021） ──
const config = {}
config.title ||= '默认标题'    // title 为 falsy 时赋值
config.theme ??= '秋日暖色'    // theme 为 null/undefined 时赋值
config.count &&= 10            // count 为 truthy 时才赋值（此时 count 不存在，不执行）
console.log(config) // { title: '默认标题', theme: '秋日暖色' }

// ── 短路求值 ──
const name = user.nickname ?? user.name ?? '匿名用户'
console.log(name) // '小松鼠'（nickname 为 undefined，取 name）
