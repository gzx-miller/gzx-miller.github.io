JSON、克隆与序列化

用 replacer/reviver 控制序列化，用 structuredClone 深拷贝循环引用与内置类型。

开场问题：课程数据导出成 JSON 存进了本地缓存，重新读回来时，price 还是数字、name 还是字符串，唯独日期从 Date 变成了一个 '2025-10-15' 的字符串。同一份数据往返一趟，怎么就变了模样？更怪的是，有人用展开语法复制这份数据，改副本竟把原对象也一起改了。

JSON 能装下什么

你要做的是一件小事：把内存里的数据变成一段能存进文件、能发上网络的文本。JSON 就是这个格式的约定。但它比想象中要窄——它只认识对象、数组、字符串、数字、布尔和 null 这几种值。

  • undefined、函数、Symbol 都不是合法值：出现在对象里，整个键会被丢弃；出现在数组里，则被替换成 null。
  • 循环引用直接抛错——一个对象引用回自己，JSON 没有语法能表示「回到自己」。
  • Date 会被降级成 ISO 字符串，Map、Set 则退化成空对象 {}。

这就是日期往返变样的根源。要记住的结论是：JSON 不是对象的「截图」，而是可传输值的一个子集——凡是子集之外的，都会被丢掉或改写。

序列化的三个参数

序列化用 JSON.stringify(value, replacer, space)，三个参数各管一段：

  • value 是要序列化的数据。
  • replacer 可以是函数，逐键拿到 (key, value)，返回什么就写入什么；返回 undefined 就等于删除这个键。
  • replacer 也可以是字符串数组，只保留数组里点名的那些键。
  • space 控制缩进，传数字或字符串，纯粹为了可读。

其中函数形式的 replacer 会从外到内遍历每个值，这就给了你一个现成的「筛子」——不需要的字段在这里返回 undefined 即可剔除。

两端各留一个钩子

第一端在序列化这侧：如果某个对象自己定义了 toJSON()，stringify 会先调用它，再用它的返回值去序列化。这比在 replacer 里按类型写一堆 if 更内聚——对象自己最清楚「我该被存成什么样」。日期对象就自带 toJSON。

第二端在还原这侧：JSON.parse(text, reviver)。reviver 同样逐键拿到 (key, value)，你可以在这一步把日期字符串重新构造成 Date——配合一个形如 /^\d{4}-\d{2}-\d{2}$/ 的判断，只重建长得像日期的那些字符串。

两端配成一对：存出去是字符串，收回来是 Date，格式就能对齐，开头那个「往返变样」的问题也就有了解法。

展开只是浅拷贝

有人会说：那我不用序列化，直接 const copy = { ...src } 复制一份不就行了？它做对了一半——顶层属性确实复制了，改 copy 上的基本类型字段不会影响 src。

但它做错的正是嵌套这一层：copy.meta === src.meta 仍然为 true，两个对象共享同一个内层引用。你改了 copy.meta.tag，src.meta.tag 会跟着一起变。一句话，展开语法只复制最外一层，嵌套结构照旧共享。

结构化克隆的边界

真正意义上的深拷贝，浏览器给了 structuredClone。它走的是「结构化克隆算法」，会把对象、数组、Date、Map、Set、ArrayBuffer 都各复制一份独立的，连循环引用也能正确重建。

  • 支持：对象、数组、Date、Map、Set、RegExp、ArrayBuffer 等可结构化类型，以及循环引用。
  • 不支持：函数会抛 DataCloneError，DOM 节点也不行。
  • 它不等于 JSON——不经过文本中转，也不受「JSON 能表示什么」那套窄集限制。

最后一条落点很实际：无论走序列化还是克隆，只要对象里有密码、令牌这类敏感字段，都应当在序列化前用 replacer 把它们过滤掉，而不是等写进日志或缓存才想起删。数据一旦离开内存，就很难收回。

往返与克隆对照

两条路各取所需

序列化与克隆是两条不同的路：JSON 走文本中转，能跨网络、能落盘，但只认值的子集，靠 replacer 与 reviver 两端钩子补足类型往返；structuredClone 走结构化克隆算法，能复制循环引用和更多类型，却只留在本进程内存里、不经过文本，也带不走函数。选哪条，取决于数据是要「存下来、发出去」，还是「留在内存里复制一份」。

「结构化克隆」是 structuredClone() 使用的复制算法，按值递归复制对象并保留类型：支持对象、数组、Date、Map、Set、ArrayBuffer 以及循环引用，复制结果与原数据不共享任何引用。它不支持函数、DOM 节点与 Symbol，遇到会抛 DataCloneError；与 JSON 往返不同，它在内存中直接完成、不经过文本，也就无法在途中过滤敏感字段，需要过滤时仍得另想办法。

关键代码

JavaScript
// ═══════════════════════════════════════════
// 1. JSON 能表示什么、不能表示什么
// ═══════════════════════════════════════════

JSON.stringify({ a: undefined, b: () => {}, c: Symbol() })   // '{}'            ← 三个键全被丢弃
JSON.stringify([undefined, () => {}])                        // '[null,null]'   ← 数组里变 null
JSON.stringify(new Date(0))                                  // '"1970-01-01T00:00:00.000Z"'  ← 退化为字符串
JSON.stringify(new Map([['a', 1]]))                          // '{}'            ← Map 退化成空对象

// ═══════════════════════════════════════════
// 2. 循环引用无法序列化
// ═══════════════════════════════════════════

const loop = { name: 'A' }
loop.self = loop
JSON.stringify(loop)                                         // 抛错：Converting circular structure to JSON

// ═══════════════════════════════════════════
// 3. stringify(value, replacer, space) 的三个参数
// ═══════════════════════════════════════════

JSON.stringify({ a: 1, b: 2 }, null, 2)                      // 带两格缩进的多行文本
JSON.stringify({ a: 1, b: 2, c: 3 }, ['a', 'c'])             // '{"a":1,"c":3}'  ← 数组 replacer 只留这些键
JSON.stringify({ name: '小明', password: '123' }, (key, value) =>
  key === 'password' ? undefined : value)                    // '{"name":"小明"}'  ← 函数 replacer 过滤敏感字段

// ═══════════════════════════════════════════
// 4. 对象上的 toJSON 自定义输出
// ═══════════════════════════════════════════

const order = {
  id: 7, createdAt: new Date(0),
  toJSON() { return { id: this.id, date: '1970-01-01' } },
}
JSON.stringify(order)                                        // '{"id":7,"date":"1970-01-01"}'  ← toJSON 的结果被采用

// ═══════════════════════════════════════════
// 5. parse(text, reviver) 在还原时重建类型
// ═══════════════════════════════════════════

JSON.parse('[1,2,3]')                                        // [1, 2, 3]
JSON.parse('{"d":"1970-01-01"}', (key, value) =>
  typeof value === 'string' && /^\d{4}-\d{2}-\d{2}$/.test(value) ? new Date(value) : value)
// 结果：{ d: Date }  ← 日期字符串被重建为 Date

// ═══════════════════════════════════════════
// 6. 展开语法只是浅拷贝
// ═══════════════════════════════════════════

const src = { meta: { tag: '热门' }, list: [1, 2] }
const shallow = { ...src }
shallow.meta === src.meta                                    // true     ← 嵌套对象仍共享引用
shallow.meta.tag = '冷门'
src.meta.tag                                                 // '冷门'   ← 改副本影响了原对象

// ═══════════════════════════════════════════
// 7. structuredClone 结构化克隆
// ═══════════════════════════════════════════

const original = { name: 'A', when: new Date(0), tags: new Set(['x']) }
original.self = original
const cloned = structuredClone(original)
cloned.self === cloned                                       // true     ← 循环引用被正确重建
cloned.tags instanceof Set                                   // true     ← Set 被克隆
cloned.when instanceof Date                                  // true     ← Date 被克隆
structuredClone({ fn: () => {} })                            // 抛 DataCloneError  ← 函数无法克隆
