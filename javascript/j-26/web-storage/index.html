Web Storage 与 IndexedDB

用 localStorage/sessionStorage 存储简单键值，用 IndexedDB 存储大量结构化数据。

开场问题：你在 localStorage 里存了一个对象，刷新页面读回来，却变成一个字符串 "[object Object]"——那个对象去哪儿了？

刷新与状态留存

假设你正在做一个在线课程页面。用户切换了主题、把某节课标记成「已学完」、在表单里填了一半的报名信息后误撞了刷新键——这些状态如果只放在内存里，页面一重载就全没了。你希望的是：主题和进度刷新之后还在，哪怕关掉浏览器明天再来也在；而那份填了一半的表单，只在当前这个标签页里保留就够了，用户把标签页关掉就该丢弃。

所以要解决的问题其实是两件：一是把数据留在浏览器里、让它活过这次页面刷新；二是决定它该活多久——是跨会话长存，还是随标签页生灭。选错了存储方式，要么用户明天回来发现设置丢了，要么用户在公共电脑上关掉页面后，隐私数据还残留在磁盘里。

本地键值存储

最省事的做法，用 localStorage：localStorage.setItem('theme', 'dark') 写入，localStorage.getItem('theme') 读回，removeItem 删一个、clear 清空。它按「键—值」成对存储，用法简单到几乎不需要学。

这个方案做对了一件重要的事：数据没有跟着页面一起消失。刷新、关标签页、重启浏览器，写进去的东西都在，而且读取时是同步的——下一行代码就能立刻拿到值，不用 await。对于「用户偏好」这种小而重要的配置，这几乎是最顺手的形态。

字符串与过期限制

  • 只能存字符串。直接存对象，会被强制转成 "[object Object]"，读回来的东西已经不是原来那个对象了。
  • 没有过期时间。localStorage 会一直留着，除非用户手动清；临时数据放进去就变成了「永久垃圾」。
  • 同步读写会阻塞主线程。数据量大时，一次读写就能让页面卡顿一下。
  • 容量有限。写超出配额时会直接抛出 QuotaExceededError，如果没接住这个异常，后续逻辑会当场中断。
  • 同步不代表会通知自己。你在当前页改了值，storage 事件不会在当前页触发，只有其他同源标签页才能收到。

序列化与分区策略

先解决「只能存字符串」。既然它只认文本，那就约定：写入前用 JSON.stringify() 把对象序列化成字符串，读取时用 JSON.parse() 还原。这样对象、数组都能进出，代价是你必须保证「存进去和读出来用的是同一套约定」，读的时候还要考虑键不存在的情况。

再解决「活多久」的问题。浏览器其实给了两个同源的键值仓库，用法完全一样，差别只在生命周期：localStorage 跨会话持久保存，sessionStorage 以标签页为单位，标签页一关就清空。于是把「长期偏好」和「临时表单进度」分开：主题、进度放前者，未提交的表单放后者。顺手记住一个反直觉点——storage 事件只在其他同源标签页触发，当前页监听不到自己的写入，所以自己写完要手动刷新一次界面。

但无论怎么分，「同步阻塞」和「容量有限」这两条都治不了。它们注定只适合小而少的数据。当数据量大、结构复杂、还要按条件查询时，就必须换一套机制——IndexedDB。它是浏览器内置的异步、基于事务的数据库，数据存放在「对象仓库」（object store）里，可以建索引按字段检索，能容纳远超键值存储的数据量。它的每一次读写都在事务里完成，配合回调或 Promise 使用，因此不会阻塞主线程。

三种方案各有位置，用「生命周期、容量、同步性」三个维度一对照就清楚了：

方案生命周期容量同步性
localStorage持久保存，跨会话、关浏览器仍在约 5MB同步，读写会阻塞主线程
sessionStorage限于当前标签页，关闭即清除约 5MB同步，读写会阻塞主线程
IndexedDB持久保存，由事务管理一致性远大于前者，按配额放开异步，基于事务，不阻塞主线程

存储寿命对照

寿命容量与选型

浏览器端存储要回答的从来不是「怎么存」，而是「存多久、存多少、要不要卡住页面」。小的长期配置交给 localStorage，临时会话数据交给 sessionStorage，量大又需要查询的交给 IndexedDB——按生命周期、容量、同步性三把尺子量一下，选型就不会错。

「Web Storage」指 localStorage 与 sessionStorage 这对键值接口：前者持久保存、跨会话可用，后者以标签页为单位、关闭即清除，二者都只能存字符串，存对象需 JSON 序列化。数据量大且结构复杂时应改用 IndexedDB——它是异步、基于事务、可建索引的浏览器数据库，数据放在对象仓库中。注意：storage 事件只在其他同源标签页触发；超配额会抛 QuotaExceededError；localStorage 的同步读写会阻塞主线程。

关键代码

JavaScript
// localStorage：关闭浏览器后数据仍然存在
localStorage.setItem('token', 'abc123')
const token = localStorage.getItem('token')

// sessionStorage：关闭标签页后数据清除
sessionStorage.setItem('currentPage', '2')

// 存储对象（需要 JSON 序列化）
const user = { name: '张三', role: 'admin' }
localStorage.setItem('user', JSON.stringify(user))
const saved = JSON.parse(localStorage.getItem('user'))

// 遍历所有键值
for (let i = 0; i < localStorage.length; i++) {
  const key = localStorage.key(i)
  console.log(key, localStorage.getItem(key))
}

// 删除与清空
localStorage.removeItem('token')
localStorage.clear()

// 监听其他标签页的存储变化
window.addEventListener('storage', (event) => {
  console.log('键', event.key, '从', event.oldValue, '变为', event.newValue)
})

// IndexedDB：大容量结构化存储
const request = indexedDB.open('CourseDB', 1)
request.onupgradeneeded = (e) => {
  const db = e.target.result
  if (!db.objectStoreNames.contains('courses')) {
    db.createObjectStore('courses', { keyPath: 'id' })
  }
}
request.onsuccess = (e) => {
  const db = e.target.result
  const tx = db.transaction('courses', 'readwrite')
  tx.objectStore('courses').put({ id: 1, title: 'Vue3 基础' })
}
