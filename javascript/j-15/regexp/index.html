正则表达式与模式匹配

用正则匹配手机号、邮箱、价格与日期，掌握捕获组和前后断言。

开场问题：手机号校验如果靠一串手写的下标判断，为什么一行 /^1[3-9]\d{9}$/ 就能把同一件事说得更清楚？

模式匹配需求

你需要在文本框里校验手机号、邮箱、身份证，还想从一段日志里把日期抠出来。这类工作的本质其实是一句话：先描述一个字符串长什么样，再拿去匹配。用 for 循环逐字符判断当然能做，可规则一旦复杂起来，代码就会失控。

不做模式化描述，代价是：判断「像不像」和「取出其中一段」这两件事，都得靠你手工维护下标，长度、位置、前后文限制全要自己照顾。

说白了，你真正需要的是一种「描述能力」：把一条规则老老实实写下来，然后反复使用；而不是每换一个字段、每换一个页面，就把同一套循环重写一遍。

逐字符下标判断

最省事的做法：写一个循环，按下标逐位判断——第一位是不是 1，第二位是不是 3 到 9，后面九位是不是数字。

这个方案做对了一件事：完全可控、逻辑透明，每一步都在你眼皮底下，不依赖任何额外语法。规则简单且短时，它是可靠的。

逐位判断四大缺陷

  • 冗长：身份证、邮箱这类规则写出来是几十行索引判断，可读性差、难以通读。
  • 难改：规则一变（比如放宽第二位范围），要回去改一串条件分支。
  • 提取难：光判断「像不像」还不够，往往要取出其中的年、月、日，手写 slice 的下标极易算错。
  • 边界多：长度、位置、以及「不能是更大数字串的一部分」这类前后文限制，统统要手动补。

正则字符类与量词

不推翻「描述规则」，而是把描述方式换成声明式的正则表达式：用字符类、量词和锚点，把「长什么样」直接写出来。

比如手机号就是 /^1[3-9]\d{9}$/——^ 锚定开头、$ 锚定结尾、[3-9] 是第二位允许的字符集合、\d{9} 表示后面恰好九个数字。规则一目了然，也不必再关心下标。

拿到模式后，按用途选方法：test() 只回答「匹配不匹配」，适合做校验；exec() 返回单次匹配的详细信息（含捕获内容）；matchAll() 与 replace() 负责处理全部匹配和替换。

要提取子串，用捕获组：普通括号是匿名组，按位置取值；命名组 (?<name>...) 更清晰，匹配后可以从结果的 groups 对象里按名字取值，不必去数第几个括号。

想限定「前面 / 后面必须有或没有某段文字」，又不想把这部分算进匹配结果，就用前后断言：前瞻 (?=...) 要求后面紧跟，负前瞻 (?!...) 要求后面不能出现；后行断言同理。它们只作为条件，不消耗字符。

断言真正的价值在于「上下文限定」。比如只想匹配后面跟着「元」字的数字，把 元 放进前瞻即可，匹配结果里只留数字、不留这个字；想排除「原价」里的数字，用负后行断言要求前面不是那两个字就行。一句话：需要「看」，但不需要「吃掉」的内容，都交给断言。

最后是修饰符，控制匹配范围：g 全局、i 忽略大小写、m 多行、s 让点号也匹配换行、u 启用 Unicode 模式。

需求方法
只要「匹配 / 不匹配」test()
取单次匹配的细节与捕获内容exec()
遍历所有匹配matchAll()（需带 g）
批量替换replace()
三个坑必须记住：第一，带 g 标志的正则，多次 exec() / test() 会因 lastIndex 前进而给出不同结果，状态挂在正则对象上，复用时尤其危险。第二，把用户输入拼进正则模式之前必须转义特殊字符，否则会改变匹配语义，甚至引发性能灾难。第三，量词尽量写具体，比如用 [0-9]{4} 而不是 .*，避免在大文本上回溯爆炸；复杂校验建议拆成多个边界清晰的正则分别判断。

校验提取与替换

正则表达式把「字符串长什么样」变成一段可复用的声明式模式。校验、提取、替换这些原本要手写下标的工作，被压缩成一行模式加一次调用——代价是要清楚它的状态与性能边界。

「正则表达式」用模式描述字符串的形状，由字符类、量词、捕获组与前后断言组合而成。test() 用于校验，exec() 提取单次匹配（含命名组），matchAll() 与 replace() 处理全部匹配；修饰符 g、i、m、s、u 控制匹配范围，其中带 g 的正则会通过 lastIndex 记住上次匹配位置。

关键代码

JavaScript
// 正则表达式与模式匹配

// ── 创建方式 ──
const literal = /^hello/i          // 字面量（编译期确定）
const dynamic = new RegExp('hello', 'i') // 构造器（可拼接变量）

// ── 字符类与量符 ──
const phone = /^1[3-9]\d{9}$/               // 手机号
const email = /^[^\s@]+@[^\s@]+\.[^\s@]+$/  // 简易邮箱

// ── test / exec ──
phone.test('13800138000')  // true
const result = /(\d{4})-(\d{2})/.exec('2025-06-15')
console.log(result[0])     // '2025-06'（完整匹配）
console.log(result[1])     // '2025'（第一个捕获组）

// ── 命名捕获组 ──
const dateRe = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/
const m = dateRe.exec('2025-06-15')
console.log(m.groups)  // { year: '2025', month: '06', day: '15' }

// ── matchAll：获取所有匹配 ──
const text = '价格：¥12、¥35、¥7'
const prices = [...text.matchAll(/¥(\d+)/g)]
console.log(prices.map((p) => p[1])) // ['12', '35', '7']

// ── replace 与回调 ──
const masked = '13800138000'.replace(/(\d{3})\d{4}(\d{4})/, '$1****$2')
console.log(masked) // '138****8000'

// ── 先行断言（lookahead） ──
// (?=...) 正向前瞻，(?!...) 负向前瞻
const strongPwd = /^(?=.*[A-Z])(?=.*\d).{8,}$/
strongPwd.test('Hello123')  // true — 含大写 + 数字 + 8位以上
strongPwd.test('hello123')  // false — 缺少大写

// ── 后行断言（lookbehind） ──
const currency = /(?<=¥)\d+/g
'¥12 和 ¥35'.match(currency) // ['12', '35']
