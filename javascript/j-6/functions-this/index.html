函数声明、参数与 this 绑定

比较函数声明、函数表达式与箭头函数，掌握默认参数、剩余参数以及 this 的四种绑定规则。

开场问题：课程列表要显示每门课的讲师，代码写成了 list.map(course.formatTitle)，结果每一行的讲师都是 undefined；可你在控制台里单独敲 course.formatTitle()，它明明能正常返回。同一个函数，为什么换个地方调用就变了？

三种写法与提升

最初你只想要一个「叫得出名字」的函数，于是写下 function formatTitle(course) {}。这叫函数声明，它的好处很实在：写在哪儿都行，甚至可以在前面就调用它——因为引擎在执行之前，先把整段声明搬到了当前作用域的顶部，这个动作叫提升。

可当函数要当作值来用时——塞进对象、传给 map、作为回调再传出去——声明就显得啰嗦。于是有了函数表达式：const format = function (course) {}。它和声明长得几乎一样，本质却是「先声明一个变量，再把一个匿名函数赋给它」。差别恰好落在提升上：变量名会提升，赋值不会，所以在赋值那一行之前调用它会直接报错。

再短一点，就走到箭头函数 const format = (course) => {}。它看着只是省了几个字，却动了一条最关键的规则——this 不再由调用方式决定。这一点放到后面单独讲，先记住：三种写法不是三个同义词，选错会带来完全不同的行为。

参数的默认与剩余

参数少传一个就会变成 undefined，最笨的补法是函数体开头塞一句 if (count === undefined) count = 1。它确实管用——缺参时也有值可算。只是每多一个可选参数就多一行判断，重复又容易漏。

更好的写法是在参数表里直接给默认值：function addToCart(item, count = 1) {}。这里要留个心眼：默认值只在传 undefined 时生效，传 null 或 0 都不会被覆盖。

参数个数不确定时，另一个办法是用剩余参数收集：function sum(...nums) {}，多余的实参会收成一个真正的数组，可以放心用 map、reduce。还有一个只在 function 里存在的对象 arguments，它装着本次调用收到的全部实参，但它只是「类数组」，没有 forEach 这类方法，得靠 length 手动遍历。箭头函数里根本没有 arguments，想收集参数只能用剩余参数。

返回值里的陷阱

函数默认会返回 undefined。这不是失误，而是一条明确的约定：只要没写 return，或者所有分支都没走到 return，调用结果就是 undefined。所以「顺手改个全局变量就算完事」的函数，拿到的返回值一定是空的。

还有一个更隐蔽的坑：return 后面的表达式如果换到下一行写，引擎会在 return 处自动补上分号，后面的值根本不会被返回，你得到的还是 undefined。所以 return 和它的值尽量写在同一行。

this 由谁来决定

很多人以为 this 是函数自己的属性，定义时定死。其实相反——this 的值在每次调用时才确定，由「怎么调」决定。同一个函数用不同方式调，this 可以是不同的东西。规则一共四条，优先级从低到高：

  • 默认绑定：裸调用 formatTitle()，严格模式或模块里 this 是 undefined，松散脚本里则是全局对象。
  • 隐式绑定：写成 对象.方法()，如 course.formatTitle()，this 就是那个对象。
  • 显式绑定：用 call、apply、bind 手动指定 this，它压过隐式绑定。
  • new 绑定：用 new 调构造函数，this 是刚创建的那个新对象，优先级最高。

四条规则里真正说了算的，是「最后起作用的那一层」。这正是开头那个 bug 的来源。

箭头函数的 this

说回 list.map(course.formatTitle)。把方法从对象上摘下来传给别人时，调用方式已经不是 对象.方法() 了，隐式绑定不成立，退回默认绑定，this 不再是 course，于是 this.title 读不到值——这就是「方法脱离对象作为回调后 this 丢失」。

补救有两种。一种是把方法重新绑回对象：list.map(course.formatTitle.bind(course))。另一种更常见——用箭头函数包一层：list.map(c => c.formatTitle())，这样 formatTitle 仍然是被 c. 调用的。

箭头函数能救场，是因为它没有自己的 this：它会直接沿用定义位置外层的 this，也就是「词法捕获」。好处是稳定，代价是之后用 call、apply、bind 也改不动它——你传进去的对象会被忽略。所以箭头函数适合做回调，却不适合需要动态 this 的方法。

亲手验证 this 绑定

把绑定说清楚

函数、参数、返回值这三样是从「怎么写」上约束函数；this 则是从「怎么调」上决定的。把「写在哪」和「谁调用」分开看，this 就不再神秘：隐式绑定看调用点前面有没有对象，显式绑定和 new 能覆盖它，而箭头函数干脆放弃自己的 this，从定义处拿。

「this 绑定」指函数被调用时 this 指向谁，按优先级由高到低为 new 绑定、显式绑定（call/apply/bind）、隐式绑定（对象.方法()）与默认绑定。箭头函数不参与这套规则，它的 this 在定义时由词法环境捕获，且不能用 call/apply/bind 改变。

expr2()              // TypeError: expr2 is not a function  ← 只提升变量名，赋值不提升

// ═══════════════════════════════════════════
// 2. 参数默认值与剩余参数
// ═══════════════════════════════════════════

function addToCart(item, count = 1) { return { item, count } }
addToCart('栗子').count        // 1     ← 缺省或传 undefined 时取默认值
addToCart('栗子', 0).count     // 0     ← 传 0 不会被默认值覆盖
addToCart('栗子', null).count  // null  ← 只有 undefined 才触发默认值

function sum(...nums) { return nums.reduce((a, b) => a + b, 0) }
sum(1, 2, 3)                   // 6     ← 剩余参数收成真数组，可用数组方法

function legacy() { return arguments.length }
legacy(1, 2, 3)                // 3     ← arguments 只是类数组，没有 forEach
// 箭头函数里根本没有 arguments，收集参数只能用 ...rest

// ═══════════════════════════════════════════
// 3. 返回值与隐式 undefined
// ═══════════════════════════════════════════

function noReturn() { const x = 1 }
noReturn()                     // undefined  ← 没写 return 就返回 undefined

function check(n) { if (n > 0) return '正数' }
check(1)                       // '正数'
check(-1)                      // undefined  ← 分支没命中，走到函数末尾

function broken() {
  return
  42                           // 这里的 42 永远不会被返回
}
broken()                       // undefined  ← return 后换行，自动分号截断

// ═══════════════════════════════════════════
// 4. this 的四种绑定
// ═══════════════════════════════════════════

const teacher = {
  name: '松松',
  introduce() { return `讲师：${this.name}` },
}

teacher.introduce()                // '讲师：松松'      ← 隐式绑定：this = teacher
const detached = teacher.introduce
detached()                         // 严格/模块下 this = undefined  ← 默认绑定

detached.call({ name: '临时讲师' })   // '讲师：临时讲师'   ← 显式绑定压过默认绑定
detached.apply({ name: '客座讲师' })  // '讲师：客座讲师'
const bound = detached.bind({ name: '固定讲师' })
bound()                            // '讲师：固定讲师'   ← bind 返回永久绑定的副本

function Course(title) { this.title = title }
new Course('异步')                 // Course { title: '异步' }  ← new 绑定，优先级最高

// ═══════════════════════════════════════════
// 5. 箭头函数的词法 this
// ═══════════════════════════════════════════

const team = {
  name: '前端组',
  members: ['小栗', '松松'],
  list() {
    return this.members.map((m) => `${this.name}：${m}`)  // 箭头沿用 list 的 this
  },
}
team.list()                        // ['前端组：小栗', '前端组：松松']

function outer() { return () => this }
outer.call({ tag: 'A' })()         // { tag: 'A' }  ← call 作用在外层，箭头沿用外层 this

const arrowFn = () => this
arrowFn.call({ tag: 'B' })         // 仍是定义处的 this，call 对箭头无效

// 方法脱离对象后作为回调，this 会丢
const titles = [{ title: '闭包' }, { title: '原型' }]
titles.map((c) => c.title)         // ['闭包', '原型']  ← 用箭头包一层，仍是被 c. 调用
