运算符与表达式

梳理算术、比较、逻辑、空值合并、可选链、逻辑赋值与位运算，掌握短路求值与权限位模型。

开场问题：商品编辑表单里用 discount || 0.9 给折扣兜底，运营把折扣填成 0（表示免费）后，页面显示的却是 0.9；同一份用户资料里，用 ?. 读取深层权限字段不再报错，可权限一旦用 0 表示「无权限」，|| 又把它和「字段缺失」混在了一起。

算术运算的细节

最自然的用法，是把运算符直接当成数学符号：a + b 就是相加。这在大多数时候没错，它做对的是让表达式读起来和公式一样。但有几个符号的脾气和数学不完全一样，照着直觉写就会偏：

  • % 是取余，结果符号跟随被除数：-7 % 3 得到 -1，和数学里的模运算并不等价。
  • ** 是幂运算，并且右结合：2 ** 3 ** 2 算的是 2 ** (3 ** 2)，等于 512。
  • ++ 与 -- 分前置、后置：const a = ++i 先把 i 加一再取新值，const b = i++ 先取旧值再加一；两者对 i 的最终影响相同，赋给变量的结果却不同。
  • 再加上浮点精度这个老问题：0.1 + 0.2 !== 0.3，涉及金额时更稳的做法是先转成整数「分」再运算。

于是迭代出第一条习惯：把运算符当表达式工具用，但心里记住「取余的符号」「幂的右结合」「自增的求值时机」「浮点精度」这四点，写的时候就不会被表面的符号骗到。

比大小与字符串

接着是比较。>、<、>=、<= 用来判断大小，数字之间比较最直观。问题出在两侧不是同一种类型时——它同样会触发隐式转换，于是比较的到底是什么，又变成了要猜的事。

字符串比较尤其容易反直觉：它按 UTF-16 码元逐位比较，先比首字符，谁大谁就大。所以 '2' > '10' 为 true——因为首字符 '2' 大于 '1'，后面的位数根本不参与；中英文混排的顺序，也不等于人眼期望的顺序。迭代的做法是：数字就比数字；字符串排序要显式给出比较器，多语言场景交给 Intl.Collator，不要靠 < 去猜。

短路返回操作数

逻辑运算符 &&、||、! 常被当成布尔运算，以为结果只会是 true／false。用它们控制流程时确实看不出差别，于是这个印象被一直保留下来。

但它做对的只是「控制流程」，真正的语义更精确：&& 与 || 在结果确定时立即短路，返回的是参与运算的那个原始操作数，而不是布尔值。于是 0 || 'x' 得到 'x'，'' || 'default' 得到 'default'，'a' && 'b' 得到 'b'。这意味着用 || 兜底时，0、空字符串、false 都会被当成「没有值」而被替换掉——开头那个 0 折扣变成 0.9，就是这么来的。短路还有一层含义：右侧若是函数调用，条件不满足时它根本不会执行，所以 flag && doSomething() 是常见的守卫写法。

迭代的方向也随之清楚：把短路当成「取值」和「守卫」，并区分「假值」与「空值」——只想在真的没有值时兜底，就该换一个运算符。

空值合并与可选链

只想在「真的没有值」时给默认值，用空值合并 ??：它只在左侧是 null 或 undefined 时才取右侧，用户填的 0、空字符串会被原样保留。于是 discount ?? 0.9 在折扣为 0 时给出 0，正是开头场景要的行为。

读深层属性时又是另一种啰嗦：早期要写 a && a.b && a.b.c 层层守护。改用可选链 ?. 后，只要链上出现 null／undefined 就短路返回 undefined，一行写完 user?.profile?.address?.city。它还有两个形态：可选索引 list?.[0] 与可选调用 fn?.()——后者只有函数确实存在时才调用。要留意的是，?. 只对 null／undefined 短路，遇到 0、空字符串会继续往下访问。

迭代成一句话：读属性用 ?.，只在空值时兜底用 ??，别再用 || 一把梭。

逻辑赋值与位运算

把「判断再赋值」合成一步，就是逻辑赋值：a ||= b 等价于 a || (a = b)，a ??= b 只在 a 为空时赋值，a &&= b 只在 a 为真时赋值。它们能让「给缺省字段补默认值」这类代码短上一行，语义也更直白。

另一类场景是「一堆开关」。权限、状态这类字段，可以用一个整数的不同二进制位并行编码：位运算会先把操作数转成32 位有符号整数，再逐位计算——| 按位或、& 按位与、^ 按位异或、~ 按位取反、<< 左移、>> 有符号右移、>>> 无符号右移。把权限定义成 2 的幂——读 1、写 2、管理 4——就能用 perms |= WRITE 授予、perms & READ 检查、perms & ~WRITE 撤销、perms ^ ADMIN 切换。一个整数装下所有开关，存储和传输都省。

迭代的结论是：权限这类场景优先用位标志，但记住 32 位边界（超出会截断），并把常量写成有名字的字面量，读起来才能对得上每一位。

亲手验证运算符

短路与取值的分工

运算符这层看着杂，其实都在讲同一件事——什么时候才去取右边的值。逻辑运算短路返回操作数，?? 只在空值时兜底，?. 安全穿透深层属性，逻辑赋值把判断与赋值合一，位运算把多个开关压进一个整数。把「假值」和「空值」分清楚，就不会再让 || 吞掉用户的 0。

「短路求值」左侧一旦能确定结果，就停止对右侧求值，并返回参与运算的那个操作数本身：&& 在左侧为假时短路、|| 在左侧为真时短路、?? 只在左侧为 null／undefined 时取右侧、?. 遇到空值短路成 undefined。短路还会跳过右侧的副作用，所以 flag && doSomething() 才成立。

// ═══════════════════════════════════════════
// 1. 算术运算符
// ═══════════════════════════════════════════

7 % 3             // 1  —— 取余
-7 % 3            // -1 —— 结果的符号跟随被除数
2 ** 3            // 8  —— 幂运算
2 ** 3 ** 2       // 512 —— ** 右结合，等价于 2 ** (3 ** 2)

let i = 5
const pre = ++i   // pre 为 6，i 为 6 —— 前置：先加再用
const post = i++  // post 为 6，i 为 7 —— 后置：先用再加

0.1 + 0.2 === 0.3 // false —— 浮点精度问题

// ═══════════════════════════════════════════
// 2. 比较与字符串比较
// ═══════════════════════════════════════════

'2' > '10'        // true  —— 字符串逐位比较，先比首字符 '2' > '1'
'b' > 'a'         // true
[1, 2] < [1, 3]   // true  —— 转成 '1,2' 与 '1,3' 再比较
'5' < 3           // false —— 两侧先转成数字，5 < 3

// ═══════════════════════════════════════════
// 3. 逻辑运算返回的是操作数
// ═══════════════════════════════════════════

0 || 'x'          // 'x'   —— 左侧是假值，返回右侧操作数
'a' && 'b'        // 'b'   —— 左侧是真值，返回右侧操作数
'' || 'default'   // 'default' —— 空字符串被当成假值
0 ?? 'default'    // 0     —— ?? 只对 null/undefined 兜底
false || 0        // 0     —— || 会跳过 false，把 0 当兜底值

// ═══════════════════════════════════════════
// 4. 可选链与空值合并
// ═══════════════════════════════════════════

const user = { profile: { bio: '收集栗子' }, list: [] }
user?.address?.city       // undefined —— 链上缺失也不报错
user?.profile?.bio        // '收集栗子'
user?.list?.[0]           // undefined —— 可选索引
user?.save?.()            // undefined —— 函数不存在时不调用，也不报错

// ═══════════════════════════════════════════
// 5. 逻辑赋值
// ═══════════════════════════════════════════

let title
title ??= '默认标题'      // '默认标题' —— 空值才赋值
let count = 0
count ||= 5               // 5 —— 假值就赋值（0 被覆盖）
let flag = true
flag &&= false            // false —— 真值才赋值

// ═══════════════════════════════════════════
// 6. 位运算与权限标志
// ═══════════════════════════════════════════

const READ  = 0b001       // 1
const WRITE = 0b010       // 2
const ADMIN = 0b100       // 4

let perms = 0
perms |= READ             // 1  —— 按位或：授予读权限
perms |= WRITE            // 3  —— 继续授予写权限
perms & READ              // 1  —— 按位与：非 0 即拥有读权限
perms & ~WRITE            // 1  —— 与非：撤销写权限
perms ^ ADMIN             // 7  —— 异或：切换管理权限

5 & 3                     // 1  —— 101 & 011
5 | 3                     // 7  —— 101 | 011
5 ^ 3                     // 6  —— 101 ^ 011
~5                        // -6 —— 按位取反，先转为 32 位有符号整数
1 << 3                    // 8  —— 左移三位
-8 >> 1                   // -4 —— 有符号右移，保留符号位
-8 >>> 1                  // 2147483644 —— 无符号右移，高位补 0
