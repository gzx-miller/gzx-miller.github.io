DOM 事件传播与事件委托

用课程列表理解捕获、冒泡、target 与 currentTarget，并用事件委托统一管理动态列表。

开场问题：课程列表里的按钮是动态渲染出来的，新加一门课就多一个按钮。给每个按钮都挂 click 监听，代码越写越乱，删掉课程时还得记住把监听器摘掉；后来改成只在外面那层容器上挂一个 click，新增、删除的按钮照样能点。一个监听器，凭什么能管住一整片会变的元素？

事件要经过三站

一次点击，并不是在目标元素上「啪」一下就结束。事件从窗口一路传下来，经过捕获阶段到达目标，再沿着原路冒泡回去——这条完整路径就是事件流。

  • 捕获阶段：从根节点向下，途经的每个元素依次收到事件，只有以 capture: true 注册的监听器才会在这里触发。
  • 目标阶段：事件到达真正触发的那个元素。
  • 冒泡阶段：从目标向上回到根，默认注册的监听器都在这一阶段触发。

冒泡这一步是后面「事件委托」得以成立的前提——正因为事件会自己向上走，父节点才有机会收到子节点的事件。

监听器的三个开关

注册监听器最常用的写法是 addEventListener(type, handler)，它的第三个参数（或 options 对象）能改变触发行为：

  • capture：在捕获阶段触发，默认 false 走冒泡。
  • once：触发一次后自动移除，适合只做一次的初始化。
  • passive：承诺这个监听器不会调用 preventDefault，常用于 scroll、touchstart，让滚动更顺。

还要把 preventDefault 与 stopPropagation 分清楚：

  • preventDefault 阻止的是默认行为（链接跳转、表单提交），事件本身仍然继续传播。
  • stopPropagation 阻止的是继续传播，默认行为该发生的还会发生。

两者管的是完全不同的两件事，混用就会漏掉一半效果。

两个不同的目标

监听器里最常被读错的是 e.target 与 e.currentTarget。前者是真正被点中的元素——可能是列表项里的一层 span 或图标；后者是挂着这个监听器的元素，无论点了内部哪个子元素，它都不变。

正因为 currentTarget 是稳定的，事件委托才有可能：你在一个不动的父容器上挂一次监听，事件里 currentTarget 永远是它，而 target 才是那个每次都在变的子元素。

一个监听器管一片

把上面两点合起来，就是事件委托：不再给每个子元素单独挂监听，而是在稳定的父节点上挂一个 handler，触发时用 e.target 判断究竟是哪一项。

判断通常分两步——先用 closest() 向上找带特征的祖先，再用 dataset 读出数据：

  • const btn = e.target.closest('button[data-id]')，找不到就 return，避免点到空隙时误判。
  • 读 btn.dataset.id 拿到这一项的标识，据此分派业务。
  • 动态增删子节点自动受益：新按钮不需要重新绑定，删掉的元素也不会留下悬空的监听器。

这正好回答了开头的问题：监听器挂在稳定的父节点上，里面的元素怎么变都不影响它。

不冒泡的那些事件

委托依赖冒泡，可偏偏有几个事件天生不冒泡：focus、blur、scroll。它们在目标上触发后不会向上传递，父节点上的冒泡监听器收不到。

办法是改用捕获阶段：把父级监听器注册成 capture: true，事件在向下传递的捕获阶段就会经过父节点，委托照样成立。

最后是关于移除：removeEventListener 必须传入与注册时同一个函数引用，匿名函数是摘不掉的。委托的额外好处正是监听器数量骤减，需要移除的也就少了；如果监听器是在 setup 或挂载时加的，记得在卸载的生命周期里用同一个引用把它摘掉。

动态列表的委托验证

把监听器提到父节点

事件流是「捕获 → 目标 → 冒泡」的一条路径，addEventListener 的 options 决定监听器落在哪一段、触发几次；preventDefault 与 stopPropagation 分别管默认行为与传播；target 是真正触发的元素，currentTarget 是挂监听器的元素。把监听器集中到稳定的父节点、用 closest 与 dataset 分派，就是事件委托——它用一个监听器接住一整片会变的子元素，代价小、维护成本低；遇到 focus、blur、scroll 这类不冒泡的事件，改走捕获阶段即可。

「事件委托」指不在每个子元素上分别注册监听器，而是利用事件冒泡，在稳定的父节点上注册一个监听器，触发时用 event.target 配合 closest() 找到真正被操作的子元素，再用 dataset 读出它的数据来分派。它天然适配动态增删的子节点，也大幅减少监听器数量；对 focus、blur、scroll 等不冒泡的事件，则需改在捕获阶段监听。

关键代码

JavaScript
// ═══════════════════════════════════════════
// 0. 取几个稳定的父节点与子节点
// ═══════════════════════════════════════════

const parent = document.querySelector('#parent')
const child = document.querySelector('#child')
const list = document.querySelector('#list')
const link = document.querySelector('#link')
const el = document.querySelector('#el')
const log = []

// ═══════════════════════════════════════════
// 1. 事件流的三站：捕获 → 目标 → 冒泡
// ═══════════════════════════════════════════

parent.addEventListener('click', () => log.push('parent 捕获'), true)   // 捕获阶段
child.addEventListener('click', () => log.push('child 目标'))           // 目标阶段
parent.addEventListener('click', () => log.push('parent 冒泡'))         // 冒泡阶段
child.click()                                                           // 顺序：parent 捕获 → child 目标 → parent 冒泡

// ═══════════════════════════════════════════
// 2. 第三个参数与 options
// ═══════════════════════════════════════════

el.addEventListener('click', handler)                        // 默认在冒泡阶段触发
el.addEventListener('click', handler, { capture: true })     // 改到捕获阶段触发
el.addEventListener('click', handler, { once: true })        // 触发一次后自动移除
el.addEventListener('scroll', onScroll, { passive: true })   // 承诺不调用 preventDefault

// ═══════════════════════════════════════════
// 3. preventDefault 与 stopPropagation 的区别
// ═══════════════════════════════════════════

link.addEventListener('click', (e) => e.preventDefault())        // 阻止默认跳转，事件仍继续传播
parent.addEventListener('click', (e) => e.stopPropagation())     // 阻止继续冒泡，默认行为照常
el.removeEventListener('click', handler)                         // 移除监听器：必须传同一个函数引用

// ═══════════════════════════════════════════
// 4. target 与 currentTarget
// ═══════════════════════════════════════════

list.addEventListener('click', (e) => {
  e.target.name          // ''        ← 真正被点中的元素，可能是列表项里的 span
  e.currentTarget.id     // 'list'    ← 挂着监听器的元素，永远是 list
})

// ═══════════════════════════════════════════
// 5. 事件委托：一次监听，分派多个子节点
// ═══════════════════════════════════════════

list.addEventListener('click', (e) => {
  const btn = e.target.closest('button[data-id]')   // 向上找到带 data-id 的按钮
  if (!btn) return                                    // 点在空中，直接返回
  console.log(btn.dataset.id)                         // '42'  ← dataset 读取 data-id
})
// 之后动态 push 的新按钮，无需重新绑定，点击照样命中这个监听器

// ═══════════════════════════════════════════
// 6. 不冒泡的事件要借助捕获阶段
// ═══════════════════════════════════════════

parent.addEventListener('focus', onFocus, true)      // focus / blur 不冒泡，用 capture 在父级监听
parent.addEventListener('scroll', onScroll, true)    // scroll 也不冒泡，同理改走捕获阶段
