模板字面量与标签模板

用标签模板实现文本高亮与 HTML 转义，掌握原始字符串和 DSL 构建。

开场问题：一条通知文案写成 '欢迎 ' + name + '，你有 ' + count + ' 条消息'，两个引号、两个加号、两个空格，少写一个就少个空格；更麻烦的是这条文案还要换行、还要把用户昵称拼进 HTML 提示框——有没有一种字符串，能像写文档一样直接把变量嵌在句子中间？

通知文案插值需求

你在写站内通知：文案里要插用户名和消息数，要分两行显示，点开还是一条带粗体昵称的 HTML 提示。用加号拼接的写法，问题不在「能不能拼出来」，而在拼接的边界全都靠人眼数：哪段是静态文字、哪段是变量、空格到底有没有漏，读代码的人得逐个加号对过去。

更深的隐患在于转义。你打算拼一段 HTML，把用户昵称放进粗体标签里：'<b>' + name + '</b>'。可昵称是用户自己填的，如果它本身就是一段带尖括号的脚本片段呢？加号拼接会把用户输入原封不动地塞进 HTML，浏览器照单执行——这就是 XSS。也就是说，拼接不仅难读，还把「哪些内容需要转义」这件事完全交给了你手动记忆。

加号拼接实现

最直接的答案就是那个老办法：用 + 把字符串和变量一段段接起来。它确实能工作，而且是纯字符串运算，没有副作用，也不需要任何新语法——在只有一两个变量的短文案里，这套写法简单到不值一提。

这个方案对的地方在于：它清楚地划出了一条边界——静态文本和动态值可以自由组合成一条输出。这条边界要保留，只是「怎么组合」可以更省心。

拼接可读性缺陷

  • 多行文本只能用 \n 拼，源码里的缩进一旦带进来，缩进空格也会变成文案的一部分。
  • 变量一多，引号和加号交织在一起，到底哪里少了一个空格、哪里多了一个引号，光看代码看不出来。
  • 用 + 拼接的 HTML 没有任何自动转义，用户昵称里的尖括号会直接变成可执行的标签。
  • 文案要复用、要统一改成模板时，散落的加号片段没法集中管理，想抽成一个「格式化函数」也找不到合适的切入口。

模板字面量与插值

第一步，换掉引号。用反引号写字符串，就得到模板字面量：换行直接回车即可，不必写 \n；变量用 ${} 插进去，里面可以放任意表达式，不限于变量名。`欢迎 ${name}，你有 ${count} 条消息` 把句子和值放在一起读，边界一眼可见。

但真正有意思的机制藏在下一步。如果不直接调用，而是把模板字面量当作参数「贴到」一个函数前面，这个函数就会变成所谓标签函数，而模板的静态部分和动态部分会被拆成两份交给它：第一个参数 strings 是字符串片段组成的数组，其余参数 values 是各个插值的值。函数拿到这两份材料之后，可以自己决定怎么拼。

这个「拆开再拼」的动作，就是一切文本 DSL 的入口。函数在拼接之前可以逐个检查每个插值，于是转义、加粗、翻译、高亮都能在这里完成。一个最典型的应用是国际化：把文案里的中文标签当成插值传进去，标签函数按当前语言查到对应词再拼回来，一条模板就能同时输出中英文。这里有个必须记住的数量关系——字符串片段的数量恒等于插值数量加一，因为每个插值两侧都有静态文本把句子隔开。

标签模板不会自动转义。它只是把插值原样交给你，如果你在标签函数里直接把插值拼进 HTML，XSS 风险一点没少。正确做法是在标签函数内部对每个插值做转义，把尖括号等特殊字符处理掉再拼——重点在于「转义这件事终于有了一个统一的发生地点」。

如果只想要「原样文本」而不想让 \n 这类转义生效，可以直接用内置标签 String.raw：它取到的是未经转义的原始片段，写正则、写路径时特别顺手。此外，片段数组还通过 strings.raw 保留了原始版本，于是工具不仅能拿到「插值了哪些值」，还能拿到「静态文本长什么样」，这正是它能解析出模板结构、进而高亮语法或校验查询的原因。styled-components 与 graphql-tag 这类库，本质就是各自写了一个标签函数。

标签模板与原始文本

插值与标签模板

模板字面量解决的是「把变量嵌进文本」的可读性问题，而标签模板更进一步，把「拼装文本」这件原本散落在加号之间的事，收拢成了可以集中控制的一道工序。插值和静态片段被拆成两份材料交给你，转义、翻译、高亮于是第一次有了统一的发生地点。

「模板字面量」指用反引号书写的字符串，支持多行文本与 ${表达式} 形式的插值。「标签模板」指把模板字面量直接贴在一个函数后面调用，函数收到 strings 字符串片段数组与若干 values 插值，两者数量满足「片段数等于插值数加一」；它默认不转义插值，HTML 转义、国际化、语法高亮、CSS-in-JS 与 GraphQL 查询等 DSL 都建立在这个机制之上，String.raw 则用于获取不解析转义符的原始字符串。

关键代码

JavaScript
// ========== 模板字面量基础 ==========
const name = 'Vue3 实战'
const price = 299

// 插值表达式：可嵌入任意 JS 表达式
const info = `课程《${name}》现价 ¥${price}，省 ${500 - price} 元`

// 多行字符串：无需手动拼接
const html = `
  <div class="card">
    <h3>${name}</h3>
    <p>价格：¥${price}</p>
  </div>
`

// ========== 标签模板 ==========
// 函数签名：(strings, ...values)
// strings：静态部分数组（长度 = values.length + 1）
// values：插值部分数组
function highlight(strings, ...values) {
  return strings.reduce((result, str, i) => {
    const val = values[i] !== undefined ? `<mark>${values[i]}</mark>` : ''
    return result + str + val
  }, '')
}

const course = 'TypeScript'
const score = 95
console.log(highlight`学员在 ${course} 考试中取得了 ${score} 分！`)
// 学员在 <mark>TypeScript</mark> 考试中取得了 <mark>95</mark> 分！

// ========== HTML 转义标签模板 ==========
function safeHtml(strings, ...values) {
  const escape = (s) => String(s)
    .replace(/&/g, '&amp;').replace(/</g, '&lt;')
    .replace(/>/g, '&gt;').replace(/"/g, '&quot;')
  return strings.reduce((result, str, i) =>
    result + str + (values[i] !== undefined ? escape(values[i]) : ''), '')
}

const userInput = '<script>alert("xss")</script>'
console.log(safeHtml`<p>用户输入：${userInput}</p>`)
// <p>用户输入：&lt;script&gt;alert(&quot;xss&quot;)&lt;/script&gt;</p>

// ========== String.raw ==========
// 获取原始字符串，转义字符不被处理
console.log(String.raw`\n \t \\`)  // 字面量 \n \t \\（不是换行和制表符）
