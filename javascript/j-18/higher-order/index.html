高阶函数、柯里化与组合

用函数组合构建价格计算器，掌握柯里化、偏函数和防抖节流。

开场问题：课程价格的算法是「先打八折、再加 6% 税、最后格式化」，可运营商这个月要改折扣率、下个月想加一条满减——每次改规则都要动那段主计算函数，为什么「打八折」这件事不能像变量一样先存起来，随手传给别人用？

定价规则拆解

你在写一个课程价格计算器。定价规则不是一句话能说清的：先按会员等级打折，再按地区加税，最后统一格式化成「¥199.00」。更麻烦的是，规则本身还会变——运营要调折扣、要临时加满减、要按活动叠加优惠。你真正想要的能力不是「算一次价格」，而是把折扣、加税、格式化这些步骤像积木一样拼起来，改了哪块只换哪块。

如果只会写「一个函数干完全部活」的代码，代价是明显的：每加一条规则就要回头改主函数，主函数的参数列表越拉越长，某一步想单独测试或者复用到别处，都做不到。规则和数据缠在一起，你就没法单独验证「打八折」到底对不对。

单步函数拆分

最自然的做法是先把每一步拆成独立的普通函数：applyDiscount(price, rate) 负责打折，addTax(price, rate) 负责加税，formatPrice(price) 负责格式化，再在计算函数里按顺序依次调用。

这个方案做对了一件很重要的事：它把「一个步骤」变成了一个可命名、可单独测试的独立单位。每个函数只关心自己的换算，输入一个数、输出一个数，逻辑干净。这一步的拆分必须保留，问题只在于接下来怎么把这些单位组装起来。

重复传参与硬编码

  • 每调用一次 applyDiscount 都要重复传一遍 rate。「打八折」这条已经确定下来的规则，却每次都得重新交代一次参数。
  • 三步的顺序被硬编码在计算函数的三行调用里。想插一条「满减」，又得回去改主函数。
  • 想复用「打八折」这个动作，只能复制那段带参数的调用，规则一变，散落各处的 0.2 全得改。
  • 到了搜索框这种高频场景，问题更明显：用户每敲一个字就发一次请求，300 毫秒里敲八个字就是八次网络请求，服务器和列表都在抖。

柯里化与函数组合

先解决「规则要重复交代参数」这一点。如果把函数写成一次只接收一个参数、每接收一个就返回一个新函数，那么「打折」就可以分两步完成：先喂给它折扣率，得到一个「已经记住八折的函数」，再把这个函数喂给任意价格。

const applyDiscount = (rate) => (price) => price * (1 - rate)，于是 const discount20 = applyDiscount(0.2) 就是一个只等价格的函数，discount20(200) 得到 160。这种把多参数函数拆成一串单参数函数的技术叫柯里化，它最大的价值是让配置和计算分开：折扣率在配置阶段就固定下来，之后反复调用不必再传。

回头看，随手在函数里返回一个函数、或者接收一个函数当参数，这件事本身有个名字：高阶函数。其实你早就在用它了——map 接收一个转换函数、filter 接收一个筛选函数、reduce 接收一个收敛函数，它们都是高阶函数，只是我们用得太顺手而没留意。

接着解决「顺序被硬编码」。既然每一步都是「一个数进、一个数出」的函数，就可以写一个组合器把若干单步函数串成一条流水线：pipe 从左到右依次执行，compose 从右到左依次执行。价格计算于是变成一句声明：

pipe(applyDiscount(0.2), addTax(0.06), formatPrice)(200)

要加满减，就在中间插一个函数；要换折扣，只改 applyDiscount 的参数。这里有一条必须记牢的规则：pipe 与 compose 的方向恰好相反，同一个项目里混用两种风格时，先确认你写的是哪一种，否则会得到「先加税再打折」这种看似对、实则错的结果。

最后解决高频调用。搜索联想、窗口滚动、按钮连点这类事件，触发频率远高于我们真正需要的处理频率，于是有了两个控制执行节奏的包装函数：

  • 防抖：事件停手一段时间后才执行一次。适合搜索联想——用户还在打字就不发请求，停下来的那一刻才发。
  • 节流：在固定时间间隔内至多执行一次。适合滚动、拖拽——不管触发多密，保证一段时间内只处理一次。

它们和柯里化一样，都是「包一层、返回一个新函数」，调用方拿到的是增强后的函数。这里有个使用上的细节：既然返回的是新函数，需要取消时就得先把返回值存下来，再调用它的 cancel；如果当场用完就丢，组件卸载时那个还在计时的防抖任务就没有办法清理了。

流水线组合与防抖

一等函数与抽象

高阶函数、柯里化、组合、防抖节流，说的其实是同一件事：把函数当作可以传递、可以拼装的值。柯里化让配置与计算分离，流线组合让步骤可以自由增删，防抖节流让执行时机可以被控制——它们都不改变数据本身，只重新组织函数的调度方式。

「高阶函数」指接收函数作为参数、或返回函数的函数，map、filter、reduce 都是代表。「柯里化」把多参数函数改写成一串单参数函数，如 (rate) => (price) => ...，便于先固定配置再重复计算。「组合」用 pipe（自左向右）或 compose（自右向左）把单步函数串成流水线。「防抖与节流」都返回新函数以控制执行频率：防抖在停止触发后执行一次，节流保证固定间隔内至多执行一次，需要取消时保存返回值再调用其 cancel。

关键代码

JavaScript
// ========== 高阶函数 ==========
// 高阶函数：接收函数作为参数，或返回函数
const courses = [
  { name: 'Vue3 入门', price: 199, students: 1200 },
  { name: 'Node 实战', price: 299, students: 800 },
  { name: 'TypeScript', price: 149, students: 2000 },
]

// map / filter / reduce 本身就是高阶函数
const names = courses.map((c) => c.name)           // ['Vue3 入门', 'Node 实战', 'TypeScript']
const popular = courses.filter((c) => c.students > 1000)
const total = courses.reduce((sum, c) => sum + c.price, 0) // 647

// ========== 柯里化 ==========
// 将多参数函数转换为单参数链
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) return fn(...args)
    return (...more) => curried(...args, ...more)
  }
}

const add = (a, b, c) => a + b + c
const curriedAdd = curry(add)
console.log(curriedAdd(1)(2)(3))  // 6
console.log(curriedAdd(1, 2)(3))  // 6

// ========== 偏函数 ==========
// 固定部分参数，生成新函数
const multiply = (a, b) => a * b
const double = multiply.bind(null, 2)
console.log(double(5))  // 10

// ========== 函数组合 ==========
// pipe：从左到右执行；compose：从右到左执行
const pipe = (...fns) => (x) => fns.reduce((v, fn) => fn(v), x)
const compose = (...fns) => (x) => fns.reduceRight((v, fn) => fn(v), x)

const discount = (p) => p * 0.8
const tax = (p) => p * 1.06
const format = (p) => `¥${p.toFixed(2)}`

console.log(pipe(discount, tax, format)(200))  // '¥169.60'

// ========== 防抖与节流 ==========
function debounce(fn, delay) {
  let timer
  return (...args) => {
    clearTimeout(timer)
    timer = setTimeout(() => fn(...args), delay)
  }
}

function throttle(fn, interval) {
  let last = 0
  return (...args) => {
    const now = Date.now()
    if (now - last >= interval) { last = now; fn(...args) }
  }
}
