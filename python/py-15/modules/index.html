模块、包与导入机制

从「模块是对象」出发，掌握 import 的各种写法、包与 __init__.py、绝对/相对导入与导入陷阱。

开场问题：你把工具函数放进 utils.py，在 main.py 里写下 import utils，运行 python main.py 一切正常；可同一段代码换成 python -m main 就跑不通了。代码一个字没改，为什么换一种运行方式，导入就会失败？

先看最朴素的做法

一开始谁都不需要「包」，把代码全写进一个文件最省事。import math、import random 引进来，直接调用即可，不需要任何目录结构：

  • import math：把整个 math 模块对象绑定到名字 math，用时写 math.sqrt(16)。
  • from math import sqrt：只把 sqrt 这一个函数绑进来，写起来短，但看不出它来自哪里。
  • import math as m：同一模块换个短名字，m.sqrt(16) 一样能用，这是 import numpy as np 那种惯例的来源。

单文件脚本阶段，这些写法够用。可代码一旦长大，一个文件塞不下，你就得拆成多个文件、放进多个目录——于是问题来了：拆开之后，谁引用谁、从哪里能找到谁，都需要一套约定。

模块就是对象：导入只是绑定一个名字

拆文件之后要先接受一个事实：一个 .py 文件就是一个模块对象。文件里定义的函数、类、变量，都是这个对象的属性。import utils 做的事情，只是把 utils 这个名字绑定到那个模块对象上——和 x = 42 绑定一个整数没有本质差别。

理解了这一点，前面那个开场问题就有了线索。Python 导入模块时，不是只看你能不能 import，它还要确定模块在包层级里叫什么名字。用 python main.py 直接运行，main 被当成顶层脚本，utils 就在旁边，找得到；用 python -m main 运行时，入口变成了包，模块的真实名字带上包前缀，若你写的仍是顶层导入，名字就对不上了。

`if __name__ == '__main__'` 到底在判断什么

每个模块都有一个内置属性 __name__。当文件被导入时，__name__ 就是这个模块名（例如 'utils'）；当文件被直接运行时，__name__ 会被设成字符串 '__main__'。于是常见写法： 

if __name__ == '__main__':
    main()

它的作用是把「脚本入口」和「可被复用的模块」分开：被别的模块导入时，main() 不会自动执行，只提供函数；只有你自己直接运行这个文件时，它才作为入口跑起来。少了这个判断，导入时会顺手执行业务逻辑，甚至触发副作用。

包与 `__init__.py`：目录如何变成包

当一个功能需要多个文件协同时，就把它们放进一个目录。这个目录只要带上 __init__.py（内容可以是空的），就被视为一个包，可以按层级被导入。__init__.py 还承担两个角色：包被导入时会先执行它（可以做初始化），以及可以用 __all__ 声明「允许 from 包 import * 导出哪些名字」。

  • __all__ = ["slugify", "normalize"]：只影响 import * 的通配范围，写清楚后别人就不会意外拿到内部实现。
  • 导入一行 from myapp.utils import slugify，会依次触发 myapp/__init__.py、myapp/utils/__init__.py 的执行。

绝对导入与相对导入：两种写法的分寸

绝对导入从包的顶层写起，路径完整，from myapp.utils import slugify 放之四海皆准；相对导入用点号省略前缀，from .utils import slugify 里的 . 表示当前包，.. 表示上一层包。

相对导入更短、重构目录时不易跟着改错，但它只能在包内部使用：如果把含相对导入的模块直接当脚本运行，Python 根本不知道「当前包」是谁，就会抛出 ImportError: attempted relative import with no known parent package——这正是开场问题里 python main.py 失败的另一半原因。

查找路径、副作用与循环导入

导入一个名字时，解释器按 sys.path 里的顺序去各目录搜索：当前脚本目录、PYTHONPATH、安装目录等，先命中哪个就用哪个。这带来第一个陷阱：自己起的文件名不要和标准库重名，一个手写的 random.py 会把自己的目录排在前面，反而「抢走」标准库的 random。

第二个陷阱是导入副作用：导入一个模块会从上到下执行它的顶层代码。如果顶层直接连数据库、读文件、发起请求，那么每次导入都会真实发生这些动作。把这类动作收进函数、用 if __name__ == '__main__' 守住，是常规防御。

循环导入：a.py 导入 b.py、b.py 又导入 a.py，常表现为拿不到某个名字（ImportError: cannot import name ...）。根因是相互依赖到了「谁先执行完都不行」的地步。拆出公共依赖、把顶层导入改为函数内延迟导入，或调整模块职责，是常见解法。

看一遍导入方式与包结构

一句话收敛

模块是对象，导入是把名字绑定到模块对象上；拆成目录后要靠 __init__.py 立成包，用绝对导入走全局路径、用相对导入走包内相对路径；再用 if __name__ == '__main__' 区分「入口脚本」与「被导入的模块」，就能避开查找路径、导入副作用和循环导入这几类常见坑。

「导入系统」指 Python 通过 sys.path 搜索、加载模块并缓存到 sys.modules 的机制。边界与例外：同一模块只在首次导入时执行一次，之后导入直接复用缓存；相对导入依赖模块已知的包上下文，脱离包直接运行会报错；__all__ 仅约束 import *，不影响其他显式导入。

关键代码

PYTHON
# ═══════════════════════════════════════════
# 1. 三种导入写法各自绑定什么名字
# ═══════════════════════════════════════════

import math                        # 名字 math 绑定到整个模块对象
print(math.sqrt(16))               # 结果：4.0，用「模块名.成员」访问

from math import pi                # 只把 pi 这一个名字绑进当前命名空间
print(pi)                          # 结果：3.141592653589793，无需模块前缀

import statistics as stats         # as 给模块起一个短别名
print(stats.mean([1, 2, 3, 4]))    # 结果：2.5

# ═══════════════════════════════════════════
# 2. 模块是对象：查看 __name__ 与缓存
# ═══════════════════════════════════════════

import sys

print(__name__)                    # 结果：__main__（本文件被直接运行时）
print(math.__name__)               # 结果：math，模块自报的名字
print("math" in sys.modules)       # 结果：True，导入过的模块会被缓存
print(len(sys.path) > 0)           # 结果：True，sys.path 是模块的搜索路径列表

# ═══════════════════════════════════════════
# 3. if __name__ == "__main__"：入口与模块分离
# ═══════════════════════════════════════════

def run_demo() -> str:
    return "只有直接运行本文件时，这段逻辑才会执行"

if __name__ == "__main__":
    # 被别的模块 import 时，__name__ 不是 "__main__"，这段不会跑
    # 因此导入本模块不会有副作用，只提供可复用的函数
    print(run_demo())              # 结果：只有直接运行本文件时，这段逻辑才会执行

# ═══════════════════════════════════════════
# 4. 包的 __init__.py 与 __all__ 导出范围
# ═══════════════════════════════════════════

# 真实包结构示例（myapp/ 目录下）：
#   myapp/__init__.py      ->  __all__ = ["slugify"]
#   myapp/utils/__init__.py
#   myapp/utils/slugify.py ->  def slugify(text): ...

__all__ = ["run_demo"]             # 只影响 from this import * 的导出范围
print(__all__)                     # 结果：['run_demo']

# ═══════════════════════════════════════════
# 5. 包内相对导入示意（需在包内运行才成立）
# ═══════════════════════════════════════════

RELATIVE_SAMPLE = """
# 位于 myapp/main.py 内部时：
from .utils import slugify          # . 表示当前包 myapp
from ..models import User           # .. 表示上一层包
# 直接把 main.py 当脚本运行会报错：
# ImportError: attempted relative import with no known parent package
"""
print(RELATIVE_SAMPLE.strip().splitlines()[1].split("#")[0].strip())  # 结果：from .utils import slugify

# ═══════════════════════════════════════════
# 6. 查找路径与同名文件抢占的陷阱
# ═══════════════════════════════════════════

print(sys.path[0])                 # 结果：脚本所在目录（排在搜索顺序最前）
print(hasattr(math, "sqrt"))       # 结果：True，正常导入到的是标准库 math
# 若当前目录存在自写的 math.py，它会排在标准库之前，把真正的 math“抢占”掉
