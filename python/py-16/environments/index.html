虚拟环境与依赖管理

用虚拟环境隔离项目依赖，掌握创建与激活、requirements.txt 与 pyproject.toml 的分工。

开场问题：你本地 pip install requests 明明装好了，脚本跑得好好的；同事把代码 clone 下来一运行，却报 ModuleNotFoundError: No module named 'requests'。同一个仓库、同一个命令，为什么他那边就是缺包？

先看最朴素的做法

新手最常见的操作，就是打开终端直接敲 pip install requests。命令立刻成功，import requests 也马上能用，看起来没有任何问题。问题是：这个包装进了哪里——它进了你机器上那一个全局的系统 Python，而不是「这个项目」。

于是麻烦会陆续出现：项目 A 要 flask==2.0，项目 B 要 flask==3.0，而全局环境只有一个，装 B 就顶掉 A；升级系统工具时 pip 可能误改系统自带包，把系统 Python 弄坏；换一台机器，别人根本不知道你到底装了哪些包、什么版本——上面那个开场问题就发生了。

给项目一间独立的房间：虚拟环境

虚拟环境（virtual environment）的思路很直白：为每个项目单独建一份「只属于它」的 Python 环境，里面有一套独立的 site-packages。项目 A 的 flask 2.0 和项目 B 的 flask 3.0 各住各的房间，互不干扰；删掉这个目录，就等于把这个项目的所有依赖一并抹掉，系统 Python 毫发无损。

  • 系统 Python 保持干净，只负责运行解释器本身。
  • 项目依赖彼此隔离，版本冲突不再传染。
  • 环境可以随时重建，配合清单就能在别人机器上一字不差地复现。

创建与激活：`python -m venv` 加一条激活命令

Python 自带 venv 模块，不用额外安装。python -m venv .venv 会在项目目录下生成一个 .venv 文件夹，把解释器与独立的包目录都装进去。创建只是第一步，之后必须激活，让当前终端里的 python 和 pip 都指向这份环境：

  1. 创建：python -m venv .venv。
  2. 激活（Windows）：.venv\Scripts\activate；激活（macOS/Linux）：source .venv/bin/activate。
  3. 确认：命令行提示符前出现了 (.venv)，说明已经进入。
  4. 退出：deactivate，随时回到系统环境。

一个容易忽略的点：没激活时敲 pip install，装的是系统 Python。「我装了但没生效」多半就是漏了激活，或者终端重启后忘了重新激活。

把依赖写下来：pip install 与 requirements.txt

环境建好了，装包还是 pip install requests，只不过现在装进的是当前虚拟环境。pip 会自动把依赖树里的包一并装上（例如 requests 会带上 urllib3、certifi）。但「装过」不等于「可复现」——别人怎么知道你装了哪些、哪个版本？答案是把它冻结成清单： 

pip freeze > requirements.txt   # 导出当前所有包及其精确版本
pip install -r requirements.txt # 在别的环境按清单一次性还原

requirements.txt 记的是精确版本（如 requests==2.31.0），好处是任何人都能装到同一套版本，坏处是它把间接依赖也钉死了，升级时清单会显得臃肿。它适合「已经定型的部署环境」。

声明依赖的现代表达：pyproject.toml

现代 Python 项目更推荐在 pyproject.toml 里声明依赖，而不是记录一堆精确版本。你写的是版本范围与意图，例如 requests>=2.31、flask~=3.0，由 pip 或构建工具去解析出满足条件的版本；还能用 [project.optional-dependencies] 区分运行依赖与开发依赖。

这两者并不冲突：pyproject.toml 表达「我允许哪些版本」，再用一份锁文件把这一次解析出来的精确版本固定下来，兼顾灵活与可复现。理解「声明范围」和「锁定结果」的区别，是依赖管理真正成熟的分界线。

工具生态与一条底线

围绕环境与依赖，社区还发展出一批工具，各管一段：pyenv 管理「用哪个 Python 版本」（3.10 还是 3.12）；venv 管理「项目内的隔离环境」；pip 负责安装；uv、poetry、pdm 则把环境、依赖解析与锁定打包成一站式体验，速度与体验各不相同。

一条底线：不要往系统 Python（尤其是 Linux 的系统解释器）里直接装业务依赖。所有业务包都应装进项目自己的虚拟环境。这样升级系统、迁移机器时，最坏也只是重建环境，而不会把机器本身搞坏。

看一遍环境流程与清单对照

一句话收敛

虚拟环境为每个项目提供一套隔离的依赖目录，用 python -m venv 创建、激活后 pip 才会作用于它；requirements.txt 冻结精确版本用于复现，pyproject.toml 声明版本范围用于表达意图，两者配合才能真正「换台机器也装得一模一样」。始终把业务依赖装进项目环境，是一条不能破的底线。

「虚拟环境」指一份独立于系统 Python 的、带有专属 site-packages 的解释器环境。边界与例外：环境必须激活后 pip 与 python 才指向它；未激活时安装会落到系统环境；重建环境是安全的，因为它只是一个可删除的目录；不同项目之间的环境不会互相影响。

关键代码

PYTHON
# ═══════════════════════════════════════════
# 1. 判断当前是否运行在虚拟环境里
# ═══════════════════════════════════════════

import sys

sys_prefix = sys.prefix                 # 当前解释器使用的环境前缀
base_prefix = sys.base_prefix           # 底层系统 Python 的前缀

in_venv = sys_prefix != base_prefix     # 两者不同即说明处在虚拟环境
print(in_venv)                          # 结果：True 或 False，取决于是否已激活
print(sys.prefix)                       # 结果：激活时是 /path/to/.venv，否则是系统路径

# ═══════════════════════════════════════════
# 2. 解释器版本与模块搜索路径
# ═══════════════════════════════════════════

print(sys.version.split()[0])           # 结果：如 3.12.2，当前解释器版本
print(sys.executable)                   # 结果：当前使用的 python 可执行文件路径
print(len(sys.path) > 0)                # 结果：True，sys.path 决定到哪些目录找模块
print(sys.path[:2])                     # 结果：前两项通常是脚本目录与标准库目录

# ═══════════════════════════════════════════
# 3. 创建 / 激活虚拟环境的命令流程
# ═══════════════════════════════════════════

VENV_COMMANDS = """
# 创建：在项目目录生成独立的 .venv
python -m venv .venv

# 激活（Windows）
.venv\\Scripts\\activate
# 激活（macOS / Linux）
source .venv/bin/activate

# 安装与冻结：此时 pip 只影响本项目环境
pip install requests
pip freeze > requirements.txt

# 退出
deactivate
"""
print(VENV_COMMANDS.strip().splitlines()[1])   # 结果：python -m venv .venv

# ═══════════════════════════════════════════
# 4. 依赖清单：声明范围与锁定精确版本
# ═══════════════════════════════════════════

REQUIREMENTS_LOCKED = [
    "requests==2.31.0",                 # 冻结后的精确版本，可复现
    "flask==3.0.0",
    "urllib3==2.1.0",
]

PYPROJECT_RANGE = [
    "requests>=2.31",                   # 版本范围，表达可接受的区间
    "flask~=3.0",
]

def parse_pinned(lines: list[str]) -> dict[str, str]:
    pairs = (line.split("==") for line in lines)
    return {name: version for name, version in pairs}

print(parse_pinned(REQUIREMENTS_LOCKED)["flask"])   # 结果：3.0.0
print(PYPROJECT_RANGE[0])                            # 结果：requests>=2.31

# ═══════════════════════════════════════════
# 5. 判断并给出提示
# ═══════════════════════════════════════════

def env_tip(in_venv: bool) -> str:
    if in_venv:
        return "已激活虚拟环境，pip install 只会影响本项目"
    return "警告：未激活虚拟环境，别再往系统 Python 里装业务依赖"

print(env_tip(in_venv))     # 结果：随当前环境状态而变
