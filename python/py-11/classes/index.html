类与对象

掌握 class、__init__ 与 self，分清实例属性与类属性，以及 @classmethod / @staticmethod 的用途。

开场问题：有三个课程对象，都想共享同一个 school 名字。于是把 school = '小松鼠学院' 写进了类里，又在某个实例上调了一次 course.school = '新名字'。奇怪的是，另外两个实例身上的 school 却纹丝不动。同一个名字，怎么在两处表现不一样？

先看最朴素的做法

要表示一门课程，最直接的办法是用字典：{'name': 'Python 入门', 'hours': 12}。几个字段、一下就能拼出来，读也行、改也行，小脚本里够用。

数据一多就露出破绽：字典只是松散的一组键值，它不知道「课程」意味着什么，也无法把「加一学时」这类动作固定下来。于是每处都用 course['hours'] += 1 这样的裸操作，字段名写错、结构不一致全要到运行时才发现。数据和行为被拆散了，缺少一个把两者捆在一起的东西。

class 与 __init__、self

class 就是那个把数据和行为捆在一起的东西。类里定义一个特殊方法 __init__，它会在创建对象时自动被调用，用来把初始值放进对象：Course('Python 入门', 12) 一执行，__init__ 就拿到这两个参数。

__init__ 的第一个参数是 self，代表正在被创建的那个对象。Python 调用时会自动把对象传进来，你只需写方法定义、不必在调用处手动传。self.name = name 的含义是「把这个对象自己的 name 设成传入的 name」。

实例属性与类属性

同样是写在类里的名字，位置不同，归属就不同：

  • 实例属性：写在方法里、以 self.x = ... 的形式赋值，属于每个对象各自一份。改一个实例的属性，不影响别的实例。
  • 类属性：直接写在类体里、不在任何方法内，属于类本身，被所有实例共享。读取时，各实例看到的是同一份。

回到开场的怪事：当 school 是类属性时，course.school = '新名字' 这句赋值并不是去改类上那份，而是在实例自己身上新建了一个同名属性，把它盖住。别的实例没有这个新属性，读取时依旧落到类属性上，于是看起来「纹丝不动」。这也正是「读共享、写独占」这条微妙规则的由来。

实例方法，以及为什么方法要 self

定义在类里、第一个参数是 self 的函数就是实例方法。它通过 obj.method() 调用时，Python 会悄悄把 obj 绑到 self 上。所以方法体里能直接读写 self 上的属性，把「操作」和「数据」自然连起来。写方法时忘了 self，调用时就会因为参数对不上而报错。

@classmethod 与 @staticmethod

除了实例方法，还有两种常见的变体，靠装饰器区分：

  1. @classmethod：第一个参数是 cls（类本身），常用来写「替代构造器」，例如 Course.from_dict(data) 从字典造对象。
  2. @staticmethod：没有 self 也没有 cls，纯粹是挂在类命名空间下的普通函数，tools 类的辅助方法适合这样放，与具体对象无关。

何时用哪个也有直觉：需要访问或创建该类的实例时用 classmethod；只借用类的名字做归类、逻辑与对象无关时用 staticmethod；要读写某个对象自己的数据时用普通实例方法。

属性查找顺序与可变类属性陷阱

访问 obj.attr 时，查找顺序是：先实例的 __dict__，找不到再查类的属性，再找不到才顺着继承链往上找。这解释了很多现象：实例没设过就落到类属性上；一旦实例自己设过同名的，就挡住类的版本。

由此要警惕一个著名陷阱：可变的类属性会被所有实例共享。比如把 tags = [] 写在类体里，任意实例 tags.append(...) 改的都是同一份列表，所有实例都跟着变。想让每个对象各自拥有一份，就应在 __init__ 里创建它，而不是依赖类属性。

常见误区：以为「实例上读到某个类属性」就等于「这个属性属于实例」。读到的值虽是共享的，但一旦在实例上赋值，就会新建实例属性、与类属性脱钩，之后二者各走各的路。

看一遍实例属性与类属性的差别

一句话收敛

class 把数据与行为捆在一起，__init__ 负责初始化、self 指向当前对象。写在 self 上的实例属性每个对象一份，写在类体里的类属性全体共享；属性查找先实例后类。用 @classmethod 访问类、用 @staticmethod 放无关工具、用普通方法读写自身数据。最后记牢：可变的类属性会被共享，每实例该独有的，请在 __init__ 里创建。

「实例属性」指绑定在某个具体对象上的属性，通常由 __init__ 中以 self.x = ... 的形式建立，各实例互不影响。边界与例外：读取属性时会先查实例再查类，因此类属性在未被实例覆盖时可被共享读取；一旦在实例上对同名属性赋值，便新建实例属性而与类属性脱钩。

关键代码

PYTHON
# ════════════════════════════════════════════
# 1. class 与 __init__、self
# ════════════════════════════════════════════

class Course:
    def __init__(self, name, hours):
        self.name = name          # 实例属性：每个对象各一份
        self.hours = hours

    def describe(self):           # 实例方法，第一个参数永远是 self
        return f"{self.name} 共 {self.hours} 学时"

python = Course("Python 入门", 12)
vue = Course("Vue3 实战", 20)
print(python.describe())          # 结果：Python 入门 共 12 学时
print(vue.name)                   # 结果：Vue3 实战


# ════════════════════════════════════════════
# 2. 实例属性 vs 类属性
# ════════════════════════════════════════════

class Student:
    school = "小松鼠学院"          # 类属性：写在类体里，全体共享

    def __init__(self, name):
        self.name = name          # 实例属性：每个对象独有的名字

a = Student("小明")
b = Student("小红")
print(a.school, b.school)         # 结果：小松鼠学院 小松鼠学院（读的是同一份类属性）

a.school = "新学院"               # 这只是给 a 新建了同名实例属性
print(a.school, b.school)         # 结果：新学院 小松鼠学院（b 依旧读类属性）
print(Student.school)             # 结果：小松鼠学院（类属性本身没变）


# ════════════════════════════════════════════
# 3. 可变类属性被共享的陷阱
# ════════════════════════════════════════════

class BadCart:
    items = []                    # 可变类属性：所有实例共享同一个列表

    def add(self, item):
        self.items.append(item)   # 说明：改的是共享的那一份

c1, c2 = BadCart(), BadCart()
c1.add("栗子")
print(c2.items)                   # 结果：['栗子']，c2 被无辜牵连


class GoodCart:
    def __init__(self):
        self.items = []           # 每个实例在 __init__ 里各自新建列表

    def add(self, item):
        self.items.append(item)

d1, d2 = GoodCart(), GoodCart()
d1.add("栗子")
print(d2.items)                   # 结果：[]，互不影响


# ════════════════════════════════════════════
# 4. classmethod 与 staticmethod
# ════════════════════════════════════════════

class Temperature:
    unit = "摄氏度"

    def __init__(self, value):
        self.value = value

    @classmethod
    def from_fahrenheit(cls, f):      # cls 指向类本身，可用来造实例
        return cls(round((f - 32) / 1.8, 1))

    @staticmethod
    def is_freezing(value):           # 与实例无关的纯工具函数
        return value <= 0

t = Temperature.from_fahrenheit(212)
print(t.value)                    # 结果：100.0
print(Temperature.is_freezing(-3))  # 结果：True


# ════════════════════════════════════════════
# 5. 属性查找顺序：先实例后类
# ════════════════════════════════════════════

print("school" in a.__dict__)     # 结果：True，a 自己也存了一份 school
print("school" in b.__dict__)     # 结果：False，b 的实例字典里没有
print(Student.school)             # 结果：小松鼠学院，类上始终保留着它
