变量、数据类型与动态类型

理解 Python 变量是「名字到对象的绑定」，掌握动态类型、可变与不可变的区别，以及类型转换与注解的边界。

开场问题：写了 a = [1, 2, 3]，又写了 b = a，接着 b.append(4)——回头看 a，它居然也变成了 [1, 2, 3, 4]。你明明只动了 b，为什么 a 跟着变？

先看最朴素的做法

Python 最让人放松的地方，是不用写类型：x = 42 一行就能开始干活，不需要像 C++ 那样先声明 int x;。写个小脚本、算个数、拼个字符串，直接上手就写，读起来也几乎没有噪音。

这份便利也埋下了第一个疑问。在 a = [1, 2, 3]、b = a 这两行里，多数人按其他语言的直觉理解为「把 a 的值复制一份给 b」。可 Python 里 b = a 没有复制——它只是让 b 这个名字指向了 a 已经指向的那个列表对象。于是 b.append(4) 改的就是同一个列表，a 自然跟着变。

变量是名字，不是盒子

要理解上面那件事，得先换一个模型。很多语言里，变量像一个盒子，赋值是把值放进盒子里，读出来就是盒子里那份值。Python 的模型不同：变量是一个名字，赋值是把名字绑定到一个已经存在的对象上。

  • a = [1, 2, 3]：创建一个列表对象，让名字 a 指向它。
  • b = a：让名字 b 指向同一个对象，没有新对象产生。
  • a = [9]：让名字 a 改指向一个新列表，而 b 仍然指向原来那个。

这套「名字绑定到对象」的模型叫对象引用语义。函数传参、容器嵌套、共享状态出问题，十有八九是把它错当成「值拷贝」来推理了。想拿到独立副本，必须显式调用 copy() 或切片 a[:]。

动态类型：便利与代价并存

既然名字只是绑定，它自然不必一辈子指向同一种类型的对象。x = 42 之后写 x = '42' 完全合法，类型在运行时随对象变化——这就是动态类型。它让原型写起来极快，也让「一份代码处理多种输入」变得自然。

代价出现在出错的时候。类型不匹配不会在写代码时被拦下，只能等到那一行真的执行：'42' + 1 会抛出 TypeError: can only concatenate str (not "int") to str。凡是「编辑器不报错、运行时才炸」的问题，根子常常就在这里：名字背后的类型没有被写清楚。

不可变与可变：修改行为的分水岭

为什么整数、字符串改起来没感觉，列表却会「牵一发而动全身」？区别在于对象可变还是不可变：

  • 不可变（int、float、str、tuple）：对象一旦创建内容就不能变。所谓「修改」其实是新建一个对象，再让名字改绑过去；原对象原封不动，其他指向它的名字看不到任何变化。
  • 可变（list、dict、set）：append、pop、update 这类操作就地修改对象本身。只要还有别的名字指向它，变化立刻对所有名字可见。

「不可变对象可以安全共享」是一条重要直觉：默认参数用 None 而不是 []、把元组当作字典键、用 frozenset 放进集合，都建立在这条性质上。

类型转换：把外部输入变成数字

程序读进来的文字永远是字符串，input() 也好、配置文件也好、HTTP 请求体也好。要用它做算术，就得显式转换：int('42') 得到 42，float('3.14') 得到 3.14，str(42) 再变回文本。

转换会在失败时抛出 ValueError，这恰恰是它的价值——它把「不可用的输入」挡在了边界上。两个容易被忽略的点：int('3.14') 会失败（要先用 float()）；bool('') 是 False，但 bool('0') 是 True，因为判断依据是「字符串是否为空」而不是它的内容像不像零。

把意图写进注解与校验

动态类型不是要放弃约束，而是把约束挪到你该负责的地方。两个实用手法：

  1. 用类型注解表达意图：def add(a: int, b: int) -> int。注解默认不做运行期强制，它的价值在于让编辑器和静态检查工具（如 mypy）替你发现类型不一致。
  2. 在系统边界做显式校验：对不可信输入用 isinstance() 或转换函数把类型「钉死」，失败就给出清晰错误，而不是让错误渗进业务流程深处。
常见误区：把 b = a 当成复制，是新手最贵的教训之一。需要独立副本时，可变对象要用 copy.copy()（浅拷贝）或 copy.deepcopy()（嵌套结构深拷贝）；不可变对象无需拷贝，共享本来就是安全的。

看一遍变量与类型的行为

一句话收敛

Python 的变量是名字到对象的绑定，类型属于对象而不属于名字，所以同一个名字可以先后指向不同类型；对象又分可变与不可变，后者「修改」即新建、可安全共享，前者就地修改会对所有引用者生效。把这三句话记住，变量共享、参数传递、容器嵌套里的大半迷惑都能自己解释清楚。

「对象引用语义」指变量保存的是指向对象的引用（名字绑定），赋值只改绑定、不复制对象。边界与例外：不可变对象因为无法就地修改，共享时看起来和「值拷贝」无异；一旦对象可变，任何一处就地修改都会通过共享引用影响所有名字，需用 copy / deepcopy 主动切断共享。

关键代码

PYTHON
# ═══════════════════════════════════════════
# 1. 变量是名字绑定到对象（引用语义）
# ═══════════════════════════════════════════

a = [1, 2, 3]                 # a 绑定到一个列表对象
b = a                          # b 绑定到同一个对象，并没有复制
b.append(4)                    # 通过 b 就地修改对象
print(a)                       # 结果：[1, 2, 3, 4]，a 也跟着变了

c = a.copy()                   # copy() 才产生一个独立的新对象
c.append(5)
print(a, c)                    # 结果：[1, 2, 3, 4] [1, 2, 3, 4, 5]

a = [9]                        # 让 a 改绑到新对象，b 不受影响
print(a, b)                    # 结果：[9] [1, 2, 3, 4]

# ═══════════════════════════════════════════
# 2. 动态类型：同一个名字可指向不同类型
# ═══════════════════════════════════════════

value = 42                     # 此刻指向 int
print(type(value))             # 结果：<class 'int'>
value = "42"                   # 重新绑定为 str，无需任何声明
print(type(value))             # 结果：<class 'str'>

try:
    total = "42" + 1           # 类型不匹配要到运行期才报错
except TypeError as error:
    print(error)               # 结果：can only concatenate str (not "int") to str

# ═══════════════════════════════════════════
# 3. 不可变类型与可变类型
# ═══════════════════════════════════════════

immutable = ("a", "b")         # 元组不可变
mutable = ["a", "b"]           # 列表可变
mutable.append("c")            # 就地修改生效
print(mutable)                 # 结果：['a', 'b', 'c']
# immutable.append("c")        # 取消注释会抛 AttributeError：元组没有 append

shared = mutable               # 共享同一个列表
shared.pop()                   # 从另一处修改
print(mutable)                 # 结果：['a', 'b']，原列表同样被改

# ═══════════════════════════════════════════
# 4. 显式类型转换
# ═══════════════════════════════════════════

print(int("42"))               # 结果：42，字符串转整数
print(float("3.14"))           # 结果：3.14，字符串转浮点
print(str(42))                 # 结果：'42'，数字转字符串
print(bool(""))                # 结果：False，空字符串为假
print(bool("0"))               # 结果：True，非空字符串恒为真
print(list("abc"))             # 结果：['a', 'b', 'c']

try:
    print(int("3.14"))         # 会抛出 ValueError
except ValueError:
    print("int() 无法直接解析小数文本")

# ═══════════════════════════════════════════
# 5. 用注解表达意图，在边界做校验
# ═══════════════════════════════════════════

def add(a: int, b: int) -> int:    # 注解只是提示，运行期并不强制校验
    return a + b

print(add(1, 2))               # 结果：3
print(add("1", "2"))           # 结果：'12'，注解并不阻止错误用法

def to_count(raw: object) -> int:
    if not isinstance(raw, (int, str)):
        raise TypeError("count 只接受 int 或 str")
    return int(raw)

print(to_count("42"))          # 结果：42，边界处把类型钉死
