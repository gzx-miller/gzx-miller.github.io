异步编程与 asyncio

用 async def 与 await 写协程，理解事件循环调度、gather/create_task 并发与 wait_for 超时。

开场问题：你用 time.sleep(1) 写了 3 次等待，程序老老实实花了 3 秒。把 sleep 换成 await asyncio.sleep(1) 后，总耗时竟然只剩 1 秒——同样的「睡 3 次」，为什么 await 能让它们重叠起来？

先看最朴素的做法

阻塞式写法最好理解：调用一个会耗时的函数，就一直等到它返回，才执行下一行。 

import time

def fetch(name):
    time.sleep(1)          # 整个线程被卡在这里
    return name

for n in ["A", "B", "C"]:
    fetch(n)               # 三次相加，约 3 秒

它的问题和上一章一样——大量时间花在等待上，而线程被 sleep 死死占住，什么也做不了。这时有人会想到开线程，但如果请求多达成百上千个，线程的创建与切换成本就不可忽视。于是 Python 提供了另一条路：让单个线程在等待时去干别的活。

协程：可以暂停和恢复的函数

协程（coroutine）是一种特殊的函数，用 async def 定义。它和普通函数最大的区别是：可以被暂停，把控制权交出去，之后再从暂停处恢复。触发暂停的关键字是 await——它后面通常跟一个「可等待对象」，表示「我在这里等，先让别人跑」。 

async def fetch(name, delay):
    await asyncio.sleep(delay)   # 挂起本协程，事件循环可去调度别的协程
    return name

请注意：await 暂停的是这个协程，而不是整个线程。线程本身仍由事件循环使用着，随即将它交给另一个准备好的协程——这正是开场问题里「3 次 sleep 只花 1 秒」的原因：三个协程几乎同时开始等待，谁先醒谁先被唤醒。

事件循环与 asyncio.run

谁在负责「暂停了就去跑别人、到点了再唤醒」？答案是事件循环（event loop）。它维护着一堆就绪/等待的任务，持续检查哪些 I/O 或定时器已经完成，再把控制权交还给对应的协程。入口很简单： 

import asyncio

async def main():
    ...

asyncio.run(main())      # 创建事件循环、运行到底、最后关闭

asyncio.run() 负责起一个事件循环并把入口协程跑完，是脚本级异步程序的唯一入口。它的位置通常在顶层，而不是嵌在别的协程里。

并发多个任务：gather 与 create_task

有了协程，怎么让它们「一起开始」？两种常用手段：

  • asyncio.gather(*coros)：把多个协程同时交给事件循环并发执行，等全部完成后按传入顺序返回结果列表。写起来最像「一次性并发」。
  • asyncio.create_task(coro)：把协程包装成一个任务并立刻排入事件循环，不等它也能继续往下写；之后可再 await task 取结果。适合「先启动、后处理」的场景。

一个常见误区：只调用 fetch() 而不 await 也不 create_task，只是创建了协程对象，并不会执行它，还会收到「coroutine was never awaited」的警告。要跑起来，必须交给事件循环。

为什么并发 I/O 更快，以及一个致命陷阱

异步的优势来自等待期间不浪费线程：一个线程就能管理成百上千个并发的网络请求，开销远小于等量线程。前提是这些任务确实是 I/O 等待（网络、磁盘），因为你等的正是「可等待」的外部事件。

别在协程里调用同步阻塞函数：如果协程里调用了 time.sleep()、同步的 requests.get() 或 open()，整个事件循环会被卡住——所有协程都停摆，异步等于白写。要用异步库（aiohttp、aiofiles）或把阻塞操作交给线程池执行。这是异步代码最容易踩的坑。

超时与取消：wait_for

异步任务等的是外部响应，就可能迟迟不回。若任由它挂着，程序会一直卡住。asyncio.wait_for(coro, timeout) 给等待设上限：超过时限还没完成，就取消该协程并抛出 asyncio.TimeoutError，由你决定重试还是报错。给所有外部调用都加上超时，是异步程序的必备防御。

看一遍事件循环调度

一句话收敛

用 async def 定义协程、await 在等待点交出控制权，由事件循环在单个线程里调度成百上千个并发 I/O；asyncio.run 启动循环，gather 一次性并发、create_task 先启动后等待，wait_for 为等待设上限。切记不要在协程里调用同步阻塞函数，否则事件循环会被一起卡死。

「事件循环」是 asyncio 的核心调度器，负责在单线程内维护就绪与等待中的协程，在 I/O 就绪或定时到期时唤醒对应的协程继续执行。边界与例外：事件循环本身跑在一个线程里，任何同步阻塞调用都会让它停摆；协程必须被 await 或包装成 task 才会真正执行；并发只对 I/O 等待有效，对纯计算没有帮助。

PYTHON
# ═══════════════════════════════════════════
# 1. async def 与 await：可以暂停的协程
# ═══════════════════════════════════════════

import asyncio
import time

async def fetch(name: str, delay: float) -> str:
    await asyncio.sleep(delay)        # 挂起本协程，控制权交回事件循环
    return f"{name} 完成于 {delay}s"

async def serial() -> list[str]:
    results = []
    for name, delay in [("A", 0.03), ("B", 0.05), ("C", 0.04)]:
        results.append(await fetch(name, delay))   # 逐个等待，总耗时相加
    return results

# ═══════════════════════════════════════════
# 2. asyncio.gather：一次性并发多个协程
# ═══════════════════════════════════════════

async def gathered() -> list[str]:
    return await asyncio.gather(      # 三个请求同时开始等待
        fetch("A", 0.03),
        fetch("B", 0.05),
        fetch("C", 0.04),
    )                                 # 结果按传入顺序返回，总耗时接近最慢的

# ═══════════════════════════════════════════
# 3. create_task：先启动，稍后再取结果
# ═══════════════════════════════════════════

async def with_tasks() -> str:
    task = asyncio.create_task(fetch("D", 0.02))   # 立刻排入事件循环
    print("先去做别的事")                            # 任务已在后台跑
    return await task                              # 需要结果时再 await

# ═══════════════════════════════════════════
# 4. wait_for：给等待设上限并支持取消
# ═══════════════════════════════════════════

async def with_timeout() -> str:
    try:
        return await asyncio.wait_for(fetch("E", 0.5), timeout=0.05)
    except asyncio.TimeoutError:
        return "超时被取消"                          # 超时的协程会被取消

# ═══════════════════════════════════════════
# 5. asyncio.run：脚本级唯一入口
# ═══════════════════════════════════════════

async def main() -> None:
    t0 = time.perf_counter()
    print(await serial())             # 结果：总耗时约 0.12s
    serial_cost = time.perf_counter() - t0

    t0 = time.perf_counter()
    print(await gathered())           # 结果：总耗时约 0.05s，明显更短
    gather_cost = time.perf_counter() - t0

    print(serial_cost > gather_cost)  # 结果：True，并发比逐个 await 更快
    print(await with_tasks())         # 结果：D 完成于 0.02s
    print(await with_timeout())       # 结果：超时被取消

if __name__ == "__main__":
    asyncio.run(main())               # 创建事件循环，跑完入口协程后关闭
