MCP Server：工具生态标准化接入

用 MultiServerMCPClient 接入两个 MCP 服务，展示跨服务工具发现与调用。

开场问题：课程助手要接入公司内部的课程库，读写本地笔记要接文件系统，查汇率要接第三方 API——每接一个数据源，你的 tool() 定义就多一份：参数怎么传、鉴权怎么做、错误怎么报，各家一套写法。第三个数据源还没接完，你已经不想维护了。

工具集成的重复劳动

工具本身不难写，难的是「接谁都要重写一遍」。这类集成的痛点在缩放时集中爆发：

  • 协议各写各的：每个数据源的连接、鉴权、错误格式都要单独适配，代码里没有统一约定。
  • 换个客户端就重写：同一批工具要让 IDE、桌面应用和你的 Agent 都能用，得各接一遍。
  • 发现机制缺失：工具藏在私有代码里，Agent 运行时才知道有哪些能力可用。

要回答的是：有没有一种标准协议，让「提供工具」和「消费工具」解耦——服务按协议暴露能力，Agent 按协议发现并调用？

MCP：给工具定一份通用接口

MCP（Model Context Protocol）就是这个标准：任何服务只要按协议实现一个 MCP Server，就能对外声明自己有哪些工具（名称、描述、参数 Schema）；任何客户端按协议连上它，就能列出并调用这些工具——服务与消费者之间不再互写适配代码。

在 LangGraph 侧接 MCP 只要三步：

  1. 配置 Server 清单：用 MultiServerMCPClient 声明要连哪些 Server——本地的用 stdio 拉起子进程，远端的用 http 连服务地址，两种可以混用。
  2. 一次拉取全部工具：client.getTools() 返回标准的 LangChain 工具数组，每个工具名自带 Server 前缀（如 courseDb__query），与原生 tool() 定义的工具用法完全一致。
  3. 照常交给 Agent：把工具数组传进 createAgent({ model, tools, systemPrompt }) 即可——模型侧看到的就是普通工具，谁来提供、走什么传输，它一概不需要知道。
值得记住的两个细节：工具名前缀不是装饰，日志里看到 math__calculate 就知道这次调用跨了哪个服务；用完 client.close() 释放 stdio 子进程与 HTTP 连接，长驻服务尤其要注意，否则连接会悄悄泄漏。

协议解耦替代逐个适配

MCP 解决的是「工具如何标准化接入」：服务按协议暴露能力，Agent 按协议发现并调用。接一个新数据源不再写适配代码——换个 MCP Server 就是换一套工具，Agent 的代码一行不用改。

「MCP（Model Context Protocol）」是工具提供方与消费方之间的标准协议：Server 声明工具（名称、描述、参数 Schema），客户端（LangGraph 用 MultiServerMCPClient）发现并调用，支持 stdio 与 http 传输混用。要记住的边界：MCP 工具进上下文后，工具描述的质量同样决定调用准确率；工具名冲突靠 Server 前缀隔离；stdio 子进程与 HTTP 连接要显式关闭；远程 Server 的鉴权信息属于密钥，走环境变量而非代码。

关键代码

TypeScript
// MCP Server：用标准协议把外部工具接进 LangGraph
// 场景：课程助手接入两个 MCP 服务——本地文件系统 + 远程课程数据库
import { MultiServerMCPClient } from '@langchain/mcp-adapters'
import { createAgent } from 'langchain'
import { ChatOpenAI } from '@langchain/openai'
import { HumanMessage } from '@langchain/core/messages'

// 示例1: 配置多个 MCP Server——stdio 本地进程与 HTTP 远程服务可以混用
const client = new MultiServerMCPClient({
  math: {
    transport: 'stdio',
    command: 'node',
    args: ['./mcp-servers/math-server.js'],
  },
  courseDb: {
    transport: 'http',
    url: 'https://mcp.example.com/course-db',
    headers: { Authorization: 'Bearer <token>' },
  },
})

// 示例2: 一次拉取所有 Server 暴露的工具，自动转换为 LangChain 工具
// 每个工具的命名空间会加上 Server 前缀，如 math__calculate、courseDb__query
const tools = await client.getTools()
console.log('已接入工具:', tools.map((t) => t.name).join(', '))

// 示例3: 把 MCP 工具直接交给 createAgent，与本地工具用法完全一致
const agent = createAgent({
  model: new ChatOpenAI({ model: 'gpt-4o-mini', temperature: 0 }),
  tools,
  systemPrompt: '你可以使用 MCP 工具查询课程数据库与执行计算，请先查证再回答。',
})

const result = await agent.invoke({
  messages: [new HumanMessage('《LangGraph 入门》这门课总共几章？每章平均多少页？')],
})
console.log('回答:', result.messages.at(-1)?.content)

// 示例4: 观察 MCP 调用过程——工具名带 Server 前缀，一眼看出跨了哪个服务
for await (const chunk of await agent.stream(
  { messages: [new HumanMessage('《LangGraph 入门》这门课总共几章？每章平均多少页？')] },
  { streamMode: 'updates' },
)) {
  const [node, update] = Object.entries(chunk)[0] as [string, any]
  const calls = (update.messages ?? []).flatMap((m: any) => m.tool_calls ?? [])
  if (calls.length) {
    console.log(`[${node}] 调用:`)
    for (const call of calls) {
      console.log(`  - ${call.name}(${JSON.stringify(call.args)})`)
    }
  }
}

// 示例5: 用完显式关闭，释放 stdio 子进程与 HTTP 连接
await client.close()

// 示例6: MCP 的价值——工具不再写死在应用里
// 换一个 MCP Server 就是换一套工具，Agent 代码一行不用改；
// Claude Desktop、IDE、LangGraph 共享同一批 Server 定义。
