调试与部署：langgraph dev 与生产化

Studio 回放、updates 日志、LangSmith 追踪——图执行的可观测性三件套。

开场问题：助手在测试环境一切正常，上线后偶发「推荐了完全不相关的课程」。你打开日志——只有一行 200 OK。图跑了哪些节点、每个节点写了什么、tool 调用传了什么参数，全都看不见。图越复杂，这行日志越像谜语。

黑盒执行的排障困境

普通函数的 bug 可以用断点一步步走；图的 bug 却藏在「节点之间」——上游写错了字段、条件边选错了分支、工具收到了错参数，最终表现在很远的下游。没有执行记录，你只能猜。而且图还多一层特殊变量：状态是逐节点合并出来的，「哪个节点覆盖了哪个字段」这种问题光看代码根本看不出来。

要回答的是：怎么让一次图运行像浏览器开发者工具里的网络请求那样，可以逐条查看、逐层展开、随时回放？

三重可观测性：Studio、日志、追踪平台

从近到远、从开发到生产，配三件工具：

  1. langgraph dev + Studio（开发期）：写一份 langgraph.json 声明图入口，npx @langchain/langgraph-cli dev 启动调试服务，浏览器打开即得可视化画布——输入初始状态、逐节点回放、展开每个节点的输入与输出、还能「从这里重跑」：改掉中间某个状态，从断点处继续，不必从头再来。
  2. 结构化日志（本地与 CI）：没有 Studio 的环境用 stream({ streamMode: 'updates' }) 逐节点打印「节点名 + 耗时 + 更新字段 + 消息条数」——排障三件套。流式本身就自带一条现成的执行时间线。
  3. LangSmith（生产）：设置 LANGCHAIN_TRACING_V2 与 API Key 环境变量，代码零改动，每次运行自动上报成树形 trace：「节点 → 模型调用 → 工具调用」，附带完整输入输出、token 用量、失败堆栈。线上问题有了第一手的复现材料。
上线前把「调试配置」换成「生产配置」：开发期的 MemorySaver 检查点重启即丢，生产必须换成持久化后端（Postgres / Redis）；Studio 只是开发工具，部署产物只需要「编译好的图 + 环境变量」；追踪数据可能含用户输入，上报前按合规要求做脱敏或采样。

运行追踪面板演示

从开发回放到生产追踪

调试与部署解决的是「图执行的可观测性与生产化」：开发期用 Studio 逐节点回放与重跑，本地用 updates 流打结构化日志，生产用 LangSmith 自动追踪；检查点换持久化实现，调试配置不上生产。图不再黑盒，问题才有据可查。

「可观测性三件套」覆盖图执行的全生命周期：Studio（langgraph dev，可视化回放、状态编辑与断点重跑）、updates 流日志（节点名 / 耗时 / 更新字段，适合本地与 CI）、LangSmith（环境变量开启，生产树形追踪含输入输出与 token）。要记住的边界：MemorySaver 只适合开发，生产换持久化检查点；追踪数据可能含隐私，注意脱敏与采样；调试页监听在本地，别把 Studio 带进部署产物。

// 调试与部署：langgraph dev 调试页、追踪与上线检查
// 场景：把开发好的课程助手从本地调试推进到生产

// 示例1: langgraph.json——声明图入口与依赖，langgraph CLI 据此工作
// {
//   "dependencies": ["."],
//   "graphs": {
//     "course_agent": "./src/agents/course-agent.ts:agent"
//   },
//   "env": ".env"
// }

// 示例2: 启动调试页——打开 Studio，可视化每一步的输入输出
// 终端执行：
//   npx @langchain/langgraph-cli dev
// 浏览器打开 http://localhost:2024：
//   - 左侧列出所有图，点击进入画布
//   - 输入初始状态点击「Submit」，逐节点回放
//   - 每个节点可展开查看「输入状态 / 输出更新 / 耗时」
//   - 支持编辑状态后「从这里重跑」，不必从头再来

// 示例3: 结构化日志——本地没有 Studio 时，用 stream 自己打印追踪
import { createReactAgent } from '@langchain/langgraph/prebuilt'
import { ChatOpenAI } from '@langchain/openai'
import { HumanMessage } from '@langchain/core/messages'

const agent = createReactAgent({
  llm: new ChatOpenAI({ model: 'gpt-4o-mini', temperature: 0 }),
  tools: [],
  prompt: '你是课程助手。',
})

const startedAt = Date.now()
for await (const chunk of await agent.stream(
  { messages: [new HumanMessage('介绍一门入门课')] },
  { streamMode: 'updates' },
)) {
  const [node, update] = Object.entries(chunk)[0] as [string, any]
  const elapsed = Date.now() - startedAt
  const keys = Object.keys(update).join(',')
  // 关键字段：节点名、耗时、更新的字段、消息条数——排障三件套
  console.log(`[trace] node=${node} t=+${elapsed}ms updated=${keys} messages=${update.messages?.length ?? 0}`)
}

// 示例4: LangSmith 追踪——设置环境变量后无需改代码，全链路自动上报
// export LANGCHAIN_TRACING_V2=true
// export LANGCHAIN_API_KEY=<your-key>
// export LANGCHAIN_PROJECT=course-agent
// 之后每次 invoke 都会在 LangSmith 生成一条 trace：
// 树形展示「节点 → 模型调用 → 工具调用」，附带完整输入输出与 token 用量

// 示例5: 上线前的检查清单
const releaseChecklist = [

  'store 同样持久化，长期记忆跨发布保留',
  '为模型与外部工具设置超时、重试与降级话术',

]
console.log(releaseChecklist.join('\n'))
