网络搜索：让智能体接入实时信息

把搜索 API 包成工具：规划搜索词、去重限长、带引用作答。

开场问题：用户问「LangGraph 1.0 什么时候发布的」。模型自信地答了个日期——错得离谱。它的知识停在训练截止那天，而 LangGraph 1.0 恰好在那之后发布。网上明明到处都是答案，模型却像个不出门的学者。

知识冻结与实时世界的落差

模型的知识来自训练数据，训练一结束，知识就冻住了：版本号、价格、新闻、今天的天气，全是它答不准的领域。上一课的 RAG 解决了「私有知识」，但它同样解决不了「昨天刚发生的事」——向量库里存的是切片时的快照。

要回答的是：怎么让智能体在需要的时候「出去查一次」，并把查到的内容用得靠谱？

搜索工具接入与三条工程纪律

机制上这件事很简单：把搜索 API 包装成一个工具。Tavily、DDGS、Exa 这些面向 LLM 的搜索服务都返回结构化结果（标题、片段、URL），包装成 tool() 交给 Agent，它就会在「知识不够新鲜」时自己调工具。真正决定成败的是三条工程纪律：

  1. 搜索词要改写：把「数据改了页面自己变」这样的口语问法，转成搜索引擎友好的关键词组合。这一步交给模型自己做（提示词里要求「先规划搜索词」），这本身就是为什么搜索要放进 Agent 而不是固定流程。
  2. 结果要限长与去重：每个结果只保留 2-3 句片段，整页塞进上下文是最常见的 token 浪费；同一事件被多家媒体转载时按标题指纹合并，否则模型的引用会全指向同一篇通稿。
  3. 引用要可核对：提示词里明确要求「每个关键结论后标注 [编号]」，并在 UI 上把来源列表随答案展示——引用不只是排版，它是用户核对事实、也是模型收敛幻觉的抓手。
联网不是免幻觉证书：搜索结果本身可能过时、被劫持或互相矛盾。高风险领域（医疗、金融）要加约束：冲突来源必须说明分歧、只采信日期最新的说法、重要结论要求双源交叉验证。另外——搜索是最容易被提示注入的入口之一，网页内容里的「指令」绝不能当系统指令执行。

搜索—去重—引用全流程演示

把实时世界接进推理循环

网络搜索解决的是「知识的时效」：搜索 API 包装成工具，由 Agent 自己决定何时查、怎么改写查询；结果去重限长后进上下文，答案带引用可核对。机制很简单，纪律决定质量。

「联网搜索工具」指把搜索 API（Tavily / DDGS / Exa 等）包装成 Agent 工具，由模型在需要实时信息时自主调用：先规划搜索词，再把结果片段注入上下文，最后带 [编号] 引用作答。要记住的边界：结果片段必须限长，整页入上下文是 token 黑洞；标题相似的结果要按指纹去重；网页内容可能含提示注入，不能当指令执行；高风险结论要求交叉验证并展示来源。

关键代码

TypeScript
// 网络搜索：让智能体接入实时信息
// 场景：热点资讯助手——搜索新闻 → 去重 → 带引用来源回答
import { createAgent } from 'langchain'
import { ChatOpenAI } from '@langchain/openai'
import { tool } from '@langchain/core/tools'
import { HumanMessage } from '@langchain/core/messages'
import { z } from 'zod'

// 示例1: Tavily 搜索工具——专为 LLM 设计的搜索 API，直接返回结构化结果
const tavilySearch = tool(async ({ query, maxResults }) => {
  const response = await fetch('https://api.tavily.com/search', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      api_key: process.env.TAVILY_API_KEY,
      query,
      max_results: maxResults,
      include_answer: false,
    }),
  })
  const data = await response.json()
  // 只把标题、片段、URL 交给模型，控制 token 消耗
  return data.results
    .map((r: any, i: number) => `[${i + 1}] ${r.title}\n${r.content}\n来源: ${r.url}`)
    .join('\n\n')
}, {
  name: 'web_search',
  description: '联网搜索实时信息，返回标题、摘要与来源链接',
  schema: z.object({
    query: z.string().describe('搜索词，尽量具体'),
    maxResults: z.number().default(5),
  }),
})

// 示例2: 去重——同一新闻被多家媒体转载时，按标题相似度合并，避免刷占结果位
function dedupeByTitle(items: { title: string; url: string }[]) {
  const seen = new Set<string>()
  return items.filter((item) => {
    const key = item.title.replace(/[\s「」【】\-—|]/g, '').slice(0, 18)
    if (seen.has(key)) return false
    seen.add(key)
    return true
  })
}

// 示例3: 约束「引用格式」——把编号来源的写法写进提示词
const agent = createAgent({
  model: new ChatOpenAI({ model: 'gpt-4o-mini', temperature: 0 }),
  tools: [tavilySearch],
  systemPrompt: `你是资讯助手。回答前必须调用 web_search 查证：
- 只依据搜索结果回答，不编造
- 每个关键结论后用 [编号] 标注来源
- 多个来源冲突时，说明分歧并给出时间最新的说法`,
})

const result = await agent.invoke({
  messages: [new HumanMessage('LangGraph 1.0 是什么时候发布的？有哪些新特性？')],
})
console.log(result.messages.at(-1)?.content)

// 示例4: 观察搜索轨迹——看模型如何改写搜索词、翻了几轮
for await (const chunk of await agent.stream({
  messages: [new HumanMessage('LangGraph 1.0 是什么时候发布的？有哪些新特性？')],
}, { streamMode: 'updates' })) {
  const [node, update] = Object.entries(chunk)[0] as [string, any]
  const calls = (update.messages ?? []).flatMap((m: any) => m.tool_calls ?? [])
  for (const call of calls) {
    console.log(`[搜索] ${call.args.query}（最多 ${call.args.maxResults ?? 5} 条）`)
  }
}

// 都只是替换一个工具实现，Agent 与提示词不变
