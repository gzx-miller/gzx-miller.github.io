记忆：短期记忆与长期记忆

用学习助手展示 checkpointer 的会话内记忆与 Store 的跨会话长期档案。

开场问题：学习助手上线第一周好评不断，第二周被差评淹没——「昨天刚说我基础差要讲慢点，今天又问我要不要从入门讲起」。你打开代码一看：每次请求都是独立的一问一答，用户昨天说过什么，今天的助手根本不知道。

无记忆对话的体验断裂

没有记忆的 LLM 应用像一位「十分钟失忆」的顾问：每轮对话都从零开始，用户被迫反复交代背景，代词「它」「那门课」全部悬空。要让对话连贯，模型在生成前必须重新「看见」之前发生过什么——记忆的本质，是把历史上下文找回来、送进这一次的模型调用。

但粗暴地「什么都记住」会付出代价：对话越长上下文越贵，token 预算撑不住；而把记忆一股脑塞进上下文，还会让关键信息被淹没。所以记忆要分两层来设计。

两种记忆各管一段

LangGraph 把记忆拆成职责清晰的两层，用两个机制分别承载。

  1. 短期记忆 = checkpointer + thread_id：编译图时挂上 checkpointer，每次 invoke 传入同一个 thread_id，框架自动把该线程的历史消息注入本轮状态。会话内的连贯性靠它——同一个 thread 的每一轮都能读到之前的消息；换了 thread，短期记忆就清零。
  2. 长期记忆 = Store + namespace：store.put(['profiles', id], {...}) 把用户画像、偏好这类跨会话的信息存进命名空间；下次任何线程启动时用 store.get / search 读回来。跨会话的身份与偏好靠它——不清除就一直在。
写入时机是设计问题：短期记忆由框架自动累积；长期记忆需要明确的写入决策——可以是节点里的一句规则（「检测到用户自述就更新档案」），也可以交给模型用工具自主决定。写入越克制，召回越精准：把每句闲聊都存进去，档案只会稀释成噪音。

短期与长期记忆演示

目录分层：线程内连贯、跨会话认人

记忆解决的是「对话如何连贯」：短期记忆由 checkpointer 按 thread_id 自动累积，管会话内的上下文；长期记忆由 Store 按命名空间持久化，管跨会话的画像与偏好。两层各管一段，互不越界。

「短期记忆与长期记忆」是 LangGraph 记忆体系的两个机制：短期记忆用 checkpointer 按 thread_id 保存线程内消息历史（换 thread 即清零），长期记忆用 Store 按 namespace 保存跨会话数据（可 get / search / put）。要记住的边界：短期记忆的 token 成本随对话轮数增长，长会话要配合截断或摘要；长期记忆写入要有策略（规则或工具），否则噪音稀释召回；生产环境两者都应换成持久化后端，内存实现重启即丢。

关键代码

TypeScript
// 记忆：短期记忆靠 checkpointer，长期记忆靠 Store
// 场景：学习助手——会话内记住上下文，跨会话记住学生偏好
import { StateGraph, StateSchema, MessagesValue, START, END, MemorySaver, InMemoryStore } from '@langchain/langgraph'
import { ChatOpenAI } from '@langchain/openai'
import { HumanMessage, SystemMessage } from '@langchain/core/messages'
import { z } from 'zod/v4'

const model = new ChatOpenAI({ model: 'gpt-4o-mini', temperature: 0 })

// 示例1: 短期记忆——用 checkpointer 按 thread_id 保存会话内的消息历史
// 同一个 thread_id 的每一次 invoke 都能读到之前的消息
const checkpointer = new MemorySaver()

const AssistantState = new StateSchema({
  messages: MessagesValue,
  profile: z.string().default(''),
})

async function chatNode(state: typeof AssistantState.State, runtime: any) {
  // 示例2: 长期记忆——从 Store 里读学生档案（跨会话、跨 thread）
  const userId = runtime.configurable?.user_id ?? 'student-01'
  const saved = await runtime.store.get(['profiles'], userId)
  const profile = saved?.value?.summary ?? '暂无档案'

  // 示例3: 组装回答——短期消息 + 长期档案一起进入模型上下文
  const response = await model.invoke([
    new SystemMessage(`你是学习助手。学生长期档案：${profile}`),
    ...state.messages,
  ])

  // 示例4: 从本轮对话里提炼新偏好，写回长期记忆
  const lastUser = state.messages.at(-1)?.content ?? ''
  if (String(lastUser).includes('我')) {
    const merged = `${saved?.value?.summary ? saved.value.summary + '；' : ''}用户自述：${String(lastUser).slice(0, 40)}`
    await runtime.store.put(['profiles'], userId, { summary: merged, updatedAt: Date.now() })
  }

  return { messages: [response] }
}

const graph = new StateGraph(AssistantState)

graph.addNode('chat', chatNode)
graph.addEdge(START, 'chat')
graph.addEdge('chat', END)

// 示例5: 编译时同时挂上 checkpointer（短期）与 store（长期）
const app = graph.compile({
  checkpointer,
  store: new InMemoryStore(),
})

// 第一次对话：告诉我姓名
const config1 = { configurable: { thread_id: 'session-1', user_id: 'student-01' } }
await app.invoke({ messages: [new HumanMessage('我叫小明，正在学 LangGraph')] }, config1)

// 同一会话再问：短期记忆起效，能接住「我叫什么」
const follow = await app.invoke({ messages: [new HumanMessage('我叫什么名字？')] }, config1)
console.log('会话内追问:', follow.messages.at(-1)?.content)

// 示例6: 换一个新会话（thread_id 变了，短期记忆清零）
// 但长期记忆还在——模型仍能从 Store 里读到小明是谁
const config2 = { configurable: { thread_id: 'session-2', user_id: 'student-01' } }
const cross = await app.invoke({ messages: [new HumanMessage('还记得我是谁吗？')] }, config2)
console.log('跨会话召回:', cross.messages.at(-1)?.content)
