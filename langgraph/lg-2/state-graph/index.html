状态图：StateGraph 工作流建模

用内容生产线展示 StateGraph：Annotation 状态、reducer 合并、条件边回环。

开场问题：你要做一条「内容生产线」：大纲 → 正文 → 质检 → 摘要。前三步还顺，可质检这一步出了岔子——正文太短要回炉重写。线性链只会从上往下走一遍，「退回上一步」这种要求一加上，链路设计立刻塌方。

回环需求击穿线性链

上一颗栗子里，Agent 的循环被封装在预置图内部，你没有亲手搭过图。现在轮到自定义工作流：质检不达标要回炉、分支要按内容动态选择——这些需求都在说同一件事，流程不是一条直线，而是一张有环的网。线性链表达不了环，而裸写 while 又回到「调度代码和业务逻辑缠在一起」的老路。

状态对象与节点函数

先把「流程怎么走」和「每一步做什么」拆开。做法是一份状态对象加一组节点函数：状态里放流程要用的所有字段（大纲、正文、重试次数、日志），节点函数只做两件事——读状态、返回一份局部更新。谁都不许就地改状态，节点之间也不许互相调用，状态对象就是它们之间唯一的约定。

这个方案做对了关键的一件事：每个节点都成了纯函数式的独立单元——可以单测、可以替换、可以重排。剩下的问题只有一个：用什么结构来编排它们。

调度器承担隐性契约

  • 顺序数组走不回头：「质检不通过就回到正文」需要从后一步指回前一步，数组表达不了。
  • 合并规则没有约定：多个节点都写 log 时，后写的会把先写的整段覆盖——覆盖还是追加，全凭自觉。
  • 循环没有刹车：回环一旦成立，「重试到什么时候停」必须显式设计，否则栈会烧穿。
  • 执行过程不可见：跑到一半失败，没有统一记录「哪个节点写了什么」，无法续跑、无法回放。

有向状态图三件套

不推翻状态与节点，把调度部分升级成 StateGraph：状态用 Annotation 声明、流转用边描述、执行交给框架。具体分四步补齐。

  1. 声明状态与合并规则：用 Annotation.Root 定义每个字段；列表和计数器这类「会反复更新」的字段必须配 reducer——log 用 concat 追加、attempts 用累加，节点返回的局部更新由 reducer 合并进总状态，覆盖与否不再靠自觉。
  2. 节点照旧是纯函数：接收当前状态、返回局部更新；正文节点重写时多返回一个 attempts: 1，计数器自己就滚了起来。
  3. 用边描述流转：普通边 addEdge 连固定顺序，条件边 addConditionalEdges 挂一个路由函数——它读状态、返回下一个节点名。质检不通过返回 'content'，回环就成立了；通过返回 'summary'，流程向前走。
  4. 给循环设终止条件：回环必须能走出去——要么质检放行、要么迭代数触顶强制走向 END。终止条件不是兜底，是环的一部分。
编译这一步做了什么：graph.compile() 把散装的节点与边变成一张可执行对象：调用 invoke 跑完整流程，调用 stream 逐步观察每个节点的状态更新——「哪个节点写了什么」从此有了统一账本。

条件边回环执行演示

状态驱动而非顺序驱动

状态图解决的是「复杂流程的编排」：把流程拆成状态、节点、边三样东西，让框架按「当前状态 → 下一跳」驱动执行。链只回答「下一步是谁」，图回答「根据现在的情况，下一步该是谁」——分支与回环因此收进了同一种结构。

「StateGraph」把工作流建模为有向状态图：状态用 Annotation 声明字段与合并规则（reducer），节点是「读状态、返回局部更新」的函数，边分普通边与条件边（路由函数读状态返回下一节点名）。要记住的边界：列表、计数器字段不配 reducer 会被整段覆盖；回环必须设计终止条件；状态字段加得越多，每次检查点序列化的负担越大——只放流程真正需要的。

关键代码

TypeScript
// 状态图：用 StateGraph 把工作流建模成「节点 + 边」
// 场景：课程内容生产线——大纲 → 内容 → 质检（不达标回炉重写）→ 摘要
import { StateGraph, Annotation, START, END } from '@langchain/langgraph'
import { ChatOpenAI } from '@langchain/openai'
import { ChatPromptTemplate } from '@langchain/core/prompts'
import { StringOutputParser } from '@langchain/core/output_parsers'

const model = new ChatOpenAI({ model: 'gpt-4o-mini', temperature: 0 })
const parser = new StringOutputParser()

// 示例1: 用 Annotation.Root 定义图状态
// messages 这类列表字段必须配 reducer，节点返回的局部更新才会「追加」而不是覆盖
const GraphState = Annotation.Root({
  topic: Annotation<string>,
  outline: Annotation<string>,
  content: Annotation<string>,
  summary: Annotation<string>,
  attempts: Annotation<number>({
    reducer: (left, right) => (left ?? 0) + (right ?? 0),
    default: () => 0,
  }),
  log: Annotation<string[]>({
    reducer: (left, right) => left.concat(right),
    default: () => [],
  }),
})

// 示例2: 节点函数——接收当前状态，返回一份局部更新
async function outlineNode(state: typeof GraphState.State) {
  const prompt = ChatPromptTemplate.fromTemplate('为「{topic}」生成一份三级课程大纲')
  const outline = await prompt.pipe(model).pipe(parser).invoke({ topic: state.topic })
  return { outline, log: [`大纲生成完成（${outline.length} 字）`] }
}

async function contentNode(state: typeof GraphState.State) {
  const prompt = ChatPromptTemplate.fromTemplate('根据大纲展开课程正文：\n{outline}')
  const content = await prompt.pipe(model).pipe(parser).invoke({ outline: state.outline })
  return { content, attempts: 1, log: [`正文生成完成（第 ${(state.attempts ?? 0) + 1} 稿）`] }
}

async function reviewNode(state: typeof GraphState.State) {
  // 质检规则：正文过短视为不合格
  const passed = state.content.length >= 500
  return { log: [passed ? '质检通过' : `质检不通过：正文仅 ${state.content.length} 字，退回重写`] }
}

async function summaryNode(state: typeof GraphState.State) {
  const prompt = ChatPromptTemplate.fromTemplate('为以下正文写 100 字摘要：\n{content}')
  const summary = await prompt.pipe(model).pipe(parser).invoke({ content: state.content })
  return { summary, log: ['摘要生成完成'] }
}

// 示例3: 条件路由函数——读状态，返回下一个节点名
function routeAfterReview(state: typeof GraphState.State): 'content' | 'summary' {
  return state.content.length >= 500 ? 'summary' : 'content'
}

// 示例4: 组装状态图
const graph = new StateGraph(GraphState)
  .addNode('outline', outlineNode)
  .addNode('content', contentNode)
  .addNode('review', reviewNode)
  .addNode('summary', summaryNode)
  .addEdge(START, 'outline')
  .addEdge('outline', 'content')
  .addEdge('content', 'review')
  // 条件边：质检不通过就指回 content，形成「改到合格为止」的循环
  .addConditionalEdges('review', routeAfterReview, {
    content: 'content',
    summary: 'summary',
  })
  .addEdge('summary', END)

const app = graph.compile()

// 示例5: 执行并观察
const result = await app.invoke({ topic: 'LangGraph 入门' })
console.log('摘要:', result.summary)
console.log('执行日志:\n' + result.log.map((line) => `  - ${line}`).join('\n'))

// 示例6: 流式观察每个节点的执行顺序与状态更新
for await (const step of await app.stream({ topic: 'LangGraph 入门' })) {
  const [nodeName, update] = Object.entries(step)[0] as [string, any]
  console.log(`[执行节点] ${nodeName} → 更新字段: ${Object.keys(update).join(', ')}`)
}
