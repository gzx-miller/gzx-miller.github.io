预加载脚本与安全桥接

编写预加载脚本，用 contextBridge.exposeInMainWorld 安全暴露白名单 API，理解上下文隔离与"绝不整对象暴露"的安全边界。

开场问题：预加载脚本里本来只想让页面能读个版本号，图省事多写了一行把整个 ipcRenderer 挂到 window 上——结果一次第三方脚本注入，就能顺着这个接口删掉你电脑上的文件。同一行代码，为什么把安全边界整个交了出去？

页面能力最小授权

页面需要一点点原生能力：读个版本号、存取一份配置。但页面本身是不可信的——它加载的第三方库、内联的模板、远程拉来的资源，任何一处都可能被注入脚本。能力越方便地交出去，被滥用时的破坏面就越大。

旧办法是把能力直接摊给页面：要么打开 nodeIntegration 让页面自己 require('fs')，要么把整个 ipcRenderer 对象挂到 window 上。它同样带来三笔必须由人承担的成本：页面一旦被注入就等于拿到这些能力的完全控制权；你无法限定它"只能做你允许的那几件事"，任意通道名它都能调；出事后无从审计，因为压根没有一份"页面被允许做什么"的清单。

那怎么才能只交出"刚好够用的那几个函数"，而不是一整串钥匙？

预加载脚本白名单

预加载脚本在渲染进程加载页面之前运行，是唯一同时能触及受限 Node 子集与 Electron API 的地方。就在这个时机，把需要的能力一个个挂出去：

contextBridge.exposeInMainWorld('api', { getVersion: () => ipcRenderer.invoke('app:get-version'), saveFile: (data) => ipcRenderer.invoke('file:save', data) })。

这个方案做对了一件事：页面拿到的是 window.api.getVersion() 这样的窄接口，而不是 ipcRenderer。能力边界由你亲手划定，页面能碰到的，只有你写进这份对象里的方法。演示里那个"安全写法"面板，展示的正是这一版。

整体暴露安全风险

  • 如果暴露的是整个 ipcRenderer 对象，页面就能 window.api.ipcRenderer.invoke('任意通道')，连你没打算给它用的通道也一并敞开，边界形同虚设。
  • 暴露整个 os、fs 模块，或干脆把 require 递给页面，等于把 Node 摊开，最小权限原则被直接违反。
  • 暴露出去的若是普通对象，页面能改写它——比如覆盖 window.api.saveFile，之后再调用就被劫持了。
  • 页面若只加事件监听、从不移除，组件反复挂载会让监听器越堆越多，最终内存泄漏。

暴露粒度与隔离边界

先补"暴露粒度"这一步，因为它直接决定攻击面。原则是逐一暴露方法，绝不暴露容器对象：页面能拿到 saveFile 这个函数，却拿不到 ipcRenderer、require、process 本体，每个函数内部才把参数整形后转给指定的通道。

再补这套机制为什么会成立。它靠的是上下文隔离（contextIsolation: true，Electron 12 起默认开启）：预加载脚本访问的 window 和页面访问的 window 不是同一个对象，exposeInMainWorld 是唯一能安全穿过这两个上下文的方式，底层还会自动处理类型转换、防止原型链污染。

再补"只给必需 + 接口固定"。按领域给方法分组命名，比如 app:、file:、window: 前缀，让人一眼看出每个接口属于哪块能力；暴露出去的对象用 Object.freeze 固定，防止页面改写。

最后补两道收尾。其一，在 preload 里对参数做第一道类型收窄——注意这只是"第一道"，主进程 handler 的校验仍不可省，两者是纵深上的配合而非互相替代。其二，凡是提供 onXxx 监听的接口，都配套提供一个 removeXxxListener，让页面能主动清理监听器，避免堆积。

最危险的那一行：把 ipcRenderer 整个暴露出去。被注入的页面可借它调用任意通道，进而触发删文件、起进程一类的主进程敏感操作——preload 里只做通道转发与参数整形，复杂业务逻辑留在主进程，才便于测试与安全审计。

两种暴露写法对照

最小权限与桥接通道

预加载脚本的关键不在于"它能拿到多少能力"，而在于"它到底交出了多少"。上下文隔离划出两个世界，exposeInMainWorld 是唯一的过桥通道，再靠逐方法暴露、只给必需、接口固定三条，让页面的能力恰好等于你显式授予的那些。

「contextBridge」是上下文隔离下唯一能安全跨越两个上下文的桥梁，contextBridge.exposeInMainWorld(key, api) 把白名单方法注入渲染进程的 window，底层自动做类型转换并防止原型污染。它只是"过桥的通道"，不是权限本身——真正的安全来自你只写进白名单的那些方法；ipcRenderer、require 这类原始对象绝不能原样递过去。

关键代码

JavaScript
// ========== 1. 基础预加载脚本 preload.js ==========
const { contextBridge, ipcRenderer } = require('electron')

// 使用 contextBridge 安全暴露 API
// 只有在这里显式暴露的方法，渲染进程才能访问
contextBridge.exposeInMainWorld('myAPI', {
  // 暴露方法
  ping: () => ipcRenderer.invoke('ping'),
  getAppVersion: () => ipcRenderer.invoke('get-app-version'),

  // 暴露事件监听
  onCounterUpdate: (callback) => {
    ipcRenderer.on('counter-update', (_event, value) => callback(value))
  },

  // 移除监听器的方法（防止内存泄漏）
  removeCounterListener: () => {
    ipcRenderer.removeAllListeners('counter-update')
  }
})

// ========== 2. 主进程对应实现 main.js ==========
const { ipcMain } = require('electron')

ipcMain.handle('ping', () => 'pong')
ipcMain.handle('get-app-version', () => app.getVersion())

// ========== 3. 渲染进程使用 renderer.js ==========
// 调用暴露的 API
async function test() {
  const result = await window.myAPI.ping()
  console.log(result) // 'pong'

  const version = await window.myAPI.getAppVersion()
  console.log('版本:', version)
}

// 监听事件
window.myAPI.onCounterUpdate((count) => {
  console.log('计数器:', count)
})

// ========== 4. 完整示例: 文件操作 API ==========
// preload.js
contextBridge.exposeInMainWorld('fileAPI', {
  // 读取文件
  readFile: (fileName) => ipcRenderer.invoke('file:read', fileName),
  // 写入文件
  writeFile: (fileName, content) => ipcRenderer.invoke('file:write', fileName, content),
  // 删除文件
  deleteFile: (fileName) => ipcRenderer.invoke('file:delete', fileName),
  // 列出目录
  listDir: (dirPath) => ipcRenderer.invoke('file:list', dirPath)
})

// main.js - 实现文件操作（带安全限制）
const fs = require('fs/promises')
const path = require('path')

const USER_DATA_DIR = app.getPath('userData')

function safeJoin(base, target) {
  const resolved = path.resolve(base, target)
  if (!resolved.startsWith(base)) {
    throw new Error('路径越界')
  }
  return resolved
}

ipcMain.handle('file:read', async (_event, fileName) => {
  const filePath = safeJoin(USER_DATA_DIR, fileName)
  return await fs.readFile(filePath, 'utf-8')
})

ipcMain.handle('file:write', async (_event, fileName, content) => {
  const filePath = safeJoin(USER_DATA_DIR, fileName)
  await fs.writeFile(filePath, content, 'utf-8')
  return { success: true }
})

// ========== 5. 暴露 Node.js 模块的子集 ==========
// preload.js - 安全地暴露部分功能
const os = require('os')

contextBridge.exposeInMainWorld('systemInfo', {
  // 只暴露部分属性，不暴露整个 os 模块
  platform: process.platform,
  arch: process.arch,
  hostname: os.hostname(),
  totalMem: os.totalmem(),
  cpusCount: os.cpus().length,
  // 暴露方法但做包装
  getUptime: () => os.uptime()
})

// ========== 8. 安全最佳实践 ==========
// 1. 开启 contextIsolation: true（Electron 12+ 默认开启）
// 2. 不要直接暴露 ipcRenderer 对象
// 3. 不要暴露 require 或 Node.js 模块的原始引用
// 4. 只暴露必要的 API，遵循最小权限原则
