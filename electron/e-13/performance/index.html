性能优化

从启动、内存、渲染三条线优化 Electron 应用，掌握延迟加载、引用释放与内存监控。

开场问题：应用冷启动要八秒，白屏一直挂在那儿。你在创建窗口前后打了时间戳，发现new BrowserWindow 本身只花了不到两百毫秒——那多出来的七秒多，凭什么也算在「启动」头上？

启动内存与渲染瓶颈

「慢」其实不是一个问题，而是三个：启动慢（从双击到首屏出现）、内存高（多开几个窗口就上 GB）、渲染卡（长列表一滚就掉帧）。用同一把尺子量这三件事，必然优化错地方。

旧办法的毛病也很典型：凭感觉优化，哪儿慢就随手加个缓存，改完也不知道到底有没有用；把所有逻辑都堆在启动路径上，app.whenReady() 之前就同步读了一堆文件、require 了一堆重模块，把主进程启动堵死，窗口根本没机会露面；每开一个窗口就新建渲染进程、关掉又不释放引用，内存只涨不降；长列表则把上万行一次全渲染进 DOM。

于是问题变成：怎么先把「慢在哪」量出来，再分别对症下药？

性能指标采样

先别急着改代码，先量。主进程里用 process.memoryUsage() 定时采样 rss（常驻内存），再用一张时间线把「双击 → 主进程 ready → 窗口创建 → 首屏渲染」几个关键点记下来；渲染侧就用 DevTools 的 Performance 面板录一段启动和关键交互。

这个方案做对了一件事：它把「先测量、后优化」定成了顺序。有了数据，你会立刻发现那七秒根本不在创建窗口那一步，而在它前面被你同步堵住的主进程启动阶段。

采样缺失与资源泄漏

  • 只测 createWindow 的耗时：漏掉了启动阶段那些同步 I/O 和 require 的阻塞，首帧其实是被它们拖住的。
  • 每个额外打开的渲染进程都有几十 MB 量级的内存成本，窗口随意堆叠很快把内存吃光。
  • 窗口与 WebContents 关闭后引用没释放：GC 收不回，内存只涨不降。
  • 长列表一次性渲染全部行：DOM 节点上万，滚动必然卡。
  • 后台窗口里的定时器和动画还在照常跑：白白耗 CPU 和电，用户却看不见。

主进程启动优化

先切启动路径，因为首屏速度是用户最直观的感受。两条：主进程里避免同步 I/O——能异步就异步，或者延后到窗口出现之后再做；非关键模块延迟加载——别在 app.whenReady() 之前 require 全量模块，等首屏出来、系统空闲时再动态 import()。在渲染进程里，把不影响首屏的任务交给 requestIdleCallback，让浏览器挑空闲帧去跑，别和首屏抢主线程。

接着松开「首屏必须等数据」这个执念：首屏不必等全部数据就绪。先用骨架屏把窗口尽快显示出来，真实内容再渐进填充——让窗口尽早可见，比把所有启动逻辑一次前置更有效。

再补内存这条线。定时用 process.memoryUsage() 采样 rss，定位异常增长；窗口关闭时主动释放对窗口和 WebContents 的引用；控制同时打开的窗口数量。想精确定位就打开 DevTools 的 Memory 面板拍堆快照，对比两次快照找出泄漏的对象。

然后是渲染这条线。长列表用虚拟滚动，只渲染当前视口里的那几行、滚动时复用节点；事件用防抖 / 节流；能交给 GPU 的动画用 CSS 硬件加速；重计算丢给 Web Worker 或子进程，别卡住 UI。

最后说一个容易被忽略的开关 backgroundThrottling。窗口失焦、切到后台后，Chromium 默认会节流它里面的定时器和动画（backgroundThrottling 默认为 true），省下不少 CPU 和电。只有当后台窗口仍需精确计时（比如一个计时类应用）时才考虑把它关掉——代价是后台也照常耗资源，大多数应用保持默认就好。

三类优化逐项对照

瓶颈定位与对症优化

性能优化不是「哪里慢改哪里」，而是先分线再对症：用 process.memoryUsage() 和 DevTools 把瓶颈量出来，启动上砍同步 I/O、延迟加载重模块、首屏先给骨架，内存在窗口关闭时释放引用，渲染上用虚拟滚动与 requestIdleCallback 把工作挪出主线程。慢的往往不是你以为的那一步。

「虚拟列表（虚拟滚动）」只渲染当前视口里可见的少量行，滚动时按 scrollTop 换算出可见区间、复用 DOM 节点，把 DOM 数量从「数据总量」降到「视口行数」。边界：需要每行等高或能预估高度；被虚拟掉的节点不在 DOM 里，所以浏览器原生页内查找（Ctrl+F）找不到它们，锚点跳转和「滚动到第 N 行」也得自己算偏移量。

const { app, BrowserWindow } = require('electron')
const path = require('path')

// 优化一: 尽早创建窗口（利用 ready 之前的时间）
// 但要等 app.whenReady() 之后
let mainWindow = null

app.whenReady().then(() => {
  createMainWindow()
})

// 优化二: 使用 ready-to-show 避免白屏闪烁
function createMainWindow() {
  mainWindow = new BrowserWindow({
    width: 1200,
    height: 800,
    show: false, // 先不显示
    backgroundColor: '#f0f0f0', // 设置背景色，减少视觉闪烁
    webPreferences: {
      preload: path.join(__dirname, 'preload.js'),
      contextIsolation: true,
      // 优化: 启用 V8 代码缓存
      // 默认已启用
    }
  })

  // 加载页面
  mainWindow.loadFile('index.html')

  // DOM 准备好后再显示
  mainWindow.once('ready-to-show', () => {
    mainWindow.show()
  })

  return mainWindow
}

  return win
}
