原生菜单与上下文菜单

用 Menu.buildFromTemplate 构建并挂载应用原生菜单，掌握 role 复用与 accelerator 快捷键。

开场问题：你在渲染进程里用 <div> 画了一个漂亮的右键菜单，交互看着完全正常——直到用户选中一段文字想"复制"，去点你菜单里的"复制"，剪贴板里却什么都没有；那个浮层还会在别处点击时愣着不消失。

手工菜单能力缺口

桌面应用想把常用操作摆到用户顺手的地方：顶部一条菜单栏，右键再弹出一组上下文操作。你第一反应是自己画——用 HTML 和 CSS 做菜单，想放什么就放什么。可一旦动手就会发现，菜单栏里的"撤销""复制""粘贴"这些词不是文案，而是系统已经实现好的动作：你画出来的只是一个长得像菜单的盒子，点下去不会真的触发系统的编辑行为，也拿不到那些动作的启用/禁用状态。

自己维护一套菜单还要背上三笔隐藏成本：平台菜单结构不一样，macOS 顶端第一个菜单是应用名，里面装着"关于 / 服务 / 隐藏 / 退出"，Windows 与 Linux 没有这一项，硬编码一套结构，到了另一个系统就会缺项或重复；文案与快捷键要自己本地化，"复制"在英文系统里该显示 Copy、快捷键要按平台显示 ⌘ 或 Ctrl，全靠手写永远对不齐；启用状态无人托管，没有选中文字时"复制"本该置灰，这套状态逻辑没人替你维护。

所以要问的是：有没有一种写法，让操作系统自己去构建这份菜单——包括外观、本地化、快捷键和启用状态？

模板数组声明菜单

最朴素的做法是用 Menu.buildFromTemplate(template) 把菜单描述成一个数组，再用 Menu.setApplicationMenu(menu) 挂上去。模板就是普通对象：{ label: '文件', submenu: [...] }，子项可以是分隔线 { type: 'separator' }，也可以带 accelerator。

这个方案做对了一件事：把菜单从"像素和事件"变成了"结构描述"。你只声明"这里有一个叫文件的菜单，里面有一项新建"，剩下的渲染外观、快捷键提示、平台细节，全交给操作系统去办；这套代码必须写在主进程里，因为菜单是系统资源，渲染进程只负责通过 IPC 请求"弹一下右键菜单"。

手写点击失效场景

  • 给"复制"手写 click：点下去剪贴板里什么都没有——DOM 层拿不到系统的编辑剪贴板，这个动作只能由系统来做。
  • 只写 label: '复制' 不写 role：英文系统的用户看到的仍是中文，快捷键提示也不对，翻译还得自己维护。
  • 快捷键写死成 'Ctrl+S'：macOS 用户看到的还是 Ctrl 而不是 ⌘，跨平台直接错位。
  • 菜单树写死一套：macOS 顶部少了应用名菜单，找不到"关于 / 退出"；Windows 上却莫名多出一个重复的"退出"。
  • click 里直接写 mainWindow.show()：窗口被关掉后再点菜单，操作的是已销毁的窗口，报错或毫无反应。

标准动作角色声明

第一件事是让标准动作用 role 声明。撤销、重做、剪切、复制、粘贴、全选、刷新、开发者工具、缩放、全屏、最小化、关闭、退出……这些都有对应的 role。写下 { role: 'copy' }，系统就自动实现行为、本地化文案并绑定默认快捷键，比手写 click 又准又省。

第二步补上平台结构差异。macOS 的第一个菜单应该是应用名，用 process.platform === 'darwin' 判断后在模板最前面插入：

  1. macOS 专用项：{ label: app.name, submenu: [{ role: 'about' }, …, { role: 'quit' }] }，把关于、服务、隐藏、退出都收在这里。
  2. 文件菜单末尾的退出项：macOS 用 { role: 'close' }（关窗），其他平台用 { role: 'quit' }（退出应用）。
  3. 窗口菜单里，macOS 额外加 { role: 'front' }，其他平台用 { role: 'close' }。

第三步才轮到自定义动作。只有系统没有内置的动作——比如"新建文件""打开文件…"——才自己写 click，并配上跨平台的 accelerator，例如 'CmdOrCtrl+N'、'CmdOrCtrl+Shift+S'；前缀用 CmdOrCtrl，就能在 macOS 上自动显示成 ⌘、在 Windows/Linux 上显示成 Ctrl。

第四步处理窗口的安全取用。click 里不要直接用某个保存下来的窗口变量（它可能已销毁），而是调用 BrowserWindow.getFocusedWindow() 取当前聚焦窗口并判空，取不到就安全返回。

最后补上下文菜单。右键菜单同样是一份模板，只是用 menu.popup({ window, x, y }) 在指定位置弹出。渲染进程拿不到 Menu，所以流程是：渲染进程把坐标通过 IPC 发给主进程，主进程用 BrowserWindow.fromWebContents(event.sender) 找到发起请求的窗口再弹出。还有一个容易忽略的点：菜单的更新是"重建再挂载"——要改菜单时，重新 buildFromTemplate 一份新的再 setApplicationMenu，而不是去改已挂载的那个实例。

两个边界：accelerator 只在应用聚焦（菜单栏可见）时生效；要让应用未聚焦时也响应按键，得改用 globalShortcut，两者职责别混。另外，菜单栏归属有平台差异——macOS 的菜单栏属于应用整体，Windows 与 Linux 的菜单栏属于某个窗口，这决定了你更新菜单时的影响范围。

菜单构建交还系统

原生菜单的关键，是把"菜单长什么样、点了做什么"交还给系统：用 buildFromTemplate 声明结构、用 setApplicationMenu 挂载，标准动作交给 role，平台差异用 process.platform 单独补，自定义动作才写 click 和 accelerator。它必须住在主进程——渲染进程只发一句"请求弹菜单"，真正的构建与系统绑定都发生在主进程。

「role（角色）」是 MenuItem 上声明"这一项是系统标准命令"的字段，例如 copy、paste、undo、quit。它会由系统实现行为、本地化文案并绑定默认快捷键。两条边界要记住：设了 role 就不该再指望自己的 click 生效（标准行为已经接管）；而且不是所有动作都有 role，业务动作必须自己写 click。

// ========== 1. 应用菜单 main.js ==========
const { app, BrowserWindow, Menu, MenuItem, shell } = require('electron')
const path = require('path')

// 构建菜单模板
function createMenu() {
  const template = [
    // App 菜单（macOS 专用，放在第一位）
    ...(process.platform === 'darwin' ? [{
      label: app.name,
      submenu: [
        { role: 'about' },
        { type: 'separator' },
        { role: 'services' },
        { type: 'separator' },
        { role: 'hide' },
        { role: 'hideOthers' },
        { role: 'unhide' },
        { type: 'separator' },
        { role: 'quit' }
      ]
    }] : []),

    // 文件菜单
    {
      label: '文件',
      submenu: [
        {
          label: '新建文件',
          accelerator: 'CmdOrCtrl+N',
          click: () => {
            console.log('新建文件')
          }
        },
        {
          label: '打开文件...',
          accelerator: 'CmdOrCtrl+O',
          click: async () => {
            // 打开文件对话框
          }
        },
        { type: 'separator' },
        {
          label: '保存',
          accelerator: 'CmdOrCtrl+S',
          click: () => {
            console.log('保存')
          }
        },
        {
          label: '另存为...',
          accelerator: 'CmdOrCtrl+Shift+S',
          click: () => {}
        },
        { type: 'separator' },
        // 不同平台的退出位置
        process.platform === 'darwin'
          ? { role: 'close' }
          : { role: 'quit' }
      ]
    },

    // 编辑菜单
    {
      label: '编辑',
      submenu: [
        { role: 'undo' },      // 撤销
        { role: 'redo' },      // 重做
        { type: 'separator' },
        { role: 'cut' },       // 剪切
        { role: 'copy' },      // 复制
        { role: 'paste' },     // 粘贴
        { role: 'selectAll' }, // 全选
        { type: 'separator' },
        {
          label: '查找',
          accelerator: 'CmdOrCtrl+F',
          click: () => {}
        }
      ]
    },

    // 视图菜单
    {
      label: '视图',
      submenu: [
        { role: 'reload' },
        { role: 'forceReload' },
        { role: 'toggleDevTools' },
        { type: 'separator' },
        { role: 'resetZoom' },
        { role: 'zoomIn' },
        { role: 'zoomOut' },
        { type: 'separator' },
        { role: 'togglefullscreen' }
      ]
    },

    // 窗口菜单
    {
      label: '窗口',
      submenu: [
        { role: 'minimize' },
        { role: 'zoom' },
        ...(process.platform === 'darwin' ? [
          { type: 'separator' },
          { role: 'front' },
          { type: 'separator' },
          { role: 'window' }
        ] : [
          { role: 'close' }
        ])
      ]
    },

    // 帮助菜单
    {
      label: '帮助',
      submenu: [
        {
          label: '官方文档',
          click: async () => {
            await shell.openExternal('https://www.electronjs.org/docs')
          }
        },
        {
          label: '关于',
          click: () => {
            // 显示关于对话框
          }
        }
      ]
    }
  ]

  // 构建菜单
  const menu = Menu.buildFromTemplate(template)
  // 设置为应用菜单
  Menu.setApplicationMenu(menu)

  return menu
}

// ========== 2. 动态添加菜单项 ==========
function addDynamicMenuItem() {
  const menu = Menu.getApplicationMenu()
  if (!menu) return

  const fileMenu = menu.items.find(item => item.label === '文件')
  if (fileMenu && fileMenu.submenu) {
    fileMenu.submenu.append(new MenuItem({
      label: '最近打开',
      submenu: [
        { label: 'file1.txt', click: () => {} },
        { label: 'file2.txt', click: () => {} }
      ]
    }))
    // 重新设置菜单
    Menu.setApplicationMenu(menu)
  }
}

// ========== 3. 上下文菜单（右键菜单） ==========
// 方式一: 主进程中创建，通过 IPC 调用
function showContextMenu(win, x, y) {
  const contextMenu = Menu.buildFromTemplate([
    { label: '复制', role: 'copy' },
    { label: '粘贴', role: 'paste' },
    { type: 'separator' },
    {
      label: '自定义操作',
      click: () => {
        console.log('执行自定义操作')
      }
    },
    {
      label: '在浏览器中打开链接',
      click: async () => {
        await shell.openExternal('https://example.com')
      }
    }
  ])

  contextMenu.popup({
    window: win,
    x,
    y
  })
}

// ========== 6. 动态切换菜单 ==========
function updateMenuForLoginState(isLoggedIn) {
  const template = [
    {
      label: '账户',
      submenu: isLoggedIn
        ? [
            { label: '个人中心', click: () => {} },
            { label: '设置', click: () => {} },
            { type: 'separator' },
            { label: '退出登录', click: () => {} }
          ]
        : [
            { label: '登录', click: () => {} },
            { label: '注册', click: () => {} }
          ]
    }
  ]
  const menu = Menu.buildFromTemplate(template)
  Menu.setApplicationMenu(menu)
}
