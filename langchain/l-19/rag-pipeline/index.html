RAG 完整流水线实现

端到端实现文档加载、切分、向量化、存储、检索、重排、生成的完整 RAG 流水线。

开场问题：加载、切分、向量化、检索、生成——单独拎出来每一步你都会写，可它们散在几个脚本片段里：换一份文档要改三处参数，想临时加一步「重排」发现函数签名对不上；等用户追问「这条答案你是从哪看到的」，你支支吾吾答不上来，后台也翻不出依据。

流水线环节割裂

前面的课里，文档切分、向量检索你都已经单独跑通过。但真正要交付的，不是几个能跑的片段，而是一条能反复跑的流水线：加载 → 切分 → 向量化 → 存储 → 检索 → 重排 → 生成，七个环节首尾相接。

旧办法是把每一步写成临时脚本，用的时候手工拼。它把三笔成本留给了你：

  1. 参数到处散：切分大小、嵌入模型、生成温度散落在不同文件，换个文档或换套模型要满仓库找。
  2. 中间结果不留痕：某一环出了问题，你没有留存下来的中间产物可以定位，只能靠猜。
  3. 回答没有出处：生成的是纯文本，用户无法核对，你也无法回溯到具体是哪份文档支撑了这句话。

要回答的是：怎样把七个环节收成一条可复用的流水线，并在其中补上「精排」与「溯源」，让回答既准又可查？

七环节单类封装

最朴素的做法：写一个类 RAGPipeline，把七个环节收成七个方法；再给两个组合方法——buildIndex 串起「加载、切分、向量化、存储」前四步，query 串起「检索、重排、生成」后三步。所有可调参数（chunkSize、chunkOverlap、嵌入模型、温度）在构造函数里定死。

这个方案做对了一件事：它把「一次性的脚本」变成了「可复用的对象」。参数收敛到一处，换文档只改输入、换模型只改构造，流水线的形状不再跟着实现细节乱动。

相似度排序局限

  • 检索回来的 Top-K 是按向量相似度排的，可「最像」不等于「最相关」：字面高度相似、其实没用的噪声块会混进上下文。
  • 检索结果不是越多越好：往提示词里塞太多块会稀释上下文、还白烧 token，真正的关键句被淹没。
  • 回答没有标注来源：用户无法核对依据，出了问题也追不回是哪份文档支撑的。
  • 文档更新后没有统一的「重建口径」，新旧内容混在同一个索引里，答案时效说不清。
  • 中间结果不留痕：某次答错了，你判断不了到底是切分切碎了，还是检索压根没召回。

检索后插入重排

不推翻这条七步流水线，而是在它上面补三层。

第一步，把节点收进类里之后，在「检索」与「生成」之间插入一步「重排」。检索阶段负责「不漏」，先宽召回一批候选（比如 k=10）；重排阶段再对这批候选逐条精算相关性，把最相关的少数几条排到最前。真实项目里这一步用交叉编码器或 Cohere Rerank 之类的重排模型，它能显著提升送进提示词那几条的质量。本课演示里的「重排」是占位实现（保持原顺序返回），正是留给你接真实重排模型的位置。

第二步，控制进提示词的块数。重排之后只保留最相关的少数几条，别把召回的全部塞进去——上下文被稀释，模型反而抓不住重点，还徒增成本。

第三步，把来源带出来。每个文档块都保留它的 metadata（来源、主题、更新时间），生成答案时连同命中的来源一起返回，做到「答得出来、也查得到」。离线建索引时就记好来源与更新时间，在线回答时才好标注依据、判断时效——本课演示的「检索到的文档」面板，就是把这一步的中间结果摊开给你看。

端到端才叫流水线：七个环节是逐级传递的，任何一环质量不足都会让最终回答失真——切分太碎，检索召回的就没有完整语义；召回太少，重排也变不出没有的答案。所以要分环节测量（召回好不好、重排有没有把相关的排上来、答案对不对），而不是只盯着最后那句回答。

链路复用与来源标注

RAG 流水线的价值在于把加载、切分、向量化、存储、检索、重排、生成七个环节收成一条可复用的链路。其中「重排」负责把最相关的排到最前、「来源标注」负责让答案可查，而整条链的质量必须分环节测量——只盯最终回答，是找不到问题出在哪一环的。

「重排（Rerank）」是在向量召回之后、生成之前插入的一道精排工序：用更强的相关性模型（交叉编码器，或 Cohere Rerank 一类服务）对候选文档逐条打分，再取最相关的少数几条送进提示词。它与召回的分工是——召回负责「不漏」，重排负责「排准」。边界：重排更慢更贵，所以只对少量候选执行；它换不掉召回，候选集里根本没有的答案，重排也变不出来。

import { ChatOpenAI } from '@langchain/openai'
import { OpenAIEmbeddings } from '@langchain/openai'
import { MemoryVectorStore } from 'langchain/vectorstores/memory'
import { Document } from '@langchain/core/documents'
import { RecursiveCharacterTextSplitter } from 'langchain/text_splitter'
import { ChatPromptTemplate } from '@langchain/core/prompts'
import { StringOutputParser } from '@langchain/core/output_parsers'
import { RunnableSequence, RunnablePassthrough } from '@langchain/core/runnables'

// 示例1: 完整 RAG 流水线类
class RAGPipeline {
  private vectorStore: MemoryVectorStore | null = null
  private embeddings: OpenAIEmbeddings
  private model: ChatOpenAI
  private textSplitter: RecursiveCharacterTextSplitter

  constructor() {
    this.embeddings = new OpenAIEmbeddings({ model: 'text-embedding-3-small' })
    this.model = new ChatOpenAI({ model: 'gpt-4o-mini', temperature: 0 })
    this.textSplitter = new RecursiveCharacterTextSplitter({
      chunkSize: 500,
      chunkOverlap: 100,
      separators: ['\n\n', '\n', '。', '！', '？', '，', ' ', ''],
    })
  }

  // 第一步：文档加载
  async loadDocuments(texts: string[], metadatas: Record<string, any>[] = []): Promise<Document[]> {
    const docs = texts.map((text, i) => 
      new Document({
        pageContent: text,
        metadata: metadatas[i] || { id: i },
      })
    )
    console.log(`加载了 ${docs.length} 个文档`)
    return docs
  }

  // 第二步：文本切分
  async splitDocuments(docs: Document[]): Promise<Document[]> {
    const splitDocs = await this.textSplitter.splitDocuments(docs)
    console.log(`切分为 ${splitDocs.length} 个块`)
    return splitDocs
  }

  // 第三步：向量化并存储
  async indexDocuments(docs: Document[]): Promise<void> {
    this.vectorStore = await MemoryVectorStore.fromDocuments(
      docs,
      this.embeddings
    )
    console.log('文档已索引到向量存储')
  }

  // 第四步：检索
  async retrieve(query: string, k: number = 4): Promise<Document[]> {
    if (!this.vectorStore) {
      throw new Error('向量存储未初始化')
    }
    const docs = await this.vectorStore.similaritySearch(query, k)
    console.log(`检索到 ${docs.length} 个相关文档`)
    return docs
  }

  // 第五步：重排（简单实现：基于相关性分数重新排序）
  async rerank(query: string, docs: Document[]): Promise<Document[]> {
    // 实际项目中可使用 Cohere Rerank 或交叉编码器
    // 这里简单返回原顺序作为示例
    console.log(`重排 ${docs.length} 个文档`)
    return docs
  }

  // 第六步：生成回答
  async generate(query: string, docs: Document[]): Promise<string> {
    const context = docs
      .map((doc, i) => `[文档${i + 1}] ${doc.pageContent}`)
      .join('\n\n')

    const prompt = ChatPromptTemplate.fromTemplate(`
你是一个专业的问答助手。请根据以下上下文回答用户的问题。
如果上下文中没有答案，请诚实地说"根据现有资料无法回答这个问题"。

上下文：
{context}

用户问题：{question}

回答：
`)

    const chain = prompt.pipe(this.model).pipe(new StringOutputParser())
    const answer = await chain.invoke({
      context,
      question: query,
    })
    return answer
  }

  // 端到端查询
  async query(question: string): Promise<{
    answer: string
    retrievedDocs: Document[]
  }> {
    // 1. 检索
    const retrievedDocs = await this.retrieve(question)
    
    // 2. 重排
    const rerankedDocs = await this.rerank(question, retrievedDocs)
    
    // 3. 生成
    const answer = await this.generate(question, rerankedDocs)
    
    return { answer, retrievedDocs: rerankedDocs }
  }

  // 批量索引
  async buildIndex(texts: string[], metadatas: Record<string, any>[] = []): Promise<void> {
    const docs = await this.loadDocuments(texts, metadatas)
    const splitDocs = await this.splitDocuments(docs)
    await this.indexDocuments(splitDocs)
  }
}

// 示例3: 带源引用的 RAG
class RAGWithSources extends RAGPipeline {
  async queryWithSources(question: string): Promise<{
    answer: string
    sources: string[]
  }> {
    const { answer, retrievedDocs } = await this.query(question)
    
    const sources = retrievedDocs.map(doc => 
      doc.metadata.source || doc.metadata.topic || '未知来源'
    )
    
    return { answer, sources }
  }
}
