Tools：工具定义与调用

用工具注册表展示 tool 函数的定义、Zod 参数 Schema 和调用过程。

开场问题：你给 Agent 挂了一个「查天气」工具，用户问「北京今天多少度」。结果模型把 city 参数填成了「今天」，工具真去查了一个叫「今天」的城市，直接报错。你没写错函数——你只是没把「这个参数要填城市名」讲清楚。

函数描述可读性

模型要调用的是你写的真实函数，但它只看得到文字。它不知道这个函数叫什么名字、要收几个参数、每个参数是什么类型、能不能留空。它做出的一切判断，都只能来自你给它的那段描述。

用「一句话自然语言描述」来交代工具，成本会一点点堆到你身上。

  1. 描述和代码要两头维护：每个工具的说明都手写在提示词里，改一次函数就得同步改一次描述，漏一处模型就开始瞎猜。
  2. 参数格式全靠解析：模型返回的是一串文本，「2 加 3」和数字 5 分不清，得自己写解析逻辑，格式稍变就崩。
  3. 不该填的地方填了，没人拦：该给数字的地方给了字符串、该给城市名的地方给了日期，工具照单全收，最后报错在一层之外。

于是问题落在：怎么把「一个真实的函数」翻译成「模型能看懂、还会照着填的说明书」？

提示词内描述

最朴素的做法：写个普通函数，再用一句话把它写进提示词——「有一个查天气的工具，大概能查某地天气」，然后让模型输出「想用哪个工具、参数是什么」，你拿到文本再自己解析、执行。

这个方案做对了一件事：它把「模型」和「真实能力」接上了。在此之前模型只会说话，现在它第一次能触发一段真正的代码——这个方向是对的。

参数校验缺失

  • 模型返回的参数是一整段纯文本，解析规则稍一变化就失败，而且失败得很隐蔽。
  • 没有类型约束：该填数字的地方它填了文本，该填城市名的地方它填了日期，你只能在运行时才来得及发现。
  • 参数一多、或某个参数只能从几个固定值里选时，纯文字描述根本管不住格式。
  • 解析失败时模型无从得知自己错了，只能整段重来，白白烧掉一轮 token。

工具声明三要素

不推翻「让模型调用真实函数」，而是把「描述」从一句话升级成一份结构化声明。第一步补：让每个工具同时声明三件事——名字（name，给机器定位）、用途（description，给你和模型判断「什么时候该用它」）、参数长什么样（schema，管住输入结构）。三者分家，各管一段。

第二步补类型约束：用 Zod 把参数 schema 写成带类型和范围的定义——哪个字段是文本、哪个是数字、哪个只能从几个枚举值里挑。有了它，模型产出的参数从「待解析的字符串」变成了「有类型的结构化对象」。先补类型，是因为开场那个「城市名填成今天」的错误，本质就是类型与格式没被约束住。

第三步补统一的封装：用 tool 函数把「声明 + 执行函数」打包成一个对象，注册给 Agent。模型按声明选工具、按 schema 填参数，运行时按名字找到对应函数、先校验参数再真正执行。到这一步，那个「参数填错却没人拦」的漏洞被堵上了——错类型根本进不到执行函数里。

第四步补错误处理：在执行函数里罩住异常和超时，并把「模型看得懂的一句话」返回回去——比如「城市名无效，请填写城市名称」。为什么放最后补？因为工具失败是常态（网络不通、参数越界、外部接口抖动），把失败变成模型能读懂的一句反馈，它才有机会改参数重试，而不是让整条推理就此中断。

两条边界要记住：描述必须写清「适用场景」和「输入格式」，这是模型挑不挑得对、填不填得准的唯一依据；参数 schema 越精确，传参错误就越少。另外，现在推荐用 tool 函数加 Zod 声明，旧版那种只收一个字符串的 DynamicTool 写法已不推荐。

工具描述不是注释，是给模型看的「使用说明书」：它会被整段交给模型，模型正是靠它决定「这个工具是干什么的、什么时候该调、参数怎么填」。描述写得含糊（比如只写「搜索」两个字），模型就会在该调时调错、或者填错参数——这不是模型笨，是你没把话说清。

三工具声明对照

类型约束声明

工具是 Agent 伸向外部世界的手，而这只手能不能被用好，取决于你会不会「写说明书」。用一份带类型约束的声明把名字、用途、参数结构一次讲清，模型才选得对、填得准；在执行函数里兜住错误、回一句人话，它才有机会自己修正。工具定义的质量，就是 Agent 能力的上限。

「参数 Schema」是对工具输入参数的结构化声明，描述每个参数的名字、类型、是否必填以及取值范围（LangChain.js 里通常用 Zod 表达）。它同时被交给模型（决定它填什么）和用于运行时（校验它填得对不对）。边界是：Schema 约束的是「形状」，填得「对不对、合不合业务」仍要执行函数自己判断，并返回可读的错误信息。

TypeScript
import { tool, Tool } from '@langchain/core/tools'
import { z } from 'zod'
import { ChatOpenAI } from '@langchain/openai'

// 示例1: 使用 tool 函数定义工具（推荐方式）
const weatherTool = tool(
  async ({ city, date }) => {
    const mockWeather: Record<string, any> = {
      '北京': { temp: 25, condition: '晴', humidity: 45 },
      '上海': { temp: 28, condition: '多云', humidity: 65 },
      '深圳': { temp: 32, condition: '雷阵雨', humidity: 80 },
    }
    const weather = mockWeather[city] || { temp: 20, condition: '未知', humidity: 50 }
    return `${city} ${date} 天气: ${weather.condition}, 温度 ${weather.temp}°C, 湿度 ${weather.humidity}%`
  },
  {
    name: 'get_weather',
    description: '获取指定城市的天气信息。查询天气预报时使用。',
    schema: z.object({
      city: z.string().describe('城市名称，如"北京"、"上海"'),
      date: z.string().describe('日期，格式 YYYY-MM-DD'),
    }),
  }
)

console.log('工具名称:', weatherTool.name)
console.log('工具描述:', weatherTool.description)

// 示例2: 直接调用工具
const result = await weatherTool.invoke({ city: '北京', date: '2024-07-01' })
console.log('调用结果:', result)

// 示例3: 定义多个工具
const searchTool = tool(
  async ({ query }) => {
    return `搜索"${query}"的结果：...`
  },
  {
    name: 'web_search',
    description: '搜索网络获取信息',
    schema: z.object({
      query: z.string().describe('搜索关键词'),
    }),
  }
)

const calculatorTool = tool(
  async ({ a, b, operation }) => {
    let result: number
    switch (operation) {
      case 'add': result = a + b; break
      case 'subtract': result = a - b; break
      case 'multiply': result = a * b; break
      case 'divide': result = a / b; break
      default: result = 0
    }
    return `${a} ${operation} ${b} = ${result}`
  },
  {
    name: 'calculator',
    description: '执行基础数学运算',
    schema: z.object({
      a: z.number().describe('第一个数字'),
      b: z.number().describe('第二个数字'),
      operation: z.enum(['add', 'subtract', 'multiply', 'divide']).describe('运算类型'),
    }),
  }
)

const tools = [weatherTool, searchTool, calculatorTool]

// 示例4: 模型调用工具（Function Calling）
const model = new ChatOpenAI({ model: 'gpt-4o-mini' }).bind({
  tools: tools.map(t => ({
    type: 'function' as const,
    function: {
      name: t.name,
      description: t.description,
      parameters: (t as any).schema ? (t as any).schema : {},
    },
  })),
})

// 示例5: 使用 withStructuredOutput 实现工具调用
const modelWithTools = new ChatOpenAI({ model: 'gpt-4o-mini' }).bindTools(tools)

const response = await modelWithTools.invoke([
  { role: 'user', content: '北京今天天气怎么样？' }
])

// 检查是否有工具调用
if (response.tool_calls && response.tool_calls.length > 0) {
  console.log('工具调用:', response.tool_calls)
  // 执行工具调用
  for (const toolCall of response.tool_calls) {
    const toolInstance = tools.find(t => t.name === toolCall.name)
    if (toolInstance) {
      const toolResult = await toolInstance.invoke(toolCall.args)
      console.log('工具结果:', toolResult)
    }
  }
}

// 示例6: 继承 Tool 类定义工具（旧方式）
class CustomSearchTool extends Tool {
  name = 'custom_search'
  description = '自定义搜索工具'

  async _call(input: string): Promise<string> {
    return `搜索结果: ${input}`
  }
}

const customTool = new CustomSearchTool()

// 示例7: 工具的元数据和标签
const taggedTool = tool(
  async ({ query }) => `结果: ${query}`,
  {
    name: 'tagged_search',
    description: '带标签的搜索工具',
    schema: z.object({ query: z.string() }),
    tags: ['search', 'production'],
    metadata: { version: '1.0.0' },
  }
)
console.log('工具标签:', taggedTool.tags)
console.log('工具元数据:', taggedTool.metadata)
