RAG 基础：文档加载与文本切分

用文档切分器展示 RecursiveCharacterTextSplitter 的块大小和重叠量配置。

开场问题：你把一份 20 页的产品手册整篇倒进向量库。用户问「退款一般几个工作日到账」，检索回来的却是整章《售后服务政策》——那句「3 到 7 个工作日」就淹没在这三千多字里，模型读了半天，要么漏掉，要么干脆自己编了个数字。

整篇入库粒度

我们把「给知识库建索引」想得太简单了：好像把整篇文档丢进去，检索时它就会自己找到相关的那一句。可实际上，一篇长文档里藏着几十上百个主题，你把它当成一个整体去向量化、去检索，就等于把几十个主题平均成了一个点——它跟谁都沾一点关系，跟谁都不真正接近。

坚持「整篇不拆」要付的代价，全都落在你身上。

  1. 检索粒度过粗：问一句具体的话，系统回你一整章，真正有用的那一句得靠模型自己从几千字里捞。
  2. 上下文塞不下：一篇文档动辄上万字，想整篇喂给模型，还没等回答就先撞上了 token 上限。
  3. 相似度被摊平：一篇文章一个向量，细节被平均掉，检索出来的「最相关」常常并不是你要的那一段。

于是问题落在一个很具体的动作上：能不能先把长文拆成「一问一答那么大」的小块，再让每一块单独去参与检索？

固定长度硬切

最省事的做法是按固定长度硬切：从头开始，每 200 个字符切一刀，切到结尾为止，于是有了块 1、块 2、块 3……

这个方案做对了一件事：把「一篇文档」拆成了一堆可以被独立处理的单元。颗粒度一下子从「一整章」缩到了「一小段」，检索时至少能命中某个更小的范围，前面那个「答案淹没在大块里」的毛病解决了一大半。

切点落在句中

  • 硬切不看内容，一刀正好落在句子里，把「3 到 7 个工作」和「日到账」劈成两块，命中哪一块都拼不出完整句子。
  • 有些答案天生要跨块：一句结论在块 1 末尾、支撑它的数据在块 2 开头，两块各自都看不全，模型就还原不出完整事实。
  • 中文不像英文有空格，按固定字数硬切还能把「售后服务」切成「售后服」和「务」这种无意义的碎片。
  • 固定长度完全无视文档结构，小标题、段落这些天然的语义边界被一律忽略，切点是随机的，而不是有意义的。

分隔符层级递归

不推翻「切小」，而是改变「在哪下刀」。第一步补分隔符层级：维护一张按优先级排好的分隔符表——段落（空行）、换行、句号、逗号、空格。切分时先用最高优先级的分隔符切；如果切出来的某一段还是超过 chunkSize，就对这一段降一级、用下一档分隔符继续切，一路降下去直到每块接近目标大小。这就是 RecursiveCharacterTextSplitter 里「递归」的含义——它不是递归函数，而是分隔符按层级逐级降级。先补层级，是因为它保证每一刀尽量落在语义边界上，而不是句子的正中间。

第二步补块重叠：让相邻块之间保留一段重复的内容（例如 chunkOverlap 取 40 个字符），前一块的结尾在后一块的开头再出现一次。为什么非要重叠？因为即便下刀落在句号上，句号两侧的内容也天然相关；让边界处的文本被两块同时看到，开场那种「答案横跨两个块」的问题就被救了回来——只要命中其中任一块，上下文都是完整的。

第三步补来源元数据：给每个块都带上它出自哪份文件、哪个章节、第几页。为什么放这里补？因为切完之后的碎片本身是没有出处的，检索命中一块却不知道它从哪来，就无法回溯原文、也无法展示引用；补上元数据，块才真正「可用」。

最后是取值的边界：chunkSize 通常落在 500 到 1500 字符之间——太小丢上下文，太大降精度；chunkOverlap 一般取 chunkSize 的 10% 到 20%。而代码这类对结构敏感的内容，应换用语言专用的切分器，按函数、按类来切，而不是按字符数。

重叠不是越大越好：chunkOverlap 的职责只是维持边界处的连续性，一旦设得过大（比如接近 chunkSize 的一半），检索结果会大段重复、白白浪费 token，还可能让同一段答案在 Top-K 里占掉好几个名额。

块大小与重叠量

切分边界准则

切分是 RAG 的第一道工序，它要回答的从来不是「切多长」，而是「在哪下刀」。按分隔符层级递归地切，让每一刀尽量落在句子、段落的边界上，再用重叠把边界处的上下文补回来，顺便给每块记下出处——颗粒度合适了，后面的检索和生成才有得谈。

「递归字符切分」是一种按分隔符优先级逐级降级的切分策略：先用段落分隔符切，某块仍超长时再降级用换行、句子、标点继续切，直到每块接近 chunkSize，配合 chunkOverlap 维持边界上下文。边界是：它按字符数而非语义单位度量，代码、表格等结构敏感的内容应改用对应的专用切分器。

const splitter = new RecursiveCharacterTextSplitter({
  chunkSize: 200,
  chunkOverlap: 40,
  separators: ['\n\n', '\n', '。', '，', ' '],
})

const docs = await splitter.createDocuments([longText])
console.log(`切分为 ${docs.length} 个块`)
docs.forEach((doc, i) => {
  console.log(`块${i + 1} (${doc.pageContent.length}字符): ${doc.pageContent.slice(0, 50)}...`)
})

const jsCode = `
function calculateSum(arr) {
  let sum = 0;
  for (let i = 0; i < arr.length; i++) {
    sum += arr[i];
  }
  return sum;
}

class DataProcessor {
  constructor(data) {
    this.data = data;
  }

  process() {
    return this.data.map(item => item * 2);
  }
}

const numbers = [1, 2, 3, 4, 5];
console.log(calculateSum(numbers));
`

const jsSplitter = RecursiveCharacterTextSplitter.fromLanguage('js', {
  chunkSize: 150,
  chunkOverlap: 30,
})

const jsChunks = await jsSplitter.createDocuments([jsCode])
console.log(`JS代码切分为 ${jsChunks.length} 块`)
