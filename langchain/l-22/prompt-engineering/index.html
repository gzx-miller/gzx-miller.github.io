提示词工程最佳实践

掌握角色设定、清晰指令、示例引导、思维链、结构化输出等提示词工程核心技巧。

开场问题：你在提示词里要求「用 200 字介绍虚拟 DOM」，模型给你洋洋洒洒 800 字；你补上一句「请简洁一点」，它反而更啰嗦了——说的是同一件事，为什么结果每次都不一样？

自然语言指令歧义

LLM 的行为由输入决定，可自然语言输入天生模糊。「把这段解释一下」——解释给谁看？多长？什么格式？你心里有数，但没写下来，模型只能靠猜。猜到什么算什么，于是每次结果都飘。

只写一句需求的旧做法，把三笔成本留给了你：

  • 结果不稳定，同一个问题要重跑几遍，再挑一个勉强能用的。
  • 格式不统一，想拿 JSON 却总是收到一段话，程序没法直接消费。
  • 判别标准藏在你的脑子里——什么算「正面」、什么算「简洁」，模型无从对齐。

要回答的是：输入到底该怎么写，才能让模型的输出稳定、可控、能直接进下游？

约束条件显式化

最省事的一步是把要求写具体：把「解释一下」换成「用 200 字，分三段——定义、原理、应用场景，面向初学者」。

这个方案做对了一件事：它把隐式的期望变成了显式的约束。字数、结构、面向谁，从「模型猜」变成「你定」。有了这几条硬指标，输出至少不会再漫无边际。

格式规范与标签失准

  • 光有指令，判别标准还是模糊：让模型给评论打「正面 / 负面 / 中性」，它可能回你一个「比较正面」——既不在你给的标签里，格式也不齐。
  • 复杂推理直接要答案容易错：模型一步跳到结论，中间的推导被跳过，错了也无从检查。
  • 输出格式依然不稳：你要求 JSON，它可能先来一句「好的，这是结果」，或者套一层代码围栏，下游解析直接失败。
  • 同一套措辞换个领域就失灵，没有可复制的套路，只能靠灵感。

角色设定与思维链

不推翻「把要求写具体」，而是按「谁在说、看样例、再推理、给结构」的顺序，一层层把模糊补成显式。

  1. 给角色：在 system 提示里框定身份，比如「你是一位资深前端架构师」。
  2. 说任务：把要做的事、输出长度与结构写清楚。
  3. 给样例：用几组「输入到期望输出」的样例把判别标准对齐。
  4. 引导推理：要求模型先分步思考，再给结论。

第一步先补角色，因为它一次性约束了全局：语气、关注点、用词深浅。同样是给代码建议，「资深架构师」和「科普作者」给出的侧重完全不同。为什么先补它？因为它是后面所有要求的总基调。

第二步补示例，也就是 Few-shot。判别标准光用文字描述总有歧义，但当你在提示里放上「正面 / 负面 / 中性」各一条样例，模型看到的是「长这样才算正面」。样例把抽象标签变成了看得见的标尺，尤其适合分类、改写这类「你说的和我理解的不一样」的任务。

第三步补思维链（Chain of Thought）。对数学题、多步推理这类任务，让模型「一步步思考再给结论」，等于把一步到位的猜测拆成一段可检查的推导。中间步骤暴露出来后，你既能看出它在哪一步想歪，复杂任务的整体准确率也会提高。

第四步补结构化输出。明确要求按 JSON 或指定字段返回，把「格式」也变成显式约束；需要生产级稳定时，再配合输出解析器（如 Zod schema）在程序侧强制校验——提示词负责引导，解析器负责兜底。

最后一件事常被忽略：提示词是要迭代的。别指望一次写对，要拿真实样例反复跑、对比、修正；而且要像对待代码那样做版本管理与回归测试——只改了几个字，可能弄好了一个场景、弄坏了另一个。事实类任务用低温度压住随机性，创作类任务才调高温度换取多样性。

提示词改动会「牵一发动全身」：它在上下文里不是独立模块，改了 A 段的措辞，可能影响 B 场景的判断。每次改动都要拿一组固定样例回归验证，别等上线后才发现旧功能退化。

五种提示技巧对照

期望显式化五要素

提示词工程本质上是「把隐式期望显式化」：用角色定基调、用清晰指令定任务、用 Few-shot 定标准、用思维链定推理过程、用结构化输出定格式，再靠真实样例迭代与回归。模型的能力没变，变的只是你喂给它的约束有多清楚。

「少样本提示（Few-shot Prompting）」指在提示词里给出少量「输入到期望输出」的示例，让模型照着示例对齐输出格式与判别标准；它不更新模型参数，只通过本次上下文影响行为。边界：示例要典型并覆盖边界类别，数量和顺序都可能影响结果；示例过多会挤占上下文、推高成本；它与「微调」（真正改动参数）不是一回事。

import { ChatOpenAI } from '@langchain/openai'
import { ChatPromptTemplate, FewShotChatMessagePromptTemplate } from '@langchain/core/prompts'
import { StringOutputParser } from '@langchain/core/output_parsers'

const model = new ChatOpenAI({ model: 'gpt-4o-mini', temperature: 0.7 })
const parser = new StringOutputParser()

// 示例1: 角色设定 (Role Prompting)
const rolePrompt = ChatPromptTemplate.fromMessages([
  ['system', `你是一位资深的前端架构师，拥有10年开发经验。
你擅长 Vue、React、TypeScript 等技术栈。
回答问题时请：
1. 先给出简洁的结论
2. 然后详细解释原理
3. 最后提供实践建议
请用专业但易懂的中文回答。`],
  ['human', '{question}'],
])

const roleChain = rolePrompt.pipe(model).pipe(parser)

const roleResult = await roleChain.invoke({
  question: '前端项目应该选择 Vue 还是 React？',
})
console.log('角色设定结果:\n', roleResult.slice(0, 200) + '...')

// 示例2: 清晰指令 + 输出格式约束
const formatPrompt = ChatPromptTemplate.fromMessages([
  ['system', '你是一个技术文档写作助手。'],
  ['human', `
请为以下技术概念写一段解释：

概念: {concept}

要求:
1. 用通俗的语言解释，让初学者能理解
2. 字数控制在 200-300 字
3. 分为三段：
   - 第一段：定义和核心作用
   - 第二段：工作原理
   - 第三段：应用场景
4. 不要使用过于专业的术语，如果必须使用请解释
`],
])

const formatChain = formatPrompt.pipe(model).pipe(parser)

const formatResult = await formatChain.invoke({
  concept: '虚拟 DOM',
})
console.log('\n格式约束结果:\n', formatResult)

// 示例3: Few-shot 示例引导
const examples = [
  { input: '产品质量很好，物流也快', output: '正面' },
  { input: '包装破损了，有点失望', output: '负面' },
  { input: '还可以吧，中规中矩', output: '中性' },
  { input: '性价比超高，强烈推荐！', output: '正面' },
]

const examplePrompt = ChatPromptTemplate.fromMessages([
  ['human', '{input}'],
  ['ai', '{output}'],
])

const fewShotPrompt = new FewShotChatMessagePromptTemplate({
  examples,
  examplePrompt,
  prefix: '请判断以下评论的情感倾向（正面/负面/中性）：',
  suffix: ['human', '{input}'],
})

const sentimentPrompt = ChatPromptTemplate.fromMessages([
  fewShotPrompt,
])

const sentimentChain = sentimentPrompt.pipe(model).pipe(parser)

const sentimentResult = await sentimentChain.invoke({
  input: '用了一个月了，质量真的不错，下次还买',
})
console.log('\nFew-shot 情感分析:', sentimentResult)

// 示例4: 思维链 (Chain of Thought, CoT)
const cotPrompt = ChatPromptTemplate.fromMessages([
  ['system', '你是一个逻辑推理助手。请逐步思考后给出答案。'],
  ['human', `
问题: {question}

请按以下步骤回答：
1. 首先，明确问题是什么
2. 然后，列出已知条件
3. 接着，逐步推导
4. 最后，给出结论

让我们一步一步来思考。
`],
])

const cotChain = cotPrompt.pipe(model).pipe(parser)

const cotResult = await cotChain.invoke({
  question: '一个水池有进水管和出水管，单独开进水管6小时可以注满，单独开出水管8小时可以放完。如果同时打开两个水管，需要多少小时可以注满水池？',
})
console.log('\n思维链结果:\n', cotResult.slice(0, 300) + '...')

// 示例5: 结构化输出提示

// 示例6: 自我一致性 (Self-Consistency)
async function selfConsistency(question: string, numSamples: number = 3): Promise<string> {
  const cotPrompt = ChatPromptTemplate.fromMessages([
    ['system', '你是一个数学题解答助手。请详细写出解题步骤。'],
    ['human', '{question}\n\n请逐步解答：'],
  ])
  
  const cotChain = cotPrompt.pipe(model).pipe(parser)
  
  // 生成多个答案
  const answers = []
  for (let i = 0; i < numSamples; i++) {
    const answer = await cotChain.invoke({ question })
    answers.push(answer)
    console.log(`答案 ${i + 1}: ...`)
  }
  
  // 用 LLM 选择最一致的答案
  const judgePrompt = ChatPromptTemplate.fromTemplate(`
以下是对同一个问题的多个解答，请选出最合理的一个答案：

问题: {question}

解答1:
{answer1}

解答2:
{answer2}

解答3:
{answer3}

请选择最合理的解答，并说明理由。
`)
  
  const judgeChain = judgePrompt.pipe(model).pipe(parser)
  
  const finalAnswer = await judgeChain.invoke({
    question,
    answer1: answers[0],
    answer2: answers[1],
    answer3: answers[2],
  })
  
  return finalAnswer
}

// 示例7: 提示词迭代优化对比
async function comparePrompts() {
  const question = '什么是闭包？'
  
  // 版本1: 简单提问
  const simplePrompt = ChatPromptTemplate.fromTemplate('{question}')
  const simpleChain = simplePrompt.pipe(model).pipe(parser)
  const simpleResult = await simpleChain.invoke({ question })
  console.log('=== 简单提问 ===')
  console.log(simpleResult.slice(0, 100) + '...')
  
  // 版本2: 角色 + 结构
  const betterPrompt = ChatPromptTemplate.fromMessages([
    ['system', '你是一位资深的 JavaScript 讲师，擅长把复杂概念讲得通俗易懂。'],
    ['human', `
请解释 "{concept}" 这个概念：

要求：
1. 用大白话解释，让初学者能懂
2. 举一个生活中的类比
3. 写一段简单的代码示例
4. 说明它的常见用途
`],
  ])
  const betterChain = betterPrompt.pipe(model).pipe(parser)
  const betterResult = await betterChain.invoke({ concept: question })
  console.log('\n=== 优化后 ===')
  console.log(betterResult.slice(0, 150) + '...')
}
