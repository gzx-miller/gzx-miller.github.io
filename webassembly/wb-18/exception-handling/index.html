异常处理：tag 与 throw

用除零保护演示 Wasm 抛出携带负载的异常并由 JS 捕获。

开场问题：你在 Wasm 里写了个订单金额的计算，除数为 0 时想向上游报一个「DIV_ZERO，字段是 discount」的错误。可选的路只有两条：返回 -1，让调用方自己去背「负数代表什么」的表；或者干脆让它崩掉——一旦崩了，JS 只收到一句干巴巴的 RuntimeError，是哪个订单、哪个字段出的错，全没了。为什么「报错」和「崩溃」在 Wasm 里会是两种完全不同的东西？

错误码语义重载

先看清两条旧路的隐藏成本。返回错误码：错误和正常结果共用同一个返回值通道，-1 既可能是「出错」，也可能是一个合法的负结果，语义被重载；想带上「哪张订单、哪个字段」，只能塞进别处或让调用方去拼；一旦调用变深，每一层都要判断、都要向上传，漏掉一层错误就断了。直接崩（trap）：粗暴是够粗暴，越界、除零、unreachable 都会让执行立刻中止，整个实例很可能就此进入不可用状态，可调用方拿到的信息量却近乎为零。

于是问题收敛成一句：怎么让 Wasm 主动抛出一个能携带结构化数据、又能被 JS 精确识别来源的错误，而且不把实例搞坏？

约定特殊返回值

最省事、也最常见的做法：返回错误码。约定若干个特殊返回值（-1 表示除零、-2 表示参数越界……），调用方每次拿到结果先判断是不是这些特殊值。

这个方案做对了一件事：它给了调用方一个「可以继续往下走」的分支。出错不等于进程结束，上层还能决定重试、降级或提示用户——这层「可恢复」的性质，正是后面要保留的。

误判负数结果

  • 错误码和正常值共用一条返回通道，-1 到底是不是错误全凭约定，一旦有合法的负数结果就会误判。
  • 它带不了上下文：出错的具体字段、订单号、原始输入，只能靠额外参数或全局状态传，跨边界时很快乱掉。
  • 深层调用要逐层检查、逐层上抛，每一层都得记得判断，漏掉一层错误就被静默吞掉。
  • 换成直接 trap（越界、除零、unreachable）虽然够直接，但它中止执行、实例可能再也不可用，且 JS 端拿到的只是没有自定义负载的运行时错误，信息同样丢失。

trap与异常区分

先把两个一直混在一起的概念拆开。trap 是运行时的机器级失败——数组越界、非法指令、显式 unreachable、除零等，执行会立刻中止，它不可被语言层的 try/catch 拦下，属于「硬失败」。异常（exception）是语言层的软失败：可以被 try/catch 捕获，可以携带数据，还能沿着调用栈向上寻找处理者。这一课要造的是后者。

先补异常的类型：tag。用 (tag $e (param i32)) 声明一个异常类型，括号里的 param 是它携带负载的签名——这里声明的是「带一个 i32」。tag 像一枚徽章，作用是让捕获端能认出「这是谁抛的」，而不是只看到一条没有出处的错误。

再补抛出：throw。在 div 里，一旦发现除数是 0，就写 throw $e，把负载（演示里是 100，用来代表错误码或上下文）随异常一起抛出。抛出之后它就像别的语言一样，沿调用栈向上寻找是否有 catch。

再补JS 侧的捕获与识别。异常跨越 Wasm/JS 边界后，JS 收到的不是字符串，而是一个 WebAssembly.Exception 对象。你可以用 e.is(tag) 判断它是不是来自你声明的那个 tag，再用 e.getArg(tag, 0) 把第 0 个负载取出来。这样 JS 能精确分辨异常来源并读到结构化数据，而不是对着一句 RuntimeError 猜发生了什么。

  1. 模块里声明 (tag $e (param i32))，定义一种携带 i32 负载的异常类型，并定义 div。
  2. div 检测到除数为 0 时 throw $e，携带负载 100。
  3. JS 侧 catch 到 WebAssembly.Exception。
  4. 用 e.is(tag) 判定来源、e.getArg(tag, 0) 取出负载并展示。

再补在 Wasm 内部就地处理。不是所有错误都得回到 JS：如果本模块内就能兜住，直接在 Wasm 里用 try/catch 处理，可以省掉一次跨界往返。要记住的是，异常可以跨越 Wasm/JS 边界传递，并且不会破坏调用栈——这正是它和 trap 最本质的差别：trap 把执行整个掀翻，异常只是把控制权交给上层的处理者。

两个容易踩的边界：其一，异常处理提案相对较新，旧运行时或某些嵌入式环境下可能不支持，实例化时就会失败，上线前应当做能力检测并准备降级路径；其二，别把异常当流程控制——它只在真正例外时抛出，正常分支该用返回值就用返回值，否则异常会成为新的性能与可读性负担。

硬失败与软失败

「出错」在 Wasm 里有两副面孔：trap 是机器级的硬失败，中止执行、不可拦截；异常是语言级的软失败，可被捕获、可携带数据。用 (tag ...) 声明异常类型、用 throw 带上负载抛出，JS 端用 WebAssembly.Exception 配合 e.is(tag) 与 e.getArg(tag, i) 就能精确识别来源并读出数据，而且不破坏调用栈。它比错误码更有信息量、比 trap 更可控，但需要环境支持，也不该被当作日常流程控制。

「trap（陷阱）」指 Wasm 运行时检测到不可继续的错误（数组越界、非法指令、显式 unreachable、除零等）时立即中止执行的机制。它属于机器级硬失败，不能被语言层的 try/catch 拦截，抛到宿主后表现为一个不带自定义负载的异常，且实例可能进入不可恢复状态。边界与例外：与之相对的是异常处理提案提供的 (tag ...) + throw，那是可捕获、可携带负载、且不破坏调用栈的软失败；判断一个错误能否恢复，先看它是 trap 还是异常。

WAT
;; 异常处理：tag 定义异常类型，throw 抛出携带 payload 的异常
(module
  ;; 声明异常类型 tag：负载为一个 i32
  (tag $e (param i32))

  ;; div(a, b)：b 为 0 时抛出 tag 并携带负载 100
  (func $div (param $a i32) (param $b i32) (result i32)
    local.get $b
    i32.eqz
    if
      i32.const 100
      throw $e
    end
    local.get $a
    local.get $b
    i32.div_s
  )

  (export "div" (func $div))
  (export "e" (tag $e))
)
