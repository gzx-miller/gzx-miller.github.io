值类型与类型系统

认识 i32、i64、f32、f64 四种数值类型，以及类型在签名与内存中的强制约束。

开场问题：结算代码把 0.1 连加十次。用 f64 算，得到 1；同一段逻辑换成 f32，结果是 0.99999994。更让人意外的是，你把一个 64 位订单号塞进 i64 参数，浏览器直接抛 TypeError——同样是「一个数」，为什么换个类型结果就变了，甚至根本传不进去？

多种数值类型

你要让 JS 和 Wasm 交换数值。JS 只有一种数字类型（双精度 number），Wasm 却有好几种，而且每一种都必须显式声明。旧办法是「反正都是数，随便传」，成本有三：类型对不上时，模块在实例化阶段就被验证器拒绝；有些值用 number 根本表达不了，硬传会静默丢位；浮点精度被降级时，没有任何提示。

所以真正要解决的是：在两种类型系统之间，什么值配什么类型、边界上又会发生什么换算？

统一双精度方案

最朴素的做法：凡是小数都用 f64，反正在 JS 里 number 就是 64 位双精度。

这个方案做对了一件事：f64 与 JS 的 number 位宽一致，能无损互传，绝大多数普通计算交给它确实没问题。

双精度类型边界

  • i64 参数或返回值不能用 number 传，必须用 BigInt，否则当场抛 TypeError。
  • 整数一旦超过 2^53，放进 number 就已经丢了精度，而 f64 也装不下这么大的整数。
  • f32 是 32 位单精度，累加这类操作会明显累积误差（0.1 加十次不等于 1）。
  • Wasm 没有字符串、对象、null 这些高层类型，它们都得绕道内存或引用类型来表达。

四种标量类型

不推翻「用数值沟通」，而是先认清手里到底有几块积木。Wasm 的标量数值类型只有四种：i32、i64、f32、f64（此外还有 128 位向量 v128 与引用类型，那是后话）。所有签名、局部变量、内存读写，都只能在这几种里选。

第一层要补的是类型声明的位置。类型不写在函数体里，而是集中在类型段：函数签名按索引去引用类型段里的条目。这样设计，验证器只需看类型层，就能快速判断参数个数与类型是否自洽，不必逐条执行指令——这正是类型系统能高效做安全检查的原因。

  1. 类型段集中声明一条 (i32, i32) -> i32 的签名。
  2. 函数的参数与局部变量都按这个类型来。
  3. 内存读写按给定类型解释字节宽度。
  4. 宿主按导出签名把入参做数值换算后传入。

第二层要补的是局部变量与内存的类型。局部变量声明时必须写类型，local.get / local.set 按那个类型取值；内存里同一段字节，用 i32.load 读和用 f32.load 读会得到完全不同的解释——类型决定了「这几个字节怎么理解」。

第三层是跨边界的换算规则。JS 的 number 进 i32 参数会被截断；进 f32 参数会被降精度；i64 则必须用 BigInt 一一对应，一位都不能少。反过来，Wasm 把 i64 返回给 JS，拿到的也是 BigInt。

于是选型就有了规则：金额这类不能出错的量，用「整数分」存 i64，或至少用 f64；只在明确需要省内存、且能接受单精度误差时才用 f32；只要涉及 i64，边界两端都写 BigInt。之所以要有类型系统，也不只是为了算得准，更是为了让编译器能生成高效的机器码、让验证器能快速拒收非法模块。

「反正都是数」是这里最大的坑：i64 不用 BigInt 会直接报错；f32 不是「小一号的 f64」，它的误差会在累加里越滚越大；而 f64 也扛不住超过 2^53 的整数。

类型位宽与用途

Wasm 的标量类型只有 i32、i64、f32、f64 四种，且所有签名、局部变量、内存读写都必须显式声明。类型集中在类型段，函数按索引引用，验证器据此做安全检查。跨边界时记住三条：i64 必须配 BigInt，f32 会丢精度，超过 2^53 的整数别指望 number。

「标量类型」指 Wasm 的四种数值类型 i32、i64、f32、f64（不含 128 位向量 v128 与引用类型），它们构成所有函数签名、局部变量与内存读写的基础。边界：i64 与 JS 互操作必须用 BigInt，否则抛 TypeError；f32 是单精度、存在舍入误差，累加场景应改用 f64 或 i64；Wasm 没有字符串、对象、null，需通过内存或引用类型表达。

关键代码

WAT
;; WebAssembly 只有四种数值类型：i32 / i64 / f32 / f64
;; 函数签名、局部变量、内存读写都必须声明类型
(module
  ;; i32 函数：整数运算
  (func $mul (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.mul
  )
  ;; f32 函数：单精度浮点运算
  (func $fadd (param $a f32) (param $b f32) (result f32)
    local.get $a
    local.get $b
    f32.add
  )

  (export "mul" (func $mul))
  (export "fadd" (func $fadd))
)
;; 注意：i64 作为参数/返回值时 JS 必须用 BigInt 传输；
;; f32 是单精度，存在舍入误差，价格计算建议用 f64。
