工具链、编译与部署

走通从源码到线上的完整流程，用 instantiateStreaming 演示流式加载。

开场问题：你照教程把一段 C 代码用 Emscripten 编译出来，输出目录里除了 .wasm，还躺着一个同名 .js，开了线程的话还多一个 worker 脚本——你不知道该把哪些传上 CDN；换成 Rust 用 wasm-pack build，又冒出一个 pkg/ 目录，里面 .js、.wasm、.d.ts 一应俱全。同样是「编译成 Wasm」，为什么不同工具链产出的文件长得完全不一样，上线时我到底要交付哪些？

产物构成与胶水层

因为 Wasm 从来不是「一个文件」，而是一包产物。Wasm 的运行时模型很克制：它只有整数、浮点和一块线性内存，没有字符串、没有对象、也不能直接碰 DOM。任何真实业务都要用到这些东西，于是工具链不得不额外生成一层 JS「胶水」，把 Wasm 的能力翻译给前端世界。不同语言、不同工具链需要翻译的东西多寡不同，产出的文件自然就不一样。

旧认知的隐藏成本就在这里：你以为产物只有一个 .wasm，于是只把 .wasm 传上线，漏掉了胶水 JS，页面直接报错；你不知道 CDN 要为它配什么响应头，instantiateStreaming 因 MIME 不对被拒；你也分不清「模块（Module）」和「实例（Instance）」，不知道同一份产物能不能安全地加载多次。问题于是收敛成一句：从源码到线上，一份 Wasm 应用到底经过哪几步、每一环产出什么文件、上线交付哪些、服务器又要配什么？

最短编译链路

走最短的链路：手写一段 WAT，用 wat2wasm 编译出一个 .wasm，前端 fetch 回来交给 instantiateStreaming 加载，调用导出的函数。

这个方案做对了一件事：它把「源码 → 二进制 → 可调用的实例」这条最短链路完整打通了，而且产物只有一个文件。理解了这一条，后面所有的「胶水」都只是围绕它做的补全。

手写WAT成本

  • 真实业务几乎不可能手写 WAT：字符串处理、结构体、内存分配、和 DOM 或 JS 的交互，用底层指令写一遍的成本和风险都高得离谱。
  • 一旦换成 C/C++ 或 Rust，工具链就会额外产出 JS 胶水，产物从一个文件变成一包，你得先知道每个文件扮演什么角色，才不会漏传。
  • 若用 -pthread 开了线程，还会多出 Worker 脚本，并连带依赖共享内存与 COOP/COEP 响应头，部署面一下子变宽。
  • 服务器 MIME 配错，instantiateStreaming 会拒绝加载；打包器也未必认识 .wasm，需要单独配置成静态资源规则。

工具链产出形态

先补编译这一步的运行原理，再逐一看各工具链的产出形态。链路本身是一样的：源码 → 编译器 → .wasm → compile 得到 Module → instantiate 注入导入得到实例 → 随静态资源部署。差别全在「用哪条工具链」上。

  1. 写源码：C/C++、Rust、AssemblyScript，或手写 WAT。
  2. 用 clang、rustc、asc 或 wat2wasm 编译成 .wasm。
  3. 用 WebAssembly.instantiateStreaming 边下载边编译并实例化。
  4. 调用 exports.add 等导出的函数，最后随静态资源部署上线。

具体到产物，值得把三条常见路径对照着记。WAT 走 wat2wasm：直出单个 .wasm，最干净，适合学习与最小示例。C/C++ 走 Emscripten（emcc）：除了 .wasm，还会生成一个 JS 胶水，负责初始化内存、提供导入（如 env）、把 C 函数映射成模块的 exports；一旦加 -pthread，还会多出 worker 脚本，并要求页面处于跨源隔离。Rust 走 wasm-bindgen：它额外生成一层 JS 绑定，专门解决「Wasm 只认数字」这件事——字符串、数组、结构体过边界时的编解码都由这层完成；再上一层的 wasm-pack build 会把这一切收进 pkg/ 目录，除了 .js 与 .wasm，还附上 .d.ts 类型声明，让前端可以直接按 ES 模块引入。AssemblyScript 则用 asc，语法接近 TypeScript，同样直出 .wasm 并配套加载器。

一句话抓住重点：胶水 JS 不是「多余的东西」，它是把 Wasm「只有数字和线性内存」这块短板补齐的翻译层。语言越靠近前端（如 AssemblyScript）、逻辑越简单（如纯 WAT），需要的胶水越少；语言越底层、越要碰字符串和宿主对象（如 C++、Rust 调 DOM），胶水就越多、越重要。

再补「模块」与「实例」的区分，它直接决定怎么部署和复用。WebAssembly.compile 得到的是一个 WebAssembly.Module——不可变、与运行时状态无关；instantiate 注入导入、生成的是实例，实例才带内存和全局变量。所以同一份产物可以安全地实例化多次，各自互不干扰——这正是上一课「多个 Worker 各自实例化同一份模块」的前提，也是缓存复用的基础：把编译好的 Module 存起来，下次直接实例化，跳过编译。

再补上网前的两个网络要素。第一是 MIME：服务器必须以 application/wasm 返回 .wasm，否则 instantiateStreaming 会拒绝加载，退回到需要完整 ArrayBuffer 的 instantiate。第二是缓存：生产环境推荐用 instantiateStreaming 做流式加载，同时给 .wasm 配内容哈希文件名加长缓存，或把 Module 缓存进 IndexedDB，让二次访问免去重复编译。若产物依赖线程或共享内存，还要额外配上 COOP/COEP。

最后补与打包器对接。多数场景下 .wasm 不作为 JS 模块被引入，而是当作静态资源：由打包器拷贝到输出目录并给出一个 URL，你在运行时 fetch 它；也可以借助 vite-plugin-wasm 这类插件把加载都替你处理掉。而 Emscripten 或 wasm-pack 生成的胶水 JS 则按普通的 ES 模块引入，它会自己去加载同目录的 .wasm——这也是为什么这些文件必须一起部署、且相对路径要对上。

三个最常见的上线事故：其一，只部署了 .wasm，漏掉工具链生成的胶水 JS，页面加载即报错；其二，服务器 MIME 没配成 application/wasm，instantiateStreaming 被拒，你却在本地开发服务器上「一切正常」；其三，用了 -pthread 线程产物，却忘了配 COOP/COEP，线程直接起不来。

五步编译流程

整包交付与部署

一份 Wasm 应用的链路是「源码 → 编译器 → .wasm → compile 得 Module → instantiate 得实例 → 部署」。不同工具链的产物形态不同，差别全在胶水层：WAT 最干净，Emscripten 会带一个 JS 胶水（开线程再加 worker 脚本），Rust 的 wasm-bindgen 加 wasm-pack 会产出一个含 .js、.wasm、.d.ts 的 pkg/ 目录。交付时要整包一起部署，服务器配好 application/wasm 与缓存，用 instantiateStreaming 加载；并牢记 Module 不可变、实例才带状态，同一份产物可被安全地多次实例化。

「胶水代码（glue code）」指工具链在 .wasm 之外额外生成的 JS 层，用来弥补 WebAssembly 只支持整数、浮点与线性内存，无法直接处理字符串、对象与 DOM 的短板：它负责内存初始化、提供导入（如 env）、对字符串与结构体做跨边界编解码，并把宿主能力暴露给模块。边界与例外：手写 WAT 或简单场景的产物可以几乎没有胶水；Emscripten 生成单个 JS 胶水（开 -pthread 时另加 worker 脚本），Rust 的 wasm-bindgen 与 wasm-pack 则会产出一个含 .js、.wasm、.d.ts 的 pkg/ 目录；部署时必须与 .wasm 一起交付并保持相对路径一致，否则实例化会因缺少导入而失败。

关键代码

JavaScript
// 工具链、编译与部署：从源码到线上
// 1. 源码（C/Rust/AssemblyScript 或手写 WAT）→ 编译器输出 .wasm
//    wabt:     wat2wasm add.wat -o add.wasm
//    emscripten: emcc main.c -o main.js (含 .wasm)
//    rustc:    rustc --target wasm32-unknown-unknown main.rs

// 2. 流式加载：边下载边编译（生产推荐，MIME 需为 application/wasm）
const response = await fetch('/add.wasm')
const { instance } = await WebAssembly.instantiateStreaming(response)

// 3. 调用导出函数
console.log(instance.exports.add(2, 3)) // 5

// 4. Module 可缓存复用：compile 得到不可变 Module，多次实例化零编译
const module = await WebAssembly.compile(bytes)
const inst = await WebAssembly.instantiate(module, importObject)

// 部署注意：MIME application/wasm；使用线程特性需 COOP/COEP 跨源隔离
