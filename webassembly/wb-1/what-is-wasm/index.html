什么是 WebAssembly：二进制格式与模块结构

从十六进制读懂 .wasm 文件的魔数、版本与各段结构，并完成首次实例化调用。

开场问题：同事丢给你一个 codec.wasm，说「直接调就行，比 JS 快十倍」。你用编辑器打开它——满屏十六进制，没有一行能读的代码，连里面有哪些函数、各要什么参数都看不出来。这段二进制凭什么能被浏览器执行，又凭什么能在没有源码的情况下被安全调用？

源码依赖成本

你想把一段计算密集的逻辑交给别人写好的模块去跑。最直接的办法是拿源码，复制进项目。但这条路夹着几件必须由你扛的成本：源码一旦分发就暴露了实现；同一份逻辑要为不同语言各写一遍；源码的体积和启动开销通常也远大于编译后的形式。

于是你盼着一种中间形态：它不是任何高级语言的源码，而是一份浏览器能直接读懂、执行的「可移植机器码」，体积小、加载快、和具体 CPU 解耦，还得让宿主在执行前就能确认它规规矩矩。问题落到：这份中间形态到底长什么样，浏览器凭什么敢执行一段来路不明的字节？

模块黑盒调用

最省事的做法：把它当黑盒。await WebAssembly.instantiate(bytes) 拿到实例，然后照着文档调 instance.exports.add(2, 3)。

这个方案做对了一件根本的事：字节码可以被引擎安全地编译执行，调用方根本不需要源码。你交出的是编译产物而不是实现，这既省下了分发源码的成本，又让跨语言复用成为可能。

导出接口不透明

  • instance.exports 里到底有什么，只能靠 console.log(Object.keys(instance.exports)) 猜；签名文档没写，就只能试。
  • 实例化失败时只抛一句 CompileError 或 LinkError，它不会告诉你究竟是哪几个字节坏了。
  • 模块声明的导入如果宿主没提供，错误要等到运行时才炸，事前无法自查。
  • 文件为什么是这个体积、哪些段能省、能不能再小，全无判断依据。

魔数与分段结构

不推翻「黑盒调用」，而是把这只黑盒拆开，一层层看进去。先认得开头那两个东西：魔数与版本号。

前 4 字节 00 61 73 6d 是魔数，它正好是 ASCII 的 \0asm（一个 NUL 字节，后跟 a s m）；紧接着 4 字节 01 00 00 00 是小端存储的版本号，当前固定为 1。引擎读到这里就知道「这是一份 v1 的 Wasm 模块」，否则直接拒收——魔数的作用，就是让引擎在解析前先确认身份。

  1. 校验：先扫描各段的类型信息，确认指令与签名自洽，非法模块当场抛 CompileError。
  2. 编译：把字节码翻译成宿主机器码。
  3. 实例化：分配内存、绑定导入，产出实例对象。
  4. 调用：经 exports.add 触发编译好的函数。

魔数之后是段（section）。每个段以一个 id 字节开头，随后是长度和内容：id=1 是类型段，声明函数签名；id=2 是导入段，声明要外部提供的依赖；id=7 是导出段，把内部函数挂成一个对外名字；id=10 是代码段，存放函数体的指令。你那个 codec.wasm 之所以「读不出函数」，正是因为没按段去读——函数名藏在导出段，签名藏在类型段。

别把段当成随意排列：每个段的 id 决定用途，多个段还要按规范给定顺序出现，漏掉或错序都会让校验失败；魔数写错哪怕一个字节，整个文件就是垃圾。
Wasm 的指令运行在一个虚拟 ISA 上，不绑定任何具体 CPU 的寄存器，所以同一份文件能在 x86、ARM、浏览器里跑——这才是「可移植」真正的含义。

十六进制拆解

可移植二进制格式

WebAssembly 不是一门语言，而是一份可移植的二进制格式：开头是魔数与版本，后面是按 id 分段的类型、导入、导出与代码。引擎先校验、再编译、再实例化，最后交给你一组可调用的导出函数。你不需要源码，也能安全地执行一份来路不明的字节。

「段（section）」指 .wasm 文件中按用途切分的二进制单元，每段以一个 id 字节开头（类型段=1、导入段=2、函数段=3、导出段=7、代码段=10），后跟长度与内容。边界：段可缺省（空模块合法），但顺序与长度必须自洽，否则校验阶段就会失败；函数名与签名分散在导出段、类型段里，所以读二进制要按段读，而不是从头顺序扫。

关键代码

WAT
;; 最小的 Wasm 模块：add(a, b) = a + b
;; 一个模块由若干"段"组成：类型段、函数段、导出段、代码段等
(module
  ;; 函数签名：(i32, i32) -> i32
  (func $add (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.add
  )
  ;; 导出段：把内部函数以 "add" 暴露给宿主 JS
  (export "add" (func $add))
)
