函数表与 call_indirect

用促销计价切换演示函数表与动态分发，JS 还能改写表项。

开场问题：计价台要根据用户当前选的促销方式，在「加价、满减、打折、拆分」四个函数之间挑一个来调用。选哪个是运行时才知道的——用户点了按钮，模块拿到一个数字。函数名字没法写死在 WAT 里，那模块怎么凭一个运行时数字，找到并调用对应的函数？

运行时函数选择

静态调用从来不是问题：直接写 call $add，调用哪个函数编译期就定死了。麻烦在于促销方式是用户点击决定的，模块运行时手里只有一个数字 op（0/1/2/3），想知道它对应哪个函数。而 Wasm 里没有「可以把函数存进变量里的函数指针」，也没有反射可以按名字查函数。

退一步，用一长串 if / else 分支，每个分支里 call 一个写死的函数行不行？代价一层层加：每新增一种运算就得改代码、重新编译；分支越铺越长，模块跟着膨胀；更要命的是，宿主完全没法在运行时替换某个实现——你想在不停机的情况下换成新算法，根本无从下手。问题于是收敛成一句：「调用哪个函数」这件事，能不能变成一个运行时可查、甚至可改的索引？

函数表结构与填充

造一张函数表——一个按索引存放函数引用的数组。(table 4 funcref) 声明 4 个槽，再用 (elem (i32.const 0) $add $sub $mul $div) 把四个函数依次填进去。调用时不写函数名，而是用 call_indirect 按索引去表里取函数执行。

这个方案做对了一件事：它把「调用哪个函数」从编译期写死的名字，变成了运行时可以变化的索引。运行到哪一步、用哪个函数，全由那个数字决定。

表索引错位风险

  • 索引对应哪个函数，纯靠约定——第 0 项是 add，全凭 elem 的填充顺序保证，一旦顺序写错就整体错位。
  • 表里各函数签名如果不一样呢？某个槽放的是 (i32) -> i32，调用点却按 (i32, i32) -> i32 去调，会发生什么？
  • 索引越界怎么办——表只有 4 项，却传进来一个 5？
  • 宿主能不能看见这张表，甚至直接改写其中一项？

引用类型表项

先补「表里放什么、怎么填」。表元素的类型统一是 funcref（函数引用，一种引用类型），用 (elem …) 段在实例化时填充：位置 0 到 3 依次是 add、sub、mul、div。dispatch(op, a, b) 里先把 op 压上操作数栈，它待会儿要当索引用。

再补「怎么按索引调」。用 call_indirect (type $binOp)：它从操作数栈顶弹出一个索引，到表里取出对应的函数引用并调用它。关键在那个 (type $binOp)——call_indirect 会在调用前校验目标函数的签名，槽里每个函数的参数和返回类型都必须与声明的类型匹配，不匹配就抛异常。注意这是运行时检查，不是编译期替你拦下的。

接着补「越界」。索引超出表的当前大小，call_indirect 会触发 trap（RuntimeError），而不是随便读到一段垃圾代码去执行。所以调用前应当自己保证 op 落在 [0, table.size) 之内。

最后补「宿主干预」，这才是函数表真正强大的地方。表可以导出，JS 侧用 table.get(i) 读到某个函数引用，用 table.set(i, fn) 改写表项。把第 0 项从 add 换成 sub 之后，dispatch(0, …) 立刻变成执行减法——不用重新编译模块，一次 table.set 就完成了热替换。多态、回调、运行时插件化，全都建立在这套「索引 + 可写表」的机制上。

别把它当静态调用看：call_indirect 的类型校验发生在运行时——表里函数签名与声明的 type 不符、或索引越界，都会在那一刻抛异常，而不是像静态 call 那样由校验器提前挡下。用之前先确认索引合法、类型一致。

间接调用签名校验

函数表把函数引用按索引排成一列，模块用 call_indirect 在运行时按索引调用并顺手校验签名，于是「调用哪个函数」从编译期写死变成了运行时可定；表还能导出，宿主用 table.get / table.set 读写表项，热替换与插件化就建立在这一点上。

「函数表（table）与 call_indirect」指函数表是一组按索引排列的 funcref（函数引用），用 (elem …) 段填充；调用方用 call_indirect 从栈顶弹出索引，取出表内函数并在调用前校验其签名。边界：表元素类型统一为 funcref；索引越界或签名不匹配会抛异常，且这个检查发生在运行时；表可导出，宿主用 table.get / table.set 读写表项，从而实现热替换与插件机制。

关键代码

WAT
;; 函数表与 call_indirect：按索引在运行时动态调用函数，并校验签名
(module
  ;; 函数表：按索引存放函数引用，最小 4 项
  (table 4 funcref)

  (func $add (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.add)
  (func $sub (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.sub)
  (func $mul (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.mul)
  (func $div (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    i32.div_s)

  ;; 元素段：把 4 个函数填入表索引 0..3
  (elem (i32.const 0) $add $sub $mul $div)

  ;; dispatch(op, a, b)：按 op 索引调用，call_indirect 会校验签名
  (func $dispatch (param $op i32) (param $a i32) (param $b i32) (result i32)
    local.get $a
    local.get $b
    local.get $op
    call_indirect (param i32 i32) (result i32)
  )

  (export "table" (table 0))
  (export "dispatch" (func $dispatch))
  (export "add" (func $add))
  (export "sub" (func $sub))
  (export "mul" (func $mul))
  (export "div" (func $div))
)
