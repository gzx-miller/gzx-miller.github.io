字符串互操作

把收货地址写入内存，交给 Wasm 求长度并原地转大写。

开场问题：你在 JS 里写下 const addr = 'squirrel hazelnut'，想交给 Wasm 处理，可它导出的函数签名清一色是 i32、f64 这些数字类型——根本没有一个叫 string 的类型。这一串字符到底怎么塞得进去？

字符串类型受限

你想让宿主和模块之间传一段文本——收货地址、用户名、一段 JSON。麻烦在于 Wasm 的类型系统里压根没有字符串：它只有 i32、i64、f32、f64 这些数字，外加 funcref、externref 这些引用。为什么不加一个 string 类型？因为 Wasm 是给各种语言共用的编译目标，C 的字符串、Rust 的 String、Go 的 string 表示法各不相同，语言层面统一不划算，索性交给编译工具去约定。

于是问题落到你身上：一段本来就是「字符序列」的数据，怎么穿过一道只认数字的边界？ 最笨的办法是把每个字符拆成一个单独的数字参数一个个传。它的成本很实在——字符数不固定，函数签名就没法固定；一千个字符要一千个参数，签名会膨胀到无法维护；就算传进去了，模块手里也只是一堆散落的数字，没有「这是一整段文本」的概念。

起始地址指针

换个思路：既然边界只认数字，而模块已经有一块按字节编号的线性内存，那就把字符串按编码写成一块字节，只把这块字节的起始地址——一个 i32——传过去。起始地址就是「指针」，模块顺着它就能摸到整段文本。

这个方案做对了一件事：它用已有的内存机制承载了任意长度的数据，把签名收敛成一个干净的 (i32)。文本再长也不用改签名，模块拿到的也不再是散落的数字，而是一个能顺藤摸瓜的位置。

长度信息缺失

  • 只给起始地址，strlen 从哪知道到哪里结束？没有终点，它会一直往下数，把内存里别的数据也当成字符串的一部分。
  • JS 的字符串是 UTF-16 code unit，一个字符可能不只占一个字节。直接按 charCodeAt 逐字符写，得到的是错的字节序列。
  • 只传地址、不传长度，模块想读回一段文本时，除了地址别无信息，容易多读或漏读。
  • 模块想把这段文本改个大写，改完又该怎样把结果交还给 JS？

零字节终止符

先补「怎么划边界」。约定一种C 风格字符串：字节序列最后额外补一个值为 0 的字节 \0 作结束符。模块侧的 strlen(ptr) 从 ptr 起逐字节 i32.load8_u，一遇到 0 就停，数出来的就是字节长度。签名因此只要 (i32) -> i32，长度不用调用方显式传——但代价也出来了：长度靠内容里的 \0 自己界定，调用方必须保证这段字节里没有意外的 0。

再补「怎么把文本变成字节」。JS 用 TextEncoder 把字符串按 UTF-8 编码成 Uint8Array，再 memBytes.set(data, 0) 写进内存，最后在末尾补一个 0。要留意：strlen 返回的是字节数，不是字符数——中文一个字在 UTF-8 里占 3 个字节，一个 emoji 可能占 4 个，所以「长度 8」不代表「8 个字符」。读回时用 TextDecoder 从内存切片解码，字节序列才重新变回字符串。

接着补「模块要改文本怎么办」。方法就是原地改内存字节。toupper(ptr) 从起点遍历，把落在 0x61–0x7A（即 a–z）范围内的字节减去 0x20，正好落进大写区间 0x41–0x5A；遇到 \0 就停。它不产生新的字符串对象，只改那块内存——因为 Wasm 里本就没有字符串对象，能改的只有字节。JS 随后用 TextDecoder 从同一块内存读回，就看到了大写结果。

两个易错点：模块端把字节只当字节，从不解析 UTF-8，所以 toupper 只对 ASCII 小写字母有效，中文字节不会被它动到一个字；而 strlen 数的是字节数，别拿它当字符数用。现代工程里这些编码、写内存、补结束符的胶水代码，通常交给 wasm-bindgen 之类的工具自动生成。

字节长度与大小写

跨边界字符串链路

字符串跨边界的完整链路只有这么几步：JS 用 TextEncoder 编码成 UTF-8 字节 → 写进线性内存并补 \0 → 只传起始地址（指针）→ 模块按字节处理 → JS 用 TextDecoder 解码读回。Wasm 没有字符串类型，它认得的一直只是地址和字节。

「C 风格字符串（C string）」指用一块以 \0（值为 0 的字节）结尾的连续字节表示字符串，起始地址即指针，长度由遍历数到 \0 得到。边界：\0 本身不计入长度；长度是字节数而非字符数（UTF-8 下一个中文占 3 字节）；模块端不解析 UTF-8，只按字节操作；toupper 这类操作是原地改写内存字节，不产生新字符串；工程中常由 wasm-bindgen 等工具自动生成编解码胶水。

WAT
;; 字符串互操作：Wasm 没有字符串类型
;; 用"内存地址 + \0 结束符"表达 C 风格字符串
(module
  (memory (export "memory") 1)

  ;; strlen(ptr)：从指针数到 \0 返回长度
  (func $strlen (param $ptr i32) (result i32)
    (local $len i32)
    block $done
      loop $loop
        local.get $ptr
        local.get $len
        i32.add
        i32.load8_u
        i32.eqz
        br_if $done
        local.get $len
        i32.const 1
        i32.add
        local.set $len
        br $loop
      end
    end
    local.get $len
  )

  ;; toupper(ptr)：把小写字母原地转大写
  (func $toupper (param $ptr i32)
    block $done
      loop $loop
        local.get $ptr
        i32.load8_u
        i32.eqz
        br_if $done
        local.get $ptr
        i32.load8_u
        i32.const 0x61       ;; 'a'
        i32.ge_u
        local.get $ptr
        i32.load8_u
        i32.const 0x7a       ;; 'z'
        i32.le_u
        i32.and
        if
          local.get $ptr
          local.get $ptr
          i32.load8_u
          i32.const 0x20     ;; 大小写差 32
          i32.sub
          i32.store8
        end
        local.get $ptr
        i32.const 1
        i32.add
        local.set $ptr
        br $loop
      end
    end
  )

  (export "strlen" (func $strlen))
  (export "toupper" (func $toupper))
)
