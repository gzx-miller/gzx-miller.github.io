智能指针与 RAII

理解 RAII 资源管理思想，掌握 unique_ptr、shared_ptr、weak_ptr 的用法与适用场景。

开场问题：用 new 申请的资源本该由 delete 释放，可只要中途有一次提前 return、或某一步抛出异常，delete 就被跳过 —— 有没有一种写法，能让「释放」像栈上的普通变量一样，无论如何都自动发生？

先朴素做法：new 与 delete 成对出现

最直接的管理方式是裸指针：new 返回一个指向堆对象的指针，用完再手动 delete。

  • 做对的地方：控制精确，何时申请、何时释放一清二楚，没有隐含成本。
  • 不足：释放点与申请点被代码路径隔开。函数中途 return、循环里的 continue / break、乃至抛出异常，都会绕过 delete；一旦漏写就是内存泄漏，重复写就是双重释放。

问题的根源是：手动释放与所有退出路径没有绑定。只要退出路径多于一条，就总有一天会漏掉。真正需要的，是一种「无论怎么离开作用域都会被执行」的释放时机。

RAII：把释放交给析构函数

C++ 恰好提供了这样一个时机：局部对象离开作用域时，其析构函数一定会被调用 —— 正常返回会，因异常而中断（栈展开）也会。RAII（Resource Acquisition Is Initialization，资源获取即初始化）就是把这个规律用起来：在构造函数中获取资源，在析构函数中释放资源。

  • 资源的生存期与对象的生存期绑定，两者同生共死。
  • 退出路径再多，也只会触发一次析构，因此不存在「漏掉某条分支」的可能。
  • 智能指针正是管理「指向对象的指针」的 RAII 包装：内部持有裸指针，析构时执行 delete。

于是「用不用智能指针」不再是风格问题，而是正确性问题：只要资源需要成对地获取与释放，就应该交给一个 RAII 对象来托管。

unique_ptr：独占所有权

std::unique_ptr 表达独占所有权：同一时刻只有一个 unique_ptr 拥有该对象。这一语义由「不可拷贝」来保证 —— 它的拷贝构造与拷贝赋值被删除，只能通过 std::move 转移。

  • 移动后源指针变为空（nullptr），但对象仍然有效，只是不再拥有资源；转移的是所有权，不是对象本身。
  • 默认删除器下它是零额外开销的：大小与裸指针相同，几乎可优化到与手写 delete 等价。
  • 用 std::make_unique<T>(args) 创建（C++14 起），避免裸 new。
  • 所有权语义也体现在函数边界：作为返回值返回时无需显式 move（有返回值优化与隐式移动）；作为参数需要交出所有权时，才用 std::move 显式转移。

shared_ptr、引用计数与 weak_ptr

std::shared_ptr 表达共享所有权：多个 shared_ptr 可指向同一对象，内部用一块控制块记录引用计数。每拷贝一次计数加一，每析构一次计数减一，减到零时才真正释放对象。因此可安全地拷贝、放进容器、跨函数传递。

  • 优先用 std::make_shared<T>(args)：它把对象与控制块一次性分配，比 shared_ptr<T>(new T) 更快、更省内存。
  • 计数增减是原子的（线程安全），但对象本身不是：多线程访问同一对象仍要自己加同步。
  • 循环引用是它最大的陷阱：A 持有 shared_ptr<B>、B 又持有 shared_ptr<A> 时，两边的计数永远不会归零，对象永不释放。

std::weak_ptr 是配套的解法：它指向 shared_ptr 管理的对象，却不增加引用计数。把循环中的一个方向改成 weak_ptr 即可打破循环。要用时通过 lock() 临时提升为 shared_ptr —— 对象还活着就拿到非空指针，已销毁则得到空指针，从而避免了访问已释放对象。

make_* 与自定义删除器

创建阶段首选 make_unique / make_shared，除了简洁，更因为它在异常安全上一锤定音：临时对象的构造与智能指针的接管之间不再有可乘之隙。

  • 自定义删除器：unique_ptr<T, D> 把删除器类型 D 作为模板第二参数，因此 unique_ptr<T, D1> 与 unique_ptr<T, D2> 是不同类型；它适合文件句柄、网络连接等非内存资源。带状态的删除器需作为构造参数传入。
  • 控制块陷阱：绝不能用同一个裸指针构造多个 shared_ptr，否则会生成多块控制块，导致重复释放；始终从已有 shared_ptr / unique_ptr 派生。
  • this 陷阱：不要在对象内部用裸 this 构造 shared_ptr。需要返回自身时，让类继承 std::enable_shared_from_this<T> 并调用 shared_from_this()。

选择策略可以一句话概括：能用栈对象就别上堆；确需堆对象就用 unique_ptr；确需共享所有权再上 shared_ptr；裸指针只保留为「非拥有」的观察者，不再用它管理资源。

看一遍三种所有权的实际行为

把所有权当作设计的一部分

智能指针不是「更安全的裸指针」，而是一套所有权声明：unique_ptr 说「这里唯一拥有」，shared_ptr 说「这里分享拥有」，weak_ptr 说「这里只观察、不拥有」。把所有权写进类型，编译器就能替你阻止拷贝独占资源、提醒你补充弱引用来切断循环。真正的内存安全，来自在写下每一个指针类型时都想清楚：这个资源，到底归谁管、什么时候放。

「RAII」指把资源的获取放进构造函数、释放放进析构函数，使资源生存期与对象生存期绑定的惯用法。「所有权」描述谁负责在何时释放资源，智能指针类型本身即是对所有权的声明。「控制块」是 shared_ptr 内部记录引用计数与删除器的结构，「引用计数」归零时才真正销毁对象。

关键代码

C++
// ═══════════════════════════════════════════
// 1. RAII：把释放交给析构函数
// ═══════════════════════════════════════════

#include <iostream>
#include <memory>
#include <cstdio>                              // std::fopen / std::fclose

class Resource {                               // 被托管的资源
public:
    Resource() { std::cout << "acquire" << std::endl; }   // 构造函数获取资源
    ~Resource() { std::cout << "release" << std::endl; }  // 析构函数释放资源
    void use() { std::cout << "use" << std::endl; }       // 结果：输出 use
};

// ═══════════════════════════════════════════
// 2. unique_ptr：独占所有权与 std::move
// ═══════════════════════════════════════════

void uniqueDemo() {
    std::unique_ptr<Resource> up = std::make_unique<Resource>();   // 结果：acquire
    up->use();                                 // 使用资源
    // std::unique_ptr<Resource> copy = up;    // 编译错误：unique_ptr 不可拷贝
    std::unique_ptr<Resource> moved = std::move(up);   // 只能移动，转移所有权
    std::cout << (up == nullptr) << std::endl;         // 结果：1，源指针已置空
    std::cout << (moved != nullptr) << std::endl;      // 结果：1
}                                              // 离开作用域，moved 析构：输出 release

// ═══════════════════════════════════════════
// 3. shared_ptr：引用计数与管理
// ═══════════════════════════════════════════

void sharedDemo() {
    std::shared_ptr<Resource> sp1 = std::make_shared<Resource>();  // 对象与控制块一次分配
    std::cout << sp1.use_count() << std::endl;  // 结果：1
    {
        std::shared_ptr<Resource> sp2 = sp1;    // 拷贝：引用计数递增
        std::cout << sp1.use_count() << std::endl;  // 结果：2
    }                                           // sp2 析构：计数递减
    std::cout << sp1.use_count() << std::endl;  // 结果：1
}                                               // sp1 析构，计数归零：输出 release

// ═══════════════════════════════════════════
// 4. weak_ptr：打破循环引用
// ═══════════════════════════════════════════

class Node {
public:
    std::shared_ptr<Node> next;                // 强引用：拥有下一个节点
    std::weak_ptr<Node> prev;                  // 弱引用：只观察，不增加计数
};

void weakDemo() {
    auto a = std::make_shared<Node>();
    auto b = std::make_shared<Node>();
    a->next = b;                               // 计数 +1
    b->prev = a;                               // 说明：若此处是 shared_ptr 则形成循环，永不释放
    if (auto locked = b->prev.lock()) {        // 提升为 shared_ptr，失败则为空
        std::cout << locked->use_count() << std::endl;  // 结果：2
    }
}

// ═══════════════════════════════════════════
// 5. 自定义删除器：管理非内存资源
// ═══════════════════════════════════════════

struct FileCloser {
    void operator()(std::FILE* fp) const {
        if (fp) std::fclose(fp);               // 自定义释放逻辑
    }
};

void deleterDemo() {
    std::unique_ptr<std::FILE, FileCloser> fp(std::fopen("data.txt", "r"));
    // unique_ptr<T, Deleter>：删除器是类型的一部分，与默认删除器不是同一类型
    std::shared_ptr<Resource> sp(new Resource(), [](Resource* p) { delete p; });
}                                              // fp 析构：调用 FileCloser 关闭文件
