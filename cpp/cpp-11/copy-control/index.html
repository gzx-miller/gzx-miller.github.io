拷贝控制：拷贝构造、拷贝赋值与 Rule of Three/Five

理解浅拷贝与深拷贝的差异，掌握拷贝构造、拷贝赋值与 Rule of Three/Five。

开场问题：Box b = a; 这行代码谁也没写拷贝相关的函数，却编译通过、也能跑；可一旦 Box 里藏着一个指针成员，程序就在析构时崩了。既然拷贝是编译器自动给的能力，为什么它会崩，又该由谁来接管？

拷贝为什么是默认就有的

Box b = a; 之所以能运行，是因为只要类没有自己声明，编译器会自动生成两个特殊的成员函数：

  • 拷贝构造函数：Box(const Box& other)，在「用已有对象初始化新对象」时被调用，包括 Box b = a; 以及按值传参、按值返回。
  • 拷贝赋值运算符：Box& operator=(const Box& other)，在「两个已存在对象之间赋值」时被调用，如 b = a;。

编译器生成的版本做的是逐成员拷贝：把源对象每个成员的值原样复制过去。对 int、std::string 这类成员，这样复制没问题；麻烦出在指针成员上。

浅拷贝与深拷贝：默认拷贝到底做了什么

回到 new 出来的指针成员 int* data。逐成员拷贝复制的是指针本身的值，也就是那块内存的地址，而不是内存里的内容。

  • 浅拷贝：只复制指针，两个对象指向同一块内存。
  • 深拷贝：为新对象另外分配一块内存，再把内容复制过去，两个对象各自独立。

浅拷贝留下的隐患有两处：一是两个对象共享一块内存，任何一方改动都会「隔空」影响另一方；二是析构时两个对象都会去 delete 同一个地址，第二次释放会触发重复释放。所以只要类持有需要手动释放的资源，就必须自己接管拷贝，把它改成深拷贝——这正是开头程序崩溃的原因。

拷贝构造函数与拷贝赋值运算符

两者要处理的情形不同，写法也有区别。

拷贝构造函数面对的是「一块全新的、还没持有资源的内存」，直接申请并复制即可：Box(const Box& other) : data(new int(*other.data)) {}。

拷贝赋值运算符面对的是「一个早就持有资源、需要先腾空再装满的对象」，因此要比拷贝构造多两步：先释放自己原有的资源，再按新内容申请。它还有两个固定要求——返回 *this 以支持链式赋值，参数用 const 引用以避免多余拷贝。

自赋值检查与异常安全

拷贝赋值里最容易忽略的一步是自赋值检查：a = a; 这种写法虽古怪，却完全合法，还可能通过别名间接发生。如果不检查就「先 delete 自己，再读对方的 data」，而对方恰恰就是自己，那么读到的就是刚被释放的悬垂指针。

应对方式有两种：

  • 入口处写 if (this == &other) return *this;，直接挡住自赋值。
  • 更稳的顺序（异常安全）：先分配新资源，确认成功后再释放旧资源。这样即使 new 失败抛异常，对象仍保持原状，不会留下「旧资源已释放、新资源没拿到」的半截状态。

Rule of Three / Five / Zero 与 =default、=delete

拷贝控制的经验被总结成几组规则：

  • Rule of Three：如果类需要自定义析构函数、拷贝构造函数、拷贝赋值运算符中的任何一个，通常三个都需要。因为它们都在回答同一个问题——「怎么管理这份资源」，只补其中一两个，往往留下不一致的漏洞。
  • Rule of Five：C++11 增加移动构造函数与移动赋值运算符后，规则扩展为五个一起考虑。
  • Rule of Zero：反过来，如果类不直接持有裸资源、一切交给 RAII 类型（如 std::string、std::vector、智能指针）管理，那就什么特殊成员函数都不用写，编译器生成的版本已经足够正确。

还有两个控制默认行为的写法：= default 显式要求编译器生成默认版本；= delete 显式禁用某个函数（例如禁止拷贝）。写出来不仅表达了意图，也让错误在编译期而不是运行期就暴露出来。

让「资源怎么复制」由类自己说了算

拷贝控制的全部工作，其实就是回答一个问题：当一个对象要从另一个同类对象复制而来时，这份资源该怎么处理。编译器默认给的是「逐字节搬运」，对普通数据正确、对持有的资源却是灾难。接手书写拷贝构造与拷贝赋值，就是把这条默认规则替换成符合本类语义的规则；而 = default、= delete 则让你在「默认够用」与「根本不许」之间也留出明确的表达。

「浅拷贝」只复制指针值，使两个对象共享同一份资源；「深拷贝」为新对象另行分配资源并复制内容，使对象彼此独立；「自赋值检查」指拷贝赋值中先判断源对象是否即自身，避免先释放后读取；「Rule of Three / Five / Zero」分别指需要自定义析构、拷贝构造、拷贝赋值三者时一并考虑、C++11 起的五项扩展，以及全交给 RAII 类型从而一项都不用写的理想情形。

关键代码

C++
// ═══════════════════════════════════════════
// 1. 默认拷贝：逐成员复制指针，埋下隐患
// ═══════════════════════════════════════════

#include <iostream>

class Box {
public:
    explicit Box(int v) : data(new int(v)) {}
    ~Box() { delete data; }
    int get() const { return *data; }
private:
    int* data;
};

int main() {
    Box a(1);
    Box b = a;                             // 默认拷贝构造：只复制指针 data
    std::cout << b.get() << std::endl;     // 输出：1
    return 0;
}   // a、b 析构时 delete 同一块内存 → 重复释放，未定义行为

// ═══════════════════════════════════════════
// 2. 拷贝构造函数：改成深拷贝
// ═══════════════════════════════════════════

class Box {
public:
    explicit Box(int v) : data(new int(v)) {}
    Box(const Box& other)
        : data(new int(*other.data)) {}    // 深拷贝：另分配一块内存再复制内容
    ~Box() { delete data; }
    int get() const { return *data; }
private:
    int* data;
};

int main() {
    Box a(1);
    Box b = a;                             // 走自定义拷贝构造，两个对象各自独立
    std::cout << b.get() << std::endl;     // 输出：1
    return 0;                              // 各自释放自己的内存，安全
}

// ═══════════════════════════════════════════
// 3. 拷贝赋值运算符与自赋值检查
// ═══════════════════════════════════════════

class Box {
public:
    explicit Box(int v) : data(new int(v)) {}
    Box(const Box& other) : data(new int(*other.data)) {}
    Box& operator=(const Box& other) {
        if (this == &other) return *this;  // 自赋值检查，防止先删自己再读自己
        int* fresh = new int(*other.data); // 先分配新资源，保证异常安全
        delete data;                       // 再释放旧资源
        data = fresh;
        return *this;                      // 返回自身引用，支持链式赋值
    }
    ~Box() { delete data; }
    int get() const { return *data; }
private:
    int* data;
};

int main() {
    Box a(1);
    Box b(2);
    b = a;                                 // 拷贝赋值
    b = b;                                 // 自赋值：被检查挡住，不产生悬垂
    std::cout << b.get() << std::endl;     // 输出：1
    return 0;
}

// ═══════════════════════════════════════════
// 4. =default 与 =delete：显式控制默认行为
// ═══════════════════════════════════════════

class NonCopyable {
public:
    NonCopyable() = default;                            // 要求编译器生成默认构造
    NonCopyable(const NonCopyable&) = delete;           // 禁止拷贝构造
    NonCopyable& operator=(const NonCopyable&) = delete; // 禁止拷贝赋值
};

int main() {
    NonCopyable a;
    // NonCopyable b = a;                  // 编译错误：拷贝构造已被删除
    return 0;
}

// ═══════════════════════════════════════════
// 5. Rule of Five：把移动版一并补齐
// ═══════════════════════════════════════════

#include <cstddef>
#include <cstring>
#include <utility>

class Buffer {
public:
    explicit Buffer(std::size_t n) : data(new char[n]), size(n) {}
    ~Buffer() { delete[] data; }                        // 1. 析构
    Buffer(const Buffer& other)                         // 2. 拷贝构造
        : data(new char[other.size]), size(other.size) {
        std::memcpy(data, other.data, size);
    }
    Buffer(Buffer&& other) noexcept                     // 4. 移动构造
        : data(other.data), size(other.size) {
        other.data = nullptr;                           // 源对象交出资源并置空
        other.size = 0;
    }
    Buffer& operator=(Buffer&& other) noexcept {        // 5. 移动赋值
        if (this != &other) {
            delete[] data;
            data = other.data;
            size = other.size;
            other.data = nullptr;
            other.size = 0;
        }
        return *this;
    }
private:
    char* data;
    std::size_t size;
};

int main() {
    Buffer a(4);
    Buffer b(std::move(a));                 // 移动构造：只搬指针，不复制数据
    return 0;                               // a 已置空，析构安全
}
