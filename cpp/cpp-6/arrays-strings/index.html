数组、C 风格字符串与 std::string

理解内置数组的特性与局限，掌握 C 风格字符串的操作，以及 std::string 的现代用法。

开场问题：一个只做「复制字符串」的小函数，源码里就是一句 strcpy，平时运行得好好的；可某次输入变长之后，程序悄悄改掉了隔壁某个变量，甚至直接崩溃——写一段文字，怎么会写到别的变量头上？

字符串与数组同源

你要处理的是一串文本：用户输入的名字、一段报文、一组编号。在 C 的世界里根本没有独立的「字符串类型」，字符串和数组是同一件事——一块连续内存。于是你必须先回答：多长？哪里结束？

把文本当成 char 数组、末尾放一个 \0 做结束标记，是最早的答案。但它把两三个成本悄悄转嫁给了你：

  • 数组不记录自己多大。数组名一旦传进函数就退化成指针，大小信息当场丢失，你只能另传一个长度参数，或者指望调用方别越界。
  • 越界不报错。写 arr[10] 编译照过，运行时悄悄读坏或写坏相邻内存，这就是未定义行为。
  • strcpy / strcat 不检查目标缓冲区多大。目标 10 字节、源 12 字节，多出来的那两个字节就覆盖到相邻变量上了。

所以真正要回答的是：能不能让「一块字符内存」和「它有多长」绑在同一个东西里，让谁都不会算错？

裸缓冲区管理

最朴素但真的能跑的做法：手动开一个足够大的缓冲区，用 \0 结尾，用 strlen 数长度。

char buf[64];
strcpy(buf, "Hello");
std::cout << buf << std::endl;

这个方案做对了一件很扎实的事：它立起了「字符串 = 一串字符 + 一个结束标记」这个模型。strlen 只要一路扫到 \0 就知道长度，输出函数也靠它知道何时停。在没有更好工具的年代，这套约定撑起了无数 C 程序。

越界写入后果

  • char s[5] = "Hello"; 里源串是 5 个字符加一个 \0、共 6 字节，塞进 5 字节数组后 \0 被挤掉，之后任何按 C 字符串进行的操作都会一路读到数组外。
  • strcpy(dst, src) 在 strlen(src) + 1 > sizeof(dst) 时照写不误，直接覆盖相邻内存——正是开场那个 bug。
  • 数组传给函数后退化：void foo(int a[]) 等价于 void foo(int* a)，函数里 sizeof(a) 得到的是指针大小，不是数组字节数，依赖它的循环全算错。
  • 想拼接两段字符串，得自己 strlen 两边、算总长、确认缓冲区够大、再 strcat——每一步都能算错，且错一步就是内存被破坏。

缓冲区长度封装

不推翻「字符 + 结束标记」，而是把「缓冲区」和「长度」封进一个对象里。这就是 std::string：容量不够时它自己扩容，拼接用 +、比较用 ==，长度随时 size() 可取。

std::string s1 = "Hello";
std::string s2 = "World";
std::string s3 = s1 + ", " + s2 + "!";
std::cout << s3.size() << std::endl; // 13

长度跟着对象走，再也不用单独传。s3.substr(0, 5) 取出前 5 个字符、s3.find("World") 返回第一次出现的位置，这些都是 std::string 的成员函数。短字符串还有 SSO（短字符串优化）：内容足够短时直接存在对象自身缓冲里，连堆分配都省了。

接着补「和旧接口打交道的桥」。很多老 API 只认 const char*，于是有了 s3.c_str()——返回一个以 \0 结尾的 const char*。C++11 起，data() 与 c_str() 都保证返回 \0 结尾的连续缓冲区。

再补数组这一侧：内置数组「定长、易退化」的毛病并没消失，所以现代写法用 std::array（固定大小、带 size()、不退化）和 std::vector（动态大小）来替代。

但这里必须补一条边界，否则很容易从一种错觉掉进另一种：std::string 的 operator[] 并不检查越界，s[100] 同样是未定义行为；要检查就用 .at()，越界会抛异常。换成 std::string 只是把最容易出错的容量管理接管了，界限判断仍要你自己守。另一个坑是字符串字面量："Hello" 的类型是 const char[N]，能隐式转成 const char*，却不能转成 char*——char* p = "Hello"; 在现代 C++ 里就该报错，因为改写它指向的字面量是未定义行为。

别再用 strcpy / strcat：它们完全不看目标缓冲区多大。退而求其次可用 strncpy / strncat，但要记得自己补 \0；更省心的做法是根本不用它们，直接用 std::string。

数组退化代价

类型接管长度

数组与字符串这件事，说到底就是把「容量」和「长度」从人的记忆里搬进类型里。裸数组和 C 风格字符串把这两件事全交给你，std::string 与 std::array / std::vector 把它们接管过去——只要不与 C 风格接口打交道，你几乎不必再手算长度。

「数组到指针退化」指在多数表达式语境里，数组名会隐式转换（退化）为指向首元素的指针，转换之后不再携带数组长度；只有 sizeof 与取地址 & 作用于数组名本身时例外。正因如此，int a[10] 传给 void f(int a[]) 后，函数内 sizeof(a) 得到的是指针大小而非 40，必须额外传入元素个数。

关键代码

C++
#include <iostream>
#include <string>

int main() {
    std::string s1 = "Hello";
    std::string s2 = "World";
    std::string s3 = s1 + ", " + s2 + "!";
    std::cout << s3 << std::endl;

    int arr[5] = {1, 2, 3};
    std::cout << arr[0] << std::endl;

    return 0;
}
