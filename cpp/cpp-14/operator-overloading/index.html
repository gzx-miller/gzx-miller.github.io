运算符重载：让自定义类型更自然

掌握 C++ 运算符重载的规则和惯用法，为自定义类型提供直观的运算符接口。

开场问题：你写了个二维向量类，很想直接写 v1 + v2，还想让 std::cout << v1 能打印它，可 + 一写出来编译器就报错——变量明明是你亲手定义的类，为什么 + 的直觉在这里不成立？

自定义类型运算

你希望自定义类型用起来像内置类型：分数能相加、日期能比较、向量能打印。最朴素的方式是给类加成员函数：v.add(other) 做加法、v.print() 做输出。

这套写法能跑，但把成本留给了使用者：

  • 调用处读起来是"方法调用"而不是表达式，a + b + c 得拆成 a.add(b).add(c)，可读性明显下降。
  • std::cout << v 这种写法根本没法做成成员函数——成员函数的左操作数必须是本类对象，而这里左边是 std::ostream。
  • 默认的 v1 == v2 比较的是对象地址而不是内容，得到的是"是不是同一个对象"，不是"值是否相等"。
  • 每种类型都有一批各自命名的方法，用户得逐个记住，无法沿用内置类型的经验。

所以要问的是：能不能让自定义类型也支持 +、==、<< 这些运算符，而且行为符合大家对这个运算符的直觉？

成员函数实现运算

最省事的做法，就是把运算都写成普通成员函数：Vector add(const Vector& other) const、bool equals(const Vector& other) const、void print() const。

它做对了一件实实在在的事：把运算的语义收进了类型自己的接口里——逻辑正确、可以复用，也不需要用户去碰私有成员。问题只在于，这些接口没有"长成运算符的样子"。

链式调用可读性

  • v1.add(v2) 缺失表达力；连续运算如 a + b + c 写成 a.add(b).add(c)，一眼看不出是"三数相加"。
  • std::cout << x 无法写成成员函数，因为左操作数是 std::ostream 而不是你的类型。
  • v1 == v2 走的是内置的地址比较，结果几乎总是 false，与"两向量相等"的本意完全不符。
  • 用户要面对一长串方法名，使用体验和内置类型割裂开来。

引入运算符重载

不推翻这些函数，只是给它们换上运算符的"外壳"：把函数名从 add 改成 operator+，语言就允许你用 v1 + v2 来调用它。这就是运算符重载——不是发明新语法，而是让自定义类型接入已有的运算符。

第一步，先做能做成成员的那些：

Vector operator+(const Vector& other) const { return Vector(x + other.x, y + other.y); }

注意它返回的是一个新对象，不修改任何一个操作数——这正符合 + 的直觉：a + b 不该让 a 或 b 发生变化。末尾的 const 表示"加法不改自己"。

第二步，判断哪些运算符不能写成成员，只能写成全局函数。规则很朴素：成员函数的左操作数必须是本类对象。凡是左操作数不是你的类型、或者两边地位需要对称的运算符，都只能放在类外：

  • operator<< 与 operator>>：左操作数是 std::ostream / std::istream，所以必须写成全局函数。它要访问私有成员，就在类里把它声明为 friend。
  • ==、<、+ 这类两边对等的运算符：写成全局函数才能让 1 + v（左操作数不是本类）也匹配得上，同时保证对称性成立。

friend std::ostream& operator<<(std::ostream& os, const Vector& v) { os << "(" << v.x << ", " << v.y << ")"; return os; }

这里有个细节：它返回 os 的引用，而不是 void，否则 std::cout << a << b 就没法链式连着写。

第三步，也是重载最容易翻车的地方——守住所重载运算符的约定语义。换了语法，但大家对这个运算符的期待没变：

  • 比较运算符返回 bool；算术运算符返回新对象、不修改操作数；复合赋值（+=）返回引用、修改左操作数；下标 operator[] 返回引用。
  • == 与 != 成对实现（通常用 == 写出 !=），< 与 > 成对；< 用于排序时必须满足严格弱序。
  • 反面例子：把 operator+ 写成"修改自己并返回引用"，v1 + v2 会偷偷改掉 v1——能编译，但语义全错，这类 bug 极难查。

第四步，补两个高频惯用法：

  1. 递增 / 递减要区分前缀和后缀：前缀 T& operator++() 返回引用（支持 ++obj）；后缀 T operator++(int) 用一个占位 int 参数区分，返回旧状态的副本。
  2. 下标运算符提供两个版本：非 const 版本返回普通引用（可写），const 版本返回 const 引用（只读）——因为 const 对象调不到非 const 的重载。

还有几条边界要记牢。operator= 必须定义为成员函数，不能是全局函数；operator() 让对象能像函数一样被调用（仿函数），标准库算法大量用它；operator* 与 operator-> 用于实现智能指针和迭代器，给自定义类型以指针语义；转换运算符 operator 类型() 要谨慎，它会造成意外的隐式转换，C++11 起可用 explicit 加以限制。至于 ::、.*、.、?: 这四个，语言干脆不允许重载。

重载不能改变运算符的"规则"，只能改变它的"作用对象"：优先级、结合性、操作数个数都不能动——+ 永远是二元、* 的优先级永远高于 +；也不能给内置类型重新定义含义。所以不要为了炫技而给无意义的运算符安排反直觉的语义，使用者会因此踩坑。

重载语义与选型

运算符重载不是造语法，而是给自定义类型一个和内置类型一致的表达方式。选对它该做成员还是全局（看左操作数是不是本类、要不要对称性），守住每个运算符约定俗成的语义（算术返回新对象、复合赋值返回引用、比较成对实现、< 满足严格弱序），你的类型就能自然地融进 +、==、<< 这些表达式里。

「严格弱序」指用 < 为元素定义排序时，这个比较必须满足的一组性质：任何元素都不小于自身（不可自反），比较结果在传递上保持自洽，且"互不小于"构成等价关系。它是 std::sort、std::map、std::set 等有序算法的前提——一旦违反（例如写成一个会随状态变化的比较），行为是未定义的，可能直接崩溃；与它相对，operator== 只需要表达"值相等"这一点。

关键代码

C++
#include <iostream>
#include <string>

class Vector {
private:
    double x, y;

public:
    Vector(double x, double y) : x(x), y(y) {}

    // 运算符重载：+
    Vector operator+(const Vector& other) const {
        return Vector(x + other.x, y + other.y);
    }

    // 运算符重载：<<（输出）
    friend std::ostream& operator<<(std::ostream& os, const Vector& v) {
        os << "(" << v.x << ", " << v.y << ")";
        return os;
    }
};

int main() {
    Vector v1(1, 2), v2(3, 4);
    std::cout << "v1 + v2 = " << v1 + v2 << std::endl;
    return 0;
}
