Lambda 表达式与捕获

掌握 Lambda 的语法、捕获列表的多种形式、mutable 与泛型 Lambda 的用法。

开场问题：想给 std::sort 传一条「按成绩降序」的规则，按老办法要么在类外另写一个只被调用一次的函数，要么专门定义一个只为了塞进参数列表的仿函数类 —— 有没有办法把这一小段逻辑就地写出来，还顺带带上外部的阈值？

先朴素做法：命名函数与函数对象

算法需要的从来不是一个「值」，而是一段可调用对象（callable）。最直接的朴素做法有两种。

  • 单独写一个命名函数：把比较规则写成顶层函数，把函数名（会退化成函数指针）传给 std::sort。
  • 写一个函数对象：定义一个重载了 operator() 的类，实例化后传进去。

朴素做法做对了两件事：规则可以复用，也能携带状态（仿函数把阈值存成成员）。但不足同样明显：为了一个只用一次、只写三行的规则，你被迫在类外多造一个名字或一整个类；逻辑离使用现场很远，读代码时要来回跳转。更麻烦的是，函数指针无法携带运行时状态，想带上阈值就只能上仿函数，样板代码随之膨胀。

Lambda：就地写出可调用对象

C++11 想解决的正是「就地定义一小段逻辑」这件事，于是给出 lambda 表达式，语法为 [capture](params) -> ret { body }：[capture] 是捕获列表，后面依次是参数列表、可选的返回类型和函数体。[]() { ... } 就是一个匿名函数。

关键要认识到：lambda 不是一个函数，而是一个对象的字面量 —— 编译器为它生成一个唯一的闭包类型（closure type），该类型重载了 operator()。因此每个 lambda 的类型都独一无二且写不出来，只能交给 auto 去接收，或用 std::function 包装成统一类型。也正因为它本质是对象，lambda 才能被拷贝、被存进容器、被当作成员。

把 lambda 传给算法时，它等价于那个手写的仿函数 —— 只不过这个类由编译器替你生成，没有名字，也不能再被别人复用。这正是它「就地」的代价与收益。

捕获列表：值捕获、引用捕获与 this

lambda 的一大能力是访问外部变量，但外部变量不会自动进入函数体，必须在捕获列表里显式声明。捕获方式决定了 lambda 与外部世界的连接是「快照」还是「通道」。

  • [x]：值捕获，在 lambda 创建时复制一份 x。之后外部 x 怎么变都与它无关，副本在 lambda 内默认是 const 的。
  • [&x]：引用捕获，捕获的是 x 的引用，调用时读到的永远是外部的最新值。
  • [=] / [&]：默认按值 / 按引用捕获所有用到的自动变量。
  • [x, &y]：混合捕获，按需分别指定，往往比 [=] / [&] 更清晰、更安全。
  • [this]：在成员函数里捕获 this 指针，从而访问成员；C++17 起还可写 [*this] 按值捕获整个对象的副本。

选择的原则很简单：需要「记住当下的值、之后不随外部变化」就用值捕获；需要「实时读改写外部状态」才用引用捕获。默认捕获 [=] / [&] 虽然省事，却会把用到的所有变量一并捕获，其中 [=] 在成员函数里会隐式捕获 this，是最常见的隐患来源，因此能显式列出就不要偷懒。

mutable、返回类型推导与泛型 lambda

值捕获的副本默认不可修改：若 lambda 体内要改写它，必须把 lambda 声明为 mutable。这里要特别留意，mutable 改的是副本，外部的原变量纹丝不动 —— 这与「用引用捕获去真正修改外部变量」是两回事，二者目的不同。

返回类型通常无需写出：函数体只有一条 return 语句时编译器按该表达式推导；有多条返回语句且类型不一致时，则需用 -> ret 显式指定。C++14 起函数体里可以写任意复杂语句，推导规则也放宽，但「返回类型要能唯一确定」这条约束始终成立。

另一个 C++14 能力是泛型 lambda：把参数写成 auto，如 [](auto a, auto b) { return a + b; }。它等价于一个模板化的 operator()，同一个 lambda 可对不同参数类型分别实例化。代价是它不再有单一的调用签名，无法直接转成函数指针去传给按具体类型取回调的接口。

生命周期陷阱与 std::function 的配合

lambda 最容易踩的坑几乎都出在捕获与生命周期的错位。引用捕获只是借用外部变量，一旦 lambda 活过了被捕获变量的生命周期，调用它就会访问已销毁的对象，属于未定义行为。危险往往不在立即调用，而在 lambda 逃逸：被存进 std::function、放进容器，或在函数返回后才异步执行时，栈上的局部变量早已析构。相较之下值捕获是自持副本，逃逸后依然安全。

当接口需要一个固定的可调用类型时，可以用 std::function<int(int)> 做类型擦除，把任意签名匹配的 lambda 装进去，代价是一次间接调用开销，且被包装的 lambda 一旦跨出作用域，就必须靠值捕获或初始化捕获来保证安全。C++14 的初始化捕获 [ptr = std::move(owner)] 允许在捕获时就地构造新变量、把 unique_ptr 之类移动独占的资源搬进 lambda，正好补齐了值捕获不能转移所有权的短板。

实践结论：能就地用就用 lambda，能用 auto 接收就用 auto，确实需要统一回调类型或跨作用域保存时再上 std::function；捕获列表尽量显式列出，避开 [=] 在成员函数里对 this 的隐式捕获，并让 lambda 的存活期短于它所引用的一切。

看一遍 lambda 的各种写法

把 lambda 当成一个匿名的函数对象

一旦把 lambda 理解成「编译器现场生成的、唯一类型的函数对象」，它的诸多特性就都有了解释：为什么必须用 auto 接收、为什么泛型 lambda 没有单一签名、为什么捕获本质是往这个对象的成员里塞数据。用好它的关键不在语法，而在每次写捕获列表时都想清楚一件事 —— 我需要的是外部变量的快照，还是一条随时可用的通道？想清楚这一点，绝大多数悬垂陷阱就能在源头避免。

「闭包」指 lambda 表达式在运行期生成的那个对象，它把捕获到的外部变量存成自身成员；「闭包类型」是这个对象的唯一匿名类型，由编译器生成。「捕获列表」决定这些成员是按值（快照）还是按引用（通道）绑定到外部变量。

关键代码

C++
// ═══════════════════════════════════════════
// 1. 基本 lambda 与它的唯一类型
// ═══════════════════════════════════════════

#include <iostream>                            // 标准输入输出
#include <vector>                              // 容器
#include <algorithm>                           // std::for_each
#include <functional>                          // std::function

int main() {
    auto greet = []() {                        // 编译器生成唯一的闭包类型
        std::cout << "hello" << std::endl;     // 结果：输出 hello
    };
    greet();                                   // 调用闭包对象的 operator()

    auto add = [](int a, int b) {              // 等价于一个重载了 operator() 的仿函数
        return a + b;
    };
    std::cout << add(3, 5) << std::endl;       // 结果：8
    return 0;
}

// ═══════════════════════════════════════════
// 2. 捕获列表：值捕获与引用捕获
// ═══════════════════════════════════════════

void captureDemo() {
    int factor = 2;
    auto byValue = [factor](int x) {           // 值捕获：创建时复制一份 factor
        return x * factor;                     // 说明：与外部 factor 后续变化无关
    };
    std::cout << byValue(5) << std::endl;      // 结果：10

    int total = 0;
    std::vector<int> nums = {1, 2, 3, 4};
    std::for_each(nums.begin(), nums.end(), [&total](int x) {   // 引用捕获：直接改写外部变量
        total += x;
    });
    std::cout << total << std::endl;           // 结果：10

    auto all = [=]() { return factor; };       // [=] 按值捕获用到的全部自动变量
    auto byRef = [&]() { return total; };      // [&] 按引用捕获用到的全部自动变量
    std::cout << all() + byRef() << std::endl; // 结果：12
}

// ═══════════════════════════════════════════
// 3. mutable 与返回类型推导
// ═══════════════════════════════════════════

void mutableDemo() {
    int base = 10;
    auto counter = [base]() mutable {          // 值捕获默认 const，mutable 才能改副本
        return ++base;                         // 说明：改的是副本，外部 base 仍是 10
    };
    std::cout << counter() << std::endl;       // 结果：11

    auto pick = [](bool flag) -> int {         // 多条 return 语句需显式指定返回类型
        if (flag) return 1;
        return 0;
    };
    std::cout << pick(true) << std::endl;      // 结果：1
}

// ═══════════════════════════════════════════
// 4. 泛型 lambda 与 std::function
// ═══════════════════════════════════════════

void genericDemo() {
    auto addAny = [](auto a, auto b) {         // 泛型 lambda：模板化的 operator()
        return a + b;                          // 说明：对不同参数类型分别实例化
    };
    std::cout << addAny(1, 2) << std::endl;    // 结果：3
    std::cout << addAny(1.5, 2.5) << std::endl;  // 结果：4

    std::function<int(int)> square = [](int x) {  // 类型擦除：统一成固定签名
        return x * x;
    };
    std::cout << square(4) << std::endl;       // 结果：16
}

// ═══════════════════════════════════════════
// 5. 捕获与生命周期：初始化捕获
// ═══════════════════════════════════════════

auto makeOwningCounter() {
    auto p = std::make_unique<int>(42);
    return [q = std::move(p)]() {              // 初始化捕获：把独占资源移进闭包
        return *q;                             // 说明：闭包持有所有权，析构时自动释放
    };
}

auto makeDangling() {
    int local = 7;
    return [&local]() { return local; };       // 危险：返回后 local 已随栈销毁
}                                              // 说明：调用它读取悬垂引用属未定义行为
