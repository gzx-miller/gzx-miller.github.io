异常处理与异常安全

掌握 try/catch/throw、栈展开机制、noexcept 语义以及异常安全与 RAII 的配合。

开场问题：一个可能失败的函数用返回码报告错误，只要有一层调用忘了检查，错误就被悄悄吞掉；而构造函数根本没有返回值可用 —— 怎么让「出错」这件事无法被忽略，同时又保证资源一定被释放？

先朴素做法：返回错误码

最传统的方式是让函数返回一个状态码（或设置 errno），由调用者判断是否成功。

  • 做对的地方：正常值就是返回值，调用成本低，也没有任何隐藏控制流。
  • 不足：错误检查是调用者的义务，只要有一处忘看返回值，错误就被静默地传播下去；错误无法自动跨越多层调用冒泡，往往要逐层判断、逐层上抛；构造函数无法用返回值报告失败；而且若函数还要返回真正的计算结果，错误码就得额外用一个出参或全局变量来腾位置。

根本矛盾在于：错误信息与正常返回值挤在同一个通道里，且没有任何机制强制调用者处理它。异常机制正是把「错误通道」独立出来的方案。

throw、try、catch 与匹配顺序

throw 表达式抛出一个异常对象，它可以是任意类型，但工程惯例是抛 std::exception 的派生类。try 块包住可能抛异常的代码，紧随其后的一个或多个 catch 块负责处理。

  • catch 按书写顺序依次匹配，因此必须把派生类异常放在基类之前；否则基类的 catch 会抢先截获，更具体的分支永远进不去。
  • 捕获通常写 catch (const SomeError& e)：按引用以避免对象切片与多余拷贝，const 表示不修改异常对象。
  • catch (...) 捕获所有异常，用于兜底、记录日志后 throw; 重新抛出当前异常；它会连未知类型一起吞下，应谨慎使用。

只要抛出的对象能匹配上某个 catch 的形参类型（含继承关系下的向上转型），异常就由该处接管；这也是为什么「类型」在异常里格外重要 —— 它同时承担了「是否需要处理、由谁处理」的分派职责。

栈展开：异常发生时资源怎么被释放

抛出异常后，若当前函数没有对应的 catch，控制权会沿调用栈向上回退，去寻找能处理的 try。回退的每一步都会销毁该作用域内已经构造完成的局部对象，这个过程叫作栈展开（stack unwinding）。

  • 正是靠栈展开，RAII 对象在异常路径上与正常路径一样会被析构，资源因此不会泄漏 —— 这是异常能与 RAII 配合得如此自然的原因。
  • 局部对象的析构按构造顺序的逆序进行。
  • 由此引出一条铁律：析构函数不应抛出异常。若析构函数在栈展开期间又抛出异常而未能就地处理，程序会调用 std::terminate 直接终止。

noexcept 与三级异常安全保证

noexcept 声明一个函数不会抛出异常。它不只是文档：C++17 起它是函数类型的一部分，会影响重载决议与函数指针类型；对不抛异常的实现，标准库在移动、容器重分配等场合会走更高效的路径。需要记住，若被标记 noexcept 的函数真的抛了异常，将直接调用 std::terminate，不会进行栈展开。

与之配套的是一套「异常安全保证」的分级描述：

  • 基本承诺：异常抛出后，程序仍处于有效状态，不泄漏资源、不破坏不变量，但具体状态可能已改变。
  • 强承诺：操作要么完全成功、要么完全失败，状态如同调用从未发生（事务性）。常见实现手法是「先复制一份副本，改副本，最后用不抛异常的 swap 一次性替换」。
  • 不抛异常承诺：函数保证永不抛出异常，用 noexcept 标注。

标准异常体系与自定义异常类

C++ 标准库提供了一套异常类型层次，根节点是 std::exception，其主要分支及常见成员如下。

  • std::logic_error 分支：程序逻辑错误，如 std::invalid_argument、std::out_of_range、std::length_error。
  • std::runtime_error 分支：运行时才能发现的错误，如 std::range_error、std::overflow_error。
  • 非 logic_error / runtime_error 的直接派生：std::bad_alloc（内存分配失败）、std::bad_cast（dynamic_cast 失败）等。
  • 所有类型都提供虚函数 what() 返回错误说明。

自定义异常类通常继承 std::runtime_error 或 std::logic_error，在构造函数里把错误信息转发给基类，从而自动复用 what()；这样既携带了业务语义，又能被 catch (const std::exception&) 统一兜底。此外，构造函数抛异常是报告对象构造失败的唯一合理方式 —— 因为对象一旦未能完整构造，析构函数不会执行，资源必须由已成功构造的成员各自负责。

看一遍异常的分派与处理顺序

把「出错」变成一条独立的控制流

异常的价值不是「多了一种 if」，而是把错误的发生与错误的处理分离开：抛出点只负责把问题交出去，处理点可能在很上层的调用里；沿途所有资源由 RAII 在栈展开时自动收拾。写好异常安全的关键因此收敛为两件事 —— 用 RAII 管住每一个资源，让析构函数永不抛异常。做到这两点，正常路径与异常路径就共享同一套释放逻辑，代码不再需要为「万一中间失败」单独铺应急分支。

「栈展开」指异常沿调用栈向上寻找处理者时，逐层逆序销毁局部对象的过程。「异常安全保证」描述函数在抛出异常后对状态的承诺，分为基本、强、不抛异常三级。「noexcept」是声明函数不抛出异常的关键字，C++17 起成为函数类型的一部分。

关键代码

C++
// ═══════════════════════════════════════════
// 1. throw、try、catch 与匹配顺序
// ═══════════════════════════════════════════

#include <iostream>
#include <stdexcept>                           // 标准异常体系
#include <vector>

class MyError : public std::runtime_error {    // 自定义异常：继承标准运行时错误
public:
    explicit MyError(const std::string& msg) : std::runtime_error(msg) {}
};

void mayThrow(bool flag) {
    if (flag) throw MyError("business failed");  // throw 表达式：抛出异常对象
}

void catchDemo() {
    try {
        mayThrow(true);
    } catch (const MyError& e) {               // 派生类在前，先被匹配
        std::cout << e.what() << std::endl;    // 结果：business failed
    } catch (const std::exception& e) {        // 基类在后，兜住其余标准异常
        std::cout << e.what() << std::endl;
    } catch (...) {                            // 兜底：捕获一切，按引用捕获避免切片
        std::cout << "unknown" << std::endl;
    }
}

// ═══════════════════════════════════════════
// 2. 栈展开与 RAII
// ═══════════════════════════════════════════

class Guard {                                  // RAII：析构即释放
public:
    ~Guard() { std::cout << "release" << std::endl; }   // 栈展开时被调用
};

void unwindDemo() {
    try {
        Guard g;
        throw std::runtime_error("boom");      // 抛出后 g 被析构（栈展开）
    } catch (const std::exception& e) {
        std::cout << "caught: " << e.what() << std::endl;
        // 结果：先输出 release，再输出 caught: boom
    }
}

// ═══════════════════════════════════════════
// 3. noexcept 与异常安全
// ═══════════════════════════════════════════

int safeDivide(int a, int b) noexcept {        // 承诺不抛：利于优化，真抛则 terminate
    return b == 0 ? 0 : a / b;                 // 说明：不抛异常的函数标注 noexcept
}

void swapStrong(std::vector<int>& a, std::vector<int>& b) noexcept {
    a.swap(b);                                 // 强保证：借助不抛的 swap 实现原子替换
}

// ═══════════════════════════════════════════
// 4. 标准异常体系与捕获
// ═══════════════════════════════════════════

void standardDemo() {
    try {
        throw std::invalid_argument("negative size");   // logic_error 分支
    } catch (const std::logic_error& e) {      // 逻辑错误：派生于 std::exception
        std::cout << e.what() << std::endl;    // 结果：negative size
    } catch (const std::exception& e) {        // 统一兜底，含 std::bad_alloc 等
        std::cout << e.what() << std::endl;
    }
}
