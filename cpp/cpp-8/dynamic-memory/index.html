动态内存管理：new/delete 与常见陷阱

理解 C++ 的手动内存管理机制，掌握 new/delete 的正确用法，以及内存泄漏、悬垂指针等常见问题的防范。

开场问题：服务跑了一整晚，内存占用只涨不降，重启一下就恢复；你翻遍代码，每一处 new 看起来都写对了——那这些借出去的内存，到底去哪了？

动态内存需求

有些对象的大小要等运行时才知道：用户输入多长、这次读到多少条记录。有些对象的生命周期又不能跟着某一个作用域走：它要在多个函数甚至多个对象之间共享。栈上的自动变量这两件事都做不到——大小编译期固定、离开作用域就销毁。

于是你需要一块「手动借、手动还」的内存，也就是堆。可这块内存也把责任原封不动交给了你：

  • 栈变量离开作用域会自动销毁，堆内存不会。你不还，它就一直被占着。
  • 销毁时机全靠人记：谁借的、什么时候还、有没有哪条分支忘了还，全在你脑子里。
  • 释放之后指针本身还在：指针不会因为 delete 而消失，误用它就是悬垂。

所以问题落成一句：怎样才能安全地借还堆内存，既拿到「运行时才定的大小」和「跨作用域的生命周期」，又不把「记得还」变成人的负担？

手动分配释放

最直接的做法：new 要一块，delete 还回去。

int* p = new int(42);
std::cout << *p << std::endl;
delete p;

new int(42) 分配一块 int 并初始化为 42，返回指向它的指针；用完 delete p 释放。这个方案做对了一件栈变量给不了的事：把分配时机第一次交给了程序自己——大小可以运行时算，生命周期可以跨函数。

数组配对释放

  • 数组要用 new int[5] 分配，释放却必须写成 delete[] arr；写成 delete arr 就是未定义行为——分配与释放必须配对：new 对 delete，new[] 对 delete[]。
  • 忘记 delete 就内存泄漏，程序占的内存只涨不降，正是开场那一幕。
  • delete p 之后 p 仍指向那块已归还的内存，再解引用就是悬垂指针，读到什么全凭运气。
  • 对同一个指针 delete 两次是重复释放，同样是未定义行为。

置空与智能指针

先立一条几乎零成本的规矩：delete 之后立刻把指针置为 nullptr。因为 delete nullptr 是安全的（什么也不做），重复释放这条就被堵住了。但要清醒：这只保护了这一个指针，其它指向同一块内存的指针照样悬垂。

再补「分配失败」。默认情况下 new 失败会抛 std::bad_alloc；如果不想用异常，可以写 new (std::nothrow)，失败时返回 nullptr，由你自己判空。

接着把「记得还」这件事从人身上挪走，也就是智能指针。std::unique_ptr 管独占所有权，离开作用域自动 delete；std::shared_ptr 用引用计数管共享所有权，最后一个持有者销毁时释放。改用它们之后，「配对」由类型系统来保证，失配、泄漏、悬垂这几类大头一并消掉。

再补「一大块连续内存」：要动态数组，直接用 std::vector；固定大小用 std::array。它们把容量和释放都接管了。于是现代 C++ 的经验法则变得很干脆——几乎不要直接写裸 new / delete。

最后有一个特殊技法必须单独交代，因为它把上面的规矩整个翻转过来：placement new，写法是 new (addr) T(...)，在一块已经分配好的地址上构造对象（内存池等场景常用）。它的清理方式和其它 new 完全不同：必须手动调用析构 obj->~T()，绝不能对它 delete——operator delete 并不会释放这块内存，而内存本身要按当初怎么来的怎么还。

new[] 一定要配 delete[]：对 new[] 出来的数组写 delete arr，不会正确地逐个析构元素，既漏掉了后面的对象，又可能破坏堆结构。此外，怀疑泄漏时可用工具定位：Linux 上的 Valgrind、Windows 上的 Dr. Memory，或编译期插桩的 AddressSanitizer。

配对悬垂验证

内存释放责任

动态内存把「大小」和「生命周期」的决定权交给程序，代价是把「记得还」也交给你。delete 后置空只堵住一种误用，真正把这责任接过去的是智能指针和容器——所以现代 C++ 的答案不是「更小心地写 new / delete」，而是「尽量不写它们」。

「悬垂指针」指仍然保存着某个地址、但该地址上的对象已经被销毁（最典型的是 delete 之后）的指针。此时对它解引用、读写或再次 delete 都是未定义行为。边界：delete p; p = nullptr; 只让这一个指针失效，其它指向同一块内存的指针仍然是悬垂的。

关键代码

C++
#include <iostream>

int main() {
    int* p = new int(42);
    std::cout << *p << std::endl;
    delete p;
    p = nullptr;

    int* arr = new int[5]{1, 2, 3, 4, 5};
    for (int i = 0; i < 5; i++) {
        std::cout << arr[i] << " ";
    }
    delete[] arr;

    return 0;
}
