类与对象：封装、访问控制与 this 指针

理解 C++ 类的定义、对象创建、访问控制（public/protected/private）以及 this 指针的作用。

开场问题：同一个 setAge 函数，p1.setAge(4) 只改了 p1，p2 纹丝不动——函数体里明明只写了一句 age = a，它凭什么知道该改哪个对象的 age？

数据与规则绑定

你想把「数据 + 操作数据的规则」绑在一起。就拿一个「人」来说：名字、年龄，外加一条规矩——年龄不能为负、也不能超过 150。

如果只是把数据摊成散变量、再写一堆函数去操作，会背上几笔隐藏的账：

  • 规矩没人守：任何人都能直接写 age = -5，那条「年龄非负」的约定形同虚设。
  • 改动面失控：字段一旦改名或多出一个，所有直接访问它的地方都得跟着改。
  • 没有「同一个东西」的边界：谈不上「这个人」和「那个人」，数据之间没有归属。

所以真正要回答的是：怎样把数据和守护数据的规则封成一个整体，让外部只能通过与规矩一致的入口来改它？

类与访问控制

最直接的做法：用 class 造一个自定义类型，把数据成员和操作它们的成员函数写在一起，再用访问权限挡住直接访问。

class Person {
  private:
    std::string name;
    int age;
  public:
    void setAge(int a) { if (a >= 0 && a <= 150) age = a; }
};

private 的数据外部碰不到，只能走 public 的 setAge，那条「年龄在 0 到 150」的规矩就被守住了。这个方案做对了一件事：把「能怎么改」从每个调用者的自觉，变成了类型的定义。

对象归属歧义

  • 光有访问权限还不够：setAge 里只写了 age = a，可同一个类能创建很多个对象，这句赋值到底改的是哪一个的 age？
  • struct 成员默认 public，class 成员默认 private；混用会让人对「这一行到底能不能访问」判断失误。
  • 有的成员函数只是「看一眼」，却也没被约束住，照样可能被误写成会改状态。
  • 类多起来之后 getter / setter 满天飞，成员函数放到类外定义时，限定写法还容易写错。

隐式this指针

先补上「到底是哪个对象」。每个非静态成员函数都有一个隐式的 this 指针，指向调用它的那个对象：p1.setAge(4) 里 this 就是 &p1，p2.setAge(4) 里就是 &p2。所以同一份函数代码能作用到不同对象上，this->age = a 不过是 (*this).age = a。

由此还有一个推论：this 的类型是「指向本类对象的 const 指针」——指针本身不能改（不能让它指到别的对象），但它指向的对象是可修改的。正因如此，把 *this 返回出去就能链式调用：obj.setX(1).setY(2)。

接着补 const 成员函数。在函数签名末尾写 const（如 int getAge() const），等于承诺「我不修改这个对象」。此时 this 的类型变成「指向 const 本类对象的 const 指针」，于是里面只能调用其它 const 成员函数——getAge() const 里就调不了 setAge。判断一个函数要不要加 const，只须问一句：它改不改对象状态。

再补初始化和访问的细节。带参构造用初始化列表 Person(const std::string& n, int a) : name(n), age(a) {} 一次性把成员初始化好，这也是初始化 const 成员和引用成员的唯一途径。另外，成员函数在类外定义时要用 类名::成员名 的限定语法；struct 与 class 的默认权限差异也要记牢，别靠运气。

还有两个常被忽略的点。其一，C++11 起可以在类里给非静态数据成员直接写默认值（in-class 初始化器），省掉构造函数里的重复赋值。其二，友元 friend 可以访问 private 成员，但友元关系不传递、不继承：A 是 B 的友元、B 是 C 的友元，并不代表 A 能碰 C 的私有成员。

给只读的 getter 都加上 const：const 成员函数里不能修改对象状态，也不能调用非 const 成员函数。加上 const 之后，它既能被 const 对象调用，也能被非 const 对象调用——少写一个 const，反而会限制住自己。

成员访问与校验

封装职责边界

类是「数据 + 守护数据的规则」的一个整体：访问权限决定谁能进哪个门，this 让同一份成员函数知道自己正作用于哪个对象，const 成员函数则把「我只读」写进类型。封装不只是把变量藏起来，而是让对象始终待在自己定义的合法状态里。

「封装」指把数据与操作数据的成员函数组织在一个类中，并用访问控制（public / protected / private）约束外部只能通过公开接口访问对象，从而在类型内部维护对象的不变量（如「年龄非负」）。边界：private 只是编译期的名字访问限制，挡不住 friend 这类越权通道；另外 class 默认 private、struct 默认 public。

关键代码

C++
#include <iostream>
#include <string>

class Person {
private:
    std::string name;
    int age;

public:
    Person(const std::string& n, int a) : name(n), age(a) {}

    void introduce() const {
        std::cout << "我叫 " << name << "，今年 " << age << " 岁。" << std::endl;
    }
};

int main() {
    Person p("栗子", 3);
    p.introduce();
    return 0;
}
