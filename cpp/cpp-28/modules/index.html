C++20 模块：替代头文件的新方式

了解 C++20 引入的模块系统，理解它如何解决头文件的问题（宏泄漏、包含顺序依赖、编译速度慢），以及基本用法。

开场问题：某个头文件里藏着一句参数宏，另一个源文件只是 #include 了它，里面一个重名的变量忽然编译报错——你根本没碰那行代码，它怎么就坏了？

预处理文本粘贴

根源在于 C++ 复用代码的方式：#include 不是「引用一个文件」，而是在预处理阶段把这个文件的全部文本原样粘进来。粘进来的东西不分你我，于是三笔成本全落到写代码的人身上。

  • 宏会泄漏。#define 一旦展开，就作用于整个翻译单元剩下的所有代码，别人的标识符只要重名就会被替换掉。
  • 包含顺序敏感。头文件 A 用到了 B 里的类型，就必须先 #include B 再 #include A；顺序错了就报「未定义」，而顺序对不对往往是试出来的。
  • 重复包含与重复解析。同一个头文件被多条路径包含，要么靠 include guard 去重，要么重复定义；更要命的是每个 .cpp 都要把这棵头文件树重新解析一遍，工程一大，编译时间几乎全耗在这里。

所以问题是：能不能有一种「导入代码」的方式，只暴露你明确要分享的东西，既不泄漏宏，也不用重复解析？

重复包含防护

最省事的补丁：给每个头文件套上 #pragma once（或传统的 include guard），保证它在同一个翻译单元里只被包含一次。

这个方案做对了一件事：它解决了「自己重复包含自己」这一类问题。同一个头文件被两条路径引到，也只会展开一次，重复定义立刻消失；成本也低，加一行就见效。

宏泄漏与顺序依赖

  • 宏照样泄漏。#pragma once 只防重复包含，管不住 #define——它已经展开进整片翻译单元了。
  • 顺序依赖还在。该先包含谁、后包含谁的约束一点没变，换个包含顺序仍然可能「未定义」。
  • 编译还是慢。去重只保证「同一个文件不被包含两次」，但每个 .cpp 仍要各自解析一遍头文件，跨文件的重复解析没有被消除。
  • 封装全靠约定。头文件里写的所有声明一律暴露给使用者，想藏起来的实现细节只能靠「别去用」来约束。

模块导出边界

不推翻「复用代码」这个目标，而是把「文本粘贴」换成一种有边界、有导出声明的结构——这就是 C++20 的模块。它分成两种文件角色：模块接口文件（习惯叫 .cppm 或 .ixx）负责声明「我导出什么」，模块实现可以就写在接口文件里，也可以拆成实现分区。

  1. 在接口文件里用 export module math; 声明一个模块，给它起个名字。
  2. 用 export 标记要对外提供的函数、类、变量；没加 export 的声明只在本模块内部可见。
  3. 使用方写 import math; 导入，只能看到被 export 出来的名字，其它一律不可见。
  4. 需要组织大型模块层次时，用 export import A; 把导入的模块再重新导出；模块内部还可以用 module math:part; 做分区。

这一换，开场那三个问题各自被对症解决：宏不再泄漏，因为模块实现里 #define 的东西不会影响导入它的人（反过来说，也不能再用宏去影响模块接口——这恰恰说明封装性变强了）；顺序依赖消失，import 与书写位置无关，导入了就可用；编译变快，模块接口只被解析并编译成模块产物一次，之后各个翻译单元直接读这份产物，不必重新解析整棵树。

迁移时还有两个现实边界必须知道。第一是与头文件互操作：可以把旧头文件 #include 进模块实现里，也可以用「头文件单元」import "header.h"; 把现有头文件当模块导入；标准库也有了自己的模块形式 import std;（C++23 起）。第二是编译器支持与 ABI：MSVC 支持最好，GCC 从 11 起需要 -fmodules-ts 和模块映射，Clang 仍在推进中；模块还会改变名称修饰（name mangling），不同编译器或版本产出的模块可能互不兼容，而标准库模块正是用来缓解这一点的。所以头文件会长期与模块共存，新项目可以优先用模块，老项目也不必急着全量迁移。

容易踩的一点：别再指望用宏给模块接口做条件编译来「影响使用者」——宏被隔离在模块实现内部，使用方既看不到也改不了。反过来，如果你把某个辅助声明忘了加 export，模块外就是访问不到，报错会写成「未声明的标识符」。排查这类错误时，第一步永远是确认那个名字到底有没有被 export。

接口与使用方分工

命名边界与单次解析

头文件的问题，是它把「复用」实现成了「文本粘贴」，于是宏泄漏、顺序敏感、重复解析全都躲不开。模块把同一件事换成了有名字、有导出边界、只解析一次的导入：导出的才可见，内部的外不外泄，接口只编译一遍。理解这一层，就明白 C++20 为什么要费这么大力气给「include 的替代品」。

「模块接口单元」指以 export module 名字; 声明模块、用 export 标记对外可见声明的那个翻译单元（文件通常命名为 .cppm 或 .ixx），它是模块对外的唯一门面。边界：只有被 export 的声明对 import 方可见；宏不会跨模块边界泄漏；模块可以用 export import 分层组织；C++20 的模块依赖编译器支持（MSVC 较好，GCC/Clang 仍在完善），并可能带来跨编译器、跨版本的 ABI 差异。

关键代码

C++
// math.cppm - 模块接口
export module math;

export int add(int a, int b) {
    return a + b;
}

export int multiply(int a, int b) {
    return a * b;
}

// main.cpp - 使用模块
import math;
import <iostream>;

int main() {
    std::cout << "3 + 4 = " << add(3, 4) << std::endl;
    std::cout << "3 * 4 = " << multiply(3, 4) << std::endl;
    return 0;
}
