构造函数、析构函数与对象生命周期

掌握各类构造函数、初始化列表、析构函数与成员/对象的初始化析构顺序。

开场问题：一个对象里藏着用 new 申请来的资源，按理说销毁对象就该把资源还回去；可只写 delete 却不写析构函数，对象一销毁，那块内存就永远没人认领。为什么「对象消失」和「资源归还」这两件事，不能自动连在一起？

对象的诞生与消亡：两个被保证调用的时刻

把对象的生命拉成一条线，它的两端各站着一个特殊成员函数：

  • 构造函数（constructor）：对象创建时被自动调用，负责把对象带到一个合法、可用的初始状态。
  • 析构函数（destructor）：对象销毁时被自动调用，负责收尾，通常是把对象持有过的资源还回去。

这两个函数看着只是普通成员函数，特殊之处在于调用时机由编译器保证：只要对象被创建，构造函数一定跑；只要对象离开作用域或被 delete，析构函数一定跑，不论中间是否提前返回、是否抛异常。名字与类名相同的是构造函数，前面加波浪号的是析构函数，二者都没有返回类型。

正因为「一定被调用」，它们是 C++ 里安放资源管理的天然位置。这里先把二者当作一对开关来理解，后面的顺序与初始化细节都围绕它们展开。

构造函数家族：默认、带参、委托与拷贝

一个类可以有多个构造函数，靠参数列表区分，各有别名：

  • 默认构造函数：可以不传参就调用，如 Point()。类没写任何构造函数时，编译器会自动生成一个；一旦自己写了带参构造，这个自动版本就消失，需要显式补回。
  • 带参构造函数：接受参数完成初始化，如 Person(const std::string& n, int a)。
  • 委托构造函数：一个构造函数把活转交给同类的另一个构造函数，如 Point(int v) : Point(v, v) {}，用来复用公共初始化逻辑。
  • 拷贝构造函数：以同类型对象的引用为参数，如 Student(const Student& other)，在「用已有对象创建新对象」时被调用。

朴素做法是每种构造都把初始化逻辑各写一遍，但一旦初始化规则变了，就要到处改、还可能改漏。委托构造把公共部分收敛到一处，是更省心的写法。

初始化列表：为什么不是函数体赋值

构造函数有一处特别的语法——初始化列表，写在参数列表之后、函数体之前：Person(const std::string& n, int a) : name(n), age(a) {}。

它和「进函数体再赋值」看着结果一样，差别却在过程：

  • 数据成员在进函数体之前就已经被初始化；函数体里的 name = n; 是赋值，意味着先默认构造一次、再覆盖一次，多做一遍工。
  • 对 const 成员与引用成员，它们必须在初始化列表里初始化，函数体里无法赋值，写法上直接编译不过。

结论很明确：能进初始化列表的成员就进列表，别留到函数体。这既是对无法赋值的成员的必要写法，也是省掉一次默认构造的效率写法。

析构函数：资源的最后一道闸门

析构函数负责收尾。一个类需要自己写析构函数的信号通常只有一个：它直接持有需要手动释放的资源，比如裸指针指向的堆内存、打开的文件句柄、占用的网络连接。

把这些资源的释放写进析构函数，就得到一条极强的保证：只要对象的生命周期正常结束，资源就一定被归还，无论中间走了多少条 return、有没有抛异常。这正是上一章 RAII 思路落地的地方。

  • 析构函数不接受参数，因此不能重载，一个类只有一个。
  • 析构函数通常不该抛异常；若析构时真要抛，必须自己就地捕获处理，否则可能直接终止程序。
  • 一个需要自己写析构函数的类，往往也还需要自己写拷贝构造与拷贝赋值——这条线索下一章会展开。

初始化顺序、explicit 与组合对象

三个容易踩坑、又常被问到的问题，放在一起说。

初始化顺序：多个数据成员按声明顺序初始化，与初始化列表里书写的顺序无关。若列表顺序和声明顺序不一致，请相信声明顺序；一旦某个成员的初始化依赖另一个成员，把依赖关系摆对声明次序才安全。

explicit：单参构造函数会带来一件副作用——允许隐式类型转换，比如把 3.0 悄悄变成一个对象。若这种转换并非本意，就在构造函数前加 explicit 关掉它，只允许显式构造。

组合对象：一个类可以把别的类对象作为成员。这时构造与析构遵循固定次序：成员先于自身构造，自身先于成员析构；若有继承，则整体是「基类 → 成员 → 自身」构造、「自身 → 成员 → 基类」析构，恰好相反。

把「初始化」与「清理」绑定到生命周期上

构造函数与析构函数之所以值得单独成章，在于它们把两件原本靠人记性的事——对象要有合法初值、资源要有人归还——变成了编译器必须执行的动作。再回看开头那个问题：如果当初把 delete 写进析构函数，那么对象销毁的那一刻，资源就已经被归还，「对象消失」与「资源归还」也就自动连在了一起。

「构造函数」在对象创建时自动调用，用于建立合法初值；「析构函数」在对象销毁时自动调用，用于释放资源，一个类只有一个且不可重载；「初始化列表」在构造函数体执行前初始化数据成员，是 const 成员与引用成员唯一可行的初始化方式；「委托构造」指某个构造函数把初始化工作转交给同类的另一个构造函数。

关键代码

C++
// ═══════════════════════════════════════════
// 1. 默认构造、带参构造与委托构造
// ═══════════════════════════════════════════

#include <iostream>

class Point {
public:
    Point() : x(0), y(0) {}                    // 默认构造：全零
    Point(int v) : Point(v, v) {}              // 委托构造：转交给下面的构造函数
    Point(int x, int y) : x(x), y(y) {}        // 带参构造
    void show() const { std::cout << x << ", " << y << std::endl; }
private:
    int x;
    int y;
};

int main() {
    Point a;
    Point b(4);
    a.show();                                  // 输出：0, 0
    b.show();                                  // 输出：4, 4
    return 0;
}

// ═══════════════════════════════════════════
// 2. 初始化列表与成员初始化顺序
// ═══════════════════════════════════════════

class Order {
public:
    Order() : total(0), item(++total) {}       // 顺序由声明顺序决定，与书写无关
    int getItem() const { return item; }
private:
    int total;                                 // 声明在前，先初始化：0
    int item;                                  // 声明在后，total 此时为 1
};

int main() {
    Order o;
    std::cout << o.getItem() << std::endl;     // 输出：1
    return 0;
}

// ═══════════════════════════════════════════
// 3. explicit：关闭单参构造的隐式转换
// ═══════════════════════════════════════════

class Meter {
public:
    explicit Meter(double v) : value(v) {}     // explicit 禁止 double 隐式转 Meter
    double value;
};

void print(Meter m) {                          // 参数按值传递
    std::cout << m.value << std::endl;
}

int main() {
    Meter m(2.5);                              // 显式构造，合法
    print(m);                                  // 输出：2.5
    // print(3.0);                             // 若无 explicit，这行会隐式转换，现在编译不过
    return 0;
}

// ═══════════════════════════════════════════
// 4. 析构函数：构造函数取资源，析构函数还资源
// ═══════════════════════════════════════════

#include <cstdio>

class FileHolder {
public:
    explicit FileHolder(const char* name)
        : handle(std::fopen(name, "r")) {      // 构造即取得资源
        if (!handle) std::cout << "打开失败" << std::endl;
    }
    ~FileHolder() {
        if (handle) std::fclose(handle);       // 析构即释放资源，避免泄漏
    }
private:
    std::FILE* handle;
};

int main() {
    {
        FileHolder f("data.txt");
    }                                          // 离开作用域，handle 自动关闭
    return 0;
}

// ═══════════════════════════════════════════
// 5. 组合对象：构造与析构的先后次序
// ═══════════════════════════════════════════

class Engine {
public:
    Engine() { std::cout << "Engine 构造" << std::endl; }
    ~Engine() { std::cout << "Engine 析构" << std::endl; }
};

class Car {
public:
    Car() { std::cout << "Car 构造" << std::endl; }    // 成员先构造，自身后构造
    ~Car() { std::cout << "Car 析构" << std::endl; }   // 自身先析构，成员后析构
private:
    Engine engine;                                     // 组合对象
};

int main() {
    Car car;   // 输出顺序：Engine 构造 → Car 构造 → Car 析构 → Engine 析构
    return 0;
}
