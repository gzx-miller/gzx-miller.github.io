运算符、表达式与类型转换

理解 C++ 各类运算符的优先级、结合律、求值顺序，以及整数提升和算术转换规则。

开场问题：下面这个判断想筛出「掩码位为 0」的情况，逻辑上没错，可它永远得不到你想要的结果：if (a & mask == 0)。同样的两个运算符、同样的操作数，为什么多加一对括号 if ((a & mask) == 0) 就对了？

先朴素做法：把式子照直觉写下来

写表达式时，多数人是照数学直觉直译的：加法先于乘法、先算括号，比较给出真假，&& 与 || 连着两个条件。这套直觉在小学算术范围内基本不出错，也解释了一个事实——C++ 的运算符确实有一套确定的优先级与结合律，表达式不是从左到右随便算的。

但直觉覆盖不到的地方恰恰是出错的地方。C++ 的运算符一共几十个，优先级表比四则运算长得多；& 既可能是「按位与」，也可能是「取地址」；<< 既可能是「位移」，也可能是「流插入」。当人凭感觉把这些符号连起来时，编译器却严格按优先级表解析，两边一错位，就出现开场那种「看起来对、结果不对」的表达式。

要解决它，得先把运算符分类理清，再谈优先级。

按用途分类：算术、关系、逻辑与位运算

把常用运算符按用途摊开：

  • 算术：+ - * / %。其中 / 对整数是向零取整，% 取余且只能作用于整数。
  • 关系：< <= > >= 与 == !=，结果是 bool。
  • 逻辑：! && ||，同样给出 bool，其中 && 与 || 具有短路性质。
  • 位运算：& | ^ ~ 与 << >>，直接操作二进制位，只对整数类型有效。

这里最容易混淆的是「按位」与「逻辑」两组的写法：& 与 &&、| 与 ||。它们做的事完全不同——a & b 逐位相与，a && b 先判断 a 的真假再决定要不要看 b。写条件判断时若手滑少打一个符号，程序可能照样能编译，却做了截然不同的事。

短路求值：逻辑运算的隐性顺序

朴素写法里，逻辑运算符常被当成「两个条件都算一遍再合起来」。但 && 与 || 的真正价值在于短路求值：

  • a && b：先算 a，若 a 为假，整个表达式已确定为假，b 根本不会求值。
  • a || b：先算 a，若 a 为真，整个表达式已确定为真，b 根本不会求值。

这既是优化，也是安全边界。它让「先判空、再解引用」成为一种可靠写法：if (p != nullptr && *p > 0)——只要前半段不成立，后半段对空指针的解引用就绝不会被执行。反过来也埋了一个坑：如果 b 带着副作用（比如自增），而你以为它总会执行，那么短路发生时副作用就被静默跳过了；if (a > b && ++x) 里 x 到底加没加，取决于 a > b 的真假。

优先级、结合律与「直接加括号」

回到开场的谜题。== 的优先级高于 &，所以编译器把 a & mask == 0 解析成了 a & (mask == 0)：先算出 mask == 0 这个布尔值，再拿它跟 a 按位与。这跟写代码的人心里想的 (a & mask) == 0 完全不是一回事。加一对括号，就恢复了本意。

这类错位的根源是：优先级表很长，但人的短期记忆装不下。== 与 &、<< 与 + -、?: 与赋值，这几组的相对顺序都反直觉。与其背表，不如把工程习惯定下来：只要一个表达式里混用了三个以上运算符，就主动加括号显式表达意图。括号的代价为零，读代码的人（包括三个月后的自己）却能一眼看懂。

整数提升、算术转换与显式转换

朴素做法常假定「运算结果就是参与运算的那个类型」。但两个不同类型的值放在一起运算时，C++ 会先做一组隐式转换，这叫通常算术转换。它分两步：

  • 整数提升：比 int 窄的整数类型（char、short、bool）先被提升为 int。所以 char c1 = 100, c2 = 200; 时，c1 + c2 是按 int 算的，结果是 300；若把它塞回 char 才会截断。
  • 类型对齐：若一方是有符号、另一方是无符号且宽度相同，有符号的一方会被转成无符号。这正是「-1 < 0u 为假」的由来。

隐式转换方便，却把意图藏了起来。C++ 的迭代是提供一组命名的显式转换，让「这里发生了转换」在代码里可见：static_cast（相关类型间的转换、去掉 const 以外的大多数场景）、const_cast（增删 const）、reinterpret_cast（重新解释位模式）、dynamic_cast（多态类型的安全向下转换）。日常最常用的是 static_cast：static_cast<double>(sum) / count 一眼就表明「这里要把整数转成浮点」，比 C 风格的 (double)sum 更容易被搜到、也更安全。

自增前后缀、求值顺序与未定义行为

先看自增。朴素理解是「i++ 和 ++i 都让 i 加 1」，差别只在返回值：i++ 返回加之前的旧值，++i 返回加之后的新值。这个理解在单独成句时没问题——i++; 与 ++i; 效果一样。差别只在「拿它当表达式的值」时才显现，比如 int a = i++; 与 int a = ++i; 得到的 a 不同，后者也更直接、少一次临时拷贝。

更严重的问题在求值顺序。多数运算符（包括 +）不规定两侧操作数的求值先后，由编译器自行安排。于是 i = i++; 这种写法里，「读 i 的旧值」和「给 i 加 1」两件事的先后没有保证；若它们在同一表达式里交错，标准将其定义为未定义行为——结果可以是任何值，程序也可能直接崩溃。int x = INT_MAX + 1; 则是另一种未定义行为：有符号整数溢出在 C++ 中是未定义的，不能指望它回绕成负数；要回绕语义就改用无符号类型。这类问题的共同点是「编译不一定报错、运行结果不可预期」，只能靠写法规避：一条语句里只修改一个变量一次。

看一遍优先级与陷阱的对照

把表达式当成一场「有规则的解析」

运算符与表达式，说到底是一场有规则的解析：编译器按优先级与结合律把符号串拆成树，再按类型规则插入隐式转换。人的直觉与这张规则表不总是一致，所以稳妥的做法是——混用运算符时主动加括号，逻辑运算善用短路特性，涉及不同类型时用 static_cast 把转换写明白，且永远不要在一条语句里重复修改同一个变量。把这些习惯固定下来，表达式就从「碰运气」变成了可预期的确定行为。

「优先级」决定相邻运算符谁先结合，「结合律」决定同优先级运算符从哪一侧开始；「短路求值」指逻辑运算在结果已定时跳过后续操作数的求值；「整数提升」把窄于 int 的类型抬到 int 再运算；「未定义行为」指标准未规定结果的情形，必须靠写法规避而非依赖。

// ═══════════════════════════════════════════
// 1. 算术、关系与位运算符
// ═══════════════════════════════════════════

#include <iostream>

int main() {
    int a = 10, b = 3;
    std::cout << a + b << std::endl;        // 结果：13
    std::cout << a / b << std::endl;        // 结果：3，整数除法向零取整
    std::cout << a % b << std::endl;        // 结果：1，取余只用于整数
    std::cout << (a > b) << std::endl;      // 结果：1，关系运算给出 bool

    int bits = 5;                           // 二进制 0101
    std::cout << (bits << 1) << std::endl;  // 结果：10，左移一位等于乘 2
    std::cout << (bits & 3) << std::endl;   // 结果：1，0101 & 0011 = 0001
    return 0;
}

// ═══════════════════════════════════════════
// 2. 逻辑运算符与短路求值
// ═══════════════════════════════════════════

int main() {
    int a = 10, b = 3, x = 0;
    if (a > b && ++x) { }                   // a > b 为真，右侧 ++x 被求值
    std::cout << x << std::endl;            // 结果：1，x 自增了

    x = 0;
    if (a < b && ++x) { }                   // a < b 为假，右侧被短路跳过
    std::cout << x << std::endl;            // 结果：0，x 未被修改
    return 0;
}

// ═══════════════════════════════════════════
// 3. 优先级与结合律
// ═══════════════════════════════════════════

int main() {
    int a = 12, mask = 0;
    bool wrong = (a & mask == 0);           // == 优先级高于 &，实际为 a & (mask == 0)
    bool right = ((a & mask) == 0);         // 结果：true，括号恢复了本意
    int c = 1 + 2 * 3;                      // 结果：7，乘法先于加法
    int d = (1 + 2) * 3;                    // 结果：9，括号改变结合顺序
    int e = a > 5 ? a : 5;                  // 结果：12，条件运算符
    return 0;
}

// ═══════════════════════════════════════════
// 4. 整数提升、算术转换与显式转换
// ═══════════════════════════════════════════

int main() {
    char c1 = 100, c2 = 200;
    int sum = c1 + c2;                      // 结果：300，char 先提升为 int
    // char bad = c1 + c2;                  // 塞回 char 会截断，结果不可预期

    int total = 350, count = 4;
    double avg = static_cast<double>(total) / count;  // 结果：87.5，显式转 double
    int again = total / count;              // 结果：87，整数除法丢小数

    unsigned int u = 10;
    if (-1 < u) { }                         // 结果：false，-1 被转成无符号大数
    return 0;
}

// ═══════════════════════════════════════════
// 5. 自增前后缀、求值顺序与未定义行为
// ═══════════════════════════════════════════

#include <climits>

int main() {
    int i = 5;
    int pre  = ++i;                         // 结果：6，先自增再取值
    int post = i++;                         // 结果：6，先取值再自增，i 变为 7

    // int bad = i++ + ++i;                 // 未定义行为：同一变量被多次修改
    // int overflow = INT_MAX + 1;          // 未定义行为：有符号整数溢出

    unsigned int wrap = 0u - 1u;            // 结果：4294967295，无符号按模回绕
    return 0;
}
