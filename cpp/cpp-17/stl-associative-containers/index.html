STL 容器（二）：map、set、unordered_map、unordered_set

掌握有序关联容器（map/set）和无序关联容器（unordered_map/unordered_set）的特性与用法。

开场问题：你只想查一下字典里有没有 David 的年龄，顺手写了一句 ages["David"]。程序没报错，可当你把整张表打印出来时，凭空多了一行 David: 0——你只是「读」了一下，它怎么就悄悄「写」进去一条了？

关键字检索与判存

你要的不是「第 5 个元素」，而是「叫 Alice 的那个人今年几岁」——也就是按一个关键字去定位数据，还得能快速判断某个键在不在。最笨的老办法是拿两个平行数组，一个存名字、一个存年龄，按下标对齐。它能跑，但成本都落在你身上：

  • 按键查找只能从头到尾逐个比对，是 O(n)；数据一大就慢。
  • 想删掉一个人，得在两个数组里各删一次、还得保证下标不再错位，稍不留神两边就对不上了。
  • 同一个键很容易被插进去两次，靠人工保证「键唯一」几乎做不到。
  • 算法本身也不知道「键」是有意义的标识，它只会傻傻地按位置找。

所以要问的是：能不能有一个容器，直接按「键」来存和取，让「查、插、删」都不必逐个扫描？

键值对与关联容器

最省事的答案是 std::map<std::string, int>：你存的是键值对，用 ages["Alice"] = 25 直接写、用 ages["Alice"] 直接读，容器内部替你维护「键唯一」这件事。

这个方案做对了一件关键的事：查找、插入、删除都是 O(log n)，而且它把键按大小排好序，遍历时天然是升序。它底层是一棵自平衡的红黑树，这棵树既保证了查找快，也保证了「随时能按顺序取出所有键」。

下标读取触发插入

  • operator[] 在键不存在时会插入一个值初始化的元素（int 是 0、std::string 是空串），于是「只是想读一下」变成了「偷偷加了一条」。
  • 每次操作都要走一遍树高，O(log n) 虽然不慢，但在海量数据、纯查找为主的场景里仍不是最快。
  • 它强制维护有序，可你未必需要这个顺序——这份「排序」是要花代价换来的。
  • 自定义的类当键时直接编译不过：容器不知道拿什么标准去比大小。

只读访问安全接口

先补最贴近日常、也最容易踩的一步：「读」不要用 operator[]。想读一个键，用 at()——键不存在时它抛 std::out_of_range，而不是悄悄插入；或者用 find()——它返回迭代器，没找到就是 end()，你显式判断一下再用 it->second 取值。把「读」和「写」在语法上分开，那个凭空出现的 David: 0 就再也不会发生了。

接着补第二个需求：我只要查得快，不在乎顺序。于是换成 std::unordered_map<std::string, int>，底层是哈希表，平均查找、插入、删除都是 O(1)。但它不是白拿的：遍历顺序未指定（取决于哈希和桶布局），而且冲突严重时最坏会退化到 O(n)。所以用无序容器，第一件事是给它一个高质量的哈希函数，并盯住负载因子，必要时用 rehash(n) 或 reserve(n) 主动留出空间。

再补「只要键、不需要值」的场景：用 set（有序）或 unordered_set（无序）存唯一键集合。insert 插入、find 查找，未找到返回 end()。一个 std::set<int> nums = {5, 2, 8, 1, 2}; 遍历出来就是 1 2 5 8——自动排序、自动去重，重复的 2 被吃掉了。

如果键本来就允许重复呢？那就补上 multimap / multiset：它们允许同一个键出现多次，用 count(key) 数出一共几条。

补到这里，一个差别就浮出来了：有序容器能做范围查询，哈希表做不了。「找出所有年龄在 20 到 30 之间的人」这种需求，要靠 lower_bound / upper_bound 拿到一个区间，再用 equal_range 取某个键的整段范围。既然只有红黑树保证了键有序，那么一旦你需要范围查询，就必须回到 map/set——这正是「要不要有序」的真正分水岭，不只是遍历好不好看。

再补如何让容器认得你自己的类型。把自定义类型当键时，两种容器的要求不同：

  1. 当 map/set 的键：要提供「小于」运算符，或传入一个自定义比较器（它必须构成严格弱序）。
  2. 当 unordered_ 的键：要提供哈希函数，以及相等比较函数——哈希说了「放哪个桶」，相等说了「桶里哪个才是它」。

补完自定义键，还有一个绕不开的现实：容器里的键是 const 的，不能就地改（改了它会破坏树序或哈希，容器再也找不到它）。C++17 为此引入了 node handles：用 extract(key) 把节点从容器里摘下来，此时你可以改它的键，再 insert 回去。摘下来的节点还能在不重新分配内存的前提下，直接搬到另一个兼容的关联容器里，避免了一次次拷贝元素。

查找操作与遍历次序

有序性与哈希表取舍

关联容器让你按「键」而不是按「位置」存取。map/set 用红黑树换来有序 + O(log n)，unordered_map/unordered_set 用哈希表换来平均 O(1)、但顺序不定。要不要有序遍历、要不要范围查询，是这两条路的分界。至于日常代码，只要记住一件事：用 operator[] 之前先问自己，我到底是在读，还是在写。

「负载因子」指无序容器中 size() / bucket_count() 的比值，衡量桶被填满的程度。它越高，哈希冲突越多，查找越可能从平均 O(1) 退化到最坏 O(n)。rehash(n) 强制把桶数调整到至少 n，reserve(n) 则提前备好容纳 n 个元素的空间、避免反复重哈希。边界：调整桶数会让已存在的迭代器失效；而无论负载因子多低，无序容器的遍历顺序都是未指定的，需要有序遍历或 lower_bound/upper_bound 范围查询时，必须改用 map/set。

关键代码

C++
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> ages;
    ages["Alice"] = 25;
    ages["Bob"] = 30;

    for (const auto& [name, age] : ages) {
        std::cout << name << ": " << age << std::endl;
    }

    return 0;
}
