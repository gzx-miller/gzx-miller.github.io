STL 迭代器与算法：sort、find、count、transform

理解 STL 迭代器概念和类别，掌握常用算法（排序、查找、变换、累加）的用法与性能。

开场问题：你想把 vector 里所有的 0 删掉，翻手册时看到一个名字正合适的函数，于是写下 std::remove(v.begin(), v.end(), 0);。运行后一检查，v.size() 一点没变，那个 0 还稳稳躺在里面——一个名字就叫「删除」的函数，为什么什么都没删掉？

手写遍历与泛型算法

你要对一串元素做最普通的事：找出某个值、统计它出现几次、求和、排序、把每个元素翻倍。最笨的办法是每种容器、每种类型都手写一遍循环。它能跑，但代价都压在你身上：

  • 同一套「查找」逻辑，在 vector 上写一遍、在数组上再写一遍、在链表上还得写一遍，重复得毫无意义。
  • 容器种类 × 操作种类的组合会爆炸式增长，每一份循环都是一次独立的手工维护。
  • 手写循环最容易在边界上出错：少走一个、多走一个、越界一个，都是难以察觉的 bug。
  • 循环体里塞满业务逻辑，一眼看不出「这段代码到底在干什么」。

所以要问的是：能不能把「算法」从「数据存在哪里」里剥出来，让同一份查找、排序、变换，对任何容器都成立？

统一算法与迭代器

答案是 STL 的算法加上迭代器：std::find(nums.begin(), nums.end(), 8)、std::count(...)、std::sort(...)——你不再写循环，而是把「一段范围」交给算法。

这个方案做对了一件最根本的事：算法把数据看成一段由迭代器标出的区间，而不是某个具体容器。迭代器可以理解成「一个指向元素的位置，而且会自己往前走」。容器负责给出 begin() 和 end()，算法只管在这两点之间干活。容器和算法就此解耦——这就是泛型编程的骨架。

这里要先立下一条全区通用的约定：范围统一写成 [first, last)，前闭后开——last 指向「最后一个元素的下一个位置」，而不是最后一个元素本身。

迭代器等级约束

  • 不同算法的「门槛」不一样：std::sort 要求随机访问迭代器，把它用在 list 上直接编译失败，而不是运行时报错，让人一时摸不着头脑。
  • std::accumulate 并不在 <algorithm> 里，而在 <numeric> 里，写漏头文件就找不到它。
  • 算法不检查迭代器是否有效、不检查范围是否合理，你传进去一个越界或颠倒的区间，得到的是未定义行为，不是一句友好的报错。
  • std::remove 名字叫删除，却根本不动容器的大小——就像开场那样，你以为什么都没发生。
  • 想把变换的结果放进另一个容器，如果那个容器是空的、还按老办法直接写进去，立刻就写越界。

半开区间边界约定

先把「半开区间」这个约定的好处想清楚，它是后面一切的地基。last 取「最后一个元素的下一个位置」，于是：last - first 恰好就是元素个数；空的区间自然表示成 first == last；循环写成 for (it = first; it != last; ++it) 正好一遍不多一遍不少。用等号做终止条件，而不是小于等于，边界就再也不用手工 +1/-1 去凑。

接着补上「迭代器分等级」这件事——它解释了为什么同一个算法有时能用、有时不能用。迭代器的能力从弱到强有五级：

  1. 输入迭代器：只读、只能向前走一次。
  2. 输出迭代器：只写、只能向前走一次。
  3. 前向迭代器：可读可写、只能单向走，但能反复遍历。
  4. 双向迭代器：可读可写、能前进也能后退（list、map）。
  5. 随机访问迭代器：可读可写、能任意跳转、能做下标和减法（vector、deque）。

算法按自己需要的最低等级来分组：只读算法（find、count、accumulate、all_of/any_of/none_of）只要输入迭代器；写算法（copy、transform、fill、replace）要前向迭代器；而排序算法要随机访问迭代器。所以 std::sort 用在 list 上根本编译不过——这不是 bug，是设计：链表给不出随机访问，就得改用链表自带的 list::sort。

现在可以正面解开开场那个谜了：std::remove 是「重排」，不是「删除」。它把不匹配的元素依次向前挪、盖住要删的位置，最后返回一个新的逻辑终点，指向「保留下来的那段」的末尾。从新终点到原来的 end() 之间的内容，值已经不确定了，但容器的 size() 没变——算法只认迭代器，它压根不知道容器有多长，也就无权把容器变小。

要真正删掉，必须让容器自己出手：用容器的 erase 把那截尾巴抹掉。这就拼成了 remove-erase 惯用法：

v.erase(std::remove(v.begin(), v.end(), val), v.end());——先把要留的挪到前面、拿到新终点，再由 erase 从新终点一直删到真正的末尾。记住：remove 之后、erase 之前，那段尾巴里的元素是「有效但值未指定」的，别去读它。

再补「结果该往哪儿放」。当目标容器还没准备好大小时，用插入迭代器适配器：back_inserter(c) 让每次写入都变成一次 push_back，front_inserter(c) 变成 push_front，inserter(c, it) 则插到指定位置。于是可以放心地把算法结果直接「灌」进空容器，不用预分配、也就不会越界。另外像 unique 这种去重，只合并相邻的重复元素，所以要先排序再去重，否则隔开的重复项它根本看不见。

最后是两个稍新的补充。C++20 的 ranges 让你直接对容器调用 ranges::sort(vec)，不必再写 begin()/end()，还能挂上「投影」只按元素里的某个字段比较，甚至用管道把多个操作串起来、惰性求值。C++17 还给了并行版本：在 <execution> 里指定执行策略 execution::par，就能让 sort 之类的算法吃满多核，例如 std::sort(std::execution::par, v.begin(), v.end())。

算法与容器解耦

STL 算法与容器之间，靠迭代器这条「桥」解耦：算法只认一段 [first, last) 区间，并对区间的迭代器等级有硬要求，这正是同一个算法能配 vector 却配不了 list 的原因。日常最该记牢的两件事是：范围一律前闭后开；名字叫 remove 的它不删，要配 erase 才真的删。

「remove-erase 惯用法」指用两步完成「删除满足条件的元素」：std::remove 只做重排——把要保留的元素前移、返回新的逻辑终点，并不改变容器大小；随后必须用容器的成员 erase 把从新终点到末尾的那截真正抹掉，写作 v.erase(std::remove(v.begin(), v.end(), val), v.end())。边界：算法无法改变容器大小（它只见迭代器、不见容器），所以删除永远得由容器自己完成；而 remove 之后、erase 之前，区间 [新终点, end) 内的元素值已未指定，读取它们是未定义行为。

C++
#include <iostream>
#include <vector>
#include <algorithm>

int main() {
    std::vector<int> nums = {5, 2, 8, 1, 9, 3};

    // 查找
    auto it = std::find(nums.begin(), nums.end(), 8);

    // 排序
    std::sort(nums.begin(), nums.end());

    // 累加
    int sum = std::accumulate(nums.begin(), nums.end(), 0);

    return 0;
}
