控制流：条件分支与循环

掌握条件判断、循环结构和跳转语句，以及 C++11 引入的范围 for 循环。

开场问题：成绩判定想输出「优秀 / 及格 / 不及格」，可 if (score >= 90) … if (score >= 60) … else … 这样写下去，一个 95 分的成绩会同时落进「优秀」和「及格」两个分支。问题不在条件，而在这几个 if 之间的连接方式——它们到底该怎么串？

先朴素做法：一个条件接一个条件地判

分支最朴素的形式就是「条件为真就做一件事」：if (score >= 90) { cout << "优秀"; }。它做对了什么？把「判断」和「动作」分开了，条件为真就执行花括号里的语句，为假就跳过——if 的本质是一个受布尔条件守卫的语句块。

不足在于「多个条件」时容易写成相互独立的 if。若把上面那段写成两个并列的 if，95 分两个条件都为真，于是「优秀」「及格」都会被打印。真正的意图是互斥的多路选择：落进某一档就不再往下判。这就引出了 else if——它把后面的判断挂在前面条件为假的分支上，形成一条「只会命中一次」的链。

把链写全就是 if / else if / else：条件从上到下依次求值，第一个为真的分支胜出，其后全部跳过；若都不满足，则落到 else。这块「守卫 + 跳链」的结构，是所有分支语法的共同骨架。

switch：把等值判断收敛成一张跳转表

当判断是「多个离散常量之间的等值比较」时，用一长串 else if (x == A) … 会显得冗余——每个条件都在重复写 x ==。朴素做法于是转向 switch：把表达式算一次，再和各个 case 标签比较。它做对了什么？语义上把「对同一个值做多路等值匹配」表达得非常集中，编译器也常能把它优化成一张跳转表。

但 switch 有一个反直觉的默认行为：case 会「穿透」。当某个 case 匹配成功后，程序从这个标签往下依次执行，直到遇见 break 或到达 switch 末尾为止——它并不会自动停在下一个 case 前。所以朴素写法里最常见的 bug，就是忘了写 break，导致多个分支被连续执行。

迭代的方向不是「记住每个 case 都要 break」，而是分清意图：要独立的就补 break；要故意合并的（多个 case 共享同一段逻辑）就让几个 case 空着、叠在一起。后者是合法且常见的写法，例如把 case 1: 和 case 2: 放在一起、共用后面一段代码。关键是让「穿透」成为有意为之，而不是遗漏。另有一条硬约束：case 标签必须是编译期的整型常量表达式，不能是变量。

循环三兄弟：while、do-while 与 for

循环的朴素动机很直接：把一件重复的事写一遍，让机器替我们重复执行。三种循环在结构上各有分工：

  • while (cond) { ... }：先判后做，条件可能一次都不成立，循环体一次都不执行。
  • do { ... } while (cond);：先做后判，循环体至少执行一次，适合「先试一次再决定要不要继续」的场景，如菜单输入。
  • for (init; cond; step) { ... }：把「初始化、条件、步进」三件事集中写在头部的括号里，适合已知迭代次数或需要显式计数器的场景。

三者可以互相改写，但表达力并不等价。选择的标准是「循环的控制信息放在哪里最自然」：计数器驱动的用 for，状态驱动的用 while，至少执行一次的用 do-while。把 for 的三个部分写清楚，本身就是一种文档，读代码的人一眼就能看出循环的起点、终点与步长。

范围 for 与 break / continue

手动写下标遍历容器时，容易在边界上出错：i <= v.size() 就多了最后一次越界访问。C++11 的范围 for 把「逐个取出元素」这件事交给语法：for (auto x : container)，无需自己维护下标与终止条件。

但范围 for 里「取出的东西是什么」由写法决定，这决定了它的用途：

  • for (auto x : container)：每次拷贝一个元素，修改 x 不影响容器。读值可以，改值不行。
  • for (const auto& x : container)：绑定到元素的只读引用，避免拷贝，大对象时性能更好，是只读遍历的推荐写法。
  • for (auto& x : container)：绑定到元素的可写引用，改 x 即改容器中的元素。

与循环体配合的两个流程控制是 break 与 continue：break 立即跳出整个循环或 switch；continue 只跳过本轮剩余语句，回到循环的条件判断处。需要提醒的是：范围 for 遍历时不要同时增删容器元素，容器结构一旦改变，迭代器就可能失效，行为随之变得不可预期。

C++17 的域内初始化：把变量关进它该在的作用域

朴素写法常为了一个「只在判断里用一次」的变量，在函数体开头先声明：auto it = find(...); if (it != v.end()) { ... }。它做对了什么？变量能用在条件里。不足是 it 的作用域泄漏到了整个函数——后面若同名复用或误用，编译器不会拦你。

C++17 允许把初始化直接写进条件：if (auto it = find(...); it != v.end()) { ... }，switch 也支持同样的写法。分号前是初始化语句，分号后是条件。这样 it 的作用域被限制在 if / else 的两条分支之内，出了这段就不可见，既少一次变量提前声明，也避免名字污染。

它体现的是一条贯穿 C++ 的原则：尽量缩小变量可见范围，让名字只在真正需要它的地方存在。

看一遍分支与循环的写法对照

把控制流当成一条「会分岔的路」

条件分支与循环，本质上是给程序的执行路径造分岔与回路：if / else if / else 负责互斥的多路选择，switch 把等值匹配收敛成跳转表（并提醒你 break 的穿透语义），三种循环按「判与做的先后」各司其职，范围 for 把容器遍历简化到只剩元素本身，C++17 的域内初始化则把临时变量的作用域收进分支。break 与 continue 再给出提前退出与跳过本轮的两个出口。把这些结构按「意图」而不是「惯性」来选，控制流就会既短又清晰。

「穿透（fallthrough）」指 switch 中某 case 匹配后未遇 break 而继续执行其后各 case 的行为，可刻意利用也可因遗漏成错；「迭代语句」是 while、do-while、for 与范围 for 的总称；「迭代器失效」指遍历中增删容器元素导致迭代器不再可用。

关键代码

C++
// ═══════════════════════════════════════════
// 1. if / else if / else 互斥多路选择
// ═══════════════════════════════════════════

#include <iostream>

int main() {
    int score = 95;
    if (score >= 90) {                      // 从上到下，第一个为真的分支胜出
        std::cout << "优秀";
    } else if (score >= 60) {               // 仅在前一条件为假时才判断
        std::cout << "及格";
    } else {
        std::cout << "不及格";
    }                                       // 结果：优秀
    return 0;
}

// ═══════════════════════════════════════════
// 2. switch 与 case 穿透
// ═══════════════════════════════════════════

int main() {
    int day = 3;
    switch (day) {                          // 只对整型常量做等值匹配
        case 1: std::cout << "周一"; break; // 结果：打印后跳出 switch
        case 2: std::cout << "周二"; break;
        case 3: std::cout << "周三"; break; // 结果：命中并打印「周三」
        default: std::cout << "其他"; break;
    }

    int level = 1;
    switch (level) {
        case 1:                             // 故意不写 break：1 与 2 共用逻辑
        case 2: std::cout << "低段位"; break;  // 结果：1 也打印「低段位」
        default: break;
    }
    return 0;
}

// ═══════════════════════════════════════════
// 3. while 与 do-while
// ═══════════════════════════════════════════

int main() {
    int i = 0;
    while (i < 5) {                         // 先判后做，可能一次都不执行
        std::cout << i << " ";              // 结果：0 1 2 3 4
        ++i;
    }

    int j = 10;
    do {                                    // 先做后判，循环体至少执行一次
        std::cout << j << " ";              // 结果：10
        ++j;
    } while (j < 5);                        // 条件为假，只跑了一轮
    return 0;
}

// ═══════════════════════════════════════════
// 4. for 循环与 break / continue
// ═══════════════════════════════════════════

int main() {
    for (int i = 0; i < 5; ++i) {           // 初始化、条件、步进集中在头部
        if (i == 2) continue;               // 跳过本轮剩余语句
        if (i == 4) break;                  // 立即跳出整个循环
        std::cout << i << " ";              // 结果：0 1 3
    }

    int n = 0, sum = 0;
    while (n < 100) {                       // 条件驱动
        sum += n;
        ++n;
    }                                       // 结果：sum 为 0..99 之和 4950
    return 0;
}

// ═══════════════════════════════════════════
// 5. 范围 for 与引用修改
// ═══════════════════════════════════════════

#include <vector>

int main() {
    std::vector<int> nums{1, 2, 3, 4, 5};

    for (int num : nums) {                  // 按值拷贝，修改不影响容器
        num *= 10;                          // 结果：nums 仍为 1 2 3 4 5
    }

    for (const auto& num : nums) {          // 只读引用，避免拷贝
        std::cout << num << " ";            // 结果：1 2 3 4 5
    }

    for (auto& num : nums) {                // 可写引用，改的是容器里的元素
        num *= 2;                           // 结果：nums 变为 2 4 6 8 10
    }
    return 0;
}

// ═══════════════════════════════════════════
// 6. C++17 在 if / switch 中初始化限制作用域
// ═══════════════════════════════════════════

#include <map>
#include <string>

int main() {
    std::map<std::string, int> stock{{"apple", 3}};
    if (auto it = stock.find("apple"); it != stock.end()) {  // 初始化写在条件里
        std::cout << it->second;            // 结果：3，it 作用域限于此 if
    }                                       // 出 if 后 it 不再可见
    return 0;
}
