控制流：if/switch/while/for/范围 for

掌握条件判断、循环结构和跳转语句，以及 C++11 引入的范围 for 循环。

开场问题：你想删掉数组里所有偶数，用 C++11 的范围 for 写得很顺手：for (int x : nums) { if (x % 2 == 0) nums.erase(...); }，结果程序要么直接崩、要么漏删一部分——明明只是「边遍历边筛选」，为什么这个看起来更安全的新语法反而出了事？

非结构化跳转

程序不能只会从上往下执行，它得能「按条件走不同的路」和「重复做同一件事」。最原始的控制靠 goto 加标签，但用多了代码会变成一张跳来跳去的网，读的人根本追不上执行流从哪来、到哪去。于是语言提供了结构化的分支与循环：if/else 二选一、switch 多路选一、while 与 for 重复执行。

可结构化只解决了「跳转清楚」，没解决「边界正确」。手工控制下标时，你要自己承担这些成本：for (int i = 0; i <= n; i++) 这种差一错误你每写一次都要数一遍；容器大小随时可能变，你手写的大小边界可能在上一次删除之后就过期了；switch 忘了 break 会「穿透」到下一个分支，执行你根本没打算执行的代码。

所以问题落到：怎么让「按条件重复」这件事，既不用手数边界，又不容易在容器变动时踩空？

手写分支循环

最朴素的做法：用 if/else 做分支、用 switch 做多路、用 for (int i = 0; i < size; i++) 或 while 做循环，全部手动控制。

这个方案做对了一件事：它把控制流显式写了出来，执行路径一眼可读，而且它其实是所有循环的基础形态——不管上层语法多花哨，最后都会落回到这套「判断条件、执行、更新」的骨架。基础形态必须先站稳。

问题在于，每一处边界都由你亲手维护，漏掉任何一处都不会报错，只会让程序在某个特定输入下静默出错。

贯穿执行越界

  • switch (day) 里 case 1: 后面忘了 break，就会连同 case 2: 一起执行——你以为只打印「周一」，实际打印出一串。
  • for (int i = 0; i <= nums.size(); i++) 手滑写成 <=，最后一次循环访问的下标已经越界，读到的是不存在的元素。
  • 迭代器版本 for (auto it = v.begin(); it != v.end(); ++it) { if (bad(*it)) v.erase(it); }，在 erase 之后 it 立刻失效，下一次 ++it 就是在操作一个悬空的迭代器，直接崩。
  • for (;;) 忘了写出跳出口，程序永远出不来，只能强杀。
  • 遍历时用 auto x 取值，每个元素都被复制一份，容器里装大对象时代价明显——而且你改 x 改的是副本，容器里的元素纹丝不动。

条件分支完善

不推翻「结构化控制流」，而是把常见的边界判断一步步交给语法去兜底。先补分支这一层，因为它最容易出现「结构性错误」而不是「算错值」。

if/else if/else 用于条件分支；switch 用于「基于整型常量多路选一」。留意 switch 的两个硬约束：case 标签必须是整型常量表达式，字符串和浮点数都不行；默认每个 case 末尾都要 break。穿透本身不是错误，只是一种容易被遗忘的行为——如果你确实想故意穿透，C++17 提供了 [[fallthrough]]，写出来告诉编译器这是你有意为之。

补完分支，接着补循环形态的选择：for 适合已知迭代次数，while 适合条件驱动（可能一次都不执行），do-while 保证至少执行一次，范围 for 用于遍历容器。按「是否预知次数 / 是否至少执行一次」来选，很多边界问题自然就消失了。

这一节真正的新东西是第三层——C++11 的范围 for。写法 for (auto& x : container) 是一层语法糖：它被编译器展开成「用 begin() 拿起点、用 end() 拿终点、每次 ++ 前进」的迭代器循环。它替你省掉了下标和终点条件，让差一错误无从发生，但语义并没有变——它仍然依赖容器的 begin() / end()。

正因为只是语法糖，取值范围方式的差别就直接决定了行为：const auto& x 是只读引用、不复制，应作为默认选择；auto& x 是可修改的引用；auto x 会复制每个元素。而最重要的一条边界是——遍历过程中不能增删容器元素。因为 erase 会让后面的迭代器失效，范围 for 手里那个「当前位置」就悬空了，这正是开场崩溃的原因。要在遍历中改变大小，就得退回传统 for 或 while，并且在每次修改后重新取回迭代器，比如 it = v.erase(it);。

最后收一个作用域的尾：C++17 起，if 和 switch 允许在条件位置初始化变量，写成 if (auto it = m.find(k); it != m.end()) {...}，it 只在 if 内部存活，用完即弃，也就减少了和外面重名的机会。

范围 for 最该记住的一条：它只是迭代器循环的语法糖，帮你免掉了手写下标，但没有替你处理「遍历中容器被修改」这件事。凡是循环体里可能 erase / push_back，就应该改用传统循环并手动管理迭代器。

循环分支写法对照

结构化控制流

结构化控制流把 goto 的乱跳换成了清晰的分支与循环；选 if 还是 switch、for 还是 while 看场景。范围 for 让边界不必再手数，但它是语法糖不是护身符——遍历过程中容器被改，那条线依然要你自己守。

「范围 for」是 C++11 的语法糖，for (auto& x : c) 会展开为基于 c.begin() 与 c.end() 的迭代器遍历，要求容器提供这对接口（内置数组也可用）。取值方式决定语义：const auto& 只读且不复制（推荐默认）、auto& 可改原元素、auto 复制元素。例外：遍历中增删元素会使迭代器失效，此时必须改用传统循环并重新获取迭代器。

关键代码

C++
#include <iostream>
#include <vector>

int main() {
    int score = 85;
    if (score >= 90) {
        std::cout << "优秀";
    } else if (score >= 60) {
        std::cout << "及格";
    }

    std::vector<int> nums = {1, 2, 3, 4, 5};
    for (int num : nums) {
        std::cout << num << " ";
    }

    return 0;
}
