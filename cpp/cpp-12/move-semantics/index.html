移动语义与右值引用

理解左值与右值、右值引用与 std::move，以及移动构造和移动赋值带来的性能提升。

开场问题：把一个装着上万条数据的 std::vector 从函数返回出来，深拷贝一步步把每条数据都复制到新对象，再立刻把源对象销毁——源内存刚复制完就没人要了。既然源对象马上就要消失，这次复制凭什么还要发生？

从一次无谓的深拷贝说起

上一章的深拷贝解决了「两个对象共享一块内存」的问题，却也带来了新代价。复盘一次按值返回大对象的全过程：如果每一步都老老实实深拷贝，就得为新对象再分配同样大的内存、逐条复制，然后立刻把源对象销毁，那块源内存刚复制完就被回收。

这次拷贝做对了什么？它保证了新对象拥有独立资源。不足在哪？源对象马上就要消失，它的资源本可以直接交出去，却被完整复制了一遍，白白付出时间与内存。迭代的方向由此清晰：与其复制，不如搬走——把资源的所有权从源对象转移到目标对象。

左值与右值：为什么需要区分

想「搬走」，前提是能判断一个表达式所代表的资源是否还有人会用。C++ 用值类别来回答这个问题：

  • 左值（lvalue）：有名字、有确定地址、还会被继续使用的表达式，如变量 a。它的资源不能随便搬走，因为后面还指望它。
  • 右值（rvalue）：临时结果、没有名字、表达式结束后就消失的表达式，如 2 + 3、函数返回的临时对象。它的资源已经没人再要，可以放心搬走。

朴素的拷贝语义把二者一视同仁，都得复制。真正缺少的是一条规则：对「马上要消失的源对象」，允许把资源偷过来。这就是移动语义要补上的缺口，而区分左右值正是它的判断依据。

右值引用与 std::move

为了能专门给右值写重载，C++11 引入了一种新类型——右值引用，写作 T&&。它只能绑定到右值（临时对象），与绑定左值的 T& 形成两组可区分的重载：f(T&) 走拷贝路线，f(T&&) 走移动路线。

但现实里经常是「手里有个左值变量，明知它之后不用了，却仍是个有名字的左值」，无法直接匹配 T&&。为此有了 std::move：它并不移动任何东西，只是把左值转换成一个右值引用，好让它匹配到移动重载——std::string t = std::move(s); 里真正的搬运由移动构造函数完成。

有一处必须记住：被移动后的对象仍是一个合法对象，但内容处于「有效但不确定」的状态，最稳妥的处理是随即给它赋新值、或不再使用，不能假设它还留着原值。

移动构造与移动赋值

移动版的拷贝控制函数与拷贝版一一对应，但参数换成右值引用，做的事从「复制资源」变成「接管资源」：

  • 移动构造函数：Vec(Vec&& other)，把 other 的指针直接接过来，再把 other 的指针置空，让它安全地脱离资源。
  • 移动赋值运算符：Vec& operator=(Vec&& other)，比移动构造多两步——先释放自己原有的资源，同样做自赋值检查。

关键在于源对象必须被置为可析构的安全状态（通常把裸指针设为 nullptr、长度归零）。否则源对象析构时会去 delete 那块已经被交出去的内存，又变成重复释放。移动的实质是一次指针交换，摊还成本几乎是常数，这也是它比深拷贝快得多的原因。

noexcept、返回值优化与完美转发

三件事都与「移动能否被采纳」有关。

noexcept：移动构造与移动赋值应尽量标为 noexcept，明确承诺不抛异常。std::vector 扩容时要搬走旧元素，若移动可能抛异常，它为了强异常安全会退而选择拷贝；标上 noexcept，才会放心走移动，性能差异相当可观。

返回值优化（RVO/NRVO）：函数按值返回局部对象时，编译器往往直接在调用方位置构造该对象，连一次拷贝或移动都省掉，这叫返回值优化（RVO，含具名的 NRVO）。因此别为了「减少拷贝」而提前 std::move(局部对象) 再返回，那样反而会阻碍这项优化。

完美转发：把接收到的参数原封不动地转交给下一层函数，左值仍是左值、右值仍是右值。它靠模板中的 Args&&... 配合 std::forward<Args>(args)... 完成，是 std::make_unique 这类工厂函数「不额外拷贝就能构造出目标对象」的动机。

从「都会复制」到「能搬则搬」

移动语义并没有推翻拷贝控制，而是在它旁边补上了一条更聪明的分支：拷贝版照顾「源对象还要继续用」，移动版照顾「源对象马上要消失」。判断走哪条分支的依据不是代码写在哪，而是实参是左值还是右值；std::move 只负责把这个判断结果调整成「可以搬」，真正的搬运仍由移动构造函数落实。至此，一条资源从申请、复制到转移的完整路径才算了然。

「左值 / 右值」按表达式是否还有名字与地址、是否会被继续使用来区分，右值的资源可以安全搬走；「右值引用」写作 T&&，只能绑定右值，用于为移动语义提供可区分的重载；「移动构造 / 移动赋值」以右值引用为参数，接管而非复制源对象的资源，并把源对象置为可安全析构的状态；「完美转发」指把实参的左/右值属性原样传递给下一层函数。

C++
// ═══════════════════════════════════════════
// 1. 左值与右值：如何区分
// ═══════════════════════════════════════════

#include <iostream>

int main() {
    int a = 1;
    int& lref = a;                         // 左值引用绑定有名字的变量 a
    int&& rref = 2 + 3;                    // 右值引用绑定临时结果 5，并延长其生命期
    std::cout << lref << " " << rref << std::endl;   // 输出：1 5
    return 0;
}

// ═══════════════════════════════════════════
// 2. 右值引用与 std::move
// ═══════════════════════════════════════════

#include <string>
#include <utility>

int main() {
    std::string s = "hello";
    std::string t = std::move(s);          // std::move 把左值转成右值引用
    std::cout << t << std::endl;           // 输出：hello
    std::cout << s.empty() << std::endl;   // 输出：1，s 被搬空但仍是合法对象
    return 0;
}

// ═══════════════════════════════════════════
// 3. 移动构造与移动赋值：接管资源而非复制
// ═══════════════════════════════════════════

#include <cstddef>
#include <utility>

class Vec {
public:
    explicit Vec(std::size_t n) : data(new int[n]), size(n) {}
    ~Vec() { delete[] data; }
    Vec(Vec&& other) noexcept : data(other.data), size(other.size) {
        other.data = nullptr;              // 源对象交出指针并置空
        other.size = 0;
    }
    Vec& operator=(Vec&& other) noexcept {
        if (this != &other) {
            delete[] data;                 // 释放自身旧资源
            data = other.data;             // 接管源对象资源
            size = other.size;
            other.data = nullptr;
            other.size = 0;
        }
        return *this;
    }
private:
    int* data;
    std::size_t size;
};

int main() {
    Vec a(5);
    Vec b(std::move(a));                   // 移动构造：只搬指针，不复制 5 个 int
    return 0;                              // 两者析构各自释放自己那份，无重复释放
}

// ═══════════════════════════════════════════
// 4. noexcept：让容器敢用移动
// ═══════════════════════════════════════════

#include <type_traits>

class SafeVec {
public:
    SafeVec() = default;
    SafeVec(SafeVec&&) noexcept {}         // 移动构造标为 noexcept
    SafeVec(const SafeVec&) {}
};

static_assert(std::is_nothrow_move_constructible<SafeVec>::value,
              "移动构造应为 noexcept，否则 vector 扩容时会改用拷贝");   // 编译期校验

int main() {
    return 0;
}

// ═══════════════════════════════════════════
// 5. 返回值优化与完美转发
// ═══════════════════════════════════════════

#include <iostream>
#include <string>
#include <utility>

Vec makeVec(std::size_t n) {
    return Vec(n);                         // RVO：直接在调用方位置构造，省掉拷贝/移动
}

template <typename T, typename... Args>
T* make(Args&&... args) {
    return new T(std::forward<Args>(args)...);   // 完美转发：保持实参的左/右值属性
}

int main() {
    Vec v = makeVec(3);
    std::string* sp = make<std::string>("hi");   // 转发到 std::string 的构造函数
    std::cout << *sp << std::endl;               // 输出：hi
    delete sp;
    return 0;
}
