函数：参数传递、重载与递归

掌握函数定义、参数传递方式、函数重载与递归，以及函数指针的基本用法。

开场问题：写了一个想「把传进来的数改成 100」的函数 void set(int x) { x = 100; }，调用后原变量纹丝不动；把形参改成 int& x 之后却成功了。同样是把变量交给函数，为什么「传值」和「传引用」的结果完全相反？

先朴素做法：把函数当成一个「可复用的动作」

函数最朴素的动机是把重复的代码打包起来：一段「算两个数之和」的逻辑写一次，起个名字 add，之后到处调用。它做对了什么？函数做到了三样事——给动作命名、把参数收进一个明确的口子、把结果通过 return 送出来。这样调用方只关心「给什么、拿什么」，不必再关心内部怎么写。

问题从「参数怎么进函数」开始。C++ 的形参默认是按值传递：调用时把实参复制一份给形参，函数体内操作的是这份副本，原变量不受影响。返回上面的例子——set(int x) 里改的是副本，所以外界看不到变化。要让函数改到调用方的原对象，就得换一种传递方式。

参数传递的四种方式

这是本章的核心，把四种方式摊开对照：

  • 按值传递 void f(int x)：复制实参。适合小对象（int、double、指针），也正因拷贝而天然与外界隔离，函数无法改到原值。
  • 按引用传递 void f(int& x)：形参是实参的别名，不加拷贝，改形参即改实参。适合「函数需要修改调用方对象」的场景。
  • 按 const 引用传递 void f(const std::string& s)：同样是别名，避免拷贝，但函数内不能修改它。大对象只读时这是推荐默认写法。
  • 按指针传递 void f(int* p)：传的是地址，函数内用 *p 访问原对象；指针可以是 nullptr，因此适合表达「这个参数可选」。

选择逻辑一句话概括：不需要改原值、且对象小，用按值；不需要改、对象大，用 const 引用；需要改原值，用引用；「可能没有」这个参数，用指针。把默认写法定为 const&，既省掉大对象的拷贝开销，又用 const 声明了「只读」的契约，出错时编译器会替我们拦下。

默认实参与返回值

朴素写法里，一个「打印问候」的函数常被写成两个版本：一个带称谓、一个用固定称谓。把两者合成一个，就用到默认实参：void greet(const std::string& name = "同学")，调用 greet() 时自动套用默认值，greet("小松鼠") 时用传入值。它做对了什么？减少了重复声明，也让「常见的调用方式」写起来更短。

它有一条限制：默认实参必须从右往左连续给。若 void f(int a, int b = 2, int c = 3) 合法，则中间或左边单给默认值就要出事——否则编译器无法知道某个实参该对上哪个形参。有关返回值：return 把控制权和结果一并交回调用处；函数返回类型决定了结果的类型，返回值会拷贝或移动给调用方的一个临时对象。若写成 const& 返回引用，就要特别小心——绝不能返回指向局部变量的引用，那是个悬垂引用（在指针一章会展开）。

函数重载与重载决议

朴素想法是「一个函数名只能对应一种参数」。但「相加」这个动作，对 int 和对 double 在概念上是一回事，硬要起两个名字（addInt、addDouble）就很笨。C++ 的办法是函数重载：同名函数可以有多份，靠参数列表（个数、类型、顺序）来区分。

决定「一次调用究竟命中哪个版本」的过程叫重载决议。编译器按「实参到形参转换的优劣」排序：完全匹配最好，需要一次「提升」（如 short 到 int）次之，需要「算术转换」（如 int 到 double）更差。于是 add(1, 2) 命中 int 版、add(1.5, 2.5) 命中 double 版。这里要注意两点：返回类型不参与重载区分（只有返回类型不同不构成重载），且当两个版本「一样好」时会出现二义性（ambiguous）编译错误。避免二义的常见手段是不给重载留「中间地带」，比如不要让 int 版和 long 版同时接受 short。

递归与调用栈

递归指的是函数直接或间接地调用自己。factorial(n) = n * factorial(n - 1) 这种写法把「阶乘」的定义原样搬进了代码，简洁得几乎和数学定义一模一样。它做对了什么：把一个大问题拆成「同样形式、但规模更小」的子问题，逻辑非常贴近人的思路。

每次递归调用，系统都会在调用栈上压入一个新的栈帧，保存本次的局部变量与返回地址。因此递归必须配两个条件才不会出事：

  • 递归基：一个明确的终止条件，如 if (n <= 1) return 1;，没有它递归永不停止。
  • 规模收敛：每次调用都必须让问题朝递归基靠近，比如 n 每次减 1。

栈帧是有限的常量空间，递归层数太深会耗尽栈，表现为栈溢出崩溃。所以深度可能很大的问题（如遍历长链）应当改用迭代，或改成显式的栈结构。递归的长处是表达力（树、回溯、分治），短处是深度受限——要在「写得清楚」和「跑得下来」之间权衡。

inline 与函数指针基础

普通函数调用有一次「跳转——返回」的开销。对于那些很小且被频繁调用的函数（如取最大值），这点开销占比可观，于是有 inline 关键字：它建议编译器把函数体就地展开，省掉调用开销。要说清的是，inline 只是建议，编译器可以不采纳；它真正的标准化含义是「允许这个定义出现在多个翻译单元而不报重复定义」，这让「把函数定义写进头文件」成为可能。

最后是函数指针：函数在程序里也有地址，int (*fp)(int, int) = &add; 让 fp 指向那个函数，之后 fp(1, 2) 等价于 add(1, 2)。它做对了什么？让「函数本身」可以作为数据传递——这正是「对数组排序时传入一个自定义比较规则」这类需求的底层机制，也是回调与策略模式的原型。

看一遍参数传递与递归示例

把函数当成一份「接口契约」

函数、参数传递与重载，本质上是给调用方提供一份接口契约：名字加参数列表决定「怎么调」，返回类型决定「拿到什么」，传参方式决定「函数有没有权限碰原对象」，默认实参与重载决定「同一动作对不同输入的表现」。递归与函数指针则把这层契约往前推了一步——前者让定义自身可复用，后者让函数能像数据一样被传递。写函数时先定契约（参数用 const& 还是引用、是否需要修改原值），再写实现，代码的边界就会清晰很多。

「形参」是函数定义里的参数，「实参」是调用时传入的值；「重载决议」是按实参到形参的转换优劣挑选重载版本的过程；「栈帧」是每次函数调用在调用栈上分配的一块空间，保存局部变量与返回地址；「二义性」指多个候选版本优劣相同、编译器无法选择的重载错误。

关键代码

C++
// ═══════════════════════════════════════════
// 1. 参数传递：值 / 引用 / const 引用
// ═══════════════════════════════════════════

#include <iostream>
#include <string>

void byValue(int x) {                       // 按值：操作的是副本
    x = 100;                                // 结果：不影响调用方的原变量
}

void byReference(int& x) {                  // 按引用：形参是实参的别名
    x = 100;                                // 结果：原变量被改成 100
}

void print(const std::string& s) {          // 按 const 引用：不拷贝、且不可修改
    std::cout << s << std::endl;            // 结果：输出传入的字符串
}

int main() {
    int a = 5;
    byValue(a);
    std::cout << a << std::endl;            // 结果：5，未被修改

    int b = 5;
    byReference(b);
    std::cout << b << std::endl;            // 结果：100，已被修改
    return 0;
}

// ═══════════════════════════════════════════
// 2. 默认实参与返回值
// ═══════════════════════════════════════════

std::string greet(const std::string& name = "同学") {   // 默认实参从右往左连续给
    return "你好，" + name;                  // 返回值拷贝给调用方
}

int main() {
    std::cout << greet() << std::endl;       // 结果：你好，同学
    std::cout << greet("小松鼠") << std::endl; // 结果：你好，小松鼠
    return 0;
}

// ═══════════════════════════════════════════
// 3. 函数重载与重载决议
// ═══════════════════════════════════════════

int add(int a, int b) {                      // 整型版本
    return a + b;
}

double add(double a, double b) {             // 浮点版本，仅靠参数列表区分
    return a + b;
}

int main() {
    std::cout << add(1, 2) << std::endl;         // 结果：3，命中 int 版
    std::cout << add(1.5, 2.5) << std::endl;     // 结果：4，命中 double 版
    return 0;
}

// ═══════════════════════════════════════════
// 4. 递归与调用栈
// ═══════════════════════════════════════════

int factorial(int n) {
    if (n <= 1) return 1;                    // 递归基：终止条件
    return n * factorial(n - 1);             // 每次规模减 1，朝递归基收敛
}

int main() {
    std::cout << factorial(5) << std::endl;  // 结果：120，5*4*3*2*1
    return 0;
}

// ═══════════════════════════════════════════
// 5. inline 与函数指针
// ═══════════════════════════════════════════

inline int maxOf(int a, int b) {             // 建议就地展开，省去调用开销
    return a > b ? a : b;
}

int main() {
    int (*fp)(int, int) = &maxOf;            // 函数指针：指向一个 int(int,int) 函数
    std::cout << fp(3, 7) << std::endl;      // 结果：7，等价于 maxOf(3, 7)
    return 0;
}
