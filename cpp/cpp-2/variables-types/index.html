变量、基本类型与类型转换

掌握 C++ 的基本内置类型、变量声明初始化、作用域规则以及隐式与显式类型转换。

开场问题：int x = 3.14; 编译器一声不吭，x 悄悄变成 3；可你把同样的意思写成 int x{3.14};，编译直接报错、拒绝生成程序——同一个 3.14 塞进 int，为什么两种写法一个静默截断、一个当场翻脸？

静态类型约束

你要在程序里存一个价格，很自然地写 double price = 19.9;；要存一个数量，写 int count = 10;。C++ 是静态类型语言：每个变量在写下来的那一刻就要定死类型，编译器据此分配固定大小的内存、决定这串二进制到底该按整数还是按浮点去解释。静态类型最大的好处是很多错误在编译期就能发现，而不是等你运行到那一行才崩。

但这份好处是有代价的：类型是你亲手选的，编译器只会照着你的选择走。坑大多出现在「两种类型相遇」的时候。你在算式里混着用 int 和 double，语言为了让你少写转换，会自动做隐式转换。可当自动转换发生在「收窄」的方向上——把浮点塞进整数、把 64 位塞进 32 位——它不会报错，只会悄悄丢掉一部分信息。等你发现金额差了 0.9，已经找不到是哪一步丢的。

旧办法（随手用一个 = 声明、转换全交给编译器）要人承担的成本：第一，窄化转换静默发生，没有警告你就不会察觉；第二，有符号与无符号混用时，负数会被悄悄转成一个巨大的正数，后面所有比较都错；第三，类型选得随意，等到数据装不下才在运行时发现。

所以问题落到：面对一堆内置类型，我该怎么选、怎么初始化、怎么转换，才能让编译器替我把「丢信息」的风险挡在编译期？

等号初始化语法

最省事的做法：声明变量时统一用一个 =，类型和转换都交给编译器去配。int x = 3.14; 编译通过、能跑；unsigned u = -1; 也能通过，只是 u 变成了一个大正数。

这个方案确实做对了一件事：它足够宽松，让安全和危险的转换在写法上看起来一样，早期代码可以很快写出来。而且大部分「安全方向」的转换（int 到 double）确实不需要你操心，这也正是语言愿意自动做隐式转换的原因。

问题在于，它把「这里其实丢了一个小数位」「这里其实把负数翻成了正数」这两件完全不同的事，写成了和普通赋值一模一样的形式。

窄化转换无警告

  • int x = 3.14; 得到 3——小数点后全丢，而编译器默认连个警告都不给（除非你开 -Wconversion）。
  • unsigned u = -1; 得到 4294967295——负数翻成一个巨大的正数，后续所有参与它的大小判断都错。
  • -1 < 0u 判断为假——因为比较时 -1 先被转成无符号，成了 4294967295，比 0 还大。你以为在判断「负数小于零」，实际在比一个大正数。
  • char 到底是有符号还是无符号由实现决定，同一段处理小整数的代码换一个平台，结果可能不同。
  • 把一个超过 2^31-1 的 long long 塞进 int，高位被直接截掉，得到的值和你预期的毫无关系。

花括号统一初始化

不推翻「类型由你自己选」，而是给「选」和「转」各加一道编译期闸门。先补的那一步是换一种初始化语法，因为它能立刻挡住最常见的窄化，成本最小。

C++11 引入的统一初始化用花括号：int x{5};。它和 = 的关键差别在于——花括号初始化禁止窄化转换。int x{3.14}; 会直接编译报错，编译器宁可让你改代码，也不让你偷偷丢数据。这就是开场两种写法差异的全部来源：= 允许窄化，{} 不允许。花括号还有个附带好处，它能初始化任何类型（数组、结构体、容器），语法统一，减少记忆负担。

补完初始化，接着要补的是「类型该怎么选」的规则，否则你只是把危险写法换了个皮。能用 int 就用 int，它与机器字长匹配、通常性能最好；short 很少有必要；确定要 64 位大整数才用 long long；要小数且在意精度用 double，别用 float；处理单个字符用 char，但如果当小整数用，就明确写 signed char 或 unsigned char。

再往下补的一层是把转换显式化。需要截断就写 static_cast<int>(pi)，而不是让编译器替你决定。(int)pi 这种 C 风格转换也能用，但它可能在你不注意时做出更危险的重新解释；C++ 风格的四兄弟——static_cast、dynamic_cast、const_cast、reinterpret_cast——把「我想做的是哪一种转换」写在了脸上，读代码的人一眼能分辨。

最后补上作用域这一步：变量不是声明了就永远活着。块作用域 { } 内的变量出了大括号就消失，让它活得尽量短能减少误用。C++17 起还可以把变量直接声明在 if 或 switch 的条件里，写成 if (int x = foo(); x > 0) {...}，x 就只在 if 内部可见，用完即弃。

初始化方式对照

类型选择责任

静态类型把「每个变量是什么」的权力交给你，也把责任交给你。选类型按范围和用途来，初始化优先用花括号让编译器挡住窄化，转换一律显式——这三条合起来，隐式转换带来的「静默丢数据」就被堵在了编译期，而不是留到你翻账单的时候才发现。

「窄化转换」指目标类型无法无损容纳源值的转换，例如 double 到 int、long long 到 int、有符号到无符号。C++11 的统一初始化 {} 会在编译期禁止窄化（int x{3.14}; 报错），而 = 与 () 形式允许它静默发生。边界：编译器默认不拦窄化，只有 {} 和 -Wconversion 会提醒你。

关键代码

C++
#include <iostream>
#include <limits>

int main() {
    int n = 100;
    double d = 3.14159;
    char c = 'A';
    bool b = true;

    // 统一初始化
    int x{5};
    // int bad{3.14};  // 编译错误！

    // 类型转换
    double pi = 3.14159;
    int intPi = static_cast<int>(pi);

    return 0;
}
