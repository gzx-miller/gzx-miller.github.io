变量、基本类型与输入输出

掌握 C++ 基本内置类型的取值范围、变量声明与初始化方式，以及标准输入输出的基本用法。

开场问题：要算一组成绩的平均分，sum 和 count 明明都没算错，可 int average = sum / count; 却把 87.5 写成了 87——数字没错、变量也没错，那小数点后面的 0.5 究竟被什么吞掉了？

从「丢失的 0.5」说起：先朴素地声明变量

最直接的做法，是给每个数据起个名字再往里放值：int sum = 350;、int count = 4;，最后 int average = sum / count;。这套写法几乎零门槛，也确实交代了一件重要的事——每个变量在编译期就必须有确定的类型，编译器据此决定为它分配几个字节、用整数指令还是浮点指令去运算。

问题恰恰出在这个「类型」上。上面式子里的 sum / count 是两个 int 相除，C++ 对整数除法采用向零取整：350 / 4 得到 87 而不是 87.5，小数部分在除法进行的那一刻就已丢掉。这不是「算错了」，而是「类型选得不够精确」。想让结果保留小数，得让参与运算的对象里至少有一个是浮点类型——double average = sum / count; 依然不行（右边先按整数算完再赋值），要写成 double average = static_cast<double>(sum) / count;。

可见「选类型」不是随手一写的小事。要把它做对，得先知道 C++ 究竟提供了哪些内置类型、各自能装多大的数。

基本内置类型：按位数与符号排布的一张清单

把内置类型摊开来看，它其实是两组坐标的组合：占多少位（宽度）决定能装下多大的数，是否有符号决定能不能装负数。

  • 整数：short（至少 16 位）、int（通常 32 位）、long、long long（至少 64 位）。标准只规定最小宽度，具体字节数由平台决定，可用 sizeof 实测。
  • 无符号整数：在类型名前加 unsigned，如 unsigned int。它只表示非负数，取值范围约为同宽度有符号类型正数部分的两倍。
  • 浮点：float（约 6~7 位有效数字）、double（约 15~16 位）、long double。用 double 装整数时，超过 2 的 53 次方就未必能精确表示。
  • 字符与布尔：char 占 1 字节，存的是字符编码值，如 'A' 实为 65；bool 取值只有 true 与 false。

这里藏着一个典型坑：同一段代码在 32 位与 64 位平台上，int 可能都是 4 字节，但 long 的宽度会变。凡是对宽度敏感的逻辑（跨平台读写二进制、位运算掩码），都不要凭记忆假定字节数，而应基于标准保证的最小宽度，或直接用固定宽度类型 int32_t、uint64_t。

无符号类型的另一个陷阱是「回绕」。unsigned int u = -1; 看着像把负数存进去了，实际是按 2 的 32 次方取模：u 变成 4294967295。更隐蔽的是比较运算——-1 < 0u 的结果是 false，因为「有符号与无符号混用」时，有符号的一方会先被转换成无符号，-1 于是也变成一个极大的正数。类型选择上的一点疏忽，会在比较、循环边界这些地方变成难以察觉的错误。

声明、初始化与「窄化转换」

朴素做法通常是「先声明、后赋值」：int x; x = 5;，或用等号凑一步：int x = 5;。它做对了什么？把「分配空间」和「写入初值」两件事分开，语义直白。但它留下的隐患是：若只写 int x; 而忘记赋值，块作用域里的内置类型变量会得到一个不确定的值，读它属于未定义行为；而 int x = 3.14; 这种「拿小数初始化整数」会被静默截断成 3，编译器一声不吭。

C++ 的迭代是引入列表初始化（也称统一初始化）：用花括号包住初值。

  • int a = 5;：拷贝初始化，传统写法。
  • int b(5);：直接初始化，用圆括号。
  • int c{5};：列表初始化，C++11 起引入。
  • int d{};：空花括号即值初始化，把对象初始化为 0，替代了容易漏的「忘记初始化」。

花括号最实在的好处是拒绝窄化转换：凡是会丢失信息的转换，编译器都会报错。int bad{3.14}; 直接编译失败，而同样的内容写成 int bad = 3.14; 只会默默截断。也就是说，花括号把「精度损失」从运行期的静默行为，提前成了编译期的显式报错。代价是多记一种语法形式，但对新代码而言，花括号初始化通常是更安全的首选。

const、constexpr 与生命周期

表示「常量」的最老做法是宏：#define PI 3.14159。它做对了什么？预处理器把 PI 原地替换成字面量，零运行时开销。但宏是纯文本替换：没有类型、不遵守作用域、也无法被调试器观察，一个拼写疏忽就会产生莫名其妙的编译错误。

下一步是用 const。它给常量加上类型与作用域，初始化后不可修改；但「不可改」发生在运行期——const int n = readInput(); 完全合法，n 要到程序跑起来才知道值。再进一步是 constexpr：它要求初始化必须是编译期常量表达式，于是这类常量能出现在数组长度、模板参数、case 标签等「必须在编译期确定」的位置。

一句话区分：const 是「运行期不可改」，constexpr 是「编译期就能算出来」。凡是天然已知的常量，优先 constexpr。

与之紧密相关的是作用域与生命周期。作用域决定「名字在哪儿可见」：块作用域的名字出块即不可见，全局作用域的名字整个程序可见。生命周期则由存储期决定：块里的局部变量是自动存储期，进入块时创建、离开块时销毁；全局变量和带 static 的局部变量是静态存储期，其中 static 局部变量只在第一次执行到声明时初始化一次，之后跨函数调用一直保留。把这两个概念分清，才能解释「为什么循环里创建的对象每轮都是新的」「为什么 static 计数器能记住上一次的值」。

auto 与 decltype：把类型交给编译器推导

手写完整类型有时极其啰嗦，比如 std::vector<int>::iterator it = v.begin();。这类类型不但长，而且一旦容器换了，还得逐处改。C++11 的 auto 让编译器从初始化式推导类型：auto it = v.begin();。

auto 的推导规则里有一条必须记住：它按值推导时会丢弃顶层 const 和引用。给定 const int ci = 42;，写 auto x = ci; 得到的是 int（const 被丢掉），而 auto& r = ci; 得到的是 const int&（保留 const）。所以想保留限定符，就显式写成 const auto& 或 auto&。

若连「按值」都不想要，而是要原样照抄表达式的类型，就用 decltype：decltype(ci) w = 7; 得到的是带 const 的 const int，引用与 const 全部保留。二者的分工可以概括为：auto 图省事、会做类型消解；decltype 要精确、会原样保留。

输入输出：类型安全的流与格式控制

早期的做法是 C 风格的 printf / scanf：优点是把格式写在一根字符串里、控制集中，缺点是格式串和参数类型各写各的，%d 对上一个 double 就是未定义行为，编译器也无从检查。

C++ 的迭代是 std::cout << 与 std::cin >>。这里的 << 和 >> 不是位移运算，而是被重载出来的「输出流插入」与「输入流提取」运算符：编译器会按实参类型挑选对应的重载版本，因此类型不匹配会在编译期被拦下。链式书写 std::cout << a << b; 则是把前一次的输出流结果作为下一次的左操作数，逐段拼出整行。

  • std::endl 既换行又刷新缓冲区，而 '\n' 只换行。频繁输出时用 '\n' 可以减少不必要的刷新。
  • 格式控制由 <iomanip> 提供，例如 std::fixed 配合 std::setprecision(2) 把浮点固定输出两位小数。
  • 输入可能失败：当 std::cin 读不到符合类型的值时，会置位 failbit，此时 if (std::cin >> x) 判定为失败，需要 std::cin.clear() 清除状态才能继续读。

最后回到最初那个坑：std::cin 向 unsigned 变量读入负数时会直接回绕成一个大正数——「输入输出的类型安全」与「类型选择」其实是同一件事的两面。

看一遍类型与转换的对照

把类型当成一份「值域台账」

变量、类型与输入输出，本质上是一份值域台账：每个对象都有确定的类型，类型划定它能装下什么、能参与哪种运算；声明决定名字可见的范围，存储期决定它活多久。写代码时先问「这个值可能多大、要不要负数、要不要小数」，再选类型；用花括号初始化把窄化转换挡在编译期；输出时交给重载的流、别用裸格式串。把这几条固定下来，前面那种「结果少了个 0.5」的问题，就会在编译阶段暴露，而不是悄悄溜进运行结果里。

「对象」指一块有名字、有类型的存储区域；「值域」是类型能表示的数集，由宽度与符号共同决定；「窄化转换」指会丢失信息的隐式转换，列表初始化会拒绝它；「存储期」决定对象的生命周期，局部变量是自动存储期，全局与 static 变量是静态存储期。

// ═══════════════════════════════════════════
// 1. 基本内置类型与取值范围
// ═══════════════════════════════════════════

#include <iostream>

int main() {
    short  s  = 32767;                      // 16 位有符号整数上界
    int    n  = 2147483647;                 // 通常是 32 位有符号整数上界
    long long ll = 9223372036854775807LL;   // 64 位有符号整数上界，后缀 LL
    unsigned int u = 4294967295u;           // 无符号 32 位上界，后缀 u
    float  f  = 3.14159f;                   // 单精度，约 7 位有效数字
    double d  = 3.141592653589793;          // 双精度，约 15~16 位有效数字
    char   c  = 'A';                        // 1 字节，实际存的是编码值 65
    bool   b  = true;                       // 只取 true 或 false

    std::cout << sizeof(int) << std::endl;  // 结果：4（本平台）
    std::cout << sizeof(char) << std::endl; // 结果：1
    return 0;
}

// ═══════════════════════════════════════════
// 2. 变量的三种初始化与窄化转换
// ═══════════════════════════════════════════

int main() {
    int a = 5;          // 拷贝初始化：传统写法
    int b(5);           // 直接初始化：圆括号
    int c{5};           // 列表初始化：花括号，C++11 起
    int d{};            // 值初始化：空花括号，初值为 0
    // int bad{3.14};   // 编译错误：窄化转换，double 到 int 被花括号拒绝
    int ok = 3.14;      // 同样内容用等号初始化：静默截断为 3
    return 0;
}

// ═══════════════════════════════════════════
// 3. const 与 constexpr
// ═══════════════════════════════════════════

const int kDay = 7;                         // 运行期常量，初始化后不可修改

constexpr int power2(int e) {               // constexpr 函数，可用于编译期求值
    return 1 << e;
}

int main() {
    constexpr int kBits = power2(3);        // 编译期即算出 8
    int buffer[power2(4)];                   // 结果：数组长度 16，编译期确定
    const int n = 10;                        // const 只保证不可改，不保证编译期可算
    return 0;
}

// ═══════════════════════════════════════════
// 4. 作用域与生命周期
// ═══════════════════════════════════════════

int counter = 0;                            // 全局变量，静态存储期，贯穿程序

void tick() {
    static int calls = 0;                   // 静态局部变量，只初始化一次
    ++calls;                                // 说明：每次进入 tick 都保留上次的值
    ++counter;
}

int main() {
    int local = 1;                          // 自动存储期，出块即销毁
    {
        int local = 2;                      // 内层块作用域，遮蔽外层同名变量
    }
    return 0;
}

// ═══════════════════════════════════════════
// 5. auto 与 decltype 类型推导
// ═══════════════════════════════════════════

#include <vector>

int main() {
    auto x = 5;                             // 推导为 int
    auto y = 3.14;                          // 推导为 double
    const int ci = 42;
    auto z = ci;                            // 推导为 int，顶层 const 被丢弃
    auto& r = ci;                           // 推导为 const int&，保留 const
    decltype(ci) w = 7;                     // 推导为 const int，原样保留限定
    std::vector<int> v{1, 2, 3};
    auto it = v.begin();                    // 推导为 std::vector<int>::iterator
    return 0;
}

// ═══════════════════════════════════════════
// 6. 标准输入输出与格式控制
// ═══════════════════════════════════════════

#include <iomanip>

int main() {
    int age = 0;
    std::cin >> age;                        // 从标准输入读入一个整数
    std::cout << "age=" << age << '\n';     // 输出：age=<读入的值>
    double pi = 3.14159265;
    std::cout << std::fixed << std::setprecision(2) << pi << std::endl;  // 结果：3.14
    if (!(std::cin >> age)) {               // 读入失败时 failbit 置位
        std::cin.clear();                   // 清除错误状态才能继续读
    }
    return 0;
}

// ═══════════════════════════════════════════
// 7. 有符号与无符号混用的陷阱
// ═══════════════════════════════════════════

int main() {
    unsigned int u = -1;                    // 结果：4294967295，负数按模回绕
    int s = -1;
    bool cmp = (s < 0u);                    // 结果：false，比较时 s 被转成无符号
    for (unsigned i = 5; i >= 0; --i) { }   // 危险：i 永不为负，条件恒真
    return 0;
}
